# Scout: report guardrails

## Question
Identify why harness feedback issues contain only metadata and the smallest coherent implementation surface for useful details, autonomous reporting, and reporting when encountered.

## Findings
- `./init.sh` passed on 2026-10-08; only the existing disarmed escalation warning appeared. No production files, board state, or GitHub issues were changed. This reconnaissance did not fetch the five issue bodies; the session owner can supply those separately.
- Metadata-only reports are the intended current implementation, not missing argument plumbing: `tools/harness-report.sh:8` explicitly forbids any outbound free-form text; `:483-502` creates only marker/version/trigger/symptom/file/optional command/exit/role/phase. `--notes-file` is parsed at `:112`, copied verbatim only into the local report at `:407`, and never read by upstream assembly. No summary, expected/actual behavior, reproduction, or evidence input exists. Required data are trigger, symptom, a valid version, at least one accepted harness-owned path, and session token (`:322-428`). A generic symptom and one path therefore satisfy all quality gates.
- The generated skill reinforces this: `.agents/skills/sdd-report/SKILL.md:138` mandates local-only prose. The canonical source is the installer heredoc `harness-install.sh:5772-5909`; generated `.agents/skills`, `.claude/commands`, and `.opencode/command` copies must not be the only edited locations.
- Tests explicitly pin the weak outcome: `tests/test_feedback_report.sh:480` requires the body to contain only fixed metadata lines and proves notes never reach upstream. `tests/test_reporting_rule.sh:449-457` pins the command's local-only prose rule. Existing F02/F03 specs under `specs/epics/E32-feedback-loop/` mandate those same old boundaries, so new work must explicitly supersede the applicable requirements rather than silently claiming to implement them unchanged.
- Four triggers are fixed in `_valid_trigger` (`tools/harness-report.sh:175`): harness-malfunction, contradictory-instruction, workaround, missing-capability. Nine symptom codes are at `:181`. Phase is optional and limited to inception, architect, builder, reviewer, scout, slice-dispatch, handoff, install (`:195`); invalid nonempty phase rejects the whole upstream report. Phase enum validity is separate from the prompt-level prohibition on reporting mid-flow.
- Timing is controlled by prose, not the tool: `AGENTS.md:67`, `docs/WORKFLOW.md:754`, and the reporting sections in orchestrator/fixer/inception/planner/driller require end-of-task or early-stop only. `tests/test_reporting_rule.sh:129-143,195-196` pins that timing. Subagents currently append a minimal ledger entry and never invoke the reporter; only session owners file. Allowing immediate owner filing can retain that ownership rule.
- No per-report consent prompt exists in the tool or command. Reporting is already automatic when `feedback.enabled` is bare `true`; new installs default on and issue an opt-out notice (`docs/INSTALL.md:417-447`, `harness-install.sh:565`). A new explicit no-confirmation instruction can remove model ambiguity without adding any CLI approval switch.
- Session cap defaults to 3; 0 suppresses upstream creation (`tools/harness-report.sh:166-172,431-446`). Stable session token comes from environment/argument, with generated skill fallback using telemetry/persisted timestamp. Do not regenerate it per immediate report. Exact-title duplicate detection is currently `[harness-feedback] <trigger> <symptom> in <first_file>` (`:461-479`): distinct defects in the same file with the same category collide; useful details alone will not fix that.
- Existing redaction (`:71-84`) handles known token forms, emails, and only several absolute-path prefixes. It is not a general secret/project-content detector. Publishing arbitrary raw notes or raw logs would invalidate the current privacy claim.
- The GitHub labeler classifies only the first versioned marker and treats all other body bytes as untrusted (`.github/workflows/harness-feedback-labeler.yml:3-5`). Retaining exactly one compatible marker avoids an unnecessary marker migration.

## Candidate implementation surface (for Architect/Builder decision)
1. Add a separate structured, bounded public-detail input to the reporter (for example a JSON file with summary, observed, expected, reproduction/evidence); keep `--notes-file` local-only. Require all useful sections to be nonempty and non-placeholder before any GitHub call. Tool must reject metadata-only invocations to the local copy with a clear reason, preserving exit-0 behavior. Draft public details from verified harness evidence, not raw project logs; never invent a reproduction.
2. Sanitize and validate the detail object centrally, include accepted details in both upstream and local report, and preserve marker integrity. Explicitly document the new privacy boundary. Reject malformed schema, oversized/control/marker injection, missing evidence, and empty-after-redaction content. Regex redaction cannot guarantee arbitrary prose is non-sensitive; prompt instructions must constrain the draft to harness behavior and sanitized examples.
3. Change the canonical reporting command to gather and pass the required details, locally retain insufficient reports without asking the user, and allow session owners to report upon verified discovery then resume work (hard-stop init exception must still stop). Update the five owner roles, subagent ledger fields, AGENTS.md, WORKFLOW, INSTALL, README, and installed templates/glue consistently. Preserve four triggers, independent review, human spec gate, opt-out, stable cap, and local fallback unless the approved scope explicitly changes them.
4. Replace obsolete positive metadata-only fixtures with complete detail fixtures; retain a negative metadata-only case. Cover missing/placeholder/redacted-away details, malformed payload, shell/marker injection, notes staying local, valid detailed report, disabled/capped/duplicate/fallback behavior, installed-layout behavior, and generated command forwarding. Update timing assertions to pin immediate autonomous filing and continued work.
5. Regenerate via `sh harness-install.sh --self`, verify manifests and all selected hosts, deliberately bump VERSION with CHANGELOG, and run init plus configured verification before independent Reviewer verdict. `tests/test_self_drift.sh` and `tests/test_reporting_rule.sh` exercise canonical-versus-generated propagation.

## Open questions / risks
- Useful semantic evidence cannot be guaranteed by character-count checks alone. Define concrete required content and placeholder rejection, with prompt responsibility for factual quality and deterministic tool rejection for absent structure.
- Decide whether same-file/category dedup collision is in scope; keeping the old key is smallest but still collapses unrelated defects.
- This policy change alters existing E32 guarantees. Route through an explicit approved spec or documented authorized fix lane; do not bypass the human spec-ready gate merely because reporting itself is autonomous.

## Evidence payload and privacy recommendation
A distinct `--details-file` JSON object can require five strings: `summary` (specific defect), `observed` (actual result), `expected` (documented contract), `reproduction` (minimal harness-only setup/action), and `evidence` (short decisive result or conflicting source excerpts). Keep `--file` as the existing separately validated ownership anchor; reference those accepted paths in evidence, with line numbers where useful. For instruction conflicts, reproduction describes the two incompatible steps and evidence quotes both harness sources; an exit code is not fabricated. Missing-capability reports must describe the repeated blocked operation and existing workflow gap.

Fail closed before `gh auth`/search/create when the payload is missing, unreadable, malformed, lacks any required field, contains non-string/extra fields, has placeholder-only values, exceeds conservative per-field/total bounds, includes control characters or a forged marker, or loses useful content after sanitation. Write the local outcome/reason and preserve raw notes locally; return 0. No confirmation prompt and no automatic raw-notes fallback. Reject known credential and project-specific path material rather than relying on redaction to make an otherwise empty report useful; validate the final sanitized payload too. The skill should compose the payload afresh from public harness source/behavior and synthetic minimal examples, excluding customer/project names, repository URLs, project file contents, environment dumps, credentials, and unrelated raw logs. If a safe factual payload cannot be formed, retain local-only and continue authorized work. No finite regex can prove prose contains no confidential meaning, so documentation must not continue claiming that arbitrary public prose has the old enum-only privacy guarantee.

Preserve exact-title duplicate and session-cap machinery initially; changing reporting time does not require changing either. On successful immediate filing, the calling owner resumes the interrupted workflow; the command's existing “report and stop” wording must mean return from the reporting invocation, not terminate the whole work session. The init nonzero reporting exception remains a report followed by hard stop.
