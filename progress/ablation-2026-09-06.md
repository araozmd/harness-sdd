# Ablation run — 2026-09-06 (docs/ABLATION.md protocol, second execution)

Two `sdd:false` fixes on one branch, run **sequentially** (never concurrently — a shared
worktree and a shared test suite would have made every wall-clock and every red
unattributable). Real Builder sub-agents, both `sonnet`. One variable: the role prose the
Builder receives — stock `agents/builder.md` (1,499 words) vs. the `docs/ABLATION.md`
skeleton (121 words), delivered verbatim.

**Deliberate design change from run 1, and why.** Run 1 swapped the skeleton onto disk at
`agents/builder.md`, which reddened 5 suites that assert that file's content — a
contaminant its own write-up flagged. Here the skeleton was delivered **inline as the
sub-agent's role prose**, with `agents/builder.md` left untouched on disk. This was not
optional by the end: run A's own work added `tests/test_reviewer.sh` R19, which asserts
`agents/builder.md`'s content, so an on-disk swap would now be a guaranteed red.

**Size assignment is inverted from run 1.** Run 1 gave the big task to the baseline and
the small one to the skeleton, so its wall/token deltas mostly measured the tasks. Here
the **skeleton got the larger task** (E99-F153: 5 files including a `harness-install.sh`
emitter, a `--self` regeneration, and a cross-file exit-code contract), the baseline the
smaller (E99-F154: 4 files, prose contract + 2 assertions). Together the two runs now
bracket the size confound from both directions.

## What the independent review campaign found

I re-ran every new assertion's mutation myself rather than trusting either report:
13 mutations in the first pass, 8 in the verification pass. Both agents' reported kills
were real. Two mutations **survived** — one per run.

**A1 (baseline, blocking).** R18 anchored `forbidden[^.]{0,60}git checkout` inside
`## What you check`. That expected value has **two** producing paths in that section: the
real prohibition, and the *negated illustration* run A added one bullet below to
demonstrate the negation trap. Relocating the real rule to an appendix left the suite
**green**. The feature whose entire subject is "what a green prose assertion does not
prove" shipped an assertion reachable by another path — the house's most-recurrent
defect, now at 4 occurrences. Fixed: anchor on `never use it`, a token only the real
prohibition carries. Verified by 4 mutations (relocate-whole, relocate-sentence-only,
polarity-flip-in-place, and relocate-leaving-a-fenced-quotation).

**A2 (baseline).** R18/R19 used the fence-blind `awk '/^## X/{k=1;next} /^## /{k=0} k'`
idiom while the repo ships `tests/lib/fence.awk` as "the one copy" and the brief asked
for the decision to be "pinned fence-aware". Not yet breaking (neither section contains a
fence today), but it is the exact defect E99-F131 closed. Fixed both extractors; proved
both directions — a fenced quotation of the rule no longer forges a pass (N4 kills), and
a fenced `##` line no longer forges a red (N5 stays green).

**B1 (skeleton).** The AUTH bucket's *remedy* sentence was unpinned: the assertions named
the fault (`gh`/`auth`/`jq`) but nothing required the message to say what to do, so
stripping "or set `pr_loop.enabled: false`" left the suite green. The brief explicitly
asked for "the message names the matching remedy". Fixed with a per-arm `pr_loop.enabled`
assertion; verified on two different arms.

**B2 (skeleton, process).** Run B found a genuinely non-obvious POSIX trap — a bare
`if cmd; then exit 0; fi; exit $?` exits **0** when the condition is false, clobbering
`$?` — diagnosed it empirically, and wrote it into a source comment. It did **not**
append it to `progress/lessons.md`. Run A did append. The stock prose says "append one
dated line… never rewrite or delete"; the skeleton never names the ledger.

## Reading (honest limits)

- **Not a clean size-controlled comparison either**, in the opposite direction from run 1.
  The skeleton's 1.6× wall-clock and 1.3× tokens are mostly the bigger task: B touched an
  installer emitter and regenerated glue; A did not. Tool uses came out nearly equal
  (70 vs 68) *across a real size gap*, which is the one number that hints the skeleton
  wasn't cheaper per unit of work.
- **On output quality the two arms are indistinguishable, and that is the finding.** Both
  produced correct, tested, suite-green work; both left exactly one unpinned assertion
  behind. The stock arm's miss was the *more serious* of the two, and it was a miss of a
  discipline its own prose spells out across three long bullets — while the skeleton only
  implies it. 1,378 extra words bought no measurable assertion quality here.
- **The skeleton kept every behavior run 1 said it kept**, on a harder task: it worked the
  inbox brief, mutation-verified with printed diffs, backed up with `cp`/restored with
  `mv`, refused to touch the other lane's files, and followed the
  "`.claude/*` is GENERATED — run `--self`" convention. That convention lives in
  `CLAUDE.md`, not in `agents/builder.md`: **the repo's own docs carried it, not the role
  prose.** Same shape as run 1's ledger finding.
- **The one candidate line to restore is the ledger append**, and it is at **one**
  occurrence, not two. Run 1's lanes landed as a single squashed commit (`a299214`), so
  its lessons entries cannot be attributed to the skeleton or the baseline arm — I could
  not confirm the failure repeated. Per the protocol ("once is an anecdote; twice is a
  line to restore") this stays recorded, not restored. **Watch it in run 3.** If it
  recurs, the line to bring back is a single sentence, not the section:
  *"Read `progress/lessons.md` before you start; when something surprising costs you a
  round, append one dated line."*
- **My own instrument failed twice, and that is data about reviewing, not about prompts.**
  A first campaign reported 8 confident kills that were all forged — the suite is a
  non-executable `#!/bin/sh` file, so `./tests/…` exited "Permission denied" and a
  non-zero rc read as a kill. And a `replace(old, new, 1)` mutation twice edited the
  *header comment* that quotes the same sentence as the `echo`, producing a landed diff
  that proved nothing. The AUTH-remedy gap (B1) happened to be real anyway, confirmed by a
  correctly-targeted rerun. Both are now in `progress/lessons.md`.
