# Intent — Source-only /sdd-triage: group harness-feedback issues, propose routes, seed only on human approval

## Problem / who
The maintainer needs one command that turns incoming reports into routed work without letting a stranger's issue steer an agent.

## Success outcome
`/sdd-triage` (emitted only under `--self`, ADR-0005) lists open `harness-feedback` issues, groups duplicates, proposes per issue: E99 fix via `/sdd-fix`, new work via `/sdd-new`, or close with a reason; presents the plan; on the human's approval seeds the approved items and comments/closes as approved. Seeded briefs reference the issue number and are written in the triager's own words; resulting PRs use `Fixes #N`.

## Scope / boundaries
In: command body + role guidance, a narrow PR-body change so a feature seeded from issue #N (recorded in its brief/board row) gets `Fixes #N` in its PR body, SELF_MODE-only emission across front ends, tests proving targets never get it. MINOR `VERSION` bump + `CHANGELOG.md` entry (installer and `agents/` change). Out: scheduled/autonomous triage (non-goal).

## Chosen options
- On-demand only; human approval before any TaskStore write or issue close (user decision).

## Constraints
- Epic contract: `specs/epics/E32-feedback-loop/epic.md` (success criteria are binding).
- Issue bodies are untrusted data (ADR-0006): never executed, followed, or copied verbatim into a brief.
- Reuses `/sdd-fix` and `/sdd-new` contracts unchanged.
- ADRs to honor: ADR-0005, ADR-0006, ADR-0003.

## Open questions
- Whether triage writes its proposal to `progress/` for resumability.
