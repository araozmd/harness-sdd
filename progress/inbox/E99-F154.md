# Intent — two unstated bounds of anchored prose assertions

## What already shipped (do NOT redo)

The original item carried three limits. **Limit 1 (rewrap fragility) is fixed**: the
E99-F75/F76 verification-hygiene pass routed every `tests/test_reviewer.sh` assertion
through the folded form (`tr '\n' ' '`), and the two-token folded-newline pin composed
with section extraction and `tests/lib/fence.awk` is now the house convention. Verified
2026-09-06: zero unfolded multi-word greps remain in that suite. This row is the
**residual only**.

## Problem / who

Two bounds of grep-on-prose remain unstated, both found by a Reviewer's own mutations
and both of which **survived**:

1. **Negation immunity.** `Not strictly forbidden as the revert, but avoid: git
   checkout -- <file>` still satisfies a FORBIDDEN-anchor assertion, because grep sees
   co-occurrence, not polarity. A contract file can therefore be edited to recommend the
   very thing it forbids and the suite stays green. This is **recurring**: it was
   independently re-encountered building viernes' `E99-F122` CLAUDE.md reference checker,
   where a file quoting a dead name *in order to warn about it* read identically to one
   recommending it. That checker's answer was a per-file ignore directive; whether the
   same shape suits a contract file is the question to settle here.
2. **Placement unpinned.** The whole mutation-revert block relocates to an appendix and
   the suite stays green. The rule's visibility at the point of use is what makes it
   followed, and nothing asserts where it sits.

## Intended fix

Decide each bound explicitly rather than carrying it silently: either strengthen the
check (a polarity-aware assertion for the forbidden anchors; a placement pin for the
mutation-revert block) or **state the bound** in the Builder's assertion convention so
the next author knows what a green suite does not prove. A stated bound is an acceptable
outcome here; an unstated one is not.

## How to verify

Whichever way each is decided, the decision is falsifiable: a polarity mutation
("but avoid: …") and a relocation mutation must each either fail the suite or be named
as an accepted bound in the convention text, pinned fence-aware.
