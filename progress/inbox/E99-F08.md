# `change-size --format json` must escape every C0 control character, not just tab

## Why this exists

Codex raised exactly one finding on PR #83, tagged **P2**. It is correct, and it is in code
that PR wrote. It was deferred under the **stated** stopping rule — `pr_loop.blocking_severities`
is `P0,P1`, fixed before the round ran — rather than a rule discovered after seeing the finding.

## The defect

`_json_escape` in `tools/change-size.sh` escapes `\`, `"` and tab. It does **not** escape the
other C0 control characters.

E99-F07 moved the tracked path scan to `git diff --numstat -z`, which correctly stops git
C-quoting special characters — so a raw control byte in a tracked pathname now reaches the
emitter *unencoded*, where before it arrived C-quoted. A tracked `src/a<CR>b.js` therefore makes
`--format json` **exit 0 while emitting JSON that `jq` rejects** with an invalid-control-character
error.

Fail-silent, not fail-loud: the caller gets a success exit and unparseable output, and only
discovers it when the consuming `jq` dies.

## Relationship to the declared limits — read this before scoping

E99-F07 explicitly documents a filename containing a literal **newline** as unsupported, on the
grounds that `-z` framing handles every other special character. That statement is about the
**path-parsing** layer and it remains true there.

This defect is one layer further out — the **JSON emitter** — and the declaration does not cover
it. So this is a genuine gap in the declaration rather than a contradiction of it. Do not close
it by widening the "unsupported" note; the emitter is a different contract from the parser, and
a tool that claims JSON output should emit valid JSON or fail loudly.

## Success outcome

`--format json` either emits valid JSON for any pathname git can track, or exits non-zero with a
named reason. It never exits 0 with output `jq` cannot parse.

## Scope / boundaries

**In scope**
- `_json_escape` handles **every** C0 control character reachable by the emitter (U+0000–U+001F),
  using the `\u00XX` form for those without a short escape, plus the existing `\\`, `\"`, `\t`,
  and the short forms for `\n`, `\r`, `\b`, `\f`.
- A regression test proving a tracked pathname containing a raw CR round-trips through
  `--format json` and parses.

**Out of scope**
- The `--format text` renderer. The concentration list's trailing-tab stripping is already
  recorded as a known limit and affects rendering only, never a count or the tier.
- Re-opening the literal-newline decision at the path-parsing layer.

## Constraints

- **Do not add a CR rule beside the tab rule.** That is the shape that produced this finding —
  it leaves the next control character to be discovered the same way. Handle the class.
- `tools/change-size.sh` is harness-owned and asserted POSIX: `sh -n`, `dash -n` and
  `/bin/bash -n` (3.2) must stay clean. Note the bash-3.2 trap E99-F07 documented: `#` is not
  honoured when re-scanning a `$( … )` body, so an apostrophe in a comment there opens a quote
  that swallows the block.
- Do not weaken the guarantees already tested in `tests/test_change_size.sh` — in particular
  **R8c (JSON escaping)** and **R7f (tab escaping)**, whose jq-free assertions exist because
  `R7f` was once entirely `jq`-gated and had no coverage on a jq-less host.
- `tools/change-size.sh` is installed body ⇒ `VERSION` bump + `CHANGELOG` entry.
- Do not freeze an exact `VERSION` string, and do not diff DO-NOT-TOUCH files against `main`,
  in any added test.

## The lens that applies here

E99-F07 found **five** assertions whose expected value was reachable by more than one code path —
each passing identically before and after the fix. `agents/builder.md` now carries the rule and
`R9c` asserts it. Every one of the five was caught by **executing** a mutation, none by
inspection, including two self-sweep attempts that had the defect they were written to close.

Applied here: an assertion that the JSON "parses" is satisfied by a fixture whose pathname has no
control character at all. The fixture must contain the raw byte, and the test must fail when the
escape rule is removed.

## Open questions

- Whether the emitter should escape DEL (U+007F) too. It is not a C0 control and JSON does not
  require it escaped, so the default answer is no — but say so explicitly rather than leaving it
  unstated.
