# Intent — Antigravity Skills migration, re-specced against the post-E23 layout

## Why this exists (read this before anything else)

A complete implementation of this feature already exists on the branch `fix/agy-skills`,
with its own four spec files, installer changes and three updated test suites. It went
through **fifteen `@codex review` rounds** on PR #87 and cannot be merged. Not because it
is wrong, but because the ground moved underneath it:

**Two features independently migrated a different front-end into the same directory.**

| | writes | for |
|---|---|---|
| **E23-F01** (merged, PR #88, on `main`) | `.agents/skills/<name>/SKILL.md` + `agents/openai.yaml` | **Codex** |
| **E99-F09** (branch, PR #87) | `.agents/skills/<name>/SKILL.md` | **Antigravity** |

They are not merely near each other — they iterate **the same name list**. Main's §5d loops
`for _c in $_cdx_cmds` (which is `$HARNESS_SDD_CMDS`, plus `$HARNESS_PR_LOOP_CMDS` when the
loop is enabled) calling `install_codex_skill`; the branch loops `for _w in
$HARNESS_SDD_CMDS` writing `.agents/skills/$_w/SKILL.md` directly. A target selecting
**both** `antigravity` and `codex` therefore has two writers for
`.agents/skills/sdd-next/SKILL.md` and every sibling.

Worse than the overwrite is the reclaim: each side deletes what it believes it owns.
Main's `reclaim_codex_skills` removes `.agents/skills/sdd-*` against `.harness/.codex-skills/`
stamps; the branch's path calls `remove_if_pristine` against a freshly generated *Antigravity*
body. Deselecting either front-end can therefore delete the other's live command glue, and
the pristine-only guard will not save it — the file genuinely is pristine, just pristine for
the other front-end.

This is why a rebase was attempted and abandoned rather than pushed through. Merging the
text produces an installer that passes its own tests and silently clobbers a selected
front-end's commands.

## Problem / who

Antigravity's harness glue predates its Skills architecture and should move to it, so
`/sdd-*` commands and the role personas are discoverable the way Antigravity now expects.
That goal is unchanged and still worth doing.

## Success outcome

A selected Antigravity target exposes the SDD workflows and personas through Antigravity's
current Skills surface, **and** a target that selects both Antigravity and Codex gets both
front-ends' glue intact — installed, reclaimed and upgraded independently, with no path
either one can delete out from under the other.

## Scope / boundaries

**In scope**
- Deciding and documenting **who owns `.agents/skills/`**, and where the other front-end's
  units live. This is the feature's central decision and it must be recorded as an **ADR**,
  not buried in an installer comment.
- The Antigravity glue migration itself.
- Reclaim-on-deselect that is provably scoped to one front-end's own units, with a test that
  **selects both front-ends and deselects one**. The absence of that test is why the
  collision reached round 15 unnoticed.

**Out of scope**
- Changing Codex's shipped layout. E23-F01 is merged and released (v0.49.0+); moving it is a
  breaking change for every target already upgraded, and needs its own decision if it is
  ever proposed.
- Antigravity model routing. The branch retired it in round 13 and edited **E17-F01's
  approved spec files** to match. That is a spec-level change to a completed feature and does
  not belong inside this feature — if it is still wanted, it goes back through the gate on
  its own.

## Constraints

- **Do not start from the branch's diff.** It is based before E23-F01 and encodes the old
  world: global `$CODEX_HOME/prompts`, a `codex_prompts_dir` resolver, and `.agents/skills/`
  as Antigravity's exclusive territory. Read it for the Antigravity Skills format and the
  fifteen rounds of hard-won edge cases; do not replay it.
- **The branch is not deleted.** `fix/agy-skills` @ `16994a5` stays reachable, and PR #87
  stays readable, so nothing salvageable is lost.
- **A test that only selects one front-end cannot detect this class of bug.** Whatever the
  ownership decision, it must be verified with both selected.
- Installed body ⇒ VERSION bump + CHANGELOG entry.
- Budget: `change_size.max_requirements: 12`. The branch changed 19 files across 22 commits;
  if the re-spec exceeds the budget, split it at decomposition rather than specifying it whole.

## Open questions

- **Who owns `.agents/skills/`?** Codex has it on `main` today, which is the cheapest answer
  (Antigravity goes elsewhere) but may not match what Antigravity's Skills discovery actually
  accepts — verify against the CLI rather than assuming.
- **Can the two coexist in one directory** under distinct unit names, or does either
  front-end's discovery claim the whole tree? This decides whether the answer is
  "namespace them" or "separate them".
- **What did the fifteen rounds actually establish?** Several rounds encode real constraints
  (symlinked destination components, pristine-vs-edited reclaim, `≤0.47.0` legacy bodies).
  Those lessons are worth carrying forward even though the diff is not.
