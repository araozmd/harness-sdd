# Intent — Source `--self` OpenCode glue

## Problem / who
The source repo's `opencode.json` and `.opencode/` glue are hand-maintained, unlike the
Claude/Codex glue E26 generates. It has already drifted: `gen_opencode_json` emits
`builder-heavy`, but the committed `opencode.json` omits it, so escalation silently no-ops on
OpenCode — the failure ADR-0002 exists to prevent. `/sdd-test-concurrency` is absent too.

## Success outcome
`harness-install.sh --self` regenerates the source repo's OpenCode glue; it is drift-gated
byte-for-byte like the other hosts; `builder-heavy` and the gated `pr-fixer` resolve; the
capability marker and gated command never enter version control.

## Scope / boundaries
In: `self_install` selection/copy/reconcile, `self_transform` verification, the `.glue-manifest`
and E26-F02 drift gate, the OpenCode host test, docs, and a `VERSION` bump.
Out: the shared skill adapter/claiming (E31-F01); emitting the gated parallel lane to source.

## Chosen options
- Reuse the existing `gen_opencode_json`/`gen_oc_agent` emitters through the real temp install.
- Force the OpenCode capability gate off for the temp install so `--self` is
  machine-independent.
- Keep `.opencode/command/` as the OpenCode-native surface (it takes precedence over a
  same-named shared skill), reusing the canonical `$CMDDIR` body.

## Constraints
Depends on E31-F01; separate PR; bump `VERSION` (installer body change).

## Open questions
Whether to harvest an OpenCode model pin into `--self` (none exists today; role existence is
sufficient per ADR-0002). Treat as a follow-up unless the reviewer requires it.
