# Intent — the mirror ignores the hook contract and full-reconciles on every write

## Problem / who

`store/local.md` already specifies the post-write hook, in normative language:

> the Orchestrator runs `store.on_write_command` … **invoked as `<cmd> "<feature-id>" "<op>"`**

`tools/sync-board.mjs` reads exactly one thing from argv — `--dry-run` — and drops the
positional arguments on the floor. So a hook the harness documents as *targeted* is
implemented as *board-wide*: **every** status write reconciles the entire board.

On the cuestiona board (181 features) that is ~17 s per transition, and it is not merely
slow. The full run also:

- re-drives `assignee` across **unrelated** issues, so one feature's status write shows up
  as churn on every other feature's issue; and
- calls `ensureOptions('Epic', …)` with the full epic list, which **renames existing board
  columns** to whatever the current labels are — a board-wide mutation performed on behalf
  of a single feature.

Two records that must agree do not: the doc states a contract nothing implements. Either
the tool honors it or the doc is wrong, and the doc is the one that is right — the id and
op are already computed and already passed at the call site.

## Intended fix

Parse the positional hook arguments and reconcile only the addressed feature.

1. Split argv into flags and positionals; `TARGETED` is true only when **both** the
   feature id and the op are present, so an argument-less invocation keeps today's
   board-wide behavior byte-for-byte. That is what makes this safe for every consumer that
   runs the tool by hand.
2. Resolve the id **before any `gh` write**. An **epic id is a legitimate hook argument** —
   `set_status` writes epic status too, and `store/local.md` says "the id selects the
   object kind" — but an epic has no feature issue, so that is a clean **no-op with exit
   0**, not an error. An id that matches neither is a hard error (exit non-zero).
3. Targeted runs must not rewrite the whole `Epic` option set: when the target's epic
   option already exists, read the current option ids and leave the field alone; fall back
   to `ensureOptions` only when the option is genuinely new.
4. Targeted runs should ask GitHub for the addressed feature's issue
   (`--search "<id> in:title"`, small `--limit`) instead of paging 500 issues.

Update `store/local.md` and `store/board-mirror.md` in the same change — the tool and the
contract are one thing, and this item exists because they drifted apart.

## How to verify

`tests/test_mirror.sh` gains, against a stubbed `gh`:

- **targeted run touches one feature** — assert the stub recorded writes for the addressed
  id and **zero** writes for any other feature. Counting the addressed one alone passes
  against the board-wide tool, which also writes it.
- **targeted epic id is a no-op** — exit 0, no `gh` write at all.
- **targeted unknown id fails** — non-zero, no `gh` write.
- **no positionals ⇒ board-wide, unchanged** — the control that keeps this backward
  compatible. Assert the same write set as before the change.
- **targeted run does not rewrite the Epic field** — assert no `field-edit` on an existing
  option; paired with a control where the epic option is new and `ensureOptions` *must*
  fire, so "it stopped calling ensureOptions entirely" cannot pass.
- **`--dry-run` still writes nothing** in both modes.

## Mutations the suite must kill

- Make `TARGETED` true on the id alone → the board-wide control must fail.
- Treat an unknown id as a no-op instead of an error → that case must fail.
- Treat an epic id as an error instead of a no-op → that case must fail.
- Restore the unconditional `ensureOptions('Epic', …)` → the Epic-field case must fail.
- Ignore positionals again → the targeted case must fail.

## Trap

The assignee re-drive and the Epic rename are *separate* board-wide effects with the same
cause. A fix that narrows the feature loop but leaves `ensureOptions` unconditional still
mutates the whole board on every write — assert them independently, or one of them will
survive under a green suite.
