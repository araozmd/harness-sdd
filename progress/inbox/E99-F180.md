# Intent — Docs sweep: human-facing docs vs 0.96.0–0.97.2

## Problem / who
The human asked to "update all the documentation". A read-only audit compared every
human-facing doc against the 0.96.0–0.97.1 CHANGELOG and the current code. It found 15
issues: 2 wrong, 7 missing, 6 cosmetic. The full audit is in the
**Appendix** at the end of this brief, with file:line references, evidence and a suggested fix for
each finding. Since the audit, 0.97.2 (E99-F179) shipped; it is test- and comment-only and
needs no user-facing doc beyond its CHANGELOG entry.

Two findings are wrong today:
- **The config seed.** `harness.config.yaml:260` and its seed source
  `harness-install.sh:314` say an invalid OpenCode pin "aborts your OpenCode run". Since
  0.97.1 it is warned about and dropped, with no model stamped.
- **WORKFLOW.md.** `docs/WORKFLOW.md:663-665` says a preflight failure exits 5. It
  actually exits 8, 9 or 10.

What is missing:
- **PR-loop changes from 0.96.1** (E99-F173). The late-comment fingerprint refusal, the
  queued-merge reconcile and cancel (`merge-verify post` exit 11), and the knobs
  `HARNESS_QUEUE_RECONCILE_CEILING` and `HARNESS_MERGE_VERIFY_CEILING` are documented only in
  the generated command body. They are absent from WORKFLOW.md, INSTALL.md, README.md and the
  config comments.
- **Duplicate-fix-id recovery from 0.96.2** (E99-F174). Allocation over every visible ref, the
  duplicate-id check, and `renumber` are absent from WORKFLOW.md and the README.

A further item the audit noted: `CHANGELOG.md:5` points at "`CLAUDE.md` → Versioning", a
section that does not exist. The versioning rule lives in `AGENTS.md` (~113-117).

## Success outcome
- All 15 audit findings are fixed, or deliberately declined with a one-line reason recorded
  in the commit or PR body. Every cosmetic item is optional, but decide each one explicitly.
- `CHANGELOG.md:5` points at the real location of the versioning rule.
- Every new or changed sentence is TRUE against the current code. Cite the code path in the
  PR body for each behavioural claim. No new claim may outrun what the code does.
- `harness.config.yaml` and the config seed in `harness-install.sh` stay in lockstep, so a
  fresh install and this repo carry the same comment text.

## Scope / boundaries
In scope:
- README.md, docs/WORKFLOW.md, docs/INSTALL.md

Out of scope:

- Historical records: CHANGELOG history entries, progress/, specs/epics/*.
- docs/BASELINE-0.78.1.md.
- Generated glue. The audit found its emitter current. If an `agents/*.md` edit changes a
  generated mirror, regenerate it with `sh harness-install.sh --self`; never hand-edit.

## Chosen options
- Keep the README thin. Give it one sentence plus a link for each new behaviour, and put
  the detail in WORKFLOW.md and INSTALL.md.
- Prefer "N suites" to a hard-coded count in example strings (agents/reviewer.md:14).

## Constraints
- **Byte-pinning risk.** docs/INSTALL.md:353 says an upgrade appends the pr_loop config
  block "byte-for-byte", so tests may pin the seed text. Read tests/test_install.sh,
  tests/test_pr_loop*.sh and tests/test_self_drift.sh (and any other suite that greps the
  seed) BEFORE editing it. Update every pin that legitimately changes, and say which.
- **Upgrade semantics.** Changing the seed changes what fresh installs write. Check what an
  UPGRADE does with an existing harness.config.yaml whose pr_loop block holds the old
  comment: whether it is left alone, appended or rewritten. Document the answer in the
  CHANGELOG entry.
- **Version.** harness-install.sh (the installed body) changes, so this is a PATCH bump to
  0.97.3 with a CHANGELOG entry, per AGENTS.md ~113-117. If only docs changed it would be
  exempt, but the seed edit makes it a body change.
- **Safety.** Never run opencode, a model, or a mutating pi.
- **Tests.** Run the full suite with `sh tools/run-tests.sh --jobs 16`, capturing rc
  reliably, and run ./init.sh.

  the pin rule, `renumber`, duplicate ids, `add-feature` allocation, `merge-verify`, exit 11,
  `thread_fingerprint`, `HARNESS_*` env knobs, the pi integrity pin, suite counts, version numbers.

- Suite count: 79 `tests/test_*.sh`. Default discovery excludes the `tests/test_umbrella.sh` aggregate

### Already correct (no action)

### Findings

### harness.config.yaml

1. **harness.config.yaml:260** (seed source **harness-install.sh:314**). Severity: **wrong**
   - Says: `opencode MUST be "provider/model" (an invalid value aborts your OpenCode run)`
   - True: an invalid value aborts only on 1.x. 2.x silently drops it. Either way the installer warns
     once and stamps no `model` key, so nothing is written that could abort a run. Evidence:
     CHANGELOG.md:9-14; docs/INSTALL.md:1184-1191; harness-install.sh:1987.
   - Fix: `opencode MUST match ^[^/#]+/[^#]+$ ("provider/model"; an invalid value is warned about and
     dropped — no model is stamped)`. Edit the seed in harness-install.sh:314 too, or fresh installs keep
     the old text.

2. **harness.config.yaml:296-300** (seed **harness-install.sh:~365-369**). Severity: **missing**
   - Says: the env-only execution knobs are HARNESS_POLL_INTERVAL, HARNESS_POLL_CEILING,
     HARNESS_FIRST_RESPONSE and HARNESS_DRY_RUN.
   - True: `HARNESS_QUEUE_RECONCILE_CEILING` (default 300) is new in E99-F173 (CHANGELOG.md:107-108;
     harness-install.sh:8766,8777). `HARNESS_MERGE_VERIFY_CEILING` (default 180,
     tools/wait-for-codex.sh:495) is also unlisted.
   - Fix: add both. Risk: docs/INSTALL.md:353 says an upgrade appends the pr_loop block
     "byte-for-byte", and tests may pin the seed bytes. Check tests/test_pr_loop*.sh and
     tests/test_install.sh before editing the seed.

### docs/WORKFLOW.md

3. **docs/WORKFLOW.md:663-665**. Severity: **wrong** (predates 0.96, but contradicts the code)
   - Says: preflight "a failure exits `5`".
   - True: preflight exits `8` (auth/tooling), `9` (environment) or `10` (usage). `5` is the wait-mode
     no-Codex-activity exit. Evidence: tools/wait-for-codex.sh:41,61-68; docs/INSTALL.md:326-329,803-804.
   - Fix: "a failure exits `8`/`9`/`10` (auth-tooling / environment / usage)".

4. **docs/WORKFLOW.md:697-705** (step 7, gate re-check + terminal state). Severity: **missing**
   - Says: resolve the Codex threads, merge (or hand back), then local cleanup "only if the merge command
     itself succeeded".
   - True: four behaviours are missing here.
     - Both terminal paths wait on required CI.
     - Both run the `merge-verify pre` receipt.
     - Both snapshot `thread_fingerprint` before the CI wait and refuse (`stale` → needs-human) on any
       difference (E99-F173 #259, CHANGELOG.md:94-102).
     - The merge path runs `merge-verify post`. Exit **11** (still OPEN = queued/auto-merge armed) means:
       reconcile for HARNESS_QUEUE_RECONCILE_CEILING, cancel via `gh pr merge --disable-auto` /
       `dequeuePullRequest`, re-read the state, then hand off with a comment on whether the cancel held
       (CHANGELOG.md:103-112; harness-install.sh:8760-8800).
     The documented limits are also missing: PR review bodies and issue comments are not fingerprinted,
     and neither are edits to a non-last comment.
   - Fix: add a short sub-paragraph to step 7 covering all of this, and say "merge landed (post receipt
     0)" instead of "merge command succeeded".

5. **docs/WORKFLOW.md:675-678** (step 3 exit list). Severity: **missing**
   - Says: lists only the wait-mode codes 0/3/2/4/5.
   - True: the script also has `merge-verify` (7, 11), `classify` (6) and `preflight` (8-10)
     (tools/wait-for-codex.sh:15-20,34-68), and step 7 now relies on them.
   - Fix: add one line pointing at the script header's exit table, or list 7/11 with step 7.

6. **docs/WORKFLOW.md:600-614** ("Lightweight fix lane"). Severity: **missing**
   - Says: nothing about id allocation or collisions.
   - True:
     - `add-feature` allocates above the max F## across the working board, HEAD and every local and
       remote-tracking ref (offline, MAX_REFS_SCANNED=200).
     - validate-board (and so init.sh) rejects duplicate feature/epic ids.
     - `tasks-lock.py renumber` is the recovery: the second-landing session renumbers its own un-landed
       row.
     Evidence: CHANGELOG.md:68-90; agents/fixer.md:240-283.
   - Fix: add a 3-4 line "Concurrent sessions / duplicate fix id" paragraph linking to
     agents/fixer.md "Duplicate fix id" and store/local.md.
