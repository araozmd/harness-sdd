# Intent — validate-board draft-warning pass crashes on non-list epics/features

## Problem / who
`tools/validate-board.py` `_emit_draft_warnings` (~line 911) runs BEFORE schema
validation (~line 975). It iterates `data.get("epics") or []` and a draft epic's
`ep.get("features") or []` without checking the type. When either one is a non-iterable
scalar, Python raises `TypeError: 'int' object is not iterable` (or `'bool'`), and the
operator sees a traceback instead of the schema error. Init still fails closed (rc=1).

Reproduced on 2026-10-18:
- `{"project":"p","epics":5}`
- `{"project":"p","epics":true}`
- `{"project":"p","epics":[{"id":"E1","title":"t","status":"draft","features":7}]}`

Each one prints a traceback.

A string or dict `epics` does not crash, but it is iterated meaninglessly; the guard
should skip it as well. The E99-F174 Reviewer found this and confirmed it predates F174.

## Success outcome
For any board shape, the warning pass never raises. When `epics` or `features` is not a
list, it skips it, and schema validation then reports `epics: expected array` /
`epics[0].features: expected array` cleanly with rc=1 and no traceback. This must hold on
both paths: with jsonschema and on the fallback.

## Scope / boundaries
- Only `_emit_draft_warnings`: iterate only when the value is a `list`.
- Keep the stderr warning text byte-identical. The comment says init.sh parity depends
  on it.
- Out of scope: any other validator behaviour.

## Chosen options
- An `isinstance(..., list)` guard, rather than a try/except around the whole pass.

## Constraints
- Every guard needs a test row that kills its mutant. Add rows for: int, bool, string and
  dict `epics`; an int `features` on a draft epic; and a valid draft epic that still
  warns, to keep the warning reachable.
- Assert both rc=1 and the absence of `Traceback`.
- tools/ ships to installs, so this is a PATCH bump to VERSION 0.96.3, plus a CHANGELOG
  entry.
