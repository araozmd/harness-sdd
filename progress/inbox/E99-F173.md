# Intent — pr-loop: late comments after the CI wait (#259) + queued merge before needs-human (#256)

## Problem / who
Two holes in the `/sdd-pr-loop` terminal paths. Both live in the canonical `sdd-pr-loop`
heredoc in `harness-install.sh`, and both affect every repo that runs the PR loop.

**#259: late review input during the CI wait is not detected.**
`thread_scan()` (harness-install.sh ~8470) emits only `"<allcodex> <id>"` per UNRESOLVED
thread. The hand-back compares pre/post snapshots (~8555-8562) and the merge path rescans
(~8648), so two cases slip through:
- A new Codex reply on a thread that was already unresolved leaves the line
  `true <id>` byte-identical.
- On the auto-merge path every vetted Codex thread was already RESOLVED. A comment added
  to a resolved thread does not reopen it, so it is invisible to both scans.

Late P0/P1 feedback can therefore be followed by an "all gates green" hand-back or by a
merge.

**#256: a queued merge is left live after the needs-human hand-off.**
Under a merge queue or repo-level auto-merge, `gh pr merge` exits 0 and the PR is only
ENQUEUED. Then `wait-for-codex.sh merge-verify … post` (~line 482-512) reaches its
ceiling without seeing `mergedAt`, and exits 7. Exit 7 also means "PR CLOSED", so the
caller cannot tell the two apart. The loop retries once, then labels `needs-human` and
returns failure, but the merge request is still live. When it merges later, nothing
records `merged`, cleans up the branch, or writes landing evidence. Nothing in the
codebase cancels or follows a queued merge (zero hits for `disable-auto`, `dequeue`,
`autoMergeRequest`).

## Success outcome
- **#259:** any change in review input during the CI wait refuses the green terminal
  action and records `stale`. That covers a new or reopened thread, a flipped Codex-only
  flag, and any new comment on ANY thread, resolved or not. The next run then reviews it
  in a fresh round. A failed scan fails closed.
- **#256:** a needs-human hand-off never leaves a live merge request behind. A PR that is
  still queued at the post-receipt ceiling is reconciled: wait a bounded extra time, and
  if MERGED take the normal `merged=1` path (marker, cleanup, evidence). Otherwise cancel
  the request through `mut` (`gh pr merge --disable-auto`, plus the `dequeuePullRequest`
  GraphQL mutation for a merge queue), re-read the state (MERGED → the merged path), then
  label needs-human. If the cancel fails, the needs-human comment says so explicitly
  ("a merge request may still be queued").

## Scope / boundaries
- **#259:** add a fingerprint helper next to `thread_scan`. It prints
  `<id> <isResolved> <comments.totalCount>` for EVERY thread, resolved included, paginated,
  with the exit status preserved. Optionally it can also count the PR's Codex review and
  issue comments. Snapshot it where `_hb_thr_pre` is taken (hand-back), and after the
  resolve loop, before `ci_required_gate` (merge path). After the wait, require a
  byte-identical result: any difference or a failed scan means stale plus needs-human,
  exactly like the existing thread-change branch. Keep the existing ownership checks.
- **#256:**
  - In `tools/wait-for-codex.sh merge-verify post`, give "still OPEN at the ceiling" its
    own exit code (e.g. 8), distinct from CLOSED (7), and document it in the header.
  - In the runbook merge block, on that code, reconcile and cancel as described above, all
    mutations through `mut`.
  - Update the retry paragraph (~8701) and the needs-human section.
- Regenerate the self-hosted copies with `sh harness-install.sh --self`; never hand-edit
  `.claude/commands/*` or the other generated files.
- Tests in `tests/test_pr_loop_hardening.sh`, as executed snippets with a stub `gh`:
  - #259: a Codex comment count that grows during the CI wait (one case on an unresolved
    thread, one on a resolved thread) → refused, `stale`.
  - #256: merge returns 0 while `mergedAt` stays null → reconcile then cancel; the cancel
    call is made through `mut`; a dry run makes no mutation; a cancel failure produces
    the "may still be queued" wording; a queue that merges during the reconcile reaches
    `merged=1`.
  - The new exit code in the wait-for-codex tests.

Out of scope: other pr-loop behaviour.

## Chosen options
- Fingerprint every thread instead of re-running classify before the terminal action:
  smaller, and it reuses the existing stale path.
- Reconcile first, then cancel, rather than only cancelling.
