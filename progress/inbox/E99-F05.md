# Intent — Scope the pr-loop first-response probe to the current round

## Problem / who
Found by Codex on PR #68 (E18-F01), round 6, tagged P2 and deliberately deferred as
diagnostic-latency-only rather than a correctness defect.

`tools/wait-for-codex.sh` arms a first-response probe (`HARNESS_FIRST_RESPONSE`, default
180s) whose job is to fail fast with exit `5` when the Codex GitHub App is not installed
or has no access — instead of making the caller wait out the full 900s ceiling for a
review that can never arrive.

The probe counts Codex issue comments and reviews **unscoped by round**. So on any round
after the first, pre-existing Codex activity from earlier rounds immediately disarms it.
The watcher then polls to the ceiling and produces a plain timeout (exit `2`) rather than
the intended missing-App diagnostic.

Observed live during PR #68: rounds 2–6 all ran with the probe effectively disarmed.

## Success outcome
On any round, a repo where Codex cannot respond fails fast with the named remedy inside
`HARNESS_FIRST_RESPONSE` seconds, instead of waiting out the ceiling.

## Scope / boundaries
**In scope**
- Filter the comment and review counts by the current trigger timestamp
  (`trigger-ts.txt`), the anchor the watcher already resolves and persists.
- A regression test proving the probe still fires on round 2+ when Codex is silent.

**Out of scope**
- The reaction check. Codex's suggestion is that reactions can stay scoped by the new
  trigger comment id, which is already round-specific by construction — verify before
  changing anything there.
- Any change to the exit-code contract (0 findings / 1 pending / 2 timeout / 3 clean /
  4 usage / 5 no-first-response), the freshness guards, or the three clean-signal forms.

## Constraints
- POSIX sh; must parse and run under both `sh` and `dash`; `set -eu` is in effect.
- `wfc_bot_seen` ends in a bare `return 1` — that is load-bearing under `set -eu`.
- Bot identity is matched EXACTLY against `chatgpt-codex-connector` and
  `chatgpt-codex-connector[bot]`. Do not reintroduce a prefix match — a lookalike login
  signalling a clean review was a P1 on the originating PR (spec R27).
- `tests/test_pr_loop.sh` must not freeze the exact `VERSION` string, and any installer
  invocation must sandbox `CODEX_HOME`.

## Open questions
- Whether the probe should count only Codex activity strictly after the trigger, or also
  treat a bot reaction on the *current* trigger comment as first response (it is already
  round-scoped, so it likely qualifies and needs no timestamp filter).
