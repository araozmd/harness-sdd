The two that remain both affect the next contributor who reads the guard in
tests/test_agents_host.sh:

1. **Call-site floor unpinned (W3/W4).** The comment above `scrub_check_dir` (~317-318)
   says "Wiring pinned by test_host_scrub_wiring". That is true for `scrub_check_dir`

   - so does changing its floor argument from `2` to `0` (W4).

   The reviewer accepted this bound: pinning the call would need a self-grep or a
   self-re-run, which is the same class as deleting any `test_x` call at the bottom of a
   suite. The comment still overclaims it, though. The guard-block comment's "Non-vacuous:
   at least the two known scrubbers must be found" also reads as if that floor were pinned.
2. **New loud false positive left undocumented.** Since round 3, the widened keyword prefix
   `(^|[^A-Za-z0-9_.$-])` also admits `"`. So a quoted message such as
   `echo "unset CLAUDECODE CODEX_THREAD_ID …"` is read as a scrub statement and goes red
   if it omits a table variable. No such line exists in tests/ today.
   - The comment already lists "a run of asserts" as an accepted false positive, but not
     this one.
