# Intent — Gate the live opencode probe in test_codex_native.sh on opencode 1.x

## Problem / who
`tests/test_codex_native.sh` is red on any host where opencode 2.x is first on PATH.
The live probe `opencode_source_host_resolves` (E31-F02 R9) runs `opencode agent list`;
opencode 2.0.32 rejects it with `Unexpected positional argument: "list"`, prints root
help, and the assertion fails with `AssertionError: DESCRIPTION`. mise installed
opencode v2.0.32 on this host on 2026-10-16. The suite passes with opencode 1.18.35
first on PATH and fails identically on `main`, so this is environmental, not a regression.
It blocks a green 75/75 full suite for every harness maintainer on opencode 2.x.

Verified on the host (opencode 2.0.32):
- `opencode --version` prints `opencode v2.0.32`; 1.x prints the bare `1.18.35`.
- 2.x has no `agent` subcommand. The nearest verb, `opencode debug agents`, returned `[]`
  for an isolated copy of the source layout. 2.x also reports the project config under a
  renamed `agents` key, so the 1.x-shaped glue is not reliably understood.
- Every `opencode debug …` call on 2.x spawns a detached `opencode serve --service`
  daemon (PPID 1) that outlives the call. A test must not leave that behind.
So there is no safe, meaningful 2.x equivalent to probe.

## Success outcome
- The full suite is 75/75 green with opencode 2.x first on PATH. The probe prints a clear
  `skip - …` line that names the detected version and why it was skipped.
- With `~/.local/share/mise/installs/opencode/1.18.35` first on PATH, the probe still
  REALLY runs and prints `ok - opencode_source_host_resolves (R9, live)`.

## Scope / boundaries
In scope: the live-probe block in `tests/test_codex_native.sh` (around lines 259-286).
- Run `opencode --version` (through a file, with a timeout, like the existing `oc()`
  helper) and parse the first `\d+\.\d+\.\d+` it prints.
- Run the existing 1.x probe only when the major is `1`.
- Skip with a clear note on any other major, on unparseable output, and on a
  timeout or error. Never fail on these, and never invoke any `debug`/`agent` verb on a
  non-1.x binary.
- Update the R9 row in `specs/epics/E31-opencode-first-class/F02-source-host-parity/E31-F02.tests.md`
  only if its wording needs to say "live on opencode 1.x".

Out of scope: making the installer's OpenCode glue 2.x-compatible (a separate, larger
capability). `tools/opencode-model-helper.sh` uses `opencode models`, which still
exists in 2.x and is not exercised by any suite. Grep confirms that no other suite and
not the installer invoke `opencode agent list`.

## Chosen options
- Version-gate plus skip, rather than porting the probe to the 2.x `debug agents`
  verb (it returns `[]` and spawns a daemon).

## Constraints
- Test-only change: no VERSION bump. `tests/` is not part of the installed body.
- The 1.x path must stay byte-for-byte the same probe. The gate must be
  mutation-checkable: forcing the gate open on 2.x must turn the suite red again, and
  forcing it closed on 1.x must drop the `ok - … (R9, live)` line.
