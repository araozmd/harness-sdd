# Intent — Doc-critic paraphrase-back comprehension mode at the feature-spec checkpoint

## Problem / who
The Doc-critic at `target-type=feature-spec` is told to "evaluate across five
dimensions" and flag only downstream-breaking issues. Nothing requires it to prove it
understood the spec. EGM's Comprehension Goldfish must first restate "what this proposes"
and "how the existing system works, per this document" in its own words; any section it
cannot paraphrase is a Blocker. That is exactly the property the Builder needs — it reads
the four files cold — and the one the author cannot test on itself. Users: the Architect
(gets the findings inline before `spec-ready`), the Builder (receives a self-contained
spec), the human at the gate.

## Success outcome
At the `feature-spec` checkpoint the Doc-critic's note opens with a paraphrase of the
spec written from the four files only (no inbox brief, no chat), followed by findings.
Any R-id, plan row or task it could not restate is a blocking finding the Architect must
fix or explicitly accept. One re-audit is allowed; leftovers after it are recorded in the
spec as accepted trade-offs so the decision is durable and visible to the Reviewer.

## Observable behavior
File — `progress/<feature>-doc-critic.md` (or wherever the checkpoint note lives today)
gains a leading `## Paraphrase` section with two sub-parts and a per-section
"could not restate" list; the Architect's hand-off checklist gains the re-audit cap and
the accepted-trade-offs write into the `.spec.md`.

## Scope / boundaries
In scope: `agents/doc-critic.md` (new mode text, calibration), `agents/architect.md`
(checkpoint step: paraphrase first, one re-audit, record trade-offs), `agents/reviewer.md`
(reads the accepted trade-offs; a trade-off is not a defect), `docs/WORKFLOW.md`,
`specs/_templates/feature.spec.md` (an optional `## Accepted trade-offs` section),
`tests/test_doc_critic.sh` anchors, RATIONALE ledger row (this is prose → capability
compensation, with an ablation threshold), CHANGELOG, VERSION.
Out of scope: additional personas, a synthesizer agent, parallel reviewer fan-out, any
change to plan-output / epic-decomposition checkpoints (a later feature may extend them).

## Chosen options
- One portable Doc-critic role file, a mode within it — no second `agents/` persona.
- Paraphrase is written from the four spec files ONLY; the inbox brief is withheld on
  purpose (the Builder never sees it either).
- Bounded: one re-audit, then leftovers become `## Accepted trade-offs` in the spec.

## Constraints
- Stage: production
- This is prose: classify it in `docs/RATIONALE.md` as capability compensation and state
  the retest threshold (ablate when a model generation ships; keep only if its absence
  reproduces a spec defect reaching review).
- Keep every existing `tests/test_doc_critic.sh` anchor; the section-extraction idiom is
  fence-blind, so place new text where the extractor reads it.
- Installer + `tests/test_install.sh` assert the installed role text.

## Open questions
- Whether "could not restate" should be a hard Architect block or a flag the human at the
  gate sees — the brief leans to block-with-one-re-audit, mirroring EGM.
- Where the checkpoint note is persisted today (confirm the path before adding a section).
