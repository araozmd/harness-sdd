# Intent — advisory drift report: living docs (product, architecture, ADRs) versus current code

## Problem / who
`specs/product.md`, `specs/architecture.md` and the ADRs are the harness's living
documents: every role reads them, the Driller amends them, the Architect cites them. Nothing
checks that the code still matches them. The existing drift guards cover the installed body
(`init.sh`) and weakened tests (`tools/test-drift-check.sh`); feature specs are historical
once `done`. EGM ships a weekly `drift-report` for exactly this gap. Users: the human
maintainer (decides doc-vs-code per divergence), the Planner on an amend, the Architect
when a plan cites an ADR that the code no longer honours.

## Success outcome
An on-demand run writes a dated report listing, per living document, the divergences
between what it states and what the code does — missing things the doc names, things the
code does that no doc names, replaced patterns — or "No drift detected". Each divergence
names the reconciliation choice (update doc / update code) for a human; the tool never
edits either. Advisory: no gate, no board write.

## Observable behavior
CLI / file — a role-agnostic command (a `/sdd-drift` skill or a direct
`tools/` helper; Architect decides, with the no-new-slash-command precedent of E34 in
mind) writes `progress/drift/<YYYY-MM-DD>.md` and prints its path; exit 0 always unless
it could not run (exit 2).

## Scope / boundaries
In scope: the living-doc set only (`specs/product.md`, `specs/architecture.md`,
`specs/adr/*.md` and product-space ADR dirs); the report writer; the role or command that
runs it; `docs/WORKFLOW.md` note on cadence (on demand, suggested per release); installer
+ `tests/test_install.sh`; RATIONALE ledger; CHANGELOG; VERSION.
Out of scope: feature specs under `specs/epics/` (historical once done), automatic fixes,
any board state, a scheduled job.

## Chosen options
- Advisory only — never a gate, never a board write.
- Deterministic part as code: extract the named paths/symbols/commands from the living docs
  and resolve them (reusing F01's resolver). Judgment part (pattern divergence) stays a
  bounded Scout-style read with a fixed report format.
- Living docs only; feature specs excluded by design.

## Constraints
- Stage: production
- Reuse E37-F01's resolver; do not reimplement path/symbol resolution (a reimplemented tool
  is a bug per feature).
- Stdlib-only; runs in an installed target from any cwd.
- Installer + test_install assertion for any new tool or command.

## Open questions
- Skill/slash command vs plain tool: E34 chose a plain tool; EGM chose a skill. The
  Architect decides, and must wire the installer either way.
- Whether a Scout sub-agent is spawned for the judgment part or the Orchestrator reads the
  deterministic report and stops there in v1.
