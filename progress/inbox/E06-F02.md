# Intent — `/sdd-plan` inception skill (vision + architecture + draft epics)

## Problem / who
For the harness maintainer and every consumer repo: today the only intake path is
`/sdd-new`, which triages **one idea at a time** to one altitude and (at altitude 3)
seeds a single `pending` epic plus its `F01`. There is no way to capture the
**whole-project vision** up front and sketch the full roadmap cheaply. Because of
that, architectural coherence emerges late — several epics in, the human discovers
refactors a whole-picture view would have prevented (the exact pain epic E06
exists to kill).

F01 just shipped the missing foundation: the `draft` epic state and the `next()`
gate that makes a roadmap of sketch-level epics safe to seed (the Orchestrator
never selects their features). F02 is the **producer** that puts those `draft`
epics — and the durable design artifacts above them — on disk.

## Success outcome
A single `/sdd-plan` session turns a project idea into, on disk and committed:
- `specs/vision.md` — the whole-project north star (problem, users, outcomes,
  non-goals) in one short document.
- `specs/architecture.md` — the system shape and the **stable upfront** decisions,
  plus a set of **ADRs** (one decision per ADR) it references.
- **N `draft` epics** seeded into `state/tasks.json`, each with a matching
  `specs/epics/<slug>/epic.md` that is **title + one-paragraph business brief
  only** — no feature specs, no `F01`, `features: []`. Every epic is `status:
  draft`, so `next()` (F01) never selects any of it until it is drilled (F03).

The human leaves with the whole picture designed, having answered a short adaptive
Q&A rather than enduring a big-bang planning marathon. Nothing becomes executable
until a later per-epic drill-down (F03) flips one `draft` epic to `planned`.

## Scope / boundaries
**In scope:**
- New `/sdd-plan` skill: a slash command (`.claude/commands/sdd-plan.md`) over a
  **portable role contract** (extend `agents/inception.md` or add a sibling role
  file — Architect's call), mirrored as an opencode agent/command so the harness
  stays AGENTS.md-portable, not Claude-only glue.
- Artifact templates in `specs/_templates/`: `vision.md`, `architecture.md`, and an
  ADR template — so the skill writes from a stable shape.
- The write path: create `specs/vision.md`, `specs/architecture.md`, the ADR
  file(s), and seed the `draft` epics (`state/tasks.json` rows with `features: []`
  + each `epic.md`). Re-validate `state/tasks.json` against the schema after
  seeding; never claim success on a validation failure.
- Adaptive, short Q&A front-end (same spirit as `/sdd-new`: at most 3 text-only
  option mockups where the shape forks) scaled to whole-roadmap intake.
- Docs: `docs/WORKFLOW.md` (where `/sdd-plan` sits relative to `/sdd-new`,
  `/sdd-drill`, `/sdd-next`), README one-liner, and the skill's own description.
- One MINOR `VERSION` bump + `CHANGELOG.md` entry (installed body changes:
  `agents/`, `specs/_templates/`, `docs/`, `.claude/` glue).

**Out of scope (other E06 features):**
- F03 `/sdd-drill` — decomposing a `draft` epic into features, ADR deltas, and the
  approval that flips it `draft → planned` + stamps `autonomous: true`. F02 only
  **produces** draft epics; it never drills, never writes feature specs, never
  moves an epic past `draft`.
- F04 — the Architect contract that makes `architecture.md` a mandatory input and
  makes feature specs cite ADRs. F02 produces the artifacts; F04 makes downstream
  specs consume them.
- F05 `/sdd-fix` and F06 drift-check.
- Any change to F01's schema enums, `next()` gating, or feature-level statuses.
- Executing or selecting any seeded work (the F01 `draft` gate already prevents it).

## Chosen options
- **Rolling-wave, producer-only:** `/sdd-plan` seeds the *whole* roadmap as cheap
  `draft` epics; depth is added one epic at a time later by F03. F02 deliberately
  stops at the sketch.
- **Reuse F01's `draft` state and gate** — no new status, no new approval
  mechanism. Draft epics are inert until drilled.
- **Empty-features draft epics are the canonical shape** — schema-valid today
  (`features` is required but has no `minItems`, so `features: []` validates); F03
  populates them. No placeholder `F01`.
- **One decision per ADR**, referenced from `architecture.md` (architecture.md is
  the index/narrative; ADRs are the atomic, citable units F04 will point specs at).
- Additive change ⇒ MINOR bump, per repo versioning policy.

## Constraints
- **Backward compatible / additive:** `/sdd-new` and `/sdd-next` are untouched and
  keep working exactly as today; repos that never run `/sdd-plan` see no behavior
  change. Absence of `specs/vision.md`/`specs/architecture.md` must remain valid.
- **Portability pillar:** the skill's contract lives in a role file + AGENTS.md, not
  solely in `.claude/`; it must run on any AGENTS.md-compatible CLI (Claude Code,
  opencode).
- **Seeds, never specs:** like Inception today, `/sdd-plan` writes briefs/artifacts
  and `draft` epics only — it must not write the 4-file feature spec, spawn the
  Architect, or move anything to an actionable state.
- Schema stays draft-07; `state/tasks.json` re-validates after seeding via the
  zero-dependency path; `./init.sh` exits 0 afterward.
- Per the permanent-suite anti-pattern memory: new tests must not freeze the exact
  `VERSION` value or diff DO-NOT-TOUCH files against `main`.

## Open questions
- **Role shape:** extend `agents/inception.md` (one intake role, two altitudes:
  single-idea vs whole-roadmap) or add a distinct `agents/planner.md`? `/sdd-new`
  triages one idea to one altitude; `/sdd-plan` is a different altitude of intake —
  Architect decides whether that's a new role or a new mode of the existing one.
- **Re-run / existing-artifact behavior:** if `specs/vision.md` /
  `specs/architecture.md` (or epics) already exist, does `/sdd-plan` refuse,
  amend-in-place, or version them? (A first-class "this project already has a plan"
  path vs a one-shot greenfield tool.)
- **Relationship to `specs/product.md` and `specs/glossary.md`** (which already
  exist): does `vision.md` supersede, complement, or absorb `product.md`?
- **ADR location & numbering:** `specs/adr/NNNN-title.md` vs `docs/adr/…`; zero-pad
  width and how `architecture.md` references them.
- **Draft-epic id allocation:** how `/sdd-plan` allocates the block of new epic ids
  (and slugs) in one shot without colliding with existing epics, and whether it
  appends to or interleaves with the current epic list.
- **How much architecture is "enough"** for a sketch session — the boundary between
  F02's upfront `architecture.md`/ADRs and the per-epic ADR *deltas* that are F03's
  job.
