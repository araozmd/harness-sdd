# Fix — Reject non-ASCII-lowercase slugs in fix-worktree validate_key under any locale

## Problem
`validate_key()` in `tools/fix-worktree.sh:19` screens the fix slug with the shell glob
`*[!a-z0-9-]*`. Bracket ranges in a `case` glob are resolved through the active locale's
**collation order**, not ASCII. Under the developer default `en_US.UTF-8`, uppercase
characters fall inside the `a-z` range and the negated class fails to match, so an invalid
slug is **accepted**:

```
en_US.UTF-8:  case "Bad-Slug" in *[!a-z0-9-]*) ... ;; esac  ->  ACCEPTED (bug)
C:            same expression                                ->  REJECTED (correct)
```

The `E99-F<NN>` id arm and the `-*` / `*-` / `*--*` arms are unaffected (they use literal
characters or `[!0-9]`, and `0-9` collates identically in both locales).

This is an input-validation hole in a helper that creates branches and worktrees from the
slug, so a malformed slug propagates into ref names on disk. It is latent on `main` today.

**Why it hid:** `verification.test_command` runs the suite in CI under a C locale, where the
expression behaves correctly. `tests/test_fix_worktree.sh::test_invalid_inputs_are_non_mutating`
fails only when run under `en_US.UTF-8` on a developer machine.

Scope was probed and is narrow — the other two validators in the harness are **not**
affected and must not be changed:

| Site | Mechanism | Under `en_US.UTF-8` |
|---|---|---|
| `tools/fix-worktree.sh:19` | shell `case` glob | **ACCEPTED (bug)** |
| `harness-install.sh:2291,2385` | `grep -Eq '^[a-z0-9-]+$'` | REJECTED (safe) |
| `init.sh:121` | Python `re.match` | REJECTED (safe) |

## Intended fix
Set the C locale for the whole script, near the top of `tools/fix-worktree.sh` alongside
the existing `set -eu`, and export it so child processes inherit it:

```sh
#!/bin/sh
set -eu
LC_ALL=C
export LC_ALL
```

Chosen over a `validate_key`-scoped `LC_COLLATE=C` and over explicit ASCII enumeration: it
gives the whole file immunity (including any glob added later), and it makes the script's
`git` plumbing output deterministic for parsing, which is what this helper does throughout.
Accepted trade-off: it is the broadest blast radius of the three options.

Leave the `case` patterns themselves as they are — with `LC_ALL=C` in force, `*[!a-z0-9-]*`
is already correct and stays readable.

Do **not** use `[[:lower:]]`: that class is itself locale-defined and would newly *accept*
accented lowercase (`é`), widening the slug grammar rather than fixing it.

## How to verify
Add one regression case to `tests/test_fix_worktree.sh` asserting the rejection under
**both** locales, so the bug cannot regress on a developer laptop or in C-locale CI:

```sh
for loc in en_US.UTF-8 C; do
  locale -a | grep -qix "$loc" || continue     # skip gracefully if unavailable
  LC_ALL=$loc tools/fix-worktree.sh create E99-F99 Bad-Slug
    -> expect: non-zero exit, "invalid slug" on stderr, and NO branch/worktree created
done
```

The case must fail against the current `main` body and pass after the fix. Register it in
the suite's runner list like the existing cases.

Then confirm:

1. `LC_ALL=en_US.UTF-8 sh tests/test_fix_worktree.sh` — passes, including the
   pre-existing `test_invalid_inputs_are_non_mutating`, which fails on `main` today under
   this locale. Its passing is the proof the hole is closed.
2. `LC_ALL=C sh tests/test_fix_worktree.sh` — still passes (no regression).
3. `sh -n tools/fix-worktree.sh` — clean.
4. The full `verification.test_command` suite — green.

## Constraints
- POSIX `sh`; match the file's existing idiom (`_`-prefixed locals, `|| return 1` guards,
  `git -C "$PRIMARY"`). No bashisms.
- Touch **only** the locale defect. Do not modify the squash-merge / teardown logic, and do
  not "fix" the unaffected `grep -E` or Python validators.
- `tools/fix-worktree.sh` is part of the installed body (`harness-install.sh:862`), so bump
  `VERSION` one PATCH (`0.38.0` → `0.38.1`) and add the matching `CHANGELOG.md` entry, per
  the repo versioning policy.
- The regression test must not freeze an exact `VERSION` string or diff DO-NOT-TOUCH files
  against `main` — that anti-pattern has broken this suite before.
- The `en_US.UTF-8` leg must skip cleanly where the locale is absent, never fail.
