# Intent — Migrate existing children to the thin layout (+ `--standalone`)

## Why this exists

`E24-F03` ships the thin-child mechanism but deliberately changes only what a **fresh**
child install writes. An already-installed child keeps its full local copy of the prose
tier forever, and `manifest.txt` records that it is in the full-copy layout. That is the
safe half.

This is the other half, and it is the destructive one: replacing 29 real body files per
child with pointer stubs, in repositories that already exist, on someone's working tree.

## Problem / who

An umbrella that has been running since before `E24-F03` gets none of the benefit — its
children still carry N byte-identical copies and still produce N identical diffs on every
upgrade. Nobody is going to re-create five child repos to opt in.

## Success outcome

An operator re-runs the cascade on an existing umbrella and its children move to the thin
layout, with **no body file lost**: a child whose prose tier is byte-pristine is converted;
a child with an edited body file keeps that file and is told which one blocked the
conversion. A thin child can be turned back into a standalone full copy on demand.

## Scope / boundaries

**In scope**
- Pristine-only conversion of an existing full-copy child: a prose-tier file is replaced by
  a stub **only** when it is byte-identical to the umbrella's copy of the same path. This is
  the same discipline `remove_if_pristine` and the skill-unit stamps already use — do not
  invent a fourth ownership rule.
- Reporting: name every file that blocked a conversion, and leave the child in the
  full-copy layout when any did. Partial conversion of one child's tier is not a state
  anyone can reason about.
- `--standalone <target>`: materialise a full local body in a thin child, replacing its
  stubs. This is the documented recovery path `ADR-0004`'s stub text promises, and the
  answer for a child that is being detached from its umbrella permanently.
- The `manifest.txt` layout record moving from "full-copy" to "thin".

**Out of scope**
- Changing the tier split, the stub format, or the `umbrella.root` mechanism — all settled
  in `ADR-0004` and shipped by F03.
- Converting anything on a plain `init.sh` run. Conversion happens only when the installer
  is invoked.

## Constraints

- **Never delete an edited body file.** The whole reason F03 deferred this is that the
  destructive direction deserves its own review. An edited `agents/builder.md` in a child is
  someone's deliberate local change; it survives, loudly.
- **The conversion must be idempotent** and safe to re-run on an already-thin child.
- **`--standalone` and the cascade must not fight.** A child converted to standalone and
  then re-cascaded would be converted straight back; decide and document whether
  `--standalone` clears `umbrella.root` (probably yes — otherwise the flag is a no-op that
  the next cascade undoes) .
- **E24-F01's guard is the observability.** A conversion that goes wrong shows up as drift
  at the top of the next session; that is the intended safety net, and the conversion must
  therefore leave the tree in a committable state.
- Bump `VERSION`; this changes the installed layout of existing targets, so read
  `AGENTS.md` → Versioning carefully on MINOR vs MAJOR.

## Open questions

- **Does conversion need an explicit opt-in flag** (`--thin`), or is re-running the cascade
  consent enough? An operator running `--umbrella` is asking for the umbrella layout, which
  argues for automatic — but silently rewriting 29 tracked files per child is exactly the
  class of surprise `E24-F02` exists to prevent, which argues for a flag plus a report.
- **What does a child do when its umbrella is unreachable at conversion time?** Almost
  certainly "convert nothing" — but say so on the record.
