# Intent — pi front-end key: shared-skill claim, `.pi/prompts` commands, host marker, worker entry, docs

## Problem / who
Harness users who drive work from the pi coding agent (pi 1.x). `--agents=pi` dies today
(`AGENT_KEYS`, `harness-install.sh:1651`); pi only sees the shared `.agents/skills` units
when another claimant was selected. See `specs/epics/E35-pi-first-class/epic.md` (verified
facts) and `progress/scout-pi-frontend.md` (every wiring site, with line refs).

## Success outcome
`sh harness-install.sh --agents=pi <target>` produces a target where pi runs the `/sdd-*`
commands natively, the host is detected as `pi`, and deselecting `pi` removes exactly what
pi added. claude/codex/opencode/antigravity behave byte-identically.

## Scope / boundaries
In scope:
- `pi` in `AGENT_KEYS` and every hard-coded key list/message (`recorded_active_selection`,
  `detect_host`/`validate_csv` messages, header comment, manifest text), picker, `--agents=all`.
- pi is a **claimant of the shared `.agents/skills/` unit** (ADR-0003; `skill_unit_claimed`),
  and the host-neutral adapter text in `gen_skill_body` names pi's invocation.
- Native commands: `.pi/prompts/<cmd>.md` for each shared command name (so pi shows
  `/sdd-next`, not only `/skill:sdd-next`), each a thin pointer to the shared unit body,
  `description` frontmatter, `$ARGUMENTS` passthrough; respects the same gates as the
  shared units (pr-loop gate, opencode-parallel-style gate if relevant, `sdd-triage`
  `--self` only).
- `HOST_MARKERS` row `pi PI_CODING_AGENT` with recorded provenance (live probe 2026-10-13,
  pi 1.2.0: `AI_AGENT=pi`, `PI_CODING_AGENT=true`, `PI_SESSION_ID`) — satisfy
  `test_agents_host` R8's provenance rule.
- `WORKER_INVOKE` row for pi: `pi -p` non-interactive (must pass `-a`; see epic facts).
- Deselect cleanup arm (pristine-only, like the others), banner/advisory counters,
  `tools/harness-owned-paths.sh`, README/AGENTS.md/docs (HARNESS, INSTALL, WORKFLOW) front-end
  lists, including a "project trust" note (pi skips project resources unless trusted).
- Update every test that hard-codes the four keys; add `tests/test_pi_front.sh`.
- VERSION MINOR bump + CHANGELOG.
Out of scope (later features): role sub-agents/dispatcher (F02), model routing (F03),
preflight/package install (F04), `--self` support for pi glue (F02).

## Chosen options
- Full E31 model (not the lighter E33 model).
- Commands via both `/skill:sdd-*` (shared units) and `/sdd-*` prompt templates.

## Constraints
- ADR-0003: one shared unit per command; pi claims it, never writes a second copy.
- Never edit `~/.pi/agent`. No network or model calls in tests.
- Lessons: run suites through their own shebang; fixtures copied from repo must delete the
  artifact under test first.

## Open questions

- Whether `.pi/prompts` needs its own gate for `sdd-fix-parallel` (pi has no known
  concurrency restriction — Architect to decide, default: same set as the shared units).
