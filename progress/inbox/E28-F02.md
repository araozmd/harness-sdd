# Intent — Planner emits a repo-topology ADR + draft umbrella manifest

## Problem / who
Repo topology (one repo vs an umbrella of N child repos) is decided by hand before the
harness exists, with no ADR and no artifact a tool can consume. The Planner already writes
`specs/architecture.md` and ADRs; it is the right place to make the topology explicit,
because that is where the deployables are named.

## Success outcome
When the Planner's architecture names MORE THAN ONE deployable (service/app/package that
ships separately), it also writes (a) one ADR "repo topology" naming each repo and why it is
separate, and (b) a draft `umbrella.manifest.yaml` at the harness root listing each child
(`path`, `init`, `test_command`, empty `delegate_cmd`, optional `scaffold_cmd`) using the
shipped `umbrella.manifest.example.yaml` shape. When it names exactly one deployable it
writes neither, and the run is byte-identical to today. The draft manifest is INERT: its
presence must NOT flip umbrella mode by itself (today presence = switch, so the draft needs
a distinct name or location — Architect decides).

## Scope / boundaries
- IN: `agents/planner.md` contract delta, `/sdd-plan` command body, manifest draft format
  (incl. the new optional `scaffold_cmd` key), tests over a fixture plan run.
- OUT: creating any repo or directory; running the installer; anything in F03.

## Chosen options
- Topology is an OUTPUT of planning, not an input to it.
- The artifact is a file on disk, so F03's promotion is testable without an LLM.

## Constraints
- Purely additive to the Planner; re-run guard and append-only id rules unchanged.
- `scaffold_cmd` is opaque to the harness (never interpreted, only run by F03).
- Prose that explains how to decide is a hobbling candidate; state the non-guessable
  facts (file name, keys, the "inert draft" rule) and stop.

## Open questions
- Draft manifest name/location so it cannot be mistaken for the live switch
  (e.g. `umbrella.manifest.draft.yaml` vs `specs/topology.yaml`).
- Should `/sdd-drill` be allowed to amend the draft manifest when an epic adds a repo?
