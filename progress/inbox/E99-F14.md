# Intent — `init.sh` should catch a board entry that disagrees with its spec

## Problem / who

PR #122 surfaced **two contracts that nothing enforces**. Both cost a review round each,
and both were invisible to `init.sh`, which is the one thing every agent runs before work.

1. **`spec_path` existence is never checked.** `tools/validate-board.py` asserts only that it
   is a *string*. E17-F05's board entry pointed at `F05-installer-stamped-arming/` while the
   spec was written to `F05-escalation-arming/`. A Reviewer following the board to an
   `in-review` feature could not read its four spec files, and `init.sh` stayed green.
   (Codex #3717571008.)

2. **A feature's `.spec.md` frontmatter `status` is never checked against the board.**
   `store/local.md:111-112` requires them in sync — "a feature id edits that feature's
   `status` … keep the feature's `.spec.md` frontmatter `status` in sync" — but nothing
   verifies it. E17-F05 shipped its spec saying `pending` while the board said `in-review`.
   (Codex #3728226119.)

**The drift is already on main and is not hypothetical:** `E17-F02` and `E17-F03` both carry
`status: pending` in their spec frontmatter while the board says `done`. E17-F01 is in sync,
so this is drift rather than a convention nobody follows.

## Success outcome

`init.sh` fails — with a named path and both values — when a board feature's `spec_path` does
not resolve, or when its `.spec.md` frontmatter `status` disagrees with the board. The two
existing mismatches are corrected in the same change, so a fresh clone is green.

## Scope / boundaries

**In scope**
- Validation in the existing board-validation path (`tools/validate-board.py`, surfaced by
  `init.sh`), so it costs no new tool and no new call site.
- Correcting `E17-F02` and `E17-F03` spec frontmatter to `done`.
- Deciding what a **missing** `.spec.md` means for a feature that has a `spec_path` — a
  `pending` feature legitimately has no spec yet, so absence must not fail. Say so explicitly.

**Out of scope**
- Any change to the status vocabulary or to `store/tasks.schema.json`.
- Auto-*fixing* either mismatch. This reports; a human or the Orchestrator writes.
- Epic-level `epic.md` frontmatter (same contract, but enumerate it before assuming it is
  the same fix — E17-F05's review found a missed path in three consecutive rounds by
  assuming an enumeration was complete).

## Constraints

- `init.sh` is a MANDATORY gate: a false positive halts all agent work. Every failure must
  name the file, the board value and the frontmatter value.
- A `pending` feature with no spec directory yet must stay green.
- POSIX sh / `dash`; green under `sh tools/run-tests.sh`.

## Open questions

- Does the same contract bind `epic.md`? Check rather than assume.
- Should a `spec_path` that resolves but is *empty* fail, or only a missing one?
