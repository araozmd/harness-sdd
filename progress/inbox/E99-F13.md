# Intent — Keep `#` inside a quoted `umbrella.root` instead of truncating at it

## Problem / who
Found by Codex on PR #109 (#3711176794) and reproduced before seeding this. The
`umbrella.root` reader strips YAML comments **before** it strips quotes:

```awk
sub(/^[[:space:]]+root:[[:space:]]*/, ""); sub(/[[:space:]]*#.*$/, "")
gsub(/^"|"$|^'|'$/, ""); print; exit
```

So a correctly-quoted, machine-written value loses everything from the first `#`:

```
written:  root: "/tmp/umb#root"
parsed:   /tmp/umb
```

Verified by running that exact awk program against that exact input.

The parser is **duplicated verbatim in two places**:
- `harness-install.sh` → `_cfg_umbrella_root_value()` (~L545–555)
- `init.sh` (~L214–222)

Consequence: a child under an umbrella whose path contains `#` resolves a truncated root.
`init.sh` reports the umbrella unreachable, and a later standalone installer run replaces the
child's thin stubs with full copies — silently undoing E24-F03 for that tree.

The user is anyone whose checkout path contains `#`. Uncommon, but the cascade **writes this
value itself**, so the harness is corrupting its own machine-written data rather than
mishandling operator input.

## Why this is its own feature and not part of E24-F03
It is a defect of the shared config parser, not of prose-tier thinning. E24-F03's PR had
already produced nine blocking findings across two implementations of the stubbing function;
pulling a parser change — one that also edits `init.sh`, which E24-F03 otherwise only appends
to — into that diff is how a tenth arrives. Split on the seam, per the review decision.

## Success outcome
A quoted `umbrella.root` round-trips exactly as written, `#` included, through both readers.

## Scope / boundaries
In scope:
- Correct comment stripping in both copies: only strip `#` that begins a comment, i.e. one
  **outside** a quoted scalar.
- A test asserting the round-trip through both readers, with a fixture whose path contains `#`.

Out of scope:
- A general YAML parser. Handle the quoted-scalar case these two readers actually write.
- De-duplicating the two parsers into one shared file. That is a real cleanup and a real
  behavioural risk — `init.sh` must stay standalone-executable — so it deserves its own
  decision rather than riding along here.
- Other config keys, unless the same `sub()` pattern is shown to affect them.

## Constraints
- POSIX awk; must pass under `dash` (CI `/bin/sh`).
- The two implementations must stay behaviourally identical — a test should pin that, since
  they have already drifted apart once by being edited separately.
- Unquoted values must still honour a trailing ` # comment`, or existing configs break.
- Installed body ⇒ `VERSION` PATCH bump.

## Open questions
- Does anything else read `harness.config.yaml` with the same `sub(/[[:space:]]*#.*$/, "")`
  idiom? Worth one grep before scoping — if there are five copies, the de-duplication
  question stops being optional.
- Preferred fix shape: strip the comment only when the `#` is not inside quotes, or strip
  quotes first and skip comment-stripping entirely for a quoted scalar? The second is simpler
  and matches how the value is always written, but changes behaviour for a quoted value with
  a genuine trailing comment.
