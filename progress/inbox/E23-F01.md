# Intent — Modern Codex skills and inherited role registration

## Problem / who

Engineers installing this portable SDD harness for current Codex receive an adapter
that still writes global custom prompts even though that Codex surface has been
removed. They can also lose named Architect, Builder, Reviewer, Scout, and
Doc-Critic registration whenever model routing is left at its default `inherit`
setting. The harness lifecycle itself is compatible; the Codex-specific glue is
not aligned with the current extension contract.

## Success outcome

Installing or upgrading the harness gives a current Codex user repository-local
SDD skills and project-local named roles that work with inherited or explicitly
pinned models. Legacy pristine Codex prompt artifacts are handled safely, docs and
versioning describe the new contract, and regression coverage proves the other
front-end adapters have not changed.

## Scope / boundaries

- In scope: replace Codex global prompt installation with skills under
  `.agents/skills`; generate `.codex/agents` role TOMLs even when every role
  inherits its model; safely clean up legacy pristine Codex prompt files; preserve
  edited user files; update installer ownership/reclamation, tests, docs,
  changelog, and the public harness version.
- In scope: cover every currently supported SDD command, including gated
  PR-loop glue when that feature is enabled.
- Out of scope: changes to the portable SDD state machine, role responsibilities,
  TaskStore schema, or the behavior/artifact layout of Claude Code, OpenCode,
  Antigravity (`agy`), and Gemini.
- Out of scope: a general plugin system or Codex runtime concurrency redesign.

## Chosen options

- Use first-class repository-local Codex skills rather than a plugin package or
  undocumented prompt compatibility shim.
- Keep Codex skills beside, without replacing, Antigravity's existing
  `.agents/rules`, `.agents/agents`, and `.agents/workflows` layout.
- Treat the user's explicit autonomous request as authorization to proceed through
  the spec gate without another approval pause.

## Constraints

- Do not alter generated Claude Code, OpenCode, Antigravity, or Gemini adapter
  content or invocation semantics.
- Codex role registration and Codex model selection must be independent: inherited
  roles omit the optional `model` key but still exist.
- Cleanup may delete only harness-owned, pristine legacy prompt artifacts; a
  user-edited file must survive.
- Preserve installer ownership guarantees and idempotence.
- Follow the harness's test-first Builder loop and Reviewer-owned `done` verdict.

## Open questions

- The Architect should choose the exact ownership-ledger and byte-comparison
  strategy for recognizing legacy pristine global prompt files across upgrades.
- The Architect should define the smallest stable skill frontmatter contract and
  how gated commands such as the PR loop are added and reclaimed.
- The Architect should identify the precise regression snapshots/assertions that
  best prove non-Codex adapters remain byte-for-byte unaffected.
