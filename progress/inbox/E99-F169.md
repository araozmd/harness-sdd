# Intent — Parallelize isolated umbrella test groups

## Problem / who
Harness maintainers and reviewers wait for the large serial `tests/test_umbrella.sh` suite after other suites finish. The existing eight-worker verification runner cannot parallelize independent groups hidden inside this single long-running suite.

## Success outcome
Full verification spends less wall-clock time waiting on the umbrella suite, with measured before/after evidence under comparable conditions. Every existing umbrella check remains covered, failures remain visible, and maintainers can still invoke the umbrella entrypoint directly.

## Scope / boundaries
Split safe, isolated umbrella test groups into suites discoverable by the existing runner. Preserve all checks, fixtures, cleanup, and direct entrypoint usability. Record benchmark conditions and results, and update relevant current documentation to explain the resulting test layout. Unrelated framework changes, runner redesign, and changes to installer or umbrella product behavior are outside scope.

## Chosen options
- The user approved splitting the serial umbrella suite into isolated groups that use the existing eight-worker runner.
- The user then asked to implement the optimization. This bounded design is authorized for autonomous specification and implementation (`sdd: true`, `autonomous: true`).
- This is a new maintenance feature under E99 (altitude 2); no consumed feature brief is extended.

## Constraints
Preserve every existing check and its meaningful assertions. Keep concurrent groups independent, with isolated temporary fixtures and reliable cleanup. Avoid duplicate execution during discovery while retaining a usable direct umbrella entrypoint. Preserve the existing runner's concurrency and failure-reporting contract. Benchmark before and after under comparable conditions; disclose variation rather than inventing a speedup. Use a temporary directory outside this repository and its ancestors/descendants when running suites that copy the repository, and account for disk headroom.

## Open questions
The Architect chooses safe group boundaries and how to retain the direct entrypoint without duplicate discovery, using the independent Scout's dependency findings. No additional product decision or approval is needed within this bounded scope.
