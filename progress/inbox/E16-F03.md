# Intent — Deterministic next() selection via zero-dep tools/next-task.mjs

## Problem / who
The Orchestrator's `next()` routing (status × sdd × autonomous × epic gate ×
depends_on × slices × owner) is prose in `agents/orchestrator.md`, re-interpreted by a
model each session — the harness's most bug-prone surface. A misread silently selects
the wrong work (or none). Serves everyone running `/sdd-next`, and future maintainers
who get unit-testable routing instead of prose archaeology.

## Success outcome
- `tools/next-task.mjs` (Node ≥18, zero external deps, same posture as
  sync-board.mjs): reads `state/tasks.json` + relevant `harness.config.yaml` keys,
  applies ALL existing gates unchanged, prints JSON: the selected feature/slice id (or
  null) + a `reason` field, and per-candidate blocking reasons when nothing is
  selectable — reusing E16-F01's reason-string vocabulary verbatim (ADR-0001).
- `agents/orchestrator.md` updated: selection step invokes the tool and trusts its
  output; the prose table stays as the tool's specification/acceptance oracle, marked
  as such.
- Behavior-preserving at introduction: a test suite exercising the documented routing
  cases (draft gate, depends_on, spec-ready gate vs autonomous, sdd:false lane,
  --mine scoping, umbrella slice topology + merged gate) — the prose table is the
  oracle; any divergence is a bug in the tool.
- Graceful fallback: if node is absent, the Orchestrator falls back to today's prose
  routing (the tool is an upgrade, not a new hard dependency).

## Scope / boundaries
- IN: tools/next-task.mjs, orchestrator.md selection step, tests, docs touched,
  VERSION/CHANGELOG (installed body).
- OUT: no gate-policy changes (what the gates ARE stays in orchestrator.md + config);
  no schema changes; no writes by the tool (read-only selection — Orchestrator still
  owns set_status).

## Chosen options
- Human approved 2026-07-24 ("All four"). depends_on E16-F01 (shared reason strings).

## Constraints
- ADR-0001 is the governing decision — honor all its consequences, especially
  "no behavior change at introduction" and read-only selection.
- Zero external deps; must handle umbrella manifests absent/present.
- Permanent-suite anti-pattern rules apply to tests.

## Open questions
- CLI shape (`--mine`, `--json`), and whether init.sh should smoke-run it when node
  exists — Architect's judgment.
