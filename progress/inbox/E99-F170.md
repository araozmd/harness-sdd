# Intent — Harden /sdd-pr-loop hand-back head check, dry-run mutations and fixer resume

## Problem / who
A downstream target (Apolo, pinned 0.89.2) stamped `/sdd-pr-loop` and Codex review of the
generated glue flagged three defects that are still present in the canonical body emitted
by `harness-install.sh` on 0.91.1:

1. **P1 — hand-back does not revalidate the reviewed head.** With `auto_merge: false` the
   loop posts the all-gates-green summary and writes `handback` to `disposed` without the
   `merge-verify pre` receipt the auto-merge path runs. A commit pushed after `pr.json`
   was captured is reported green although Codex reviewed an older head — and the
   terminal `handback` marker then short-circuits the next invocation at that head.
2. **P1 — `HARNESS_DRY_RUN=1` only skips the trigger comment.** `gh pr ready`, the PR
   checkout, fixer commits and the round push, `needs-human` labels, `resolveReviewThread`
   mutations, terminal comments and (with auto-merge) the merge still run. A dry run also
   writes its stub round into the real cache, where its `outcome`/`disposed` markers
   consume budget and can masquerade as a completed hand-back.
3. **P2 — resume re-dispatches completed fixers.** Re-entering an observed-but-undisposed
   findings round hands every blocking comment to a fixer again, ignoring existing
   `fix-<comment_id>.md` notes, local fixer commits, and `acted.json` rows (which are also
   appended a second time, inflating the trend count).

## Intended fix
In the canonical `/sdd-pr-loop` body inside `harness-install.sh` only:
- Hand-back path: run the same reviewed-head receipt (`merge-verify … pre`) before posting
  the success summary or writing `handback`; on a moved/unreadable head take the
  needs-human state with no success comment and no `disposed` marker.
- Dry run: route every remote/repository mutation through one `mut` wrapper that logs
  and skips under `HARNESS_DRY_RUN=1`; never dispatch fixers or push; never merge; keep
  the dry-run round cache in its own `dry-run/` root so it cannot poison a real run.
- Resume: a `fix_done <comment_id>` helper (fix note present, or a `(#<id>)` fixer commit
  after the round's reviewed head) filters dispatch; `acted_append` becomes idempotent per id.
Regenerate the self-hosted glue with `sh harness-install.sh --self`; patch release.

## How to verify
Extend `tests/test_pr_loop.sh` with: placement checks (head receipt before the hand-back
post/marker), extraction-and-execution of the `mut`, `fix_done` and `acted_append`
helpers against a scratch git repo, and a sweep proving every mutating command in the
body's code blocks goes through `mut`. Run the focused suite, `./init.sh`, and
`tools/run-tests.sh`. Independent Reviewer approval before the PR.
