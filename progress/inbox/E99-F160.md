# Fix — pin the `models:` seed-block byte-identity invariant

## Problem
The `models:` block exists twice and the two copies must stay byte-identical: the heredoc
`harness-install.sh` appends to a migrating target's config, and the shipped block in
`harness.config.yaml`. The heredoc's own comment states why — a FRESH install (which copies
the config verbatim) and an UPGRADED install (which only migrates) must converge on the same
text, or the two populations drift apart silently.

Nothing enforces it. Found during the E99-F159 review: mutant **M6** desynced
`harness-install.sh:271` from `harness.config.yaml:227` and **survived the full 47-suite
run**. The invariant the comment calls load-bearing is unpinned.

The sibling `workers:` block is already pinned — `tests/test_install.sh:154`,
`test_workers_block_seeded_migrated_converge`, which strips the block from an installed
target and `cmp -s`'s the freshly-seeded copy against the migrated one. `models:` never got
the same treatment.

Pre-existing; E99-F159 did not widen it. Deliberately left out of that fix to keep it inside
its brief's file list, and recorded there as owed a board row.

## Intended fix
Add the near-copy of `test_workers_block_seeded_migrated_converge` for the `models:` block,
following that test's existing shape rather than inventing a new one. It must fail if the
two copies ever diverge by a byte.

Prefer an assertion that compares the two sources directly over one that only re-checks
convergence after an install: the failure mode is an author editing one copy and not the
other, and the test should name that, not a downstream symptom.

## How to verify
- The new test passes on `main` as-is.
- **Mutate to prove grip**: change one byte in `harness-install.sh`'s `models:` heredoc,
  leaving `harness.config.yaml` alone — the new test must fail with a message that names the
  desync. Restore, then mutate the other copy and confirm it fails there too. Run the two
  mutations **separately**: the E99-F159 round-1 rejection was caused by batching two
  independent paths into one mutant, which proves only that one is pinned.
- `./tools/run-tests.sh` stays green, `./init.sh` exits 0.
