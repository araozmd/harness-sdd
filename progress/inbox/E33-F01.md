# Intent — Native Antigravity invocation adapter, dynamic subagent dispatch, and documentation

## Problem / who
Engineers using Google Antigravity (CLI `agy` or Desktop/IDE) cannot easily run the full harness-sdd SDD lifecycle with native multi-agent isolation. Historical Antigravity support (E07) was retired in E29 because `.agents/agents/*.md` personas were not discoverable without global plugin bundles. Today, Antigravity natively discovers `.agents/skills/`, but the harness skills lack explicit Antigravity documentation, and role delegation currently assumes Claude subagents or Codex roles.

## Success outcome
Antigravity is supported as a first-class front end:
1. `.agents/skills/*/SKILL.md` invocation adapters explicitly document Antigravity `/sdd-*` slash commands alongside Codex `$sdd-*` and OpenCode `/sdd-*`.
2. `agents/orchestrator.md` and `.agents/skills/sdd-next/SKILL.md` define the dynamic subagent dispatch pattern (`define_subagent` from `agents/*.md` prompts) so role isolation (Architect → Builder → Reviewer) is enforced in Antigravity.
3. Canonical documentation (`AGENTS.md`, `README.md`, `docs/WORKFLOW.md`) accurately describes Antigravity usage, requirements, and invocation.
4. All existing tests pass without regressions, and `init.sh` remains completely green.

## Scope / boundaries
- **In scope:**
  - Invocation adapter updates in `.agents/skills/`.
  - Orchestration instructions for Antigravity dynamic subagent definition.
  - Updating `AGENTS.md`, `README.md`, and `docs/WORKFLOW.md`.
  - Adding test coverage for Antigravity skill adapter syntax.
- **Out of scope:**
  - Re-introducing heavy installer emitter matrices in `harness-install.sh`.
  - Creating machine-local plugin bundles under `~/.gemini/antigravity-cli/plugins/`.
  - Rewriting existing Claude, Codex, or OpenCode role files.

## Chosen options
- Use shared `.agents/skills/` without separate directories.
- Use dynamic `define_subagent` calls at runtime rather than static files on disk.

## Constraints
- 100% repository-local: no machine-global configuration.
- Must preserve independent Reviewer gate and context hygiene.
- Must not break `harness-install.sh`, `init.sh`, or existing test suites.
