# Intent — Uncited plan rows block: plan-cite-check tool + Reviewer gate

## Problem / who
`agents/architect.md` already says every plan decision cites the R-id(s) it serves. The plan
template's API and Files-to-change tables have an `R-id` column; its Data model table does
not (it carries the citation only in the section heading, `## Data model  (serves: R#, R#)`). Nothing enforces it: the doc-critic's
YAGNI finding is advisory and the Reviewer verifies R-id↔test, not plan-row↔citation. That
gap is how a WAF appears in an MVP plan. ADR-0009 decision 4 makes an uncited row a defect;
this feature ships the mechanism.

## Success outcome
- `tools/plan-cite-check.py <feature.plan.md> [--spec <feature.spec.md>] [--adr-dir
  specs/adr]` parses the plan's Data model, API/interface and Files-to-change tables plus
  any `## Deferred` subsection; exits non-zero listing each row whose citation column has no
  `R#` and no `ADR-NNNN`, each `R#` that does not exist in the spec, and each `ADR-NNNN` that
  resolves to no file (reusing the namespace rule from the ADR-citation check in
  agents/reviewer.md). A table whose section heading carries `(serves: R#…)` inherits that
  citation for every row lacking its own; this feature also adds an `R-id` column to the
  Data model table in `specs/_templates/feature.plan.md` so new plans cite per row. Prose
  outside tables is not parsed.
- The doc-critic feature-spec checkpoint additionally flags a plan that omits a sticky NFR
  (list from the ADR template, E36-F03) or adds a bolt-on row without an `R-id`; the
  `init.sh` warn-only sweep also reports a `Status: deferred` ADR with no `Trigger:` line
  (both moved here from E36-F03 to keep that feature under the size budget).
- The Reviewer runs it as a new numbered check; a non-zero exit is a REJECT with the tool's
  output quoted. The doc-critic runs it at the feature-spec checkpoint and reports advisory.
- `init.sh`'s warn-only sweep runs it over every `spec-ready`/`in-progress` feature plan.
- The tool ships via the installer like `tools/task-diagnostics.py`; `tests/test_install.sh`
  asserts its presence; a dedicated suite covers: clean plan, uncited row, dangling R-id,
  dangling ADR, deferred subsection, and a plan with no tables (passes).
- Fixtures: a positive and a negative plan under `tests/fixtures/`.

## Scope / boundaries
In scope: the tool, Reviewer + doc-critic prose, init.sh sweep, installer wiring, tests,
docs/RATIONALE.md control-table row. Out of scope: judging whether a cited row is
*justified* (that stays with the doc-critic's YAGNI finding); sdd:false fixes (no plan).

## Chosen options
- Python, stdlib only, like task-diagnostics.py; table parsing by header row, not by position.
- Blocking in the Reviewer, advisory in the doc-critic (same split as other controls).

## Constraints
- Honor ADR-0009 and the ADR-citation namespace rule already in agents/reviewer.md.
- Depends on E36-F03 for the `## Deferred` subsection shape and `Status: deferred` ADRs.
- Register the control in docs/RATIONALE.md as durable (it protects a contract, not a
  model weakness).

## Open questions
- Whether a `DO NOT TOUCH` row needs a citation (proposal: no, it is a constraint, not a
  decision) — Architect decides.
