# Intent — Worktree-per-fix isolation helper for concurrent fix branches

## Problem / who
Concurrent fixes cannot share one working tree — they would stomp each other's edits
and branch checkout. This feature gives the harness a helper that runs each fix in its
own `git worktree` on its own branch, so N Builder→Reviewer chains (driven by F03) work
in isolation and each produces an independent PR. The user is the parallel dispatcher
(F03) and, transitively, the human watching independent fix PRs land.

## Success outcome
Given a fix id, the helper provisions an isolated worktree on a fresh
`feat/<id>-<slug>` branch off `main`, the fix's Builder→Reviewer loop runs entirely
inside it, and the worktree is torn down on success/merge — leaving no stray worktrees
or branches. Two fixes running at once never collide on the working tree.

## Scope / boundaries
- In scope: create (`git worktree add`) / teardown helpers; branch naming
  `feat/<id>-<slug>` off `main`; recreation of gitignored local files the fresh
  worktree needs (per `docs/CONFIG-LAYERING.md`); tracking active worktrees under
  `.claude/worktrees/`.
- Out of scope: the concurrency/dispatch logic and conflict guard (that is F03); board
  writes (done via F01's lock); auto-resolving merge conflicts.

## Chosen options
- One git worktree + one branch per fix, off `main`.
- Register active worktrees under the existing (currently empty) `.claude/worktrees/`.

## Constraints
- **Depends on E15-F01** — any board write from inside a worktree goes through F01's
  lock.
- Gitignored local files (personal-layer config) must be recreated/linked in the fresh
  worktree or the fix will run against a broken environment.
- Teardown must be idempotent and safe (never delete a worktree with uncommitted work
  without surfacing it).
- Installed-body change ⇒ VERSION bump (MINOR); installer wiring asserted in
  `tests/test_install.sh` if any installed file changes.

## Open questions
- Where the helper lives (`tools/fix-worktree.sh` vs. an existing tools entry point) —
  Architect to choose, matching current `tools/` conventions.
- Worktree location on disk (under repo `.git/worktrees` vs. a sibling temp dir) and
  how gitignored files are materialized there.
