# Intent — pi role sub-agents: `.pi/agents/<role>.md` + `tools/pi-dispatch.sh` fallback, `--self`

## Problem / who
pi core has no sub-agents, so the Orchestrator cannot hand a role a clean context on pi.
Decision recorded in ADR-0007.

## Success outcome
On a pi target the Orchestrator delegates every role (architect, builder, builder-heavy,
reviewer, scout, doc-critic, pr-fixer, plus any other role the claude/codex emitters ship)
in an isolated child context: via the `subagent` tool when `pi-subagents` is loaded, else
via `tools/pi-dispatch.sh <role> <task-file>`.

## Scope / boundaries
In scope:
- Emit `.pi/agents/<role>.md` in pi-subagents format: `name`, `description`, `tools`
  (translated allowlist: read, bash, edit, write, grep, find, ls — read-only roles get no
  edit/write), `systemPromptMode`, `inheritProjectContext: true`, `inheritSkills` decision,
  body = resolved pointer to canonical `agents/<role>.md` (ADR-0004).
  `model`/`thinking` keys are left to F03 (emit none in F02 → inherit).
- `tools/pi-dispatch.sh <role> <task-file>`: `pi -p -a --no-session [--model] [--thinking]
  --tools <allowlist> --append-system-prompt <resolved role body> "<task>"`, reading the
  role's allowlist from the generated `.pi/agents/<role>.md` (single source), non-zero exit
  propagation, output to stdout; testable with a stub `pi` on PATH.
- Orchestrator / sdd-next dispatch prose for pi (beside the Codex/Antigravity paragraphs,
  `agents/orchestrator.md:572-584`).
- `--self` accepts pi; regenerate and commit this repo's `.pi/agents` + `.pi/prompts`; drift
  gate covers them (precedent E31-F02).
- Deselect cleanup for `.pi/agents`.
Out of scope: model/thinking stamping (F03), package install (F04).

## Constraints
- Tool allowlist translation table must be one function, tested.
- No real `pi` invocation in tests (stub binary).

## Open questions
- `systemPromptMode: replace` vs `append` for role files (Architect to decide; note pi's
  default system prompt carries tool docs).
