# Intent — test_frontend_retirement.sh flakes under parallel load

## Problem / who
`tests/test_frontend_retirement.sh` failed 3 times in full `sh tools/run-tests.sh --jobs 16` runs:
- 2026-10-17, during PR #276
- 2026-10-18, during E31-F03 build round 1
- 2026-10-18, earlier during PR #271/#276

Each time it passed when re-run alone. E99-F175 tried to reproduce it under load and got 0 failures in 32 runs, so its cause is still unknown. A flaky suite costs every Builder and Reviewer an extra full-suite run and argument, and it trains people to ignore red.

## Success outcome
The root cause is found with evidence, and fixed at the cause. The suite passes reliably under `--jobs 16`.

## Scope / boundaries
- Reproduce first:
  - E99-F175 found that synthetic CPU load alone did not trigger it. Run the REAL full suite in a loop (`--jobs 16`, several iterations) and capture the failing assertion and output on failure.
  - Also try parallel runs of test_frontend_retirement alongside the suites that ran concurrently when it failed: installer-heavy ones such as test_install, test_self_*, test_codex_native and test_umbrella*.
- Candidate causes to check:
  - shared paths: fixed temp names, `$SRC` writes, `.harness/` in the source tree, `/tmp` collisions, `mktemp` misuse;
  - git index or lock contention from other suites touching the repo;
  - reads of the live board or repo state that other suites mutate in place;
  - timing assumptions;
  - stub stdin/EPIPE, the E99-F175 pattern;
  - TMPDIR on tmpfs.
- Fix the cause. Do not add retries or sleeps unless the root cause genuinely is a timing bound.
- Out of scope: other suites, unless the root cause lies in a shared helper or in a sibling suite that pollutes shared state. In that case, fix it there.

## Chosen options
- Evidence first.

## Constraints
- Test-only, so no VERSION bump, unless a shipped tool is the cause; then PATCH 0.97.1 and update the CHANGELOG.
- Report the reproduction rate before and after the fix.
- If 20+ real full-suite iterations do not reproduce it, report that honestly with the run count. Then harden the most plausible cause only with evidence of the hazard, e.g. a demonstrated shared-path collision, and say so plainly.
