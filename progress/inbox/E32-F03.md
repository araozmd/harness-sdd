# Intent — Reporting rule + /sdd-report command on every front end: four triggers, end-of-task and early-stop filing

## Problem / who
Agents must know *when* a harness defect is worth reporting and actually do it, on Claude, Codex and OpenCode alike.

## Success outcome
`AGENTS.md` / role prompts carry a short reporting rule with the four triggers and the explicit non-triggers; a `/sdd-report` (`$sdd-report`) command drafts the structured report and calls F02's tool; the **session-owning top-level role** (Orchestrator, or Fixer/Inception/Planner/Driller when it owns the session) invokes it on end-of-task and early-stop (abort/park/fail) when a trigger fired; sub-agents (Builder, Reviewer, Architect, …) only append trigger notes under `progress/` for it to pick up.

## Scope / boundaries
In: rule text, command emitted via existing emitters for all front ends (ADR-0003), regenerated `--self` glue, fixture scenarios per trigger and non-trigger (prompt-contract tests in the style of existing `tests/`). MINOR `VERSION` bump (reporting goes live). Out: the filing mechanics (F02).

## Chosen options
- Triggers: harness malfunction; contradictory/impossible instruction; workaround taken; missing capability.
- Never: project code/test failures, transient network/auth errors, agent mistakes the harness correctly caught.
- File at end of task or on early stop, never mid-flow.

## Constraints
- Epic contract: `specs/epics/E32-feedback-loop/epic.md` (success criteria are binding).
- No hand-edits to `.claude/*`; run `sh harness-install.sh --self`.
- Keep rule text short; role prompts are context budget.
- ADRs to honor: ADR-0003, ADR-0006, ADR-0004 (follow F01's umbrella-child resolution).
