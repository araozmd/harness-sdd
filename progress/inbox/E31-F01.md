# Intent — OpenCode claims the shared `.agents/skills` units

## Problem / who
OpenCode is documented as the harness's third front end, but it reads the Codex-native
`.agents/skills` surface without being a claimant (ADR-0003), the shared `SKILL.md` adapter
speaks Codex only, and the OpenCode concurrency gate is bypassed because the shared
`sdd-fix-parallel` unit is written unconditionally. This serves the harness operator who runs
OpenCode in a repo the harness installed.

## Success outcome
Selecting `opencode` installs the shared units; deselecting it while Codex remains leaves them
in place; the shared body is correct for both hosts; `/sdd-fix-parallel` cannot run in OpenCode
unless `/sdd-test-concurrency` marked the install `supported`.

## Scope / boundaries
In: `skill_unit_claimed()`, `gen_skill_body()` adapter, the `sdd-fix-parallel` capability
precondition, ADR-0003 claiming set, docs, and the mixed-selection tests.
Out: `.opencode/` source glue and `--self` (E31-F02); command-body changes beyond the gate.

## Chosen options
- One body, self-gating the workflow (not the file), because Codex still needs the unit and
  OpenCode would still read any unit on disk.
- Keep the historical `.harness/.codex-skills/` ledger name.

## Constraints
ADR-0003's one-unit/one-body rule; a `codex`-only selection must be byte-identical; no new
dependency.

## Open questions
None blocking.
