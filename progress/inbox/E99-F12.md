# Intent — Surface a non-GNU/BSD `grep` so local runs are not silently unlike CI

## Problem / who
Discovered while fixing E99-F11. On this development machine `grep` resolves to **ugrep
7.5.0**, a third-party replacement — not GNU grep, not BSD grep. It **drops lines containing
invalid UTF-8 under every locale**, including `LC_ALL=C`.

Every harness script shells out to `grep`: `init.sh`'s ADR-citation sweep, `tools/change-size.sh`,
`tools/pr-gate.sh`, the landing audit, and most of the 29 test suites. So local behaviour can
diverge from CI in ways **no test here can surface**, because the suites run under the same
`grep` they would need to be testing.

The concrete cost is already recorded: two E99-F11 findings could not be reproduced or
refuted locally, and both fixes shipped on documented `LC_ALL` semantics rather than on
evidence. That is the right call for one PR and a bad steady state.

The user is anyone running the harness on a machine whose `grep`, `sed`, or `awk` has been
replaced — increasingly common, since these are popular Homebrew/`cargo install` swaps.

## Success outcome
The operator learns, once, that their `grep` is not one of the two flavours the harness's
scripts and tests assume — before a suite passes or fails for a reason unrelated to the code.

## Scope / boundaries
In scope: a **warn-only** probe. Detect the flavour and say so.

Out of scope:
- Failing the gate. `init.sh` runs before every agent step; a hard failure over a working
  `grep` would be a far worse false positive than the problem it reports.
- Rewriting any script to avoid `grep`, or vendoring one.
- `sed`/`awk` — the same class, but scope this to the tool with a demonstrated divergence
  rather than speculating about the others.

## Constraints
- Warn-only, one line, once per run. `init.sh` is the hot path.
- Must not fire for GNU grep or BSD grep — those are the assumed flavours and the overwhelming
  majority. A warning everybody sees is a warning nobody reads.
- Zero new dependencies; POSIX sh.
- Detection must not depend on `--version` succeeding: some builds print to stderr, some exit
  non-zero. Fail SILENT on an unreadable version rather than warning about a `grep` that may
  be perfectly standard.
- Installed body ⇒ `VERSION` PATCH bump.

## Open questions
- Where does the warning belong: `init.sh` (every session, hot path) or `tools/run-tests.sh`
  (only when the suites run, which is where the divergence actually bites)? The second is
  narrower and probably right — the failure mode is *tests passing for the wrong reason*, not
  agent work going wrong.
- Is a behavioural probe better than a version string? Feeding one known invalid-byte line
  through `grep -c ''` and checking the count is 1 detects the actual divergence rather than
  the brand — and would also catch a future GNU/BSD regression. Costs one subprocess.
