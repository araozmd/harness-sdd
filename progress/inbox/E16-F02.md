# Intent — Deletion ledger + "why a harness" rationale docs

## Problem / who
The harness never states *why it exists*, so (a) new users can't judge why they should
adopt it over "just prompt the model", and (b) maintainers can't tell which mechanisms
are load-bearing process versus scaffolding that should be deleted as models improve.
The 2026-07-24 harness-engineering investigation produced the two-layer answer the
industry converged on (Anthropic, OpenAI, LangChain, Thoughtworks): a **temporary
capability-compensation layer** (built for deletion) and a **durable trust-and-intent
layer** (specs, approval gates, auditability, verification — persists regardless of
model intelligence). The human explicitly requested this rationale be added to the
docs for other users.

## Success outcome
- A `docs/RATIONALE.md` (name = Architect's call) that other users can read cold:
  why a harness at all, the two-layer model, and the claim that harness value shifts
  (not disappears) as models improve — bottleneck moves from "can the model write the
  code" to "can humans specify, verify, and trust what it wrote".
- A **deletion ledger** section (same doc or sibling): every notable harness mechanism
  classified as `compensation` (e.g. init.sh structural gate, DO-NOT-TOUCH enforcement,
  context_reset_threshold, cross-file consistency audit, multi-round build↔review) or
  `durable` (EARS specs + R-id traceability, role separation, human gates, drift check,
  telemetry, ownership, umbrella contracts), each with a one-line "re-test at next
  model generation" note saying what evidence would justify removal.
- Linked from README/AGENTS.md/docs index wherever the docs map lives, and installed
  with the harness body (so consumers get it).

## Scope / boundaries
- IN: the new doc(s), docs-index/README/AGENTS.md link lines, installer wiring if
  docs/ files are enumerated explicitly (verify how harness-install.sh ships docs/),
  VERSION/CHANGELOG per policy (installed body changes).
- OUT: no behavior changes, no agent-contract changes, no removal of any mechanism —
  the ledger *classifies*; deletions are future features driven by its re-test notes.

## Chosen options

  rationale to the docs to allow other users understand why we are using the harness".
