# Intent — Installer promotion: single install → umbrella coordinator from the manifest

## Problem / who
There is no supported path from a single-target install to an umbrella coordinator.
`--umbrella` only DISCOVERS existing depth-1 git children; it never creates one. So once
the plan (F02) says "three repos", the owner is back to hand-creating dirs, `git init`,
copying the manifest and re-running the cascade — the exact toil this epic exists to remove.

## Success outcome
One installer invocation (flag name is the Architect's call, e.g. `--promote <manifest>` or
`--umbrella <dir> --from-manifest <file>`) turns a single-target install into an umbrella
coordinator: it converts the existing `.harness/` into the coordinator profile, and for each
child in the manifest that does not exist it `mkdir` + `git init`s it, runs the optional
`scaffold_cmd` inside it (opaque, best-effort, failure named loudly), then reuses the
existing cascade to install the child profile, populate the live manifest, and run the
landing audit. `--shared-repo` composes with it. `--dry-run` previews exactly what would be
created. Re-running is idempotent (existing children untouched, identical to a plain cascade).

## Scope / boundaries
- IN: `harness-install.sh` promotion path, coordinator-profile conversion of an existing
  single install (board/specs/progress carried over, not lost), tests in `tests/` for
  create-missing / all-exist / dry-run / scaffold_cmd failure / idempotent re-run.
- OUT: GitHub remotes, branch protection, Codex App, any stack scaffolding logic. The
  harness runs `scaffold_cmd`; it never knows what it does.

## Chosen options
- Reuse the cascade; do NOT reimplement discovery or child install ("reimplementing a tool
  invites a bug per feature", progress/lessons.md).
- Local git only; the output names the remote work the human still owes.

## Constraints
- Every gate fails closed: a missing/invalid manifest, a child path outside the umbrella,
  or an unlanded child aborts non-zero with the path named.
- A single install that never promotes stays byte-identical.
- Must be asserted in `tests/test_install.sh` (installer-wiring lesson).

## Open questions
- Coordinator conversion: does the promoted root keep its own `state/tasks.json` as the
  umbrella board (draft epics from `/sdd-plan` live there) — how do slices map to it?
- Should promotion refuse when the working tree is dirty, given the landing audit?
