# Intent — Installer agent picker: arrow-key + spacebar checkbox UI

## Problem / who
A human running `harness-install.sh` on an interactive TTY hits `toggle_select`
(harness-install.sh ~L267-320), today a **numbered** list: you read the entries,
type space/comma-separated numbers, then a blank line to confirm. Users naturally
expect a checkbox UI — move the cursor with ↑/↓ and toggle the highlighted entry
with the **spacebar** — and report that the numbered model is awkward and not
discoverable (you can't move up and hit space to select/unselect).

## Success outcome
On a raw-capable interactive TTY, the agent picker shows the four agent keys
(`claude gemini opencode antigravity`) as a cursor-driven checkbox list:
- ↑/↓ (and ideally `k`/`j`) move a `>` cursor between rows,
- **Space** toggles the highlighted row's `[x]`/`[ ]`,
- **Enter** confirms the current selection and returns it.
Pre-check state still seeds from the saved `.harness/.agents` set (or ALL on a
fresh install), exactly as the numbered version does today.

## Scope / boundaries
- In scope: a new cursor/spacebar interaction for the interactive-TTY branch only,
  plus a clean **graceful fallback** to the existing numbered `toggle_select` when
  raw terminal mode is unavailable.
- Out of scope: the `--agents=`/`HARNESS_AGENTS=` override path, the non-TTY
  "ALL agents" default, the `.harness/.agents` persistence format, and the set of
  selectable agent keys — none of these change.

## Chosen options
- Arrow-key + spacebar TUI (↑/↓ move · Space toggle · Enter confirm), with a
  graceful fallback to the current numbered list when raw mode is unavailable or
  stdin is not an interactive TTY.

## Constraints
- Stay portable / POSIX-sh — no new binary dependencies. Use `stty` for raw mode
  with a guaranteed restore (trap/`stty sane`/saved settings) so a quit or Ctrl-C
  never leaves the user's terminal in raw mode.
- Detect raw-mode capability and **fall back** to numbered `toggle_select` (and the
  no-TTY ALL default) when it's not available — never hard-fail the install.
- All prompts/UI to **stderr**; stdout stays purely the resolved selection
  (one key per line, normalized) so the captured `SELECTED` contract is unchanged.
- The resolved set, fallback path, override path, and persistence must remain
  behaviorally identical to today — only the interactive presentation changes.

## How to verify
- The numbered fallback still works in non-interactive / piped contexts: existing
  `tests/test_install.sh` (driven via `--agents=`/`HARNESS_AGENTS=` and no-TTY)
  must stay green unchanged — the harness test suite in
  `verification.test_command` passes.
- Manual smoke on a real TTY: run the installer, confirm ↑/↓ moves the cursor,
  Space toggles `[x]`/`[ ]`, Enter confirms, and the persisted `.harness/.agents`
  matches the on-screen checks. Ctrl-C / quit restores the terminal (no stuck raw
  mode).

## Open questions
- Exact key bytes to accept beyond ↑/↓ + Space + Enter (e.g. `k`/`j` vim keys,
  `q`/Esc to abort) — Builder's judgment, keep it minimal.
