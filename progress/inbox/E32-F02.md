# Intent — tools/harness-report.sh: redaction pass, versioned body marker, duplicate search, per-session cap, progress/ fallback

## Problem / who
The act of filing must be deterministic and testable, because it is automatic and privacy-sensitive; prompts decide *when*, this tool decides *how*.

## Success outcome
One tool takes a structured report and: exits 0 without filing when `feedback.enabled` is false; builds the upstream body **only from allow-listed structured fields** — trigger enum, harness `VERSION`, host, role, phase, harness-owned file paths (each validated against `tools/harness-owned-paths.sh`; anything else dropped), harness command name, exit code, and a fixed-vocabulary symptom code — and rejects any field value outside its allow-list; derives the issue **title** and any duplicate-search query sent to GitHub **exclusively** from the same allow-listed categorical fields (fixed format `[harness-feedback] <trigger> <symptom-code> in <harness-file>`), so free-form text never appears in the title or search query; keeps any free-form text (summary, expected vs observed) **only** in the local `progress/feedback/` copy, never upstream; still runs the redaction pass (secrets/tokens/emails/absolute paths) on the assembled body as defense in depth; stamps the versioned marker (ADR-0006 — this spec defines its grammar); searches open issues on `feedback.repo` and skips on a duplicate (no comment); enforces `feedback.max_per_session`; falls back to `progress/feedback/<timestamp>.md` when `gh` is missing/unauthenticated/fails. It never exits non-zero in a way that fails the caller's task.

## Scope / boundaries
In: the tool, marker grammar, MINOR `VERSION` bump (new installed tool), redaction corpus + fixture tests with a stubbed `gh`. Out: triggers/prompts (F03), labels (F04).

## Chosen options
- Filing is automatic, no human confirmation (user decision).
- Duplicate ⇒ no new issue, no comment.
- Fallback reports stay local, no auto-retry.

## Constraints
- Epic contract: `specs/epics/E32-feedback-loop/epic.md` (success criteria are binding).
- POSIX sh like the rest of `tools/` (or python3 stdlib — `init.sh` already requires python3).
- Never includes project source or any free-form text upstream: every transmitted field (title, body, search query) is derived exclusively from the allow-listed fields above, so privacy does not depend on redaction recognizing arbitrary project text (redaction is a second layer, not the guarantee).
- Tests never hit the real GitHub API.
- ADRs to honor: ADR-0006, ADR-0004.

## Open questions
- Duplicate matching key: resolved — the key is built only from the allow-listed categorical fields (the fixed-format title / marker fields), never from free-form text; the spec picks which of those fields participate.
- The symptom-code vocabulary (fixed enum; the drill/spec names it).
- How the per-session cap is counted (session id source). Only the session-owning top-level role calls the tool (drill decision), so there are no concurrent writers.
