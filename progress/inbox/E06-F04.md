# Intent — Architect contract: `architecture.md` mandatory input, specs cite ADRs

## Problem / who
For the harness maintainer and every consumer repo: F02 (`/sdd-plan`) now produces
`specs/architecture.md` + `specs/adr/NNNN-*.md`, and F03 (`/sdd-drill`) records, in
each feature's inbox brief, the `ADR-NNNN` ids that feature must honor (the F03-D7
hook). But the **Architect's contract still ignores all of it**: when it writes a
feature's 4-file spec it reads only the inbox brief, never `architecture.md`/the
ADRs, and the spec never cites the decisions it touches. So the durable design
artifacts the planning tier produces are write-only — nothing downstream consumes
them. That is exactly the gap epic E06 set out to close: *"specs written after
inception cite the architecture decisions they touch; 'we lacked the whole picture'
refactors stop recurring."* This feature makes the Architect **consume** the
architecture, closing the loop F02/F03 opened.

## Success outcome
- The **Architect's contract (`agents/architect.md`)** requires, when writing a
  feature spec, reading `specs/architecture.md` and the relevant
  `specs/adr/NNNN-*.md` as a **mandatory input** (alongside the inbox brief) —
  whenever those artifacts exist.
- Every feature spec **cites the `ADR-NNNN` ids it touches** and states how it
  honors (or, if it must diverge, how it departs from) each — surfaced in a defined
  place in the spec, fed by the ids the F03 inbox brief already lists.
- The contract **degrades gracefully** for legacy repos that never ran `/sdd-plan`
  (no `architecture.md`, no `adr/`): the Architect notes their absence and proceeds —
  no failure, no fabricated citations. Existing specs without ADR citations remain
  valid.
- The **Reviewer** can confirm the citation is present and coherent for features
  that have architecture artifacts to cite (a check it can actually run), without
  blocking legacy/no-architecture features.
- The change is documented (`docs/SPEC-FORMAT.md`, `docs/WORKFLOW.md`, the
  `specs/_templates/feature.spec.md` template) and carries one MINOR `VERSION` bump.

## Scope / boundaries
**In scope:**
- Amend `agents/architect.md`: add `specs/architecture.md` + `specs/adr/*` to "Read
  these first" as mandatory-when-present input, and require the spec to cite the
  ADR ids it touches (consuming the ids the F03 brief records).
- Add an **ADR-citation section** to the `specs/_templates/feature.spec.md` template
  (e.g. "## Architecture alignment" / "ADRs touched") with a defined shape so the
  citation lands in a consistent, checkable place.
- A minimal, additive Reviewer clause (`agents/reviewer.md`) so the citation is
  verified for features that have architecture artifacts — without blocking
  no-architecture features.
- Docs: `docs/SPEC-FORMAT.md` (the new section + the cite-your-ADRs rule),
  `docs/WORKFLOW.md` (where the contract sits relative to `/sdd-plan`/`/sdd-drill`),
  README if it lists the SDD contract.
- Tests (`tests/test_architect_adr.sh` or fold into an existing suite) wired into
  `harness.config.yaml`, plus one MINOR `VERSION` bump + `CHANGELOG.md`.

**Out of scope:**
- F06 (drift check on epic rollup) — separate feature.
- Changing `/sdd-plan` (F02) or `/sdd-drill` (F03), the ADR file format/numbering,
  or `architecture.md`'s shape — F04 only makes the Architect/Reviewer **consume**
  them.
- Retro-fitting ADR citations onto already-written specs (E00–E05, E06-F01..F03/F05).
  The contract applies to specs written **after** this lands; old specs stay valid.
- Any TaskStore schema change (citation lives in the spec markdown, not the store).
- Auto-generating or validating the *content* of ADRs (this is about citing ids,
  not checking the decision is correct).

## Chosen options
- **Consume, don't reshape:** F04 changes only how the Architect (and Reviewer) read
  and reference the F02/F03 artifacts; it touches no producer.
- **Mandatory-when-present, graceful-when-absent:** architecture.md/ADRs are required
  input when they exist; their absence is a documented, non-failing path for legacy
  repos (preserves backward compatibility — the harness pillar).
- **Reuse the F03-D7 hook:** the Architect reads the touched `ADR-NNNN` ids the
  drill-down already recorded in the inbox brief, rather than re-deriving them.
- Additive change ⇒ MINOR bump, per repo versioning policy.

## Constraints
- **Backward compatible / additive:** repos without `specs/architecture.md` behave
  exactly as today; no existing spec is invalidated; `/sdd-new`'s altitude-3 flow
  (which doesn't produce architecture.md) still works.
- **Portability pillar:** the contract lives in the role files + docs/templates
  (portable across AGENTS.md CLIs), not in `.claude/` glue.
- Per the permanent-suite anti-pattern memory: new tests must not freeze the exact
  `VERSION` value or diff DO-NOT-TOUCH files against `main`; any fixture includes the
  required root `project` field and uses a temp store.
- Coordinate with E06-F05 (in-flight): F05 also edits `agents/reviewer.md` and
  `docs/WORKFLOW.md` additively — keep F04's edits to those files additive and
  non-overlapping so the branches merge cleanly.

## Open questions
- **Citation placement:** a dedicated `## Architecture alignment` section listing
  `ADR-NNNN` + a one-line "how this honors it", versus inline per-requirement ADR
  tags, versus citing in `plan.md` (the technical file) instead of/in addition to
  `spec.md`. Which is most checkable and least noisy?
- **Enforcement strength:** does the Architect *fail/stop* if `architecture.md`
  exists but the brief lists no touched ADRs (is "touches no decision" a legitimate
  state, explicitly recorded as "ADRs touched: none"), or is the section optional
  when genuinely nothing applies?
- **Reviewer strictness:** is a missing citation (when architecture artifacts exist)
  a hard reject or a "suspected"/soft flag? How does the Reviewer tell "legitimately
  touches no ADR" from "forgot to cite"?
- **Legacy detection:** how exactly does the Architect decide architecture.md is
  "absent" vs "present" — file existence only, or also an empty/template-only file?
- **Umbrella/shared-contract specs:** do cross-repo shared `.spec`/`.plan` and their
  slices also cite ADRs, or is that out of scope for this feature?
- **Divergence path:** when a feature must intentionally depart from an ADR, does
  F04 just require it be *stated* in the spec, or does it (out of scope?) hand off to
  an ADR-delta via `/sdd-drill`? (Likely: state it; deltas remain F03's job.)
