# Intent — Refuse ambiguous sweep config keys and malformed feature IDs

## Problem / who
Issue #237 identifies two fail-open checks in `tools/sweep-scratch.sh`: escaped double-quoted YAML keys can hide a non-local TaskStore backend, and a feature ID ending in a newline passes the current regex. An operator using `--apply` must not delete scratch based on a stale local board or malformed IDs.

## Intended fix
Refuse escaped double-quoted mapping keys at the document top level and directly under `store:` before assuming a local backend; leave unrelated nested keys alone. Require a full feature ID match. Keep the existing parser and fail-closed behavior otherwise. Follow `progress/issue-triage/approved-design.md` and `plan-237.md`.

## How to verify
Add disposable-repository `--apply` fixtures for escaped `store` and `tasks` keys and a final-newline feature ID beside a valid `done` feature. Each unsafe fixture must fail without classifying or deleting scratch; an unrelated escaped key must leave ordinary local behavior working. Run the focused suite, `./init.sh`, and configured verification. Obtain independent Reviewer approval before a PR.
