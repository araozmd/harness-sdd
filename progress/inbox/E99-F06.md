# Installer: keep `.harness/progress/` run dirs out of the consumer's VCS

## Why this exists
The harness source ignores its own run dirs — `.gitignore:2` is `progress/*/`, with
`progress/.gitkeep`, `progress/README.md` and `progress/inbox/**` re-included. That ignore is
**not propagated to consumers**. The installer seeds a targeted `.harness/.gitignore`
(`harness-install.sh`, the `_ignores` block) covering `telemetry.jsonl`, `jira.pat`,
`state/tasks.json.lock` and `.pr-loop/` — but not `progress/*/`.

So in an installed target every agent run dir is committable, and in practice gets committed.
On `viernes-bookings-api` PR #76 the diff carried:

```
262  .harness/progress/PR76-round-11/build.md
213  .harness/progress/PR76-round-12/build.md
 99  .harness/progress/PR76-round-11/review.md
 91  .harness/progress/PR76-round-12/review.md
 67  .harness/progress/PR76-round-12/builder-brief.md
 62  .harness/progress/PR76-round-11/builder-brief.md
```

796 lines — 5% of that PR's additions — of per-round agent scratch shipped inside the product
diff and re-read by the reviewer on every one of twelve rounds.

## What to change
Add `progress/*/` to the installer's seeded `.harness/.gitignore`, keeping the same
re-inclusion shape the source `.gitignore` uses so the parts that **are** durable state stay
tracked:

- ignore `progress/*/` (run dirs)
- keep `progress/inbox/` and `progress/inbox/**` — the per-feature briefs the Architect reads
  just-in-time are real, shared, must-be-committed artifacts
- keep `progress/README.md` and `progress/.gitkeep`

Mirror it into `tests/test_install.sh` as an assertion, both for a fresh install (file seeded
with the pattern) and for the append path (existing `.harness/.gitignore` gains the pattern
without losing what is already there).

## Constraints
- **The append path must stay append-only.** The existing block appends any missing pattern to
  a pre-existing `.harness/.gitignore` and must never clobber a target's own additions.
- Ordering matters in a `.gitignore`: the re-inclusion lines have to follow the ignore line, or
  `progress/inbox/**` stays ignored. Assert the resulting behavior, not just the presence of
  the strings — `git check-ignore` is the honest test.
- A file **already tracked** is unaffected by a new ignore rule. Note in the fix that an
  existing target must `git rm -r --cached .harness/progress/<run-dir>` once; the installer
  must not do this itself, since untracking files in someone's repo is not an installer's call.
- `harness-install.sh` and `tests/test_install.sh` are built-in immutable paths for the fix
  lane — this fix edits both by design, so it must run as an ordinary `/sdd-fix`, not through
  the parallel lane's shared-path allowance.
- Do not freeze an exact VERSION or diff DO-NOT-TOUCH files against `main` in the added test.

## Not in scope
- Retro-untracking anything in any target repo.
- The `.harness/progress/` layout itself, or what agents write there.
