# Intent — Greenfield single-repo path: install into an empty dir, then /sdd-plan

## Problem / who
The harness owner starting a NEW product today opens a clean Claude session in an empty
folder and hand-prompts the repo layout before the harness exists. The single-repo
greenfield path already works (v0.78.1 installs into an empty, non-git dir without
complaint, and `/sdd-plan` is the brainstorm), but nothing documents it as the front door
and nothing tests it, so it is not trusted and gets bypassed.

## Success outcome
`docs/INSTALL.md` has a "Starting from nothing" section that says: make an empty dir,
run the installer, `git init` (or let the human do it), run `/sdd-plan`, then `/sdd-drill`.
A test in `tests/` installs into an empty non-git directory and asserts a usable layout
(AGENTS.md, .harness/, seeded board, `/sdd-plan` command present) and that `init.sh`
passes there. The existing "Bootstrap (first run)" section is reconciled so there is ONE
story (E00-F01 bootstrap task vs `/sdd-plan`), not two competing ones.

## Scope / boundaries
- IN: docs + tests for the existing behavior; any tiny installer message tweak needed so the
  "Next steps" banner points a greenfield target at `/sdd-plan`.
- OUT: any topology decision, any umbrella creation, any new command (those are F02/F03).

## Chosen options
- The front door for a new product is "install first, plan second" — NOT a pre-harness
  brainstorm. Rationale: never accrete a second intake (docs/RATIONALE.md #2).
- Always start single-repo; the plan earns the topology later (float, don't pin).

## Constraints
- Zero new interactive prompts. Ablation doctrine applies: code over prose, structural over
  compliance.
- Must not change single-target install behavior beyond the banner text.
- Tests must not freeze the exact VERSION (see progress/lessons.md).

## Open questions
- Should the installer `git init` an empty non-git target itself, or only tell the human?
  (The landing audit needs a repo; today "no git" is tolerated for the coordinator only.)
- Where does the E00-F01 bootstrap task sit relative to `/sdd-plan` on a greenfield target —
  keep both, or make E00-F01 point at `/sdd-plan`?
