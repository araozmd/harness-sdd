# Intent — Test-assertion drift check across the feature branch: tool + Reviewer gate

## Problem / who
The Reviewer catches a deleted or commented-out test because the R-id then has no passing
test. It does not catch a test whose assertion was weakened so it still passes: this repo's
own history records weak assertions slipping through three times (assertion reachable by
another path; surviving mutations). The operator attributes the absence of tampering to
strong models; the ablation doctrine says measure, do not assume. With E36-F01 every R-id's
test goes GREEN at a pair commit, which gives a baseline to diff against. ADR-0008's
consequence names this check.

## Success outcome
- `tools/test-drift-check.sh <base-ref> [<head-ref>] [--tests-md <feature.tests.md>]` lists,
  for every test file touched between the refs (test paths classified by the same
  `change_size.test_paths` + built-in patterns the pre-PR check uses), each removed or
  modified assertion line, each newly added skip/only/xfail marker, and each test name
  present at base and absent at head. Assertion patterns: a built-in list (`assert`,
  `expect(`, `t.is`, `t.ok`, `fail(`, plus the harness suites' own `ok`/`fail` helper calls)
  extended by a new `change_size.assert_patterns` list; no bare `[ ... ]` or `should`
  matching, which would flag ordinary sh edits. Any modified or removed assertion fails the
  check unless waived — the tool does not try to judge whether a change tightened or
  weakened it. Exit non-zero when anything is found; exit 0 with one summary line otherwise.
  Pure additions never fail it.
- The Reviewer runs it with base = the feature branch's merge-base with main and, when
  pair commits exist (E36-F01), additionally per pair commit → head; a non-zero exit is a
  REJECT unless `.tasks.md` carries a waiver line `waive-test-drift: <exact test name> — <reason>`
  for that test (exact-match, one per test).
- `sh tools/run-tests.sh` stays the Reviewer's primary command; this is an added check.
- Installer ships the tool; `tests/test_install.sh` asserts it; a suite covers: no test
  change, weakened assert, deleted test, added skip, legitimate addition, and a tasks.md
  waiver.

## Scope / boundaries
In scope: the tool (POSIX sh + git + awk, like the suites), Reviewer prose, installer wiring,
tests, docs/RATIONALE.md control row (durable: verification constant). Out of scope: mutation
testing; judging assertion *strength*; pr-fixer changes.

## Chosen options
- Diff-based, not AST-based: cheap, language-agnostic, good enough to force a human look.
- Waiver lives in `.tasks.md`, the Builder's only worklist, so it is reviewed where it is made.

## Constraints
- Honor ADR-0008. No hard dependency on E36-F01: pair commits, when present, are used as
  finer-grained baselines; the merge-base mode is the contract.
- Runs under dash; no GNU-only flags (BSD grep on this box).

## Open questions
- None blocking (the "tightened" question is resolved above: report and fail unless waived).
