# Intent — mutation evidence must be the LITERAL edit the contract names

## Problem
On E14-F08 a mutation runner entry LABELLED as the contract's `InlineError` mutation
applied a DIFFERENT edit; the mislabeled mutant went red under the contract's title and
certified an assertion that could NOT detect the real defect. A broken assertion passed
review — label-vs-evidence. (The finding's part 2 — the ad-hoc severity classifier —
already shipped as `wait-for-codex.sh classify` in v0.69.0; note it, do not re-fix.)

## Intended fix
Harden agents/reviewer.md's mutation checks (§3b/3c region): a mutation counts as
evidence ONLY when the applied edit is byte-for-byte the edit the contract names, and
the runner MUST print the applied diff (`diff <file>.mutbak <file>` or equivalent) into
the run record so label and evidence can be compared; a mutant whose printed diff does
not match its label is an instrument failure, recorded as such, never as a kill.
Pin the new contract in tests/test_reviewer_mutation_mandate.sh (section-scoped,
fence-aware, two-token anchored — per the F75 convention).

## How to verify
Revert the reviewer.md addition in place → the new pin goes red naming it; restore.
Full: sh tools/run-tests.sh --jobs 8.
