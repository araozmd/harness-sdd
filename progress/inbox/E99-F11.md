# Intent — Landing audit: match git-quoted paths

## Problem / who
Filed from PR #103 round 6 (P2). The E24-F02 landing audit subtracts the harness's own
deliberate ignores from git's ignored set, and builds the subtraction pattern for the
configurable `telemetry.log` from the config value.

When that override contains **whitespace** (`log: "custom/my log.jsonl"`),
`git status --porcelain --ignored=matching` returns the path in git's **quoted** form —
`".harness/custom/my log.jsonl"`, with surrounding double quotes — which the generated ERE
does not match. The path is therefore not subtracted, and the target reports
`no vcs (cannot verify)` permanently: the audit never runs there again.

## Verified
Reproduced end to end: install, set `log: "custom/my log.jsonl"`, re-run so `install_one`
seeds the ignore, create the file, commit everything, re-run the cascade → `no vcs`.

**It fails safe.** The audit under-claims (`cannot verify`) rather than over-claiming
(`landed`), so it cannot produce the false clean E24-F02 exists to prevent. That is why it
was filed rather than fixed in a seventh review round.

## Success outcome
A target whose `telemetry.log` override contains whitespace is audited normally.

## Scope / boundaries
`tools/harness-owned-paths.sh` and the audit block in `harness-install.sh`. No change to
what the audit checks, to its exit codes, or to `init.sh`.

## Constraints
- The fix must handle git's quoting rules, not just spaces: git also quotes paths containing
  non-ASCII bytes, backslashes and control characters, and escapes them C-style inside the
  quotes. `core.quotePath` affects this too. Prefer `-z` (NUL-delimited, never quoted) over
  un-quoting by hand — `git status --porcelain -z` emits raw paths, which sidesteps the
  entire quoting grammar rather than reimplementing it.
- Keep the existing regression cases green; add one whose fixture **asserts** the override
  really is ignored and really does contain whitespace (unasserted fixture preconditions
  produced three green-but-empty cases while E24-F02 was being written).
- `VERSION` PATCH; `harness-install.sh` and `tools/` are installed body.

## Open questions
- Does `-z` interact with the `set --` pathspec expansion the audit already uses? It changes
  the output delimiter, not the input, so probably not — but check before assuming.
- Worth applying the same `-z` treatment to the count query for consistency, or is that
  scope creep? The count only needs a line total, which quoting does not affect.
