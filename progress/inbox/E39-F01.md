# Intent — Docs for humans: docs/agents/ machine layer, diagrams, logo, concise guides

## Problem / who
Two audiences read the same docs today:
- **Humans** (people evaluating, installing, upgrading and operating the harness) drown in
  agent-contract detail.
- **Agents and tests** need that detail kept exactly as it is.

The README is 544 lines and `docs/` about 4,000 lines (INSTALL 1,450, WORKFLOW 1,140,
UMBRELLA 485, SPEC-FORMAT 248, RATIONALE 181, CONFIG-LAYERING 117, HARNESS 122, ABLATION 87,
BASELINE-0.78.1 51). The prose has accumulated AI filler: restated hedges, "this is
important because" padding, incident archaeology in user-facing text, and the same rule
explained three times.

## Success outcome
- **README:** reads in under five minutes and holds the logo, what the harness is, why it
  works (one diagram of the spec → build → review loop with its gates), a 3-step
  quickstart, and links.
- **Human docs:** each one is short, plain and skimmable, with Mermaid diagrams wherever a
  flow, state machine or structure is described.
- **`docs/agents/` (for machines):** holds the exact contracts (exit codes, env vars, edge
  cases, precedence, incident-driven rules) moved verbatim. Every test and role prompt
  that cited a doc still resolves.

## Observable behavior
Files: a rewritten `README.md`, rewritten human `docs/*.md`, and a new `docs/agents/*.md`
layer. The layer is announced at the top of `docs/agents/README.md` as "for agents —
exact contracts; humans start at docs/". It ships to consumers with the rest of `docs/`.
Also new: `assets/logo.svg`, already placed by Inception from the human's pick, plus
optional hero art.

## Scope / boundaries
In scope:
- `README.md` and every file in `docs/`.
- New `docs/CONCEPTS.md`, the human explanation of the method: specs (EARS, 4-file
  spec), the role loop, gates, code-over-prose / ablation, and the Elephant–Goldfish
  review principle adopted in E37.
- New `docs/agents/`: the machine layer, contract text moved verbatim.
- Mermaid diagrams, embedded in markdown (GitHub renders them, and they diff with the
  text). At least these:
  - the role loop with its status states;
  - install single-repo vs umbrella cascade;
  - the upgrade flow (E38 update check);
  - the PR review loop.
- `assets/logo.svg` (done) and at most 1–2 Recraft hero/illustration images for the
  README or CONCEPTS. Generate them with the Recraft MCP (vector, matching palette:
  indigo #1F0A5C-ish + coral #FF6047-ish).
- Re-pointing every test assertion and every role-prompt citation (`agents/*.md`,
  `AGENTS.md`, `CLAUDE.md`, installer comments that cite docs sections) to the moved text.

Out of scope:
- Rewriting `agents/*.md` role prompts or `AGENTS.md`. They already are the machine
  layer; only their doc citations get updated.
- Renaming the product, `.harness/`, `harness-install.sh` or any installed path.
- A docs website or generator.
- Changing behavior.

## Chosen options
- **Split:** a separate `docs/agents/` directory as the "for machines" section, chosen
  over in-file "For agents" sections and over trimming in place.
- **Scope:** README plus all of `docs/`.
- **Diagrams:** Mermaid for flows and structures; Recraft only for the logo and 1–2 hero
  images.
- **Logo:** abstract triangle loop (#3), not the elephant + goldfish. The human does not
  want to look like they are borrowing an external named concept. Placed at
  `assets/logo.svg`.

## Constraints
- **Stage:** production.
- **No contract lost.** Move behavioral sentences, never paraphrase them: 54 test files
  grep these docs for pinned phrases. Prefer re-pointing a test's path to the moved
  verbatim text over editing the assertion. Where a human doc keeps a short plain-language
  version of a rule, the exact text lives in `docs/agents/` and the test points there.
- **Prose assertions** must stay anchored two-token checks and must FAIL on a mutated
  file, per the house test-authoring convention. Don't weaken any assertion to make it
  pass.
- **Tests must not** freeze VERSION or diff DO-NOT-TOUCH files against main.
- `docs/` ships in the installed body (HARNESS_BODY_PROSE), so `docs/agents/` and
  `assets/` must install correctly. Decide whether `assets/` ships (probably not, since
  it's repo-only branding) and keep the README image path working on GitHub. Bump
  VERSION MINOR because the installed body changes.
- **Brand name** is undecided. Keep it a single substitutable token in the README title
  and wordmark. The logo SVG has no text.
- **Change size:** about 4,500 lines touched will exceed `change_size` advise
  thresholds. Slice it into reviewable PRs, for example:
  - F01: README + CONCEPTS + logo + `docs/agents/` scaffold;
  - F02: INSTALL;
  - F03: WORKFLOW;
  - F04: the remaining docs.
- **Machine limits:** one test run at a time, `--jobs 4` at most.
