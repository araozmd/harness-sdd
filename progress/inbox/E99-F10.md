# Intent — Drift guard follow-ups (PR #98 round-3 P2s)

## Problem / who
Three findings landed on PR #98 round 3, all P2, all against the E24-F01 drift guard in
`init.sh`. `pr_loop.blocking_severities` is `P0,P1`, rounds 2 and 3 both returned zero
blocking findings, and the merge gate said `merge` — so they were filed rather than fixed
in a fourth round that would have extended a review that had already converged twice.

The user is anyone running the guard: two of these degrade the diagnostic, and one halts
the harness on a legitimate file.

## The three findings

**1. `.codex/agents/` is a shared namespace — this is the one that matters.**
`harness-install.sh:2624-2675` describes `.codex/agents/` as shared with the operator and
explicitly preserves foreign or edited role files, using last-written ownership stamps
under `.harness/.model-agents/codex/`. The guard's directory-wide pathspec claims all of
it, so a project's own `.codex/agents/project-role.toml` fails the **mandatory** gate and
halts every agent step. Reproduced by Codex on a real Codex target.

This is the same false-positive class the round-2 narrowing fixed for `.agents/` — the
narrowing simply did not cover `.codex/`. It is the risk E24-F01's own spec named as
dominant. Fix it the same way: claim only what the installer owns. Unlike `.agents/`,
there is an ownership ledger available (`.harness/.model-agents/codex/`), so the choice is
between enumerating the six generated role filenames and consulting the stamps — pick
whichever does not duplicate installer knowledge into `init.sh`, which is the constraint
that shaped the original pathspec design.

**2. SIGPIPE while capping the drift sample.**
`printf '%s\n' "$DRIFT" | head -n 10` under `set -euo pipefail`: when the porcelain output
exceeds the pipe buffer, `head` closes its input, `printf` dies with 141, `pipefail`
propagates it and `set -e` aborts — *before* the elision count, the recovery command, or
the `fail()` diagnostic print. Reproduced with 1,800 long-named untracked files: `init.sh`
exited 141 with no message.

The gate still fails closed, which is why this is not urgent — it just fails
uninformatively at exactly the moment the operator most needs the diagnostic (a very large
unlanded drift). Cap without an early-closing pipeline.

**3. `$PROJECT_ROOT` is unquoted in the recovery command.**
On a repo path containing whitespace the printed command cannot be pasted and run — git
receives only the first word as `-C`. The pathspec arguments are already quoted; the root
is not. Cosmetic, but the command exists solely to be copied.

## Success outcome
A project's own `.codex/agents/*.toml` never trips the gate; a very large drift prints its
diagnostic instead of dying at 141; the recovery command survives a path with spaces.

## Scope / boundaries
`init.sh`'s drift-guard block and `tests/test_init_drift_guard.sh` only. No installer
change, no change to what the guard checks under `.harness/`, and no revisiting of the
E24-F01 requirements — these are defects against the shipped R2/R3/R4/R5, not new
behavior.

## Constraints
- `sdd: false` — this is the fix lane, not a re-spec. Three targeted fixes, one PR.
- Each fix gets a first-class regression case with its **fixture preconditions asserted**,
  matching the existing suite's discipline (an assertion whose expected value has a second
  producing path proves nothing).
- The suite must keep passing under `dash` — `/bin/sh` is dash on Ubuntu CI, and the whole
  round-1 P1 was this exact portability trap.
- `VERSION` PATCH bump; `init.sh` is installed body.

## Open questions
- For finding 1: enumerate the six generated Codex role filenames, or read the ownership
  stamps under `.harness/.model-agents/codex/`? The stamps are authoritative and avoid
  duplicating installer knowledge into `init.sh`, but they add a filesystem read to the
  hot path. Prefer the stamps if the cost is negligible.
- Is there a fourth instance of the same over-claim? `.gemini/agents/` was added in the
  same breath as `.codex/agents/` and has not been audited against its installer section.
  Check it as part of this fix rather than discovering it in a later review round.
