# Intent — Derived waves and critical path: `next-task --waves` + Driller report

## Problem / who
The operator re-types "build this in waves, critical path first, fan the rest out" into
every session and hand-picks which features to run on which machine. The information is
already on the board as `depends_on`, but only the deterministic selector consumes it, one
feature at a time. ADR-0010 decides waves are a projection, never stored; this feature ships
the projection and surfaces it where the roadmap is born (the Driller's report).

## Success outcome
- `node tools/next-task.mjs --waves [--json] [--epic E##]` prints wave 1..N. Definition (shared
  verbatim with ADR-0010 and E36-F07): `done` features are wave 0; wave N is the set of
  non-done features whose every dependency is in a wave below N; a feature with no
  dependencies is wave 1. Parked and gated features stay in their wave but are shown with
  their reason codes from task-diagnostics, so the view explains why something is not
  runnable. `--waves` and `--epic` are two new `parseArgs` flags (unknown arguments throw
  today); `--waves` is mutually exclusive with `--feature` and `--mine`, and `--epic`
  requires `--waves`. It also prints the critical path (longest chain by feature count, ties by
  ADR-0001 order) and marks which wave-1 features are `autonomous: true`.
- A cycle or a dangling `depends_on` reuses the existing cycle-witness / reason-code output;
  the tool never invents a wave for an invalid graph.
- `agents/driller.md` ends its report with the `--waves --epic <id>` output for the epic it
  seeded; `.claude/commands/sdd-drill.md` says so through its emitter.
- docs/WORKFLOW.md gains "Running in waves and across machines": read the wave, run
  `/sdd-next <id>` per machine from wave 1, or `--mine` with `owner`; states the known
  limitation that bare `/sdd-next` on identical boards picks the same feature.
- Tests: fixtures with a linear chain, a diamond, two independent components, a cycle; JSON
  output asserted field by field.

## Scope / boundaries
In scope: `tools/next-task.mjs` (one new function + two flags), `tools/task-diagnostics.py` only
if a reason code is missing, driller prose + sdd-drill emitter, docs, tests, installer
assertion of the flag's help text. Out of scope: spawning anything (E36-F07); any board write;
a lease/claim field (ADR-0010 non-goal).

## Chosen options
- Extend `next-task.mjs` rather than a new tool: one selector, one graph validator (ADR-0001).
- Human output is a table per wave; `--json` is the contract tests assert.

## Constraints
- Honor ADR-0001 and ADR-0010. No new state on the board.
- `node` is already a harness dependency for next-task; add none.

## Open questions
- Whether `--waves` should default to the whole board or require `--epic` — proposal: whole
  board, `--epic` filters.
