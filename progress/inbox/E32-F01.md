# Intent — feedback.* config block seeded on fresh install and upgrade, with the one-line opt-out notice

## Problem / who
Installed harnesses need a single, visible switch for automatic upstream reporting. Users: operators of every target repo.

## Success outcome
`harness.config.yaml` carries `feedback: { enabled: true, repo: araozmd/harness-sdd, max_per_session: 3 }` on a fresh install; an upgrade of an install lacking the block seeds it identically; both print one line naming the repo and how to disable. `enabled: false` is honored by every consumer.

## Scope / boundaries
In: config block, installer seeding (fresh + upgrade), notice, config docs (`docs/INSTALL.md`, `docs/CONFIG-LAYERING.md` as relevant), MINOR `VERSION` bump + CHANGELOG. Reporting only goes live with F03, so the notice is accurate but inert until then. Out: the reporter itself (F02), prompts (F03).

## Chosen options
- Default ON (user decision 2026-09-25), with the notice as the transparency mechanism.
- Cap default: `max_per_session: 3` (drill decision).

## Constraints
- Epic contract: `specs/epics/E32-feedback-loop/epic.md` (success criteria are binding).
- An existing operator-edited `feedback` block is never overwritten on upgrade.
- Honors E20/E26 config-merge conventions; this source repo also gets the block via `--self`.
- ADRs to honor: ADR-0004.

## Open questions
- How the block resolves for an umbrella child (ADR-0004), child-local vs root config. **This feature owns the answer**, including where F02's `progress/feedback/` fallback lives for a child.
- Where the upgrade notice prints (installer stdout vs cascade summary).
