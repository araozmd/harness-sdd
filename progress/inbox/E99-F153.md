# Intent — `wait-for-codex.sh` exit 5 conflates faults with opposite remedies

## Problem / who

`preflight` returns **exit 5** for at least five unrelated conditions, including two
whose remedies point in opposite directions:

- **the Codex GitHub App is absent / unauthorized** → install or authorize it, or accept
  manual review and set `pr_loop.enabled: false` so the loop stops stranding PRs.
- **the repo slug is unresolvable** → you are in the wrong directory; re-run from the
  child repo, not the umbrella root.

Same number, opposite fixes, distinguishable only by reading the message text — and the
message is on stderr, which the caller's `case "$rc"` never sees. The second case is not
hypothetical: running a pr-loop step from an umbrella root has bitten the viernes project
repeatedly, and it is the most likely cause of the incident that produced the original
item. The wrong diagnosis IS the argument: an ambiguous code sent a real project chasing
an App-installation problem it did not have, and the item then sat on a board for five
days on a false premise.

## Intended fix

Split the preflight failures into distinct exit codes (App/auth vs. environment vs.
usage), keep `5` meaning what the `/sdd-pr-loop` body already documents so no installed
consumer's `case` arm silently changes meaning, and give each arm a remedy sentence
naming its own fix. Update the exit-code table in the command body and `docs/INSTALL.md`
in the same change.

## How to verify

`tests/test_pr_loop.sh` gains one case per split arm, driving the real preflight against
a fixture that reproduces each fault, asserting the code AND that the message names the
matching remedy. Mutation: collapse two arms back to a shared code → the new cases fail.

## One trap the fix's own tests must carry

Codex's bot identity is spelled **two** ways: `chatgpt-codex-connector[bot]` from REST,
`chatgpt-codex-connector` from GraphQL. Three separate attempts to survey App presence
returned a confident "0 for all six repos" — including one proven to have activity —
by matching the unsuffixed name by equality. Accept exactly the two literals (this repo
already does, in the watcher); never prefix-match, which would let
`chatgpt-codex-connector-evil` pass as the bot.
