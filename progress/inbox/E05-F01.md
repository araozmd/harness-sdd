# Intent — Reviewer cross-file consistency + explicit build↔review rounds

## Problem / who
The in-loop Reviewer (`agents/reviewer.md`) serves the Orchestrator's `in-review`
phase. In real use it missed several consistency defects that an independent external
reviewer (Codex) caught on PR #10 — e.g. a new dispatch step in `orchestrator.md` that
violated a precondition (`status: in-progress`, "Builder never opens a PR") declared in
the *unchanged* `builder.md`. Root cause: the Reviewer is handed only the curated
feature files and anchors on tests passing, so a prose/contract contradiction between a
changed file and the un-changed file it invokes produces no failing test and is never
inspected. The user (harness maintainer) wants the in-loop Reviewer to catch this class
itself, and wants the build↔review iteration loop made explicit (per Anthropic's
long-running-harness article, the evaluator sends specific feedback and several
build↔review rounds run until green).

## Success outcome
- `agents/reviewer.md` gains a **cross-file consistency** check: for any change to a
  role/contract/prose file, the Reviewer must load the *collaborators the change
  references* (not just the curated feature files) and verify the change's preconditions
  are satisfied by — and do not contradict — the contracts it invokes. The P1 from
  PR #10 (in-session dispatch vs Builder Loop A) is the canonical worked example.
- The **build↔review multi-round loop** is explicit in `agents/reviewer.md` and
  `agents/orchestrator.md`: reject → actionable file-based feedback → `in-progress` →
  Builder addresses → re-review, repeating until green, with the rounds recorded.

## Scope / boundaries
- IN: edits to `agents/reviewer.md` and `agents/orchestrator.md` (and any wording in
  `AGENTS.md`/docs needed for coherence). Optionally a tiny test asserting the new
  Reviewer checklist item exists.
- OUT: changing the schema, adding a status value, or building the telemetry (that is
  E05-F02). OUT: replacing `/pr-loop` — the external Codex pass stays independent; this
  only strengthens the *in-loop* Reviewer.

## Chosen options
- Keep the external `/pr-loop` (Codex) pass as an independent layer; this feature makes
  the in-loop Reviewer better, not a replacement.
- Pre-approved by the human in-session → seeded `autonomous: true` so the loop can run
  through the gate this session.

## Constraints
- `agents/*.md` is installed body → a `VERSION` bump (MINOR ✨) and CHANGELOG entry are
  required (see repo `CLAUDE.md` → Versioning).
- Honor the curate-don't-dump principle: the Reviewer loads collaborators *of the diff*,
  not the whole repo — scoped expansion, not a context dump.

- Is a test warranted for a prose-only change, or is the role-content assertion pattern
