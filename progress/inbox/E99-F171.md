# Intent — Gate /sdd-pr-loop hand-back and auto-merge on required CI

## Problem / who
Codex review of the downstream stamps of 0.91.2 (Apolo:
`.claude/commands/sdd-pr-loop.md:958`, `.harness/.codex-skills/sdd-pr-loop/SKILL.md:562`)
flagged a P1: "Check required CI before declaring the hand-back green / before leaving the
review loop". When the gate returns `merge` for a clean or non-blocking review (e.g. a
clean first round), the runbook breaks out of the loop before §6, the only place that runs
`gh pr checks --required`. As a result:
- `auto_merge: false` posts "all gates green" and records a terminal `handback` while
  required CI is pending or failing. The marker then short-circuits later invocations at
  that head.
- `auto_merge: true` proceeds to `gh pr merge` with no required-CI check of its own.

## Intended fix
In the canonical `/sdd-pr-loop` body (the `sdd-pr-loop` heredoc in `harness-install.sh`):
- Add one `ci_required_gate` helper that polls `gh pr checks <n> --required` every
  `HARNESS_POLL_INTERVAL` up to `HARNESS_POLL_CEILING`. All required checks passing
  passes the gate, and so does a repo with no required checks. A failing required check,
  checks still pending at the ceiling, or an unreadable answer fails it.
- Run it on BOTH terminal paths before anything is claimed. On the hand-back it runs
  before the green summary and before the `handback` marker. On auto-merge it runs before
  `gh pr merge`. A failure goes to needs-human: label (through `mut`), no green comment,
  and no `disposed` marker, so the next run re-enters the round on its cached verdict and
  checks CI again.
- Clarify step 5's `merge` routing so it no longer reads as "go to step 6".
Then regenerate the self-hosted glue with `sh harness-install.sh --self`. Patch release
0.91.3.

## How to verify
Extend `tests/test_pr_loop_hardening.sh`: execute the helper and both terminal blocks
against a stub `gh` whose `pr checks --required` answers pass / fail / pending / none, in
every body (the self-hosted copies and a fresh install). Assert:
- failing CI produces no green post, no `handback`, no merge, and a `needs-human` label;
- pending CI is bounded by the poll ceiling;
- passing CI or no required checks lets the terminal path proceed;
- a dry run labels nothing and posts nothing.
Then run `./init.sh` and `sh tools/run-tests.sh`, and get an independent Reviewer's
approval.
