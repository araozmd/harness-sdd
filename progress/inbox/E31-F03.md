# Intent — OpenCode 2.x compatibility

## Problem / who
mise installed opencode v2.0.32 on the maintainer host on 2026-10-16. The harness emits
OpenCode glue in the 1.x shape (`opencode.json` `agent` key, `.opencode/agent/*.md`,
`.opencode/command/*.md`), so OpenCode 2.x users may silently get no harness roles or
commands. Observed on 2.0.32, in an isolated copy of the source layout (see E99-F172):
- There is no `agent` subcommand. `opencode agent list` fails with
  `Unexpected positional argument: "list"`.
- `opencode debug config` reports the project config under a renamed `agents` key.
- `opencode debug agents` returned `[]` for the source layout. It was NOT verified
  whether that was due to the agent dir, the key rename, or the background service's
  cwd.
- Every `opencode debug …` call spawns a detached `opencode serve --service` daemon
  (PPID 1) that outlives the call.
- `opencode --version` prints `opencode v2.0.32`; 1.x prints the bare `1.18.35`.
- `opencode run` and `opencode models` still exist.

## Success outcome
A target installed with `--agents=opencode` works on both OpenCode 1.x and 2.x: the
roles are discoverable, `/sdd-next` resolves, and `pr-fixer` is registered. A live probe
proves it on each major, without leaving daemons behind.

## Scope / boundaries
In scope:
- Investigate the 2.x config and discovery shape against the real 2.x source or docs.
- Emit glue that both majors accept, or select it by detected major.
- Add a 2.x live probe to tests/test_codex_native.sh next to the 1.x one gated in
  E99-F172.
- Check whether `tools/opencode-model-helper.sh` still parses `opencode models` on 2.x.

Out of scope: dropping 1.x support.

## Chosen options
None yet.

## Constraints
- Never leave a `serve --service` daemon running: probes must stop the daemon they
  started.
- Keep the 1.x emission byte-stable unless a change is intended. The frozen v0.78.1
  oracle in test_codex_native.sh guards it.

## Open questions
- Does 2.x accept the 1.x keys as aliases?
- Is a dual-shape config possible, or must emission be chosen by major (and how is the
  major known at install time)?
