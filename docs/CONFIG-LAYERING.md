# Config layering — shared vs personal

When a harness install lives in a **shared** repo (a team clones it — e.g. a spec or
umbrella repo, see [`UMBRELLA.md`](./UMBRELLA.md)), one question comes up fast:

> *Should every developer share the same `CLAUDE.md`?*

**Yes — keep one shared, checked-in `CLAUDE.md`.** Do **not** fork it per developer; that
splinters the project's source of truth and the agents drift apart. Agent CLIs already
layer their config, so *personal* settings have a separate home. The rule is just:
**project facts are shared and committed; per-developer state is local and gitignored.**

## The three layers

| Layer | Lives in | Scope | VCS |
|---|---|---|---|
| **Project** | `CLAUDE.md` / `AGENTS.md` / `GEMINI.md` (incl. the `harness:begin..end` block), `.harness/` | facts true for everyone on the project: architecture, conventions, the harness entrypoint | **committed** (shared) |
| **Personal** | `.claude/settings.local.json`, `.claude/scheduled_tasks.lock` | one developer's permissions, model pick, local hooks, runtime locks | **gitignored** (never shared) |
| **User-global** | `~/.claude/CLAUDE.md`, your global agent settings | prompt/model preferences that follow *you* across every project | not in any project repo |

The harness-generated `.claude/agents/*` and `.claude/commands/*` are **project** layer —
they are regenerated by the installer and **should** be committed so teammates get the
same `/sdd-next`, sub-agents, etc.

## What the installer does

To keep personal state out of a shared repo, `harness-install.sh` seeds (or extends,
append-only — it never clobbers your existing entries) the **project-root** `.gitignore`
with the personal-layer paths:

```gitignore
.claude/settings.local.json
.claude/scheduled_tasks.lock
# Per-tool MCP scratch dirs your setup may create — add your own (example):
#.playwright-mcp/
```

It deliberately ignores **specific files** under `.claude/`, not the whole directory, so
the shared `agents/` and `commands/` stay tracked while a developer's `settings.local.json`
never gets committed.

## Practical guidance

- **Keep project facts in `CLAUDE.md`.** Architecture, conventions, the harness block —
  things every teammate and agent needs identically.
- **Push personal preferences up to `~/.claude/CLAUDE.md`** (your model, prose style,
  habits) — they follow you, not the project.
- **Let permissions/hooks live in `.claude/settings.local.json`** (gitignored). If your
  whole team genuinely needs a permission, put it in the *committed* `.claude/settings.json`
  instead — a deliberate shared choice, not a personal leak.
- **Don't commit per-tool MCP scratch dirs (e.g. `.playwright-mcp/`), scheduler locks, or
  telemetry** — these are runtime scratch. (The harness also seeds a `.harness/.gitignore`
  for the local-only `telemetry.jsonl`; see [`INSTALL.md`](./INSTALL.md).)
