# Three supported front ends and native Codex workflow — Technical Plan

## Stack and interfaces

POSIX shell installer and existing shell/Python/Node test utilities; no new production dependency, endpoint, config scalar, or TaskStore field. Existing `.harness/.agents`, model/skill stamps, and `.claude/.glue-manifest` remain at their paths. (R1–R12)

| Interface | Defined behavior | Requirements |
|---|---|---|
| Consumer `--agents`, `HARNESS_AGENTS` | Existing precedence; `all` expands to three; `host` uses only retained markers. Explicit `gemini`/`antigravity`, including `HARNESS_HOST_AGENT`, fail before writes. Ambient retired markers are ignored. | R1, R11 |
| Recorded consumer selection | Filter retired keys, retain supported keys, report migration. Retired-only fails before writes and names `--agents=claude`, `--agents=codex`, or `--agents=opencode` recovery. Version stamp remains the prerequisite for prior removal authority. | R2 |
| Source `--self` | No selector defaults to `claude,codex`. Explicit `claude`, `codex`, or their CSV combination is honored; `all` means both source-supported hosts. `host` resolves to Claude or Codex and otherwise fails with self-mode guidance; explicit OpenCode self selection fails rather than silently generating a different host. CLI-over-env precedence remains unchanged. | R5 |
| Codex skill | `$sdd-next`, `$sdd-new <intent>`, `$sdd-drill <epic>`; accompanying text supplies existing `$ARGUMENTS`. `/skills` is discovery UI, not a replacement custom `/sdd-*` command. | R8 |
| Codex PR fixer | Seven standard native roles, plus `pr-fixer` only with gate on; native skill dispatch uses the available host's named-role controls, not an invented CLI or SDK tool schema. | R9, R10 |

## Decisions

### Active support and legacy cleanup are separate (R1–R4)

Shrink the active registry, picker, host-marker table, worker invocation table, and retired model-resolution cases. Capture the **unfiltered prior selection and ownership evidence before body/config replacement**, separately from the active selection. A no-version-stamp orphan `.agents` file never grants removal authority. A legacy version-stamped install without `.agents` retains the old non-Codex ownership baseline, including retired keys for cleanup, while its resolved supported selection is `claude,opencode`.

Keep a clearly named, bounded cleanup-only compatibility helper for the v0.78.1 emitted Gemini/Antigravity shapes. Prefer actual last-written stamps. Where Antigravity has no stamp, compare with the pre-upgrade installed command/role/config material and frozen legacy emission shape before that evidence is replaced. Do not regenerate the old reference from newly changed command text: pristine historical workflows would look edited. If evidence is unavailable or ambiguous, preserve and warn rather than infer ownership. Cleanup-only helpers never install retired glue or participate in active model/worker discovery.

Reclaim `.gemini/agents/<known-role>.md`, `.agents/rules/harness.md`, known `.agents/agents/*.md`, known `.agents/workflows/sdd-*.md`, and the exact GEMINI harness block only when the relevant ownership guard permits it. Never recursively delete `.agents/` or `.gemini/`. Codex-selected skills survive the retirement of the other historical claimant. If the final active selection omits Codex, apply existing atomic skill reclaim guards, preserving edited skill+policy units. Keep historical stamp directory names. Exclude retained retired files from active drift ownership so migration cannot turn a preservation warning into a mandatory init failure.

### Source generation and model preservation (R5–R7, R11)

Extend `self_install()`'s real temporary install, `self_transform()`, and existing manifest rather than adding a second adapter. Emit source `.claude/agents/`, `.claude/commands/`, `.codex/agents/`, and `.agents/skills/` with policy companions. Transform only the existing target-to-source path conventions, retaining literal shell expressions and `.pr-loop` paths. Default source generation keeps Claude and adds Codex; consumer defaults remain unchanged.

Harvest Claude model frontmatter as today. Harvest valid existing Codex per-role `model` choices into a separate Codex-only map; an omitted Codex model remains inherited. Preserve explicit consumer pins through existing resolution. Never translate Claude aliases to Codex or write preferences into the seed template. For source Codex managed roles, treat a valid model-only edit as a supported override; preserve and warn on any other edited or unproven existing artifact. Capture ownership/model evidence before overwriting. The first source generation creates missing files, adopts only demonstrably generated existing files, and leaves collisions alone.

Extend `.claude/.glue-manifest` to track the generated source set for both hosts, including skill policy companions and arming verdict. Retain its path to avoid changing the init contract. Reclaim only previously manifested pristine artifacts on host deselection or gate-off; preserve customized leftovers with a diagnostic and stop claiming them as current managed outputs. Do not silently bless unrelated pre-existing files by hashing them into a new manifest. Deterministic ordering and normalization must make repeated unchanged runs identical. Use existing escalation semantics; do not invent a cross-host model equivalence rule. The default combined source set is UNARMED when Codex inherits, even if Claude alone would be ARMED. Emit/record that consequence; retain Claude model bytes and allow explicit Claude-only self generation to retain its prior arming result.

### Native invocation and isolated PR fixes (R8–R10)

Adapt Codex-facing command invocation references narrowly at the generated skill boundary. Rewrite invocation spelling only, not shell paths, quoted shell programs, `$ARGUMENTS`, code expressions, workflow logic, or canonical Claude/OpenCode bodies. Include a short Codex continuation/invocation note in native roles as needed because canonical shared role files retain portable command spelling. Completion output gives one correct next-step line for each selected host.

Generate Codex `pr-fixer.toml` using the existing native role emitter and existing canonical `agents/pr-fixer.md`, with description and required `developer_instructions`; inherit its model by default and use existing compatible resolution if configured. Extend its stamp, gate-off/deselect cleanup, source generation, and relevant role-count assertions together. Replace the explicit Codex in-session exception in the canonical PR-fixer guidance and Codex skill with native fresh-role dispatch. Keep per-comment handoff files, commits, acted-record discipline, round caps, approvals, and PR-loop policy unchanged. Document that a host unable to start the required fresh role must report the limitation and handoff path rather than impersonate a completed isolated review.
