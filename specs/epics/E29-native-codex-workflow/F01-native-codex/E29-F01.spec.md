# Three supported front ends and native Codex workflow — Functional Spec

## Approval status

The human approved this four-file contract and autonomous implementation on 2026-09-14. The documentation baseline is merged in PR #184 and tagged v0.78.1. The Orchestrator promoted E29-F01 into the TaskStore and advanced it to in-progress on its dedicated feature branch.

## Context

The user wants Claude Code as the primary supported host, Codex second, and OpenCode third; Gemini CLI and Antigravity support ends in this change. Native Codex already has valid project-local role TOMLs on codex-cli 0.154.0, but source `--self` ignores Codex, continuation advice mixes invocation syntax, and PR fixes run in the host context. This feature closes those concrete gaps while preserving existing SDD gates and file handoffs. Complexity is `complex` because it reaches the 12-requirement budget and changes ownership-sensitive migration and generated copies, defect classes already recorded in `progress/lessons.md`.

## Business rules

- A supported front end means selectable installation, active host/worker/model mapping, generated integration, and current usage documentation. Historical references and bounded cleanup-only code are not active support.
- Fresh consumer defaults, source Claude model choices, Codex inheritance/pins, existing OpenCode behavior, and fresh `pr_loop.enabled: false` remain unchanged.
- Native Codex is the SDD host. External Builder delegation and PR #183 are separate work.
- A cleanup may remove only proven harness-owned bytes or a delimited harness pointer block; an edited or unproven file survives with a diagnostic. A symlink is never ownership proof.

## Architecture alignment

`specs/architecture.md` is absent. `specs/product.md` is a retained Viernes example rather than the harness design; the harness intent and AGENTS.md define this feature's scope. All four platform ADRs were read.

- ADR-0001 — Keep task selection and human-gate decisions in the existing deterministic selector; no Codex-specific state machine.
- ADR-0002 — Preserve `builder-heavy` as a distinct native role referencing the same Builder body; no second prompt or model migration.
- ADR-0003 — Preserve one atomic skill unit per command, its policy companion, and `.harness/.codex-skills/` ownership evidence. **Intentional divergence:** the active claimant set becomes `{codex}` because Antigravity is retired; prior Antigravity claims remain migration input. The historical ADR is not rewritten by this feature.
- ADR-0004 — Consumer glue remains local and points at consumer `.harness/` paths, including thin children; source glue alone resolves the same bodies from repository root.

## Acceptance criteria (EARS)

- **R1** — When resolving an explicit selection or active host/worker/model mapping, the installer shall expose only `claude`, `codex`, and `opencode` as supported front ends, rejecting explicit retired selectors before target mutation with a diagnostic naming supported replacements.
- **R2** — When upgrading an existing installation without an explicit new selection, the installer shall resolve the recorded selection by removing retired keys with a notice, preserving surviving supported keys, and stopping before mutation if none survive; an existing pre-selection installation shall retain the historical surviving baseline `claude,opencode` without inventing prior Codex ownership.
- **R3** — When retiring previously selected Gemini or Antigravity glue, the installer shall reclaim only proven pristine legacy artifacts and delimited GEMINI pointer content, preserving custom files, edits, symlinks, and every skill unit still claimed by the final active Codex selection with its policy companion.
- **R4** — After retirement reconciliation, the installed drift ownership helper shall exclude preserved retired glue from mandatory harness-owned paths while continuing to claim proven active Codex artifacts.
- **R5** — When `--self` runs, the installer shall generate selected source Claude/Codex integrations through the same emitters as consumer installs, defaulting to both and honoring explicit supported self selections with source-root body paths.
- **R6** — When source glue is regenerated, the installer shall preserve existing valid per-role Claude/Codex model choices and foreign or edited Codex artifacts, without changing consumer seed model defaults or writing global Codex configuration.
- **R7** — When source glue is regenerated or checked for drift, the installer and source drift check shall reconcile and verify the selected Claude/Codex generated artifact set through the existing manifest, with byte-identical output on a second unchanged run.
- **R8** — When emitting Codex-facing workflow instructions or install completion advice, the installer shall identify the selected host's actual entrypoint syntax, using `$sdd-*` skill invocation and explicit argument handling for Codex.
- **R9** — While Codex is selected, the installer shall reconcile an isolated native `pr-fixer` role and its skill dispatch under the existing `pr_loop.enabled` gate, using the same pristine-only ownership protection as other Codex roles.
- **R10** — When the native Codex SDD workflow delegates a role, its guidance shall require a fresh role context with file-only handoffs, preserving init-failure halt, the human spec gate, and an independent Reviewer verdict before completion.
- **R11** — When installing or regenerating the retained integrations, the installer shall preserve the established Claude and OpenCode behavior and consumer seed values except for the supported-set, migration, host advice, and combined-source arming consequences explicitly described in this spec.
- **R12** — When publishing this feature, the repository shall provide a current documentation package comprising a freshly written canonical root AGENTS.md preserving the harness entrypoint rules, README/install/workflow guidance for the three-host priority and native Codex usage, and release notes describing retired-selection migration and the scope of locally verified execution, without rewriting historical records.

## Out of scope

OpenCode improvements; external executor/delegate wrappers; PR #183; new Codex model defaults or API schema conversion; broad role-prompt rewrites; new intake/planner/driller TOMLs merely for role-count parity; schema/store changes; global Codex settings; whole-tree relocation; historical-spec cleanup; external PR-loop execution during the local smoke.

## Release decision and open questions

Proposed feature release: **0.79.0**, following the separately recorded **0.78.1** baseline. The installed body gains native source Codex and isolated PR-fix capability, so a patch is insufficient. Retired explicit selectors are a deliberate CLI compatibility break and must be called out as such. Under this repository's pre-1.0 version policy, this support-scope change uses a MINOR release: it does not change layout or TaskStore schema or require target data migration, the stated MAJOR triggers. This is not a claim that removing selectors is backward-compatible in general SemVer terms.

Source selection tradeoff: default `--self` emits Claude+Codex. Under the existing conservative all-selected-host escalation policy, inherited Codex models make the combined arming verdict UNARMED even when preserved Claude Builder/heavy choices differ. This proposal accepts that visible consequence; it does not fabricate Codex pins or change arming policy. Explicit Claude-only self generation retains the previous Claude-only arming result.

No unresolved implementation-choice question blocks this proposal. Human approval covers the concrete source-selection policy, retired-only stop, gated pr-fixer, and release classification above.
