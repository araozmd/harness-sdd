# Host detection + explicit `--agents=host` — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.
> POSIX `sh`, zero new dependencies — same dialect as `harness-install.sh` (`set -eu`).
>
> **The shape of this diff:** one data table, three small functions, one new flag, one
> branch inside `resolve_agents`, and one behavior-preserving refactor. Nothing that runs
> today changes course unless the caller names `host` (R22).

## Stack & dependencies

- Language: POSIX `sh`, the existing `harness-install.sh` dialect. (serves: R30)
- New dependencies: **none**. Detection is `case`/parameter-expansion over environment
  variables; no `env`, no `ps`, no `/proc`, no process-tree walking. (serves: R11, R30)
- Test harness: the existing `sh tests/*.sh` convention, plus one new suite file.

## Data model — the marker table  (serves: R1, R6, R7, R8)

A declarative, newline-delimited table near the `AGENT_KEYS` block
(`harness-install.sh` §"agent registry", ~:426). One row per **detectable** agent key:

```
HOST_MARKERS="
claude CLAUDECODE CLAUDE_CODE_ENTRYPOINT
"
```

| Column | Meaning |
|---|---|
| 1 | agent key — must be a member of `AGENT_KEYS` |
| 2..n | session-marker variable names; the row matches if **any** is set and non-empty (R2) |

Rules baked into the table's comment header (they are requirements, not style):

- **Only session markers.** A row's variables must be ones the front-end *injects into the
  environment of processes it launches*. Ambient config/credential variables are forbidden
  by name: `CODEX_HOME`, `HOME`, `TERM_PROGRAM`, and anything ending `_API_KEY`. (R6)
- **`claude CLAUDECODE` is mandatory** and verified. (R7)
- **Every other row requires empirical verification** and an adjacent comment recording the
  CLI + version + how it was observed. No row ⇒ that front-end is undetectable ⇒ the
  fallback ⇒ today's behavior. Shipping with only the `claude` row is acceptable. (R8)

### Verification procedure the Builder must follow before adding a row (serves: R8)

For each candidate front-end, on a machine where it is installed:

1. In a **plain terminal**: `env | sort > /tmp/plain.env`.
2. From **inside that CLI**, via its shell/exec tool: `env | sort > /tmp/<cli>.env`.
3. `comm -13 /tmp/plain.env /tmp/<cli>.env` — the delta is the candidate marker set.
4. Accept a variable only if it is (a) in the delta, (b) named after the CLI's *session*
   rather than its configuration/credentials, and (c) present in that CLI's **default**
   mode (not only in a sandboxed/experimental mode).
5. Record CLI + version in the row comment. If nothing qualifies, **add no row**.

**Leads (not requirements — verify or discard):** `codex` → `CODEX_SANDBOX` /
`CODEX_SANDBOX_NETWORK_DISABLED` (present in the 0.145.0 binary; absent when the sandbox is
off, so at best a partial detector). `gemini` → `GEMINI_CLI` (**caution:** the same string
appears in the Antigravity `agy` binary, so if both set it, it discriminates neither and
must be used for neither). `opencode` → nothing found by binary-string inspection of 1.18.5;
every `OPENCODE_*` token there is a read-side config knob. `antigravity` → the `agy` binary
carries `ANTIGRAVITY_CONVERSATION_ID`, `ANTIGRAVITY_LS_ADDRESS`, `ANTIGRAVITY_SIDECAR_*`,
which look like desktop/sidecar IPC rather than CLI session markers.

**Counter-evidence to keep in mind while verifying** (all observed on the author's machine
inside a Claude Code session): `CODEX_HOME` unset while `CODEX_COMPANION_SESSION_ID` was set
to the *Claude Code* session id; `GEMINI_API_KEY` and `OPENCODE_API_KEY` both set. A
name-prefix match is not evidence.

## Interface — new symbols

| Symbol | Kind | Contract | R-id |
|---|---|---|---|
| `HOST_MARKERS` | data | the table above | R1, R6, R7, R8 |
| `marker_present <var>` | fn | true iff `$var` is set and non-empty (`eval` + `[ -n ]`) | R2 |
| `detect_host` | fn | prints one agent key, or nothing; never writes, never exits non-zero | R1, R3–R5, R9–R11 |
| `precheck_baseline <target>` | fn | prints the sorted keys representing "this target's current shape" | R13, R14, R22, R23, R26 |
| `--print-agents` | flag | with `<target>`: prints `host=…` + `baseline=…`, writes nothing, exits 0 | R23, R24 |
| `HARNESS_HOST_AGENT` | env | explicit host declaration; invalid ⇒ warn + ignore | R9, R10 |
| `host` | override token | whole-value-only resolution mode | R12–R16 |

### `detect_host` — algorithm (serves: R1–R5, R9–R11)

1. If `HARNESS_HOST_AGENT` is non-empty:
   - it is exactly one token **and** `agent_known` ⇒ print it, return. (R9)
   - otherwise ⇒ one warning line naming the value, then fall through to step 2 as if unset.
     Never `die`. (R10)
2. Walk `HOST_MARKERS`; collect the keys whose row has at least one present marker (R2), via
   `normalize_keys` so the result is sorted and unique.
3. Count the hits: `1` ⇒ print that key (R3). `0` ⇒ print nothing (R4). `>1` ⇒ print nothing
   and emit one diagnostic naming the candidates (R5).

`detect_host` writes its diagnostics to **stderr** and its verdict to **stdout**, because it
is consumed via command substitution — the same contract `tui_select`/`toggle_select`
already use.

### `precheck_baseline <target>` — a behavior-preserving extraction (serves: R13, R14, R22, R26)

```
if   [ -f "<target>/.harness/.agents" ] -> normalize_keys of that file
else                                     -> normalize_keys "$AGENT_KEYS"     (ALL)
```

This is **exactly** what `resolve_agents`'s interactive branch computes inline today
(`:964-969`); extracting it changes no behavior (R22). It gets three callers:

1. `resolve_agents`'s interactive branch (replacing the inline `if [ -f "$_persisted" ]`).
2. The `host`-undetected fallback (R13, R14) — this single expression satisfies both: a
   target with no existing install has no persisted file, so it yields ALL (R13); a target
   with one yields the persisted set, and a legacy pre-E08 install yields ALL (R14).
3. `--print-agents`'s `baseline=` line (R23).

One function, three callers ⇒ the diagnostic can never disagree with reality (R26). **E19-F02
changes this function and essentially nothing else** — that is the point of extracting it now.

### `resolve_agents` — updated resolution order (serves: R12–R16, R22, R25)

1. **Override present** (`$AGENTS_OVERRIDE` non-empty):
   - the comma-split tokens include `host` **alongside** any other token ⇒ `die` with the
     "host is a resolution mode, pass it alone" message. Detect this **before**
     `validate_csv` so the error is specific rather than the generic "unknown agent key
     'host'". (R16)
   - the trimmed value is exactly `host` ⇒ `SELECTED` = `detect_host`'s key, else
     `precheck_baseline "$_t"`; print the R25 report line. (R12, R13, R14, R15)
   - otherwise ⇒ `validate_csv` exactly as today. (R22)
2. **Interactive** (`[ -t 0 ]`): `_base="$(precheck_baseline "$_t")"`, then `tui_select` /
   `toggle_select` exactly as today. (R22, R26)
3. **Neither**: `SELECTED` = ALL — unchanged. (R22)

`AGENT_KEYS` is not modified, so `host` never becomes a picker row (R17). `SELECTED` only
ever holds concrete keys, so the existing `printf '%s\n' "$SELECTED" > "$H/.agents"` (~:2785)
already satisfies R18 with no change.

### `--print-agents` (serves: R23, R24)

Parsed in the arg loop beside `--agents`. In single-target mode, **after** the existing
target validation and **before** `install_one`, when the flag is set: print
`host=$(detect_host)` then the space-joined `precheck_baseline "$TGT"`, then `exit 0`.
Combined with `--umbrella` ⇒ `die` with a usage message, mirroring how `--dry-run` /
`--shared-repo` are guarded as umbrella-only (in the inverse direction). (R24)

## DO NOT TOUCH

- **`AGENT_KEYS`** (`harness-install.sh:426`) — adding `host` would leak it into both
  pickers and into `.harness/.agents`. It stays exactly `claude gemini opencode antigravity
  codex`. (R17, R18)
- **The `PRIOR_AGENTS` block in `install_one`** (~:1006-1025), including the
  `grep -vx codex` legacy-baseline exclusion and its comment. This feature supplies
  `SELECTED`; it changes no removal authority. (R19)
- **The §7 / §7b reclamation logic**, `remove_if_pristine`, `_owners_file`,
  `_owners_live`, `_owners_claim`, `_owners_release`, `_is_pr_loop_cmd` and every
  `codex_prompts_dir` caller (~:609-706, ~:2785-3005). The E18-F01 cross-target ownership
  ledger is what makes shared `$CODEX_HOME/prompts` reclamation safe; nothing here may
  weaken, bypass, or pre-empt it. (R20, R21)
- **`validate_csv`'s token grammar** — it keeps validating against `AGENT_KEYS` only. The
  `host` mode is intercepted *before* it, never inside it. (R16, R17)
- **`agent_known`, `agent_selected`, `normalize_keys`, `tui_capable`, `tui_select`,
  `toggle_select`** — reused, not modified.
- **The semantics of the interactive and no-TTY branches of `resolve_agents`** — the
  interactive branch's baseline is *extracted*, not changed; the no-TTY branch stays
  `SELECTED = ALL`. (R22)
- **`AGENTS.md` and `write_pointer AGENTS.md`** — always written, never gated.
- **Canonical `agents/*.md` role bodies**, `store/tasks.schema.json`, `init.sh`,
  `tools/*`, the 4-file spec format, any status value.
- **Umbrella plumbing** (`--umbrella`, `manifest_upsert`, `--shared-repo`, `--dry-run`,
  `migrate_config`) — unchanged.
- **`tests/test_install.sh`'s existing assertions** — they are the additivity guard (R22).
  They run non-TTY with no override and must keep passing byte-for-byte.

## Approach notes

- **Additivity is the load-bearing invariant (R22).** Verify it first and last: the entire
  existing suite must stay green without edits (beyond the two *added* host assertions). If
  any existing assertion needs changing, the design has drifted — stop and re-read this plan.
- **The test suite exports `CODEX_HOME` globally** (`tests/test_install.sh:17`). If a marker
  row ever used `CODEX_HOME`, detection would resolve `codex` in *every* test and look
  correct in CI while being wrong everywhere else. This is precisely why R6 names it. The
  new suite must therefore construct its environment explicitly:
  `env -i PATH="$PATH" HOME="$X/home" CODEX_HOME="$X/ch" [MARKER=1] sh "$SRC/harness-install.sh" …`.
  `env -i` is POSIX and available on both macOS and GNU.
- **Ambiguity is deliberately not a tie-break.** Do not order the table by "confidence" and
  take the first hit. Nesting (one CLI shelling out to another) inherits the outer markers,
  and there is no env-only way to tell inner from outer.
- **Detection must never abort.** Everything in `detect_host` runs under `set -eu`; guard
  every expansion with `${VAR:-}` and make sure no `grep` returning 1 propagates. A miss is
  normal operation.
- **Print exactly one report line** (R25) via `info`, and state *which* fallback was used —
  e.g. `agents: host undetected — keeping this install's selection (claude)` vs
  `agents: host undetected — selecting all front-ends`.
- **Trim before comparing to `host`.** `--agents=" host "` is the mode; reuse the same `sed`
  trim `validate_csv` already applies. Matching is exact-lowercase (`Host` remains an unknown
  key, consistent with the existing keys).
- The Builder is free to choose the table encoding (heredoc + `while read`, or a `case`
  dispatch) and the exact diagnostic wording; the spec pins only the resolved behavior, the
  two `--print-agents` line formats, and the forbidden-marker rule.
