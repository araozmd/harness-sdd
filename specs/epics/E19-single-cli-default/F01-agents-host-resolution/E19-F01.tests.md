# Host detection + explicit `--agents=host` — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable
> check. The Reviewer fails the feature if any R-id lacks a passing check.
>
> `tests/test_agents_host.sh` is a flat POSIX-`sh` script like the rest of the suite, so the
> "test name" is the section label its `pass "…"` line carries — the same convention the
> existing E08 block in `tests/test_install.sh` uses.
>
> **Environment discipline (mandatory).** Every detection-sensitive invocation runs as
> `env -i PATH="$PATH" HOME="$X/home" CODEX_HOME="$X/ch" [MARKERS…] sh "$SRC/harness-install.sh" …`
> so no ambient marker on the developer's machine can influence the outcome, and every
> installer-invoking run sandboxes `CODEX_HOME` under its own temp dir. No check freezes the
> exact `VERSION` string; no check diffs a DO-NOT-TOUCH file against `main`.

## Concrete check sketches

These pin the *shape* of the checks the table names. Wording and helper names are the
Builder's; the observable behavior is not.

**`host_single_marker` (R1, R3, R7)**
`env -i PATH=… HOME=… CODEX_HOME=… CLAUDECODE=1 sh harness-install.sh --print-agents "$T"`
prints `host=claude`.

**`host_empty_marker_is_absent` (R2)** — same run with `CLAUDECODE=` (empty) prints
`host=` (empty).

**`host_no_marker_undetected` (R4)** — same run with no marker at all prints `host=`.

**`host_ambiguous_is_undetected` (R5)** — set the markers of two *shipped* rows at once and
assert `host=` is empty and stderr names both candidates. If only the `claude` row ships,
this check sets `HARNESS_HOST_AGENT` to a two-token value instead and asserts the same
fall-through — and the Reviewer records that the multi-row case stays unexercised until a
second marker is verified.

**`host_forbidden_markers` (R6)** — for each of `CODEX_HOME`, `GEMINI_API_KEY`,
`OPENCODE_API_KEY`, `ANTHROPIC_API_KEY`, `TERM_PROGRAM` set **alone**, `host=` is empty.
Plus a source check that the `HOST_MARKERS` table body contains no `_API_KEY`, no
`CODEX_HOME`, and no `TERM_PROGRAM` token.

**`host_marker_rows_documented` (R8)** — every non-`claude` row in the `HOST_MARKERS` block
has a comment on or adjacent to it (the verification provenance). A table with only the
`claude` row passes trivially.

**`host_env_declaration_wins` (R9)** — `CLAUDECODE=1 HARNESS_HOST_AGENT=opencode` ⇒
`host=opencode`.

**`host_env_declaration_invalid_warns` (R10)** — `HARNESS_HOST_AGENT=bogus` (and separately
`=host`, and `="claude gemini"`) each: exit 0, stderr carries a warning naming the value, and
`host=` falls back to the marker verdict.

**`host_mode_stamps_detected_only` (R12)** — `CLAUDECODE=1 … --agents=host "$T"` ⇒
`CLAUDE.md` + `.claude/commands` present; `GEMINI.md`, `opencode.json`, `.opencode/`,
`.agents/`, `$CODEX_HOME/prompts` absent; `AGENTS.md` present (never gated).

**`host_undetected_fresh_is_all` (R13)** — no marker + `--agents=host` into an empty dir ⇒ all
five front-end artifacts present, the same set a no-override non-TTY run produces.

**`host_undetected_upgrade_keeps_selection` (R14)** — install with `--agents=claude`, then
re-run with **no** marker and `--agents=host`: `.harness/.agents` still holds exactly
`claude`, and `GEMINI.md` / `opencode.json` / `.agents/` were **not** created. This is the
anti-widening check the human's ruling added. Separately, a legacy-shaped target
(`.harness-version` present, `.agents` deleted) + `--agents=host` undetected ⇒ ALL.

**`host_mode_env_and_upgrade` (R15)** — `HARNESS_AGENTS=host` behaves identically to
`--agents=host`; and a second `--agents=host` run over an existing install resolves the same
way without prompting and exits 0.

**`host_mixed_token_rejected` (R16)** — `--agents=host,gemini` exits non-zero, the message
mentions `host`, and the target has no `.harness/` afterwards (fresh dir ⇒ nothing written).

**`host_not_a_registry_key` (R17)** — source: the `AGENT_KEYS` assignment does not contain
`host`. Integration: after any successful run, every line of `.harness/.agents` is one of the
five known keys.

**`prior_agents_unchanged` (R19)** — source: the `PRIOR_AGENTS` block still carries its
`grep -vx codex` legacy exclusion. Integration: a legacy-shaped upgrade (`.harness-version`
present, `.agents` absent) that selects `claude` deletes nothing from `$CODEX_HOME/prompts`.

**`host_fresh_removes_nothing` (R20)** — pre-seed the sandboxed `$CODEX_HOME/prompts` with a
foreign file plus a `.sdd-pr-loop.owners` ledger naming another target; run
`CLAUDECODE=1 … --agents=host` into an empty dir; both survive untouched.

**`host_upgrade_removal_respects_pristine` (R21)** — install `--agents=claude,codex`,
hand-edit one global prompt, then re-run with `CLAUDECODE=1 --agents=host`: the pristine
prompts are reclaimed, the hand-edited one survives with a warning — i.e. the existing rule,
unchanged.

**`additive_no_host_unchanged` (R22)** — with `CLAUDECODE=1` set but **no** `host` token and
no `HARNESS_HOST_AGENT`: a non-TTY no-override run stamps all five; `--agents=claude` stamps
exactly claude. Plus: the whole pre-existing `tests/test_install.sh` passes with no edits to
any pre-existing assertion.

**`print_agents_contract` / `print_agents_writes_nothing` (R23, R11)** — exit 0; stdout is
exactly the two `host=` / `baseline=` lines in that order; the target directory's file list is
byte-for-byte identical before and after (capture with `find … | sort`). Run it once against
an empty dir and once against an installed target.

**`print_agents_umbrella_rejected` (R24)** — `--print-agents --umbrella <dir>` exits non-zero
and creates no `.harness/` anywhere under `<dir>`.

**`host_reports_resolution` (R25)** — a `--agents=host` run's combined output contains one
line naming `claude` (detected), or naming the applied fallback (undetected) — and the two
undetected cases (ALL vs kept-selection) are distinguishable in the text.

**`baseline_single_helper` (R26)** — source: `resolve_agents`'s interactive branch and the
`host`-undetected fallback and the `--print-agents` path all call `precheck_baseline`, and the
old inline `if [ -f "$_persisted" ]` baseline computation is gone.

**`docs_document_host_mode` (R27)** — `docs/INSTALL.md` mentions `--agents=host`,
`HARNESS_HOST_AGENT`, `--print-agents`, and **both** fallbacks; `README.md` and the
`harness-install.sh` header mention `host`; after an install, `.harness/manifest.txt` mentions
it too.

**`suite_wired_into_verification` / `suite_hygiene` (R28, R29)** — `harness.config.yaml`'s
`verification.test_command` contains `tests/test_agents_host.sh`; and the new suite's own
source contains no `git diff … main`, no literal current version string, and sets/passes
`CODEX_HOME` on every `harness-install.sh` invocation.

**`version_and_changelog` (R31)** — `VERSION` is strictly greater than `0.39.0` by a MINOR
step, and `CHANGELOG.md` has an entry for it. Compare **by parsed components**, never by
freezing the literal string.

## Behavioral / end-to-end checks (Reviewer, by hand)

- From inside a real Claude Code session, run
  `./harness-install.sh --print-agents /tmp/somerepo` and confirm `host=claude`.
- From a plain terminal (no CLI), run the same and confirm `host=` is empty.
- Install into a scratch repo with `--agents=host` from inside Claude Code and confirm only
  `CLAUDE.md`, `.claude/` and `AGENTS.md` appear — no `GEMINI.md`, no `opencode.json`, no
  `.agents/`, and nothing new under `~/.codex/prompts`.
- Re-run the installer interactively against a scratch repo with **no** `host` token and
  confirm the picker still pre-checks exactly what it did before this feature (that is R22 —
  the fresh-install baseline change is E19-F02).

## Non-functional checks

- Lint: `verification.lint_command` is empty — n/a. The installer must stay POSIX `sh`; if
  `shellcheck` is available locally, the new functions should be clean of new warnings.
- Types: `verification.typecheck_command` is empty — n/a.
- `./init.sh` exits 0 in the harness source repo and in an installed target (R30).
