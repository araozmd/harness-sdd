# Fresh-install pre-check baseline = the detected host — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.
> POSIX `sh`, zero new dependencies.
>
> **The shape of this diff:** one new branch inside one function, plus docs and tests. If
> the diff to `harness-install.sh` is larger than that, E19-F01 did not land as specced —
> stop and reconcile before continuing.

## Stack & dependencies

- Language: POSIX `sh`, the existing `harness-install.sh` dialect. (serves: R12)
- New dependencies: **none**. Everything this feature needs (`detect_host`,
  `precheck_baseline`, `normalize_keys`) exists after E19-F01.
- Prerequisite: **E19-F01 merged**. This plan assumes `precheck_baseline <target>` exists and
  is the single source of the picker's pre-check set, the `--print-agents` `baseline=` line
  and the `host`-undetected fallback (E19-F01 R26).

## The change  (serves: R1, R2, R3, R4, R6)

`precheck_baseline <target>` today (post-F01):

```
if   [ -f "<target>/.harness/.agents" ] -> normalize_keys of that file
else                                     -> normalize_keys "$AGENT_KEYS"     (ALL)
```

becomes:

```
if   [ -f "<target>/.harness/.agents" ]          -> normalize_keys of that file   (R3)
elif [ -f "<target>/.harness/.harness-version" ] -> normalize_keys "$AGENT_KEYS"  (R4)
else
     _h="$(detect_host)"
     [ -n "$_h" ] && printf '%s\n' "$_h"                                          (R1)
                  || normalize_keys "$AGENT_KEYS"                                 (R2)
fi
```

Three things about this that matter:

1. **The middle branch is the whole "upgrades must not silently narrow" guarantee** (R4, R9).
   The existing-install test is `.harness-version`, **not** the absence of `.agents`. A
   pre-E08 install has every front-end stamped and no persisted selection; if it fell through
   to detection, a human pressing Enter on the pre-checked picker would *delete* working glue.
2. **The `host`-undetected fallback keeps working unchanged.** E19-F01 R13/R14 route through
   this same function; in that path detection has by definition already failed, so the new
   `else` branch yields ALL for a target with no existing install — exactly F01's R13. No
   special-casing is needed, and none may be added.
3. **`detect_host` is called at most once per resolution.** It is pure and cheap, but the
   `--print-agents` path prints `host=` and `baseline=` from two calls; that is acceptable
   (identical results) and keeps the code trivial. Do not add caching.

Nothing else in `resolve_agents` changes: the interactive branch still calls
`precheck_baseline` (R6), and the no-TTY/no-override branch still assigns ALL directly (R5),
never consulting the helper.

## DO NOT TOUCH

- **`HOST_MARKERS`, `marker_present`, `detect_host`, `HARNESS_HOST_AGENT`, the `host`
  override branch, `--print-agents`** — E19-F01 owns all of them. This feature consumes them
  unmodified. In particular: **do not add a marker row here.**
- **`AGENT_KEYS`** — `host` is not a key and never becomes one.
- **The `PRIOR_AGENTS` block in `install_one`**, including the `grep -vx codex` legacy
  exclusion. (R7)
- **The §7 / §7b reclamation logic**, `remove_if_pristine`, and the `_owners_*` ownership
  ledger for the gated global Codex prompt. (R8)
- **The no-TTY/no-override branch of `resolve_agents`** — stays `SELECTED = ALL`. (R5)
- **`tui_select` / `toggle_select`** — they receive a baseline; they do not compute one.
- **`AGENTS.md`**, canonical `agents/*.md` role bodies, `store/tasks.schema.json`, `init.sh`,
  `tools/*`, umbrella plumbing.

## Approach notes

- **The regression to fear is the pre-E08 upgrade.** Write that test first (an existing
  install with `.harness-version` present and `.agents` deleted, plus a marker set): the
  baseline must be all five. If it is not, the branch order is wrong.
- **The tests cannot drive the real picker** (it requires a TTY). They assert the baseline
  through `--print-agents`, which E19-F01 R26 guarantees is the same value the picker seeds
  from. That guarantee is the reason `--print-agents` exists; keep the single-helper property
  intact rather than duplicating the logic for the diagnostic.
- **Environment discipline is inherited from E19-F01** and is not optional: `env -i` plus only
  the variables under test, and a sandboxed `CODEX_HOME` on every installer-invoking run.
  The wider suite exports `CODEX_HOME` globally, so an uncontrolled environment silently
  changes what these assertions mean.
- **Docs are half this feature's value.** The new default is the first thing a user notices
  and "how do I add another CLI later?" is their immediate next question; R11 exists so the
  answer is not buried in a source header comment.
