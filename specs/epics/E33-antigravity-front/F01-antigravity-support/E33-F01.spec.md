# Native Antigravity invocation adapter, dynamic subagent dispatch, and documentation — Functional Spec

## Context
Google Antigravity is a modern AI-assisted development platform with support for workspace skills (`.agents/skills/`) and dynamic runtime subagents (`define_subagent` / `invoke_subagent`). Prior Antigravity support in E07 attempted to stamp bare `.agents/agents/*.md` files, which Antigravity did not discover without machine-global plugins, causing Antigravity to be retired in E29. This feature restores first-class Antigravity support by standardizing `/sdd-*` slash command invocation in the existing `.agents/skills/` units and defining dynamic runtime subagent leasing in the Orchestrator contract.

## Business rules
- The harness remains 100% repository-local. No machine-global plugins (`~/.gemini/antigravity-cli/plugins/`) are required.
- Context isolation is strictly enforced: every role handoff (Orchestrator → Architect → Builder → Reviewer) must run in a clean context without forwarded chat history.
- Existing Claude, Codex, and OpenCode workflows, commands, and tests must remain completely unaffected.

## Architecture alignment
- ADR-0003 — `.agents/skills/<name>/` holds ONE shared unit per command, claimed by every front-end that reads it: this feature honors ADR-0003 by reusing `.agents/skills/` as the single shared surface for Antigravity and Codex without creating divergent skill copies.
- ADR-0004 — Source glue resolves bodies from repository root: this feature honors ADR-0004 by reading role definitions directly from `agents/*.md`.

## Acceptance criteria (EARS)

- **R1** — When an agent or user invokes any harness skill (`sdd-next`, `sdd-plan`, `sdd-drill`, `sdd-new`, `sdd-fix`, `sdd-fix-parallel`, `sdd-pr-loop`) in Antigravity, the skill's invocation adapter shall recognize `/sdd-<name>` as a supported invocation syntax, binding accompanying text to `$ARGUMENTS`.
- **R2** — While executing under Antigravity, the Orchestrator shall define ephemeral role subagents (`architect`, `builder`, `reviewer`) via `define_subagent` with system prompts sourced from canonical `agents/<role>.md` files, and dispatch tasks using `invoke_subagent` to guarantee context isolation.
- **R3** — When delegating to the Reviewer in Antigravity, the system shall ensure the Reviewer runs in an isolated subagent context containing only the role definition, specs, git diff, and progress notes, preserving the independent Reviewer gate.
- **R4** — The documentation in `AGENTS.md`, `README.md`, and `docs/WORKFLOW.md` shall identify Antigravity as a supported front end and specify `/sdd-*` slash-command usage and dynamic subagent dispatch.
- **R5** — When running verification tests, a dedicated test script `tests/test_antigravity_front.sh` shall confirm that all `.agents/skills/*/SKILL.md` units document Antigravity invocation syntax and that `init.sh` remains green.

## Out of scope
- Re-introducing heavy installer emitter matrices in `harness-install.sh`.
- Machine-global plugin packaging under `~/.gemini/antigravity-cli/plugins/`.
- Modifying Claude Code `.claude/` or Codex `.codex/` role configurations.
