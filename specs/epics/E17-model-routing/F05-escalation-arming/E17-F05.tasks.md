# Installer-stamped escalation arming — Task Breakdown

Each task is independently verifiable. **Commit before mutation-testing** (T9).

---

### T1 — `escalation_verdict` in `harness-install.sh`

Add `escalation_verdict <front-end>` beside `models_any` (which it mirrors in shape). It calls
`resolve_model "$1" builder` and `resolve_model "$1" builder-heavy` and compares — nothing else.
Four total cells: `raise` / `none` / `same` / `neither`.

**Done when:** the four cells are reachable from real configs and no alias table, pin lookup, or
tier parsing appears anywhere in the new code.

---

### T2 — the symlink guard + `write_escalation_arming`

`escalation_arming_is_symlinked` (the `opencode_stamp_is_symlinked` shape). The writer:

- symlinked ⇒ warn, return, **write nothing and remove nothing**;
- gate: at least one selected front-end satisfies `models_any` ⇒ write; else `rm -f` the
  regular file if present;
- content: `armed`/`blocked`, then `fe=verdict` per selected front-end in `$AGENT_KEYS` order.

**Done when:** re-installing the same target twice yields a byte-identical artifact.

---

### T3 — wire it into `install_one`, and the manifest

Call site after §6 (opencode.json), so every `resolve_model` diagnostic has already been
emitted once by the warn-once ledger. Add `.harness/.escalation-arming` to the MODEL ROUTING
block of `manifest.txt` with one line on what absence means.

**Done when:** a fresh `--agents=claude` install of a fully-`inherit` target has **no**
`.harness/.escalation-arming`, and a configured one has it with the expected content.

---

### T4 — the second gate in `tools/builder-role.sh`

`--arming <path>`, defaulting to `$(dirname "$_config")/.escalation-arming`. Read line 1 only;
anything other than exactly `armed` leaves the gate shut. Escalation requires
`_threshold -gt 0` **and** armed, routed through the existing `_escalate` helper so the
complexity trigger cannot bypass it.

Update the tool's header comment: the "it no longer guesses / the operator asserts" paragraph is
now **false**. Replace it with what actually happens — the installer resolved it, this reads the
verdict — keeping the two review-finding citations, which are still why the design is what it is.

**Done when:** `armed` + threshold escalates; every other combination returns `builder`; the
tool still never reads `models:`, `progress/`, the spec body, or `git`.

---

### T5 — the two decline advisories

Distinguish "no verdict recorded" from "blocked by `<fe>=<verdict>` …". Advisory only — the
decision is already made from line 1, so a malformed detail line changes wording and nothing
else. Never non-zero exit.

**Done when:** the two messages are textually distinct, the blocked one names the front-end,
and both exit 0.

---
