# Per-role model selection — Test Contract

> Every R-id maps to a concrete, executable check. The Reviewer fails the feature if any
> R-id lacks a passing test.
>
> **Conventions (non-negotiable).** Both suites are straight-line `sh` scripts —
> `set -eu`, `T="$(mktemp -d)"`, `trap 'rm -rf "$T"' EXIT`, `fail()`/`pass()` helpers, one
> `pass "<summary> (Rnn)"` per group. **Every installer invocation sandboxes `CODEX_HOME`**
> (`export CODEX_HOME="$T/codex-home"` for the suite, plus a per-run
> `CODEX_HOME="$TB/ch"` where isolation must be crisp) and, where `$HOME` matters, `HOME`
> too. All runs are non-TTY, so selection is always driven by `--agents=<csv>`.
> **Anti-patterns that will be rejected:** freezing an exact `VERSION` string (assert a
> `CHANGELOG.md` heading instead — see `tests/test_install.sh:91-97`) and diffing
> DO-NOT-TOUCH files against `main`.
>
> Test-name column uses `file::function-or-block`. Both files run from the repo root via
> the existing `sh tests/*.sh` convention and are registered in
> `verification.test_command`.

## Test detail — the checks that are easy to get wrong

**R11 — the universality invariant (highest-value test).**
Install twice into two fresh `mktemp -d` targets with `--agents=claude,gemini,opencode,antigravity,codex`:
`$TA` with the seeded config untouched (all `inherit`), `$TB` with the whole `models:`
block stripped from `$TB/.harness/harness.config.yaml` before a second run. Then
`diff -r` the two targets excluding `.harness/harness.config.yaml` and
`.harness/manifest.txt` — must be empty. Add explicit negative assertions:
`grep -rq '^model:' "$TA/.claude/agents"` fails, `grep -q '"model"' "$TA/opencode.json"`
fails, `grep -rq '^model:' "$TA/.agents/agents"` fails, `[ -d "$TA/.gemini/agents" ]`
fails, `[ -d "$TA/.codex/agents" ]` fails, `[ -f "$TA/.harness/.opencode.stamp" ]` fails.

**R5 — `inherit` is never a literal.**
With a config mixing `inherit` and real tiers, assert `grep -rn 'inherit' "$T"` matches
nothing outside `.harness/harness.config.yaml`, `.harness/docs/` and
`.harness/specs/` (the config and the shipped docs legitimately mention the word).

**R7 / R9 / R10 — stderr, not stdout, and exit 0.**
Capture with `_w="$(CODEX_HOME=… sh "$SRC/harness-install.sh" … 2>&1 >/dev/null)"`
(the `tests/test_install.sh:813-824` deselect idiom) and assert both the message content
and that the run still succeeded. For R7 also assert the message appears **once**, not
once per role: `[ "$(printf '%s\n' "$_w" | grep -c 'pin.codex.cheap')" = "1" ]`.

**R19 — exactly one model key per role.**
After editing `.harness/harness.config.yaml` and re-running, assert both the new value is
present and that no role definition accumulated a second key:
`[ "$(grep -c '^model:' "$T/.claude/agents/builder.md")" = "1" ]`.

**R20 — the three `opencode.json` cases.** In three separate targets:
(a) pre-existing target whose `opencode.json` is the pristine **model-free** body ⇒ after
adding a models config and re-running, the file gains the model members;
(b) `.harness/.opencode.stamp` present and matching ⇒ a further config change re-stamps;
(c) the operator appends a line to `opencode.json` ⇒ re-run leaves it byte-identical and
warns on stderr.

**R21 — determinism (protects R22).**
Install, `cp -R` the stamped artifacts aside, install again with the same config and
selection, then `cmp -s` each pair. This is the guard that keeps `remove_if_pristine`
able to reclaim stamped files at all.

**R22 / R23 — deselection.**
Install all five with a fully populated `models:` block, then re-run with
`--agents=claude` only. Assert `.agents/agents/*.md`, `.gemini/agents/*.md`,
`.codex/agents/*.toml` and `opencode.json` are gone, the `agents/` dirs and their parents
are gone, and `.harness/.opencode.stamp` is gone. Then repeat with one file edited
(`printf 'x\n' >> "$T/.gemini/agents/scout.md"`) and assert it survives with a warning on
stderr.

**R26 — regeneration overwrites an edit; deselection does not (the BR6 seam).**
This is the half of BR6 that R23 does *not* cover, and the two must be asserted in the
same suite so the contract cannot drift back into ambiguity (`E17-F01.spec.md`
§ *Amendments* A1). In one target: install with `$ALL`, set a tier and the codex pin so
both trees materialize, re-run so the artifacts exist, then append a marker to
**both** `.gemini/agents/<role>.md` and `.codex/agents/<role>.toml`
(`printf 'zzz-user-edit\n' >> …`, the `test_deselect_preserves_user_edits` idiom). Re-run
the installer with `$ALL` and the config **byte-unchanged** — no `set_tier`, no `set_pin`,
so this is a routine re-install, not a config change (that is R19's case). Assert:
- the marker is gone from both files (`grep -q 'zzz-user-edit' … && fail`);
- both files still carry exactly one model key, i.e. the regenerated body is the normal
  one (`[ "$(grep -c '^model:' …)" = "1" ]`, `[ "$(grep -c '^model = ' …)" = "1" ]`);
- `.claude/agents/<role>.md` and `.agents/agents/<role>.md` behave the **same** when
  edited the same way — this is the assertion that pins "matching the pre-existing
  generated-glue contract" rather than just describing it;
- `opencode.json` is **not** in this test — R20(c) owns it and requires the opposite
  (edited ⇒ untouched + warning).
Then, in a **separate** target (`mk r26b`), re-assert the deselect half so the pair is
visible in one place: edit a `.gemini/agents/<role>.md`, re-run with `--agents=claude`,
and assert the file **survives** with its edit and a warning on stderr — R23 unchanged.
One `pass "… (R26)"` line for the group.

**R16 — project-local codex, explicitly.**
Assert `[ -f "$T/.codex/agents/builder.toml" ]` **and**
`[ -d "$CODEX_HOME/agents" ]` is false, so a regression that writes into the operator's
global config is caught immediately.

## Behavioral / end-to-end checks (Reviewer performs)

- Install into a scratch repo with `--agents=claude`, set `architect: reasoning` and
  `scout: cheap`, re-run, and confirm `.claude/agents/architect.md` and
  `.claude/agents/scout.md` carry different `model:` values while `builder.md` (left on
  `inherit`) carries none.
- Confirm the install output is readable: at most one advisory line per (front-end, tier),
  not thirty.

## Non-functional checks

- `verification.test_command` runs green end to end, with
  `sh tests/test_model_routing.sh` appended to the chain.
- `sh -n harness-install.sh` parses clean (POSIX `sh`, no bashisms introduced).
- Lint / typecheck: not configured for this repo (`lint_command` / `typecheck_command`
  are empty) — nothing to run.
