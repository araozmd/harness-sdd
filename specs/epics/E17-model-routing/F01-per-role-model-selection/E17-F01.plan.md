# Per-role model selection — Technical Plan

> Every decision cites the R-id(s) it serves. Grounded in `progress/E17-F01-scout.md`
> (repo recon, file:line) and `progress/E17-F01-cli-model-surfaces.md` (vendor research,
> confidence-marked).

## Stack & dependencies

- Language: POSIX `sh` (`harness-install.sh`), plus `grep`/`awk`/`cmp`/`sed` only.
- New dependencies: **none**. No YAML parser is introduced — the config reads use the
  existing ad-hoc section-scoped `awk` idiom (`_cfg_telemetry_log`, `harness-install.sh:244`).
- Tests: plain `sh` scripts under `tests/`, `fail()`/`pass()` helpers, no test runner.

## Scope decision 1 — codex and gemini get NEW project-local per-role artifacts

Scout established that only three of five front-ends have any per-role generated
artifact today. For `codex` and `gemini`, "stamp a model per role" means *creating a
native per-role agent definition that does not exist yet*. **Decision: F01 creates
both, project-local, conditionally.**

| | decision | rationale |
|---|---|---|
| `gemini` | create `.gemini/agents/<role>.md` (markdown frontmatter) | Gemini's `--model` flag and `/model` command are documented as **not** reaching sub-agents, so frontmatter is the only lever that exists — a "session-level fallback" is provably ineffective here. Project-local `.gemini/agents/` is a documented location and mirrors every other front-end's workspace-local glue. |
| `codex` | create `.codex/agents/<role>.toml` **inside `$TARGET`**, never in `$CODEX_HOME` | Codex is the one front-end whose existing glue is machine-**global** (`$CODEX_HOME/prompts/*`). That is only safe because the prompt bodies are target-independent. A **model stamp is target-dependent**: writing per-role models to `~/.codex/agents/` would let target A silently retune target B on the same machine. Project-local also keeps deselection inside `$TARGET`, where the pristine-compare machinery already lives. |

**Risk accepted and recorded:** project-local `.codex/agents/` discovery is *unconfirmed*
in the research. If Codex does not read it, the file is **inert** — a no-op, not a
breakage. The alternative (a wrong write into the operator's global config) is actively
harmful. If a later confirmation shows the global path is required, promoting the
emitter is a localized change to one function and needs **no config migration**.

**Conditional creation is required by R11/R17.** Both new trees are created **only**
when at least one role resolves to a concrete value for that front-end. With no
`models:` block configured, the target tree stays byte-identical to today — which is the
feature's hardest constraint.

**Consequence for `codex` specifically (R7).** Codex has *no floating tier alias* (it
requires a bare model id), and the harness is forbidden from shipping frozen ids. So a
codex tier that is not pinned resolves to nothing and `.codex/agents/` is never created.
This is honest, not vacuous: the pin is the designed mechanism, and the seeded config
ships commented `pin.codex.*` examples so the operator sees exactly what to write. The
same applies to `opencode` (`provider/model` required).

## Scope decision 2 — `inherit` compiles to key omission on every front-end

Research: `inherit` is valid on Claude/Antigravity/Gemini, **absent** on Codex, and a
**hard error** on OpenCode (which aborts the user's run with a useless message).
Meanwhile *"key absent"* means *"inherit the session model"* on **all five**. Therefore
the harness writes the literal `inherit` **nowhere** (R5) and always omits instead. One
rule, no per-front-end special case, and it makes R11 (byte-identity when unconfigured)
fall out for free.

## Scope decision 3 — unknown tier warns, unknown pin is written verbatim

- Unknown **tier** → warn + resolve as `inherit` + exit 0 (R9). Rationale: there *is* a
  provably-safe fallback (today's behavior), and hard-failing would make an older
  installer refuse a config written for a newer harness. Contrast `validate_csv`
  (`harness-install.sh:323`), which dies on an unknown agent key — correct there, because
  no safe fallback exists.
- Unknown **pin value** → written verbatim, unvalidated (R8). The installer cannot know
  vendor model lists. **One exception (R10):** an `opencode` pin without a `/` is
  syntactically invalid for OpenCode and would *abort the operator's OpenCode runs*, so
  it is warned about and dropped. This is a format check, not a model-list check.

## Data model — the `models:` config block  (serves: R1, R2, R3, R4, R8)

Exactly **one level of nesting** under `models:`. This is deliberate: the repo has no
YAML parser and nothing reads two-level-nested keys today (Scout §3), so grandchildren
would require indentation-sensitive `awk`. Dotted composite keys keep every read on the
proven `_cfg_telemetry_log` shape.

```yaml
# Per-role model routing (E17-F01) — OPT-IN and INERT by default.
# Tiers: reasoning | standard | cheap | inherit
# `inherit` compiles to KEY OMISSION on every front-end — the generated agent
# definitions are byte-identical to a harness without this block.
# NOTE: `orchestrator` applies only where the orchestrator is a spawned sub-agent
# (Claude) or the configured primary agent (OpenCode). The model of the session you
# launched by hand is chosen by how you launched it, not by the harness.
models:
  default: inherit        # tier for any role not listed below
  orchestrator: inherit
  architect: inherit      # try: reasoning
  builder: inherit        # try: standard
  reviewer: inherit       # try: standard
  scout: inherit          # try: cheap
  doc-critic: inherit     # try: cheap
  # Exact-value escape hatch: `pin.<front-end>.<tier>`, written VERBATIM in that
  # front-end's own vocabulary. REQUIRED for codex and opencode, which have no
  # floating tier alias — an unpinned tier there stamps nothing.
  #   opencode MUST be "provider/model" (an invalid value aborts your OpenCode run)
  #   codex    MUST be a bare model id (the provider comes from `model_provider`)
  #   antigravity accepts only tier aliases and needs `agy` >= 1.1.5 (inert below it)
  # pin.opencode.reasoning: ""
  # pin.opencode.standard: ""
  # pin.opencode.cheap: ""
  # pin.codex.reasoning: ""
  # pin.codex.standard: ""
  # pin.codex.cheap: ""
  # pin.claude.reasoning: ""
```

| Key | Type | Notes |
|---|---|---|
| `models.default` | tier string | fallback tier for unlisted roles (R4) |
| `models.<role>` | tier string | one per role; roles are `orchestrator architect builder reviewer scout doc-critic` |
| `models.pin.<front-end>.<tier>` | string | verbatim native value; empty/absent ⇒ no pin (R8) |

Unrecognized keys under `models:` are **ignored**, so a newer config never breaks an
older installer (BR7).

### Built-in tier → native value table  (serves: R6, R7)

| tier | claude | antigravity | gemini | codex | opencode |
|---|---|---|---|---|---|
| `reasoning` | `opus` | `pro` | `pro` | *(pin required)* | *(pin required)* |
| `standard` | `sonnet` | `pro` | `pro` | *(pin required)* | *(pin required)* |
| `cheap` | `haiku` | `flash` | `flash` | *(pin required)* | *(pin required)* |
| `inherit` | *omit* | *omit* | *omit* | *omit* | *omit* |

Every built-in value is a **floating vendor alias**, so a new model release is picked up
without a harness change (BR2). Antigravity has only two tiers upstream
(`flash`/`pro`), so `reasoning` and `standard` both map to `pro` — stated, not hidden.

## Interface — new shell functions in `harness-install.sh`

| Function | Signature | Serves |
|---|---|---|
| `_cfg_models_value` | `<config-file> <key>` → prints the `models.<key>` scalar (comment-stripped, unquoted), empty if unset. Same section-scoped `awk` shape as `_cfg_telemetry_log`; the `.` in dotted keys must be matched literally, not as a regex wildcard. | R1–R4, R8 |
| `model_tier` | `<role>` → prints the resolved tier (`models.<role>` → `models.default` → `inherit`), warning once on an unrecognized tier and printing `inherit`. | R4, R9 |
| `resolve_model` | `<front-end> <role>` → prints the native value, or **empty** to mean "omit the key". Applies: tier → pin lookup → built-in alias → omission; enforces the OpenCode `/` guard. Pure function of (config bytes, front-end, role). | R5–R10, R21 |
| `models_any` | `<front-end>` → exit 0 iff at least one role resolves to a non-empty value for that front-end. Gates the conditional `.gemini/`, `.codex/` trees. | R17 |
| `gen_gemini_agent` | `<role> <description> <dest>` — hoisted so **both** the install stamp and the deselect compare call it. | R15, R22 |
| `gen_codex_agent` | `<role> <description> <dest>` — likewise. | R16, R22 |

`resolve_model` must be **idempotent and side-effect free** on stdout: the informational
message of R7 and the warnings of R9/R10 go to **stderr**, and must be emitted **once
per (front-end, tier)** rather than once per role, so the output does not degenerate into
six identical lines.

### Notes on specific edits

- **Both halves of the config, always.** A fresh install copies `$SRC/harness.config.yaml`
  verbatim (`:672`) and **never** calls `migrate_config`; an upgrade **only** calls
  `migrate_config` (`:685`). Missing either half makes fresh and upgraded targets diverge.
  `fix_lane` (`harness-install.sh:193-201` + `harness.config.yaml` tail) is the exact
  2-file precedent to copy.
- **Timing is already safe.** `resolve_agents` runs at `:629` and the config is
  seeded/migrated at `:671-686`, while all stamping happens at `:1035-1514` — so
  `$H/harness.config.yaml` is guaranteed present and migrated before any `resolve_model`
  call (Scout §3).
- **`remove_owned` stem lists are unchanged.** The new artifacts use *new directories*
  (`.gemini/agents/`, `.codex/agents/`) and are reclaimed by `remove_if_pristine`, not by
  `remove_owned` — so `$HARNESS_CLAUDE_SHIMS` / `$HARNESS_SDD_CMDS` need no edits.
- **Never `rm -rf`.** Follow the existing pattern: delete named files, then `rmdir`
  (which fails harmlessly if the user left their own files there).
- **CMDDIR cleanup stays deferred** past §7 (`:1502-1506`, `:1639`). Do not move it.

## Recommended split (for the human, via the Orchestrator)

**Recommendation: split.** Five front-ends, two of which require a brand-new artifact
type with its own install path, deselect path, manifest entry, docs and tests, plus a
new config schema, a resolver, a migration and the opencode never-clobber rework, is a
large single feature — larger than any prior feature in this repo. The seam is clean:

| slice | R-ids | content |
|---|---|---|
| **F01 core** | R1–R14, R18–R25 | config schema + `migrate_config` + resolver + built-in tier table + stamping for the three front-ends that already have a per-role artifact (claude, opencode, antigravity) + opencode re-stamp rework + deselect symmetry + docs/VERSION/tests |
| **F01b new artifacts** | R15–R17 (+ their deselect and manifest/doc lines) | `.gemini/agents/*.md` and `.codex/agents/*.toml` emitters, their §7 deselect cases, manifest/docs additions, tests |

Why the seam is safe: **F01b adds no config key and no resolver change.** It only adds
two emitters and two deselect cases that consume the already-shipped `resolve_model`.
Completing it later therefore requires **no config migration** — which is also exactly
what the E17-F02 constraint demands ("leave room for a second Builder variant without a
config migration"): tiers are keyed off *role names* in a flat map, so a future
`builder-heavy` is one new line, not a schema change.

If the human prefers one shot, the spec as written is complete and buildable as-is; the
task list below is already ordered so that T14–T18 (the F01b slice) can be lifted out
whole without disturbing anything before them.

## Approach notes

- **Determinism is the load-bearing property (R21/R22).** `remove_if_pristine`
  regenerates its reference at deselect time, so every generator that gains a model line
  must gain it identically on both paths. Because all generators are hoisted functions
  that call `resolve_model` against `$H/harness.config.yaml`, this holds automatically —
  *provided* the Builder does not duplicate any emission logic into the deselect branch.
  Emit exactly once, from one function, per artifact type.
- **Known, accepted degradation:** if the operator edits `models:` and then deselects a
  front-end **without** re-running the installer in between, the regenerated reference
  will not match the on-disk file, so it is left in place with the existing "differs from
  the generated stamp (edited)" warning. That is safe and is the same behavior class as a
  genuine user edit. `.harness/.opencode.stamp` closes this gap for `opencode.json`
  specifically, because that file is never regenerated on a plain re-run.
- **Message volume.** Six roles × five front-ends is 30 resolutions per run. Warnings and
  the R7 info line must be de-duplicated to one line per (front-end, tier) so the install
  output stays readable.
- **Frontmatter key order** is part of the byte contract for the pristine compare. Pick an
  order once (`claude`: `name`, `description`, `tools`, `model`; `antigravity`:
  `description`, `model`) and never vary it by config state — the key is either present in
  its fixed position or absent.
