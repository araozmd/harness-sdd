# Worker roster: invocable CLIs as versioned data — Tasks

> Atomic, sequential steps. Work top to bottom, one at a time. Each names the R-id(s) it
> satisfies. The whole feature lives in `harness-install.sh` plus one new test suite.

- [ ] **T1** (R5, R6, R7) — Add the `WORKER_INVOKE` table to `harness-install.sh`, **after
      the closing `"` of `HOST_MARKERS`, never above it**: one row per agent key,
      `<key> <command-name> [<capability> …]`, carrying **only** non-derivable capabilities.
      Seed the five rows from the plan's table.
- [ ] **T2** (R5, R6, R7) — Add the provenance comment directly above the new table, headed
      `# WORKER_INVOKE PROVENANCE` — **not** a bare `# PROVENANCE` line, which
      `tests/test_agents_host.sh` uses to open its positional host-evidence range (see the
      plan's DO NOT TOUCH). For every `non-interactive` claim, record the entrypoint it was
      verified with. Record `gemini` explicitly as **unverified, no claim**, with the reason —
      an unverified row is the defect `HOST_MARKERS` R8 exists to prevent.
- [ ] **T3** (R1, R2) — Add `worker_roster_enabled()`: read `workers.roster` from
      `harness.config.yaml`; return true **only** on the literal `true`. Absent, `false`,
      empty and unrecognized all return false.
- [ ] **T4** (R12) — Add `worker_roster_is_symlinked()`, mirroring
      `escalation_arming_is_symlinked`.
- [ ] **T5** (R5, R6, R7, R8) — Add `worker_roster_detect()`: for each key in `AGENT_KEYS`
      order, test its command with `command -v <name> >/dev/null 2>&1`; skip the key when it
      does not resolve. **Use the lookup as a boolean and discard its stdout** — the entry
      records no path (R5, spec → *Recorded decision 4*), so do not capture, canonicalize or
      store what `command -v` printed; that value is relative under a relative `PATH`
      component, is environment-derived JSON content, and re-importing it re-opens six closed
      review findings. Then derive `harness-selected` from membership in `SELECTED` (the tag
      reports selection, not a successful stamp — do NOT try to prove the glue was written) and
      `host-detectable` from having a `HOST_MARKERS` row; union with the table's non-derivable
      tags; sort the result. **No rostered CLI is executed** — a `PATH` lookup only. **Do NOT
      filter the loop by `agent_selected`** — that is what `write_escalation_arming` does and it
      is the one thing the roster must not copy (plan → *The `agent_selected` trap*). Selection
      is a capability, never a filter; an unselected but installed CLI still gets an entry.
- [ ] **T6** (R4, R5, R9) — Add the emitter: `schema: 1`, `generated_by`, the sorted
      `capability_vocabulary`, then `workers[]` in `AGENT_KEYS` order, each entry carrying
      `key`, `command` and `capabilities` — **and no `path`**. Output must be valid JSON and
      byte-stable across runs with identical inputs. Emit `generated_by` as the **fixed literal**
      `harness-install.sh`, never `$0` — an invocation-dependent path is both environment-derived
      JSON content and a fourth R9 input. **No JSON escaper is required and none should be
      added**: every value emitted here is a harness-authored literal (`AGENT_KEYS`, the
      `WORKER_INVOKE` table, the fixed vocabulary, that one constant), so an escaper would be
      code no fixture can distinguish from its absence — see plan → *JSON emission*. Instead,
      leave a comment beside the emitter stating that invariant and that any future
      environment-derived field re-incurs class-wide escaping (`tools/change-size.sh`'s
      `_json_escape`, the E99-F08 artifact — never `tools/pr-round-trend.sh`'s two-character
      `sed`). Structure still needs care: no trailing comma after the last `workers[]` entry,
      and a well-formed `"workers": []` when nothing resolves.
- [ ] **T7** (R1, R2, R3, R10, R12) — Add `write_worker_roster()` wiring T4→T3→T5→T6 in that
      order: symlink ⇒ warn and return, touching nothing; gate off ⇒ remove an existing roster
      and `info` the reclamation; gate on ⇒ overwrite from freshly detected state. Call it
      from `install_one`.
- [ ] **T8** (R11) — Add `workers.json` to the `_ignores` list that seeds/ensures
      `.harness/.gitignore`, alongside the telemetry log.
- [ ] **T9** (R1, R2) — Add the `workers:` block to `migrate_config` (append-only, following
      the `telemetry:` case) and to `harness.config.yaml` with `roster: false` plus the
      comment explaining the opt-in and the local-only/gitignored contract. The two texts must
      be **byte-identical** — a fresh install copies the config verbatim while an upgrade only
      migrates, and this repo tests that they converge.
- [ ] **T10** (R1, R11) — Extend `tests/test_install.sh` to assert the installer generates the
      roster wiring and the `.gitignore` entry, **and that the seeded and migrated `workers:`
      blocks are byte-identical**. **Every new installer-generated artifact must be asserted
      there** — this has been a repeat review finding, do not skip it.
- [ ] **T11** (R1–R12) — Write `tests/test_worker_roster.sh` per `E17-F04.tests.md`. It is
      auto-discovered by `tools/run-tests.sh`; sandbox `HOME`/`CODEX_HOME` and use per-case
      `mktemp` fixtures like every other suite. **Sandbox `PATH` too** — the suite has to
      control which CLIs appear present.
- [ ] **T12** — Bump `VERSION` (MINOR — new backward-compatible capability in the installed
