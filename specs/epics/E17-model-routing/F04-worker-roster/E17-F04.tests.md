# Worker roster: invocable CLIs as versioned data — Test Contract

> Every R-id maps to a concrete test. The Reviewer fails the feature if any R-id lacks a
> passing test. All cases live in `tests/test_worker_roster.sh` unless noted.
>
> **The suite controls `PATH`.** Presence is the variable under test, so each case builds a
> `mktemp` bin directory holding stub executables for the keys it wants present and sets
> `PATH` to it. A case that inherits the developer's real `PATH` tests that machine, not the
> requirement. Stubs exist to be **found**, never run — see R8.

## How the harder cases must be written

These are the four that a plausible-looking test would fail to actually verify. Getting them
wrong is how a green suite ships a broken requirement.

- **R8 — a negative requirement needs a test that can catch a violation, AND an anchor.**
  Asserting the installer exits 0 proves nothing. Each stub on the sandbox `PATH` must be an
  executable that **records that it ran** (append its own name to a witness file) and exits
  non-zero. After the install, assert the witness file **does not exist**. A stub that merely
  exits 0 would let an implementation calling `<cli> --version` pass.
  **Anchor the negative assertion to a run that provably reached the detection path.** "The
  witness file does not exist" is equally true when the sandbox `PATH` was misconfigured, the
  gate was off, or the roster code never ran at all — an assertion satisfied by a second path
  proves nothing about the first. So the same case must also assert that
  `.harness/workers.json` exists and contains the stubbed keys.
- **R9 — byte-identity, not equivalence.** `cmp -s run1.json run2.json`, not a field-by-field
  comparison. Ordering bugs (`AGENT_KEYS` order vs detection order, unsorted capabilities) are
  precisely what a semantic comparison hides, and R9 exists because of them.
- **R10 — the fixture's first roster must be DISTINGUISHABLE from a correct one.** Seed a
  roster containing a key whose command is **not** on the sandbox `PATH`, then re-run with the
  gate on and assert that key is gone. Seeding a roster that already matches the expected
  output makes the assertion pass whether or not anything was overwritten, which proves
  nothing.
- **R2 — enumerate the permitted deltas; do not assert "nothing changed".** The gate-off
  target is **not** byte-identical to a pre-feature target and cannot be: the installer seeds
  the documented `workers.roster: false` key, and `_ignores` is unconditional so the
  `.gitignore` line appears too (which is why R11 is ubiquitous). A test that asserts "no
  other installer output changed" therefore **fails a correct implementation**, and the Builder
  would resolve that by weakening the test or deleting the config key — one defeats the test,
  the other defeats R1. So: install with the gate off, and assert no `workers.json`, plus the
  two named deltas present, plus nothing else added.

Four further traps, from the same family — the last two were added after the doc-critic pass
found that nothing in the suite varied the selection or the capability evidence:

- **R3 vs R12 must be independently reachable.** The symlink guard runs *before* the gate, so
  a symlinked roster with the gate off must be **left in place**, not reclaimed. Add that as a
  control inside `R12_symlink_is_refused` — otherwise an implementation that checks the gate
  first passes both tests while deleting a symlink it should never touch.
- **R6 needs a control that fires.** Pair "key absent from `PATH` ⇒ no entry" with the same
  fixture plus that one stub added, asserting the entry appears. Silence on a fixture that
  could never have produced an entry proves nothing — the discipline
  `tests/test_board_spec_consistency.sh` already applies to every rule expected to stay quiet.
- **R5's selection case is the only thing standing between this feature and a silent bug.**
  `write_escalation_arming` filters its `AGENT_KEYS` loop with `agent_selected`; the roster
  must not, and a roster that wrongly copies that filter is **byte-identical to a correct one
  on any machine where everything is selected**. So `R5_unselected_cli_is_still_rostered` must
  install with a narrowed selection (e.g. `--agents=claude`) while stubs for at least two
  other keys sit on the sandbox `PATH`, and assert those keys still have entries — carrying
  `host-detectable`/`non-interactive` as earned, but **not** `harness-stamped`. Without this
  case nothing in the suite varies the selection, and the bug ships.
- **R7 must test presence AND absence per tag.** The closure check
  (`R7_capabilities_are_closed`) is satisfied by an implementation that emits an empty
  vocabulary and empty capability lists everywhere, so on its own it verifies nothing about
  the derivation rules — which is where all the feature's real content lives.
  `R7_each_tag_tracks_its_evidence` pairs each tag with a key that has its evidence and a key
  that does not: `host-detectable` on a key with a `HOST_MARKERS` row vs `gemini` (which has
  none), `non-interactive` on `codex` vs `gemini`, `harness-stamped` on a selected vs an
  unselected key. `non-interactive` is the one genuinely new fact the `WORKER_INVOKE` table
  exists to record, and nothing else in the suite asserts it.

## Behavioral / end-to-end checks

- Install into a scratch target with `workers.roster: true` and a sandbox `PATH` holding
  stubs for `claude` and `agy` only. Confirm `.harness/workers.json` parses, has `schema: 1`,
  holds exactly two entries in `AGENT_KEYS` order, `gemini` is absent, and `claude` carries
  `host-detectable` while a key with no `HOST_MARKERS` row does not.
- Re-run that install with `--agents=claude`. Confirm `antigravity` still has an entry (it is
  installed on this machine), and that its capabilities lost `harness-stamped` while keeping
  what it earned. This is the umbrella/selection distinction the whole design turns on.
- Flip `workers.roster` back to `false`, re-run, and confirm the file is gone and the
  reclamation was reported.
- Confirm `git status` in that target is clean — the roster must be ignored, not untracked
  noise (R11).
