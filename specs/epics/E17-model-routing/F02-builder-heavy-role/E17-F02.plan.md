# The `builder-heavy` role — Technical Plan

## Shape

Two kinds of change. The first is additive plumbing that the existing generators absorb; the
second is the one real defect (§6), which must land **before** the OpenCode member is added or
the feature is untestable on an upgraded target.

| 1 | `agents/builder-heavy.md` | New. Thin pointer at `agents/builder.md`. |

| 3 | `harness-install.sh` `MODEL_ROLES` | One name. |

## 1. `agents/builder-heavy.md`

The `.claude/agents/` mirrors in this repo are the established pointer shape. The body names
`agents/builder.md` as canonical and says why the second name exists, so a reader who arrives
at the heavy variant learns the rule (ADR-0002) rather than inferring it from a stub. It must
contain **no instruction text of its own** — that is R1, and it is what stops the drift
ADR-0002 rejected option 2 over.

## 2–3. Config + `MODEL_ROLES`

`models:` grows `builder-heavy: inherit   # try: reasoning`, placed directly after `builder:`
so the pair reads together. The line exists **twice** — `harness.config.yaml` (copied verbatim
on a fresh install) and the `migrate_config` heredoc (the block seeded when absent) — and
E17-F01's own test note is explicit that missing either makes fresh and upgraded targets
diverge. `MODEL_ROLES` gains the bare name; `models_any` and the diag de-dup follow for free.

## 4. `ag_personas()`

One row:

```
builder-heavy	The Implementer at the escalation tier. Same discipline and same instruction body as `builder`; differs only by the model it resolves to.
```

This single row is consumed by six call sites — Antigravity install + reclaim, Gemini install +
reclaim, Codex install + reclaim — which is why the table exists. **No generator is added.**

## 5. Claude

`emit_agent builder-heavy "Read, Write, Edit, Bash, Grep, Glob" "<the ag_personas wording>"`,
with the tool list copied **exactly** from `builder` — a different tool list would be a
behavioral difference, which ADR-0002 forbids. `HARNESS_CLAUDE_SHIMS` gains the stem so
deselect can reclaim it.

## 6. The OpenCode stamp — the defect fix

Today (`harness-install.sh` §5g):

```sh
if grep -q '"model":' "$TARGET/opencode.json"; then
  cp "$TARGET/opencode.json" "$H/.opencode.stamp"
else
  rm -f "$H/.opencode.stamp"          # ← the bug
fi
```

The `else` branch rests on "a model-free body is already reproducible from
`gen_opencode_json`", which is true only for the installer version that wrote it. Replace both
branches with an unconditional `cp`: the stamp records **what we last wrote**, which is the
only thing that can prove ownership across a shape change.

The two comparison sites then need no change at all — §5g's re-stamp test and §7's removal
test both already consult `.opencode.stamp` first and fall back to a freshly generated body.
Making the stamp always present is what makes that first arm fire. The fallback arm stays, and
stays load-bearing: it is what lets a target installed *before* this release still be
recognised, because for that target the freshly generated legacy body no longer matches — so
the fallback covers the pre-stamp generation exactly once, on the run that creates the stamp.

Ordering matters. **The stamp change must be its own commit, landing before the
`gen_opencode_json` member is added** (T5 before T6). Landed together, an upgraded target's
first run compares a 6-role file against a 7-role reference with no stamp yet on disk, and the
warning path fires anyway — the fix would be inert on precisely the targets it exists for.

Comment and doc consequences: `docs/INSTALL.md:32` and `:721` and the installer manifest at
`harness-install.sh:2573` all describe the stamp as "model routing only". They become "the
last generated body", which is what it now is.

## 7. `gen_opencode_json`

One `_oc_m_builder_heavy="$(_oc_model builder-heavy)"` and one member, placed immediately
after `builder` to match the config ordering. The surrounding column alignment is cosmetic but
the file is compared byte-for-byte, so the member is written once and never reformatted.

`gen_oc_agent` (the file-based `.opencode/agent/<role>.md` path) is **not** touched: it exists
only for the gated `pr-fixer`, which is deliberately outside `MODEL_ROLES`.

## Risks

- **A count assertion left at six does not fail loudly.** It pins the old set while the
  installer emits seven. The brief flags this; the by-name requirement in R10 is the structural
  answer, and the mutation battery proves it.
- **`opencode.json` is compared byte-for-byte in four places.** A stray whitespace change to
  the `agent:` map makes every installed target's file read as edited. The new member is
  written once, in one function, and never re-indented.
