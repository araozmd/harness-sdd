## Anti-tautology

Five specific ways these cases could pass while proving nothing, and what stops each:

- **A count of seven is satisfied by any seventh file.** The reclaim bug this suite guards
  against leaves a *stale* artifact behind, which a `= "7"` assertion happily accepts. Every
  amended count assertion is therefore paired, in the same run, with a by-name check that
  `builder-heavy.<ext>` is the seventh — and, in `deselect_reclaims_builder_heavy`, with the
  assertion that the directory is back to six *named* files.

- **R5's "no warning" is an absence assertion.** Its positive control is
  `opencode_edited_file_is_still_refused`, run against the **same** installer in the **same**
  suite: one target upgraded clean, one target with a real user edit refused with the warning
  and left byte-identical. Without the second case, deleting the pristine check entirely would
  pass R5.

- **A not-byte-exact legacy candidate fails exactly like the bug.** During specification the
  first hand-built legacy body differed by one blank line, and the run was indistinguishable
  from the fix not working — same warning, same six roles. `opencode_upgrade_gains_the_new_role`
  therefore asserts the *positive* outcome (seven roles by name, stamp created, regeneration
  message) rather than merely the absence of the warning, so a silently-wrong candidate cannot
  pass by producing no output.

- **R5's fixture must genuinely be a previous-release file.** A fixture hand-written to look
  six-role proves nothing about what the shipped installer produced. The case builds it by
  installing from a **`git archive` of the merge-base commit** into a scratch source tree, and
  asserts the precondition that the resulting `opencode.json` has exactly six `agent:` keys and
  no `builder-heavy` **before** upgrading. If that precondition does not hold, the case fails
  rather than silently testing nothing.

- **R1 could pass on an empty file.** "Contains no instruction text" is trivially true of a
  stub. The case asserts both directions: the file **does** name `agents/builder.md`, and it
  does **not** contain a body line that `agents/builder.md` also contains — computed against
  the real Builder body in the same run, not a hardcoded string that drifts.

- **R3 could pass because nothing resolved at all.** The case's positive control is the same
  config with `default: cheap`: `builder-heavy` must then resolve to the cheap alias, proving
  the fall-through path is live and not merely silent. It then asserts the re-run left
  `harness.config.yaml` byte-identical.

## Mutation proof (required before the PR is opened)

Each mutation is applied to the **committed** implementation, one at a time, `git diff --stat`
checked to confirm it actually applied, the suite run, then reverted with `git checkout --` and
`git status` verified clean before the next.

| mutation | must fail |
|---|---|
| drop the derived legacy candidate from the §5g pristine test | R5 |
| drop the derived legacy candidate from the §7 removal test | R6 |
| revert the `.opencode.stamp` write to the `grep -q '"model":'` conditional | R5 (second run / idempotence) |
| widen the pristine test to accept anything (`true` in place of the `cmp` chain) | R5a |
| drop the `builder-heavy` member from `gen_opencode_json` | R4, R5 |
| drop the `builder-heavy` row from `ag_personas` | R4 (codex/gemini/antigravity), R7 |
| drop `builder-heavy` from `MODEL_ROLES` | R9 |
| drop `builder-heavy` from `HARNESS_CLAUDE_SHIMS` | R7 (claude) |
| drop the `emit_agent builder-heavy` call | R4 (claude) |
| omit `builder-heavy: inherit` from the `migrate_config` seed heredoc | R2 |
| make `resolve_model` return the `builder` tier for `builder-heavy` | R9 |
| replace each amended by-name check with a bare count of seven | R10 |

A surviving mutation is treated as a signal that the **rule** is under-specified — an
unconstrained degree of freedom in the implementation — not merely that the test is thin.
The last row is deliberate: it is a mutation of the *test suite*, and it must fail, because R10
exists precisely to make counting insufficient.
