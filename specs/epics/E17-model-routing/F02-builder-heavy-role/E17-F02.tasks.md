# The `builder-heavy` role — Task Breakdown

Ordered so each task leaves the tree green. One commit per task.

**T5 and T6 ship together, and T5 has two halves that are useless apart.** Widening the
pristine test by a derived legacy candidate is what lets an already-installed target accept the
new shape; making the stamp unconditional is what stops that candidate list from growing at
every future role addition. The unconditional stamp *alone* is inert — reproduced against the
merge-base installer. See the plan's §6.

- [x] **T1 — The pointer body.**
      `agents/builder-heavy.md`: a thin pointer at `agents/builder.md` naming ADR-0002 as the
      reason a second name exists. No instruction text of its own. Covers **R1**.

- [x] **T2 — Config, both copies.**
      `harness.config.yaml` **and** the `migrate_config` seed heredoc in `harness-install.sh`
      gain `builder-heavy: inherit   # try: reasoning`, directly after `builder:`. Missing
      either makes a fresh target and an upgraded one diverge. Covers **R2**.

## Verification gate

`sh tools/run-tests.sh` (32 suites — this feature adds `test_builder_heavy.sh`) + `sh tools/change-size.sh`. Suites must also pass under
`dash`, since CI `/bin/sh` is dash. `dash tests/test_pr_loop.sh` fails at `R22 … (got 126)`
**pre-existing on main**.

## Standing constraint

`tests/test_next_task.sh` runs `git diff --quiet` on `store/tasks.schema.json`,
`tools/task-diagnostics.py` and `init.sh` — the suite fails on any *uncommitted* change to
those. This feature touches none of them, but commit before re-running if that changes.
