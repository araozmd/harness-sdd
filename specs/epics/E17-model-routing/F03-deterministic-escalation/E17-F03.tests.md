## Anti-tautology

- **A truth table can be satisfied by a constant.** `builder` is the answer in most cells, so
  a tool that ignored its arguments entirely and always printed `builder` would pass a
  carelessly chosen table. Every case therefore asserts **both** outcomes, and
  `the_truth_table` fails if the set of distinct answers it observed is not exactly
  `{builder, builder-heavy}` — a constant implementation cannot produce both.

- **R7's "no warning" is an absence assertion.** Its positive control is
  `unknown_value_is_coerced_and_reported` in the same run: one invocation must produce
  **empty** stderr, another must produce a **non-empty** advisory. Asserting silence alone
  would also pass against a tool that never writes to stderr at all, which would defeat R2.

- **`0` must disable, not invert.** `round > 0` is true for every round ≥ 1, so the naive
  implementation turns the off-switch into always-escalate — passing any test that only
  checked "0 behaves differently from 2". The case asserts `builder` at rounds 1, 2, 3 **and**
  99, and pairs it with threshold 2 at round 99 returning `builder-heavy` in the same run, so
  "always standard" cannot pass either.

- **The boundary is off-by-one bait.** `round > n` and `round >= n` differ by exactly one
  rejection, and either passes a test that samples only round 1 and round 9. `threshold_boundary`
  pins n=2 from both sides: round 2 ⇒ `builder`, round 3 ⇒ `builder-heavy`.

- **R9 must beat a *reachable* heavy answer.** Asserting `delegate` ⇒ `builder` proves nothing
  if the other inputs would have said `builder` anyway. The case passes `complex` at round 99
  with threshold 2 — inputs that return `builder-heavy` under `in-session` **asserted in the
  same run** — so the delegate arm is shown to override a genuinely reachable escalation.

- **R12's "returns builder" is satisfied by escalation being broken outright.** The case's
  positive control runs first and in the same invocation set: the *identical* inputs must
  return `builder-heavy` once opted in. Only then does the off config's `builder` mean
  "declined" rather than "escalation never worked".

- **The leak check must not match the tool's own output.** "The rule does not infer model
  resolution" was first written as a grep for `builder-heavy|models|pin\.` over the
  non-comment source — which the tool fails by *printing* `builder-heavy` and by naming
  `models.builder-heavy` and `pin.<front-end>.<tier>` in the advisory it writes for a human.
  Narrowed to the thing actually forbidden — reading the `models:` section
  (`_cfg_scalar models`) — and paired with a control asserting it still reads `escalation`,
  so the check cannot pass because the reader was deleted entirely.

- **Only the tag is declined out loud.** A `complexity: complex` spec that does not escalate
  must report, because the operator expressed intent. The round arm stays **silent** while
  escalation is off: with no threshold configured there is no round it "would have" exceeded,
  and warning anyway would put a line on every build of every target that never opted in.
  Both directions asserted, so neither silence nor noise can pass unnoticed.

- **R6's upgrade path is where the last feature was caught.** Seeding only the shipped config
  makes a fresh target and an upgraded one diverge, and nothing else in the suite would
  notice. The case installs, **strips the `escalation:` block**, re-installs, and asserts the
  key is back — the same shape as `test_install.sh`'s `models:` migration case.

## Named gap — the prose half

`prose_records_the_choice` and half of `telemetry_contract_intact` are **role-content
assertions**: they grep `agents/*.md` for required clauses. That proves the instruction is
present. **It does not prove a running Orchestrator obeys it** — the same limitation
`tests/test_reviewer.sh` records for its own prose-only feature, where the behavioral
criterion is a documented manual check.

Stated here rather than left implied. Putting the rule in `tools/builder-role.sh` is what
shrinks this gap: the *rule* is executable and mutation-tested, so only the **call site**
rests on prose, instead of the whole decision procedure.

## Mutation proof (required before the PR is opened)

Applied to the **committed** implementation, one at a time, `git diff --stat` checked to
confirm each actually applied, reverted with `git checkout --` and `git status` verified clean
between runs. (Committing first is not optional — a mutation against an uncommitted fix
destroys it.)

| mutation | must fail |
|---|---|
| `round > n` → `round >= n` | R3 boundary |
| `0` disables → `0` treated as an ordinary threshold | R6 zero-disables |
| drop the `delegate` early return | R9 |
| out-of-vocabulary value → treated as `complex` | R2 |
| out-of-vocabulary value → non-zero exit | R2 (never fails the build) |
| drop the advisory line on coercion | R2 / R7 control pair |
| default threshold 2 → 3 | R3 truth table |
| omit `escalation:` from the `migrate_config` seed | R6 upgrade path |
| return a constant `builder` | R3 (distinct-answers assertion) |
| emit `phase: "builder-heavy"` in the documented record | R11 |
| default `after_rejections` back to a positive value | R6 fresh+upgrade seeding |
| let `0` leave the `complexity` trigger live | R6 zero-disables |
| drop the advisory on a declined `complex` tag | R12 |
| re-introduce a `models:`-reading arming check | R12 (no-inference) |

A surviving mutation is treated as a signal that the **rule** is under-specified, not merely
that the test is thin.
