# Docs for humans, slice 1 — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E39-F01:R1 … E39-F01:R12`.
> This is the **first of five slices** of epic E39. It ships the foundation (README, CONCEPTS,
> brand, the `docs/agents/` layer and its index) and, above all, the **conventions and tools**
> that F02–F05 reuse to split `INSTALL.md`, `WORKFLOW.md`, `UMBRELLA.md`, `SPEC-FORMAT.md`,
> `CONFIG-LAYERING.md`, `HARNESS.md`, `ABLATION.md` and `BASELINE-0.78.1.md`. The slice plan is
> in *Business rules → Slice plan*.

## Context

Two readers share one text. A human evaluating, installing or operating the harness opens a
546-line `README.md` and about 4,000 lines of `docs/` that grew by appending a contract every
time a review found an edge case. Agents and tests need exactly that detail: **56 test suites**
grep these files for pinned phrases (`docs/WORKFLOW.md` 34 suites, `README.md` 27,
`docs/INSTALL.md` 18, `docs/SPEC-FORMAT.md` 8, `docs/RATIONALE.md` 7, `docs/HARNESS.md` 6,
`docs/UMBRELLA.md` 5, `docs/CONFIG-LAYERING.md` 2; `ABLATION.md` and `BASELINE-0.78.1.md` 0),
and the role prompts, `AGENTS.md`, the installer's printed hints and three `tools/*.py`
docstrings cite doc sections by heading. The brief (`progress/inbox/E39-F01.md`) chose a
separate **`docs/agents/`** directory as the machine layer, Mermaid for diagrams, an abstract
triangle-loop logo (`assets/logo.svg`, already placed), and — after intake — the brand name
**harness-loop**. Nothing installed is renamed: `.harness/`, `harness-install.sh`,
`harness.config.yaml`, `/sdd-*` and every other installed path keep their names under the new
brand.

This slice touches only `README.md` and new files, so it can land first and define the rules
the heavier slices follow. Its measured coupling: 27 test files mention `README.md`, of which
**21 read the source README** (the rest name fixture or target READMEs); those 21 split into
**12 whose token stays in the human README** (command names, CLI names, the two `RATIONALE.md`
link texts, the `#bootstrap-first-run` anchor, `--agents=host`, the ADR sentence) and **9 that
pin contract sentences** which move verbatim to `docs/agents/README.md` and are re-pointed by a
path-only edit (table in the plan). The installer needs no change for the layer itself —
`docs` is one entry of `HARNESS_BODY_PROSE`, copied with `cp -R`, and the thin-child stub
tier recurses into it — so a new subdirectory ships to every target by construction; the
version still bumps MINOR because the installed body gains files and two tools.

`specs/architecture.md` is absent in this repository; the ADR set under `specs/adr/` is present,
so the `## Architecture alignment` section below cites it (graceful degradation per
`agents/architect.md`). Stage is `production` (`specs/product.md`).

## Business rules

**Decisions (the brief's open questions, resolved).**

- **D1 — Layout: one machine file per human doc, same basename.** The counterpart of
  `docs/<NAME>.md` is `docs/agents/<NAME>.md`; the counterpart of the repository `README.md` is
  `docs/agents/README.md`, which also carries the layer's announcement, index and conventions.
  Per-topic files (`exit-codes.md`, `env-vars.md`) were rejected: tests slice sections by
  heading inside one file and assume adjacency (`span FILE '## A' '## B'`), so a per-topic
  scatter would force assertion rewrites, and a per-doc mirror keeps every re-point a pure
  path substitution and gives each later slice a disjoint file set. Harness docs are
  `docs/UPPER-CASE.md`; a lowercase `docs/x.md` in a citation is an external doc (pi's
  `docs/security.md`), never a harness doc — the citation lint relies on this.
- **D2 — `docs/history/` archives measurements.** `docs/BASELINE-0.78.1.md` moves verbatim to
  `docs/history/BASELINE-0.78.1.md` in F05 (0 suites cite it). The convention is declared
  here so every slice knows where history goes.
- **D3 — `RATIONALE.md` and `ABLATION.md` are not folded into CONCEPTS.** `RATIONALE.md`'s
  section list, ledger shape and "no images, no Mermaid" rule are pinned by
  `tests/test_rationale_docs.sh`; it already is the durable record of *why*, and CONCEPTS
  summarises it in plain language and links to it. `ABLATION.md` is the maintainer's
  measurement protocol and stays a human doc (trimmed in F05, no diagram required).
  `HARNESS.md` folds into CONCEPTS in F05 and remains as a ≤20-line pointer page (6 suites
  and the installed `AGENTS.md` map name it).
- **D4 — Regression lint: yes, three pieces.** A permanent suite (`tests/test_docs_for_humans.sh`)
  enforces the human-doc style rules on a registry of converted docs; `tools/doc-cite-check.py`
  resolves every doc citation (path and heading) in the role prompts, entrypoints, installer and
  tools; `tools/docs-move-check.sh <base-ref>` is the pre-PR proof that no contract vanished
  (every backticked token in a human doc at base survives somewhere in the doc set at head,
  and every removed contract-bearing line was moved, not dropped).
- **D5 — `assets/` does not ship.** It is repository branding; `HARNESS_BODY_PROSE` is
  unchanged. Because `docs/` ships and `assets/` does not, no file under `docs/` may carry a
  relative Markdown link, reference definition, image target or HTML `src`/`href` into `assets/` (a code-span mention
  such as `` `assets/logo.svg` `` is fine). The one exception is `docs/BRAND.md`, which may embed
  art by an absolute canonical URL — `https://raw.githubusercontent.com/araozmd/harness-loop/main/assets/…`
  or `https://github.com/araozmd/harness-loop/blob/main/assets/…` — which resolves in an installed
  target once the file is on `main`. The repository README is not shipped and embeds the art by
  relative path.
- **D6 — Brand.** Name `harness-loop`, a single token. It appears in exactly three
  authored sites — the README heading (the wordmark image's alt text), `docs/BRAND.md` and the wordmark SVG — and the tagline is
  authored once in `docs/BRAND.md` and copied byte-for-byte into the README (the suite compares
  them), so a rename or re-tag is a three-site edit. Positioning: *fast and safe — the gates are
  what make autonomous speed safe*. The working tagline is the human's:
  `Autonomous agents, safely: every change is independently reviewed before it merges.` (the
  name is not repeated: the wordmark heading above it carries it). It claims only what the process does (spec, gate, review); no speed numbers.
- **D7 — Art is an input, not a task.** `assets/logo.svg` exists; `assets/logo-wordmark.svg`
  and `assets/social-preview.png` (1280×640) are produced by the Orchestrator with Recraft and
  placed in `assets/` before the Builder's R11 task; an optional hero illustration may join
  them. The Builder never generates images; a missing input blocks T11b, not the slice.

**The conventions (C1–C8).** Written once, in `docs/agents/README.md` → `## Conventions`, and
followed by every E39 slice:

- **C1 Layout** — as D1/D2.
- **C2 Move verbatim** — contract text moves at paragraph granularity; a moved section keeps
  its heading line byte-identical and its body byte-identical **except** the target of a
  relative Markdown link, which may be retargeted so it resolves from the new location (link
  text, code spans and everything else are unchanged). Never paraphrase a moved sentence. A
  human doc may keep a plain-language restatement, but the exact sentence lives in the
  counterpart and the test points there.
- **C3 Path-only re-point** — a test assertion or a citation that pinned moved text changes
  **only the path** (`docs/X.md` → `docs/agents/X.md`); the pattern, the fail message and the
  anchor are untouched. Never weaken an assertion to make it pass.
- **C4 Prove it before the PR** — `tools/docs-move-check.sh <base-ref>` exits 0 (no vanished
  token) and `tools/doc-cite-check.py` exits 0; the Reviewer reruns both.
- **C5 Human style** — plain language, one idea per paragraph, imperative steps; a line budget
  per doc (README 150, `docs/README.md` 60, CONCEPTS 220, BRAND 90; default 300 for a doc a
  later slice registers, any override recorded in the registry with a reason); at least one
  Mermaid diagram where a flow, state machine or structure is described; none of the filler
  phrases in R6; no incident archaeology (no feature ids `E##-F##`, no review-comment ids, no
  "round N", no reviewer attributions such as `Codex r3` or `Codex #…` — the CLI name itself is
  fine) — those stay in the counterpart.
- **C6 Navigation** — a human doc links its counterpart within its first 15 lines; the index
  in `docs/agents/README.md` lists every `docs/agents/*.md`; every relative link under
  `README.md` and `docs/**` resolves.
- **C7 Shipping** — as D5, including the `docs/BRAND.md` exception for absolute canonical URLs.
- **C8 Brand** — as D6; installed names never change.

## Architecture alignment

- ADR-0004 — A child resolves the harness body through pointer stubs at the same paths: the
  machine layer rides the existing `docs` prose-tier entry (a nested directory under it), so a
  thin child receives `docs/agents/*` as stubs at the same paths and a full copy receives the
  files; no new tier entry, no installer change for the layer.
- ADR-0005 — Source-only surfaces are emitted only by `--self`: `assets/`, `README.md` and
  `docs/BRAND.md`'s image inputs are repository-only and are never emitted into a target; the two
  new tools ship in `tools/` like every other body tool and emit nothing.
- ADR-0008 — Vertical slices; red/green pairs: the epic is sliced by human doc (each slice
  observable as "this doc reads short and every pinned phrase still resolves"), and the tasks
  file pairs one failing test with each R-id.

## Accepted trade-offs

> Doc-critic checkpoint: first pass 1 `could-not-restate` (fixed: the nine commands are now
> enumerated), re-audit none. The entry below is a design trade-off recorded for the gate, not
> a cold-reader leftover.

- README-origin operator text (store configuration, telemetry, board mirror, source layout)
  lands in `docs/agents/README.md` by the provenance rule C1 even though some of it is operator

## Open questions

- The Elephant–Goldfish wording in `docs/CONCEPTS.md` (R5): the spec pins the section heading
  and the two mechanisms it must name (paraphrase-back, drift report); the human may prefer a
  different metaphor sentence — edit at the gate, the test does not pin the prose.
- Tagline refinement (D6): the Builder copies the human's working tagline; a refinement is a
  one-line edit in `docs/BRAND.md` plus the README copy.
