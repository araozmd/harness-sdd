# Docs for humans, slice 2: INSTALL split — Functional Spec

> R-ids in this document are `R1 … R11`; their fully-qualified form is `E39-F02:R1 … E39-F02:R11`.
> This is the **second of five slices** of epic E39. It follows the conventions **C1–C8** written
> in `docs/agents/README.md` → `## Conventions` by slice 1 (E39-F01) and reuses slice 1's
> machinery — `tests/test_docs_for_humans.sh`, `tools/doc-cite-check.py`,
> `tools/docs-move-check.sh` — without inventing a parallel one. The slice-plan row it
> implements is `E39-F01.spec.md` → *Business rules → Slice plan* → `E39-F02`.

## Context

`docs/INSTALL.md` is 1,511 lines. It is the operator's first stop after the README, and it is
also a contract: **17 test suites** slice it by heading and pin phrases inside the slice
(`tests/test_agents_host.sh`, `test_escalation.sh`, `test_feedback_config.sh`,
`test_feedback_report.sh`, `test_greenfield.sh`, `test_install.sh`, `test_installer_toggles.sh`,
`test_opencode_compat.sh`, `test_pi_agents.sh`, `test_pi_front.sh`, `test_pi_integrity.sh`,
`test_pi_preflight.sh`, `test_pr_loop.sh`, `test_promote.sh`, `test_reporting_rule.sh`,
`test_sdd_fix_parallel.sh`, and the registry/link rows of `test_docs_for_humans.sh`); five of
them read the **installed** copy (`.harness/docs/INSTALL.md`). Two more suites name it only in a
comment (`test_init_drift_guard.sh`, `test_planner_topology.sh`). Outside `tests/`, the file is
cited by six comment lines in `harness-install.sh` (one of them a section pointer,
`docs/INSTALL.md § Per-role model routing`, that `tools/doc-cite-check.py` resolves against a
heading), one comment in `init.sh`, two comment lines in `harness.config.yaml`, fourteen
heading-anchored links from `README.md` and sibling docs (`docs/agents/README.md` ×7,
`docs/HARNESS.md` ×3, `docs/UMBRELLA.md`, `docs/WORKFLOW.md`, `docs/CONFIG-LAYERING.md`,
`docs/BASELINE-0.78.1.md`), and one title pointer in `docs/WORKFLOW.md` (`"Codex reasoning
effort" section`). No role prompt and no `AGENTS.md` row cites it. The installer prints no
hint that names the file; the "printed hints" the slice plan anticipated are comments, and
the only one a lint checks is the `§` pointer.

Measured on `origin/main` (`181fd3a9`, VERSION `0.110.1`): `tools/docs-move-check.sh
origin/main` → `0 vanished tokens, 0 dropped lines, 0 moved lines, 0 human docs examined`;
`python3 tools/doc-cite-check.py` → `0 findings, 59 files scanned`; every heading-anchored
relative link under `README.md` and `docs/**` resolves today (0 stale anchors), which is what
makes an anchor lint (R8) safe to arm. One pointer is already wrong by title, not by path:
`docs/INSTALL.md` line 58 sends the reader to `../README.md` → *Observability*, a section that
slice 1 moved to `docs/agents/README.md` → `## Observability (telemetry)` (carried from the
slice-1 review).

The human reader needs three things from INSTALL: how one repository gets the harness
(and how an umbrella of repositories gets it in one command), what happens when a newer
harness ships (the update check, the two consents, the backup, the proof that their files
survived), and which files are theirs. Everything else — host-marker tables, the feedback
block's resolution grammar, model-routing tiers, self mode, Gemini retirement, the pi
preflight — is exact contract that agents and suites rely on and moves **verbatim** to the
machine layer. The slice-1 review rejected round 1 for a plain-language absolute that was
false (`autonomous: true` and `/sdd-fix` skip the human gate); this slice therefore pins its
human sentences (R5) **and** names the over-claims a rewrite of this doc tends to produce
(an installer that "git inits", an update that "upgrades itself", an "uninstall" that does
not exist).

`specs/architecture.md` is absent in this repository; the ADR set under `specs/adr/` is present
(ADR-0001 … ADR-0011), so the `## Architecture alignment` section below cites it (graceful
degradation per `agents/architect.md`). Stage is `production` (`specs/product.md`).

## Business rules

**Decisions.**

- **D1 — The whole document moves; the human doc is new text.** `docs/agents/INSTALL.md` is
  the 0.110 `docs/INSTALL.md` **entire** — H1, intro paragraph and all 47 `##`/`###` sections in
  base order — with exactly three kinds of difference: an announcement blockquote inserted
  after the H1; relative link targets retargeted so they resolve from `docs/agents/` (C2); and
  the line-58 pointer retargeted (D4). A per-section keep-or-move triage was rejected: the 17
  suites slice sections by heading and assume adjacency, so any section left behind would
  force a per-suite judgment call and a split assertion; moving everything keeps every
  re-point a pure path substitution (C3). The human `docs/INSTALL.md` is written fresh under
  its own headings; the one heading it shares with the counterpart is `## Bootstrap (first run)`,
  kept so the README's `docs/INSTALL.md#bootstrap-first-run` link (a slice-1 kept token) still
  resolves. Two files carrying the same heading is allowed (C2 is about moved text, not
  heading uniqueness across files).
- **D2 — Anchored links follow the heading; plain-path links stay.** A relative link whose
  target is `INSTALL.md#<slug>` points at a specific section, and that section now lives in
  the counterpart; its target becomes `agents/INSTALL.md#<slug>` (from `docs/`) or
  `INSTALL.md#<slug>` (from `docs/agents/`) — a path-only edit, the link text untouched (C3).
  A plain `INSTALL.md` link is navigation to the human guide and stays as it is; the human
  guide links its counterpart in its first lines (C6). The same rule applies to a title
  pointer (`docs/INSTALL.md`'s "Codex reasoning effort" section → `docs/agents/INSTALL.md`'s …).
  This touches one line each in `docs/HARNESS.md`, `docs/UMBRELLA.md`, `docs/CONFIG-LAYERING.md`,
  `docs/BASELINE-0.78.1.md` and two lines in `docs/WORKFLOW.md` — F03–F05 files (seven of the
  fourteen anchored links plus the title pointer; the other seven sit in `docs/agents/README.md`,
  a slice-1 file this slice edits anyway for the index row). Accepted: leaving them would ship
  links that open the right file at the wrong place, and R8 would fail; each edit is a single
  target substitution that F03–F05 move verbatim later.
- **D3 — Anchors become a lint (R8).** Slice 1's `R9_relative_links_resolve` strips anchors
  ("resolve to an existing path"), so a heading that leaves a file leaves no trace. This slice
  adds the anchor check to the same suite with the GitHub slug rule `tools/doc-cite-check.py`
  already implements (lowercase; drop every character not `[a-z0-9 _-]`; spaces → `-`). The
  baseline has 0 stale anchors, so arming it costs nothing and every future move is caught.
- **D4 — The stale line-58 pointer.** In the counterpart the sentence keeps its text and link
  label (C2) and its target becomes `README.md#observability-telemetry` — the sibling
  `docs/agents/README.md`, where `## Observability (telemetry)` now lives — so the trailing
  `→ Observability` title resolves again. The label `../README.md` is kept because C2 forbids
  changing moved text and because that backtick span is a token `docs-move-check.sh` would
  otherwise report as vanished (it occurs nowhere else in the doc set). Recorded under
  *Accepted trade-offs*. The human doc states the telemetry fact in its own words and links the
  same section.
- **D5 — Slice-1 follow-ups: two in, three out.** *In*: **pin the R2/R9 scan sets** (lesson
  2026-11-13 r2: a scan-every-file lint pinned by one planted fixture pins the check, not the
  scan set) — R9 plants one defect per scan-set member; and the **line-58 pointer** (D4). *Out*
  (explicitly, not silently): the stricter README "every change" pin, the "G10 sentence-head
  anchor" and the `/sdd-fix --gated` exception wording — all three live in `README.md` /
  `docs/CONCEPTS.md`, slice-1 files this slice does not touch; they are an E99 fix or a later
  slice's business, and are listed under *Out of scope*.
- **D6 — Accuracy over coverage.** Every behavioral sentence in the human INSTALL is checked
  against the moved contract (the counterpart section named in the plan's *Accuracy table*)
  before it is written; a sentence that cannot be traced is not written. The human doc may
  omit a rule; it may not misstate one. `docs/README.md`'s index line for INSTALL is corrected
  for the same reason: the harness has no uninstall procedure, so the word goes.
- **D7 — No tool changes.** The anchor lint and the scan-set pins live in
  `tests/test_docs_for_humans.sh`; `tools/doc-cite-check.py` and `tools/docs-move-check.sh` are
  unchanged (their fixtures and rows stay green by construction). The two tools are used, not
  edited.

**Conventions.** C1–C8 of `docs/agents/README.md` → `## Conventions` apply unchanged: layout
(C1), verbatim move (C2), path-only re-point (C3), the two proofs before the PR (C4), human
style with the default budget 300 and a required diagram (C5), navigation (C6), shipping (C7 —
the counterpart keeps one moved link to `specs/adr/…`, outside the installed body; it was
already there and is retargeted, not added), brand (C8 — the human doc does not repeat the
brand token; installed names never change).

## Architecture alignment

- ADR-0004 — A child resolves the harness body through pointer stubs at the same paths:
  `docs/agents/INSTALL.md` is one more file under the existing `docs` prose-tier entry, so a
  thin child receives it as a stub and a full copy receives the bytes; no new tier entry and no
  installer change for the layer.
- ADR-0005 — Source-only surfaces are emitted only by `--self`: nothing this slice adds is
  source-only; both INSTALL files ship with `docs/` to every target, which is why the
  five suites that read the installed copy keep reading an installed copy (at the new path).
- ADR-0008 — Vertical slices; red/green pairs: the epic is sliced by human doc; this slice
  is observable as "INSTALL reads short and every pinned phrase still resolves", and the
  tasks file pairs one failing test with each R-id.

## Accepted trade-offs

- `docs/agents/INSTALL.md` telemetry sentence (R1, D4) — the link label still reads
  `../README.md` while its target is the sibling `README.md#observability-telemetry` —
  accepted because C2 forbids editing moved text and the backtick span is a token
  `docs-move-check.sh` would report as vanished; the target and the `→ Observability` title are
  now correct, and the human doc states the fact cleanly.
- Eight single-line edits in five F03–F05 docs (R7, D2: seven anchor retargets and one title
  pointer) — a small overlap with slices that are declared disjoint — accepted because the
  alternative ships links that open the right file at the wrong section, and each edit is one
  target substitution that the later slice moves verbatim.

## Open questions

- Heading wording in the human INSTALL (R2 pins eight `##` headings): the human may prefer
  different words at the gate; a rename is a one-line edit in the doc and in the R2 row, and
  only `## Bootstrap (first run)` is load-bearing (the README anchor).
- Whether `docs/README.md`'s one-word correction (drop `uninstall`, R5) should instead say
  "remove a front-end" — the installer does reclaim deselected glue; the Builder may write
  either, the test only forbids `uninstall`.
