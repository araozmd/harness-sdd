# Docs for humans, slice 2: INSTALL split — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and every row names the mutant that kills it. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives that is not a listed known limit.
>
> **Suite.** The slice-1 suite `tests/test_docs_for_humans.sh` (DH) gains the rows below under a
> `# ---- E39-F02` comment; new row functions are named `F02_R<n>_<slug>` (the `R<n>` is this
> spec's R-id) and the suite's "defined but not dispatched" sweep is widened to see them. The
> house helpers are reused, never duplicated: `slice`, `unfenced`, `folded`, `mermaid_blocks`,
> `has_heading`, `nlines`, `link_targets`, `broken_links`, `mirror`, `registry_each`. Rows that
> mutate a doc copy it under `$T` first and never touch `$ROOT`; the suite never reads `VERSION`
> as a literal and never git-diffs a DO-NOT-TOUCH file against `main`. Exit codes are asserted
> as `rc -eq N`. Installer behaviour (R10 shipping) lives in `tests/test_install.sh`; the move
> proof (R1's `docs-move-check.sh` clause) and the path-only diff (R6) are Reviewer behavioural
> checks because a permanent suite must not diff against `main`.
>
> **Mutants.** Each row names the smallest edit that must turn it RED. The Reviewer's mutation
> campaign applies each one in isolation on a copy (`cp` / `mv …mutbak` discipline from
> `agents/reviewer.md`), confirms the mutation applied (`grep` the planted text first), and
> restores between mutations.

## Behavioral / end-to-end checks

- **Render.** Open the branch on GitHub (or a Mermaid-capable preview): both INSTALL diagrams
  render; no diagram falls back to a code block; the `subgraph` labels and the `[y/N]` prompts
  show as written.
- **Five-minute read.** Read `docs/INSTALL.md` top to bottom. Over five minutes, or any
  paragraph that needs a second read, is a rejection with the paragraph named. Then, for every
  absolute in the doc (`never`, `always`, `nothing`, `every`, `all`, `only`), open the owning
  counterpart section from the plan's *Accuracy table* and confirm the sentence; a sentence the
  contract does not support is a rejection even if the regex pin passes.
- **Move proof.** `sh tools/docs-move-check.sh <base>`: exit 0, `0 vanished tokens, 0 dropped
  lines, <M> moved lines, 1 human docs examined`. Then `diff <(git show <base>:docs/INSTALL.md)
  docs/agents/INSTALL.md`: only the blockquote and the retargeted link lines differ.
- **Path-only diff.** The R6 `git diff -U0 … | uniq -u` command: the only survivors are the new
  DH rows, the widened sweep line, the registry line and the `test_install.sh` loop extension.
- **Citations.** `python3 tools/doc-cite-check.py` at the repo root: exit 0. Then, in a scratch
  mirror, revert the installer's `§ Per-role model routing` comment to `docs/INSTALL.md` and rerun
  with `--root`: exit 1 naming `harness-install.sh`.
- **Install.** `sh harness-install.sh --agents=all <tmp-target>`: both INSTALL files present
  under `<tmp-target>/.harness/docs/` and identical; `sh harness-install.sh --self` leaves
  `git status` clean.
- **Sibling docs.** `git diff --stat <base> -- docs/HARNESS.md docs/UMBRELLA.md docs/WORKFLOW.md
  docs/CONFIG-LAYERING.md docs/BASELINE-0.78.1.md` shows 3/1/2/1/1 changed lines and every
  changed line differs only in a link target or the WORKFLOW title pointer's path.
- **Mutation campaign.** Apply each row's mutant in isolation; every one reds its row; restore.
