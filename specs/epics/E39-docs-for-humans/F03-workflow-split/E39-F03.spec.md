`test_test_drift_check.sh`, `test_waves.sh`); six of them read the **installed** copy
(`.harness/docs/WORKFLOW.md`: `test_escalation.sh`, `test_install.sh`, `test_plan_cite.sh`,
`test_readiness_check.sh`, `test_sdd_next_wave.sh`, `test_stage_nfrs.sh`). Three more suites and

`test_umbrella_11_rollback.sh` and `tests/lib/umbrella/thin.sh`; "the marker files" below);
those stay, because the human doc keeps the path. Outside `tests/`, the path is cited by **28 lines**: two role prompts
(`agents/orchestrator.md` ×2, `agents/fixer.md` ×1), `AGENTS.md` ×3, the `/sdd-next` command
emitter in `harness-install.sh` (one heredoc line, mirrored into three **generated** files —

`docs/CONCEPTS.md`, `docs/HARNESS.md`, `docs/INSTALL.md`, `docs/README.md` ×1 each,
`docs/agents/INSTALL.md` ×2, `docs/agents/README.md` ×4). Our own suite

`tests/fixtures/frontend-v0.78.1/` (10 lines), the board, the changelog and earlier specs are

Measured on `origin/main` (`5d4a5a39`, VERSION `0.111.0`): `tools/docs-move-check.sh origin/main`
→ `0 vanished tokens, 0 dropped lines, 0 moved lines, 0 human docs examined`; `python3
tools/doc-cite-check.py` → `0 findings`; `sh tests/test_docs_for_humans.sh` → all rows pass
(slice 2's anchor lint is armed, so every heading-anchored link under `README.md` and `docs/**`
resolves today). `harness-install.sh`'s `HARNESS_BODY_PROSE` lists `docs`, so both WORKFLOW
files ship to every install and the installed-copy suites keep reading an installed copy.

The human reader needs four things from WORKFLOW: how an idea becomes a task, the feature
state machine (what each status means, who moves it, where the human gate sits, when it is
skipped, what a rejection does and when the heavier Builder takes over), the PR review loop
(what happens between "the Reviewer approved" and "it merged", and when the loop hands the PR
back to a person), and what to do when `/sdd-next` finds nothing. Everything else — the
routing oracle, the ownership and wave rules, the park record and the landing-evidence
decision table, the ADR-citation and stage grammars, the drift and doc-critic checkpoints, the
exact exit codes of `tools/wait-for-codex.sh`, the arming-verdict rules — is exact contract
that agents and suites rely on and moves **verbatim** to the machine layer. The slice-1 review
rejected round 1 for a plain-language absolute that was false ("nothing is built until a human
approves": `autonomous: true` and the `/sdd-fix` lane skip the gate); the slice-2 review round 1
found a spec check command that could not run and plan text that differed from the shipped
wording. This slice therefore pins its human sentences (R5) with each exception stated, names
the over-claims a rewrite of this doc tends to produce ("nothing is built until…", a Reviewer
approval that writes `done`, a loop that "merges automatically", a gate that "always pauses"),
pastes the exact text the Builder ships, and uses only check commands that run on this branch.

`specs/architecture.md` is absent in this repository; the ADR set under `specs/adr/` is present
(ADR-0001 … ADR-0011), so the `## Architecture alignment` section below cites it (graceful
degradation per `agents/architect.md`). Stage is `production` (`specs/product.md`).

## Business rules

**Decisions.**

- **D1 — The whole document moves; the human doc is new text.** `docs/agents/WORKFLOW.md` is
  the 0.111 `docs/WORKFLOW.md` **entire** — H1, all 37 `#`/`##`/`###` headings in base order,
  both existing Mermaid blocks — with exactly two kinds of difference: an announcement
  blockquote inserted after the H1; and relative link targets retargeted so they resolve from
  `docs/agents/` (C2). A keep-or-move triage was rejected for the same reason as in slice 2:
  31 suites slice the doc by heading and assume adjacency, so moving everything keeps every
  re-point a pure path substitution (C3). The human `docs/WORKFLOW.md` is written fresh under
  its own headings; it shares **no** heading with the counterpart (no slice-1 kept token
  depends on a WORKFLOW anchor — the README links the file plain), so two files never carry the
  same slug.
- **D2 — Which citations follow the text (the decision table).** Every citation of
  `docs/WORKFLOW.md` falls in exactly one class; the class decides the disposition:

  | class | shape | disposition | sites |
  |---|---|---|---|
  | anchored link | `WORKFLOW.md#<slug>` | follows the heading → counterpart, path-only | `docs/agents/README.md:156` |
  | section pointer | a path followed by a named section, table or copy — `→ "Title"`, `("Title")`, "for the decision table", "copied exactly into …", "see the state machine in" | follows the content → counterpart | `docs/agents/INSTALL.md:1130`, `agents/fixer.md:65`, `agents/orchestrator.md:40`, `agents/orchestrator.md:588`, `docs/UMBRELLA.md:424`, `docs/SPEC-FORMAT.md:123` (+ its byte-pinned copy in `tests/test_readiness_check.sh`) |
  | agent-facing instruction | an `AGENTS.md` step, a command body, a suite | the reader is an agent and needs the contract → counterpart | `AGENTS.md:25`, `AGENTS.md:44`, `harness-install.sh:6873` (+3 generated), the 31 suites |
  | evidence pointer | `docs/RATIONALE.md`'s ledger column "where it lives" | names where the contract text lives → counterpart (label and target) | `docs/RATIONALE.md:99,105,109,115` |
  | plain navigation link | `[text](WORKFLOW.md)` or "See `docs/WORKFLOW.md`." naming no section, in an index or a human doc | the human guide is the right landing; it links its counterpart in its first lines (C6) → **keep** | `README.md:65`, `docs/README.md:11`, `docs/CONCEPTS.md:82`, `docs/HARNESS.md:57`, `docs/INSTALL.md:197`, `docs/SPEC-FORMAT.md:248` (the state machine and the gate are both in the human doc), `docs/agents/INSTALL.md:377`, `docs/agents/README.md:100`, `docs/agents/README.md:379`, `AGENTS.md:102` (a counterpart row is **added** beside it) |

  | installed-file marker ("the marker files": three suites + one helper) | a path appended to, stubbed or diffed as a file | the file still exists at that path → **keep** | `tests/lib/umbrella/thin.sh:5`, `test_umbrella_05_conversion.sh` ×2, `test_umbrella_07_symlink_compare.sh` ×5, `test_umbrella_11_rollback.sh` ×4 |
  | synthetic fixture | the `mkrepo` docs of `tests/test_docs_for_humans.sh` | not this doc → **keep** | 13 lines |
  | frozen baseline | `tests/fixtures/frontend-v0.78.1/**` | a historical install → **keep** | 10 lines |

  Two sites in a counterpart that is itself moved text (`docs/agents/INSTALL.md:1130`, a
  section pointer that `tools/doc-cite-check.py` would otherwise report, and
  `docs/agents/README.md:156`, a link target C2 allows to move) are edited path-only; the
  first is a C2 tension recorded under *Accepted trade-offs*. The two plain links in moved
  text (`docs/agents/INSTALL.md:377`, `docs/agents/README.md:379`) are **not** edited: C2 is
  kept strict where nothing forces the edit.
- **D3 — Agents read the contract.** `AGENTS.md`'s step 4 and its gate sentence, the
  Orchestrator's "route by status" and landing-record pointers, the Fixer's "Selective SDD"
  pointer and the `/sdd-next` command body all address an agent that must route on the exact
  table; each re-points to `docs/agents/WORKFLOW.md`. The emitter line in `harness-install.sh`
  is the single source of the three generated command files: edit it, run
  `sh harness-install.sh --self`, commit the regenerated files, never hand-edit them
  (`CLAUDE.md`, E26-F01). `AGENTS.md`'s reference table gains a row for the counterpart and
  keeps the human row.
- **D4 — Sibling-doc edits are single lines in later slices' files.** `docs/RATIONALE.md`
  (four lines), `docs/SPEC-FORMAT.md` (one line) and `docs/UMBRELLA.md` (one line) are F05 /
  F04 files; each edit substitutes one path token, and the later slice moves the line
  verbatim. Because these six lines change a backtick token (not only a link target),
  `tools/docs-move-check.sh` reports each as an informational `DROPPED-LINE`; R1 pins the
  exact set so a seventh is a finding. Accepted: leaving them ships pointers to a human doc
  that no longer holds the cited table, grammar copy or capability text.
- **D5 — Accuracy over coverage.** Every behavioral sentence in the human WORKFLOW is checked
  against the counterpart section named in the plan's *Accuracy table* before it is written;
  every absolute (`never`, `always`, `nothing`, `every`, `only`) carries its exception in the
  same sentence or is not written. The human doc may omit a rule; it may not misstate one.
- **D6 — Reuse the slice-2 rows; generalise, do not duplicate.** The shape, diagram, accuracy
  and over-claim rows of slice 2 are specific to INSTALL by their argument lists only. This
  slice generalises two helpers in place — `install_shape_problems` → `shape_problems <file>
  <headings> <anchors> <counterpart-basename>` and `diagram_problems` gains a fifth argument `<type>` (default
  `flowchart`) — with the slice-2 rows passing their own lists, so `F02_R2_human_shape`,
  `F02_R3_install_diagram` and `F02_R4_upgrade_diagram` keep passing unchanged in meaning. No
  tool changes: `tools/doc-cite-check.py` and `tools/docs-move-check.sh` are used, not edited.
- **D7 — The state diagram is a state diagram.** The human doc's feature diagram is a
  `stateDiagram-v2` (the type `docs/CONCEPTS.md` → `## The loop` already uses), not a
  flowchart, and it draws the `done` edge on the **merge**, never on the approval
  (`tests/test_landed_evidence.sh` R19 forbids `in_review --> done: Reviewer approves` in the
  contract doc; the human doc obeys the same rule by its own pin).

**Conventions.** C1–C8 of `docs/agents/README.md` → `## Conventions` apply unchanged: layout
(C1), verbatim move (C2), path-only re-point (C3), the two proofs before the PR (C4), human
style with the default budget 300 and a required diagram (C5), navigation (C6), shipping (C7 —
the counterpart keeps its three moved links to `../../agents/fixer.md`, `../../store/local.md`
and `../../specs/adr/0002-…`, outside the installed body; they were already there and are
retargeted, not added), brand (C8 — the human doc does not repeat the brand token; installed
names never change).

## Architecture alignment

- ADR-0002 — `builder-heavy` is a tier, not a second prompt: the human doc's escalation
  sentence says "the same instructions at a heavier model tier" and never implies a different
  Builder; the routing rule itself stays in the counterpart.
- ADR-0004 — A child resolves the harness body through pointer stubs at the same paths:
  `docs/agents/WORKFLOW.md` is one more file under the existing `docs` prose-tier entry, so a
  thin child receives it as a stub and a full copy receives the bytes; the umbrella suites
  that stub or edit `docs/WORKFLOW.md` keep working on the human doc at the unchanged path.
- ADR-0005 — Source-only surfaces are emitted only by `--self`: nothing this slice adds is
  source-only; both WORKFLOW files ship with `docs/` to every target, which is why the six
  suites that read the installed copy keep reading an installed copy (at the new path), and
  why the regenerated `/sdd-next` bodies cite the installed path through the emitter.
- ADR-0008 — Vertical slices; red/green pairs: the epic is sliced by human doc; this slice is
  observable as "WORKFLOW reads short and every pinned phrase still resolves", and the tasks
  file pairs one failing test with each R-id.
- ADR-0011 — Escalation arms per front-end: the human doc names "the installer's arming
  verdict" as the second yes and does not restate the per-front-end rule, which stays verbatim
  in the counterpart's "Which Builder runs" section (`tests/test_escalation.sh` F182-R12 pins
  it there, on the installed copy).
