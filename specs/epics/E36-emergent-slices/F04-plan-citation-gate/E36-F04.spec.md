# Uncited plan rows block: plan-cite-check tool + Reviewer gate — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E36-F04:R1 … E36-F04:R12`.

## Context

E36-F03 declared and recorded the stage-aware NFR contract (ADR-0009 decisions 1–3) and
pinned one **citation grammar** in `docs/SPEC-FORMAT.md` → *Plan rows cite an R-id or an
ADR*: the stage line, the deferred-ADR header, the plan-row citation, and the two-form
`## Deferred` subsection. It enforced none of it, and said so on four surfaces
(`agents/architect.md`, `docs/SPEC-FORMAT.md`, `docs/WORKFLOW.md`, `CHANGELOG.md`): "E36-F04
will enforce it (not yet enforced)". This feature is that enforcement — ADR-0009 decision 4:
**an uncited plan row is a defect**, detected by a tool with an exit code, reported advisory
by the doc-critic at the spec checkpoint, and **rejected** by the Reviewer.

The mechanism is `tools/plan-cite-check.py`: a stdlib-only Python lint, a pure function of
the plan file, its spec and the `specs/` tree, in the mould of `tools/tasks-pair-check.py`
(E36-F01). It lints the F03 grammar **byte-exactly** — the regexes are copied from
SPEC-FORMAT, not re-derived — and resolves `ADR-NNNN` citations with the **namespace rule**
`agents/reviewer.md` and `init.sh` section 2c already share. It also carries the two sweeps
F03 handed over: `deferred` ADRs with no `Trigger:` line and an unrecognized `stage:` value,
both surfaced warn-only by `init.sh`. The Reviewer gains a numbered check 8 that rejects on
exit 1 and — reusing E36-F01's merge-time rule — **flags instead of rejecting** a plan written
before this tool merged (E36-F02 and E36-F07 are in flight on sibling branches today with
plans that have no `## Deferred`; nothing ambushes them). The role prose on all four
surfaces flips from future to present tense, and the tests that pinned the future tense flip
with it.

The user is anyone running the Architect → Builder → Reviewer loop, in this repo or in a
consumer repo that installed the harness. Prose is the pointer; the tool is the mechanism
(docs/RATIONALE.md, structural over compliance) — this control gets a ledger row.

**Complexity basis.** `complex`, on three stated signals from `agents/architect.md`:

- the spec sits exactly at `change_size.max_requirements` (12 of 12); the seam I would split
  on (tool vs. gate prose) would ship a lint nothing runs, or a Reviewer check naming a tool
  that does not exist, so it is not split;
- the lint is a **validator for a schema that already ships** on five surfaces with
  byte-exact test pins (`tests/test_stage_nfrs.sh` R4/R6/R7/R10/R11). A validator that
  disagrees with its schema is the defect class the harness has already paid for (lessons
  2026-09-05, 2026-09-16), and here the schema is frozen first, so the tool must copy it;
- ADR-0009 decision 4 reaches across `tools/`, `init.sh`, `agents/reviewer.md`,
  `agents/doc-critic.md`, `agents/architect.md`, one template, three docs, the installer and
  the deletion ledger.

## Business rules

- **The grammar is F03's; this feature lints it, it does not redefine it.** The source of
  truth is `docs/SPEC-FORMAT.md` → *Plan rows cite an R-id or an ADR* (items 1–4) together
  with `specs/epics/E36-emergent-slices/F03-stage-deferred-adrs/E36-F03.plan.md` → *Data
  model*. The regex bytes the tool uses are those: `^stage: (discovery|pilot|production)$`,
  `^- \*\*Status:\*\* deferred`, `^- \*\*Trigger:\*\* \S`, `R[0-9]+`, `ADR-[0-9]{4}`, the four
  headings `## Data model`, `## API / interface`, `## Files to change`, `## Deferred`, the
  table header `| Bolt-on | Deferred by | Trigger |`, and the line `Deferred: none — <why>`.
  Where the grammar is silent the `.plan.md` of this feature states the tool's reading
  (section bounds, header/separator detection, cell splitting) as the tool's own contract —
  never by widening what SPEC-FORMAT says. Two consequences are accepted, not fixed here: a
  `## CLI / interface` heading (E36-F02/F07 use it) is **not** one of the four, so its rows
  are not parsed; and a `(serves: R#…)` suffix on a heading does **not** stand in for a row
  citation (SPEC-FORMAT item 3) — the inbox brief's "inherit from the heading" proposal is
  declined for that reason, and the plan template's `## Data model` table gains an `R-id`
  column instead so new plans cite per row.
- **Four violation classes, one exit code.** Under the four headings (outside fenced code —
  the CommonMark rule `tests/lib/fence.awk` encodes), a table row (`^|`) that is neither the
  header row nor the separator row and carries no `R[0-9]+` and no `ADR-[0-9]{4}` token is
  `uncited-row`. With `--spec`, an `R<n>` cited in such a row that the spec does not declare
  (spec `R-id` lines read exactly as `tasks-pair-check` reads them) is `unknown-rid`. An
  `ADR-NNNN` cited in such a row that resolves to no ADR file under the namespace rule is
  `unresolved-adr`. The `## Deferred` subsection is **either** a `| Bolt-on | Deferred by |
  Trigger |` table with at least one data row whose *Deferred by* cell holds an `ADR-[0-9]{4}`
  token — an ADR that **resolves, is `Status: deferred` and carries a non-empty `Trigger:`** —
  **or** exactly one line `Deferred: none — <why>`; a missing subsection, both forms, neither
  form, an empty table, a row with no ADR in its second cell, or a cited ADR that is not a
  deferred-with-trigger ADR is a `deferred-*` violation. Any violation ⇒ exit `1`, one
  `plan-cite-check: <code> <plan>:<line> …` line per offender, then a `FAIL <n> violation(s)`
  line. No violation ⇒ exit `0` and one `plan-cite-check: ok …` line. Prose outside tables is
  never parsed; a plan with no tables under the four headings and a well-formed `## Deferred`
  passes. The grammar names the token `R[0-9]+`; where it is silent on boundaries the tool
  reads a token as starting at a non-alphanumeric boundary, so `PR304` or `CR12` in a cell is
  not a citation (and cannot trip `unknown-rid`) — recorded here as the tool's reading, not a
  change to the grammar. `<heading>` in a finding is the matched heading name, one of the
  four, without its suffix.
- **A plan-row `unresolved-adr` is a reject, by design — the spec-level soft flag is
  unchanged.** `agents/reviewer.md` → *ADR-citation check* soft-flags a dangling id in a
  `.spec.md`'s `## Architecture alignment` because "typo" and "ADR legitimately renamed" are
  indistinguishable there. A `.plan.md` row is different: ADR-0009 decision 4 makes the row's
  citation the row's justification, so a citation that resolves to nothing justifies nothing
  and the row is uncited in substance. Check 8 therefore rejects on every exit-1 code
  (grandfathering aside); `init.sh` 2c and the Reviewer's spec-level clause keep their flag
  posture, and the two surfaces still agree on *resolution* (same namespace rule) while
  differing, deliberately, on the verdict class.
- **Flags, as the brief did not spell them.** The brief sketched `--adr-dir specs/adr`; the
  namespace rule needs the whole `specs/` tree (every `adr/` under it), so the flag is
  `--specs-dir <dir>` with the ancestor default above. The `stage-unrecognized` sweep finding
  is this feature's addition, not an F03 hand-over: grammar item 1 reads any unrecognized
  value as `production` silently, and a sweep is the only place that silence can be heard.
- **Namespaces, exactly as `init.sh` 2c and `agents/reviewer.md` resolve them.** A namespace
  is a directory literally named `adr/` under the `specs/` tree; its token is the parent
  directory's basename, `platform` for `specs/adr/`; only `*.md` directly inside counts, and an
  ADR's number is the leading digits of its filename. `<ns>/ADR-NNNN` (or `<ns> ADR-NNNN` when
  `<ns>` is a known token) resolves against that namespace **only**; an unknown `<ns>/` never
  resolves; a bare `ADR-NNNN` resolves against **any** namespace and is a miss only when it
  resolves in none. Emphasis and quote wrappers (`*`, `` ` ``, `"`, `'`) around a citation
  are stripped before matching, as 2c does. The `specs/` tree is `--specs-dir` when given,
  else the nearest ancestor of the plan path whose basename is `specs`.
- **Never swallow a failure.** An absent, unreadable, non-UTF-8 or non-regular plan, spec or
  specs dir; a spec with zero `R-id`s; a missing positional; an unknown flag; a flag without
  its value — each is exit `2` with `plan-cite-check: error: <what>` and the usage on stderr,
  never `0`. Exit `2` is "the check did not run" on every surface that consumes it (Reviewer,
  doc-critic, `init.sh`): no surface treats it as a pass. Files are read as UTF-8; a trailing
  `\r` (CRLF) is stripped from every line before any rule is applied. Paths are taken from
  `argv` verbatim — never re-quoted, split or shell-expanded — so a path with spaces or a
  quote character works.
- **Two sweeps, one mode, warn-only in `init.sh`.** `plan-cite-check.py --sweep <specs-dir>`
  reports (exit `1`) every ADR in any namespace whose header has `^- \*\*Status:\*\* deferred`
  but no line matching `^- \*\*Trigger:\*\* \S` (`deferred-no-trigger <path>`), and a
  `stage:` line inside `<specs-dir>/product.md`'s first `---` block that does not match
  `^stage: (discovery|pilot|production)$` (`stage-unrecognized <path>:<line> <text>` — the
  value reads as `production`, so a typo or an inline comment is silent until swept; an
  absent `stage:` line is not reported). `init.sh` runs the sweep and the plan lint over every
  board feature in `spec-ready`, `in-progress` or `in-review` with `sdd: true` and a
  `spec_path`, prints each finding as a `⚠️` line and **never** fails the gate on either —
  the Reviewer owns the verdict, exactly as 2c already does for ADR citations.
- **The Reviewer gate is a reject; the doc-critic is advisory** (ADR-0009 decision 4; the
  brief's chosen split). `agents/reviewer.md` gains numbered check **8** under `## What you
  check`: run the tool with `--spec`; exit `1` ⇒ reject with the tool's output quoted; exit
  `2` ⇒ the check did not run, fix the invocation, never approve on an unrun check. The
  doc-critic runs the same command at the `feature-spec` checkpoint and reports the output as
  advisory findings, and additionally flags a plan that omits a **sticky NFR** the feature's
  scope touches (the four in `specs/_templates/adr.md`: tenant isolation, the auth boundary,
  secrets out of the repo, validation at the system edge) or that adds a **bolt-on** row
  (encryption at rest, WAF, rate limits, backups, caching) citing no `R-id` and not deferred.
  Judging whether a *cited* row is justified stays the doc-critic's YAGNI finding (brief: out
  of scope for the tool). `sdd: false` items have no `.plan.md` and are exempt.
- **Grandfathering reuses E36-F01's merge-time rule, keyed on this tool's own merge.**
  `plan-cite-check.py --grandfathered <plan.md> [--base <ref>]` is the same algorithm as
  `tasks-pair-check.py --grandfathered` with the tool paths changed to
  `tools/plan-cite-check.py` / `.harness/tools/plan-cite-check.py`: the tool's date is the
  committer time of the first first-parent commit on the default branch (`origin/HEAD`, else
  `origin/main main origin/master master origin/trunk trunk`) touching either path; the
  plan's date is the author time of the earliest commit on `HEAD` that added it; older ⇒
  exit `0` (flag), else exit `1` (reject class), exit `2` when not in a git work tree or no
  base resolves. While the tool is not on the default branch every plan is flagged. It is a
  **deliberate second copy**, not an import: the two tools must install and run
  independently (no tool-to-tool coupling), and keying on `tasks-pair-check`'s merge date
  (2026-10-25) would ambush every plan written between that merge and this one — including
  E36-F02's and E36-F07's. The Reviewer runs it only on exit `1`: `0` ⇒ flag ("add
  `## Deferred` and cite each row, or justify"), `1` ⇒ reject, `2` ⇒ flag with "grandfather
  check did not run: <stderr>". Plans of `done` features are never re-reviewed and are not
  retro-fitted.
- **Fenced code is invisible to the lint.** The tool carries `iter_unfenced()`, a deliberate
  second copy of `tests/lib/fence.awk`'s CommonMark rule (as `tasks-pair-check.py` does), and
  the suite feeds the same edge corpus to `fence.awk` and to the copy, requiring identical
  output — a table inside a fenced example (SPEC-FORMAT's own `## Deferred` example is one) is
  never a row.
- **Present tense everywhere, pinned.** The four "will enforce / not yet enforced" sentences
  flip to present tense naming the tool; `tests/test_stage_nfrs.sh` R7/R11 flip their anchors
  with them, and the bounded sections must no longer contain `not yet enforced`. Historical
  `CHANGELOG.md` entries (0.101.0) are not rewritten — the new release entry records that
  enforcement landed.
- **Mutation sweep before hand-off.** The Builder runs the whole-clause mutation campaign in
  `.tests.md` (one mutant at a time, backup-copy revert, printed diff, under
  `scratchpad/E36-F04-builder/`); a survivor earns a new test row, never a comment. Prose
  pins anchor whole sentences with bounded gaps (`A[^.]{0,N}B`) on **installed** files, never
  single tokens — a token that also occurs in a sibling sentence has a second producer
  (lesson 2026-10-26).
- **Generated glue is never hand-edited.** `.claude/`, `.codex/`, `.opencode/`, `.pi/`,
  `.agents/` are regenerated by `sh harness-install.sh --self`. This feature changes no
  emitter (role shims defer to the canonical files; the installer edit is one `chmod +x`
  line), so `--self` must produce no diff; `tests/test_self_drift.sh` is the check.
- **Ledger layer: Capability compensation, like C9 — a recorded departure from the brief.**
  The brief asked for a *durable* row. The lint exists because models grow uncited NFR
  machinery; that is a model tendency the tool compensates for, and the ablation condition
  that would retire it is exactly C9's shape. The durable property — the citation grammar and
  R-id traceability — already lives in D1 (`docs/SPEC-FORMAT.md`). So `C10` sits beside `C9`,
  and this sentence is the record of why.
- **Installed body changes ⇒ SemVer MINOR bump** (new tool, `init.sh`, four role/template
  files, three docs), with a `CHANGELOG.md` entry and a `docs/RATIONALE.md` ledger row. The
  target is the **next MINOR over the then-current `VERSION`** at merge time (E36-F02 and
  E36-F07 bump in parallel; the Builder re-reads `main` before the final rebase). No test
  freezes the literal or diffs a DO-NOT-TOUCH file against `main`; DO-NOT-TOUCH files are
  checked with `cksum` before and after.

- platform ADR-0001 — Deterministic next selection: untouched; the `init.sh` sweep reads the
  board read-only to pick `spec-ready`/`in-progress`/`in-review` features and writes nothing.

No divergence from any ADR. The brief's heading-inheritance proposal is declined in favor of

## Acceptance criteria (EARS)

> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md.

- **R1** — When `python3 tools/plan-cite-check.py <plan> --spec <spec>` is run on a readable
  plan whose every table row under `## Data model`, `## API / interface`, `## Files to change`
  and `## Deferred` (outside fenced code) carries an `R[0-9]+` token the spec declares or an
  `ADR-[0-9]{4}` token that resolves, and whose `## Deferred` is well-formed, the tool shall
  exit `0` and print one line beginning `plan-cite-check: ok` — including when the plan is
  CRLF-terminated, when a table under one of the four headings sits inside fenced code (any
  fence form `tests/lib/fence.awk` accepts), when the plan has no tables at all under the
  four headings but a `Deferred: none — <why>` line, and for this feature's own `.plan.md`
  and `E36-F03.plan.md` (dogfood).
- **R2** — If a table row (`^|`) under one of the four headings, outside fenced code, that is
  neither the table's header row nor its separator row carries no `R[0-9]+` token and no
  `ADR-[0-9]{4}` token, then the tool shall exit `1` and print
  `plan-cite-check: uncited-row <plan>:<line> <heading>` for that row — while a header row, a
  separator row, a table row under any other heading (including `## CLI / interface` and
  `## DO NOT TOUCH`), a prose line, and a `(serves: R#…)` suffix on the heading shall produce
  no such line and shall not stand in for the row's own citation.
- **R3** — If `--spec` is given and a row under one of the four headings cites an `R<n>` that
  the spec does not declare (a spec `R-id` is a line `- **R<n>** …` or `- **R<n> — Title.** …`
  outside fenced code), then the tool shall exit `1` and print
  `plan-cite-check: unknown-rid <plan>:<line> R<n>`; while if `--spec` is absent, the tool
  shall not check `R-id` existence and its `ok` line shall say `spec: not checked`.
- **R4** — If a row under one of the four headings cites an `ADR-NNNN` that resolves to no
  `NNNN-*.md` under the namespace rule (`<ns>/ADR-NNNN` or a known `<ns> ADR-NNNN` against
  `specs/<ns>/adr/` only, `platform` = `specs/adr/`, an unknown `<ns>/` never; a bare
  `ADR-NNNN` against any `adr/` namespace under the specs dir), then the tool shall exit `1`
  and print `plan-cite-check: unresolved-adr <plan>:<line> <citation> <reason>`; while a
  qualified citation that resolves in its namespace and a bare citation that resolves in any
  namespace shall produce no such line, and a wrapper (`*`, `` ` ``, `"`, `'`) around the
  citation shall not change the verdict.
- **R5** — If the plan's `## Deferred` subsection is missing, or holds both a
  `| Bolt-on | Deferred by | Trigger |` table and a `Deferred: none — <why>` line, or holds
  neither, or holds more than one `Deferred: none` line, or holds that table with no data
  row, or holds a data row whose second cell carries no `ADR-[0-9]{4}` token, or cites in a
  data row an ADR that resolves but lacks `^- \*\*Status:\*\* deferred` or lacks
  `^- \*\*Trigger:\*\* \S`, then the tool shall exit `1` and print one
  `plan-cite-check: deferred-<reason> <plan>[:<line>] …` line naming the case
  (`section-missing`, `form both|neither|<n>-none-lines`, `table-empty`, `row-no-adr`,
  `by-not-deferred`, `adr-no-trigger`); while a table whose every row cites a resolving
  deferred-with-trigger ADR, or exactly one `Deferred: none — <why>` line with prose lines
  beside it, shall produce no `deferred-*` line.
- **R6** — If the plan path is missing or given twice, a flag is unknown, `--spec` /
  `--specs-dir` / `--base` lacks its value, the plan or the spec is absent, unreadable, not a
  regular file or not valid UTF-8, the spec declares zero `R-id`s, or no specs dir is given
  and no ancestor of the plan path is named `specs`, then the tool shall exit `2` and write
  `plan-cite-check: error: <what>` plus the usage to stderr and nothing to stdout — never
  exit `0`; while a plan path containing a space and a single quote, passed verbatim in
  `argv`, shall be read as that path (exit `0` on a clean plan).
- **R7** — When `python3 tools/plan-cite-check.py --sweep <specs-dir>` is run, the tool shall
  exit `1` and print `plan-cite-check: deferred-no-trigger <adr-path>` for every ADR in any
  `adr/` namespace under `<specs-dir>` whose header has `^- \*\*Status:\*\* deferred` and no
  line matching `^- \*\*Trigger:\*\* \S`, and
  `plan-cite-check: stage-unrecognized <specs-dir>/product.md:<line> <text>` when the first
  `---` block of `<specs-dir>/product.md` has a `stage:` line not matching
  `^stage: (discovery|pilot|production)$`; and exit `0` with one `plan-cite-check: ok` line
  when neither occurs (an absent `stage:` line or an absent `product.md` is not a finding);
  and `init.sh` shall run that sweep and the plan lint (with `--spec`) over every board
  feature in `spec-ready`, `in-progress` or `in-review` with `sdd: true` and a `spec_path`
  holding a `*.plan.md`, print each non-zero result as a `⚠️` line naming the feature id and
  the tool's first finding (exit `2` as "did not run"), print an `✅` line when all are clean,
  and exit `0` regardless.
- **R8** — When `python3 tools/plan-cite-check.py --grandfathered <plan> [--base <ref>]` is
  run inside a git work tree, the tool shall exit `0` with a line
  `plan-cite-check: grandfather flag: <reason>` when the tool is not yet on the default branch
  or the plan's first-add author time is strictly older than the committer time of the first
  first-parent commit on the default branch touching `tools/plan-cite-check.py` or
  `.harness/tools/plan-cite-check.py`; exit `1` with `plan-cite-check: grandfather reject:
  <reason>` otherwise (including a plan with no commit on `HEAD`); and exit `2` with an
  `error:` line when the path is outside a git work tree, when `--base` does not resolve, or
  when `--base` is absent and no default branch resolves (a repo with no `origin/HEAD` and
  none of the fallback names).
- **R9** — `agents/reviewer.md` § `## What you check` shall carry a numbered item **8** that,
  for an `sdd: true` feature, runs `python3 "$HARNESS_DIR/tools/plan-cite-check.py"` on the
  feature's `.plan.md` with `--spec` its `.spec.md`, rejects on exit `1` quoting the tool's
  output, treats exit `2` as a check that did not run (never an approval), names the installed
  path `.harness/tools/plan-cite-check.py`, states the grandfather rule as the
  `--grandfathered` command (exit `0` flag, `1` reject, `2` flag "did not run"), exempts
  `sdd: false` items, states that a plan-row `unresolved-adr` is a reject while the
  spec-level ADR-citation soft flag is unchanged, and leaves check 2's sentence "A requirement
  without a passing test = reject" and check 7's `tasks-pair-check.py --grandfathered`
  sentence in place; and `agents/doc-critic.md`
  shall tell the critic, at the `feature-spec` checkpoint, to run the same command and
  report its output as advisory findings, and to flag a plan that omits a sticky NFR the
  feature touches (the four named) or adds a bolt-on row (the five named) with no `R-id` and
  no deferral — advisory only, never blocking.
- **R10** — `specs/_templates/feature.plan.md`'s `## Data model` table shall carry an `R-id`
  column (header `| Entity | Field | Type | Notes | R-id |`, placeholder row ending `| R# |`)
  while every anchor of `tests/test_stage_nfrs.sh` R6 still holds; and the Stage section of
  `agents/architect.md`, the grammar section of `docs/SPEC-FORMAT.md` and the Stage section of
  `docs/WORKFLOW.md` shall each name `tools/plan-cite-check.py` as the enforcement in present
  tense (the Architect's section telling it to run the tool before hand-off and that it must
  exit `0`; SPEC-FORMAT's saying the tool turns the grammar into an exit code, `0`/`1`/`2`,
  and that the section is the schema it lints; WORKFLOW's naming the tool, the `init.sh`
  sweep, the doc-critic flags and Reviewer check 8) and shall contain no `not yet enforced`
  within those sections — with `tests/test_stage_nfrs.sh` R7/R11 flipped to pin the new
  sentences.
- **R11** — A fresh `harness-install.sh` run shall ship `.harness/tools/plan-cite-check.py`
  executable and byte-identical to the source; the installer source shall carry the line
  `chmod +x "$H/tools/plan-cite-check.py"`; `.harness/init.sh` shall name
  `tools/plan-cite-check.py`; `.harness/agents/reviewer.md` and `.harness/agents/doc-critic.md`
  shall name the tool; `.harness/specs/_templates/feature.plan.md` shall carry the `R-id`

  shall read `tests/test_tasks_pairs.sh`'s fence edge corpus identically to
  `tests/lib/fence.awk`.
- **R12** — `VERSION` shall change from its `main` value (the Reviewer confirms a MINOR step

  body names `E36-F04` and `plan-cite-check` and says enforcement is now real, and the newest
  `## [` heading shall equal the `VERSION` file's value — read at test time, never as a frozen
  literal; and `docs/RATIONALE.md`'s deletion ledger shall carry a row
  `C10 — Plan-row citation lint` in the *Capability compensation* layer whose "evidence to
  reconsider" cell states the ablation condition under which the lint may be removed, with
  `tests/test_rationale_docs.sh` counting 24 rows and accepting `C1`–`C10`.

## Out of scope

- Widening the grammar: `## CLI / interface` (or any heading other than the four) is not
  parsed; heading-level `(serves: …)` inheritance is declined (SPEC-FORMAT item 3); a range
  `R1–R12` is not expanded (each explicit `R<n>` token is checked, as `tasks-pair-check`
  does). Changing SPEC-FORMAT's grammar items 1–4 is an F03-grammar change, not this feature.
- Judging whether a cited row is *justified* (doc-critic YAGNI, brief), or whether a deferred
  bolt-on is the right call for the stage. The tool does not read `stage:` to pick a
  verdict; the sweep only reports an unrecognized value.
- Retro-fitting `## Deferred` or per-row citations onto `done` features' plans, or onto
  in-flight plans spec'd before this merged — those are grandfathered (flag, not reject).
- Making `specs/_templates/feature.plan.md` itself lint-clean: it is a form with `R#` and
  `ADR-NNNN` placeholders (`tests/test_stage_nfrs.sh` R6 pins the `ADR-NNNN` row), not a plan.
- A `DO NOT TOUCH` row citation (brief open question): `## DO NOT TOUCH` is a bullet list, not
  one of the four headings — a constraint, not a decision — so nothing there is parsed.
- Rewriting historical `CHANGELOG.md` entries (the 0.101.0 "will be E36-F04" lines are
  history); ADR-0009's status line ("effective on E36-F04") stays as written.
- Any change to `tools/tasks-pair-check.py`, `tests/lib/fence.awk`, the `/sdd-*` command
  emitters in `harness-install.sh`, the TaskStore schema, or `harness.config.yaml`.
- `sdd: false` fixes (no `.plan.md`); umbrella slice plans beyond what the single-repo rule
  already covers. A child-repo plan resolves against the child's own `specs/` tree
  (`agents/architect.md`: slices follow the ADR set of the repo they live in), so a child
  plan citing an umbrella-only ADR is `unresolved-adr` — accepted; cite the child's ADR or
  pass `--specs-dir` at the umbrella's tree deliberately.
- Keeping `tools/tasks-pair-check.py` byte-identical is a DO-NOT-TOUCH obligation checked by
  the Builder (T0/T15 `cksum`) and the Reviewer (check 4), not a permanent-suite row: a suite
  that compares a file to a record of itself proves nothing (lesson 2026-09-16).
- Grandfather awareness in the `init.sh` sweep (it is warn-only; a legacy in-flight plan
  warns each session until it is re-spec'd or `done`).

## Open questions

- None blocking. The brief's two questions are resolved above: a `DO NOT TOUCH` row needs no
  citation (not parsed); heading inheritance is declined in favor of the template's `R-id`
  column. The grandfathering mechanism is E36-F01's, keyed on this tool's own merge.
