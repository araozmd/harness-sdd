# Test-assertion drift check — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.
> Start high-level; the Builder picks internals not pinned here. Normative terms (base,
> head side, hunk pairing, attribution, finding line, summary line) are defined in

## Stack & dependencies

- Language: POSIX `sh` (`#!/bin/sh`, `set -eu`, `LC_ALL=C`), `git`, `awk`, `grep`, `sed`.
  Must parse and run under `dash` (the runner's strict shell) — no `local`, `[[ ]]`,
  `echo -e`, arrays, `${var//…}`. No GNU-only flags: BSD `grep`/`sed`/`awk` on this box.
  Regexes are **extended** (`grep -E`, awk ERE); no `\b`, `\d`, `\s`, `-P`.
- New dependencies: none.
- Tool invocation shape (R1, R9):
  `tools/test-drift-check.sh <base-ref> [<head-ref>] [--tasks-md <feature.tasks.md>]`.
  `-h`/`--help` prints usage and exits `2` (same convention as `change-size.sh usage()`,
  which exits its usage code). Any other `-`-prefixed token is an unknown flag → exit `2`.

## Data model  (serves: R5, R12)

No tables. One config key, in the existing top-level `change_size:` mapping:

| Entity | Field | Type | Notes |
|---|---|---|---|
| `change_size` | `assert_patterns` | YAML list of strings (ERE) | Default `[]`. ADDED to the built-ins, never replacing them. Read with the exact `_extra`-style section-scoped awk `change-size.sh` uses for `test_paths` (a same-named key outside `change_size:` is never read). Read line by line (here-doc, not `for … in $(…)`) so an entry containing a space survives. |

Seed text (byte-identical in BOTH `harness.config.yaml` and the `change_size` heredoc in
`harness-install.sh`'s `migrate_config` — see "Files to change"), appended directly after the
`generated_paths: []` line:

```yaml
  # Assertion patterns for the Reviewer's test-drift check (E36-F06), one EXTENDED REGEX per
  # entry, MATCHED AGAINST THE LINE TEXT of a changed test file and ADDED to the built-ins
  # (assert/expect(/t.is/t.ok/fail( + the harness suites' ok/fail helpers). Entries are used
  # VERBATIM (no YAML unescaping), so write a literal `(` as `[(]`. Empty = built-ins only.
  # Never add a bare `[` or `should`: every ordinary sh edit would become a finding.
  assert_patterns: []      # e.g. - "(^|[^A-Za-z0-9_])verify[(]"
```

### Finding and summary lines (R9) — exact shapes

```
DRIFT assert-modified | tests/test_foo.sh:42 | test_budget_tiers | [ "$n" = 50 ] || fail "R1 n" -> [ "$n" -ge 1 ] || fail "R1 n"
DRIFT assert-removed | tests/app.test.js:17 | parses empty input | expect(out).toEqual([]);
DRIFT skip-added | tests/app.test.js:9 | parses empty input | it.skip('parses empty input', () => {
DRIFT test-removed | tests/test_foo.sh:— | test_gone | test_gone
WAIVED test-removed | tests/test_foo.sh:— | test_budget_tiers | replaced by test_budget_tiers_json (T4)
test-drift-check: 5 findings, 1 waived, 2 test files examined (base 5ee8e07)
```

- Field separator is exactly ` | ` (space, pipe, space) — **no padding**; the tests anchor on
  one space before each pipe. The detail is the LAST field and is printed raw, so a `|`
  inside it is harmless for consumers that split on the first three separators.
- `<line>` is the literal `—` for `test-removed` (there is no single line); numeric otherwise.
- `N` in the summary counts `DRIFT` + `WAIVED` lines (5 above), `W` the `WAIVED` subset.

## Approach notes

### Built-in lists (R4, R6, R7) — the Builder ships these verbatim, one ERE per line

Assertion patterns (`ASSERT_RE` entries; a line matching ANY entry is an assertion line):

```
(^|[^A-Za-z0-9_])assert[A-Za-z_]*[[:space:](!.]
(^|[^A-Za-z0-9_])expect\(
(^|[^A-Za-z0-9_])t\.(is|ok|not|true|false|truthy|falsy|deepEqual|notDeepEqual|equal|notEqual|like|throws|notThrows|regex|snapshot|pass|fail|Error|Errorf|Fatal|Fatalf|Fail|FailNow)\(
(^|[^A-Za-z0-9_])fail\(
(^|[^A-Za-z0-9_])(ok|fail)[[:space:]]+["']
(^|[^A-Za-z0-9_])(pytest\.)?raises\(
```

Deliberately absent: `\[`, `should`, `must`, `test `, `pass "` (that is a NAME, R7). Note
`ok "…"` is an assertion here and NOT a name: removing an `ok` line yields exactly one
`assert-removed` and no `test-removed`.

Skip/only/xfail markers (`SKIP_RE` entries; only `+` lines are checked):

```
\.(skip|only|todo)\(
(^|[^A-Za-z0-9_])x(it|test|describe)\(
@pytest\.mark\.(skip|skipif|xfail)
(^|[^A-Za-z0-9_])pytest\.skip\(
@unittest\.(skip|skipIf|skipUnless|expectedFailure)
(^|[^A-Za-z0-9_])t\.(Skip|Skipf|SkipNow)\(
#\[ignore
@(Disabled|Ignore)([^A-Za-z0-9_]|$)
["']skip - 
```

Test-name extractors (by file extension; `.sh` or no extension with a `#!/bin/sh`/`bash`
shebang → sh; `.py` → Python; `.js .mjs .cjs .ts .tsx .jsx` → JS; `.go` → Go; anything else →
no names):

| Language | Pattern (ERE, anchored at line start) | Name | Direction |
|---|---|---|---|
| sh | `^[[:space:]]*([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*\(\)` | the identifier | backward |
| sh | `^[[:space:]]*pass[[:space:]]+"([^"]*)"` and the `'…'` form (NOT `ok` — that is an assertion helper, R4) | the quoted text | forward |
| Python | `^[[:space:]]*(async[[:space:]]+)?def[[:space:]]+(test_[A-Za-z0-9_]*)` | the `test_*` identifier | backward |
| JS/TS | `^[[:space:]]*(it\|test\|describe)(\.(only\|skip\|todo\|each))?[[:space:]]*\([[:space:]]*(['"\`])` | the text up to the next same quote | backward |
| Go | `^func[[:space:]]+(Test[A-Za-z0-9_]*)[[:space:]]*\(` | the `Test*` identifier | backward |

BSD awk has no capture groups: extract with `match()` + `RSTART`/`RLENGTH` + `substr()`, then
strip the fixed prefix/suffix (the probe in `progress/E36-F06/architect.md` shows the idiom
working under dash with the system awk). Attribution directions beyond the table: a
decorator line `^[[:space:]]*@` (Python/Java) attributes **forward** to the next definition;
ties between a backward and a forward candidate go to the backward one.

A name is "present" in a file if any line yields it; duplicates count once. `test-removed` is
computed per file as (names at base) minus (names at head). sh helper functions (`fail()`,
`mkrepo()`) are names too — deleting one is a finding and is waivable; that is the intended
"force a human look" behaviour, not a bug to engineer around.

### Diff plumbing (R1, R3)

- File list: `git diff --name-status -M <base> [<head>]`; statuses `A M D R<nn>`; for `R` the
  old path is the base side, the new path the head side. Untracked files (working-tree mode
  only): `git ls-files --others --exclude-standard`, treated as `A` with base text empty.
- Per file: `git diff -U0 --no-color --no-ext-diff <base> [<head>] -- <path>` (for `R`, pass
  both paths; for an untracked file, `git diff --no-index /dev/null <path>` or treat every
  line as `+`). Parse `@@ -a,b +c,d @@` to track base/head line numbers; inside a hunk collect
  `-` and `+` lines that match `ASSERT_RE`; pair k-th with k-th.
- Head text for name extraction: `git show <head>:<new>` when a head ref is given, else the
  working file (`cat`). Base text: `git show <base>:<old>`. A deleted file has empty head text.
- Pass regex lists to awk via `ENVIRON`, not `-v` (the `\.` decoding bug `change-size.sh`
  documents). Join ERE alternatives with `|` in a here-doc loop, never `for x in $(…)`.
- Binary files (`-` in numstat or `Binary files differ`) are skipped silently.

### Waiver parsing (R10)

`awk` over the `--tasks-md` file: strip an optional `- ` list marker and leading whitespace;
lines not starting with `waive-test-drift:` are ignored (so the spec's own prose example with
`<exact test name>` placeholders never parses as a waiver unless it is at line start). Split
on the FIRST ` — ` (U+2014 is three bytes in UTF-8: `\342\200\224`; match it literally under
`LC_ALL=C`, e.g. with `index()` on the byte string). Empty name or empty reason → exit 2 with
`test-drift-check: malformed waiver (expected 'waive-test-drift: <test name> — <reason>'): <line>`.
A waiver that matches no finding is NOT an error (the fixture it waives may have been fixed
since) — it is simply unused.

### Reviewer section text (R11) — ship this, adjusting only wording that a test does not anchor

```markdown
## Test-drift check before the verdict (E36-F06)

`sh tools/run-tests.sh` is still your primary command; this is an added check that the
primary one cannot make. A green suite says every assertion that still exists passes — it says
nothing about an assertion that was weakened so it still passes, or a test whose name quietly
left the file. Run the drift check on the branch you are approving:

```sh
_def="$(git symbolic-ref --quiet --short refs/remotes/origin/HEAD 2>/dev/null || echo main)"
sh "$HARNESS_DIR/tools/test-drift-check.sh" "$_def" --tasks-md specs/epics/<epic>/<feature>/<feature>.tasks.md
```

Pass the **default branch**, not a hard-coded `origin/main`: the tool takes the merge-base
itself, so a stacked branch or a rebased one is measured from the point a reviewer actually
reads. **When the branch carries pair commits** (E36-F01 — one commit per red/green pair), run
it once more per pair commit,
`sh "$HARNESS_DIR/tools/test-drift-check.sh" <pair-sha> --tasks-md <same file>`, so a test that
went green at that commit and was weakened later is caught against the finer baseline. Pass the
same `--tasks-md`: without it a finding already waived there prints as `DRIFT` and exits `1`,
a false REJECT. Pair commits are optional; the merge-base run is the contract.

Read the exit code, not the prose:

- `0` — no assertion-pattern line was removed or modified, no skip/only marker was added and
  no extracted test name was removed in any touched test file (or every such finding is waived
  and printed as `WAIVED`). That is all exit `0` covers. Other changed lines in a test file —
  fixtures, setup, expected values such as `want=3` → `want=$(add 1 2)` — are not checked, so
  you still read the test diff yourself (3b). Carry on.
- `1` — at least one `DRIFT` line. **REJECT** unless the finding is waived: a line
  `waive-test-drift: <exact test name> — <reason>` in the feature's `.tasks.md`, one per test,
  exact name. Quote the `DRIFT` lines in `progress/<run>/review.md`. The tool does not judge
  whether the edit tightened or weakened the assertion, and neither should you from the diff
  alone — check it the way 3b says: delete the mechanism it claims to pin and watch it go red.
- `2` or `3` — the check **did not run** (usage error; a ref that does not resolve; no merge
  base). That is not a verdict in either direction: fix the invocation and run it again. Do not
  approve on an unrun check.

Record the summary line and the decision for any `WAIVED` finding in your verdict.
```

### Known limits to state in the tool's header (so prose never over-claims — reviewer 3c)

Moved assertions are findings; multi-line assertions are detected only on the lines that
match; label rewording in sh suites reads as `test-removed`; an inserted `exit 0` is not a
marker; LF/TAB in pathnames are unsupported; `describe(` blocks count as names.
