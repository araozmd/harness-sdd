# Test-assertion drift check — Tasks

> Atomic, sequential steps. The Builder works these top to bottom, one at a time. Each task
> names the R-id(s) it satisfies. Per ADR-0008 the list is **red/green pairs**: for each
> requirement, first the failing test named in `E36-F06.tests.md`, then the minimal code that
> passes it; each pair ends in a commit so a later weakening of that test is a diff the
> Reviewer can detect. There is no trailing "write tests" task. Exact text, regex lists and
> file sites are in `E36-F06.plan.md`.
>
> Fixture discipline for every test task: a **fresh temp git repo** per case (`mkrepo` idiom
> from `tests/test_change_size.sh`: `git init -q`, user config, `checkout -b main`, seed
> commit, then a `feature` branch), never a copy of this repo; each fixture changes **one
> thing** so only the code path under test can produce the expected line (lessons: "assertion
> reachable by another path", "fixture copied from the repo inherits the artifact").
> A waiver line that must NOT match uses a different name, never a prefix-only typo in prose.

## Waivers

> One `waive-test-drift: <exact test name> — <reason>` per line, added by T23 after the
> tool reports them. Nothing is pre-waived: a waiver written before the finding exists would
> be a guess about a name, and a guessed name waives nothing.
