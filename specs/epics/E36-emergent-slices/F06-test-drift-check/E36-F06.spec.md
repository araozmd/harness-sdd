# Test-assertion drift check — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E36-F06:R1 … E36-F06:R12`.

## Context

The Reviewer catches a deleted or commented-out test because the R-id then has no passing
test. It does not catch a test whose **assertion was weakened so it still passes**. This
repo's own `progress/lessons.md` records weak assertions slipping through three times
("assertion reachable by another path"; "a surviving mutation means rewrite"). The operator
attributes the absence of tampering to strong models; the ablation doctrine
(`docs/RATIONALE.md`, principle 3) says *verification is the constant* — measure it, do not
assume it. ADR-0008 names this check as the consequence of per-requirement red/green pairs:
once a test went green at a pair commit, a later weakening is a **diff** the Reviewer can
detect, independent of which model built the feature (ADR-0002).

This feature ships `tools/test-drift-check.sh`: a diff-based, language-agnostic, POSIX
`sh + git + awk` tool that lists, for every **test file** touched between a base ref and
head, every removed or modified **assertion line**, every newly added **skip/only/xfail
marker**, and every **test name** present at base and absent at head. It reports and fails;
it never judges whether a change tightened or weakened an assertion — that is the human's
look it exists to force. Waivers live in the feature's `.tasks.md`, the Builder's only
worklist, so they are reviewed where they are made. The Reviewer runs it as an **added**
check beside `sh tools/run-tests.sh`, which stays primary.

### Why `complexity: complex`

Two of `agents/architect.md`'s stated bases hold:

1. **The feature is at the size budget.** It has exactly 12 R-ids against
   `change_size.max_requirements: 12`; the installer/version/changelog obligations were
   folded into one R-id to stay there.
2. **The plan names a defect class the harness has already paid for.** The new config key
   `change_size.assert_patterns` lands in a block that exists **twice** — the seed in
   `harness.config.yaml` and the heredoc in `harness-install.sh` — a byte contract compared
   in more than one place (E17-F04, E99-F159 mutant M6). And the test-path classifier is
   exactly the kind of logic that gets re-typed and drifts; the spec forces reuse through
   one source (R2) rather than a second copy.

## Business rules

- **Diff-based, not AST-based.** Cheap, language-agnostic, good enough to force a human
  look. Every rule below is a line-level rule over `git diff` output.
- **Report and fail; never judge strength.** Any modified or removed assertion line is a
  finding. The tool does not try to decide whether the edit tightened or weakened it.
- **Pure additions never fail.** New test files, new tests, new assertion lines produce no
  finding. The one exception is an added **skip/only/xfail marker**, which is a finding even
  in a new file — a new `.only(` disables every other test in the run.
- **Test files are whatever the pre-PR check calls test files.** The tool uses the same
  classifier `tools/change-size.sh` uses (built-in `TEST_RE` + `change_size.test_paths`),
  obtained from that tool — never a second copy. The same goes for reading the
  `change_size:` config block: one parser, in `change-size.sh`, queried by the drift tool.
- **The tool runs against the repository containing the cwd** (`git rev-parse
  --show-toplevel`); every path it prints is repo-relative.
- **Built-ins are conservative.** The assertion patterns match `assert`, `expect(`, `t.is`,
  `t.ok`, `fail(`, and the harness suites' own `ok "…"` / `fail "…"` helper calls. They
  never match a bare `[ … ]` test or the word `should`, which would flag ordinary sh edits.
  A repo extends them through `change_size.assert_patterns`; an empty or absent list means
  built-ins only.
- **Waivers are exact, per test, in `.tasks.md`.** A line
  `waive-test-drift: <exact test name> — <reason>` waives every finding attributed to that
  one test name and nothing else. The flag that points the tool at the file is
  **`--tasks-md`**, named for what it reads; the brief's `--tests-md` spelling is **not** a
  flag (an unknown flag is a usage error) because the waiver does not live in `.tests.md`.
- **Fail closed at the gate.** For the Reviewer, exit `1` is a REJECT unless waived; exit
  `2`/`3` means the check did not run and is not a verdict — fix the invocation and re-run.
- **Merge-base mode is the contract.** Pair commits (E36-F01), when present, are additional,
  finer-grained baselines the Reviewer also runs against. Nothing here depends on E36-F01.
- **`sh tools/run-tests.sh` stays the Reviewer's primary command.** This is an added check.
- **Generated glue is never hand-edited.** `.claude/agents/*`, `.claude/commands/*`,
  `.codex/`, `.opencode/`, `.pi/`, `.agents/` are installer output. The Reviewer prose is
  edited in canonical `agents/reviewer.md` only; if a generated surface must change, the
  path is `sh harness-install.sh --self` and committing the regenerated output.
- **Permanent-suite anti-pattern.** No test freezes the exact `VERSION` or diffs a
  DO-NOT-TOUCH file against `main`. Fixtures are fresh temp git repos, never copies of this
  repo.

## Definitions (normative — the tests use these exact terms)

- **Base.** The commit `git merge-base <base-ref> <head>` where `<head>` is `<head-ref>` when
  given, else `HEAD`. Passing the default branch therefore yields merge-base semantics;
  passing a pair commit that is an ancestor of head yields that commit itself.
- **Head side.** When `<head-ref>` is omitted, the **working tree** (committed + staged +
  unstaged changes relative to base, plus untracked non-ignored files, exactly the set
  `tools/change-size.sh` measures). When `<head-ref>` is given, that commit only.
- **Touched test file.** A path in the diff (added, deleted, modified, or renamed — renames
  by git's default detection, compared old path → new path) whose **repo-relative path**
  matches the effective test ERE (R2). A deleted test file yields findings for every name
  and assertion it held. Paths containing LF or TAB are a documented non-goal.
- **Assertion line.** A diff content line (`-` or `+`, excluding the `---`/`+++` headers)
  whose text matches at least one entry of the effective assertion pattern list (R4 + R5).
- **Hunk pairing (modified vs removed).** Within one `-U0` hunk, list the `-` assertion
  lines and the `+` assertion lines in order. The k-th `-` and the k-th `+` form one
  **`assert-modified`** finding (detail `old -> new`); each `-` assertion line without a
  partner is an **`assert-removed`** finding; each `+` assertion line without a partner is
  an addition and is **never** a finding. A line moved verbatim elsewhere is still a `-`
  line and is a finding (waivable) — the tool does not track moves.
- **Skip marker.** A `+` line matching an entry of the built-in marker list (R6).
- **Test name.** A string extracted from a file's text by the built-in extractors (R7).
  A file no extractor recognizes contributes **no** names (its assertions and markers are
  still checked).
- **Attribution (enclosing test).** Each `assert-*` / `skip-added` finding carries exactly
  one test name: the nearest extracted name by line distance in the direction the extractor
  declares — **definitions** (sh `name()`, py `def test_`, JS `it(`/`test(`/`describe(`, Go
  `func Test`) attribute **backward** (nearest at or before the line); sh **labels**
  (`pass "…"`, the house success-record call) attribute **forward** (nearest at or after the
  line, since a label closes the block above it); and a Python/Java **decorator line**
  (`^[[:space:]]*@`) attributes **forward** to the next definition, since it decorates what
  follows. When a backward and a forward candidate both exist, the nearer by line distance
  wins; on a tie the backward definition wins. `-` lines (and therefore every `assert-*`
  finding, including `assert-modified`) attribute in the **base** file; `+` lines
  (`skip-added`) attribute in the **head** file. When no name exists, the test name is the
  repo-relative path itself, and a waiver may name that path exactly (it then waives only
  unattributable findings in that file).
- **Finding line.** One stdout line: `DRIFT <kind> | <path>:<line> | <test name> | <detail>`
  — the separator is exactly space, `|`, space; no padding — with `<kind>` ∈
  {`assert-modified`, `assert-removed`, `skip-added`, `test-removed`}, `<path>` the head path
  (old path for a deleted file), `<line>` the base line number for `-`-derived findings, the
  head line number for `skip-added`, and the literal `—` for `test-removed` (a removed name
  has no single line). `<detail>` is the last field and may contain anything (the removed
  text; `old -> new`; the marker line; the removed name). A waived finding prints the same
  shape with the prefix `WAIVED` and the waiver's reason as detail.
- **Summary line.** Exactly one stdout line, always last:
  `test-drift-check: <N> findings, <W> waived, <F> test files examined (base <short-sha>)`
  where `N` counts every finding **including** waived ones (`N` = `DRIFT` lines + `WAIVED`
  lines), `W` the waived subset, and `F` every touched test file (renames without content
  change and binary files included; files that produced no finding included).

## Architecture alignment

`specs/architecture.md` is absent in this repository. The ADR set under `specs/adr/` is
present, so citations are required. This is a single-namespace project, so bare ids are
used. ADR ids seeded from the brief: ADR-0008; added from the epic's pointer for F06:
ADR-0002.

- ADR-0008 — Vertical slices are the unit of decomposition; tasks pair one failing test with
  the code that passes it: this feature is the Consequences bullet made real ("the Reviewer
  gains a model-independent signal for test tampering"). The tool diffs test files from a
  baseline (merge-base always; a pair commit when one exists) so a later weakening of a
  test that went green is a detectable diff, and the Reviewer gate consumes it.
- ADR-0002 — `builder-heavy` is a model tier, not a second Builder prompt: the check is a
  tool with an exit code, run by the Reviewer regardless of which tier built the feature;
  it adds no Builder prose and no second Builder discipline, so escalation stays a pure
  routing decision.

## Acceptance criteria (EARS)

> Each is one testable behavior with a stable id. See `docs/SPEC-FORMAT.md`.

- **R1 — Scope and baseline.** When invoked as `tools/test-drift-check.sh <base-ref>
  [<head-ref>]` inside a git repository, the tool shall examine exactly the touched test
  files between the base (`git merge-base <base-ref> <head>`) and the head side (working
  tree incl. untracked non-ignored files when `<head-ref>` is omitted; the named commit
  otherwise), and shall emit no finding for a changed file whose path is not a test file,
  even when that file loses a line matching an assertion pattern.
- **R2 — Classifier and config reuse.** The tool shall obtain its test-path ERE solely by
  invoking the sibling `tools/change-size.sh --print-test-re --repo <top>` (sibling resolved
  relative to its own location; `<top>` = `git rev-parse --show-toplevel` of the cwd), and
  shall obtain the configured `change_size.assert_patterns` entries solely by invoking
  `tools/change-size.sh --print-list assert_patterns --repo <top>`. `change-size.sh
  --print-test-re` shall print the built-in `TEST_RE` extended by every
  `change_size.test_paths` entry on one line; `--print-list <key>` shall print each entry of
  the named `change_size:` list on its own line (nothing for an absent or empty list); both
  use the measuring path's `HARNESS_DIR` / `.harness/` / repo-root config resolution, exit
  `0`, and require no base ref. Replacing the sibling with a stub that prints a different
  ERE shall change which files the drift tool examines.
- **R3 — Assertion findings.** When a touched test file's diff contains a `-` assertion
  line, the tool shall report it as `assert-modified` when hunk pairing gives it a `+`
  partner and as `assert-removed` otherwise, one finding line per `-` assertion line, each
  attributed to its enclosing test; `+` assertion lines without a partner shall produce no
  finding.
- **R4 — Built-in assertion patterns.** The tool shall ship a built-in assertion pattern
  list (extended regular expressions, matched against the line text) that matches each of:
  a word-bounded `assert` family (`assert …`, `assert(`, `assertEqual(`, `assert.ok(`,
  `assert_eq!(`), `expect(`, `t.is(`/`t.ok(` (and the ava/Go `t.<method>(` family named in
  the plan), `fail(`, `raises(`/`pytest.raises(`, and the harness suites'
  `ok "…"`/`fail "…"`/`fail '…'` helper calls; and that shall **not** match a line whose only
  test-like content is a bare `[ … ]` conditional, the word `should`, or a `pass "…"` label.
- **R5 — Configured assertion patterns.** Where `change_size.assert_patterns` in the
  resolved `harness.config.yaml` lists one or more entries (read per R2), the tool shall
  treat each entry **verbatim** as an additional assertion ERE (never replacing the
  built-ins; no YAML unescaping is performed, so a literal `(` is written `[(]`, e.g.
  `- "verify[(]"`); when the key is absent or the list is empty, the tool shall use the
  built-ins only.
- **R6 — Skip markers.** When a touched test file's diff (including a wholly new file)
  contains a `+` line matching a built-in skip marker (`.skip(`, `.only(`, `.todo(`,
  `xit(`/`xtest(`/`xdescribe(`, `@pytest.mark.skip`/`skipif`/`xfail`, `pytest.skip(`,
  `@unittest.skip*`/`expectedFailure`, `t.Skip*(`, `#[ignore`, `@Disabled`/`@Ignore`, and
  the harness suites' quoted `skip - ` literal), the tool shall report one `skip-added`
  finding per such line; a removed marker shall produce no finding.
- **R7 — Test names and `test-removed`.** The tool shall extract test names with these
  built-in extractors — sh: a function definition `name()` and the quoted label of a
  `pass "…"` call (not `ok`, which is an assertion helper); Python: `def test_*` (incl.
  `async def`); JS/TS: the first
  string argument of `it(`/`test(`/`describe(`; Go: `func Test*(` — and shall report one
  `test-removed` finding for each name present in a touched test file at base and absent
  from the same file (new path for a rename) at head; a rename with no content change shall
  produce no finding.
- **R8 — Clean run.** If no touched test file yields a finding (no test change at all, or
  pure additions of files, tests and assertion lines), then the tool shall exit `0` and
  print exactly one line on stdout — the summary line — and nothing on stderr.
- **R9 — Exit codes and finding format.** The tool shall exit `1` when at least one
  unwaived finding exists, printing each finding as a finding line followed by the summary
  line; exit `2` on a usage error (no `<base-ref>`, unknown flag such as `--tests-md`,
  `--tasks-md` without a readable file, malformed waiver line); and exit `3` when it cannot
  diff (not a git repository, `<base-ref>` or `<head-ref>` does not resolve, no merge base),
  with a one-line reason on stderr for `2` and `3`.
- **R10 — Waivers.** Where `--tasks-md <file>` is given, the tool shall read every line
  matching `^[[:space:]]*(-[[:space:]]+)?waive-test-drift:[[:space:]]*<name>[[:space:]]+—[[:space:]]+<reason>`
  (`—` is U+2014; `<name>` and `<reason>` non-empty after trimming), shall mark as `WAIVED`
  every finding whose attributed test name equals `<name>` byte-for-byte, shall leave every
  other finding unwaived (a prefix, a different name, or a second test in the same file is
  not waived), and shall exit `0` with `W > 0` in the summary when every finding is waived.
- **R11 — Reviewer gate and control row.** `agents/reviewer.md` shall carry a section
  headed `## Test-drift check before the verdict (E36-F06)`, placed after the change-size
  section and before `## Verdict`, that instructs the Reviewer to run
  `tools/test-drift-check.sh` with base = the default branch (merge-base taken by the tool,
  never a hard-coded `origin/main`) and `--tasks-md <feature>.tasks.md`; to additionally run
  it per pair commit → head, with the same `--tasks-md`, when E36-F01 pair commits exist; to
  treat exit `1` as a REJECT unless waived via `waive-test-drift:`; to treat exit `2`/`3` as
  "the check did not run" (re-run; never approve on an unrun check); and to keep
  `sh tools/run-tests.sh` as the primary command. `docs/RATIONALE.md`'s deletion ledger shall carry a `D14 — Test-assertion
  drift check` row in the Durable trust and intent layer pointing at the tool and the
  Reviewer section.
- **R12 — Shipped body.** The installer shall install `tools/test-drift-check.sh` executable
  under `.harness/tools/`, the installed `agents/reviewer.md` shall name it, the
  `change_size:` block seeded by `harness-install.sh` and the one in the root
  `harness.config.yaml` shall both carry `assert_patterns: []` and shall be byte-identical
  to each other; `VERSION` shall be bumped one SemVer MINOR and `CHANGELOG.md` shall carry a
  matching entry naming E36-F06 (no test asserts the literal version).

## Out of scope

- Mutation testing; judging assertion *strength*; any AST or language-server parsing.
- pr-fixer changes; Builder prose changes; a second scheduler or stored state.
- Tracking moved assertions (a verbatim move is a `-` line and needs a waiver).
- Multi-line assertions: only the physical lines that match a pattern are detected.
- A `change_size.skip_patterns` or `test_name_patterns` config key (not asked for; the
  built-in lists are documented in the plan and extendable in a later feature).
- Pathnames containing LF or TAB (documented non-goal, as in the brief's `sh + git + awk`
  constraint).
- Any change to `pr_loop` or to the Reviewer's R-id↔test traceability rule (epic non-goal).

## Open questions
