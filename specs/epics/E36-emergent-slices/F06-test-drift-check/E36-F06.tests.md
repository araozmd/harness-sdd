# Test-assertion drift check — Test Contract

> The traceability matrix: every R-id in `E36-F06.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any R-id lacks a passing test.
>
> All new cases live in `tests/test_test_drift_check.sh` (POSIX `sh`, `#!/bin/sh`,
> `set -eu`, `LC_ALL=C`, the house `fail`/`pass` helpers; discovered automatically by
> `tools/run-tests.sh` as `tests/test_*.sh` and executed under the strict shell, so it must
> parse and run under dash). `tests/test_drift_check.sh` is an unrelated existing suite.
>
> **Fixture rules (from `progress/lessons.md`).** Every case builds its own throwaway git
> repo under `mktemp -d` (`mkrepo`: `git init -q`, user config, `checkout -q -b main`, seed
> commit, `checkout -q -b feature`) — never a copy of this repo. Each fixture changes **one
> thing**, so only the code path under test can produce the expected line: a weakened-assert
> fixture keeps every test name intact (else `test-removed` alone reddens it); a deleted-test
> fixture deletes a body with **no** assertion-pattern line (else `assert-removed` alone
> reddens it). Exit codes `0/1/2/3` are the tool's own documented contract and ARE asserted
> exactly; lookup misses (`command -v`) are asserted `≠ 0` only. Tools are invoked as
> `sh "$ROOT/tools/<tool>.sh"` (never a bash-shebang script via `sh`). Assertions about one
> finding anchor its `DRIFT <kind>` prefix and its payload on the **same line**. Prose
> contracts slice the section with `tests/lib/fence.awk` and anchor tokens inside that slice.
> Any case that runs `harness-install.sh` does so under
> `env -i PATH="$PATH" HOME="$T/home" CODEX_HOME="$T/ch"` so no global prompt dir or real
> home is touched. Exit-2 fixtures always pass a VALID base ref so only the flag under test
> can produce the 2. No case asserts the exact `VERSION` literal or diffs a DO-NOT-TOUCH file
> against `main`. Case names below are the `pass "<name>"` labels.

## Behavioral / end-to-end checks (Reviewer)

- On this very branch: `sh tools/test-drift-check.sh main --tasks-md specs/epics/E36-emergent-slices/F06-test-drift-check/E36-F06.tasks.md`
  exits 0, and every finding it prints is a `WAIVED` line whose name appears under the
  tasks file's `## Waivers` with an honest reason (the new suite's marker literals;
  `test_rationale_docs.sh`'s 13→14 edits). Run it once WITHOUT `--tasks-md`: exit 1 and the
  same lines as `DRIFT` — proving the waivers, not an absence of findings, produced the 0.
  Then, in a scratch copy, weaken one assertion in `tests/test_test_drift_check.sh` itself
  and re-run: exit 1 with one unwaived `DRIFT assert-modified` line naming that suite.
- Mutation (3b), one at a time with `*.mutbak` restore, confirming the suite goes RED:
  - swap `assert-modified`/`assert-removed` pairing (always report removed) → `R3a` reds;
  - drop the `--print-test-re` call and hard-code `TEST_RE` → `R1d_stub_classifier` reds;
  - add `should` to the built-in list → `R4b_negatives` reds;
  - make waiver matching a prefix match → `R10b_non_match` reds;
  - compare waiver names case-insensitively → add a probe (`Test_gone`) and confirm `R10b`
    or a sibling reds — if nothing reds, that is an unpinned degree of freedom to report;
  - delete the `assert_patterns` lines from ONE of the two seed copies →
    `test_change_size_block_seeded_vs_heredoc_converge` reds and names the source;
  - remove `!fence` guarding from the R11 slicer → `tests/test_change_size.sh` R9d (the
    repo-wide fence-rule meta-check over `tests/test_*.sh`) reds.
- Runner: `sh tools/run-tests.sh` summary names the strict shell (dash where available); the
  new suite and `tools/test-drift-check.sh` pass the `-n` pre-flight under it.
