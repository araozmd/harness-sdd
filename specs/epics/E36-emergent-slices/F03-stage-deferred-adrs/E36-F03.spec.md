# Product stage and deferred-decision ADRs with triggers — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E36-F03:R1 … E36-F03:R12`.

## Context

On MVP and pilot projects the Architect's `.plan.md` grows encryption at rest, a WAF, rate
limiting and retries that no requirement asked for, because nothing in the project says what
stage it is in and the model fills the gap with production defaults. "Be minimal" is
compliance prose that ablates (docs/RATIONALE.md). ADR-0009 decisions 1–3 record the
structural alternative: **declare the stage once** in `specs/product.md` frontmatter; **defer
bolt-on NFRs by writing** a deferred-decision ADR with a `Trigger:` line, never by omitting
them; **never defer sticky NFRs** at any stage. This feature ships the declaration (the
installer stub and this repo's own `product.md`), the two template shapes (ADR
`Status: deferred` + `Trigger:`; plan `## Deferred`), the role prose that reads the stage
(Planner, Driller, Architect), and the docs. Everything here is **declare and record**;
**enforcement** — the plan-row citation tool, the `init.sh` trigger sweep, the doc-critic
flags and the Reviewer gate (ADR-0009 decision 4) — is E36-F04, which depends on this
feature and lints exactly the forms pinned under *Business rules → The citation grammar*.

The user is anyone running `/sdd-plan` → `/sdd-drill` → `/sdd-next`, in this repo or in a
consumer repo that installed the harness. A project that never declares a stage sees no
behavior change: absent means `production`, which is today's behavior.

**Complexity basis.** `complex`, on two stated signals from `agents/architect.md`:

- the spec sits exactly at `change_size.max_requirements` (12 of 12); the seam I would split
  on (templates/installer vs. role prose) would ship a `## Deferred` shape no role fills, or
  prose pointing at a template that does not exist, so it is not split;
- it carries one grammar in more than one place — the stage frontmatter line, the deferred-ADR
  header form and the plan-row citation form are stated in `specs/_templates/adr.md`,
  `specs/_templates/feature.plan.md`, `agents/architect.md`, `docs/SPEC-FORMAT.md` and
  `docs/WORKFLOW.md`, and E36-F04 will build a lint against them. A validator that disagrees
  with its schema is a defect class the harness has already paid for (lessons 2026-09-05,
  2026-09-16); here the schema ships first, so it must be stated once and copied exactly.

## Business rules

- **The stage is declared once, in `specs/product.md` frontmatter** (ADR-0009 decision 1):
  a line `stage: discovery | pilot | production` inside the file's first `---` YAML block.
  **Absent or unrecognized ⇒ `production`** — the default is today's behavior, so a project
  that never sets it sees no change. `specs/product.md` is **project-owned**: the installer
  seeds the stub once and never overwrites project edits; no role rewrites it (the Planner's
  existing rule stands). The value is read, never inferred: a role that wants the stage runs
  `sed -n '/^---$/,/^---$/p' specs/product.md | grep '^stage:'` (or the equivalent) and takes
  the literal.
- **Bolt-on NFRs are deferred by writing, not by omitting** (decision 2). For each bolt-on the
  stage excludes, the Architect writes or cites a deferred-decision ADR — an **ordinary ADR**
  at `specs/adr/NNNN-<title>.md` (4-digit, strictly above the max existing number, no reuse —
  the Driller's allocation rule) whose header carries `- **Status:** deferred` and a
  **mandatory** `- **Trigger:** <observable condition>` line (first regulated customer, N
  users, a named compliance deadline). The ADR is the parking lot; the plan cites it. A
  deferred ADR is **not an ADR delta**: it records no change to an accepted decision, it
  records a decision *not yet taken* and the tripwire that reopens it — so it is the **one
  ADR kind the Architect may author**; the existing rule that the Architect never authors
  an ADR delta (that is the Driller's job) stands for every other ADR.
- **Sticky NFRs are never deferred at any stage** (decision 3). The list is short and lives
  in `specs/_templates/adr.md`'s guidance: **tenant isolation, the auth boundary, secrets out
  of the repo, validation at the system edge**. Extending it is a change to ADR-0009 (a spec
  change), not a role's judgment call. The bolt-on examples live beside it: **encryption at
  rest, WAF, rate limits, backups, caching**.
- **A bolt-on is never added without an `R-id`.** When a plan carries a bolt-on (a WAF row, a
  retry policy, a cache), the row cites the `R-id` that asked for it; if no `R-id` asks, the
  Architect either defers it (a row in `## Deferred`) or drops it — never adds it silently.
  This is Architect prose here; E36-F04 makes an uncited row a rejection.
- **The citation grammar (what E36-F04 will lint).** Stated once here, copied exactly into
  the template, the role prose, SPEC-FORMAT and WORKFLOW:
  1. **Stage line** — in `specs/product.md`, inside the first `---` block:
     `^stage: (discovery|pilot|production)$` — the value is the whole rest of the line, so
     no inline comment is allowed on it (explanatory comments go on their own `#` line in
     the block, as the stub shows). Absent or any other value reads as `production`.
  2. **Deferred ADR header** — in `specs/adr/NNNN-*.md` (or a product space's `adr/`):
     a line `^- \*\*Status:\*\* deferred` **and** a line `^- \*\*Trigger:\*\* ` followed by
     a non-empty condition. `deferred` without a `Trigger:` line is a defect (F04's sweep).
  3. **Plan-row citation** — every table row under a `.plan.md`'s `## Data model`,
     `## API / interface`, `## Files to change` and `## Deferred` headings carries an
     `R[0-9]+` token or an `ADR-[0-9]{4}` token (ADR-0009 decision 4; the `<ns>/ADR-NNNN`
     qualified form counts, the `ADR-` prefix is what is matched).
  4. **`## Deferred` subsection** — in `.plan.md`, either a table with header
     `| Bolt-on | Deferred by | Trigger |` whose every row's *Deferred by* cell holds an
     `ADR-[0-9]{4}` token, **or** the single literal line `Deferred: none — <why>`
     (e.g. `Deferred: none — stage is production`). Never both, never neither.
- **Roles read the stage; only the human writes it.** The Planner reads it before writing
  `architecture.md` and the ADRs and scopes upfront NFR decisions to it (a bolt-on the stage
  excludes becomes a deferred ADR with a trigger, not an accepted one and not an omission);
  the Driller reads it with the design artifacts and records `Stage: <value>` in every inbox
  brief's `## Constraints` beside the `ADR-NNNN` ids (the F03-D7 hook, so the Architect
  receives the stage from the brief it specs from); the Architect reads it and applies the
  rules above. None of them writes `specs/product.md`.
- **No enforcement here.** The plan-cite tool, the `init.sh` warn-only sweep for `deferred`
  ADRs lacking a `Trigger:`, the doc-critic flags and the Reviewer rejection are E36-F04. This
  feature's tests pin **shapes and prose**, not behavior of a lint.
- **Generated glue is never hand-edited.** `.claude/`, `.codex/`, `.opencode/`, `.pi/`,
  `.agents/` are regenerated by `sh harness-install.sh --self`. This feature changes **no
  emitter** (role shims point at the canonical files; the installer edit is the project-owned
  stub text and its guarded refresh, not glue), so `--self` must produce no diff;
  `tests/test_self_drift.sh` is the check.
- **Guarded stub refresh, one rule, no flag.** The installer's `specs/product.md` branch
  already migrates a file byte-identical to a *known prior shipped stub* and preserves
  everything else byte for byte. The stub shipped from v0.81.1 through the release before
  this one becomes a second known prior; a target whose `product.md` is still that pristine
  text is refreshed to the new stub (it gains `stage:`), an edited one is preserved. A target
  whose stub is **not** refreshed loses nothing: absent `stage:` is `production`.
- **Installed body changes ⇒ SemVer MINOR bump** (installer stub, three role files, two
  templates, two docs), with a `CHANGELOG.md` entry. The target is the **next MINOR over the
  then-current `VERSION`** at merge time (W1 siblings bump in parallel; the Builder re-reads
  `main` before the final rebase). "MINOR, not PATCH" is verified by the Reviewer reading the
  diff; no test freezes the literal or diffs a DO-NOT-TOUCH file against `main` (lesson
  2026-09-16) — DO-NOT-TOUCH files are checked with `cksum` before/after.

## Architecture alignment

> `specs/architecture.md` is **absent** in this repo (never written; the ADR set exists under
> the single platform space `specs/adr/`). Per `agents/architect.md` graceful degradation the
> section is not strictly required; it is written anyway because the brief records the ADR
> this feature ships, and the Reviewer's ADR-citation clause keys on `sdd: true`.

- platform ADR-0009 — Non-functional requirements are stage-aware: this feature **implements
  decisions 1–3** (the `stage:` declaration with absent ⇒ `production`; deferred ADRs with a
  mandatory `Trigger:`; the sticky list that is never deferred) as a stub field, two template
  shapes, three role sections and two doc sections. It **records** decision 4's citation
  grammar (plan rows cite an `R-id` or an `ADR-NNNN`) in the plan template and SPEC-FORMAT so
  E36-F04 can enforce it, and implements none of the enforcement.
- platform ADR-0008 — Vertical slices / red-green pairs: this feature's own `.tasks.md` is in
  pair form and orders the installer stub (the only behavior observable at the product
  boundary — a fresh install's file) first; the plan template's new subsection cites `R-id`s
  the same way the existing sections do.

**Stated refinement, not a divergence.** `agents/architect.md` today says the Architect
"do[es] not author an ADR delta". ADR-0009 decision 2 has the Architect *write or cite* a
deferred-decision ADR. This spec reconciles them by definition, not by exception: a deferred
ADR records a decision not yet taken plus its trigger, so it is not a delta to any accepted
decision; the Architect's new section says so and the "no ADR delta" sentence is left intact.

## Acceptance criteria (EARS)

> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md.

- **R1** — When `harness-install.sh` runs against a target with no `specs/product.md`, the
  installer shall seed `.harness/specs/product.md` whose first `---` YAML block contains the
  exact line `stage: production` (no trailing comment — the line must match the stage-line
  regex) preceded by a separate `#` comment line naming `discovery | pilot | production` and
  stating that an absent value means `production`, and shall print the existing
  `seeded specs/product.md (stub)` verdict.
- **R2** — If a target's `.harness/specs/product.md` is byte-identical to the stub shipped
  from v0.81.1 (the `/sdd-plan` front-door text without a `stage:` line), then an upgrade run
  shall replace it with the current stub and print a stdout line containing
  `specs/product.md refreshed`; while if the file differs from every known shipped stub, the
  run shall leave it byte-identical and print `specs/product.md preserved`.
- **R3** — This repository's `specs/product.md` shall begin with a `---` YAML frontmatter
  block that contains the line `stage: production`.
- **R4** — `specs/_templates/adr.md` shall list `deferred` as a `Status:` value beside
  `proposed` and `accepted`, and shall carry a header line beginning `- **Trigger:**` whose
  guidance states the line is **mandatory** when the status is `deferred` (the observable
  condition that reopens the decision) and omitted otherwise.
- **R5** — `specs/_templates/adr.md` shall carry guidance naming the four sticky NFRs
  (`tenant isolation`, `auth boundary`, `secrets out of the repo`, `validation at the system
  edge`) with the sentence `never deferred at any stage`, the five bolt-on examples
  (`encryption at rest`, `WAF`, `rate limits`, `backups`, `caching`), and the statement that
  extending the sticky list is a change to ADR-0009 (a spec change), not a role's judgment.
- **R6** — `specs/_templates/feature.plan.md` shall carry a `## Deferred` subsection whose
  body is the table header `| Bolt-on | Deferred by | Trigger |` with an `ADR-NNNN`
  placeholder row **and** guidance naming the alternative single line `Deferred: none — <why>`
  and the stage source (`specs/product.md` frontmatter, `production` when absent); and the
  template's header blockquote shall state that every table row cites the `R-id` it serves
  or the `ADR-NNNN` that defers it.
- **R7** — `agents/architect.md` shall carry a section `## Stage and NFRs (ADR-0009)` that
  tells the Architect to read `stage:` from `specs/product.md` frontmatter (absent or
  unrecognized ⇒ `production`); when the stage is `discovery` or `pilot`, to write or cite one
  deferred ADR (`- **Status:** deferred` with a `- **Trigger:**` line) per bolt-on it leaves
  out and cite it from `## Deferred` or the plan row; never to add a bolt-on without an
  `R-id`; that sticky NFRs are `never deferred at any stage`; and that a deferred ADR is the
  one ADR kind the Architect may author — while keeping the existing "does not author an ADR
  delta" sentence and every other section intact.
- **R8** — `agents/planner.md` shall carry a section `## Stage (ADR-0009)` that tells the
  Planner to read `stage:` from `specs/product.md` frontmatter before writing
  `specs/architecture.md` and the ADRs (absent ⇒ `production`), to record a bolt-on the stage
  excludes as a deferred ADR with a `Trigger:` rather than an accepted ADR or an omission, to
  never write `specs/product.md` itself, and to name the stage it read in its completion
  report.
- **R9** — `agents/driller.md` shall carry a section `## Stage (ADR-0009)` that tells the
  Driller to read `stage:` from `specs/product.md` frontmatter with the design artifacts
  (absent ⇒ `production`) and to record `Stage: <value>` in every inbox brief's
  `## Constraints` section beside the recorded `ADR-NNNN` ids; and
  `specs/_templates/inbox-brief.md` shall carry a `Stage:` placeholder line under
  `## Constraints`.
- **R10** — `docs/WORKFLOW.md` shall carry a section `## Stage and NFRs (ADR-0009)` with a
  two-column table headed `| Sticky (never deferred) | Bolt-on (deferred by an ADR with a
  trigger) |` listing the four sticky and five bolt-on items of R5, the stage field and its
  default, the deferred-ADR and `## Deferred` forms, and the statement that enforcement
  (the citation tool, the trigger sweep, the Reviewer gate) is `E36-F04`.
- **R11** — `docs/SPEC-FORMAT.md` shall carry a section `## Plan rows cite an R-id or an
  ADR` that states the four grammar items of *Business rules → The citation grammar*
  verbatim in substance: the stage line regex `^stage: (discovery|pilot|production)$`, the
  deferred-ADR header lines `- **Status:** deferred` and `- **Trigger:**`, the plan-row rule
  (`R[0-9]+` or `ADR-[0-9]{4}` token in every row under the four headings), and the
  `## Deferred` two-form rule (`| Bolt-on | Deferred by | Trigger |` table or
  `Deferred: none — <why>`), naming `E36-F04` as the lint that enforces them.
- **R12** — `VERSION` shall change from its `main` value (the Reviewer confirms a MINOR step
  from the diff), `CHANGELOG.md` shall carry a `## [<that version>] — <date>` section whose
  body names `E36-F03` and `stage`, and the newest `## [` heading shall equal the `VERSION`
  file's value — read at test time, never as a frozen literal; the section check anchors on
  the historical body text, so a later release prepended above it stays green.

## Out of scope

- The plan-row citation tool (`plan-cite-check`), the `init.sh` warn-only sweep of `deferred`
  ADRs lacking a `Trigger:`, the doc-critic flags for an uncited row or a deferred sticky
  NFR, and the Reviewer rejection — all E36-F04 (ADR-0009 decision 4; brief).
- Any runtime security scanning; a security checklist product (epic non-goal).
- Changing existing ADRs (`0001`–`0010`) or retro-fitting `## Deferred` onto `done` or
  in-flight features' `.plan.md` files — no retro-fit; E36-F04 decides how it treats plans
  written before this merged.
- A `stage` field on the TaskStore (`state/tasks.json` / `store/tasks.schema.json`) or in
  `harness.config.yaml` — the stage is product constitution, not board state or harness
  config (brief: chosen option "stage lives in `specs/product.md` frontmatter").
- Reading the stage anywhere but the roles' prose — no tool resolves it in this feature.
- A `docs/RATIONALE.md` deletion-ledger row: this feature ships a schema field and two
  template shapes (structure, not a compensation mechanism); E36-F04's lint is the
  compensation and gets the row.
- Touching `agents/doc-critic.md`, `agents/reviewer.md`, `agents/builder.md`, or any
  `/sdd-*` command emitter in `harness-install.sh`.
- The Driller's observable-slice / walking-skeleton rules (E36-F02) — the Driller edit here
  is one new standalone section so the two branches merge cleanly.
