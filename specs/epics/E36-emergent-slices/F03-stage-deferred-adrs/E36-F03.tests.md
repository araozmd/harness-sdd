# Product stage and deferred-decision ADRs with triggers — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and every row names the mutant that kills it. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives.
>
> **Suite.** A new POSIX `sh` suite, `tests/test_stage_nfrs.sh` (SN), `set -eu`, `fail`/`pass`,
> run by `tools/run-tests.sh` under the strictest shell it can probe (dash on CI) — assert
> `rc -eq N`, never a shell-dependent code. At the top it performs **one fresh install**:
> `T="$(mktemp -d)"`, `CODEX_HOME="$T/ch" HOME="$T/home" sh "$ROOT/harness-install.sh"
> --agents=claude "$T/tgt"`, `I="$T/tgt/.harness"`; `trap 'rm -rf "$T"' EXIT` and
> `trap 'exit 1' HUP INT TERM`. Every prose contract is a **whole-file** `grep -qF` /
> `grep -qE` on the **installed** copy under `$I` (no heading slicer — nothing to be
> fence-blind about); co-occurrence anchors fold newlines (`tr '\n' ' ' | grep -qiE
> 'A[^.]{0,80}B'`). R3 greps the source `specs/product.md` (project-owned, not installed).
> The suite never reads `VERSION` as a literal, never diffs a DO-NOT-TOUCH file against
> `main`, never writes `state/` or a live spec. Installer behavior (R1, R2) lives in
> `tests/test_install.sh` beside the existing `product.md` assertions.
>
> **Markdown escaping.** Table cells below escape `|` as `\|` for markdown only. The literal
> grep strings are `proposed | accepted | deferred`, `| Bolt-on | Deferred by | Trigger |`
> and `| Sticky (never deferred) | Bolt-on (deferred by an ADR with a trigger) |` — bare
> pipes, no backslash (`grep -qF` takes them literally).
>
> **Pre-change RED.** Each anchor was confirmed RED on the pre-change blob (install from a
> `git stash`-ed tree into a second temp dir) before being trusted — lesson 2026-09-06.

Re-install into a fresh temp dir after each prose mutant (the suite reads installed copies).

## Behavioral / end-to-end checks (Reviewer)

- Fresh install into an empty temp dir (`CODEX_HOME`/`HOME` sandboxed): open
  `.harness/specs/product.md` — the frontmatter reads `status: draft`, a `# stage: …` comment
  line, then the bare `stage: production`; run `sed -n '/^---$/,/^---$/p' .harness/specs/product.md | grep '^stage:'` — one
  line. Then run the same pipeline on this repo's `specs/product.md` — `stage: production`.
- Take a done feature's `.plan.md` (e.g. `E36-F01.plan.md`) and this feature's own: the
  latter carries `## Deferred` with `Deferred: none — stage is production`; the former does
  not and is **not** expected to (no retro-fit).
- Write a throwaway deferred ADR from the installed template into a scratch dir: the header
  has `- **Status:** deferred` and `- **Trigger:**`; the guidance block names the four sticky
  and five bolt-on items. Delete it.
- Simulate the v0.81.1 target by hand: `sh harness-install.sh <dir>`, overwrite
  `<dir>/.harness/specs/product.md` with `git show main:harness-install.sh | sed -n
  '/PRODUCT_STUB_CURRENT_EOF$/,/^PRODUCT_STUB_CURRENT_EOF/p' | sed '1d;$d'`, re-run — stdout
  says `refreshed`, file gains `stage:`. Append a line, re-run — `preserved`.
- `sh harness-install.sh --self` leaves `git status --short` empty of generated-glue paths.
- `cksum` of every DO-NOT-TOUCH file recorded before T1a equals the value after T13b.

  no bare `/^#+ /` idiom crept in).

  one ~200-line suite, prose).
