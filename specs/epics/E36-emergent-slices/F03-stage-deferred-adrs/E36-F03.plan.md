# Product stage and deferred-decision ADRs with triggers — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it serves (or
> the ADR that defers it — this plan dogfoods its own `## Deferred`). Start high-level; don't
> over-specify internals that might be wrong. The Builder reads `progress/lessons.md` first;
> the lessons this plan leans on are named inline.

  tasks-lock remaps linked worktrees).
- **Test-runner slot.** Another worker may hold this machine's single runner slot; run only
  the suites you touched (`sh tests/test_stage_nfrs.sh`, `sh tests/test_install.sh`,
  `sh tests/test_architect_adr.sh`, `sh tests/test_sdd_plan.sh`, `sh tests/test_sdd_drill.sh`,

  relaunch a run that was killed.

## Data model  (serves: R1, R3, R4, R6, R11)

No stored state. The only data model is the **citation grammar**, one definition carried on
five surfaces (ADR template R4, plan template R6, Architect R7, SPEC-FORMAT R11, WORKFLOW R10)
that E36-F04 will lint. Pin it here once; copy it, do not paraphrase it:

| Entity | Form | Notes | R-id |
|---|---|---|---|
| stage line | `^stage: (discovery\|pilot\|production)$` inside the first `---` … `---` block of `specs/product.md` | absent or any other value ⇒ `production`. Read with `sed -n '/^---$/,/^---$/p' specs/product.md \| grep '^stage:'`. **No inline comment on the value line** — the regex is `$`-anchored, so `stage: pilot   # …` would silently read as `production`; the stub puts its explanation on a separate `#` comment line inside the block (doc-critic finding 1). | R1, R3, R11 |
| deferred ADR header | `^- \*\*Status:\*\* deferred` **and** `^- \*\*Trigger:\*\* \S` | both lines in the header list under the `# ADR-NNNN —` title, where `Status:` / `Date:` already sit. `deferred` without `Trigger:` is a defect (F04's sweep). The filename and numbering are the ordinary ADR rule (4-digit, above max, no reuse). | R4, R11 |
| plan-row citation | a table row (`^\|`) under `## Data model`, `## API / interface`, `## Files to change`, `## Deferred` carries an `R[0-9]+` or `ADR-[0-9]{4}` token | the header and separator rows are exempt; `<ns>/ADR-NNNN` qualifies because `ADR-` is what is matched. The `(serves: …)` suffix on a heading does not stand in for a row citation. | R6, R11 |
| `## Deferred` | **either** a table headed `\| Bolt-on \| Deferred by \| Trigger \|` with ≥1 rows whose second cell holds `ADR-[0-9]{4}`, **or** exactly one line `Deferred: none — <why>` | never both, never neither; the *Trigger* cell copies the ADR's `Trigger:` text so the plan is readable without opening the ADR. | R6, R11 |

## API / interface  (serves: R1, R2)

The only executable surface is the installer's `specs/product.md` branch.

| Interface | Shape | R-id |
|---|---|---|
| `product_stub_current()` | emits the **new** stub: frontmatter `status: draft`, a comment line `# stage: discovery \| pilot \| production — absent means production (ADR-0009)`, then the bare `stage: production`, plus the unchanged `/sdd-plan` front-door body | R1 |
| `product_stub_prior_0_81_1()` | **new** function, emits the stub shipped v0.81.1 → the release before this one, byte-identical to today's `product_stub_current()` output (move the heredoc, do not retype it; `git show main:harness-install.sh` is the oracle) | R2 |
| `product_stub_prior()` | unchanged (the v0.1.0 → v0.81.0 blob) | R2 |
| seed branch verdicts | absent ⇒ `seeded specs/product.md (stub)`; byte-identical current ⇒ `specs/product.md pristine (…)`; byte-identical to **either** prior ⇒ `cp` the new stub, `specs/product.md refreshed (was a pristine earlier shipped stub; project edits are preserved)`; anything else ⇒ `specs/product.md preserved (project-authored)`; symlink / non-regular ⇒ preserved, never written through. Exactly one verdict line per run, on stdout. | R1, R2 |

**Decision — a second prior blob, not a heuristic.** The installer comment already forbids a
general "was it seeded by us?" test; this adds one more known blob to the `cmp -s` chain and
keeps the rule "migrate only a byte-identical known stub". **Decision — the stub keeps
`status: draft`** and adds `stage:` below it, so `product.md` stays a one-block YAML header
and nothing that reads `status:` moves.

**ADR template guidance (R4, R5)** — after the header list (`Status`, `Date`, `Trigger`), add:

```markdown
> ## Stage-aware NFRs (ADR-0009)
> A **deferred** ADR parks a bolt-on NFR the product's stage excludes
> (`stage:` in `specs/product.md` frontmatter — `discovery | pilot | production`,
> `production` when absent). It is an ordinary ADR with `- **Status:** deferred` and a
> **mandatory** `- **Trigger:** <observable condition>` line — the condition that reopens it
> (first regulated customer, N users, a named compliance deadline). The feature plan cites it from its
> `## Deferred` subsection.
>
> **Sticky NFRs are never deferred at any stage:** tenant isolation, the auth boundary,
> secrets out of the repo, validation at the system edge. This list is ADR-0009's;
> extending it is a change to that ADR (a spec change), not a role's judgment call.
> **Bolt-on examples** (deferrable by a deferred ADR): encryption at rest, WAF, rate
> limits, backups, caching.
```

**Prose-contract tests** — whole-file `grep -qF` (fixed string) or `grep -qE` on the INSTALLED
copy under `$I`. **Table cells in this plan and in `.tests.md` escape `|` as `\|` for
markdown only** — the literal grep strings are `proposed | accepted | deferred`,
`| Bolt-on | Deferred by | Trigger |` and
`| Sticky (never deferred) | Bolt-on (deferred by an ADR with a trigger) |`, with bare pipes; where two tokens must co-occur, fold newlines (`tr '\n' ' ' | grep -qiE
'A[^.]{0,80}B'`). Verify each anchor FAILS on the pre-change blob (`git stash` the prose file,
re-install into a second temp dir, run) before trusting it — lesson 2026-09-06.

**Assertions reachable by another path** (lesson, recurred 3×): the installed templates/roles
are `cp -R` copies, so an installed-file grep proves the *source* content, which is what we
want — but the R2 fixture must be the test's own heredoc, not the installer's
`product_stub_prior_0_81_1` function, or deleting that function would leave the test green.

**Exit codes under dash.** The suite asserts `rc -eq 0`, captures with
`set +e; …; rc=$?; set -e`; a `var="$(… | grep …)"` under `set -eu` needs `|| true`.

**Mutation protocol** — see `.tests.md`; every row names the mutant that kills it. Run them one
at a time with `cp <file> <file>.mutbak` / `mv` back, print each applied diff, under
