# Per-requirement red/green task pairs — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it serves.
> Start high-level; don't over-specify internals that might be wrong. The Builder reads
> `progress/lessons.md` first; the lessons this plan leans on are named inline.

## Stack & dependencies

- Language/framework: POSIX `sh` (suites, run under dash by `tools/run-tests.sh`), Python 3
  stdlib only (the lint — same profile as `tools/task-diagnostics.py`), Markdown.
- New dependencies: **none**. `python3` is already a hard harness dependency (`init.sh`,
  `tools/tasks-lock.py`).
- Repo root for every command: the linked worktree on `feat/E36-F01-task-pairs`. Never touch
  the primary checkout or a sibling `harness-sdd-E36-*` worktree.

## Data model  (serves: R5, R6, R7, R8)

No stored state. The lint is a pure function of two files. Its **grammar** is the only data
model and it must be identical to the one `docs/SPEC-FORMAT.md` (R3) and the template (R1)
describe — one definition, four surfaces, so pin it here once:

| Entity | Rule | Notes |
|---|---|---|
| fenced code | CommonMark fence rule, as `tests/lib/fence.awk` encodes it | backtick **or** tilde run ≥ 3, indented 0–3 spaces; a closer is the same char, at least as long, with no info string; a backtick opener carries no backtick in its info string. Lines inside a fence are **skipped** in both files. Port the rule into Python inside the tool (it cannot source awk); the suite pins the port with the four delimiter forms R9d of `tests/test_change_size.sh` uses. State the duplication in the tool's docstring — it is a deliberate second copy, pinned by test, not a hidden one. |
| spec `R-id` | line matches `^[ \t]*-[ \t]+\*\*(R[0-9]+)(?:\*\*\|[ \t]+(?:—\|–\|-))` — the house form `- **R1** —` and the bold-title form `- **R1 — Title.**` (E36-F06, four done specs); `- **R8's clause**` is not an R-id | collected in order of first appearance, duplicates collapse. Zero ids ⇒ exit 2 (R8). |
| task line | `^[ \t]*-[ \t]+\[[ xX]\][ \t]+\*\*([Tt][0-9]+)([A-Za-z]+)?\*\*(?:[ \t]*\(([^)]*)\))?[ \t]*(?:—|–|-)?[ \t]*(.*)$` | `T-id` = group 1 + group 2 (e.g. `T3a`). kind (suffix lower-cased first): `a` ⇒ **test**, `b` ⇒ **code**, none, **any other letter or more than one letter** (`T1c`, `T4r`, `T1ab`) ⇒ **other** — never silently dropped, so a `T1c (R1)` first task reports `first-task-not-test R1 T1c`. Continuation lines (indented, no `- [ ]`) are not tasks. |
| cited `R-id`s | every `R[0-9]+` token inside group 3 | a range `R1–R4` yields `R1` and `R4` only — by design; document it (R3). |
| write-tests task | cited set empty **and** text matches `(?i)\bwrite\b.*\btests\b` | wherever it sits (R7). A cited task that says "write the failing tests" is exempt. |
| violation | one of `first-task-not-test <R-id> <T-id>`, `no-task <R-id>`, `write-tests-task <T-id>` | fixed reason words; each printed on its own stdout line prefixed `tasks-pair-check: `. |

## API / interface  (serves: R5, R6, R7, R8, R9)

| Interface | Shape | R-id |
|---|---|---|
| CLI | `tools/tasks-pair-check.py <feature.tasks.md> --spec <feature.spec.md>` (`--spec` required; `-h/--help` prints usage, exit 0). Parse argv by hand, or subclass `argparse.ArgumentParser` and override `error()` — stock argparse prints `usage: … error:` and exits 2 **without** the `tasks-pair-check: error:` line R8 requires. | R5–R8 |
| exit 0 | every spec `R-id`'s first citing task has kind test, and no write-tests task; stdout last line `tasks-pair-check: ok <k> R-ids, <m> tasks` | R5 |
| exit 1 | ≥1 violation; one `tasks-pair-check: <reason> …` line per violation, then `tasks-pair-check: FAIL <n> violation(s)`; violations are ordered: spec `R-id` order for the first two reasons, then task order for `write-tests-task` | R6, R7 |
| exit 2 | missing `--spec`, unreadable/missing file, zero spec `R-id`s; stderr `tasks-pair-check: error: <what>` + usage line | R8 |
| Reviewer | `python3 "$HARNESS_DIR/tools/tasks-pair-check.py" "<dir>/<feature>.tasks.md" --spec "<dir>/<feature>.spec.md"` — non-zero ⇒ reject (exit 2 is a broken spec, also a reject); **grandfather**: on a non-zero lint exit run `tasks-pair-check.py --grandfathered <tasks.md>` — exit 0 (the `.tasks.md`'s first-add author time is older than the tool's first first-parent commit on the default branch, i.e. its merge; or the tool is not on the default branch yet) ⇒ flag instead of reject, exit 1 ⇒ reject; `sdd: false` exempt | R9 |

**Decision — a test task is identified by the `a` suffix, not by a word in its text.** Suffix
is structure; "RED" in the text is vocabulary the template teaches but the lint does not
require, so a localized or reworded task cannot false-fail. Decision — the lint does **not**
check `a`→`b` adjacency or pair order (spec *Out of scope*); YAGNI until a real tasks file
needs it.

## Approach notes

**Sequencing.** Walking skeleton first: the lint's `ok` path (R5) is the thinnest end-to-end
observable (a file, an exit code), so it is pair 1. Then the lint's refusals (R8, R6, R7),
then the template (R1 — verified by running the lint on it), then the prose (R2, R3, R4), the
Reviewer check (R9), installer wiring (R10), the ledger (R11), version (R12). The feature's
own `.tasks.md` follows this order in pair form and must itself exit 0 under the lint — the
Builder runs it after T6b as a self-check.

**Template shape (R1)** — write exactly this skeleton (placeholders may vary, structure may
not). Test names come from `specs/_templates/feature.tests.md`'s rows so the three templates
agree:

```markdown
# <Feature title> — Tasks

> Per-requirement red/green pairs (ADR-0008). For each R-id in the .spec.md: `T<n>a` writes
> the failing test named in `.tests.md` and observes RED; `T<n>b` writes the minimal code and
> observes GREEN; the Builder commits after each GREEN. Order pairs so the walking-skeleton
> R-id (the thinnest end-to-end observable behavior) comes first. Refactor tasks are explicit
> and cite the R-ids whose tests guard them. There is no trailing "write tests" task:
> `python3 tools/tasks-pair-check.py <this file> --spec <feature>.spec.md` must exit 0.

- [ ] **T1a** (R1) — write failing `tests/test_handoff.py::test_take_over_assigns_agent`; run it; observe RED
- [ ] **T1b** (R1) — minimal code: add `handoffRequested` to `models/conversation.py` …; observe GREEN; commit
- [ ] **T2a** (R2) — write failing `…::test_bot_active_badge`; observe RED
- [ ] **T2b** (R2) — minimal code …; observe GREEN; commit
- [ ] **T3a** (R3) — write failing `…::test_5xx_shows_retry`; observe RED
- [ ] **T3b** (R3) — minimal code …; observe GREEN; commit
- [ ] **T4a** (R4) — write failing e2e `handoff.spec.ts` (Playwright); observe RED
- [ ] **T4b** (R4) — minimal code …; observe GREEN; commit
- [ ] **T5a** (R5) — write failing `tests/test_analytics.py::test_handoff_event`; observe RED
- [ ] **T5b** (R5) — minimal code …; observe GREEN; commit
- [ ] **T6** (R1, R2) — refactor: <extract …>; R1/R2 tests stay GREEN; commit
- [ ] **T7** — Run `./init.sh` + the test command; all green before hand-off
```

**SPEC-FORMAT section (R3)** — the section must state, in prose a grep can anchor: the
`T<n>a` / `T<n>b` pair per `R-id` with RED then GREEN; refactor tasks explicit and citing
`R-id`s; a task with no `R-id` that reads "write … tests" is rejected wherever it sits; lines
inside fenced code are ignored by the lint; ranges are not expanded; the behavioral rule —
"own pair by default", "grouped by co-citing the behavioral `R-id` on the `a` task of the pair
it exercises", "never a code-only first task"; and the lint invocation. Put the pair example
in a fenced block (so a fence-blind slicer would truncate the section).

**Reviewer item 7 (R9)** — sits inside `## What you check`; a position-pinned test extracts
that section (fence-aware) and anchors `tasks-pair-check.py` … `reject`, `predates` …
`flag`, and `sdd: false` … `exempt` inside it. Spell `$HARNESS_DIR` the way item 1 / the
change-size section do. State the grandfather rule as the `--grandfathered` command (first-add
author epoch of the `.tasks.md` vs. the tool's merge into the default branch), so "older" is
a number comparison, not a judgment; in
this repo the W1 siblings F02/F03/F05/F06 are the first files it protects.

**Ledger row (R11)** — one table row after `C8`, `Capability compensation` layer:
*Why it exists now*: "Models decompose code-first and tests-last by default; the lint turns
ADR-0008's per-requirement red/green order into a deterministic exit code the Reviewer
rejects on, instead of a prose request." *Evidence to reconsider or remove*: "Ablation:
controlled runs on a materially newer model where the Architect, given the pair template but
**without** the lint, emits zero `first-task-not-test` / `write-tests-task` violations across
a predeclared feature set; retest with the template also removed. Retain while it catches
any." Pointers: `tools/tasks-pair-check.py` and `agents/reviewer.md`. The row's label must be
exactly `C9 — Task-pair shape lint` so the updated inventory check finds it.

**Prose-contract tests** — follow `agents/builder.md`'s section-then-two-token rule, but
slice with `FENCE_AWK` + `fence_delim($0)` from `tests/lib/fence.awk`, never the bare
`/^#+ /` idiom (fence-blind; `test_change_size.sh` R9d reds a suite that slices without
it). Verify each anchor FAILS on the pre-change blob (`git stash` the prose file, run, pop)
before trusting it — lesson 2026-09-06.

**Assertions reachable by another path** (lesson, recurred 3×): the installed copy of the
tool is executable even without the `chmod +x` line because `cp -R` preserves the source
mode — so R10's pin on installer wiring is the **source grep** for the chmod line, not the
`-x` on the installed copy; keep both and know which one is the pin. Likewise R1 is proved by
**running the lint** on the template, not by grepping for `RED`.

**Fence-port pitfall (found while prototyping this grammar).** A character-run counter
written as `while s[i:i+1] == ch and ch in "`~"` never terminates on an **empty line**: the
empty slice equals the empty `ch`, and `"" in "`~"` is `True` in Python. Guard on `ch` being
non-empty before the membership test, and give the suite's `fx_spec` fixture at least one
blank line and one whitespace-only line so the hang is a test failure, not a Reviewer
timeout. Expected result of the pinned grammar on existing files (prototype, 2026-10-25):
this feature's own `E36-F01.tasks.md` → `ok 12 R-ids, 27 tasks`; the old template → 6
violations ending `write-tests-task T5`; `E35-F05.tasks.md` → 12 `first-task-not-test`.

**Exit codes under dash.** The suite asserts `rc -eq 0/1/2`, never a shell-dependent code;
capture with `set +e; …; rc=$?; set -e`.

**Mutation protocol** — see `.tests.md`; every row names the mutant that kills it. Run them
one at a time with `cp <file> <file>.mutbak` / `mv` back, print each applied diff, under
`scratchpad/E36-F01-builder/`.
