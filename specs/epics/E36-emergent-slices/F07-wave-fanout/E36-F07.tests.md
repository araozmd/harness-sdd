## Fixtures

- **Installed target.** `tests/test_sdd_next_wave.sh` installs once:
  `HOME=$TMP/home CODEX_HOME=$TMP/codex HARNESS_AGENTS="claude,codex,opencode" sh
  "$ROOT/harness-install.sh" "$T"`; every prose case reads `$T/.harness/agents/orchestrator.md`,
  `$T/.claude/commands/sdd-next.md`, `$T/.opencode/command/sdd-next.md`,
  `$T/.agents/skills/sdd-next/SKILL.md`, `$T/.harness/docs/WORKFLOW.md`,
  `$T/.harness/harness.config.yaml`. The sandboxed `CODEX_HOME` is mandatory (memory: codex
  glue installs global prompts).
- **Selector boards** (R3, R4) are written under `$TMP` in non-canonical order and run with the
  installed `node "$T/.harness/tools/next-task.mjs" --waves --json --tasks … --config …`
  (same `write_config`/`write_board`/`run_tool` helpers as `tests/test_waves.sh`). The live
  board is never read.
- **Git fixtures** (R5, R7) follow `tests/test_fix_worktree.sh::make_source_fixture` (bare
  origin + primary clone, `.gitignore` with `.claude/worktrees/`, a copy of `tools/`), under
  a hostile global git config (`GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1
  GIT_TEMPLATE_DIR=''`), with any git path listing read NUL-framed. The R7 fixture adds a
  minimal valid `state/tasks.json` (two features, schema-valid) and `store/tasks.schema.json`
  so `tasks-lock.py` validates.
- **Runner lock** (R8): private `TMPDIR=$TMP/lock`, lock file holds the suite's own `$$`,
  `HARNESS_RUN_TESTS_NESTED` unset for that one invocation, absolute suite path.
