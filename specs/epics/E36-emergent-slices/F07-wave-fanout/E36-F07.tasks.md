# `/sdd-next --wave` fans out one wave into isolated worktrees — Tasks

> Per-requirement red/green pairs (ADR-0008). For each R-id in `E36-F07.spec.md`: `T<n>a`
> writes the failing test named in `E36-F07.tests.md` and observes RED; `T<n>b` writes the
> minimal code or prose that turns it GREEN; the Builder commits after each GREEN. Pairs are
> ordered walking-skeleton first (R1: the generated body carries the token). There is no
> trailing "write tests" task:
> `python3 "$HARNESS_DIR/tools/tasks-pair-check.py" E36-F07.tasks.md --spec E36-F07.spec.md`
> must exit 0.
>
> **Machine rule for this build.** One `tools/run-tests.sh` per machine. Iterate with
> `sh tests/test_sdd_next_wave.sh` / `sh tests/test_fix_worktree.sh` (single suites take no
> lock); run `sh tools/run-tests.sh` once, serially, before hand-off. If it exits 5, another
> run holds the slot: stop and report; do not relaunch. A killed run is a stop, not a retry.
>
> **Prose contracts are asserted on INSTALLED files** (whole-file `grep -qF`), so the new
> suite installs once into a `mktemp` target (sandboxed `HOME`/`CODEX_HOME`,
> `HARNESS_AGENTS="claude,codex,opencode"`) and every "edit the heredoc" task ends with
> `sh harness-install.sh --self` + staging the regenerated glue.
