# `/sdd-next --wave` fans out one wave into isolated worktrees — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it serves.
> Start high-level; the Builder picks internals not pinned here. The coordinator and the
> worker are **portable role/command contracts executed by the host agent** (the same shape as
> `/sdd-fix-parallel`); the only new executable behaviour is the id-grammar widening in
> `tools/fix-worktree.sh` and the installer's config seeding.

## Stack & dependencies

- Language: role prose (`agents/orchestrator.md`), the `sdd-next` heredoc in
  `harness-install.sh` (POSIX `sh`, runs under dash), `tools/fix-worktree.sh` (POSIX `sh`,
  `set -u`, caller's locale with the one `LC_ALL=C` pin in `validate_key`), POSIX `sh` tests
  (`#!/bin/sh`, `set -eu`, run under dash by `tools/run-tests.sh`), `python3` inside tests for
  JSON extraction (the house `json_field` helper from `tests/test_waves.sh`).
- New dependencies: **none**. `node` (selector), `python3` (tasks-lock), `git` are already
  required.

## Data model  (serves: R2, R4, R6, R9, R10)

Nothing is stored on the board (ADR-0010). Three data shapes exist only in config, in the
manifest, and in the worker's return value.

| Entity | Field | Type | Notes | R-id |
|---|---|---|---|---|
| `harness.config.yaml` → `workflow` | `max_wave` | positive integer | default `3`; seeded by `migrate_config` into preserved configs lacking it; read by the coordinator only; `--max N` overrides it for one run | R2, R10 |
| manifest `progress/wave-<stamp>/summary.md` | header | text | `wave: <N>`, `cap: <n> (<--max\|workflow.max_wave\|default>)`, `scope: <epic\|whole board>`, `selector: <the exact next-task command run>` | R6 |
| manifest | one row per `waves[0].features[]` record | text | `<id> \| <classification> \| <branch or ->` \| `<worktree or ->`; classifications: `selected`, `cap-deferred`, `skipped: not-runnable [<code>…]`, `skipped: not-autonomous`, `skipped: status:<status>`, `skipped: route:<route>`, `provisioning-failed: <stderr>` | R4, R5, R6 |
| worker return | `verdict` | closed vocabulary | `pr-opened` \| `runner-busy` \| `interrupted` \| `stopped: <reason>`; plus the feature's last status, branch, worktree, PR URL (or `-`), and the transition records it made. `runner-busy` is consumed by W6 and never reaches the final table; a second refusal is `stopped: runner-busy twice`. `interrupted` is observed at the worker boundary (sub-agent/tool call cancelled or killed, or no verdict returned) — a runner exit of 1 is a red suite, never a signal | R7, R8, R9 |

Config seed text (byte-identical in `harness.config.yaml` and in the `migrate_config` insert
in `harness-install.sh`), placed directly after the `identity: ""` line inside `workflow:`:

```yaml
  # Worker cap for `/sdd-next --wave` (E36-F07): how many wave features run at once in their
  # own worktrees. `--max N` overrides it for one run. Keep it small: workers share one
  # machine and one `tools/run-tests.sh` slot (one run per machine, exit 5 otherwise).
  max_wave: 3
```

The installer line is the single-line form the `_mc_insert_after` idiom takes (one `printf`
per line, same as the `identity:` seed at `harness-install.sh` ~L220-234); the presence check
is scoped to a `max_wave:` **inside** the top-level `workflow:` section (write a
`_cfg_has_workflow_max_wave` beside `_cfg_has_workflow_identity`, same awk shape), so a
same-named key under another section never suppresses seeding (R10).

## CLI / interface  (serves: R1, R2, R3, R4, R9)

`/sdd-next` argument mapping — the existing closed scope gains one token set:

| `$ARGUMENTS` | Action | R-id |
|---|---|---|
| (empty) / `--mine` / `E##-F##` | unchanged | R1 |
| `--wave` | wave coordinator mode; `cap` from `workflow.max_wave` (else 3); selector `--waves --json` | R1, R2 |
| `--wave --max N` | `cap` = N (`^[1-9][0-9]*$`) | R1, R2 |
| `--wave --epic E##` | selector `--waves --json --epic E##`; first **listed** wave is fanned out | R1, R3 |
| `--wave --max N --epic E##` (either order after `--wave`) | both | R1 |
| `--wave --mine`, `--wave E##-F##`, `--max N` without `--wave`, `--epic` without `--wave`, `--max 0`, `--max x`, `--epic E36-F01`, repeated tokens, anything else | invalid: select nothing, change nothing, print the usage line `usage: /sdd-next [--mine \| E##-F## \| --wave [--max N] [--epic E##]]` | R1 |

Coordinator phases — named **W1–W7** so the prose can cite them; each maps to the fix lane's
P1–P7 and reuses its discipline **by reference** (`agents/fixer.md` → "Parallel dispatch mode"
P2 provisioning, P3 manifest completeness, P5 fan-out-before-wait, P6 exclusive wave, P7
aggregate exit) with the differences stated in the Orchestrator section:

| Phase | Does | Stops when | R-id |
|---|---|---|---|
| W1 preflight | `init.sh`; native concurrency; `execution.builder.backend: in-session`; `umbrella.manifest` empty; resolve `cap` | any check fails → name it, point to `/sdd-next <id>`, exit non-zero, no mutation | R2 |
| W2 wave read | run the selector; branch on `outcome`; take `waves[0]`; classify records (R4) | `error`/`blocked` → print `reason.detail` + `blocked[]`, exit non-zero; empty `waves` → `no runnable wave`, exit 0; no eligible → `no eligible feature in wave <N>`, exit 0 | R3, R4 |
| W3 provision | sequential `tools/fix-worktree.sh create <id> <slug>` per selected (installed: `.harness/tools/fix-worktree.sh`); slug rule (R5) | a failed create → `provisioning-failed`, siblings continue | R5 |
| W4 manifest | write `progress/wave-<stamp>/summary.md` with every record | — | R6 |
| W5 fan-out | spawn every provisioned worker before awaiting any; exact inputs (id, primary's absolute brief path or `-`, branch, worktree, `HARNESS_DIR=<worktree>`, manifest path); each worker reads its status from its own worktree board on entry and resumes there | — | R7 |
| W6 exclusive pass | after W5 settles, re-spawn each `runner-busy` worker one at a time, selection order, same inputs (it resumes from its worktree board); second `runner-busy` → `stopped: runner-busy twice` | — | R8 |
| W7 report | summary table + merge plan; exit 0 iff all `pr-opened` | — | R9 |

Summary table and merge plan (R9) — reference shape; tests pin only the literals the spec
names (`pr-opened`, `runner-busy`, `interrupted`, `next MINOR`, `merge order`):

```
Wave 2 (epic E36) — cap 3 (workflow.max_wave)
feature  | branch                        | PR    | verdict
E36-F04  | feat/E36-F04-plan-cite-check  | #310  | pr-opened
E36-F07  | feat/E36-F07-wave-fanout      | -     | stopped: runner-busy twice
merge order: E36-F04, E36-F07
Before /sdd-pr-loop on each PR after the first: merge the updated main into the branch
(one merge commit); VERSION = next MINOR over the then-current main; place this entry
above main's newest CHANGELOG entry under that version; keep both sides of
progress/history.md and state/tasks.json. done and teardown follow the normal path.
```

## Approach notes

**Order of work (walking skeleton first).** R1 is the product boundary: the generated body
must carry the token before anything else is observable. Then R10 (config) and R2 (preflight)
because every later phase reads `cap`; then R3/R4 (consume the envelope); R5 (helper
widening — the only executable production change); R6/R7/R8/R9 (prose + executed seams);
R11 (docs + regen); R12 last.

**Consume, do not re-derive (R3, R4).** Branch on `outcome` before reading any wave field
(F05 R3: an `error` envelope has none of the four wave fields). `waves[0]` is the first listed
wave; print its `wave` number verbatim. The eligibility predicate reads four record fields
and nothing else — not `blocked[]` (except to print codes in `skipped: not-runnable`), not
the board. The `spec_path` for the slug is the only board read the coordinator makes
(`state/tasks.json` → the feature's `spec_path`); it is read, never written.

**Slug (R5).** `F07-wave-fanout/` → `wave-fanout`; `F12-Plan_Cite Check` → `plan-cite-check`;
a `spec_path` of `specs/epics/E1-x/F2-/` → `wave`. Validation is then the helper's own
`validate_key` — the coordinator never builds a path from the slug itself.

**Helper widening (R5) — untrusted-environment handling.** `tools/fix-worktree.sh` already
checks every git call's status, parses only ASCII-by-construction output, and uses
`--porcelain` records split on literal prefixes; the change is two `case` arms and the usage
string. Keep the arms inside the `LC_ALL=C` pin and restore the caller's locale on every path
exactly as today. Do not introduce a pipeline whose status is lost: the new test case checks
`create`'s exit status directly (`_out="$(…)" || fail`) and reads the worktree path from
`$_out`, never from `ls | head`. The suite's own git fixture runs under the hostile global
config idiom already in `tests/test_fix_worktree.sh` where it exists; where the new suite
creates its own repo, set `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1
GIT_TEMPLATE_DIR=''` on `init`, `add`, `commit` (lesson 2026-10-19). Where a test lists
paths from git, use NUL framing (`git status --porcelain -z`, `git ls-files -z`) and read
with `tr '\0' '\n'` only for display; never word-split a path list.

**`HARNESS_DIR` (R7).** `tools/tasks-lock.py`'s precedence rule 1: an explicit `HARNESS_DIR`
always wins over linked-worktree auto-discovery, which would otherwise remap a worker's write
onto the **primary** checkout (memory: "tasks-lock remaps linked worktrees"). The spec's
executed check provisions a real linked worktree with the widened helper, runs
`HARNESS_DIR="$wt" python3 "$wt/tools/tasks-lock.py" set-status <id> spec-ready` from inside
`$wt`, and asserts `cksum` of the primary's `state/tasks.json` is unchanged while the
worktree's changed (and the status field reads `spec-ready`). The control for this test: the
same call under `env -u HARNESS_DIR` from inside the linked worktree writes the primary's
board (that is the remap) — assert it, so the test proves the override is the thing that
matters. `env -u` is required: the invoking session or the runner may export `HARNESS_DIR`,
and an inherited value would make the control pass or fail by accident.

**Cap is the only brake (R2).** `--max 50` is accepted; the section says so in one sentence
and names the operator as the owner of values above the default. Touched suites run
unlocked in every worker; only the full `test_command` is serialized by the runner's lock.
No hard ceiling is added (doc-critic advisory, decided: explicit statement over a second
limit).

**Runner lock (R8).** The executed probe: in a private `TMPDIR`, write
`$TMPDIR/harness-run-tests.lock` containing the test's own `$$` (a live pid), unset
`HARNESS_RUN_TESTS_NESTED` (the runner skips the claim when nested — `run-tests.sh` ~L112),
run `sh tools/run-tests.sh tests/test_sdd_next_wave.sh` and assert exit 5 and that no suite
output appears. Restore the marker afterwards. Prose: the Orchestrator section must carry the
exact phrases the tests grep (`exit 5`, `runner-busy`, `does not re-invoke`, `one at a time`,
`interrupted`, `never relaunched`); write them once, verbatim, in the `### Test-runner lock`
subsection.

**Merge plan (R9).** The plan is printed, recorded in the manifest, and documented in
`docs/WORKFLOW.md`. The coordinator opens no PR and merges nothing; `done` keeps the
post-merge path (`agents/orchestrator.md` "Writing `done`" plus the house `chore/<ID>-done`
PR). Teardown is the operator's `tools/fix-worktree.sh teardown <id> <slug>` from a clean
primary after the merge.

**Generated glue (R1, R11).** Edit only the heredoc; run `sh harness-install.sh --self`; stage
every regenerated file; `tests/test_self_drift.sh` fails otherwise. The installed `sdd-next`
bodies must stay byte-identical across targets (existing `cmp -s` chain in
`tests/test_install.sh`).

**Mutation campaign before hand-off (mandatory; see T15).** Earlier E36 tools needed extra
review rounds without one. For every clause the suite pins — each `case` arm in
`validate_key`, the `max_wave` seed line and its presence check, each pinned phrase in the
Orchestrator wave section, each token in the `sdd-next` mapping — mutate the **whole clause**
(delete the arm, drop the line, remove the phrase, swap the token) one at a time, run the
touched suites, and record that each mutant reds exactly the case that claims it. Restore
with `cp -p` and compare `sha256` + mode after every mutant (lesson 2026-09-17/2026-10-26). A
surviving mutant means rewrite the test, not "retest".

**Lessons carried (progress/lessons.md).** Never assert an exact exit code for a lookup miss
unless documented; whole-file `grep -qF` for prose (the awk section extractor is
fence-blind); never freeze VERSION; never `git diff` a DO-NOT-TOUCH file against `main` — use
`cksum` before/after inside the suite; sandbox `CODEX_HOME` and `HOME` in every
installer-invoking test; pass absolute suite paths to `run-tests.sh`; one `run-tests.sh` at a
time on this machine — if it exits 5, stop and report, do not relaunch.
