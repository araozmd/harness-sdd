# Driller observable-slice rule and walking skeleton — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it serves.
> This feature is prose + one template shape + one emitter sentence. There is no tool, no
> schema field, no board write. The Builder's freedom is in wording; the anchors the tests
> pin are listed below and are the contract.

## Stack & dependencies

- Language: Markdown role files and templates; one POSIX `sh` heredoc edit in
  `harness-install.sh`; a new POSIX `sh` test suite (`#!/bin/sh`, `set -eu`, run under dash
  by `tools/run-tests.sh`); `grep -qF` / `grep -qE` / `tr '\n' ' '` only.
- New dependencies: **none**.

## Data model  (serves: R2, R4, R6, R7)

one template section — these literals are the contract, carried verbatim wherever cited:

## Approach notes

**Order (walking skeleton first).** The thinnest end-to-end path is the template: a user
who runs `/sdd-new` after this lands gets a brief with a place to write the observable
behavior (R4). Then the roles that fill it (R5 Inception, R3 Driller), the rule that makes the
fill meaningful (R1, R2), the checker (R6, R7), the installed surfaces (R8), docs (R9), release
record (R10). `E36-F02.tasks.md` follows that order.

**Section anchors the tests pin (so the Builder knows the contract).** Whole-file `grep -qF`:
`## Observable slice — the shape rule beside the size budget (ADR-0008)`,
`Observable-slice exemption:`, `## Observable behavior`, `walking skeleton`,
`product boundary`, `HTTP`, `CLI`, `UI`, `exit code`, `max_requirements`,
`## Epic-decomposition checks — observable slices (ADR-0008)`, `observable-behavior-missing`,
`walking-skeleton-missing`, `internal-only-outcome`, `exemption-recorded`,
`## Observable slices and the walking skeleton (ADR-0008)`. Folded co-occurrence
(`tr '\n' ' ' | grep -qiE`): `merged[^.]{0,40}consum` (R1), `advisory[^.]{0,40}never blocks`
and `never[^.]{0,30}blocked[^.]{0,30}shape` (R2), `only consumer is another epic` (R2),
`lowest[^.]{0,20}F##` or `lowest-numbered` (R1, R6), `depends_on` inside the section (R1,
R6), `fresh[^.]{0,80}lowest` and `amend[^.]{0,80}not raised` (R6). **Every literal and
co-occurrence anchor for R1, R2, R3, R6, R7 is evaluated over the new section's line range**
(`sed -n "${a},${b}p"` between the two heading line numbers), never the whole file — the
whole file already contains `max_requirements`, `depends_on`, `file`, `UI`, so a whole-file
grep could not be RED before the change. Placement: `grep -n '^## '` and compare line
numbers — new driller section strictly between the size-budget heading and the seed heading;
new doc-critic section strictly between `## Review scope and calibration` and
`## Advisory-only behavior`; template `## Observable behavior` strictly between
`## Success outcome` and `## Scope / boundaries`; WORKFLOW section strictly between
`## Change-size discipline` and `## Architecture-aligned specs`. Every anchor is confirmed RED
on the pre-change blob (`git stash` the prose file, or `git show main:<file> > "$T/pre.md"`)
before the Builder trusts it — a co-occurrence anchor proves co-occurrence, not polarity
(lessons 2026-09-06), so the placement pins carry the structural weight.

**Negative controls the suite must carry.** The template fixture: `cp` the template to `$T`,
assert the order; `sed '/^## Observable behavior/,/^## Scope/{/^## Scope/!d;}'` the section out
and assert the order check now fails (proves the check is live). The installed `/sdd-drill`
step-7 bound: assert the same literals are **absent** from step `12.`'s range (so an
instruction that drifted into F05's step would red here, not silently pass).

**Doc-critic wording.** Keep "advisory" and "never block" in the new section itself, not only in
`## Advisory-only behavior`, so `tests/test_doc_critic.sh` R5/R18 keep their existing anchors
and the new section is self-contained for a reader who lands on it. Do **not** introduce
"reject" or "fail the drill" as the critic's action anywhere in the section (those two are the
negative pins; "never block" is the positive one).

**Anchor hygiene.** The house folded idiom `[^.]{0,N}` stops at any period — including the one
in `epic.md` or `e.g.` — so an anchored pair of tokens must sit in one sentence with no such
token between them; when the natural sentence needs `epic.md` between the two tokens, anchor on
a different pair or use `[^;]{0,N}`. The RED/GREEN observation in each pair is what proves the
anchor is live.

**Generated-glue merge with E36-F05.** Both features edit the `sdd-drill.md` heredoc (step 7
here, step 12 there) and both regenerate the same `.claude/`, `.opencode/`, `.agents/`,
`.codex/`, `.pi/` files and `.claude/.glue-manifest`. On a rebase conflict in a **generated**
file: resolve the installer heredoc by hand (the two steps do not overlap), then re-run
`sh harness-install.sh --self` and `git add` the output — never hand-merge a generated file.

**Driller wording.** Mirror the E21-F01 section's register ("Record the decision either way",
"This is advisory and it never blocks") so a reader sees the two rules as siblings. The
cross-epic sentence is **one** sentence; the spec's *Business rules* give the text.

**Emitter edit.** The heredoc is `<<'EOF'` (no expansion) — write the literal sentence; keep
step numbering intact (`7.` stays `7.`). After editing, run `sh harness-install.sh --self`,
confirm `git status --short` lists only generated files plus the installer, and commit them
together. `tests/test_self_drift.sh` reds any hand edit.

**Install test.** Fresh-install fixtures in `tests/test_install.sh` already exist (`$T`);
sandbox `CODEX_HOME` as every installer-invoking test does (memory: codex global prompts).
Assert on the **installed** copies, never on `$SRC` alone — a source grep proves nothing
about the install (lessons: assertion reachable by another path).

**Release record.** `VERSION` is the next MINOR over `main`'s value when the Builder is ready
to open the PR; the test derives the newest `CHANGELOG.md` heading with
`sed -n 's/^## \[\([0-9][0-9.]*\)\].*/\1/p' | head -1` and compares it to `cat VERSION`, and
finds **some** `## [` section whose body names `E36-F02` and `Observable-slice exemption`.

**Lessons carried (progress/lessons.md).** Never assert an exact exit code for a lookup miss;
whole-file `grep -qF` for prose contracts (the section extractor is fence-blind); confirm
every anchor RED before trusting it; never freeze VERSION; never `git diff` a DO-NOT-TOUCH
file against `main`; a fixture copied from the repo inherits the artifact under test, so the
template negative control deletes the section first; sandbox `CODEX_HOME` in every
installer-invoking test.
