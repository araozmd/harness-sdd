# Driller observable-slice rule and walking skeleton — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and every row names the mutant that kills it. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives.
>
> **Suite.** A new POSIX `sh` suite, `tests/test_observable_slices.sh` (OS), `set -eu`,
> `fail`/`pass`, `+x` bit, `trap 'exit 1' HUP INT TERM` beside its `EXIT` trap, run by
> `tools/run-tests.sh` under the strictest shell it can probe (dash on CI). Fixtures live under
> `T="$(mktemp -d)"`. The suite never reads `VERSION` as a literal, never diffs a
> DO-NOT-TOUCH file against `main`, never writes `state/` or a live spec or brief.
>
> **Idioms.** Literals: whole-file `grep -qF` (the awk section extractor is fence-blind — not
> used here). Co-occurrence: `tr '\n' ' ' < file | grep -qiE 'A[^.]{0,N}B'`. **Placement**:
> `ln() { grep -n "^$2" "$1" | head -1 | cut -d: -f1; }` on `## ` headings, then integer
> comparison `[ "$a" -lt "$b" ] && [ "$b" -lt "$c" ]`; a missing heading yields an empty
> string and the comparison fails loudly under `set -eu`. Every anchor was confirmed RED on
> the pre-change blob (`git show main:<file>`) before being trusted.
>
> **Install cases** live in `tests/test_install.sh` on its fresh-install fixture `$T`
> (`CODEX_HOME` sandboxed), appended as one block after the existing `E09: /sdd-plan +
> /sdd-drill glue …` pass line.

diff (non-empty, or the run is void), under `scratchpad/E36-F02-builder/` (or `-reviewer/`).
Anchor each mutation to the line **kind** you mean (a heading, a bullet, a table row), not a
`replace(old, new, 1)` that may land on a comment or an illustration (lessons 2026-09-06).

## Behavioral / end-to-end checks

- Reviewer dry-run, Driller side (no board write): read `agents/driller.md`'s new section as
  the Driller would, decompose a two-feature toy epic ("a CLI that prints a greeting; store the
  greeting in a file") and confirm the rule yields F01 = "`greet` prints the greeting (CLI,
  exit 0)" as the skeleton and merges "greeting storage" into the slice that reads it — i.e.
  the text is actionable, not only greppable.
- Reviewer dry-run, Doc-critic side (the brief's "fixtures exercise the three findings",
  recorded in the spec as a dry-run rather than a suite assertion): under `$T`, write a toy
  `epic.md` whose feature table lists `F01`–`F03` and three briefs — `F01.md` with
  `## Success outcome` "the `greetings` table exists" and no `## Observable behavior`;
  `F02.md` with the section still at the template placeholder; `F03.md` whose
  `## Success outcome` names only "a `GreetingRepository` interface" while its
  `## Observable behavior` is filled. Read `agents/doc-critic.md`'s new section as the critic
  would, with all three brief paths passed: expect `walking-skeleton-missing` **and**
  `observable-behavior-missing` on F01, `observable-behavior-missing` on F02,
  `internal-only-outcome` on F03. Then add `Observable-slice exemption: E00-F03 — repository
  consumed by F02` to the toy `## Notes` and expect F03's finding to become
  `exemption-recorded`. Then pass only `F03.md` (amend): expect no
  `walking-skeleton-missing` and F01/F02 unread. Record the outcome in the review note.
- Run `sh harness-install.sh --self` on the branch head; `git status --short` is empty
  (every generated file committed).
