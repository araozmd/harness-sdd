# Driller observable-slice rule and walking skeleton — Functional Spec

> R-ids in this document are `R1 … R10`; their fully-qualified form is `E36-F02:R1 … E36-F02:R10`.

## Context

The Driller (`agents/driller.md`) is the only role that decides a feature's size and shape,
and today its only rule is the `change_size.max_requirements` count (E21-F01). A
decomposition "F01 data model, F02 API, F03 UI" is legal and is the LLM default; nothing
can be exercised until the last feature lands, and the doc-critic has no property to check
at the `epic-decomposition` checkpoint beyond completeness. ADR-0008 decision 1 names the
shape rule — a feature is a vertical slice with at least one behavior observable at the
product boundary, the first feature of an epic is the walking skeleton, an internal-only
candidate is merged into its consumer. This feature installs the rule where decomposition
happens (the Driller), gives every brief a place to state the observable behavior (the
inbox-brief template, filled by Inception and the Driller), and gives the doc-critic three
named findings to raise. E36-F01 shipped decision 2 (task pairs); this is decision 1.

The user is anyone running `/sdd-drill` or `/sdd-new` in this repo or a consumer repo. The
rule is **advisory-but-recorded**, mirroring the E21-F01 size rule exactly: the Driller
decomposes and records, it never emits `blocked` or refuses to seed on shape alone, and a
legitimately internal epic (a pure library, an epic consumed only by another epic) is
handled by one recorded `Observable-slice exemption:` line in `epic.md` Notes that the
doc-critic can find mechanically.

**Complexity basis.** `standard`. The spec sits at 10 of 12 `R-id`s. ADR-0008 reaches five
prose files, but each carries an independent, grep-testable contract; there is no tool, no
validator-vs-schema pair, and the only literal carried in more than one place
(`## Observable behavior`, `Observable-slice exemption:`) is pinned by a test in every file
that carries it. No contradiction between existing components had to be resolved.

## Business rules

- **Shape rule beside the size rule (ADR-0008 decision 1).** Every feature the Driller
  seeds names at least one behavior observable at the **product boundary** — HTTP, CLI, UI,
  file output, or exit code. `max_requirements` stays the size proxy; this rule says nothing
  about count and never changes the size rule's semantics.
- **Walking skeleton.** The first feature of a **fresh** epic (the lowest `F##` seeded by a
  default, non-amend drill) is the walking skeleton: the thinnest end-to-end path a user or
  client can exercise, with no intra-epic `depends_on`. Cross-cutting setup (migrations
  framework, CI, auth middleware) is legitimate as that skeleton's **content**, never as its
  own horizontal feature. Amend mode (`/sdd-drill` on a `planned` epic) appends features; it
  does not re-judge the existing first feature.
- **Internal-only candidates merge into their consumer.** A candidate whose outcome is only
  internal (a table, a module, an interface, a migration, a schema, a config key) is merged
  into the slice that consumes it. When the merge would push the consumer over
  `max_requirements`, the size rule's split applies — along **observable seams** (a
  read-only surface, the one operation that commits state), not back into layers.
- **Recorded exemption, one mechanical token.** When the Driller seeds a feature whose
  outcome is nonetheless internal, or a fresh epic whose first feature is not end-to-end, it
  writes exactly one line per exempted feature in the epic's `epic.md` `## Notes`, beginning
  `Observable-slice exemption:` and naming the feature id and why. The exemption for an epic
  whose only consumer is another epic is one sentence (resolves the brief's open question):
  *an epic consumed only by another epic has no product boundary of its own, so its walking
  skeleton is the thinnest path the consuming epic can exercise, and the exemption line
  names that consuming epic and the surface where the behavior becomes observable.*
- **Advisory and it never blocks.** The Driller does not emit a `blocked` record on shape and
  does not refuse to seed a feature because its outcome is internal; `blocked` is a closed
  vocabulary about dependencies and ownership (E21-F01 R6, unchanged). The doc-critic's new
  findings are advisory like every finding it raises (RATIONALE C5): apply inline, proceed,
  no human gate, no status, no schema change.
- **The brief carries the observable behavior.** `specs/_templates/inbox-brief.md` gains a
  `## Observable behavior` section — one line, `<surface> — <what a user or client sees>` —
  placed after `## Success outcome` and before `## Scope / boundaries`. Inception
  (`/sdd-new`) and the Driller (`/sdd-drill`) both fill it. Existing briefs are **not**
  retro-fitted, and the critic reads only the briefs the Driller passed in the current run
  (see the scope signal below), so a legacy brief is never flagged.
- **Three named doc-critic findings** at `target-type=epic-decomposition`, each with a
  stable id so a progress note and a test can cite it:
  - `observable-behavior-missing` — a reviewed brief has no `## Observable behavior`
    section, or the section is empty or still the template placeholder;
  - `walking-skeleton-missing` — on a fresh drill, the lowest-numbered feature's brief does
    not describe an end-to-end path: its observable behavior names no product-boundary
    surface, or its `## Success outcome` stops at an internal artifact, or the feature has an
    intra-epic `depends_on`;
  - `internal-only-outcome` — a brief whose `## Success outcome` names only internal
    artifacts and nothing a user or client can exercise.
  An `Observable-slice exemption:` line in the epic's `## Notes` that names the feature id
  downgrades the matching finding to an `exemption-recorded` note (reported, not raised);
  an exemption line that names no feature id is itself reported. The critic's only scope
  signal is the set of brief paths the Driller passed (the briefs written in this run): a
  drill is **fresh** when the lowest-numbered feature of the epic's table is among them, else
  it is an **amend** — `walking-skeleton-missing` is not raised and unpassed (legacy) briefs
  are never read, so a pre-existing brief without the section is never flagged by an amend.
- **Generated glue is never hand-edited.** The `/sdd-drill` command body is emitted by
  `harness-install.sh`; its step 7 gains the brief-fill and exemption-line instruction, and
  `.claude/`, `.codex/`, `.opencode/`, `.pi/`, `.agents/` are regenerated by
  `sh harness-install.sh --self` and committed. The `/sdd-new` body already says "copy the
  template", so it needs no emitter change; `tests/test_self_drift.sh` is the check.
- **Prose contracts are asserted on the installed file** with whole-file `grep -qF` (the
  house section extractor is fence-blind — lessons 2026-09-16), and every anchor is
  confirmed RED on the pre-change blob before it is trusted.
- **Installed body changes ⇒ SemVer MINOR bump** (three role files, one template, the
  installer, docs) with a `CHANGELOG.md` entry. The target is the **next MINOR over the
  then-current `VERSION`** on `main` at merge time (W1 siblings bump in parallel; the Builder
  re-reads `main` before the final rebase). No test pins the literal; the pairing test reads
  `VERSION` at run time and compares it with the newest `CHANGELOG.md` heading.
- **Out of the Driller's hands, out of this feature.** Planner epic sketches, the
  Architect's pair ordering (E36-F01), the Reviewer, `max_requirements` semantics and any
  mechanical tool with an exit code are out of scope (see *Out of scope*).

## Architecture alignment

> `specs/architecture.md` is **absent** in this repo (never written; the ADR set exists under
> the single platform space `specs/adr/`). Per `agents/architect.md` graceful degradation the
> section is not strictly required; it is written because the brief records the ADR this
> feature implements and the Reviewer's ADR-citation clause keys on `sdd: true`.

- platform ADR-0008 — Vertical slices are the unit of decomposition; tasks pair one failing
  test with the code that passes it: this feature **implements decision 1** — the
  observable-slice rule, the walking skeleton and the merge-into-consumer rule — in the
  Driller, the brief template, Inception and the doc-critic, as an advisory-but-recorded rule
  beside the E21-F01 size budget. Decision 2 (task pairs) is E36-F01, already shipped; this
  spec's own `.tasks.md` is in pair form.
- platform ADR-0010 — Waves derived from `depends_on`: honored by **not** adding any stored
  state; the exemption is a line in `epic.md` Notes, the walking skeleton is a property of
  the feature table (lowest `F##`, empty intra-epic `depends_on`), nothing is written to the
  board.
- platform ADR-0009 — stage-aware NFRs: not touched (E36-F03 owns the stage and the
  deferred-decision ADRs); the merge-into-consumer rule is a shape rule, not an NFR rule.

No divergence from any ADR.

## Acceptance criteria (EARS)

> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md.

- **R1** — `agents/driller.md` shall carry a section headed
  `## Observable slice — the shape rule beside the size budget (ADR-0008)` whose text states
  the three clauses of ADR-0008 decision 1: every seeded feature's brief names at least one
  behavior observable at the product boundary (naming `HTTP`, `CLI`, `UI`, `file` and
  `exit code`); the first feature of a fresh epic is the walking skeleton (the thinnest
  end-to-end exercisable path, with no intra-epic `depends_on`); and a candidate whose outcome
  is only internal is merged into the slice that consumes it — and shall state that
  `max_requirements` remains the size proxy beside it.
- **R2** — The same `agents/driller.md` section shall instruct the Driller to record, for an
  internal-only feature it seeds anyway or a fresh epic whose first feature is not end-to-end,
  exactly one line in the epic's `epic.md` `## Notes` beginning `Observable-slice exemption:`
  that names the feature id and why; shall carry the one-sentence exemption for an epic whose
  only consumer is another epic; and shall state that the rule is advisory, never blocks, and
  never produces a `blocked` record on shape alone.
- **R3** — The same `agents/driller.md` section shall instruct the Driller to fill each
  seeded feature's brief `## Observable behavior` section with one line — the surface and what
  a user or client sees — and, for the walking-skeleton feature, the end-to-end path that line
  describes.
- **R4** — `specs/_templates/inbox-brief.md` shall carry a `## Observable behavior` section,
  positioned after `## Success outcome` and before `## Scope / boundaries`, whose body is a
  one-line placeholder naming the surface and what a user or client sees, while the template's
  existing frontmatter keys (`feature`, `seeded_by: inception`, `date`) and the sections
  `Problem`, `Success outcome`, `Scope`, `Chosen options`, `Constraints`, `Open questions`
  remain present (`tests/test_inception.sh` R5 stays green).
- **R5** — `agents/inception.md` § `## Write the intent brief (R4, R5)` shall list
  **Observable behavior** — the surface and what a user or client sees — among the body
  sections the brief must contain, between the **Success outcome** and **Scope / boundaries**
  bullets.
- **R6** — `agents/doc-critic.md` shall carry a section headed
  `## Epic-decomposition checks — observable slices (ADR-0008)` that defines, for
  `target-type=epic-decomposition`, three findings with these ids and triggers:
  `observable-behavior-missing` (a brief with no `## Observable behavior` section, or one
  that is empty or still the template placeholder
  `<HTTP / CLI / UI / file / exit code> — <what a user or client sees>`),
  `walking-skeleton-missing` (on a fresh drill, the lowest-numbered feature's brief is not
  end-to-end: no product-boundary surface, a `## Success outcome` that stops at an internal
  artifact, or an intra-epic `depends_on`), and `internal-only-outcome` (a brief whose
  `## Success outcome` names only internal artifacts and nothing a user or client can
  exercise) — and shall define the critic's only scope signal: the briefs under review are
  the brief paths the Driller passed (those written in this run); a drill is **fresh** when
  the lowest-numbered feature in the epic's feature table is among them, otherwise it is an
  **amend**, in which case `walking-skeleton-missing` is not raised and briefs the Driller
  did not pass are not read.
- **R7** — The same `agents/doc-critic.md` section shall state that an
  `Observable-slice exemption:` line in the epic's `## Notes` naming the feature id downgrades
  the matching finding to an `exemption-recorded` note that is reported but not raised, that
  an exemption line naming no feature id is itself reported, and that all three findings are
  advisory like every other finding (no gate, no status, no schema change).
- **R8** — A fresh `harness-install.sh` run shall ship `.harness/agents/driller.md`,
  `.harness/agents/doc-critic.md` and `.harness/agents/inception.md` carrying the R1–R3 /
  R5–R7 anchors, `.harness/specs/_templates/inbox-brief.md` carrying `## Observable behavior`,
  and `.claude/commands/sdd-drill.md` whose step `7.` names `## Observable behavior` and
  `Observable-slice exemption:` — the latter emitted by the `sdd-drill.md` heredoc in
  `harness-install.sh` and present in the committed `.claude/commands/sdd-drill.md` only as
  `sh harness-install.sh --self` output (`tests/test_self_drift.sh` R1 stays green).
- **R9** — `docs/WORKFLOW.md` shall carry a section headed
  `## Observable slices and the walking skeleton (ADR-0008)` placed after
  `## Change-size discipline (`change_size:`)` and before
  `## Architecture-aligned specs (the Architect cites ADRs)`, stating the three clauses of
  the rule, the `Observable-slice exemption:` Notes line, the three doc-critic finding ids,
  and that the rule is advisory and never blocks.
- **R10** — `VERSION` shall change from its `main` value (the Reviewer confirms a MINOR step
  from the diff), `CHANGELOG.md` shall carry a `## [<that version>] — <date>` section whose
  body names `E36-F02` and `Observable-slice exemption`, and the newest `## [` heading shall
  equal the `VERSION` file's value — read at test time, never as a frozen literal; the
  section check anchors on the historical body text so a later release prepended above it
  stays green.

## Out of scope

- Any change to `max_requirements` semantics, to the `change_size:` block, or to the Driller's
  size-rule section (E21-F01) beyond the one cross-reference the new section carries.
- Planner epic sketches (`agents/planner.md`, `/sdd-plan`); the Architect's pair ordering
  (E36-F01); the Reviewer (`agents/reviewer.md`); the Builder.
- A mechanical tool with an exit code for any of the three findings. Two of the three
  (`walking-skeleton-missing`, `internal-only-outcome`) are judgments about prose; the brief
  chose the doc-critic as the checkable surface. If a mechanical `observable-behavior-missing`
  check is wanted later it is a separate "enforce" feature on the F03/F04 seam ("declare and
  record" vs "enforce"), not an addition here.
- **Deviation from the brief, recorded:** the brief asked for "`tests/test_doc_critic.sh`-style
  fixtures [that] exercise the three findings". `test_doc_critic.sh` is a static-grep contract
  suite, and the three findings are raised by a model reading prose, so no shell fixture can
  exercise them without the test re-implementing the rule it claims to check (an assertion
  reachable by another path). The automated contract is the grep suite (R6, R7); the three
  toy briefs that exercise the findings are a **Reviewer dry-run** in `E36-F02.tests.md`
  § *Behavioral / end-to-end checks*, not a permanent-suite assertion.
- Retro-fitting `## Observable behavior` onto existing briefs under `progress/inbox/` (including
  this feature's own brief) or `Observable-slice exemption:` lines onto existing epics; the
  rule applies to drills and intakes run after this lands.
- Any `/sdd-new` emitter change (the command already copies the template), any `.codex` /
  `.opencode` / `.pi` / `.agents` edit other than `--self` output, any `store/` or `init.sh`
  change, and the Doc-critic checkpoints table in `docs/WORKFLOW.md` (E36-F04 edits it).
- Changing `agents/driller.md` § `## Completion report` or the `/sdd-drill` step `12.`
  (E36-F05 owns both), or § `## Read the draft epic + design artifacts as input (R6)` (E36-F03
  is expected to add the product stage there).

## Open questions
