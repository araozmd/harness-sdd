# Jira sync via REST API + PAT (no MCP) — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any R-id lacks a passing test. Tests extend the
> **existing** shell suites already wired into `verification.test_command`
> (`tests/test_mirror.sh`, `tests/test_install.sh`) — no new suite is added. Jira REST is
> exercised via a **stubbed endpoint / injected transport** (record every call), never a
> live Jira and never MCP. Assert **behavior**; never pin the exact VERSION; never diff
> DO-NOT-TOUCH files (esp. `state/tasks.json`) against `main`.

## Test intent notes (how each check stays a behavior test)

- **R1 / R2 — REST-only, single code path.** Run the configured `jira` sync against a
  **stubbed Jira REST transport** (a recording fake endpoint on `base_url`, or an injected
  fetch shim that logs every request) and assert every Jira interaction is an HTTPS REST
  call to `base_url` and **nothing else** — grep the tool source and the recorded calls for
  the absence of any MCP transport (no `mcp`, no non-REST client). For R2, assert the body
  carries exactly one `jira` implementation: `tools/sync-board.mjs` is the only file with a
  `jira` provider branch (no sibling Jira tool/script in `tools/`).

- **R3 — idempotent reconcile.** Seed the stub so the feature's issue already exists
  (search by the feature-id key returns a hit); run the sync and assert it issues **no**
  "create issue" REST call for the already-mapped feature (it transitions the existing
  issue). Assert the reconcile decision via the recorded calls, not a real board.

- **R4 — inert default (exists).** Reuse the existing `::inert_default_noop` guardrail —
  an empty provider is a pure no-op that makes no network call (extend it to confirm no
  Jira endpoint is contacted).

- **R5 — Bearer PAT header.** Assert the recorded request carries
  `Authorization: Bearer <PAT>` (not a Basic `email:token` header). Confirm the tool never
  builds a Basic auth header for the `jira` provider in F01.

- **R6 — PAT resolution + precedence.** `::jira_pat_env_precedence`: set both `JIRA_PAT`
  and a `pat_file` with **different** sentinel values; assert the request uses the env
  value. `::jira_pat_file_fallback`: unset `JIRA_PAT`, provide the `pat_file`; assert the
  request uses the file value (trimmed).

- **R7 — missing PAT fails closed.** With `provider: jira` fully configured but no
  `JIRA_PAT` and no readable `pat_file`, assert the tool exits **non-zero**, the message
  names `JIRA_PAT` and the pat_file path, and the recording endpoint sees **no** request.

- **R8 — PAT never leaks.** Use a unique sentinel PAT value; after any run (success,
  dry-run, and error paths) grep the tool's stdout+stderr, the fixture `tasks.json`, and
  the seeded `harness.config.yaml` for the sentinel and assert **absence**. Assert the
  seeded `.gitignore` covers the PAT file path (cross-checked in R16).

- **R9 — misconfig errors before network.** With `provider: jira` but a missing `base_url`
  or `project_key`, assert non-zero exit, the message names the missing key, and the
  recording endpoint sees **no** request.

- **R10 — issue-type map.** With defaults, assert the epic create/reconcile targets Jira
  issue type **Epic** and the feature targets **Story** (via the recorded request body).
  With `issue_type_map` overriding feature→Task, assert the feature request uses **Task**.

- **R11 — status map + transition.** Assert a feature's status maps to the Jira workflow
  state (identity by default) and the recorded call transitions the issue to it; with a
  `status_map` override, assert the mapped custom state name is used. Nothing hard-coded.

- **R12 — assignee no-op for jira.** With `mirror.board.assignee` set, assert the `jira`
  run makes **no** assignee-setting REST call (the knob is recognized but deferred to E10);
  the run must not couple `owner` to a Jira assignee.

- **R13 — one-way.** After a stubbed-REST run (and after `--dry-run`), snapshot the fixture
  `tasks.json` before/after and assert it is unchanged (fixture-local snapshot in the temp
  dir — **not** a diff against `main`).

- **R14 — dry-run.** Run with `--dry-run` against the recording endpoint and assert the
  tool prints "would …" intents and issues **no** mutating REST call (no create/transition),
  and leaves the fixture `tasks.json` unchanged.

- **R15 — auth error fails closed.** Configure the stub endpoint to return **401** (and a
  second case **403**); assert the tool exits non-zero, prints an actionable message naming
  the PAT/scope requirement, and does **not** echo the sentinel PAT value.

- **R16 — installer wiring (asserted, per recurring Codex finding).** In
  `tests/test_install.sh`, run the installer into a temp target (sandboxing `CODEX_HOME`)
  and assert `.harness/tools/sync-board.mjs` exists **and** is executable
  (`[ -x "$T/.harness/tools/sync-board.mjs" ]`), and that the seeded `.gitignore` contains
  the default Jira PAT file path (so a PAT can never be committed by default).

- **R17 — docs pin.** Grep `store/board-mirror.md` for the governing phrases: `jira`
  mirror provider is implemented (not a stub), Server/DC REST + Bearer PAT (Cloud out of
  F01 scope), `JIRA_PAT` env + gitignored `pat_file` + precedence, `base_url`/`project_key`,
  `issue_type_map` (epic→Epic/feature→Story), `status_map` workflow mapping, REST+PAT-only /
  no-MCP transport, the one-way invariant, and the `assignee` E10 deferral. Also grep
  `store/jira.md` for the mirror cross-reference. Assert presence of governing phrases, not
  verbatim paragraphs.

- **R18 — VERSION bump (shape, not a git delta).** Assert `VERSION` parses as valid SemVer
  (`MAJOR.MINOR.PATCH`, numeric segments) and that `CHANGELOG.md` carries a matching entry
  — the same stable shape-only form used by sibling gate suites. Do **not** hard-code the
  exact new string and do **not** compare the working tree against `HEAD`/`main`
  (permanent-suite anti-patterns that break the gate once committed).

## Behavioral / end-to-end checks (Reviewer)
- Run `tests/test_mirror.sh` and confirm: inert default is a true no-op (no Jira call); a
  configured `jira` run dispatches only to the stubbed REST endpoint with a Bearer PAT and
  never to MCP; the PAT resolves env-first then file; missing PAT / missing config fail
  closed before any network call; a re-run reconciles without duplicating; issue-type +
  status maps are honored; assignee is a no-op for jira; a 401/403 fails closed with a
  PAT-free message; `--dry-run` mutates nothing; and the fixture `tasks.json` is unchanged
  after any run (one-way).
- Grep the tool output, fixture `tasks.json`, and seeded config for the sentinel PAT and
  confirm it never leaks.
- Run the installer into a temp dir and confirm `.harness/tools/sync-board.mjs` is
  installed executable and the seeded `.gitignore` ignores the Jira PAT file.
- Read `store/board-mirror.md` + `store/jira.md` and confirm they pin the Server/DC
  REST+PAT jira mirror contract (Cloud out of scope), the env/pat_file convention, the
  field/status maps, the no-MCP/one-way invariants, and the mirror-vs-backend
  cross-reference.
