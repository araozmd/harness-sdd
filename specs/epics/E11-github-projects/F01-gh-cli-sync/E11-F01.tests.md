> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any R-id lacks a passing test. Tests are shell
> suites in the harness style, extending the **existing** suites already wired into
> `verification.test_command` (`tests/test_mirror.sh`, `tests/test_install.sh`) — no new
> suite is added. Assert **behavior**; never pin the exact VERSION and never diff
> DO-NOT-TOUCH files (esp. `state/tasks.json`) against `main`.

## Test intent notes (how each check stays a behavior test)

- **R1 / R2 — gh-only, single code path.** Reuse the existing dispatching fake-`gh`
  pattern (a `gh` shim on `PATH` that records every invocation). Assert a configured run
  dispatches to `gh project` / `gh issue` / `gh api` and to **nothing else** — in
  particular, grep the tool source and the recorded calls for the absence of any MCP
  transport (no `mcp`, no non-`gh` network client). For R2, assert the body carries
  exactly one `github-projects` implementation: `tools/sync-board.mjs` is the only file
  matching the `github-projects` provider branch (no sibling GitHub-Projects tool/script
  in `tools/`).

- **R3 — idempotent reconcile.** With a dispatching fake `gh` that returns a
  pre-existing issue + project item for the feature, run the sync and assert it does
  **not** emit a "created issue" / "add … to project" action for the already-mapped
  feature (it reconciles the existing item). Do not require a live GitHub; assert the
  reconcile decision via the tool's dispatch/log, not a real board.

- **R4 — inert default (exists).** The current `::inert_default_noop` case already proves
  an empty provider is a pure no-op that never touches the `gh` shim — keep it as the R4
  guardrail.

- **R5 — config shape / no new key.** Assert the tool reads `owner`/`project_number`/
  `repo` from the existing `mirror.board` block (existing `::ghprojects_parses_config`),
  and add a check that this feature introduces **no** new committed `mirror.board.*` key
  and no committed secret (grep the seeded config / tool for the existing key set only).

- **R6 / R13 — docs pin.** Grep `store/board-mirror.md` for: "Projects v2" (and a
  statement that Classic is unsupported), a minimum `gh` version, the `project` + `repo`
  scopes, the `gh`-only / no-MCP wording, and the one-way invariant. Assert the presence
  of the governing phrases, not verbatim paragraphs.

- **R7 — preflight fails closed (the new behavior).** With `provider: github-projects`
  fully configured, run the tool three ways using a fake `gh` on `PATH`: (a) `gh` absent
  (empty `PATH`), (b) `gh --version` reports a below-minimum version, (c) `gh` reports it
  lacks the required scope. Each must exit **non-zero**, print a message that names `gh`
  and the Projects-v2/scope requirement, and make **no** board-mutating call (assert the
  recording shim shows no `project item-edit` / `issue create`). Preserve the
  node-absent skip-and-report pattern.

- **R8 — misconfig errors before gh (exists).** The current
  `::ghprojects_misconfig_errors` already asserts a missing-key run exits non-zero,
  names the key, and never shells out to `gh` — keep it as the R8 guardrail.

- **R9 — status only, assignee preserved.** Reuse the existing `::assignee_status_gated`
  and `::assignee_default_inert` cases to prove status projection + the **unchanged**
  `assignee` behavior (assignee unset ⇒ never touched; set ⇒ status-gated reconcile).
  Add no assertion that couples `owner` (E10) to `assignee`; the point is F01 does **not**
  expand ownership here.

- **R10 — one-way.** After a dispatching fake-`gh` run (and after a `--dry-run`), assert
  the tool never wrote `state/tasks.json`: snapshot the fixture `tasks.json`
  before/after and assert it is unchanged (fixture-local snapshot in the temp dir — **not**
  a diff against `main`).

- **R11 — dry-run.** Run with `--dry-run` against a dispatching fake `gh` and assert the
  tool prints "would …" intents and issues **no** mutating `gh` call (no `item-edit` /
  `issue create` / `issue close`), and leaves the fixture `tasks.json` unchanged.

- **R12 — installer wiring (asserted, per recurring Codex finding).** In
  `tests/test_install.sh`, run the installer into a temp target (sandboxing `CODEX_HOME`)
  and assert `.harness/tools/sync-board.mjs` exists **and** is executable
  (`[ -x "$T/.harness/tools/sync-board.mjs" ]`), mirroring the existing
  `telemetry-report.py` presence assertion.

- **R14 — VERSION bump (shape, not a git delta).** Assert `VERSION` parses as valid
  SemVer (`MAJOR.MINOR.PATCH`, numeric segments) and that `CHANGELOG.md` carries a
  matching entry — the same stable shape-only form used by sibling gate suites. Do
  **not** hard-code the exact new string and do **not** compare the working tree against
  `HEAD`/`main` (permanent-suite anti-patterns that break the gate once committed).

## Behavioral / end-to-end checks (Reviewer)
- Run `tests/test_mirror.sh` and confirm: inert default is a true no-op (no `gh` call);
  a configured run dispatches only to `gh`; the strengthened preflight fails closed on an
  absent/too-old/under-scoped `gh` with no board mutation; a re-run reconciles without
  duplicating; `--dry-run` mutates nothing; and the fixture `tasks.json` is unchanged
  after any run (one-way).
- Run the installer into a temp dir and confirm `.harness/tools/sync-board.mjs` is
  installed and executable.
- Read `store/board-mirror.md` and confirm it pins Projects v2 (Classic unsupported),
  the minimum `gh` version, the `project`+`repo` scopes, the `gh`-only/no-MCP transport,
  and the one-way invariant.

- Full gate: `./init.sh` green, then `verification.test_command` green (the two touched
