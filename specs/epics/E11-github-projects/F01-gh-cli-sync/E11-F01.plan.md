# GitHub Projects sync via `gh` CLI (no MCP) — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it
> serves. Start high-level; the mirror already exists — this plan **completes** it and
> pins its contract, it does not redesign it.

## Extend vs replace decision  (serves: R1, R2, R6, R9, R10)

**Decision: EXTEND / COMPLETE the existing mirror. Do NOT replace or fork it.**

Rationale (the load-bearing part of this plan):

- `tools/sync-board.mjs` **already is** a `gh`-CLI-only, no-MCP, idempotent,
  inert-by-default `github-projects` projection. It uses `gh project view` /
  `gh project field-list` / `gh project item-list` / `gh project item-add` /
  `gh project item-edit`, `gh issue` (create/list/close/reopen/edit), and
  `gh api graphql` — i.e. it is **already** the enterprise-safe transport the brief
  demands. The mutation it runs (`updateProjectV2Field` with
  `ProjectV2SingleSelectFieldOptionInput`) is a **Projects v2** GraphQL mutation and the
  `gh project` subcommands are the **v2** surface, so Projects v2 is already the de-facto
  target — F01 only pins and documents it.
- Replacing it would create the exact defect the epic warns against — **two divergent
  GitHub code paths** — and would throw away the mirror's already-tested idempotency,
  `status_map`, and inert-default behavior (`tests/test_mirror.sh`).
- Therefore F01's real, testable deliverable is the **gap-closure**, not a rewrite:
  1. **Preflight the transport** (R7): make the `gh`-availability / Projects-v2 / scope
     check explicit and actionable *before* any board mutation, instead of the current
     thin `gh --version` existence check that lets a missing `project` scope surface as a
     mid-run crash.
  2. **Close the installer-wiring gap** (R12): the installer already `copy tools` +
     `chmod +x sync-board.mjs`, but **`tests/test_install.sh` does not assert** the tool
     ships executable in a fresh install. Add that assertion (recurring Codex P1 on
     installer wiring — do not skip).
  3. **Pin the contract in docs** (R13): `store/board-mirror.md` states Projects v2 (not
     Classic), the minimum `gh` version, the `project` + `repo` scopes, the `gh`-only /
     no-MCP transport, and the one-way invariant.
  4. **VERSION bump** (R14) for the installed-body change.

Everything else the brief lists (outbound projection, idempotent reconcile, config
under `mirror.board`, inert default, one-way invariant) is **already satisfied** by the
existing mirror; F01's spec asserts those behaviors as regression guardrails (R1, R3,
R4, R5, R10, R11) so completing the feature verifies the whole contract, not only the
new preflight.

## Resolved open questions  (serves: R2, R6, R9)
1. **Extend vs replace the GitHub path** → **Extend** (see decision above). One tool,
   one `github-projects` implementation; no second code path.
2. **`gh project` surface: Classic vs Projects v2** → **Projects v2** is pinned and
   supported; Classic is unsupported. The mirror already speaks the v2 GraphQL / `gh
   project` surface, so this is a documentation + preflight pin, not a rewrite.
3. **Assignee / ownership sync** → **Deferred to E10 (E10-F03).** F01 projects status
   only; the pre-existing `mirror.board.assignee` behavior is preserved untouched and
   is **not** extended to carry the E10 `owner` semantics here.

## Stack & dependencies
- Language: Node.js (existing `tools/sync-board.mjs`, ESM, dependency-free).
- External tool: **`gh` CLI** (developer-provided, already authed). No new dependency,
  no MCP, no new npm package.
- Test harness: POSIX `sh` suites (`tests/test_mirror.sh`, `tests/test_install.sh`), run
  from `verification.test_command`.

## Data model  (serves: R3, R5, R9)
No new persistent schema. The projection maps existing `state/tasks.json` entities onto
the board; config keys are the **existing** `mirror.board` shape (no additions).

| Entity | Field | Type | Notes |
|---|---|---|---|
| feature (from tasks.json) | `id` / `title` / `status` | string | title `"<id> — <title>"` is the issue-match key (R3) |
| mirror.board config | `provider` / `owner` / `project_number` / `repo` | scalar | existing keys; `provider` empty ⇒ inert (R4, R5) |
| mirror.board config | `status_map` / `assignee` | map / string | existing optional keys; `assignee` preserved as-is (R9) |

## Interface / behavior  (serves: R1, R7, R8, R11)
No HTTP API. The interface is the CLI command and its exit contract:

| Invocation | Behavior | R-id |
|---|---|---|
| `node .harness/tools/sync-board.mjs` | project tasks.json → configured Project via `gh` | R1, R3 |
| `node .harness/tools/sync-board.mjs --dry-run` | print intended changes; mutate nothing | R11 |
| provider empty/`none` | no-op, exit 0, never calls `gh` | R4 |
| `gh` absent / too old for Projects v2 | exit non-zero, actionable message, before any mutation | R7 |
| missing `owner`/`project_number`/`repo` | exit non-zero, names missing key, before `gh` | R8 |

## DO NOT TOUCH
- `state/tasks.json` — the source of truth; the mirror is one-way and never writes it
  (R10). No test may diff it against `main`.
- The `jira` / `azure-boards` stub branches in `tools/sync-board.mjs` — they stay
  recognized no-op stubs (their own epics E12/E13/E14).
- The `mirror.board` **config shape** in `harness.config.yaml` — reuse it; add **no** new
  key (R5). (The installer's existing `mirror:` seeding/migration stays as-is.)
- Any MCP glue — none exists and none is added (R1).
- The Orchestrator / `/sdd-next` / ownership (`workflow.identity`, `owner`) code paths —
  E10's territory (R9); F01 touches none of it.
- Do **not** pin an exact `VERSION` string in any permanent test, and do **not** diff any
  DO-NOT-TOUCH file against `main` in a permanent test (recurring anti-pattern).

## Approach notes
- **Preflight design (R7) is the Builder's call**, within the constraint: it must be a
  `gh`-only capability check (e.g. parse `gh --version`, or probe a cheap `gh project`
  capability) that fails **closed** with a message naming `gh` and the Projects-v2 /
  scope requirement, and it must run **before** the first mutating `gh` call. It must not
  regress the inert-default path (R4): an empty provider still returns before any `gh`
  contact. Keep the message actionable (what to install / which scope to add).
- **Idempotency (R3)** is already implemented (issue-by-title map → project-item map);
  the spec asserts it as a guardrail. No change needed unless the preflight refactor
  touches the reconcile loop — if so, preserve the exact match keys.
- **Installer assertion (R12):** mirror the shape used for `telemetry-report.py`
  (`[ -f "$T/.harness/tools/…" ]`) but also assert the executable bit for
  `sync-board.mjs`. Sandbox `CODEX_HOME` for any installer-invoking case (existing suite
  guard) — reuse the suite's temp-dir + `CODEX_HOME` pattern.
- **Test ethos:** assert **behavior**, never the exact VERSION; for R14 assert the
  **shape** (`VERSION` parses as SemVer `MAJOR.MINOR.PATCH` + a matching `CHANGELOG.md`
  entry exists), the same shape-only form used by sibling suites — never compare the
  working tree to `HEAD`/`main`.
