# `execution.builder.backend` prompt in the installer picker — Technical Plan

> Every decision cites the R-id(s) it serves. Start high-level; the Builder picks
> internals not pinned here.

## Stack & dependencies

- POSIX `sh` + `grep`/`awk`/`sed` only — the installer's existing ethos. **No new
  dependencies** (R14 keeps `init.sh` green).
- Line numbers below are from `harness-install.sh` at `VERSION` 0.41.0 and are hints, not
  contracts — locate by function name.

## Design in one paragraph

Add a **second question** to the installer: after `resolve_agents` resolves the front-end set,
`resolve_builder_backend` resolves one enum value with the precedence *override → interactive
prompt → current effective value*, storing it in a global. Later, at the existing config
seed/preserve stage, `set_builder_backend` writes it into the target's
`harness.config.yaml` by replacing **one scalar on one line**. `migrate_config` grows one more
table entry so the `execution:` block exists on a preserved config that predates it. The
front-end picker, `--print-agents`, and every E19 helper are untouched.

## Interface  (serves: R4, R5, R12)

| Surface | Form | Behavior |
|---|---|---|
| flag | `--builder-backend=<value>` / `--builder-backend <value>` | override; wins over env; empty value ⇒ no override (R4) |
| env | `HARNESS_BUILDER_BACKEND=<value>` | override; empty ⇒ no override (R4) |
| legal values | `in-session`, `delegate` | anything else aborts non-zero before any write (R5) |
| report | one stdout line per target, e.g. `   builder backend: delegate (explicit --builder-backend)` | R12 |
| warning | one stderr/stdout warning naming `execution.builder.delegate_cmd` + the config path | R11 |

`--print-agents` output is **frozen at two lines** — `tests/test_agents_host.sh` asserts the
exact stdout line count. Do not add a third line to it (R12).

## Config write shape  (serves: R7, R8, R9, R10)

Target region in `harness.config.yaml` (source lines ~48–70):

```yaml
execution:
  builder:
    backend: in-session      # ← only this scalar is ever rewritten
    delegate_cmd: ""         # ← read-only for this feature
```

- The writer replaces **only the value token** on the backend line, preserving indentation and
  any trailing comment; every other byte of the file is untouched (R7).
- When the resolved value already equals the current value, the writer is **not invoked at
  all**, so the file is trivially byte-identical (R8).
- `migrate_config` gains one entry that keys off the **top-level `execution:` header only**
  (`^execution:[[:space:]]*(#.*)?$`), matching how the `mirror:` / `fix_lane:` / `models:` /
  `pr_loop:` entries already handle multi-level blocks. Header absent ⇒ append the whole
  `execution:` + `builder:` + `backend:` + `delegate_cmd:` block at EOF. Header present ⇒ do
  nothing. **Do not** try to insert a nested key into an existing `execution:` block: a
  present-but-partial block would get a duplicate `builder:` mapping, which is invalid YAML
  and strictly worse than the status quo (R9).

## Approach notes

- **Order of the two questions matters for UX and for the F02 seam.** Both are resolved back
  to back at the top of `install_one`, before any output from the body copy; the *write*
  happens later, at the config stage. E20-F02 adds its prompt as one more call in the same
  resolve block and one more apply in the same config block.
- **Fresh vs upgrade.** On a fresh install the config does not exist when the prompt runs, so
  the current effective value is the built-in `in-session` — which is exactly what the seeded
  file will contain (R10). On an upgrade the config exists and pre-selects the persisted
  value, which is what "pre-selected from current values on a re-run" means.
- **Umbrella cascade.** The override applies to every child (like `--agents`); the prompt
  fires per target (like the picker). No caching — see the spec's *Out of scope*.
- **The `read -r` residue.** Only the literal keystroke plumbing (`read -r` and two `printf`
  menu lines) is outside automated reach; every decision it feeds is in
  `builder_backend_answer`, which the suite extracts and unit-tests (R2). Keep the prompt
  function that thin — logic that migrates into it becomes untestable.
- **Non-interactive means silent.** In the no-TTY / no-override path the resolver must not
  merely resolve to the same value — it must not invoke the writer at all, so the file's mtime
  and bytes are untouched (R6, R8).
