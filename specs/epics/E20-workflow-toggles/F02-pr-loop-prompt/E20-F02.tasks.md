# `pr_loop.enabled` prompt in the installer picker — Task Checklist

> Sequential, atomic steps. Each lists the R-id(s) it satisfies. This is the Builder's only
> worklist. Read `E20-F02.plan.md` "DO NOT TOUCH" before starting: `seed_pr_loop_optin`,
> `pr_loop_enabled`, `_cfg_pr_loop_value`, the §7b pass, every E20-F01 function,
> `tests/test_install.sh` and `tests/test_pr_loop.sh` are all off-limits.

## 1. The pure decision function

- [x] **T1** — Add `pr_loop_answer <answer> <current>` to `harness-install.sh`, beside the
  E20-F01 helpers. Pure: no `read`, no config access, no file write, no global. Prints one of
  the literals `true` / `false` and nothing else. Truth table: `1` / `n` / `no` / `false`
  (word forms case-insensitive) ⇒ `false`; `2` / `y` / `yes` / `true` ⇒ `true`; empty or
  anything else ⇒ `<current>`. **(R2)**
- [x] **T2** — Give it the shape contract in a comment above it: the opening line is exactly
  `pr_loop_answer() {`, no line inside the body is exactly `}`, so
  `sed -n '/^pr_loop_answer() {$/,/^}$/p'` yields a sourceable definition. Note that the raw
  answer must never be written to the config — E18-F01 R18b makes `Yes` / `1` / `True`
  resolve OFF, so only the mapped literal is emitted. **(R2)**

## 2. The prompt

- [x] **T3** — Add `pr_loop_prompt <current>`: menu to **stderr**, resolved value to stdout.
  It must name the current effective value as the Enter-default and state that the loop needs
  the **Codex GitHub App** on the repo plus an authed **`gh`**. Body = menu `printf`s +
  `read -r` + `pr_loop_answer "$ans" "$current"`. No loop, no re-ask, no config read, no
  write. Add the "keep this function this thin" comment. **(R1)**

## 3. The resolver

- [x] **T4** — Add globals `PR_LOOP_CHOICE="false"` / `PR_LOOP_CHOICE_SOURCE="unchanged"` and
  `resolve_pr_loop <target>`: current effective value = `_cfg_pr_loop_value <cfg> enabled`
  normalized so only the literal `true` is true (absent file/block/key, empty, malformed ⇒
  `false`); then precedence *non-empty `$PR_LOOP_OVERRIDE` → `[ -t 0 ]` prompt → current*.
  It must **not** read `HARNESS_PR_LOOP_ENABLED`. **(R1, R4, R5, R6)**
- [x] **T5** — Call `resolve_pr_loop "$TARGET"` in `install_one` immediately after
  `resolve_builder_backend "$TARGET"` (~:1600), with a comment marking it as the third
  question, resolved-only (the write happens at §2b). **(R1, R3)**

## 4. The writer

- [x] **T6** — Add `set_pr_loop_enabled <config-file> <value>`: `awk` scoped to the top-level
  `pr_loop:` section; replace **only** the value token on the `enabled:` line, preserving
  indentation and everything after the value; write via `$f.tmp` + `mv`. A same-named
  `enabled:` under any other section must be untouched. **(R7)**
- [x] **T7** — Extend it: when the section exists but carries no `enabled:` key, insert the
  **canonical** line (byte-identical to `seed_pr_loop_optin`'s / `migrate_config`'s, modulo
  the value) immediately after the `pr_loop:` header. **(R7, R10)**

## 5. Wiring the apply into §2b

- [x] **T8** — In `install_one` §2b (~:1663–1686), after the builder-backend apply: read the
  current gate value with `_cfg_pr_loop_value`, and call `set_pr_loop_enabled` **only** when
  it differs from `$PR_LOOP_CHOICE`. Do not call the writer on a match. **(R7, R8, R9, R11)**
- [x] **T9** — In the same block, when `HARNESS_PR_LOOP_ENABLED` is set and its normalized
  value differs from `$PR_LOOP_CHOICE`, print exactly one stderr warning naming the variable
  and carrying the stable token `PER-RUN override`, stating it was not persisted. No warning
  when it is unset or agrees. **(R5)**
- [x] **T10** — In the same block, print exactly one stdout report line with a stable
  greppable prefix (e.g. `pr_loop.enabled: <value> (<source>)`) — chosen so it cannot collide
  with the §7b stderr text `pr_loop.enabled is not true`. **(R12)**

## 6. Arg parsing

- [x] **T12** — Validate the non-empty override in the same place the builder-backend override
