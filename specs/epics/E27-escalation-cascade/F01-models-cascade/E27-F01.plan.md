# E27-F01 — Plan

## Where the change lives

Everything is in `harness-install.sh`; no tools/ copies, no sdd-pr-loop heredoc impact.

1. **`UMB_MODELS_CFG` global, set per target in `install_one`** (next to `MODEL_DIAG`):
   `_umc_body="$(umbrella_body_dir "$H")"` → non-empty ⇒
   `UMB_MODELS_CFG="$_umc_body/harness.config.yaml"`, else empty. Computed once per
   target — `resolve_model` runs in `$(…)` subshells which inherit the global, exactly
   like `MODEL_DIAG`. `umbrella_body_dir` already prefers the cascade's
   `HARNESS_UMBRELLA_ROOT` env over the child's persisted `umbrella.root`, so both the
   `--umbrella` loop and a standalone child re-run resolve the same coordinator config;
   the coordinator itself and single-repo targets resolve nothing (R6).

2. **`_model_tier_resolve <role>` — the resolution core**, setting `_mtr_tier` +
   `_mtr_src` (`own` | `umbrella` | `default`) in the caller's shell. `model_tier`
   becomes a thin printer over it (existing callers unchanged). Chain: child role →
   child default → validate (warn-once on garbage ⇒ inherit) → if `inherit` and
   `UMB_MODELS_CFG` non-empty: coordinator role → coordinator default → validate with a
   coordinator-naming warn key (R7) → non-inherit ⇒ `_mtr_src=umbrella`. Final empty ⇒
   `inherit`/`default`.

3. **Pin cascade in `resolve_model`** (R3): after the child pin lookup,
   `[ -n "$_rm_pin" ] || _rm_pin="$(_cfg_models_value "$UMB_MODELS_CFG" "pin.…")"` —
   placed BEFORE the existing `inherit`-pin and OpenCode-shape guards so the winning
   pin is validated identically.

4. **Report line** (R5): in `install_one` near `write_escalation_arming` (§6b), when
   `UMB_MODELS_CFG` is non-empty, loop `MODEL_ROLES` calling `_model_tier_resolve`
   directly (no subshell, so `_mtr_src` is readable) and emit one `info` line listing
   `role=tier(source)` for non-inherit roles + a trailing `others inherit` summary.
   R4 needs no code: `escalation_verdict` → `resolve_model` → `model_tier` already
   flows through the same choke point.

## Risks

- `model_tier` output is captured in many `$(…)` sites — keep its stdout contract
  byte-identical (one line, tier only).
- Warn-once keys must differ between child-garbage and coordinator-garbage so both
  diagnose (`tier:` vs `utier:` prefixes).
- `test_model_routing.sh` pins single-repo behavior — R6 regression cover exists.

## Out of scope

Cascading any other config section (pr_loop, verification…) — models only, per drill.
