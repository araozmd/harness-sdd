# pi environment preflight + approval-gated pinned `pi-subagents` install — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any R-id lacks a passing test.
>
> **Suite.** A new POSIX `sh` suite, `tests/test_pi_preflight.sh` (PP), with `set -eu`
> and `fail`/`pass`. Its cases run through one `inst` helper:
> `inst <stub-mode-file|-> <extra env|-> <stdin-spec> <args…>`.
>
> **Hermetic.** Copy the sandbox from `tests/test_pi_agents.sh:37-51`:
> - the real PATH minus every directory holding a `pi` executable;
> - the setup fails if `pi` still resolves;
> - `env -i` with an isolated `HOME=$T/home`, `PI_CODING_AGENT_DIR` unset (so the agent
>   dir is `$T/home/.pi/agent`) and an isolated `CODEX_HOME`.
>
> The stub `pi` is added to PATH per case. **No case runs the real `pi`, npm or the
> network.** Point `TMPDIR` at a path outside the repo.
>
> **The stub `pi`** (`$T/stubbin/pi`, POSIX sh) reads its behavior from a control file
> whose path is passed in the env (`STUB_CTL`). It appends one record per invocation to
> `$STUB_LOG`: argv NUL-separated, `pwd -P`, whether fd 0 is `/dev/null` (`[ -t 0 ]` +
> `readlink /proc/self/fd/0` where available), and `PI_OFFLINE`. Per-verb modes:
> - `--version`: `ok:<text>` (printf `%b`, so ESC/NUL/newline rows are expressible),
>   `rc:<n>:<text>`, `sleep`, `huge` (65 KiB).
> - `list`: `real`, `text:<%b>`, `rc:<n>`, `sleep`. `real` renders the fact-5 format
>   from `.pi/settings.json` `packages` + `.pi/npm/node_modules/<name>` presence, plus an
>   optional user-scope `$HOME/.pi/agent/settings.json`.
> - `install`: `real`, `rc:1`, `noop` (exit 0, write nothing), `add-subagents` (`real`
>   plus a top-level `subagents: {}`), `rc1-subagents` (writes a top-level `subagents: {}`
>   and then exits 1), `sleep`. `real` is a python read-merge-write of
>   `packages`, mirroring fact 3, plus `mkdir -p .pi/npm/node_modules/pi-subagents`.
>
> **Runtime.**
> - The pure functions (`pi_deps_decision`, `pi_deps_answer`) are extracted with `sed`
>   and run in-process.
> - One installer run takes ≈0.4 s. Table cells reuse one installed target per table and
>   re-run the installer (the upgrade path), as background jobs joined with `wait`.
> - The timeout cells set `HARNESS_PI_PROBE_TIMEOUT=1` / `HARNESS_PI_INSTALL_TIMEOUT=1`.
> - Target: the suite runs in ≤ 45 s wall-clock.
>
> **Agent-dir snapshot.** Every case that seeds `$T/home/.pi/agent` also takes a recursive
> snapshot of it before the run: `find … -exec cksum` plus a listing of link targets
> (`readlink`). After the run it asserts the snapshot is byte-identical (R6/R7).

## Behavioral / end-to-end checks

- The Reviewer runs `sh tests/test_pi_preflight.sh` standalone with the sandbox. It also
  runs the full suite with `tools/run-tests.sh --jobs $(nproc)`, with `TMPDIR` on disk
  outside the repo.
- On this host, the Reviewer may run **read-only** against the real binary:
  `sh harness-install.sh --agents=pi --pi-deps=check <scratch-target> </dev/null`.
  - Expected stdout: `pi 1.2.0`, `trust: undecided`, `pi-subagents: absent`, a
    `conflict … (dangling symlink)` line, `1 dangling symlink(s) under ~/.pi/agent/agents/`,
    and the printed command.
  - Exit 0.
  - `~/.pi/agent` byte-identical before and after, ignoring pi's own transient `*.lock`
    lock directories (fact 6).
- **Never** run `--pi-deps=install` against the real binary on this host.
