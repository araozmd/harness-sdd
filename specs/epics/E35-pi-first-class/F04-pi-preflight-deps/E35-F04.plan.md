# pi environment preflight + approval-gated pinned `pi-subagents` install — Technical Plan

> Translates the `.spec.md` into design. Every decision cites the R-id(s) it serves. The
> verified pi facts are numbered in the spec's Context (fact 1–10). Cite them; do not
> re-derive them from pi's docs.

## Stack & dependencies

- POSIX `sh` in `harness-install.sh`, plus `python3 -I` here-docs for:
  - the bounded `pi` runner;
  - the trust classifier;
  - the `pi list` parser;
  - the settings precondition.

  This follows the `pi_settings_file_overridden` precedent. No `timeout(1)`: macOS lacks it.
- New dependencies: none. `python3` is already used. Without it the preflight degrades to
  one line (R7).

## Report format  (serves: R2–R7, R9–R11)

Every line goes to **stdout** through `info`/`ok`, prefixed `pi preflight: `. Warnings use
`info "pi preflight: ⚠️ …"`, never stderr. The existing suites capture stderr, so this
keeps their output stable (see Approach). The prefix comes on every line, from
installer-authored text only. Interpolations are limited to:

- the parsed version, which has already passed the R3 grammar;
- the target path;
- the agent dir path;
- integers;
- fixed words.

No pi stdout or stderr is printed for a probe (R7). Lines, in order:

```
pi preflight: pi 1.2.0 (>= 1.0.0)                      | not found on PATH | … below the 1.0.0 floor | version: unknown
pi preflight: trust: trusted | distrusted | undecided | unknown (<fixed reason word>)  [+ fix line]
pi preflight: pi-subagents: pinned 0.78.0 (project|user) | mismatch | absent | unknown | not probed
pi preflight: conflict: a subagent extension (pi example or legacy pi-subagents clone) that registers a conflicting subagent tool at <path> [(dangling symlink)]
pi preflight: <n> dangling symlink(s) under <agent dir>/agents/ (left untouched)
pi preflight: install: <one of: not needed | installed and verified | not approved — run: <command> | not attempted: <reason> | failed: <exit N|timed out|not verified>>
```

Where the line names a fix, it is one line, e.g.
`pi preflight: fix: run /trust in an interactive pi session in <target>, then /reload; headless runs need -a`.

For an `undecided` trust state, the fix line also says pi's `defaultProjectTrust`
setting may already trust the project (spec, Out of scope).

## The bounded runner  (serves: R7)

`pi_run <timeout> <capture:0|1> <args…>` is one python here-doc. It runs
`subprocess.Popen(["pi", *args], cwd=TARGET, stdin=DEVNULL, start_new_session=True, …)`.

- With capture=1, stdout and stderr go to temp files: a 64 KiB read cap for parsing.
  `PI_OFFLINE=1` is added to the env.
- With capture=0 (install only), the child's stdout and stderr both go to the installer's
  **stderr**. The user sees npm progress, and the installer's stdout report stays
  installer-authored.
- On timeout it runs `os.killpg(pgid, SIGKILL)`, so npm grandchildren die too, and returns
  rc 124.

`command -v pi` decides presence. The runner execs whatever `pi` PATH resolves, so the
tests' PATH discipline controls it.

## Trust classifier  (serves: R4)

`pi_trust_state <agent-dir> <target>` prints `trusted|distrusted|undecided|unknown`.

- The agent dir comes from the **existing** `pi_user_agent_dir`, which is F03's and is
  already resolved exactly as pi resolves it (fact 7). Do not write a second resolver.
- An empty agent dir ⇒ `unknown`.
- The file is resolved with `os.stat`, so symlinks are followed:
  - absent, a dangling symlink included ⇒ `undecided`. pi's `existsSync` is false for a
    dangling link, so pi sees no file;
  - not `S_ISREG` (a dir or a FIFO — never `open()` it) ⇒ `unknown`;
  - over 1 MiB, or unreadable (a symlink loop, `ELOOP`, included) ⇒ `unknown`.
- Parse: strip one leading BOM (pi does too), then `json.loads` with the NaN/Infinity
  constants rejected. A non-dict, or any value not in {True, False, None}, ⇒ `unknown`.
- Walk from `os.path.realpath(target)` to `/`. The first key whose value is True or False
  wins; None is skipped. With no hit ⇒ `undecided`.

## `pi list` parser  (serves: R5)

`pi_list_status` runs `pi_run 15 1 list -a` and parses the captured stdout. First strip
ANSI SGR sequences, in case `FORCE_COLOR` leaks. Then every line must match exactly one of:

- `No packages installed.`;
- `User packages:` / `Project packages:`;
- an empty line;
- `  <non-space…>`, an entry, optionally ending ` (filtered)`;
- `    <anything>`, a path line, only directly after an entry.

Any other line, a non-zero rc, or rc 124 ⇒ `unknown`. Output: `pinned project`,
`pinned user`, `mismatch`, `absent` or `unknown`. `pinned` requires:

- the section header;
- an entry line equal to `  npm:pi-subagents@<PIN>`, not filtered;
- a following path line.

Project is reported first when both scopes hold the pin. Any entry containing
`pi-subagents` that is not a qualifying pinned entry makes the status `mismatch`. This
holds even when a pinned entry is present elsewhere (fail closed: pi may load the
non-pinned entry).

## Conflict scan  (serves: R6)

The scan is plain `sh` tests, `[ -e "$p" ] || [ -L "$p" ]`, over these paths:

- `<ad>/extensions/subagent/index.ts`
- `<ad>/extensions/subagent/index.js`
- `<ad>/extensions/subagent/package.json`
- `<ad>/extensions/subagent.ts`
- `<ad>/extensions/subagent.js`

`dangling` = `[ -L ] && [ ! -e ]`. The count of dangling links directly under
`<ad>/agents/` comes from a `for f in "<ad>/agents/"* "<ad>/agents/".*` loop with `-L`/`-e`
tests: no `find -L` and no recursion. Every operation is a read: no `rm`, `ln`, `mkdir` or
redirect touches `<ad>`.

## Shape matrix  (serves: R9)

`pi_install_paths_safe` checks the paths `pi install -l` and the `npm install --prefix .pi/npm`
it spawns write (fact 2–3). A path is safe
when it is:

| Path | Allowed shapes | Unsafe |
|---|---|---|
| `.pi` | real directory, or absent | symlink (live/dangling), non-directory |
| `.pi/settings.json` | absent, or regular file, not a symlink, link count 1 | symlink (live/dangling), directory/FIFO/other, hard link (nlink > 1) |
| `.pi/npm` | absent, or real directory | symlink (live/dangling), non-directory |
| the ENTIRE existing `.pi/npm/` tree, any depth, hidden names included, walked without following links (`package.json`, `.gitignore`, lockfiles, `node_modules/.package-lock.json`, `node_modules/.bin`, `@scope/*`, nested files) | every entry a real directory or a regular file with link count 1 | any other symlink, any other node type, a hard-linked file; `node_modules` must be a directory |

The one exception: a symlink whose immediate parent directory is named `.bin` and whose resolved
target lies inside `realpath(.pi/npm)` (npm's own bin links from a previous install). npm writes
through any other link or hard link it finds (reproduced with npm 11.20.0 for the lockfiles,
`node_modules/.package-lock.json` and `node_modules/.bin`), so there are no per-name layers. The
check uses `[ -L ]` before `[ -d ]`/`[ -f ]`, so a link is never classified by its target.
The link count comes from `python3 os.lstat(...).st_nlink`, which is portable; avoid
`stat -c`.

The `.pi/settings.json` content precondition is the strict Node-JSON parse of
`pi_settings_file_overridden`:

- a BOM, `NaN`/`Infinity` or invalid UTF-8 ⇒ unsafe;
- it must be a dict;
- `packages`, when present, must be a list.

A `subagents` key does **not** make it unsafe. pi preserves the key (fact 3), and F03
already reads it as `unstamped`.

Reason words for `not attempted:` are a fixed set:

- `pi missing`
- `pi below floor`
- `pi version unknown`
- `backend status unknown`
- `project distrusted`
- `project trust unknown`
- `unsafe path <rel>`, where `<rel>` is a fixed name (`.pi`, `.pi/settings.json`, `.pi/npm`,
  `.pi/npm/node_modules`, `.pi/npm/package.json`, `.pi/npm/.gitignore`,
  `.pi/npm/package-lock.json`, `.pi/npm/npm-shrinkwrap.json`) or the literal `.pi/npm/<other>`
- `user-scope mismatch`
- `unsafe .pi/settings.json content`
- `python3 missing`

## Decision function  (serves: R8)

`pi_deps_decision <mode> <source> <stdin_tty> <stderr_tty> <umbrella> <answer>` is
**pure** and prints `install`, `prompt` or `print-command`. It follows the
`builder_backend_answer` SHAPE CONTRACT: its opening line is exactly
`pi_deps_decision() {`, no inner line is exactly `}`, and it is defined at column 0, so
the suite can extract it with `sed -n '/^pi_deps_decision() {$/,/^}$/p'`.

- `install` + `flag` ⇒ `install`.
- `check` + stdin tty + stderr tty + no umbrella ⇒ `prompt`.
- Everything else ⇒ `print-command`.

`pi_deps_answer <answer>` is pure and prints `yes` only for `y`/`yes` in any case, after
trimming surrounding whitespace. Everything else, including empty input, prints `no`.

`pi_deps_prompt` stays thin. It writes the question to stderr, naming the package, the pin,
the target and the exact command, with `[y/N]`. It then reads one line with
`read -r … || :`, so EOF ⇒ empty ⇒ `no`. The TTY tests are `[ -t 0 ]` and `[ -t 2 ]`.
Both are required because the question goes to stderr: a user whose stderr is redirected
never sees it.

## Placement and the F03 interaction  (serves: R2, R10)

The new section is `# ── 6a-pi. pi environment preflight (E35-F04) ──` in `install_one`,
placed **after** §6 (opencode.json) and **before** §6b `write_escalation_arming`. At that
point every `.pi/` file this run writes exists. Guards:

- `agent_selected pi`;
- `[ "${SELF_MODE:-0}" != 1 ]`;
- mode ≠ `skip`, else the single skip line.

### F03 interaction, settled

- `pi install -l` writes only `packages` and never `subagents` (fact 3).
- R9 refuses an unparsable, non-object or BOM'd `.pi/settings.json`. A pre-install file is
  therefore either absent or a strict object. If it was fine for F03 it stays fine after
  the install; if it was `unstamped`, because of a `subagents` key, it stays `unstamped`.
- The verdict cannot flip from the install alone. Even so, R10 re-runs
  `pi_builder_overridden` after **any** install attempt: success, failure or timeout. When
  it holds, R10 calls `mark_unstamped pi`. This is a blunt, monotone backstop against a
  future pi that writes more keys, or a half-written file after a kill.
- Because the section precedes §6b, arming is computed once, from the post-install state.
  It is never written and then recomputed.

The install mutates nothing else the installer owns. `.pi/npm/` and `.pi/settings.json`
are not stamped, not reclaimed and not in `tools/harness-owned-paths.sh` (DO NOT TOUCH).

## Approach notes

- **Ordering inside §6a-pi.**
  1. `python3` present?
  2. Version probe.
  3. Trust and conflict, which need no pi.
  4. `pi list -a` probe, only when the version is OK.
  5. Decision.
  6. Preconditions (R9), checked at the moment of install, not earlier.
  7. Install.
  8. Verify probe.
  9. F03 re-check.
  10. Set `PI_DEPS_FAILED` when mode `install` came from the flag and the outcome is not
      `installed and verified` and not already `pinned`.

  Without `python3`, steps 2–9 are replaced by the skip line. Under the flag `install`,
  the skip line is followed by `install: not attempted: python3 missing` and
  `PI_DEPS_FAILED=1`.
- **The `install:` line is always printed** when the preflight runs (not skipped):
  - `pinned` ⇒ `install: not needed`;
  - `unknown` / `not probed` ⇒ `install: not attempted: <reason>`, with no prompt;
  - `absent` / `mismatch` ⇒ the R8 decision.
- **"Approved but nothing to do".** A status of `pinned` means no prompt and no install.
  Under the flag `install` this is a success.
- **`unknown` backend status under approval** ⇒ `not attempted: backend status unknown`.
  A blind install over an unreadable list cannot be verified either.
- **Upgrades.** The preflight runs on every pi-selected run. Re-running with the pin
  present prints `pinned` and asks nothing.
- **Existing suites.** Report lines are stdout-only. The sandboxed pi suites
  (`test_pi_front.sh`, `test_pi_agents.sh`) have no `pi` on PATH, so they now print
  `not found on PATH` lines on stdout. Run the **full** suite after wiring §6a-pi, with
  `tools/run-tests.sh --jobs $(nproc)`: an exact-stdout comparison elsewhere may need the
  new lines. When it does, adjust the expectation and do not add a skip.
- **Lessons applied.**
  - One predicate per hazard. `pi_install_paths_safe` is the only path guard; do not
    re-check a path in the caller (2026-10-13 builder: equivalent mutants).
  - Whole-string `case` validation for the version grammar, not a line-based `grep`
    (2026-09-25).
  - The shape matrix, hostile-pi table and trust table all land in round 1 (2026-10-14,
    2026-10-16).
