# Integrity-pin the `pi-subagents` install — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and **every row names the mutant it kills**. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives.
>
> **Suite.** A new POSIX `sh` suite, `tests/test_pi_integrity.sh` (PI), with `set -eu` and
> `fail`/`pass`. Reuse E35-F04's sandbox and its `pi` stub
> (`tests/test_pi_preflight.sh:30-260`):
> - the PATH holds no real `pi`;
> - `env -i` with an isolated `HOME`, so the agent dir is `$T/home/.pi/agent`;
> - the `STUB_CTL`/`STUB_LOG` stub.
>
> Factor the stub and sandbox into `tests/lib/pi_stub.sh`, sourced by **both** suites, so
> the two never drift. A stub copied into two suites is the "body and its copy diverge"
> class. **No case runs the real `pi`.** Point `TMPDIR` at a path outside the repo, created
> first.
>
> **Fixture installer (`FXI`).** This implements plan §4. At setup:
> 1. Write a synthetic `pi-subagents` tree of 3 files: `package.json` with
>    `{"name":"pi-subagents","version":"0.78.0"}`, `index.ts`, and `lib/a.js`. Compute its
>    tree digest with the suite's **own** implementation of plan §Tree digest.
> 2. Pack it with `tar -czf` as `package/…`, and compute that tarball's `sha512-` integrity.
> 3. Copy the repo into `$T/fx` (excluding `.git`, `scratchpad`, `node_modules`, `progress`).
> 4. `sed` the two constant lines.
> 5. Assert the diff has exactly 2 changed lines.
>
> `INST` is the unpatched `$SRC/harness-install.sh`; `FXI` is `$T/fx/harness-install.sh`.
>
> **Stub additions, mirroring the empirical baseline (plan §Empirical findings).**
> - `install real` writes a realistic `.pi/npm`: `package.json` with `"pi-subagents": "^0.78.0"`,
>   a v3 `package-lock.json` whose `node_modules/pi-subagents` entry carries the canonical
>   `resolved` and the synthetic integrity, and the synthetic tree.
> - `install tamper` does the same, then appends a byte to `index.ts`.
>
> **Common assertions.**
> - Every **refusal** row runs under `--pi-deps=install` with pi `1.2.0`, trust `trusted`
>   and backend `absent`. The exception is R2 **prior**, which uses `mismatch` on purpose.
>   The row asserts:
>   - the exact `install: not attempted: <reason>` line;
>   - no stub record after the `list -a` record, so no `pi` and hence no `npm` runs (R7);
>   - exit **5**;
>   - `.harness/.escalation-arming` written (the run finished).
> - Every **control** row asserts an `install` record and `installed and verified` (run with
>   `FXI`).
> - Every stdout is checked for no ESC byte.
>
> **Exempt rows.** Rows named `ctrl…`, F04-precedence rows (the reason belongs to an F04
> guard that F04's own mutants pin) and the real-npm rows name no F05 mutant. Every other row
> must name one.
>
> **Mutation protocol (T18).** Apply each named mutant alone. Print the applied diff and
> require it to be non-empty. Run the suite: the named row must red. A survivor gets a new
> row, not a comment.

## Real-npm end-to-end (offline)

`PI::test_real_npm`, skipped with a printed `SKIP` only when `npm` is not on the sandbox PATH.

**Setup.**
- A python `http.server` bound to port 0 serves the synthetic tarball as
  `pi-subagents@0.78.0`, which depends on `dep@1.0.0`, and a clean `dep@1.0.0`. Under
  `/evil/` it also serves a tampered `dep-1.0.0.tgz` whose `postinstall` writes a canary.
- A shim `pi` on PATH implements `list` like the stub, and `install` by running the **real**:
  `npm install pi-subagents@0.78.0 --prefix .pi/npm --legacy-peer-deps`, with
  `npm_config_registry` pointing at the server, a fresh `npm_config_cache`, and an empty
  `npm_config_userconfig`.

**Rows.**
- **(a)** `FXI` and a clean target ⇒ `installed and verified`. The real npm-written lockfile
  and tree satisfy R8 and R9.
- **(b)** a `.pi/npm/yarn.lock` steering `dep` to `/evil/` ⇒ R3 refusal, canary absent, no
  registry request. Without R3, npm would fetch the evil `dep` and the canary would fire
  (fact 6), so this row is live.
- **(c)** a second run of (a) ⇒ `install: not needed`.
- **(d)** `.pi/npm/node_modules` left from (a), with settings changed to `@0.77.0` ⇒ the R2
  refusal.

## Behavioral / end-to-end checks

- The Reviewer runs these standalone: `sh tests/test_pi_integrity.sh` and
  `sh tests/test_pi_preflight.sh`. Then the full suite: `tools/run-tests.sh --jobs $(nproc)`
  with `TMPDIR=/var/tmp/E35-F05-reviewer/`, created first.
- The Reviewer may replay the plan's empirical table against the **built** installer, using
  the plan's local-registry method and a shim `pi` like `PI::test_real_npm`. Each steering
  setup must end with the installer refusing **before** npm runs: the registry log shows no
  request.
- The Reviewer may also run a **read-only** check on this host, which leaves `~/.pi/agent`
  byte-identical (F04 tests.md):
  `sh harness-install.sh --agents=pi --pi-deps=check <scratch-target> </dev/null`.
- **Never** run `--pi-deps=install` with the real `pi`, and never touch `~/.pi/agent`.
