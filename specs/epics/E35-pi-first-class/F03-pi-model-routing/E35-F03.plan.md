# pi model routing — Technical Plan

> Translates `E35-F03.spec.md` into a design. Every decision cites the R-ids it serves.
> Line numbers are at `30fcba3` (`HI:` = `harness-install.sh`) and are only hints. Locate
> code by function name.

## Stack & dependencies

- POSIX `sh` (installer, dispatcher, tests), plus `awk`, `sed`, `grep`, `cmp` and `cksum`.
  This is the existing toolset.
- New dependencies: none. No test runs the real `pi`, a model, or the network. Dispatcher
  cases reuse F02's stub `pi`.

## Resolved questions

| question | decision | why | R |
|---|---|---|---|
| Ladder values | `cheap→low`, `standard→medium`, `reasoning→high`, `frontier→xhigh`. `off`, `minimal` and `max` are never emitted. | This is the `codex_effort_alias` ladder value for value, so the same tier means the same effort on both CLIs. `max` mirrors Codex's never-emitted `ultra`: the harness cannot know whether the pinned model supports it. `off`/`minimal` would make a tier *weaker* than inherit. | R1 |
| Separate `thinking:` key, or a `model:` suffix? | A **separate key**, stamped even when no model is pinned. | `pi-subagents` and `pi -p` both accept `thinking` with no model, and both inherit the session model. With a suffix, a thinking level would need a model, so an unpinned tier could not differentiate `builder-heavy`. That would make pi arm only with pins, unlike Codex. | R1, R4, R8 |
| A pin's own `:<level>` suffix | **Rejected** (warn once, no `model:`). It is not split off as an override. | `pi-subagents` ignores `thinking:` when `model:` already carries a known-level suffix (`applyThinkingSuffix`, `replaceExisting=false`). `pi -p` lets `--thinking` win. Stamping such a pin would run one role at two levels depending on the path, which ADR-0007 forbids. Splitting it off would add a second thinking dial, which E99-F161 rejected for Codex. | R2, R3 |
| Non-level colon suffixes (`:free`, `-v1:0`, `:thinking`, `:HIGH`) | Accepted verbatim, as part of the id. | pi's strict `--model` parse treats them as part of the id, and they are real ids. The level match is exact and case-sensitive, like pi's `isValidThinkingLevel`. | R2 |
| Echo a rejected value in the warning? | Only when it passed the length and charset rules. | A config value can carry ESC or other control bytes, so echoing it verbatim lets a config write to the operator's terminal. | R3 |
| Dispatcher strictness | The charset check stays. Add a 256-byte cap, a leading-`-` reject, a suffix-vs-`thinking:` conflict reject, and a duplicate-key reject. Do **not** require the `provider/id` shape. | The dispatcher guards argv safety and B/C agreement. `pi-subagents` loads a hand-edited `model: sonnet`, so rejecting it in C alone would itself be drift. A repeated key is last-wins in `pi-subagents` and first-wins in `fm_get`, so it is drift. | R6 |
| `--self` | pi resolves from the source seed config. There is no harvest. | The seed is all-`inherit` by contract, so the committed `.pi/agents/*.md` are unchanged and `.escalation-arming` gains an honest `pi=neither`. pi model ids are `provider/id` and cannot be harvested from the claude shims, so a harvest would invent values. | R12 |
| `builder-heavy` description string | Unchanged. | It is compared byte-for-byte across every front end's glue. Rewording it would break R10. | R10 |

### Role file, exact frontmatter order (serves: R4)

```
---
name: <role>
description: <codex_personas description>
model: <resolve_model pi role>          ← only when non-empty
thinking: <resolve_pi_thinking role>    ← only when non-empty
tools: <pi_tools translation>
systemPromptMode: append
inheritProjectContext: true
inheritSkills: false
allowNestedSubagents: true              ← only for Task-bearing roles (F02)
---
<F02 body, unchanged>
```

Values are written unquoted on one line. The R2 charset excludes quotes, `#`, whitespace
and `$`, so the line is safe for `pi-subagents`'s `^([\w-]+):\s*(.*)$` parser and for the
dispatcher's `fm_get`. The F02 body rule "no `$`" is untouched.

### Pin grammar — `pi_pin_verdict` (serves: R2, R3)

The checks run in this order, and the first failure is the verdict:

1. **`length`** — the value is longer than 256 bytes. Measure bytes: run `${#v}` under
   `LC_ALL=C`, or equivalent.
2. **`charset`** — any byte outside `A-Za-z0-9._:/@-`. Use
   `case "$v" in *[!A-Za-z0-9._:/@-]*)`. This is the **same bracket expression** as
   `tools/pi-dispatch.sh`'s model check, and the plan requires the two to stay textually
   equal.
3. **`form`** — any of the following:
   - no `/`;
   - the provider (text before the first `/`) is not `[A-Za-z0-9][A-Za-z0-9._-]*`;
   - the id (text after the first `/`) is empty, begins or ends with `/` or `:`, or contains
     `//`.
4. **`suffix`** — the text after the last `:` is exactly one of `off minimal low medium high
   xhigh max`.
5. Otherwise **`ok`**.

An empty pin never reaches the verdict. `resolve_model` treats it as absent (with umbrella
fallback), exactly as today. The literal `inherit` is handled by the existing check that
runs before the new arm.

Warning text: `⚠️  models.pin.pi.<tier> <reason> — ignored, no model: written to
.pi/agents (thinking still follows the tier)`. The `<reason>` for each verdict:

| verdict | reason text | value echoed? |
|---|---|---|
| `length` | `is longer than 256 bytes` | no |
| `charset` | `has characters outside [A-Za-z0-9._:/@-]` | no |
| `form` | `= '<v>' is not in provider/id form` | yes |
| `suffix` | `= '<v>' ends in a :<thinking> suffix; thinking comes from the tier ladder` | yes |

- two `model:` lines → 3;

Config-shape rows, which exercise lookup rather than grammar:

- `  # pin.pi.cheap: "a/b"` (commented) → never resolves.

- `pin.pi.turbo: "a/b"` (unknown tier key) → no effect.

## Approach notes

- **Sequencing.** Build the pure functions and their in-process table test first. Then do
  the emitter and the dispatcher. Then arming. Do `--self` last: run
  `sh harness-install.sh --self` and commit the two regenerated root files. Run
  `sh tests/test_pi_front.sh`, `tests/test_escalation.sh`, `tests/test_models_cascade.sh`,
  `tests/test_codex_native.sh`, `tests/test_self_mode.sh` and `tests/test_self_drift.sh`
  after each step. They are the R10 regression net.
- **Warn-once keys.** `resolve_model` and `resolve_pi_thinking` run in `$(…)` subshells and
  are called again by `models_any`/`escalation_verdict`. The `MODEL_DIAG` file dedups.
  Use keys that are per tier for the pin (`pipin:<tier>`), so N roles on one tier warn once.
- **Mutation-checked guards (lesson: prove the guard, not some other omission).** The test
  copies the source tree **once** into a fixture. Variant installers then sit as sibling
  files in that tree (for example `harness-install.m1.sh`), so `SRC` resolves to the same
  copy. Each variant must contain its marker exactly once (`grep -c` = 1).
  - **M1** — neutralize the `pi` arm's verdict check. Hostile row 25 then reaches `model:`.
  - **M2** — corrupt `pi_thinking_alias`'s `reasoning` value to `bogus_zz`. Expect a
    warning and no `thinking:`.
  - **M2b** — M2 with the `resolve_pi_thinking` guard also neutralized. `thinking: bogus_zz`
    reaches the file.
  - **M3** — drop the `pi` second-axis block from `escalation_verdict`. The no-pin
    standard/reasoning cell flips from `raise` to `neither`.
  - **M4** — remove the dispatcher's duplicate-key check, in a copy of `pi-dispatch.sh` in a
    fixture `.harness/tools/`. The duplicate row reaches the stub.
  - **M5** — remove the suffix-conflict check. Row 20-with-thinking reaches the stub.
- **Test runtime.** Run the pin-grammar table **in-process**: extract `pi_pin_verdict` with
  `awk '/^pi_pin_verdict\(\) \{/,/^\}/'` and run it under `sh -c`. No install per row, which
  is why the function must be self-contained. End-to-end rows ride four tiers per install
  (cheap, standard, reasoning and frontier pins, each with a role on that tier), so the 23
  single-line rejected rows (rows 11–33) need six installs, which run in parallel. Run independent install cells as background jobs
  and `wait` (collect each cell's verdict in a file, then fail on any). Reuse the
  F02 `inst` helper, the stub `pi` and the sandbox `PATH`.
- **Upgrade path (R5)** needs no migration code. An F02-era role file equals its F02 stamp,
  so `install_pi_unit`'s "live == stamp" branch already rewrites it. The test only proves it.
- **`--self` (R12).** No harvest. In self mode `resolve_model pi` falls through to
  `$H/harness.config.yaml` (the copied seed), which is all-`inherit`, so the emitted bytes
  are unchanged. `.escalation-arming` becomes:

  ```
  blocked
  claude=raise
  codex=neither
  opencode=neither
  pi=neither
  ```
