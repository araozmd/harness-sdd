# pi model routing — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any R-id lacks a passing test.
>
> The cases go into two existing POSIX `sh` suites, each with `set -eu` and the
> `fail`/`pass` helpers:
> - `tests/test_model_routing.sh` (MR) holds the resolver, verdict, regression and config
>   cases. It uses its `mk`/`set_tier`/`set_pin`/`run`/`run_err` helpers.
> - `tests/test_pi_agents.sh` (PA) holds the role-file, dispatcher, arming and `--self`
>   cases. It uses F02's `inst` helper, the sandbox `PATH` and the stub `pi`, which logs
>   argv NUL-separated to `$STUB_LOG/argv`.
>
> No case runs the real `pi`, a model, or the network.
>
> **The hostile-pin table** is the plan's table (rows 1–35, plus the dispatcher-only rows
> and the config-shape rows). Each suite holds it **once**, as a here-doc of
> `row-id<TAB>yaml-rhs<TAB>value-read<TAB>installer-verdict<TAB>disp-no-thinking<TAB>disp-with-thinking`.
> - The installer cases write the `yaml-rhs` column into the config.
> - The grammar and dispatcher cases use the `value-read` column.
> - A `—` in a dispatcher column means the row is skipped there.
> Every table-driven case iterates that here-doc. No case hard-codes a row a second time.
> Bytes that a here-doc cannot hold literally are written as `printf` escapes in both value
> fields and expanded with `printf '%b'` when a row is read: the UTF-8 byte (row 31), ESC
> (row 32), TAB (row 33) and the newline (row 35).
>
> **Runtime.** The grammar runs in-process: `pi_pin_verdict` is extracted with awk. E2E
> install cells run as background jobs and are joined with `wait`, and mutants share one
> copied source tree. Target: each suite grows by no more than 60 s of wall-clock.

## Behavioral / end-to-end checks

The Reviewer exercises the following by hand in a scratch target:

1. Run `--agents=pi` with `builder: standard`, `builder-heavy: reasoning`, and
   `pin.pi.reasoning: "anthropic/claude-opus-4"`.
2. Read `.pi/agents/builder-heavy.md`.
3. Run `.harness/tools/pi-dispatch.sh builder-heavy <task>` with the stub `pi`. The argv
   must carry `--model anthropic/claude-opus-4 --thinking high`.
4. Read `.harness/.escalation-arming`. It must say `armed` and `pi=raise`.

## Non-functional checks

- `sh -n harness-install.sh tools/pi-dispatch.sh` must be clean. Run `shellcheck` where it
  is available; there must be no new warnings.
- Both suites must pass under `dash` and `bash --posix`.
