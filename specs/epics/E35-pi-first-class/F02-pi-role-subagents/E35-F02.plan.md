# pi role sub-agents — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.
> Line numbers are from v0.92.0 (HI = `harness-install.sh`). Re-locate each site by its
> symbol before editing, because the numbers drift.

## Stack & dependencies

- POSIX `sh` (`harness-install.sh`, `tools/harness-owned-paths.sh`, the new
  `tools/pi-dispatch.sh`). Suites are POSIX `sh` under `tests/`, run by
  `sh tools/run-tests.sh` (under dash where available). `self_reconcile` stays Python.
- New dependencies: none. **No test runs the real `pi`**, a model or the network. The
  dispatcher is exercised only against a stub `pi` placed first on a sandbox PATH. That
  sandbox PATH strips every directory holding a real `pi`, reusing the `SANDBOX_PATH`
  construction from `tests/test_pi_front.sh`.

## Resolved questions (from the brief)

1. **`systemPromptMode: append`** (R1).
   - With the default `replace`, the child loses pi's base prompt: the tool documentation
     and guidelines. All it would have left is a pointer body a few lines long, which
     tells it to "use the read tool" without the tool's documentation.
   - `append` is also what option C does natively (`--append-system-prompt`). So the B
     child and the C child assemble the same prompt: pi base, plus `AGENTS.md` project
     context, plus the role pointer. That is the ADR-0007 "B and C cannot drift"
     consequence, made concrete.
2. **`inheritProjectContext: true`, `inheritSkills: false`** (R1, R7).
   - Project context (`AGENTS.md`) is how every harness role finds `.harness/`.
   - The skills catalog is withheld. The `/sdd-*` workflows are the Orchestrator's entry
     points. A Builder or Reviewer that can see and run `sdd-next` can re-enter the loop
     from inside a role, which bypasses the gates.
   - The dispatcher mirrors this with `--no-skills`, and loads context files by default
     (it passes no `-nc`).
3. **Roles = `codex_personas`** (R1). That is the seven `ag_personas` roles, plus
   `pr-fixer` while `pr_loop.enabled`. Codex has the same set, and it is the role set the
   Claude shims cover too. The descriptions come from `ag_personas`/`PR_FIXER_DESC`
   (single-line, no leading quote). That fits `pi-subagents`' line-based parser.
4. **Tool translation = one table plus one function** (R3). See "Tool tables" below.
   - `Task` maps to no pi tool. It becomes `allowNestedSubagents: true`, not `tools:
     subagent`.
   - Reason: the allowlist must stay valid for option C. `pi --tools subagent` names an
     extension tool that may not be loaded. Under C, nested delegation runs
     `pi-dispatch.sh` through `bash`, which both Task-bearing roles (orchestrator,
     architect) already have.
   - The depth default (2) covers session → architect → doc-critic, so no
     `maxSubagentDepth` is emitted. That holds because **on pi the Orchestrator runs in the
     main session** (the session that runs `/sdd-next`) and is never itself delegated;
     the Orchestrator prose says so (R12). `.pi/agents/orchestrator.md` ships for role-set
     parity with Codex and for an operator who starts a pi session as that role.
5. **Dispatcher interface** (R7, R8): `tools/pi-dispatch.sh <role> <task-file>`. It reads
   the allowlist and body from the generated role file, which is the single source.
   - The body goes through a temp **file**, never inline text. `--append-system-prompt`
     reads a path when the path exists, so passing a file is unambiguous.
   - The task is inlined into one argv element behind a fixed preamble. That way the
     message never starts with `-` or `@`.
   - Test strategy: a stub `pi` that records argv, cwd and the appended file, prints
     canned stdout, and exits `$STUB_RC`.
6. **`--self` plus the drift gate** (R10, R11). `--self` accepts pi, and the source default
   becomes `claude,codex,opencode,pi`. The existing `self_reconcile` gives pristine,
   symlink and wrong-type protection; only its allow-list grows. `test_self_drift.sh`
   purges `.pi/` in its fixtures, so committed `.pi` files are compared, not inherited
   (lesson 2026-09-05). It also lists every committed `.pi` file in `_must`.
7. **Prose** (R12). One pi paragraph in `agents/orchestrator.md`, after the Antigravity
   paragraph. One parenthetical line in the `$CMDDIR/sdd-next.md` heredoc, after the
   Antigravity line at HI:5358.
8. **Advertise / other keys.** These are not emitted. `advertise` is opt-in catalog noise;
   the Orchestrator prose names roles explicitly. Project role files deliberately override
   `pi-subagents`' builtin `scout` and `reviewer`. That is the point: the harness roles win
   in a harness project.

### Role file, exact bytes (installed form)

`<desc>` is the role's description field from `all_codex_personas`. `<tools>` is
`pi_tools "$(claude_role_tools <role>)"`. The `allowNestedSubagents` line, and the
final paragraph, appear only when the role's Claude list contains `Task`, which today
means orchestrator and architect.

```
---
name: <role>
description: <desc>
tools: <tools>
systemPromptMode: append
inheritProjectContext: true
inheritSkills: false
allowNestedSubagents: true
---

You are the harness **<role>** role, running in an isolated pi child context.

Read `.harness/agents/<role>.md` with the read tool and follow it exactly; resolve every relative path it mentions against `.harness/`. Run `./.harness/init.sh` before any work and halt on a non-zero exit. Hand off through `.harness/progress/` files, never by forwarding chat history.

To delegate a role, start it in a fresh context: use the `subagent` tool when it is available, otherwise write the task to a file under `.harness/progress/` and run `.harness/tools/pi-dispatch.sh <role> <task-file>`; if neither works, stop and report the limitation and the handoff file path. Never simulate another role in this context.
```

Constraints:

- **No `$` anywhere** (R4). A future pi template expansion can never bite.
- **No `---` line in the body.** The dispatcher's body extraction ends the frontmatter at
  the first closing `---`.
- **`--self` maps cleanly.** The existing `self_transform` rewrites "mentions against
  `` `.harness/` ``" to "mentions against the repository root" and strips every other
  `.harness/`. The source copy therefore reads `` `agents/<role>.md` ``,
  `` `./init.sh` ``, `` `progress/` `` and `` `tools/pi-dispatch.sh` ``. Keep the phrase
  "mentions against `` `.harness/` ``" byte-exact, or that rule will not fire.

### Tool tables (R3)

`claude_role_tools <role>` is the **only** role→Claude-tools table. It is a new function,
defined *outside* the Claude-gated block, because pi needs it when `claude` is not
selected. Each existing `emit_agent <role> "<literal>"` call at HI:5297-5326 becomes
`emit_agent <role> "$(claude_role_tools <role>)"`, which yields byte-identical shims:

| role | Claude list (verbatim, order kept) | pi `tools:` | nested |
|---|---|---|---|
| orchestrator | `Read, Bash, Edit, Grep, Glob, Task` | `read, bash, edit, grep, find, ls` | yes |
| architect | `Read, Write, Edit, Grep, Glob, Bash, Task` | `read, bash, edit, write, grep, find, ls` | yes |
| builder | `Read, Write, Edit, Bash, Grep, Glob` | `read, bash, edit, write, grep, find, ls` | no |
| builder-heavy | `Read, Write, Edit, Bash, Grep, Glob` | `read, bash, edit, write, grep, find, ls` | no |
| reviewer | `Read, Bash, Grep, Glob, Edit` | `read, bash, edit, grep, find, ls` | no |
| scout | `Read, Grep, Glob, Bash` | `read, bash, grep, find, ls` | no |
| doc-critic | `Read, Grep, Glob, Write` | `read, write, grep, find, ls` | no |
| pr-fixer | `Read, Edit, Bash, Grep, Glob` | `read, bash, edit, grep, find, ls` | no |

`claude_role_tools` on an unknown role prints nothing and returns 1.

`pi_tools <claude-list>` is the **only** translation:

- Split on `,`, trim spaces, and map each token: `Read→read`, `Bash→bash`, `Edit→edit`,
  `Write→write`, `Grep→grep`, `Glob→find,ls`, `Task→∅`.
- Emit the union in canonical order `read, bash, edit, write, grep, find, ls`, joined
  with `, `.
- Any other token (including an empty one): print `pi_tools: unknown Claude tool '<tok>'`
  on stderr, nothing on stdout, and return 1.

**Fail before the first write.** `pi_tools_preflight` runs in the §5f-pi block before any
pi write, in the main shell, never in a pipeline subshell. It translates every role in
`all_codex_personas`, and on the first failure it calls
`die "pi role tools: <message>"`.

`pi_role_nested <claude-list>` returns 0 iff a trimmed token equals `Task`. It sits beside
`pi_tools` in the same section, as the table's `Task` row.

## Generalized pi unit helpers (R5, R6). Generalize, never duplicate

F01 already has the right predicate (`pi_node_unsafe <path> <d|f>`) and the right
algorithm. F02 parameterizes the F01 functions by `<kind>`, and must **not** copy them:

```
pi_unit_live_unsafe  <kind> <name>  = pi_node_unsafe $TARGET/.pi d || pi_node_unsafe $TARGET/.pi/<kind> d || pi_node_unsafe $TARGET/.pi/<kind>/<name>.md f
pi_unit_stamp_unsafe <kind> <name>  = pi_node_unsafe $H/.pi-<kind> d || pi_node_unsafe $H/.pi-<kind>/<name>.md f
discard_pi_unit_stamp <kind> <name>
gen_pi_unit   <kind> <name> <dest>  = case kind: prompts → gen_pi_prompt; agents → gen_pi_agent
install_pi_unit  <kind> <name>      = F01 install_pi_prompt's algorithm, verbatim, kind-parameterized
reclaim_pi_units <kind> <names> <label> = F01 reclaim_pi_prompts's algorithm, verbatim, kind-parameterized
```

- **Messages.** Keep F01's four warnings **byte-identical for `prompts`**. Take the nouns
  from the kind:
  - `prompts`: "pi prompt template" / "prompt template";
  - `agents`: "pi role file" / "pi role file".

  So `tests/test_pi_front.sh` passes unchanged (except its R12 doc assertion, below).
- **F01 call sites.** §5d-pi, §7 and §7b call the `prompts` kind. The F01 names
  (`install_pi_prompt`, `reclaim_pi_prompts`, `pi_prompt_*`) are removed. Leaving them as
  wrappers is not permitted: two names for one rule is how a later edit forks them.
- **Prune order** in `reclaim_pi_units`:
  - `$H/.pi-<kind>` (if not unsafe);
  - `.pi/<kind>` (if neither `.pi` nor `.pi/<kind>` is unsafe);
  - `.pi` (if not unsafe).

  Each is pruned with `rmdir … 2>/dev/null || true`, so a non-empty dir (`.pi/prompts`, `.pi/settings.json`)
  keeps `.pi`.
- **Precedence.** For every unit, the stamp-unsafe check runs **before** the live-unsafe
  check, exactly as in F01.
- **`set -e` hygiene.** Every conditional echo is a plain `if`, and every helper ends
  `return 0`.

## Filesystem shape matrix (R5, R6, R8, R10). The complete contract

Paths that F02 writes, removes, prunes or reads:

| id | path | expected type | written by | removed/pruned by | read by |
|---|---|---|---|---|---|
| L1 | `.pi` | dir | I/G+ (`mkdir -p`) | D/G- (prune) | DISP, SELF |
| L2 | `.pi/agents` | dir | I/G+ | D/G- (prune) | DISP, SELF |
| L3 | `.pi/agents/<role>.md` | regular file | I/G+ | D (every role), G- (`pr-fixer`) | DISP, SELF |
| S1 | `.harness/.pi-agents` | dir | I/G+ | D/G- (prune) | owned-paths |
| S2 | `.harness/.pi-agents/<role>.md` | regular file | I/G+ | D/G- | owned-paths |
| T | the dispatcher's `<task-file>` argument | regular, readable (a symlink to one is accepted: it is operator input, not owned) | — | — | DISP |

The dispatcher writes **nothing** in the repository. Its only write is one `mktemp` file,
removed on every exit path (`trap`).

**Operations:**

- **I**: install. Covers both a fresh install and a re-run.
- **G+**: `pr_loop` flipped false→true, pi selected. Only `pr-fixer` is new.
- **D**: deselect pi (§7).
- **G-**: `pr_loop` flipped true→false, pi selected (§7b). Only `pr-fixer`.
- **SELF**: `--self` in the source repository. `self_reconcile`'s `safe()` covers L1–L3;
  S1 and S2 are not used.
- **DISP**: `tools/pi-dispatch.sh`.

**Shapes per component:**

- **A**: absent.
- **F**: regular file. On L3, split into three sub-shapes:
  - **Fs**: byte-equal to its stamp;
  - **Ff**: byte-equal to the fresh bytes, with no stamp;
  - **Fe**: edited or foreign.
- **Dd**: directory.
- **Sv**: symlink to an existing outside node that holds a **victim**:
  - for L1, a dir holding `agents/<role>.md` (byte-fresh), and a variant holding an
    **empty** `agents/` (the prune victim; lesson 2026-10-13);
  - for L2 and S1, a dir holding a byte-fresh `<role>.md`;
  - for L3 and S2, a byte-fresh file.
- **Sx**: dangling symlink.

On a dir component, **F** is *file-where-dir*. On a file leaf, **Dd** is *dir-where-file*.

**Outcome codes:**

- **W**: leaf and stamp written. Re-install is byte-idempotent.
- **RM**: leaf and stamp removed, empty dirs pruned. An absent leaf is a silent no-op.
- **KD**: leaf, and any victim, left byte-identical. Exactly **one warning per affected
  role** (a directory cell on I affects every role, so 7 or 8 warnings; a leaf cell affects
  one). Stamp dropped, unless the stamp path is unsafe.
- **KD0**: removal only, when nothing (no node, no link) exists at L3: no warning, stamp
  dropped unless the stamp path is unsafe (F01 `reclaim_pi_prompts` semantics).
- **KK**: leaf, stamp and victim all left byte-identical. Exactly one warning per affected
  role.
- **UC**: SELF: "left unchanged and unclaimed" warning; the path is absent from
  `.claude/.glue-manifest`; the victim is unchanged.
- **E3**: dispatcher exits 3, prints nothing on stdout, and never invokes the stub.
- **OK**: dispatcher runs the stub.

| component | shape | I / G+ | D / G- | SELF | DISP |
|---|---|---|---|---|---|
| L1 | A | W | RM (no-op) | W (claimed) | E3 |
| L1 | Dd | (see leaf rows) | (see leaf rows) | (see leaf rows) | (see leaf rows) |
| L1 | F | KD every role; no `mkdir` abort | KD0 every role (nothing can exist at L3); the file survives | UC | E3 |
| L1 | Sv (both victims) | KD every role; nothing written through | KD for roles whose victim leaf exists, KD0 for the rest; victim file **and** the empty `agents/` both survive | UC | E3 |
| L1 | Sx | KD every role; the link stays dangling, no target is created | KD0 every role | UC | E3 |
| L2 | A (`.pi` exists, e.g. `.pi/prompts/` from a 0.92.0 install) | W; `.pi/prompts/` untouched | KD0 (no-op); `.pi` kept because `.pi/prompts/` remains | W | E3 |
| L2 | F | KD every role | KD0 every role; the file survives | UC | E3 |
| L2 | Sv | KD every role | KD for roles whose victim leaf exists, KD0 for the rest; the victim survives | UC | E3 |
| L2 | Sx | KD every role | KD0 every role | UC | E3 |
| L3 | A | W | KD0 (stamp dropped) | W | E3 |
| L3 | Fs | W (overwrite) | RM | W (pristine by manifest) | OK |
| L3 | Ff | W | RM | W (identical) | OK |
| L3 | Fe | KD "foreign or edited" | KD "no matching stamp" | UC | OK (the dispatcher is not an ownership check) |
| L3 | Dd | KD | KD | UC | E3 |
| L3 | Sv | KD; the victim is unchanged | KD; the victim survives | UC | E3 |
| L3 | Sx | KD | KD | UC | E3 |
| S1 | A | W (created) | RM | — | — |
| S1 | F | KK every role (one warning each); **no live file written** | KK; **no live file removed** | — | — |
| S1 | Sv | KK; nothing stamped through | KK | — | — |
| S1 | Sx | KK | KK | — | — |
| S2 | Dd | KK | KK | — | — |
| S2 | Sv | KK; the victim is unchanged | KK | — | — |
| S2 | Sx | KK | KK | — | — |
| T | A / Dd / Sx / unreadable | — | — | — | exit 2 (unreadable is not tested: `-r` is always true under root) |

Every installer cell above also carries these four invariants:

- the exit status is 0;
- a **canary role** that has no hostile shape is still processed normally in the same
  run (written on I, removed on D);
- `.pi/prompts/` and `.pi/settings.json` stay byte-identical;
- no path outside L1–L3, S1, S2 and the F01 prompt paths changes. Check this with a
  `find`/`cksum` snapshot diff of the target, plus the victim directory.

## Dispatcher: `tools/pi-dispatch.sh` (R7, R8)

```
usage: pi-dispatch.sh <role> <task-file>
```

1. **Arguments.** `$# -ne 2` → exit 2. Validate `<role>` against the whole string:
   `case "$1" in ''|[!a-z]*|*[!a-z0-9-]*) exit 2;; esac`. A glob class also matches a
   newline (lesson 2026-09-25).
2. **Task file.** `[ -f "$2" ] && [ -r "$2" ]` must hold, else exit 2. Resolve it to an
   absolute path **before** any `cd`.
3. **Root.** Set `H="$(CDPATH= cd -- "$(dirname -- "$0")/.." && pwd -P)"`, then use the
   `harness-report.sh` idiom: `case "$H" in */.harness) PROJ="${H%/*}";; *) PROJ="$H";; esac`.
4. **Role file.** `R="$PROJ/.pi/agents/$role.md"`. Exit 3 when any of these holds:
   - `.pi` or `.pi/agents` is a symlink or exists as a non-dir;
   - `R` is a symlink, is absent, or is not regular.

   This is the same rule as `pi_node_unsafe`, re-stated locally in four lines, because a
   `tools/` script cannot source the installer. Pin it with a comment naming
   `pi_node_unsafe`.
5. **Frontmatter.** Line 1 must be `---`. The frontmatter ends at the next line that is
   exactly `---`; no closing line → exit 3. Inside the frontmatter, take the first
   `^tools: ` value, `model: ` value and `thinking: ` value.
   - `tools` with all spaces removed must be non-empty and match
     `case … in *[!A-Za-z0-9_:,.*/+-]*) exit 3`. Anything else → exit 3.
   - `model`, when present, must be non-empty and within `[A-Za-z0-9._:/@-]`.
   - `thinking`, when present, must be one of `off|minimal|low|medium|high|xhigh|max`.
6. **Body.** Write the lines after the closing `---` to `mktemp`. Remove the file with
   `trap 'rm -f "$_tmp"' EXIT INT TERM`.
7. **pi on PATH.** `command -v pi` must succeed, else exit 127.
8. **Run.** From `$PROJ`, run:

   ```
   cd "$PROJ" && pi -p -a --no-session --no-skills [--model M] [--thinking T] --tools "$tools" --append-system-prompt "$_tmp" "$msg"
   ```

   `msg` is built as `printf 'You are the harness %s role (dispatched by pi-dispatch.sh). Your task follows.\n\n%s' "$role" "$(cat "$task")"`.
   Do **not** `exec`, so the trap can still remove the temp file. Capture `rc=$?` with the
   `set -e`-safe idiom (`pi … || rc=$?`). Exit `$rc`.
**Check order is the contract** (R8): steps 1–2 (exit 2) before step 4–5 (exit 3) before
   step 7 (exit 127). So a bad role file with no `pi` on PATH exits 3.
9. **Output.** Every diagnostic goes to stderr, prefixed `pi-dispatch: `. stdout carries
   only pi's stdout.

Header comment: usage, exit codes (0/pi rc, 2, 3, 127), the single-source rule (the
allowlist and body come from the generated role file), and "never reads or writes
`~/.pi/agent`".

## Approach notes

- **One iteration source per surface.** Install iterates `codex_personas`. Deselect
  iterates `all_codex_personas`. Gate-off is exactly `pr-fixer`. This mirrors §5f/§7 for
  Codex.
- **Description lookup inside `gen_pi_agent`.** Use
  `all_codex_personas | awk -F'\t' -v r="$1" '$1==r{print $2; exit}'`, so install and
  both removal paths compute identical bytes from a role name alone.
- **Matrix test performance.** Leaf cells (L3, S2) are per-role, so one target hosts up to
  eight cells at once, with the remaining roles as canaries. Directory cells (L1, L2, S1)
  need one target per cell per operation. Budget about 45 installer runs at ~1.6s each,
  keeping the suite under ~90s.
