# pi role sub-agents — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E35-F02:R1 … E35-F02:R12`.

## Context

E35-F01 made `pi` a selectable front end with `/sdd-*` commands, but pi core has no
sub-agents. On pi the Orchestrator → Architect → Builder → Reviewer loop therefore runs in
one context, and the independent-Reviewer gate is lost. ADR-0007 fixed the design:

- **Option B (primary).** Generated `.pi/agents/<role>.md` files in the format of the
  community `pi-subagents` package, which registers a `subagent` tool.
- **Option C (always available).** A shell dispatcher, `tools/pi-dispatch.sh`, that runs
  one role as a separate `pi -p` process. The harness never *requires* B.

This feature ships both, plus the Orchestrator prose that picks between them, `--self`
support for pi (so this repository commits its own `.pi/agents` and `.pi/prompts`), and the
drift gate over them. Model and `thinking` stamping is E35-F03. Installing the pinned
package is E35-F04.

Verified facts this spec relies on (pi 1.2.0 docs; `pi-subagents` 0.78.0 docs and
`src/agents/frontmatter.ts`):

- `pi-subagents` discovers project agents at `.pi/agents/**/*.md`, only when the project
  is trusted.
  - A file without `name` or `description` is silently skipped.
  - A project agent overrides a same-name builtin. The package ships builtin `scout` and
    `reviewer`.
- Its frontmatter parser is line-based: `key: value` on one line, and surrounding quotes
  are stripped but not unescaped. A one-line unquoted scalar is the only safe shape.
- `tools:` is a strict allowlist of tool names. pi's builtin tool names are `read`, `bash`,
  `edit`, `write`, `grep`, `find` and `ls`.
- Nested delegation needs `tools: subagent` or `allowNestedSubagents: true`. The default
  depth cap is 2.
- `systemPromptMode` defaults to `replace`, which drops pi's base prompt (tool
  documentation and guidelines). `append` keeps it.
- `inheritProjectContext: true` keeps `AGENTS.md`. `inheritSkills` controls whether the
  child sees the skills catalog.
- `pi -p` exits non-zero on an error, aborted or length stop. The relevant flags:
  - `-a` trusts project resources for that process.
  - `--tools <csv>` replaces the default tool set.
  - `--append-system-prompt <text|path>` appends text, or the contents of an existing file.
  - `--no-skills` disables skill discovery.
  - `--no-session` keeps the session in memory only.

### Why `complexity: complex`

Three of `agents/architect.md`'s stated bases hold:

1. **The feature is at the size budget.** It has exactly 12 R-ids against
   `change_size.max_requirements: 12`. Model stamping (F03) and package install (F04) are
   already split out.
2. **It contains a defect class the harness has already paid for.** E35-F01 took 12
   review rounds because hostile filesystem shapes were found one round at a time
   (`progress/lessons.md`, 2026-10-14). This spec enumerates the full shape matrix up front
   (plan § "Filesystem shape matrix").
3. **It contains a byte contract compared in more than one place.** The role-file bytes
   are compared at install, at deselect, at pr-loop gate-off and by `--self`
   reconciliation.

**Change-size note.** Production lines are expected well under `advise_lines`. The
touched-file count will pass `advise_files: 25`, though, because `--self` regenerates
about 20 committed glue files (the `.pi/agents/*.md` and `.pi/prompts/*.md` files, three
`sdd-next` copies, and `.claude/.glue-manifest`). Those are generated outputs, not hand
edits. It stays under `escalate_files: 50`, and no split is warranted: an emitter without
its committed output reds the drift gate (R11).

## Business rules

- **One canonical body.** A role file is a thin pointer to `agents/<role>.md` (ADR-0004).
  It never inlines the role definition. The dispatcher sends that same pointer body, so the
  B and C paths cannot drift (ADR-0007).
- **One role set.** pi gets the same role set as Codex (`codex_personas`):
  - orchestrator, architect, builder, builder-heavy, reviewer, scout and doc-critic;
  - `pr-fixer` while `pr_loop.enabled` is true.
- **One tool table.** Each role's pi allowlist is a translation of its Claude Code tool list.
  The role→Claude-tools table and the Claude→pi translation are each defined exactly once.
  Read-only roles get no `edit` or `write`.
- **Pristine-only ownership, with the full shape matrix.** The installer overwrites or
  removes a role file only when it is provably pristine (byte-equal to its stamp or to the
  fresh bytes), and only when every component of its live path and stamp path has the
  expected node type. Anything else is left unchanged, with a warning, and the install
  never aborts. The F01 predicate `pi_node_unsafe` is reused, not duplicated.
- **No model or thinking keys in F02.** Role files carry no `model:` or `thinking:` line,
  so every role inherits the session's model. The dispatcher already honors those keys
  when present, so F03 only has to stamp them.
- **The other front ends do not change.** Claude, Codex, OpenCode and Antigravity glue is
  byte-identical, with two exceptions: the one appended pi sentence in the shared
  `sdd-next` body, and the operator-facing text that lists front ends.
- **Never touch `~/.pi/agent`** or `.pi/settings.json`. Every artifact is repository-local.

## Architecture alignment

`specs/architecture.md` is absent in this repository. The ADR set under `specs/adr/` is
present, so citations are required. This is a single-namespace project, so bare ids are
used.

- ADR-0007 — pi role sub-agents: B is implemented as the generated `.pi/agents/<role>.md`
  files, and C as `tools/pi-dispatch.sh`. The Orchestrator prose uses `subagent` when it is
  available, otherwise the dispatcher, so B is never required. The dispatcher reads its
  allowlist and body from the generated role file, so B and C share one source.
  - **Staged, not divergent:** ADR-0007 §1 says role files carry the resolved `model` and
    `thinking`. F02 emits neither, so every role inherits; E35-F03 adds the stamps. The
    dispatcher already forwards both keys (R7), so F03 changes only the emitter.
- ADR-0004 — resolved body via pointer stubs: each role file's body points at
  `.harness/agents/<role>.md`, resolved to `agents/<role>.md` in the source layout by the
  existing `self_transform`. The body is never inlined.
- ADR-0005 — source-only surfaces are emitted only by `--self`: `--self` now accepts `pi`.
  `.pi/prompts/sdd-triage.md` exists only in the source repository, via `--self`, never in
  a target.
- ADR-0003 — one shared skill unit per command: unchanged membership. `--self` with pi
  writes the F01 `.pi/prompts` pointers into this repository; they are not a second body.
  The one pi sentence added to the `sdd-next` body lands in the single shared body.
- ADR-0002 — builder-heavy is a tier: `builder-heavy` gets exactly `builder`'s tool list
  and body shape, so the role files differ only by name and description. pi stays excluded
  from `.harness/.escalation-arming` (E35-F01 R11) until F03.

## Acceptance criteria (EARS)

- **R1** — When `pi` is selected, the installer shall write one `.pi/agents/<role>.md`
  for each role in `codex_personas` (`pr-fixer` only while `pr_loop.enabled` is true), and
  no other role file. Each file's frontmatter shall hold exactly these lines, in this
  order:
  - `name: <role>`
  - `description: <the role's codex_personas description>`
  - `tools: <R3 translation>`
  - `systemPromptMode: append`
  - `inheritProjectContext: true`
  - `inheritSkills: false`
  - `allowNestedSubagents: true`, only for a role whose Claude tool list contains `Task`

  It shall carry no `model:` or `thinking:` line. A re-install shall be byte-idempotent.
- **R2** — While `pi` is not selected and was not previously selected, the installer shall
  create no `.pi/agents/` path and no `.harness/.pi-agents/` ledger.
- **R3** — The installer shall derive every role's Claude Code `tools:` value and every
  role's pi `tools:` value from one role→Claude-tools table, and shall produce the pi value
  with one translation function. The table: `Read→read`, `Bash→bash`, `Edit→edit`,
  `Write→write`, `Grep→grep`, `Glob→find, ls`, and `Task→`(no pi tool). The output is in
  the canonical order `read, bash, edit, write, grep, find, ls`, with duplicates removed.
  The translation shall exit non-zero and print nothing on stdout for an unknown token, and
  the install shall then fail with a message naming the token. The generated `.claude/agents/*.md`
  shims shall stay byte-identical.
- **R4** — Each `.pi/agents/<role>.md` body shall:
  - point at `.harness/agents/<role>.md` with the read tool;
  - require `./.harness/init.sh` first, halting on a non-zero exit;
  - require hand-offs through `.harness/progress/`.

  For a role carrying `allowNestedSubagents: true`, and only for such a role, the body
  shall also give the delegation rule: the `subagent` tool when available, otherwise
  `.harness/tools/pi-dispatch.sh <role> <task-file>`, otherwise stop and report. The body
  shall contain no frontmatter delimiter and no `$`.
- **R5** — If a `.pi/agents/<role>.md` matches neither its last-written stamp in
  `.harness/.pi-agents/` nor the freshly generated bytes, or if any component of its live
  path or stamp path is a symlink (live or dangling) or exists as the wrong node type, then
  the installer shall:
  - leave the role file and every symlink target unchanged;
  - print exactly one warning per affected role, naming the path;
  - continue the install with exit status 0.

  An unsafe stamp path leaves the stamp unchanged too. A foreign or edited file, or an
  unsafe live path, drops the stamp unless the stamp path is itself unsafe. This holds for
  every cell of the plan's shape matrix, on install and on pr-loop gate-on. Otherwise the
  installer shall write the file and its stamp.
- **R6** — When `pi` is deselected, the installer shall remove every proven-pristine
  `.pi/agents/<role>.md` (all roles, `pr-fixer` included) with its stamp. When
  `pr_loop.enabled` turns false while `pi` stays selected, it shall do the same for
  `pr-fixer` only. Every R5 refusal rule shall hold on these removal paths for every
  matrix cell. A role with nothing at its live path is skipped without a warning, and
  its stamp is dropped unless the stamp path is unsafe. Pruning:
  - `.pi/agents/`, `.harness/.pi-agents/` and `.pi/` are pruned only when empty and safe;
  - nothing is deleted, written or pruned through a symlink;
  - `.pi/prompts/` and `.pi/settings.json` are never touched.
- **R7** — When `tools/pi-dispatch.sh <role> <task-file>` runs with valid inputs, it shall
  run `pi` from the project root (the parent of `.harness/` when installed, else the
  repository root) with exactly these arguments:

  ```
  -p -a --no-session --no-skills [--model <m>] [--thinking <t>] --tools <tools> --append-system-prompt <file> <message>
  ```

  - `<tools>` is the role file's `tools:` value with spaces removed.
  - `--model` and `--thinking` are passed only when the role file carries those keys.
  - `<file>` holds exactly the role file's body after the closing `---`.
  - `<message>` is a fixed preamble line naming the role, a blank line, then the task
    file's contents (trailing newlines may be stripped).

  It shall pass pi's stdout through unchanged, exit with pi's exit status, and leave no
  temporary file behind.
- **R8** — If the dispatcher gets the wrong argument count, a role name outside
  `[a-z][a-z0-9-]*`, or a task file that is absent, non-regular or unreadable, then it
  shall exit 2. If the role file is absent, a symlink, the wrong node type, or under a
  symlinked or non-directory `.pi` or `.pi/agents`, or if its `tools:` is missing, empty or
  outside the allowed charset, or its `model:` or `thinking:` is invalid, then it shall
  exit 3. If no `pi` is on `PATH`, it shall exit 127. Checks run in that order (2, then
  3, then 127). In every one of these cases it shall
  print a `pi-dispatch:` diagnostic on stderr, nothing on stdout, and never invoke `pi`.
- **R9** — While `.harness/.agents` lists `pi`, `tools/harness-owned-paths.sh all` shall
  print `:(literal).pi/agents/<role>.md` for each regular, non-symlinked stamp under a safe
  `.harness/.pi-agents/` whose live path is safe. Otherwise it shall print no
  `.pi/agents` pathspec.
- **R10** — When `harness-install.sh --self` runs, it shall:
  - accept `pi`;
  - select `claude,codex,opencode,pi` by default and for `--agents=all`;
  - regenerate `.pi/agents/*.md` and `.pi/prompts/sdd-*.md` into the source layout through
    `self_transform` (no `.harness/` prefix left);
  - record them in `.claude/.glue-manifest`;
  - treat a symlinked, wrong-type or edited path as "left unchanged and unclaimed" without
    writing through it.

  This repository shall commit the regenerated files.
- **R11** — When a pi role-file or pi prompt-template emitter changes without
  regeneration, or when a committed `.pi/agents/*.md` or `.pi/prompts/*.md` is hand-edited,
  `tests/test_self_drift.sh` shall fail and name the path.
- **R12** — The Orchestrator prose and the shared `sdd-next` body shall carry a pi
  paragraph beside the Codex and Antigravity ones. On pi, delegate each role with the
  `subagent` tool when `pi-subagents` is loaded, otherwise run
  `tools/pi-dispatch.sh <role> <task-file>`, otherwise stop and report the limitation and
  the handoff path; and the Orchestrator itself runs in the main pi session and is never
  delegated. The installer manifest text shall list `.pi/agents/*.md`,
  `.harness/.pi-agents/` and `tools/pi-dispatch.sh`. The following five docs shall describe
  pi role isolation (`.pi/agents/` plus `pi-dispatch.sh`), and none of them shall still say
  "arrives with E35-F02":
  - README.md
  - AGENTS.md
  - docs/HARNESS.md
  - docs/INSTALL.md
  - docs/WORKFLOW.md

## Out of scope

- `model:`/`thinking:` stamping, `models.pin.pi.*`, the tier→thinking ladder, and pi
  escalation arming (E35-F03).
- Detecting, validating or installing `pi-subagents`, project-trust preflight, and the
  ADR-0007 §4 conflict report for pi's example `subagent` extension (E35-F04).
- `advertise:`, `excludeTools`, `maxSubagentDepth`, `extensions`, `skills` or any other
  `pi-subagents` key not listed in R1.
- Any change to `.harness/` itself as a path component (the installer owns it), to
  `.pi/prompts` ownership semantics (E35-F01 R7, re-expressed but behavior-preserving), or
  to `~/.pi/agent`.
- Editing past CHANGELOG entries. The 0.92.0 "arrives with E35-F02" line stays as history.
