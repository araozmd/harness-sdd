## Stack & dependencies

- POSIX `sh` (`harness-install.sh`, `tools/harness-owned-paths.sh`) and POSIX `sh` suites
  under `tests/`. Suites run through `sh tools/run-tests.sh`, under dash where available.
- New dependencies: none. No test runs `pi`, a model, or the network. Only `command -v` is
  used, against a stub on a sandbox PATH.

## Resolved questions (from the brief)

1. **Template body: a pointer to the skill file, not a `/skill:` expansion.**
   - pi expands a template's text once, at input. A `/skill:sdd-next` line *inside* a
     template is not re-expanded, so it would be delivered to the model as literal text.
   - Inlining the workflow, as `.opencode/command` does, would create a second copy of
     the body, which ADR-0003 and ADR-0004 forbid.
   - So the template tells the model to read `.agents/skills/<cmd>/SKILL.md` with the
     `read` tool and follow it, and passes `$ARGUMENTS` through.
   - The pointer bytes depend only on the command name and its description, which keeps
     the stamp contract (R7) simple.
2. **No separate `sdd-fix-parallel` gate on `.pi/prompts`.**
   - The template set is exactly the shared-unit set emitted in the same run. The unit is
     already reachable as `/skill:sdd-fix-parallel` whenever the project is trusted, so
     gating only the template would be a gate on one path. E31-F01 recorded that "a gate
     that only covers one path is not a gate".
   - pi has no known concurrency restriction. Its delegation story is F02. If F02 finds a
     restriction, it belongs in the shared body, the way E31-F01 handled OpenCode, so it
     covers both surfaces.

## Data model (serves: R6, R7, R10)

| Artifact | Shape | Owner | R-id |
|---|---|---|---|
| `.pi/prompts/<cmd>.md` | the template shape below | harness, pristine-only | R6, R7 |
| `.harness/.pi-prompts/<cmd>.md` | a byte copy of the last template the installer wrote | harness ledger | R7, R10 |

**Template shape (R6), exact bytes.** `<desc>` is the first `description:` value of
`$CMDDIR/<cmd>.md`, which is the same value `gen_skill_body` reads:

```
---
description: <desc>
---
Run the harness `<cmd>` workflow. Use the read tool to open `.agents/skills/<cmd>/SKILL.md` and follow it exactly — it is the single shared body for this command. Treat the text between the markers below as the workflow's accompanying arguments (empty means none).

<arguments>
$ARGUMENTS
</arguments>
```

Constraints on the shape:

- The body contains no other `$`, `${` or `$<digit>` sequence, because pi would substitute
  it.
- `<desc>` values today contain no `$`. The R6 test asserts that the whole file contains
  exactly one `$`.
- No `argument-hint` key. Frontmatter is exactly the three lines `---`,
  `description: <desc>`, `---`.

### HOST_MARKERS provenance text (R8)

The format is load-bearing (see `tests/test_agents_host.sh::prov_entry`): the entry starts
with `#   pi` at exactly three spaces of indent, and continuation lines are indented
deeper. Insert the entry after the `opencode` entry, above `# REJECTED CANDIDATES`:

```
#   pi          pi 1.2.0 — PI_CODING_AGENT=true, observed 2026-10-13 in a shell spawned by
#               the session's bash tool under `pi -p` (`comm -13` against a plain login
#               shell); pi's docs/environment-variables.md states pi sets it for every
#               child process it launches.
```

Append to the REJECTED CANDIDATES sentence:

> `AI_AGENT` (pi sets `AI_AGENT=pi`, but the variable is a generic cross-vendor convention,
> so its NAME discriminates no front end — the same reason `AGENT` is rejected);
> `PI_SESSION_ID` (present whenever `PI_CODING_AGENT` is, so it adds no detection power,
> and one verified marker is enough).

Write those REJECTED lines with a single space after `#`, never three. Otherwise
`prov_entry` would open a new entry on them.

### Adapter sentence (R5)

`gen_skill_body` keeps the existing adapter `printf` line byte-identical. Immediately after
it, add one line:

```
In pi, invoke `/<cmd>` (the harness prompt template) or `/skill:<cmd>`; pi loads project prompt templates and skills only after the project is trusted (`/trust`, or `-a` on a headless run).
```

Emit it with a format string carrying two `%s` and two `"$_gcs_name"` arguments, like the
existing line. The *emitted text* must contain no `$`. It must not contain `/skills`,
because `tests/test_codex_native.sh` and `tests/test_self_mode.sh` assert that the adapter
never names `/skills`. It must not contain `$` either. Do not name the `.agents/skills/`
path in this sentence.

### §5d-pi block (R6, R7)

Gated on `agent_selected pi`, placed after §5d so that each pointer's target was just
written. Iterate exactly `_cdx_cmds`, the list §5d used: `$HARNESS_EMITTED_CMDS`, plus
`$HARNESS_PR_LOOP_CMDS` when `pr_loop_enabled`. One iteration source is what lets R6 "same
set as the shared units" hold by construction. For each `<cmd>`:

1. **Symlink guard.** If `.pi`, `.pi/prompts`, `.pi/prompts/<cmd>.md`, `.harness/.pi-prompts`
   or `.harness/.pi-prompts/<cmd>.md` is a symlink, warn and skip this command. Discard the
   stamp only when **neither** `.harness/.pi-prompts` **nor** the stamp leaf is a symlink
   (the `codex_skill_stamp_is_symlinked` rule); otherwise never touch the stamp.
2. **Generate.** Write the template to a temp file with a new
   `gen_pi_prompt <cmd> <dest>` function.
3. **Decide.** The command is *safe* when the destination is absent, or byte-equals the
   stamp, or byte-equals the fresh body. Otherwise warn
   `⚠️  .pi/prompts/<cmd>.md is a foreign or edited prompt template — left unchanged`,
   remove the stamp, and skip this command.
4. **Write.** `mkdir -p` `.pi/prompts` and `.harness/.pi-prompts`, write the destination,
   and copy it to the stamp.

Then print `ok "pi prompt templates /sdd-… installed (.pi/prompts/ — load after project trust)"`.

### Shared removal helper (R7)

`reclaim_pi_prompts <cmd-list> <label>` is used by both §7 and §7b, so the two removal
paths cannot diverge. For each command:

- Apply the symlink guard from §5d-pi step 1. A symlinked component means: keep the file
  and warn.
- When the live file byte-equals the stamp, or the fresh body: delete it.
- Otherwise: keep it and warn
  `⚠️  .pi/prompts/<cmd>.md has no matching stamp (foreign or edited) — left in place`.
- Remove the stamp only when neither `.harness/.pi-prompts` nor the stamp leaf is a
  symlink (same rule as install step 1).

After the loop:

- Prune `.harness/.pi-prompts`, `.pi/prompts` and `.pi`, each with `rmdir … 2>/dev/null || true`.
- Print the removed paths on stdout, the way `reclaim_skill_units` does.

### §7 `pi)` arm (R4, R7)

```
pi)
  _pi_removed="$(reclaim_pi_prompts "$HARNESS_OWNED_CMDS" pi)"
  [ -z "$_pi_removed" ] || echo "⚠️  removed deselected agent 'pi' glue:$_pi_removed" >&2   # use a plain if, not a trailing && (set -e)
  if ! skill_unit_claimed; then
    _pi_skill_removed="$(reclaim_skill_units "$HARNESS_OWNED_CMDS")"
    if [ -n "$_pi_skill_removed" ]; then echo "⚠️  removed deselected agent 'pi' skills:$_pi_skill_removed" >&2; fi
  fi
  ;;
```

Write the first conditional as a plain `if`, like the existing arms, so the loop's last
status stays zero under `set -e`. `HARNESS_OWNED_CMDS` never contains `sdd-triage`, so a
target never touches the source-only name (ADR-0005).

## Approach notes

- **One predicate, every caller.** R3 and R4 widen only `skill_unit_claimed`. Do not add
  `agent_selected pi` at any call site.
- **One iteration source.** The §5d-pi block iterates the same `_cdx_cmds` value that §5d
  used. Hoist it if needed, and do not recompute it, so R6 cannot drift from the
  skill-unit set.
- **One generator, two compares.** `gen_pi_prompt` is the only producer of template bytes.
  Install and both removal paths compare against it and against the stamp.
- **Description source.** Use `sed -n 's/^description: //p' "$CMDDIR/<cmd>.md" | sed -n '1p'`,
  the same extraction `gen_skill_body` uses, so the template and the skill advertise the
  same text.
- **set -e hygiene.** Every new conditional echo is a plain `if`. Trailing `[ … ] && echo`
  in a loop body can end the arm with a non-zero status.
- **Detection order.** Nesting is real: a pi session that shells into Claude Code inherits
  `PI_CODING_AGENT`. Two matching rows give "undetected" plus one diagnostic. That is the
  existing R5 behavior, and it needs no code.
