# pi front-end key — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E35-F01:R1 … E35-F01:R12`.

## Context

Harness users who drive work from the pi coding agent (`@earendil-works/pi-coding-agent`
1.x) get nothing on purpose today. `AGENT_KEYS` (`harness-install.sh:1651`) has no `pi`, so
`--agents=pi` dies. pi only sees the shared `.agents/skills/sdd-*` units when another
claimant (codex, opencode, antigravity) happens to be selected, and nothing specifies,
tests or owns that path. A pi-only target receives no commands at all.

This feature makes `pi` a selectable front-end key with the same model OpenCode got in E31:

- pi **claims** the shared `.agents/skills/` units (ADR-0003).
- pi gets native `/sdd-*` commands via `.pi/prompts/<cmd>.md` prompt templates.
- pi is detectable as the session host.
- pi is listed as a non-interactive worker CLI.
- Deselecting pi removes exactly what pi added.

Role sub-agents (F02), model routing (F03) and environment preflight (F04) are separate
features. Until F02 lands, a pi session can run the `/sdd-*` workflows, but it has no
isolated role contexts. The docs must say so.

Verified facts this spec relies on (epic, live probe 2026-10-13, pi 1.2.0):

- A `pi -p` session's shell tool sees `PI_CODING_AGENT=true`, `AI_AGENT=pi` and
  `PI_SESSION_ID=<uuid>`.
- `pi -p` runs once and exits non-zero on an error, aborted or length stop. A headless run
  must pass `-a` (`--approve`), or pi skips project resources.
- `.pi/prompts/<name>.md` becomes `/<name>`. The template takes a `description`
  frontmatter field and substitutes `$ARGUMENTS`, `$@`, `$1` and `${…}`. pi loads it only
  after the project is trusted.
- pi discovers project `.agents/skills/` only when the project is trusted and the `read`
  tool is enabled. The skill is invocable as `/skill:<name>`.

### Why `complexity: complex`

Three of `agents/architect.md`'s stated bases hold:

1. **The feature is at the size budget.** It has exactly 12 R-ids against
   `change_size.max_requirements: 12`. F02–F04 were already split out to get here.
2. **It honors an ADR whose constraints reach across several files.** ADR-0003's claimant
   predicate binds:
   - the §5d install gate, the §7 deselect arms and the §7b gate-off pass;
   - `tools/harness-owned-paths.sh`;
   - the docs;
   - four existing suites.

   ADR-0003 itself warns that forgetting a claimant "fails silently in the destructive
   direction".
3. **It contains a byte contract compared in more than one place.** The prompt-template
   bytes are compared at install time (to decide whether an existing file may be
   overwritten), at deselect and at pr-loop gate-off. The harness has already paid for
   that defect class: E17-F01's `opencode.stamp` and E23's skill-unit stamps.

## Business rules

- **One unit, one body.** pi claims the existing shared `.agents/skills/<cmd>/` unit. It
  never writes a second copy of a command body. A `.pi/prompts/<cmd>.md` template is a
  thin pointer to that unit, not a copy of the workflow.
- **Same command set on both pi surfaces.** A command reachable as `/skill:<cmd>` is
  reachable as `/<cmd>`, and the reverse also holds. Both obey the same gates:
  - the `pr_loop.enabled` gate for `sdd-pr-loop`;
  - source-only `sdd-triage` is never in a target (ADR-0005).
- **Pristine-only ownership.** The installer overwrites or removes a pi template only when
  it is provably pristine: byte-equal to its last-written stamp, or byte-equal to the
  freshly generated template (the latter covers a lost stamp; the bytes are the harness's
  own output either way). A file the user wrote or edited survives, with a
  warning.
- **The four existing keys do not change.** claude, codex, opencode and antigravity
  selections produce byte-identical glue, with two exceptions:
  - one appended adapter sentence in the shared `SKILL.md`, which every claimant shares by
    ADR-0003;
  - the descriptive text that lists front ends (messages, manifest, docs).
- **Never touch `~/.pi/agent`.** Every artifact is repository-local.

## Architecture alignment

`specs/architecture.md` is absent in this repository. The ADR set under `specs/adr/` is
present, so citations are required. This is a single-namespace project, so bare ids are
used.

- ADR-0003 — One shared skill unit per command, claimed by every front end that reads it:
  `pi` joins the claiming set. One body, install when any claimant is selected, reclaim only
  when the last claimant leaves. The ADR's update block records the new membership.
- ADR-0004 — A child resolves the harness body through pointer stubs at the same paths: a
  `.pi/prompts/<cmd>.md` template is a pointer to the resolved shared unit. It never inlines
  the workflow. All generated pi glue stays in the program-read tier, as a full local file.
- ADR-0005 — Source-only surfaces are emitted only by `--self`: `sdd-triage` never gets a
  pi template in a target. `--self` support for pi glue is deferred to F02, so in this
  feature `--self --agents=pi` keeps dying with the existing "source mode" message.
- ADR-0007 — pi role sub-agents: this feature ships only the `pi -p` worker-invocation row
  that ADR-0007's fallback (option C) relies on. It adds no role files and no dispatcher;
  F02 owns those.
- ADR-0002 — builder-heavy is a tier: untouched. pi is excluded from the escalation-arming
  verdict until F03 gives it a resolver (R11), so no verdict is fabricated.

## Acceptance criteria (EARS)

- **R1** — When `--agents` or `HARNESS_AGENTS` names `pi`, the installer shall accept it,
  write `pi` to `.harness/.agents`, and keep `pi` selected on a later non-interactive
  re-run that names no selection. `--agents=all` shall resolve to
  `antigravity claude codex opencode pi`.
- **R2** — While `pi` is not selected and was not previously selected, the installer shall
  create no path under `.pi/` and no `.harness/.pi-prompts/` ledger.
- **R3** — When `pi` is selected and no other claimant is, the installer shall install the
  shared `.agents/skills/<cmd>/` units: one per standard command, plus `sdd-pr-loop` while
  `pr_loop.enabled` is true.
- **R4** — When `pi` is deselected, the installer shall leave every shared skill unit in
  place while another claimant (`codex`, `opencode`, `antigravity`) remains selected. It
  shall reclaim the proven-pristine units when `pi` was the last claimant.
- **R5** — The shared `SKILL.md` invocation adapter shall keep its existing adapter sentence
  byte-for-byte, and shall add one sentence naming both pi invocations, `/<cmd>` and
  `/skill:<cmd>`, plus the project-trust prerequisite. The added sentence shall not contain
  the substring `/skills` or the character `$`.
- **R6** — When `pi` is selected, the installer shall write one `.pi/prompts/<cmd>.md` for
  each command in this run's shared-unit command list (standard commands, plus
  `sdd-pr-loop` while `pr_loop.enabled` is true), whether or not that unit was rewritten,
  and no other. Each file shall contain:
  - a frontmatter block holding exactly the canonical command's `description`;
  - a body pointing at `.agents/skills/<cmd>/SKILL.md`;
  - exactly one substitution token, `$ARGUMENTS`.
- **R7** — If a `.pi/prompts/<cmd>.md` exists that matches neither the freshly generated
  template nor its last-written stamp in `.harness/.pi-prompts/`, or if any component of
  its path is a symlink, then the installer shall leave the file unchanged and print a
  warning. This holds on install, on pi deselection and on pr-loop gate-off. Otherwise the
  installer shall overwrite the file on install, and on removal shall delete it with its
  stamp, pruning `.pi/prompts/` and `.pi/` only when they are empty.
- **R8** — When `--agents=host` runs with `PI_CODING_AGENT` set and non-empty and no other
  front end's marker set, the installer shall select `pi` only. The `pi` `HOST_MARKERS` row
  shall pass `tests/test_agents_host.sh`'s R8 provenance check.
- **R9** — Where `workers.roster` is enabled and a `pi` executable is on `PATH`, the
  installer shall write a `.harness/workers.json` entry `{"key": "pi", "command": "pi"}`
  whose capabilities include `non-interactive` and `host-detectable`, and `harness-selected`
  only when `pi` is selected.
- **R10** — While `.harness/.agents` lists `pi`, `tools/harness-owned-paths.sh all` shall
  print `:(literal).pi/prompts/<cmd>.md` for each regular, non-symlinked stamp under
  `.harness/.pi-prompts/`, plus the shared skill-unit pathspecs. Otherwise it shall print
  no `.pi/` pathspec.
- **R11** — While `pi` is selected, the installer shall exclude `pi` from
  `.harness/.escalation-arming`. The file carries no `pi=` line, and pi's presence does not
  change the armed/blocked verdict computed from the other selected front ends.
- **R12** — The installer's operator-facing text and the docs shall name `pi` wherever they
  enumerate supported front ends. That means:
  - the retired-agent, unknown-recorded-agent and no-supported-agent diagnostics;
  - the header comment;
  - the `.harness/manifest.txt` agent-selection line;
  - the pi-only and multi-host post-install advisory;
  - README.md, AGENTS.md, docs/HARNESS.md, docs/INSTALL.md and docs/WORKFLOW.md.

  Each of those docs shall carry the pi project-trust prerequisite (`/trust`, or `-a` on a
  headless run) and state that pi role isolation arrives with E35-F02.

## Out of scope

- `.pi/agents/<role>.md`, `tools/pi-dispatch.sh`, Orchestrator dispatch prose for pi, and
  `--self` support for pi (E35-F02).
- `models.pin.pi.*`, the tier-to-`thinking` ladder, and escalation arming for pi (E35-F03).
- Preflight checks of pi trust or installation, and any `pi install` (E35-F04).
- Any write under `~/.pi/agent`, or to `.pi/settings.json`.
- Changing the canonical command bodies, or `HARNESS_SDD_CMDS` membership.
- Renaming `.harness/.codex-skills/` (ADR-0003 keeps the historical name).
- Removing the "role isolation arrives with E35-F02" note: E35-F02 owns deleting it from
  the five docs and from the R12 assertion in `tests/test_pi_front.sh`.

## Open questions

None remain for approval. The brief's two open questions are resolved in the plan
("Resolved questions"):

- The template body is a pointer to `.agents/skills/<cmd>/SKILL.md`, not a `/skill:`
  expansion.
- `.pi/prompts` uses the same command set as the shared units, with no separate
  `sdd-fix-parallel` gate.
