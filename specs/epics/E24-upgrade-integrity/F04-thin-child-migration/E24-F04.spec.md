# Migrate existing children to the thin layout (+ `--standalone`) — Functional Spec

## Context

`E24-F03` shipped the thin-child mechanism and deliberately changed only what a **fresh**
child install writes. An already-installed child keeps its full local copy of the prose tier
forever, `manifest.txt` records that it is in the full-copy layout, and the cascade says so
out loud (`child already holds a full body — left as-is`). That was the safe half.

This is the other half, and it is the destructive one: replacing the prose tier with pointer
stubs **in repositories that already exist, on someone's working tree**. An umbrella running
since before F03 gets none of the benefit — its children still carry N byte-identical copies
and still produce N identical diffs on every upgrade — and nobody is going to re-create five
child repos to opt in.

**Correction to the brief's count.** The brief says 29 prose-tier files. Measured on `main`
the tier is **30**: `AGENTS.md` (1), `agents/` (12), `docs/` (7), `specs/_templates/` (9),
`specs/glossary.md` (1). The number is load-bearing only as an order of magnitude — it moves
whenever a body file is added — so **no requirement and no test in this feature asserts a
literal count**, exactly as none asserts a literal `VERSION`.

### Why `complexity: complex`

Three of `agents/architect.md`'s stated bases hold, and this is the basis, not a feeling:

1. **It landed exactly on the size budget.** 12 requirements against a `max_requirements` of
   12, with a named seam it did not take (see *Recorded decision D*). Stated honestly: **R5
   and R7 are regression locks on behavior F03 already shipped**, not new capability — they
   are there because the obvious implementation of `--thin` breaks the maintenance path, and
   a lock without a requirement is a lock the Reviewer cannot check. Two of the twelve
   therefore buy safety rather than function, which is an argument the gate may weigh against
   *Recorded decision D*.
2. **It honors an ADR whose constraints reach across several files** — `ADR-0004`'s tier
   line governs `harness-install.sh` §1, the manifest, `init.sh`'s report, the config schema
   and `docs/UMBRELLA.md` at once.
3. **It re-enters a defect class this harness has already paid for.** F03's `stub_tree` took
   four blocking findings for reimplementing `cp -R`'s traversal one filesystem shape at a
   time, and this feature needs the *comparison* traversal over the same trees. It also adds
   a byte-identity comparison beside two that already exist (`remove_if_pristine`, the
   skill-unit stamps) — a byte contract compared in more than one place is on the list.

## Business rules

- **Pristine-only, and the reference is the umbrella's copy.** A prose-tier file is replaced
  by a stub only when it is byte-identical to the umbrella's copy of the same relative path
  — the copy the stub will point at. That is the question conversion actually asks: *if I
  drop this content and redirect, does the child lose anything?* Comparing against anything
  else answers a different question.
- **All-or-nothing per child.** A tier is converted whole or not at all, and every path that
  blocked it is named. Partial conversion of one child's tier is not a state anyone can
  reason about, and "which of my 30 files is a stub today?" is not a question an operator
  should have to ask git.
- **Fail closed.** Where byte-identity cannot be *established* — the umbrella is unreachable,
  the comparator is unavailable, a path exists on one side only — nothing is converted. The
  absence of evidence of an edit is not evidence of its absence.
- **Not fatal.** A child that cannot resolve its umbrella is a **supported state, not a
  degraded one** (F03's acceptance bar: CI, a lone clone, a PR reviewer's checkout). Refusing
  to convert is a warning, never an install failure.
- **Consent once, then maintenance.** The first conversion of a given child requires an
  explicit `--thin`; afterwards the child is thin and the F03 maintenance path keeps it thin
  with no flag and no prompt. See *Recorded decision A*.
- **Discovery without action.** An operator must be able to find out that the option exists
  without exercising it. An unflagged run reports what it *would* convert and converts
  nothing. It is a **discovery** mechanism only — it is not step one of the migration, and
  *Recorded decision E* explains why documenting it as such would be wrong.
- **The conversion leaves a committable tree.** E24-F01's drift guard is this feature's
  observability: a conversion that went wrong shows up as drift at the top of the next
  session. That only works if the converted tree is one a `git commit` can land whole.
- **`--standalone` is the documented way back.** A thin child can be re-materialised into a
  full local body on demand — the answer for a child being detached from its umbrella.

## Architecture alignment

- platform ADR-0004 — *a child resolves the harness body through pointer stubs at the same
  paths*: this feature is the migration the decision explicitly deferred ("migrating
  already-installed full-copy children … and a `--standalone` flag … are follow-up work").
  It changes **neither** the tier split, **nor** the stub format, **nor** the `umbrella.root`
  mechanism — it only moves an existing target from one of the decision's two recorded
  layouts to the other, and back.
- platform ADR-0003 — *one shared skill unit per command*: honored, and it is a boundary this
  feature must not cross. Skill units and every generated front-end glue file are
  program-tier: conversion never reads, writes, stubs or removes them. A glue file touched by
  this feature means the tier line has been crossed.
- platform ADR-0001 — *deterministic `next` selection*: untouched. Board state is
  project-owned and stays per child; nothing about task selection moves to the umbrella.

## Acceptance criteria (EARS)

> 12 requirements against a `change_size.max_requirements` of 12 — exactly on the budget,
> with no slack. The seam this feature declined to cut on is recorded in *Recorded decision D*.

- **R1** — When the installer runs with `--thin` against a target that resolves an installed
  umbrella body, and every file of that target's prose tier is byte-identical to the umbrella
  body's copy of the same relative path, the system shall replace that target's prose tier
  with pointer stubs of the same form a fresh thin install writes.
- **R2** — If any prose-tier path differs between the target and the umbrella body — content,
  or present on one side only — then the system shall convert no file in that target and
  shall leave the target in the full-copy layout.
- **R3** — When the system refuses a conversion under R2, it shall name every differing
  prose-tier path in its output.
- **R4** — Where the installer runs **without** `--thin` against a target that resolves an
  umbrella body and holds a full-copy prose tier, the system shall report whether that target
  would convert — naming the same differing paths R3 names when it would not — and shall
  convert nothing.
- **R5** — When the installer runs against a target whose prose tier is already stubs, the
  system shall keep that target in the thin layout without `--thin` being passed and without
  prompting.
- **R6** — If `--thin` is passed for a target that records a non-empty `umbrella.root` which
  does not resolve to an installed harness body, then the system shall convert nothing, shall
  report the unreachable umbrella as a warning, shall leave that target's full local body in
  place, and shall exit with the same status it would have exited without `--thin`.
- **R7** — When `--thin` runs against a target whose prose tier is already stubs, the system
  shall leave every prose-tier path byte-identical to its content before that run.
- **R8** — When a converted target's harness-owned paths have been committed, `init.sh` in
  that target shall exit zero reporting no drift, and that target's `manifest.txt` shall
  record the `thin` body layout.
- **R9** — When the installer runs with `--standalone` against a target whose prose tier
  holds pointer stubs, the system shall replace every one of those stubs with the
  corresponding full body file from the installer's own source.
- **R10** — When `--standalone` is applied to a target, the system shall clear that target's
  `umbrella.root`.
- **R11** — Where `--standalone` is applied to a target that already holds a full local prose
  body, the system shall leave that target in the full-copy layout — materialised from the
  installer's source as an ordinary run does — shall still clear `umbrella.root`, and shall
  exit zero.
- **R12** — If `--standalone` is passed together with `--umbrella`, or together with
  `--thin`, then the system shall abort with a usage error before writing to any target.

## Recorded decisions

> The brief left two questions to the approval gate. Both were decided on **2026-08-17** and
> are recorded here — with their reasoning — rather than answered in a commit message, so a
> later reviewer can see *why* before helpfully reopening them. Decisions C and D are the
> Architect's, recorded for the same reason.

### Recorded decision A — conversion requires `--thin` the first time, then the layout carries it

- A **first** conversion of a given child requires the operator to pass `--thin`. Re-running
  the cascade without it converts nothing (R4).
- Once a child is converted it **is** a thin child, and every later cascade maintains the thin
  layout with **no flag and no prompt** (R5). The flag is a one-time consent per child, not a
  permanent ceremony.
- An **unflagged** cascade against a full-copy child must **report what it would convert**, so
  an operator discovers the option instead of never learning it exists — without converting
  anything (R4).

**Reasoning.** Silently rewriting 30 tracked files per child is precisely the class of
surprise `E24-F02` exists to prevent. But requiring the flag *forever* would make the common
case — maintaining an already-thin umbrella — needlessly manual, and would train operators to
pass `--thin` reflexively, which is the same thing as not having a flag. The mechanism is
present rather than invented: the installer already distinguishes the two layouts, and
`manifest.txt` already records which one a target holds (F03 R8).

**One clarification the mechanism deserves, because the wording invites a wrong
implementation.** The durable record that a child is thin is the **stub sentinel on disk** —
`child_is_full_copy` is the existing ownership signal, and F03's maintenance branch already
keys off it. `manifest.txt` *reports* the layout; it is not consulted to decide it. A Builder
who makes the manifest the source of truth has introduced a second answer to a question that
already has one.

### Recorded decision B — an unreachable umbrella converts nothing, warns, and does not fail

**Decision.** Convert nothing, warn, leave the full copy in place, and **do not fail the
install** (R6).

**Reasoning — it follows from the safety rule, not from taste.** Conversion is
**pristine-only**: a file is stubbed only when byte-identical to the umbrella's copy. With the
umbrella unreachable there is nothing to compare against, so byte-identity cannot be
established and no deletion can be justified. Fail closed.

It must not be fatal because F03 already treats a child entered on its own — CI, a lone
clone, a PR reviewer's checkout, a fresh worktree — as a **supported state, not a degraded
one**. An installer that aborts there would convert F03's supported state into a broken one,
in the exact repositories the epic exists to keep working.

The same fail-closed rule extends to every other way the comparison can fail to *establish*
identity (a missing comparator, an unreadable path). Absence of evidence of an edit is not
evidence of its absence.

### Recorded decision C — `--standalone` clears `umbrella.root`, and what that does and does not buy

**Decision.** `--standalone` clears the target's `umbrella.root` (R10).

**Reasoning.** `umbrella.root` means exactly one thing — *resolve my prose body from here*.
After `--standalone` that statement is false, so leaving the key set records a relationship
that no longer holds, and `init.sh` keeps reporting an umbrella linkage that no longer governs
anything. Clearing it costs nothing structurally: umbrella **membership** is established by
the cascade's directory discovery and `umbrella.manifest.yaml`, not by this key, so a
detached child keeps its manifest entry, its slices and its dispatch.

**And the honest limit, because the brief's argument for clearing it is weaker than it
looks.** The brief argues that otherwise "the next cascade converts it straight back, making
the flag a no-op". It would not: after `--standalone` the child is a **full-copy** child, and
F03 R9 makes every cascade leave a full-copy child alone. What actually undoes the
detachment is an explicit `--thin` run — and clearing `umbrella.root` does **not** prevent
that either, because the cascade re-records the key for every child it installs and the
shipped config seeds `root: ""`, so "cleared" is indistinguishable from "never set".

So the durability of `--standalone` comes from the **layout**, not from the key: a standalone
child survives every run that does not pass `--thin`. Clearing the key is still right — for
truthfulness, for `init.sh`'s report, and for the child that is being moved out of the
umbrella tree altogether — but it is not an opt-out flag and this spec does not sell it as
one. A per-child permanent exclusion would need a new recorded key, which is a new decision
and out of scope here.

### Recorded decision D — the split this feature declined, and why

The named seam is **R9–R12 (`--standalone` and its flag validation)**, and it is a real one:
conversion deletes content, `--standalone` materialises it, and the two share only the tier
list, the layout switch and the config writer.

It was not taken because splitting buys less than it looks like it does. The review risk in
this feature is concentrated entirely in the destructive half (R1–R8, 8 requirements), and
that half is identical in size either way — cutting `--standalone` out does not shrink the
diff anyone has to read carefully. What it would cost is a full SDD cycle for a
**4-requirement** feature, and a release in which `ADR-0004`'s recovery story is documented
but unimplemented for the one case that needs it (detaching a child while its umbrella is
still reachable — the unreachable case already re-materialises today, because
`umbrella_body_dir` returns nothing and §1 falls back to the full copy).

**The argument against that reasoning, stated so the gate can act on it:** this spec lands on
12 of 12 with no slack, and two of those twelve (R5, R7) are regression locks rather than new
behavior. A gate that wants headroom for the destructive half has a clean, cheap cut
available.

If the approval gate disagrees, cut exactly there: **E24-F04 keeps R1–R8, a new E24-F05 takes
R9–R12**, no renumbering, no shared code moved.

### Recorded decision E — a stale child blocks its first `--thin` run, the migration command is `--umbrella --thin` run twice, and the report is a record rather than a rescue

**A stale child blocks, and that is correct.** A child installed from an older `VERSION` has
prose files that differ from the freshly upgraded umbrella body, so R2 blocks its conversion
and R3 names them. This is not a mis-detection to work around: at the moment of comparison the
child genuinely holds content the umbrella does not, and the pristine rule has exactly one
meaning. The alternative — teaching the comparison to tell "stale" from "edited" — needs a
per-file record of what the installer last wrote, which is new ownership machinery and a
fourth answer to a question that already has three.

**The migration command is `harness-install.sh --umbrella <dir> --thin`, run until it
converges** — normally once, twice when the children were behind:

- Run 1: the coordinator is upgraded first, so it holds the current body. Children already at
  that body convert. Children that were behind are named, upgraded by that same run, and not
  converted.
- Run 2 (only if run 1 named anything): those children now match, and convert.

**Do not document an unflagged "preview pass" as step one of the migration.** It was the
obvious procedure and it is wrong, because the unflagged path is the ordinary full-copy
branch and that branch has always been `rm -rf` + `cp -R` over the whole prose tier. A preview
run therefore *destroys the very differences it just reported*, so by the time a flagged run
follows, nothing can block and the report was a fiction. R4's preview is a **discovery**
mechanism for an operator who ran an ordinary cascade — that is all it is, and Decision A is
the only thing it serves.

**And the honest limit, which the brief overstates.** The brief's success outcome says an
edited body file "survives, loudly". It is named loudly (R3); it does **not** survive. The
full-copy path replaces the whole prose tier from source on every installer run and always
has — this feature neither introduces that nor is scoped to fix it (see *Out of scope*). What
R2/R3 actually guarantee is narrower and is the guarantee that matters for a **destructive
layout change**: the installer will not **redirect** a path to content the umbrella does not
hold, and it will tell you which paths it refused to redirect and why. The pre-run content is
recoverable from git, because E24-F01's guard already requires the installed body to be
committed — so the report names paths whose previous content `git diff` in that child still
shows. The report says so.

## Out of scope

- **Changing the tier split, the stub format, or the `umbrella.root` mechanism.** All settled
  in `ADR-0004` and shipped by F03. This feature moves targets between the two recorded
  layouts; it does not redefine either.
- **Converting anything on a plain `init.sh` run.** Conversion happens only when the
  installer is invoked. `init.sh` reads; it does not migrate.
- **Preserving a locally edited body file across an ordinary upgrade.** The full-copy path
  already replaces the whole prose tier from source on every run (`rm -rf` + `cp -R`), and
  changing that is a different feature with a different review. What this feature guarantees
  is narrower and is the guarantee that matters here: it will not **redirect** a path whose
  content the umbrella does not hold. See *Recorded decision E* — this is the one place the
  brief's success outcome is not achievable as written, and it is not achievable today either.
- **A per-child permanent opt-out from `--thin`.** See *Recorded decision C*; it needs a new
  recorded key.
- **PROJECT-OWNED paths.** `harness.config.yaml` (beyond the single `umbrella.root` scalar),
  `init.project.sh`, `specs/product.md`, `specs/epics/`, `state/`, `progress/` stay per child,
  always.
- **Changing what a single-repo install does.** With no `umbrella.root` recorded there is
  nothing to resolve, so `--thin` is inert *and silent* there. That inertness is not
  out-of-scope prose — it is the negative control R6 is tested against, since R6's warning is
  conditional on a recorded-but-unresolvable root and a warning that fires unconditionally
  would pass a presence-only test.
