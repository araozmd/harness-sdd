## Fixture shape — build it in this order, and assert it

Every conversion case needs a **full-copy child of a reachable umbrella** — the state F03
deliberately leaves alone, and the real pre-F03 state this feature exists to migrate. Build it
the way the product does:

1. `harness-install.sh <umb>/<child>` — **single-target first**, so no `umbrella.root` is ever
   written and the child gets the complete local body.
2. `harness-install.sh --umbrella <umb>` — the cascade then records `umbrella.root` and, per
   F03 R9, leaves the full body alone.

**Do not invert those two steps.** Cascading first and then re-installing single-target does
**not** produce a full-copy child: `umbrella_body_dir` prefers `HARNESS_UMBRELLA_ROOT` but
falls back to the child's own config (`harness-install.sh:721-722`), which §2a has already
persisted (`:2522-2527`) — so the single-target run resolves the umbrella and re-stubs. A
Builder who hits that and "fixes" it by hand-editing the child's config has replaced the
product's own state machine with a fixture, which is the divergence this section exists to
prevent.

**Assert the precondition either way:** before the `--thin` run, `agents/builder.md` in that
child must be a real body file (`is_stub` false, and a known body substring present). A
conversion test whose fixture was never full-copy proves nothing.

## Anti-tautology — what each test must not be satisfiable by

- **R1 is paired with the fresh-thin control it claims equality with.** `converted_equals_fresh_thin`
  compares a converted child's whole prose tier against a *freshly cascaded* thin child's,
  byte for byte. "Contains the sentinel" is satisfiable by a body that was never written; "is
  identical to what a fresh thin install produces" is not, and it is also the requirement.
- **R2 must assert bytes before and after, not existence.** Checksum the child's prose tier
  before the blocked `--thin` run and compare after: every path stays present in **both**
  outcomes, so presence cannot distinguish converted from refused. The edited file itself is a
  poor witness — R2's claim is about the *other 29*, so the assertion is "no path in the tier
  became a stub", swept over the whole tree, not sampled.
- **R2's second case (a child-only extra file) is not redundant.** It is the case where the
  conversion would *delete* content rather than redirect it, and a `cmp`-per-known-path
  implementation passes it while being wrong.
- **R3 asserts the tier-relative path, never `diff`'s wording** — and the implementation has
  to *build* that path, because `diff` does not always print it: `Only in <dir>: <name>` splits
  it in two, a whole missing entry goes to stderr with exit 2, and `diff -r` without `-q` on
  the two regular-file entries prints no filename at all (`.plan.md` → *The comparison*). So
  R3's assertions must cover **three shapes**: an edited file, a child-only extra file, and one
  of `AGENTS.md` / `specs/glossary.md`. Seed **two** differing paths at minimum and assert
  **both** — one blocker is satisfiable by an implementation that reports the first and stops.
- **R4's real proof is the mutation row, not an on-disk assertion.** "The tier is still a full
  copy afterwards" is the *trivially true* half — it is exactly today's shipped behavior
  (`harness-install.sh:2465-2469`), so an unmodified installer passes it. Assert it anyway for
  the record, but R4 is only genuinely proven by the mutation *"the unflagged path converts
  anyway"* failing, plus the preview line being present and naming the right target.
- **R5 must run the unflagged installer against a genuinely thin child** and assert the stubs
  survived. This is the regression lock on F03's maintenance branch; it fails loudly if
  `--thin` is implemented by gating that branch.
- **R6 needs a genuinely unreachable umbrella, and "move the umbrella root" does not produce
  one.** The cascade records a **relative** root (`../../`, derived at
  `harness-install.sh:6182-6201`), so renaming `<umb>` moves the child with it and `../../`
  still resolves — the test would quietly exercise the ordinary path. What actually breaks
  resolution while leaving a non-empty `umbrella.root`: delete `<umb>/.harness/.harness-version`
  (or `<umb>/.harness`), move the **child** out from under the umbrella, or rewrite the key to
  an absolute path that does not exist.
  Build the fixture as a **full-copy child of a reachable umbrella** (above), *then* break the
  umbrella. Starting from an already-thin child is the trap: the copy branch re-materialises a
  full body, so "the body is still full-copy" passes with R6 unimplemented. Assert three
  things: exit 0, the warning, and the body still full-copy.
- **R7 asserts bytes captured before the run**, not "the run said nothing changed".
- **R8 asserts drift-clean *after* an explicit commit, and dirty before it.** Without the
  "dirty before" half, a guard that never runs also passes.
- **R11 is not "the bytes did not change".** `--standalone` takes the ordinary copy branch, so
  a stale or edited full-copy target legitimately comes out **re-installed from source**. The
  assertion is the layout (no stub anywhere in the prose tier), the cleared key, and exit 0 —
  a byte-identity assertion here would encode a guarantee the design does not make and would
  pass only because the fixture happened to be pristine.
- **`f04_docs_contract` asserts an absence as well as a presence.** `docs/UMBRELLA.md` must
  name `--umbrella … --thin` as the migration command and must **not** present an unflagged
  cascade as step one of a migration — that procedure destroys the differences it reports
  (*Recorded decision E*), and it is the wrong doc a reviewer is most likely to write.
- **R10's control is the same file's other keys.** Assert `umbrella.manifest` and at least one
  hand-editable value in that config are untouched — a writer that clears the key by
  truncating the section would otherwise pass.
- **Never assert a literal count of prose-tier files** (today 30) and never assert a literal
  `VERSION`. Both change under unrelated work; both have already produced false failures here.

## Idiom constraints for this suite

- **`grep -c` counts matching *lines*, not occurrences.** Where a count is asserted, use
  `grep -o <pattern> | wc -l | tr -d ' '`. And never bind a possibly-zero `grep -c`/`grep -q`
  result directly under `set -eu` — `grep` exits 1 on no match and kills the suite before the
  assertion runs; guard with `|| true` and assert the value. **The same hazard applies to the
  product code this feature adds**: `diff` exits non-zero precisely in the interesting case,
  and `harness-install.sh` is `set -eu` (`:101`).
- **Any prose-contract assertion over `docs/UMBRELLA.md` uses a fence-aware section
  extractor** (`sect()`/`span()` as in `tests/test_stacked_doctrine.sh:66-76`). The bare house
  awk idiom stops at the first `#` inside a fenced block. To be precise about *why*, since a
  Builder who checks will find the present tense false: `docs/UMBRELLA.md`'s fences carry no
  `#` comments **today** — this is a forward-looking precaution, because T12 adds new fences
  to that very file and a `#` comment in one would truncate the span and make
  `f04_docs_contract` pass over text it never read. Do not delete the constraint on the
  grounds that the file is currently safe.
- **`grep`/`awk` on the development box are BSD.** No GNU-only flags (`grep -P`, `awk`
  gensub). `diff` output is never matched by wording — only by the tier-relative path the
  implementation normalises it into.
- Every fixture under its own `mktemp -d`; sandbox `CODEX_HOME` **and** `HOME` on every
  `harness-install.sh` invocation; suites must pass under `dash`.

## Regression contract — this feature must change nothing here

- **E24-F01's drift guard and E24-F02's landing audit pass unchanged**, in both layouts *and
  across the transition*. Stubs are ordinary tracked files at the same pathspecs. If either
  needs a line changed, the design has drifted from `ADR-0004`, and that is the finding.
- `tools/harness-owned-paths.sh` is untouched and its existing assertions stay green.
- **Every F03 R-id stays green with no assertion edited**, in particular R4 (the program tier
  is a full local copy in a thin child), R5 (no `umbrella.root` ⇒ complete body) and R9 (an
  unflagged run leaves a full-copy child alone).
- The front-end glue suites (`test_install.sh`, `test_pr_loop.sh`, `test_model_routing.sh`,
  `test_agents_host.sh`) stay green with no assertion edits — all glue is program tier
  (`ADR-0003`).

## Non-functional

- `sh tools/run-tests.sh` fully green; suites pass under `dash` (`/bin/sh` is dash on CI).
- `sh -n harness-install.sh` and `bash -n init.sh` clean.
- `sh tools/change-size.sh` within the configured budget.
