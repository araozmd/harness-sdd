## Fixture shape — build it in this order, and assert it

Every conversion case needs a **full-copy child of a reachable umbrella** — the state F03
deliberately leaves alone, and the real pre-F03 state this feature exists to migrate. Build it
the way the product does:

1. `harness-install.sh <umb>/<child>` — **single-target first**, so no `umbrella.root` is ever
   written and the child gets the complete local body.
2. `harness-install.sh --umbrella <umb>` — the cascade then records `umbrella.root` and, per
   F03 R9, leaves the full body alone.

**Do not invert those two steps.** Cascading first and then re-installing single-target does
**not** produce a full-copy child: `umbrella_body_dir` prefers `HARNESS_UMBRELLA_ROOT` but
falls back to the child's own config (`harness-install.sh:721-722`), which §2a has already
persisted (`:2522-2527`) — so the single-target run resolves the umbrella and re-stubs. A
Builder who hits that and "fixes" it by hand-editing the child's config has replaced the
product's own state machine with a fixture, which is the divergence this section exists to
prevent.

**Assert the precondition either way:** before the `--thin` run, `agents/builder.md` in that
child must be a real body file (`is_stub` false, and a known body substring present). A
conversion test whose fixture was never full-copy proves nothing.

## Anti-tautology — what each test must not be satisfiable by

- **R1 is paired with the fresh-thin control it claims equality with.** `converted_equals_fresh_thin`
  compares a converted child's whole prose tier against a *freshly cascaded* thin child's,
  byte for byte. "Contains the sentinel" is satisfiable by a body that was never written; "is
  identical to what a fresh thin install produces" is not, and it is also the requirement.
- **R2 must assert bytes before and after, not existence.** Checksum the child's prose tier
  before the blocked `--thin` run and compare after: every path stays present in **both**
  outcomes, so presence cannot distinguish converted from refused. The edited file itself is a
  poor witness — R2's claim is about the *other 29*, so the assertion is "no path in the tier
  became a stub", swept over the whole tree, not sampled.
- **R2's second case (a child-only extra file) is not redundant.** It is the case where the
  conversion would *delete* content rather than redirect it, and a `cmp`-per-known-path
  implementation passes it while being wrong.
- **R2's umbrella-reference case is the only one in which the two candidate references
  disagree.** Every other fixture installs the umbrella and the child from the same `$SRC`, so
  `prose_tier_blockers "$H" "$SRC"` satisfies all of them and the "reference = the umbrella
  body" rule is untested by construction. This case seeds the divergence on the **umbrella**
  side (append to `<umb>/.harness/agents/<file>` after the fixture is built) and converts
  **single-target** — a cascade re-installs the coordinator first and would erase it. It
  asserts three things: the run blocks, it names that path, and it names **exactly** that
  path — the last one is what stops "a reference that blocks every child" from satisfying it.
  Assert as a precondition that the child is still byte-identical to `$SRC`, or the case does
  not discriminate between the two references at all.
- **The comparison and the write must name the SAME tree, and only one case can prove it.**
  `prose_tier_blockers` judges the child against the umbrella body; `stub_tree` rebuilds the
  tier with `rm -rf` + `cp -R`. If that copy comes from `$SRC`, the child is judged on one tree
  and rebuilt from another, and both mismatches are destructive: a path the child **and** the
  umbrella hold that `$SRC` lacks (a shared house addition — what an umbrella is *for*) is
  reported pristine and then **deleted** while the run prints `CONVERTED`, with no `differs:`
  line and no "re-installed from source" disclosure, because both belong to the refusal branch;
  and a `$SRC` path the umbrella lacks is **created** as a stub naming a file the umbrella
  cannot supply, whose own text then misreads the dangling target as "a checkout separated from
  its umbrella". Both were measured on this branch. Seed both in **one** child — each difference
  must be shared by child and umbrella, so neither blocks — and assert the conversion *happened*
  first: "the shared path survived" is satisfied for free by any change that refuses to convert.
  A second child cannot share that umbrella: direction 2 is seeded by removing a path from the
  umbrella, which would block any sibling that still holds it.
- **The MAINTENANCE arm needs its own case, on the tier the conversion built.** Fixing the write
  reference in the conversion branch leaves the already-thin branch free to disagree, and it did:
  the very next install — ordinary *or* `--thin` — rebuilt the tier from `$SRC` and undid the
  conversion in both directions at once, printing its ordinary success line either way. Measured:
  one `--thin` then one unflagged run and `agents/shared-extra.md` is gone, `agents/pr-fixer.md`
  back as a stub the umbrella cannot resolve. So the case **reuses the converted child** rather
  than building an equivalent one by hand — the claim is about what happens to a tier the product
  produced — and it runs **both** invocations, because an implementation that fixed `--thin`
  alone still loses the shared path on the next unflagged cascade, which is the run that happens
  by itself. Its control is the `prose body resolved from the umbrella` line, printed by that arm
  alone: a run that converted, refused or skipped the child satisfies every survival assertion for
  free. **This is also R7's real idempotence case.** `thin_is_idempotent` uses a *cascade*, and a
  cascade re-installs the coordinator from `$SRC` before every child — so its umbrella body and
  `$SRC` can never disagree and it cannot see this class no matter what it asserts. R7 was
  therefore claiming more than it measured; byte-equality is re-asserted here, on the one fixture
  where the two trees do disagree.
- **Making the umbrella the one authority creates a new obligation: what if it is OLDER than the
  installer?** `$HARNESS_BODY_PROSE` is *this* installer's list, and an umbrella installed by an
  earlier one may simply not hold an entry on it. Both wrong answers were measured on the fixture:
  re-sourcing that entry from `$SRC` gives the child a stub naming `../../.harness/specs/glossary.md`,
  a file the umbrella cannot supply, **with no warning at all** — the very defect this round is
  fixing, reintroduced through the back door; and `die`ing exits 1 on an *ordinary maintenance*
  run, wedging every cascade against that umbrella including the ones that would upgrade it. The
  rule is **skip**: left exactly as found, named on stderr, exit 0. Assert **both** directions —
  an already-thin child keeps its existing stub byte-for-byte (the destructive half), a fresh child
  gets **no** path there (the invention half) — plus that the other four entries were still
  stubbed, or "no dangling stub" is satisfied by a run that wrote no tier at all, plus that the
  message does **not** also name an entry the umbrella *does* hold, or it discriminates nothing.
- **R2's all-or-nothing rule covers the WRITE, not only the pristine check.** A tier written
  one entry at a time — build it, swap it, start the next — leaves entries 1-3 converted and
  4-5 full copies when entry 4 fails, which is the mixed layout the rule exists to forbid.
  Measured: `chmod 0555` on a full-copy child's `.harness/specs` and `--thin` produced 20 stubs
  and 10 real files in one child. The write therefore has **two** halves and each needs its own
  trigger, because a different mechanism covers each: a failed **swap** (that same 0555 fixture,
  which refuses the `mv` out of `specs/`) is undone by a rollback, and a failed **build** writes
  nothing at all because no entry is swapped until every entry has been built. Neither trigger is
  exotic and neither needs root.
  **The build half's trigger lives in the UMBRELLA BODY**, because the umbrella body is the only
  tree a thin tier is ever built from — a doctored `$SRC` no longer reaches that code path at
  all — and it is an **unreadable regular file** inside `specs/_templates` (tier entry 4 of 5),
  run against a **fresh** child through `HARNESS_UMBRELLA_ROOT`. Not a *missing* entry: an entry
  the umbrella does not hold is deliberately **skipped**, so absence can no longer fail a build.
  Not a `0000` **directory** either: that one also defeats the `rm -rf` of the staging tree, so
  the run dies with the wrong message.
  Assert the failure came from the prose-tier write itself — an abort before it leaves the tier
  whole for free — and assert **bytes**, not presence: the rolled-back child must still be
  byte-identical to the umbrella copy that made it convertible.
- **A self-referential `umbrella.root` is not the unreachable-umbrella case.** `"../"` on a
  non-child resolves to that target's *own* `.harness`, which is a directory, is not a symlink
  and does hold `.harness-version` — so it satisfied every strictness rule and the tier was
  compared *with itself*, found pristine, and replaced by 30 stubs each naming itself, exit 0,
  reporting `CONVERTED`. The fixture is a plain single-target install plus one hand edit; do
  **not** install an umbrella above it, and assert as a precondition that the target *does*
  carry `.harness-version`, or the refusal is R6's and the case proves nothing. Assert also
  that no `differs:` line was printed — a refusal that comes from blocking paths would mean the
  fixture stopped being convertible and the guard was never what saved it. Four spellings
  (`../`, `./../`, absolute, and a route through a symlink), because only a comparison of
  resolved **physical** paths answers all four; a string comparison against `../` passes the
  first and converts the other three.
- **R3 asserts the tier-relative path, never `diff`'s wording** — and the implementation has
  to *build* that path, because `diff` does not always print it: `Only in <dir>: <name>` splits
  it in two, a whole missing entry goes to stderr with exit 2, and `diff -r` without `-q` on
  the two regular-file entries prints no filename at all (`.plan.md` → *The comparison*). So
  R3's assertions must cover **three shapes**: an edited file, a child-only extra file, and one
  of `AGENTS.md` / `specs/glossary.md`. Seed **two** differing paths at minimum and assert
  **both** — one blocker is satisfiable by an implementation that reports the first and stops.
- **R3's one-sided case must be seeded on the UMBRELLA side too, in its own fixture.** A
  child-only extra file and an umbrella-only file are normalised by *different arms* — `Only in
  <child>/…` vs `Only in <umbrella>/…` — so a suite that only ever seeds the child side leaves
  the umbrella arm unpinned, and neutralising it degrades the refusal from
  `differs: agents/newfile.md` to `differs: agents` while every case stays green. "The umbrella
  is ahead of the child" is *Recorded decision E*'s state and the ordinary one after an umbrella
  upgrade, so it is the direction this feature exists for. It needs its **own** umbrella:
  seeding it in the `extra`/`shapes` umbrella would block `extra` for a second reason and
  dissolve the case above.
- **Byte identity has to be pinned by a WHITESPACE-ONLY difference, and nothing else can pin
  it.** The safety argument is "stubbed only when byte-identical"; `diff -rq` → `diff -rqw` is a
  one-character relaxation to identity-modulo-whitespace that CONVERTS a child that is not
  pristine, and every fixture whose seeded edit adds text passes under `-w` as well. Append a
  trailing space to line 1 — never new text — and assert as a precondition that the edit is a
  real byte difference *and* invisible to `diff -w`, or the case degenerates into the `AGENTS.md`
  shape and pins nothing. Seed it on `specs/glossary.md`: that is also the only prose-tier entry
  no other fixture makes differ, so the same case is what stops the sweep being rewritten as a
  hardcoded tier list that silently drops an entry.
- **R4's real proof is the mutation row, not an on-disk assertion.** "The tier is still a full
  copy afterwards" is the *trivially true* half — it is exactly today's shipped behavior
  (`harness-install.sh:2465-2469`), so an unmodified installer passes it. Assert it anyway for
  the record, but R4 is only genuinely proven by the mutation *"the unflagged path converts
  anyway"* failing, plus the preview line being present and naming the right target.
- **R5 must run the unflagged installer against a genuinely thin child** and assert the stubs
  survived. This is the regression lock on F03's maintenance branch; it fails loudly if
  `--thin` is implemented by gating that branch.
- **R6 needs a genuinely unreachable umbrella, and "move the umbrella root" does not produce
  one.** The cascade records a **relative** root (`../../`, derived at
  `harness-install.sh:6182-6201`), so renaming `<umb>` moves the child with it and `../../`
  still resolves — the test would quietly exercise the ordinary path. What actually breaks
  resolution while leaving a non-empty `umbrella.root`: delete `<umb>/.harness/.harness-version`
  (or `<umb>/.harness`), move the **child** out from under the umbrella, or rewrite the key to
  an absolute path that does not exist.
  Build the fixture as a **full-copy child of a reachable umbrella** (above), *then* break the
  umbrella. Starting from an already-thin child is the trap: the copy branch re-materialises a
  full body, so "the body is still full-copy" passes with R6 unimplemented. Assert three
  things: exit 0, the warning, and the body still full-copy.
- **R7 asserts bytes captured before the run**, not "the run said nothing changed".
- **R8 asserts drift-clean *after* an explicit commit, and dirty before it.** Without the
  "dirty before" half, a guard that never runs also passes.
- **R11 is not "the bytes did not change".** `--standalone` takes the ordinary copy branch, so
  a stale or edited full-copy target legitimately comes out **re-installed from source**. The
  assertion is the layout (no stub anywhere in the prose tier), the cleared key, and exit 0 —
  a byte-identity assertion here would encode a guarantee the design does not make and would
  pass only because the fixture happened to be pristine.
- **`f04_docs_contract` asserts an absence as well as a presence.** `docs/UMBRELLA.md` must
  name `--umbrella … --thin` as the migration command and must **not** present an unflagged
  cascade as step one of a migration — that procedure destroys the differences it reports
  (*Recorded decision E*), and it is the wrong doc a reviewer is most likely to write.
- **R10's control is the same file's other keys.** Assert `umbrella.manifest` and at least one
  hand-editable value in that config are untouched — a writer that clears the key by
  truncating the section would otherwise pass.
- **Never assert a literal count of prose-tier files** (today 30) and never assert a literal
  `VERSION`. Both change under unrelated work; both have already produced false failures here.

## Idiom constraints for this suite

- **`grep -c` counts matching *lines*, not occurrences.** Where a count is asserted, use
  `grep -o <pattern> | wc -l | tr -d ' '`. And never bind a possibly-zero `grep -c`/`grep -q`
  result directly under `set -eu` — `grep` exits 1 on no match and kills the suite before the
  assertion runs; guard with `|| true` and assert the value. **The same hazard applies to the
  product code this feature adds**: `diff` exits non-zero precisely in the interesting case,
  and `harness-install.sh` is `set -eu` (`:101`).
- **Any prose-contract assertion over `docs/UMBRELLA.md` uses a fence-aware section
  extractor** (`sect()`/`span()` as in `tests/test_stacked_doctrine.sh:66-76`). The bare house
  awk idiom stops at the first `#` inside a fenced block. To be precise about *why*, since a
  Builder who checks will find the present tense false: `docs/UMBRELLA.md`'s fences carry no
  `#` comments **today** — this is a forward-looking precaution, because T12 adds new fences
  to that very file and a `#` comment in one would truncate the span and make
  `f04_docs_contract` pass over text it never read. Do not delete the constraint on the
  grounds that the file is currently safe.
- **`grep`/`awk` on the development box are BSD.** No GNU-only flags (`grep -P`, `awk`
  gensub). `diff` output is never matched by wording — only by the tier-relative path the
  implementation normalises it into.
- Every fixture under its own `mktemp -d`; sandbox `CODEX_HOME` **and** `HOME` on every
  `harness-install.sh` invocation; suites must pass under `dash`.
