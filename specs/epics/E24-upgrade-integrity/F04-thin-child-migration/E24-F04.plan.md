# Migrate existing children to the thin layout (+ `--standalone`) — Technical Plan

> Every decision cites the `R-id`(s) it serves. The mechanism (tiers, stub text,
> `umbrella.root`) is F03's and `ADR-0004`'s; this plan adds a **gate**, a **comparison**,
> and a **reverse**.

## Stack & dependencies

- POSIX `sh` (must run under `dash`), the existing `awk` config readers/writers, and the
  existing `cp -R` / `cmp -s` idioms.
- **One new runtime command in `harness-install.sh`: `diff -r`.** Rationale below; it is
  POSIX, it is already relied on by several suites in `tests/`, and its absence is handled
  fail-closed rather than assumed away.
- No schema change, no new config key, no symlinks, no new tool file.

## The three moving parts

| Part | What it is | R-id |
|---|---|---|
| `THIN_OPT_IN` | a global set by `--thin`; decides **whether to act**, never **what to compute** | R1, R4 |
| `prose_tier_blockers` | one function: prints the prose-tier paths that block a conversion, empty when the tier is convertible | R1–R4, R6 |
| `STANDALONE` | a global set by `--standalone`; forces the full-copy branch in §1 and clears `umbrella.root` in §2a | R9, R10, R11 |

**The flag decides whether to act, never what to compute (R1/R4).** `prose_tier_blockers` runs
at the same point, over the same inputs, with the same result whether or not `--thin` was
passed. `--thin` chooses between *convert* and *report what would have happened*. One code
path, so the preview cannot drift from the action it previews — which is the whole value of
the preview.

## Where it hooks in  (serves: R1, R2, R4, R5, R6, R9)

`install_one` §1 already ends with exactly the branch this feature extends
(`harness-install.sh:2454-2470`):

```sh
_umb_body="$(umbrella_body_dir "$H")"
BODY_LAYOUT=full
if [ -n "$_umb_body" ] && ! child_is_full_copy "$H"; then     # ← F03: maintain thin (R5)
  BODY_LAYOUT=thin; ... stub_tree ...
else
  ... copy ...                                                # ← F03: full copy
fi
```

The new shape, stated as behavior rather than as code the Builder must copy:

1. `STANDALONE=1` ⇒ take the **copy** branch unconditionally, whatever `umbrella_body_dir`
   says (R9, R11). This is the only branch `--standalone` needs; the ordinary full-copy path
   already materialises the whole body from `$SRC`.
2. Otherwise, if the target resolves an umbrella body **and** is not already full-copy ⇒ stub,
   exactly as today. This is the F03 maintenance path and **it must remain reachable with no
   flag** — R5 is a regression lock on it, because the obvious implementation of `--thin`
   (gating the whole stub branch behind the flag) breaks every already-thin child on the next
   unflagged cascade.
3. Otherwise, if the target resolves an umbrella body and **is** full-copy — the F03 "left
   as-is" case — compute `prose_tier_blockers`:
   - blockers empty **and** `--thin` ⇒ **convert**: take the stub branch (R1).
   - blockers empty and no `--thin` ⇒ report "would convert … re-run with `--thin`", copy as
     today (R4).
   - blockers non-empty ⇒ copy as today, and report every blocker (R2, R3, R4). The message
     is identical with and without the flag except for its verb, and it states that those
     paths have been re-installed from source by this run — because they have, on both
     branches, exactly as every install has always done (*Recorded decision E*). Naming a
     path the operator can no longer read without saying where it went is worse than not
     naming it.
4. Otherwise (`umbrella_body_dir` empty) ⇒ copy, as today. Where `--thin` was passed **and**
   the config records a non-empty `umbrella.root`, emit the unreachable-umbrella warning
   (R6). Where no `umbrella.root` is recorded at all, say nothing: a coordinator and a
   single-repo target are not children, and `--thin` warning on every cascade's coordinator
   is noise that trains people to ignore the warning that matters.

Ordering is already correct and must not be changed: the check reads the target's on-disk
prose tier, and §1 has not yet written to it (`HARNESS_BODY_LOCAL` is copied first, the prose
tier last). A Builder who moves the check after the copy is comparing the installer against
itself and will get a green, meaningless "always convertible".

## The comparison  (serves: R1, R2, R3)

```
prose_tier_blockers <harness-dir> <umbrella-body-dir>
  → prints one line per blocking prose-tier path; prints nothing when convertible
```

**Reference = the umbrella body's copy, at the same relative path.** Not `$SRC`. The question
conversion asks is *"if I drop this content and point at the umbrella, does the child lose
anything?"*, and the umbrella's copy is the thing the stub will name. In a cascade the two
happen to coincide — `install_one "$UMB"` runs **before** the child loop
(`harness-install.sh:6084`), so the coordinator's prose body is `$SRC`'s — but they are not
the same reference and a single-target `--thin` run in a child proves it.

**Use `diff -r`; do not walk the trees.** The predicate needed is "are these two trees
identical", which is `diff -r`'s exit status — one call, no traversal of our own, no output
parsing for the *decision*. F03's `stub_tree` is the precedent and the scar: reimplementing
`cp -R`'s traversal in POSIX `sh` cost four blocking findings, one per filesystem shape
(nested dirs, recursion frames, `..name` and two-char dotfiles, directory symlinks), and it
was fixed by *calling the tool and post-processing*. Do the same here.

- **Decision:** `diff -rq <child>/<rel> <umbrella>/<rel>` per prose-tier entry; non-zero ⇒
  that entry blocks. The exit status is the contract.
- **`-q` is mandatory, not an optimisation.** Two `HARNESS_BODY_PROSE` entries are regular
  files, not directories (`harness-install.sh:700`): `AGENTS.md` and `specs/glossary.md`.
  `diff -r` on two regular files prints the **hunks and no filename at all**, so without `-q`
  those two entries can never be named and R3 would be satisfiable only by a fixture that
  happens to edit an `agents/*.md`.
- **Report (R3) — normalise `Only in`, do not emit `diff`'s wording raw.** The two messages
  are not equally usable:
  - `Files <a>/<rel> and <b>/<rel> differ` — contains the full path. Usable as-is.
  - `Only in <dir>: <name>` — contains the directory and the basename **separately**. The
    string `agents/extra.md` never appears, so a test asserting the path would fail against a
    correct implementation. This form must be rewritten to `<dir>/<name>` before it is
    emitted.
  - A whole tier entry absent on one side is a third case: `diff` exits **2** and writes
    `diff: <path>: No such file or directory` to **stderr**, so a stdout-only capture names
    nothing. Fold stderr in, or synthesise a reason line that contains the path.
  R3's contract is "**name every differing prose-tier path**", so the emitted line contains
  the tier-relative path in every one of those three cases. The test asserts that path and
  never the surrounding wording; never `grep -c` the output (see the test contract).
- **Capturing that output must not abort the install.** `harness-install.sh` runs under
  `set -eu` (`:101`), and `diff` exits non-zero exactly in the case this feature cares about,
  so a bare `_out="$(diff -rq A B)"` kills the run the moment a child differs — the same
  hazard the test contract documents for `grep`. Capture inside an `if`, or with `|| :`
  (`tests/test_installer_toggles.sh:435` is the in-repo precedent), and keep the exit status
  separately.
- **A path present on only one side blocks** (R2). This is not over-strictness: `stub_tree`
  begins with `rm -rf` + `cp -R "$SRC/<rel>"`, so a child-local extra file in the prose tier
  would be *deleted* by a conversion. Blocking is the only safe answer, and it is strictly
  safer than the ordinary copy path, which deletes it silently today.
- **Fail closed when the comparator is unavailable.** If `diff` does not resolve on `PATH`,
  treat the tier as non-convertible and say why. Same logic as *Recorded decision B*:
  byte-identity that cannot be **established** is not byte-identity. Defence in depth, in the
  same spirit as F03's `stub_files_in` write checks — not claimed as tested, because a
  portable fixture cannot remove `diff` from `PATH` without also removing it from the harness
  running the test.

## The conversion itself  (serves: R1, R7, R8)

**Reuse `stub_tree` unchanged.** A converted child must be byte-indistinguishable from a
fresh thin child — same shape, same stub text, same sentinel — and the only way to guarantee
that is to run the same function. Anything else creates a second definition of "what a thin
child looks like", which is how the two-copies-of-a-contract defect class starts.

That also gives R7 (idempotence) for free by construction: `stub_tree`'s output depends only
on the body-relative path and the configured umbrella root, never on `VERSION` and never on
the file it replaces (F03's R7). An already-thin child re-run under `--thin` reaches the
maintenance branch first (step 2 above) and never enters the conversion path at all — R7's
test must therefore assert bytes, not that a branch was skipped.

**R8 needs nothing new.** Stubs are ordinary tracked files at the same pathspecs;
`tools/harness-owned-paths.sh` expresses ownership as an **exclusion**, so every stub is
already inside the owned set and no path is added or removed. `BODY_LAYOUT=thin` on the
conversion branch makes `manifest.txt` record the layout through F03's existing text. If R8
needs a line changed in `harness-owned-paths.sh`, `init.sh` or the audit, this design has
drifted from `ADR-0004` and **that is the finding**, not a test to update.

## `--standalone`  (serves: R9, R10, R11, R12)

| Concern | Design |
|---|---|
| CLI shape | a modifier flag in **single-target** mode, applied to the ordinary positional target — so `harness-install.sh --standalone <target>` reads as the brief spells it, parsed like `--agents=…  <target>` |
| With `--umbrella` (R12) | abort with a usage error **before anything is written**: it names one target, and "re-materialise every child" is not a request anyone has made |
| With `--thin` (R12) | abort with a usage error **before anything is written**: the two flags ask for opposite layouts in one run |
| Materialisation | the **ordinary full-copy branch** of §1, sourced from `$SRC` — the installer's own body, exactly like every other install. No new copy path, and a `--standalone` run from a newer installer correctly lands the newer body |
| Clearing the key | `set_umbrella_root "$H/harness.config.yaml" ""` at §2a (`harness-install.sh:2516-2527`), which already exists, is idempotent and is section-scoped |
| Idempotence (R11) | a target that is already full-copy takes the same branch and produces the same result; the key is cleared either way |

`set_umbrella_root` writes `root: ""`, which is byte-identical to the shipped seed — so
clearing is a no-op on a target that never had one, and §2a should skip the write when the
value already matches, as the F03 path does, to keep an ordinary re-run byte-identical.

## `VERSION`: MINOR, and the argument rather than the assertion

`AGENTS.md` → Versioning: *MAJOR = breaking layout / `tasks.schema.json` change **requiring
target migration***. This feature is literally about migrating targets, so MAJOR is the
reading to take seriously rather than wave away.

It is **MINOR (✨)**, and *Recorded decision A* is what makes it so:

- **No target's layout changes without an operator explicitly asking.** `--thin` is required
  for the first conversion of each child (R1, R4). A target that never sees the flag is
  byte-identical to today — that is the definition of backward-compatible, and it is the
  opposite of "requiring target migration".
- **No format, schema or path changes.** No `tasks.schema.json` change, no new config key, no
  path added or removed from the harness-owned set. The two layouts and the config key are
  already shipped (F03, v0.54.0); this adds a transition between them.
- **It is reversible in-product**, by `--standalone` (R9) — a MAJOR-worthy migration is
  characteristically one you cannot walk back with a flag.

**And the counterfactual is the honest part of this argument:** had Decision A gone the other
way — conversion automatic on any cascade — MAJOR would have been correct, because every
existing child's installed layout would change on upgrade with no operator action. The
version level and the consent decision are the same decision seen twice.

## DO NOT TOUCH

- **`tools/harness-owned-paths.sh`.** Ownership is an exclusion, stubs sit at the same
  pathspecs, and the set is already correct in both layouts. Editing it to "know about"
  conversion reopens the false-positive class E99-F10 needed four corrections for.
- **`gen_body_stub`, `HARNESS_STUB_SENTINEL`, `HARNESS_BODY_PROSE`/`HARNESS_BODY_LOCAL`,
  `umbrella_body_dir`, `child_is_full_copy`.** The stub format, the tier split and the
  resolution rule are `ADR-0004` and out of scope. A converted child must be
  byte-indistinguishable from a fresh one; changing any of these makes that untestable.
- **`stub_tree` / `stub_files_in`.** Reused verbatim. Seven review rounds are encoded in those
  two functions' handling of symlinks, recursion frames, dot-names and read-only modes.
- **`remove_if_pristine` and the skill-unit stamps.** They are the ownership rule this feature
  *reuses the discipline of*; it does not extend, generalise or refactor them into a shared
  helper. Three call-shapes with one rule is fine; one helper serving three call-shapes is a
  refactor with its own review surface.
- **Every front-end glue generator** — all glue is program tier (`ADR-0003`). A glue generator
  changed by this feature means the tier line has been crossed.
- **`init.sh`'s drift guard and the E24-F02 landing audit.** They must pass unchanged in both
  layouts and across the transition. Needing a line there is the signal, not the fix.
- **PROJECT-OWNED paths** — `state/`, `progress/`, `specs/epics/`, `init.project.sh`,
  `specs/product.md`, and `harness.config.yaml` apart from the single `umbrella.root` scalar.

## Approach notes

- **The coordinator must never be converted.** It holds the authoritative body. It is
  protected by construction — no `umbrella.root`, no `HARNESS_UMBRELLA_ROOT` on its own
  `install_one` call, so `umbrella_body_dir` prints nothing — but *by construction* is exactly
  the kind of protection that quietly stops holding, so the test suite asserts it under
  `--thin` explicitly.
- **`--thin` works in single-target mode too.** Converting one child is a legitimate
  operation; `install_one` is shared, so this costs nothing beyond not forbidding it.
- **The `umbrella.root` doc edit goes in the comment block *above* the key, never as a
  trailing comment.** `harness.config.yaml:212` is exactly `  root: ""` — two-space indent, no
  trailing comment — and R10/R11's "clearing is byte-identical to the seed" property depends
  on `set_umbrella_root` reproducing that line verbatim. A trailing comment on that line
  breaks it silently.
- **Never print or assert a literal count of prose files.** The report's "would convert N
  paths" is computed at run time. A test that pins `30` fails the day someone adds an
  `agents/*.md` — the same defect class as freezing a `VERSION` string, which this repo has
  now paid for three times.
- **Mutation-test before hand-off, and commit first.** At minimum: make `prose_tier_blockers`
  always print nothing (R2, R3 must die; R1 must live); gate the F03 maintenance branch behind
  `THIN_OPT_IN` (R5 must die; R1 must live); make `--standalone` leave `umbrella.root` set
  (R10 must die); make the unreachable-umbrella path `die` (R6 must die). Confirm each
  mutation actually applied before reading the result — a surviving mutation is a real
  defect, not a retest.
