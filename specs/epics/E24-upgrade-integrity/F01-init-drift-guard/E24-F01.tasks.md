# `init.sh` drift guard — Task List

> The Builder's only worklist. One task at a time, in order.

- [ ] **T1** — In `init.sh`, add the drift-guard section between section 1 (structural
      checks, ends `init.sh:35`) and section 2 (TaskStore). Guard the whole block on
      `[ -f "$HARNESS_DIR/.harness-version" ]` and skip silently when absent.
      *(R1, R6)*

- [ ] **T2** — Inside the block, skip silently unless
      `git -C "$PROJECT_ROOT" rev-parse --is-inside-work-tree` succeeds. Suppress its
      stdout and stderr; a non-git directory is a normal state, not a diagnostic.
      *(R7)*

- [ ] **T3** — Read `${HARNESS_SKIP_DRIFT_CHECK:-}` (the `:-` is required under
      `set -u`). When non-empty, print one line saying the drift check was skipped by
      request, and skip. Place this check *after* T1/T2 so an override on a target with
      no install stays silent rather than announcing a skip of a check that never applied.
      *(R8)*

- [ ] **T4** — Define the pathspec set once, as a shell array or positional list, exactly
      as enumerated in `.plan.md` → *The path set*: `.harness/` plus the six
      `:(exclude)` project-owned entries, plus the six root-level generated-glue paths.
      Do not enumerate the harness-owned files.
      *(R4, R5)*

- [ ] **T5** — Run `git ls-files -- <pathspec>` **first**. If it returns zero lines, print
      a warning that the installed harness is not version-controlled and drift cannot be
      verified, then continue the gate without failing. Do not run `git status` in this
      branch.
      *(R9)*

- [ ] **T6** — Run `git status --porcelain -- <pathspec>`. On empty output print one
      success line and fall through to section 2.
      *(R10)*

- [ ] **T7** — On non-empty output, count the lines, print at most the first 10 paths, and
      when the count exceeds 10 print the `git -C … status --porcelain -- …` command that
      lists the rest. Then call the existing `fail()` helper with a message naming the
      count and stating that the installed harness is not committed. Mention
      `HARNESS_SKIP_DRIFT_CHECK=1` as the override.
      *(R2, R3)*

- [ ] **T8** — Create `tests/test_init_drift_guard.sh` per `.tests.md`. POSIX sh, zero
      dependencies, `mktemp -d` fixtures, sandboxed `CODEX_HOME` and `HOME` on every
      `harness-install.sh` invocation. Do **not** name it `test_drift_check.sh` (taken by
      E06-F06) and do not edit that suite.
      *(R1–R10)*

- [ ] **T9** — Run `sh tools/run-tests.sh` and confirm the whole suite is green, not just
      the new file. `init.sh` is on the hot path of several other suites; a regression
      there will surface as an unrelated failure.

- [ ] **T10** — Bump `VERSION` by one PATCH (`init.sh` is installed body) and add a
      `CHANGELOG.md` entry describing the guard, the escape hatch, and the ownership
      scoping.

- [ ] **T11** — Document the guard in `docs/INSTALL.md`: what trips it, what the message
      means, the `HARNESS_SKIP_DRIFT_CHECK` escape hatch, and the three inert cases (no
      install, no git, nothing tracked). Add one line to `docs/HARNESS.md` if it
      enumerates `init.sh`'s checks.
