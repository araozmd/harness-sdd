# The cascade lands the upgrade — Technical Plan

## The shared ownership helper (R8) — the core of this feature
New `tools/harness-owned-paths.sh`, POSIX sh, zero deps. It prints the git pathspecs the
harness owns, one per line, for a given harness directory:

```
tools/harness-owned-paths.sh body <harness-dir>   # the installed body, minus project-owned
tools/harness-owned-paths.sh all  <harness-dir>   # body + generated front-end glue
```

It carries the whole set built up over E24-F01 and E99-F10 — the `.harness/` exclusions, the
`.agents/` narrowing, the OpenCode glue, and the per-file `.codex`/`.gemini` resolution from
the `.harness/.model-agents/<tool>/` ownership ledger with its symlink and regular-file
refusals. That logic is **moved, not rewritten**: it is the reviewed set, and re-deriving it
would restart the four-round hardening E99-F10 just finished.

Both callers then resolve through it:
- `init.sh` reads it into `HARNESS_BODY` / `HARNESS_OWNED` in place of its inline arrays.
- `harness-install.sh`'s post-cascade audit calls it once per target.

**`init.sh` degrades if the helper is missing.** An install predating this feature, or a
partial copy, has `init.sh` but no helper. That must not hard-fail the gate every session —
consistent with every other ambiguous case in the guard, it warns once and skips the drift
check. `tools/` is harness-owned and ships together, so this is a torn-install path, not a
supported configuration.

## The audit (R1–R6, R9)
A new block at the very end of the cascade, after the `--shared-repo` step and before the
final `ok "umbrella cascade complete"`. It re-uses `INSTALLED_CHILDREN` (already accumulated
for `--shared-repo`) plus the coordinator `$UMB`.

Per target, exactly two reads, both read-only (R9):
1. `git -C <target> rev-parse --is-inside-work-tree` — not a work tree ⇒ report, do not count
   (R5).
2. `git -C <target> status --porcelain -uall -- <pathspecs>` — non-empty ⇒ unlanded, count the
   lines (R2, R4).

`-uall` for the reason E99-F10 established: an upgrade that ADDS a body file leaves it
untracked, and `status.showUntrackedFiles=no` would hide exactly the drift being audited.

Output shape:
```
── landing audit ──
   unlanded  viernes-bff        29 harness-owned path(s)
   unlanded  lia-api            27 harness-owned path(s)
   landed    viernes-web
   no git    infra-notes        (not a work tree — cannot verify)
❌ install: the cascade wrote an upgrade that is NOT COMMITTED in 2 of 4 target(s).
   Commit the harness files in each, or agents there will run on a body no commit describes.
```

## Exit codes (R3)
`die()` exits 1 for every installer failure today. The audit uses **`exit 3`**, so a wrapper
or CI job can tell "the install broke" (1) from "the install succeeded and is unlanded" (3).
Conflating them loses the distinction that makes the exit code actionable. Documented in the
usage header beside the existing flags.

## Files to create or change
| File | Change |
|---|---|
| `tools/harness-owned-paths.sh` | **New.** The single ownership definition. |
| `init.sh` | Resolve the pathspecs through the helper; degrade if absent. |
| `harness-install.sh` | Copy the helper into `.harness/tools/`; add the audit; document exit 3. |
| `tests/test_umbrella.sh` | Audit cases (R1–R7, R9). |
| `tests/test_init_drift_guard.sh` | Helper-missing degradation + a differential case for R8. |
| `docs/INSTALL.md`, `docs/UMBRELLA.md` | The audit, exit 3, and that it never commits. |
| `VERSION`, `CHANGELOG.md` | MINOR — new capability. |

`tools/` is already copied wholesale into `.harness/tools/` and chmod'd, so the helper ships
with no new installer wiring beyond an executable bit.

## DO NOT TOUCH
- Child discovery, `manifest_upsert`, `install_one`, the `--shared-repo` block.
- The dry-run branch — it `exit 0`s before the audit is reached; verify, do not restructure.
- `init.sh`'s guard *behaviour*. Only the source of its path list moves. The E24-F01 and
  E99-F10 test cases must pass unchanged — that is the regression contract for the extraction.

## Risks
- **Silent behaviour change during extraction.** The mitigation is that the whole existing
  drift-guard suite (30 assertions) must pass untouched; if extraction changes the set, those
  cases fail. R8 adds a differential case on top.
- **Audit cost.** Two git reads per target, once per cascade. Negligible against an install.
