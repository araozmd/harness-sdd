## The R8 differential — why this is not a "both call the helper" grep
Asserting that both files *mention* the helper proves nothing about agreement. The case is
**differential**: build one target, perturb a path, and require that `init.sh`'s verdict and
the cascade audit's verdict agree — across a matrix that includes a project-owned path (both
must ignore), a body path (both must flag), root glue (both must flag), and a user file in
the `.agents/` tree (both must ignore). A second inline copy that drifts fails the matrix even
though both files still reference the helper.

## Anti-tautology
- **R5, R7** assert a non-failure, satisfiable by an audit that never runs. Each is paired with
  a positive control on the same fixture: R5 also asserts a *git* child in the same cascade is
  audited and can fail; R7 asserts the same umbrella without `--dry-run` does run the audit and
  exits 3.
- **R6** ("all landed ⇒ 0") is paired with R2 on the same fixture, so "exit 0" is not reachable
  by an audit that is absent.
- **R9** compares `git rev-parse HEAD`, `git status --porcelain` (full, unfiltered) and the
  index mtime before and after — an audit that committed or staged anything changes at least
  one. Asserting "no new commit" alone would pass on an audit that staged without committing.

## Suite-wide constraints
Carried from the existing suites: never assert an exact `VERSION` literal; never couple a
CHANGELOG assertion to the top version; never `git diff` a DO-NOT-TOUCH file against `main`;
every fixture under its own `mktemp -d`; sandbox `CODEX_HOME` **and** `HOME` on every
`harness-install.sh` invocation.

## Non-functional
- `sh tools/run-tests.sh` fully green — in particular the **30 existing drift-guard assertions
  must pass unchanged**, which is the regression contract for extracting the path set.
- The suites must pass under `dash` (`/bin/sh` is dash on Ubuntu CI).
- `sh -n tools/harness-owned-paths.sh`, `bash -n init.sh`, `sh -n harness-install.sh` clean.
