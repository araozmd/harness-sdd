# The cascade lands the upgrade (or reports that it did not) — Functional Spec

## Context
`harness-install.sh --umbrella` prints `✅ umbrella cascade complete` after it has *written*
files. Whether any of it was committed is outside its model of "done". The `~/repos/viernes`
cascade produced exactly that green finish and five children each carrying 26–29 uncommitted
files, indefinitely.

E24-F01 closed the consumer side: `init.sh` now refuses to run on an unlanded harness. This
closes the producing side, so the guard is a backstop rather than the normal way anyone finds
out. One person upgrading N repos in one command is precisely the situation where N-way manual
follow-up gets skipped.

### Resolved during specification

**The commit path does not ship.** The brief left this open and asked for the smaller change
that fully fixes the problem. Report-and-exit does: the defect is that the operator was told
the upgrade was complete when it was not. Committing into N repos the operator did not ask you
to commit into is a much larger claim on their working tree, and the constraints it would have
to honor — never stage unrelated work, never touch a foreign branch — are exactly the accidents
this epic exists to prevent. `--dry-run` also proves the installer's own users expect it to be
conservative about writing.

**Ownership classification becomes shared code, not a second copy.** The brief required this
audit to reuse F01's answer. F01's pathspec set lives inline in `init.sh`; a second inline copy
in `harness-install.sh` would drift on the first feature that adds a body path — and E99-F10
already showed that set needs four corrections in its first week. It is extracted to one helper
both callers invoke. That also settles, in the smallest possible way, the concern raised after
E99-F10's third round: there is now one implementation of "what does the harness own".

## Business rules
- **The installer reports; it never commits.** No staging, no committing, no branch changes, no
  writes to any target's git state.
- **"Complete" is a claim about state reached, not files written.** A cascade that leaves work
  unlanded must not exit zero.
- **One definition of ownership.** The audit and `init.sh` resolve the checked paths through the
  same helper; they cannot disagree.
- **Ambiguity degrades to reporting, never to a failure.** A target that is not a git work tree
  cannot be "unlanded" — it is reported and does not fail the cascade.

## Architecture alignment
ADRs touched: none — `specs/architecture.md` is absent in this repo (graceful degradation per
`agents/architect.md`), and neither ADR-0001 (deterministic `next` selection) nor ADR-0002
(`builder-heavy` as a tier) is constrained by an installer-side post-cascade audit.

## Acceptance criteria (EARS)

- **R1** — When a cascade finishes, the system shall audit the coordinator and every child it
  installed into, and report for each whether its harness-owned paths are committed.
- **R2** — If any audited target has uncommitted harness-owned paths, then the system shall exit
  non-zero.
- **R3** — The exit code used for "installed but unlanded" shall differ from the code used for a
  generic installer failure, so a caller can distinguish "the install broke" from "the install
  succeeded and is unlanded".
- **R4** — The summary shall name each unlanded target together with its count of drifted paths.
- **R5** — Where an audited target is not a git work tree, the system shall report it as not
  version-controlled and shall not count it as unlanded.
- **R6** — When every audited target is landed, the system shall print one confirming line and
  exit zero.
- **R7** — Where `--dry-run` is given, the system shall write nothing and shall not run the audit.
- **R8** — The set of harness-owned paths the audit checks shall be produced by the same helper
  `init.sh` uses, so the two cannot diverge.
- **R9** — The system shall not stage, commit, or otherwise modify the git state of any target.

## Out of scope
- Committing or pushing on the operator's behalf, under any flag. See *Resolved above*.
- Single-target (non-umbrella) mode. The failure that motivated this is N-way; adding it to
  single-target mode would widen the diff for a case where the operator is already looking at
  the one repo they just installed into.
- Any change to what the cascade installs, or to child discovery.
- Any change to `init.sh`'s guard behavior — only the *source* of its path list moves.
