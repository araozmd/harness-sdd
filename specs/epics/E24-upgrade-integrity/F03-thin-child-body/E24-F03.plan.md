# Thin the child: umbrella-resolved body with local fallback — Technical Plan

## Stack & dependencies
- POSIX `sh` (must run under `dash`), plus the existing `awk`-based config readers.
- New dependencies: none. No symlinks, no new tool, no schema change.

## The two tiers  (serves: R2, R4, R5)

`install_one`'s body copy is a flat list of `copy <relpath>` calls
(`harness-install.sh:1888-1903`). It splits into two lists, and the split is the feature:

```sh
# RESOLVABLE — consumers read prose and can follow a reference (ADR-0004).
HARNESS_BODY_PROSE='AGENTS.md agents docs specs/_templates specs/glossary.md'
# STANDALONE — consumers PARSE or EXECUTE these; a pointer is not a schema.
HARNESS_BODY_LOCAL='init.sh store tools umbrella.manifest.example.yaml umbrella.gitignore.example'
```

`umbrella.manifest.example.yaml` and `umbrella.gitignore.example` are standalone-tier: they
are copied *from* by an operator setting up an umbrella, so a stub would be actively wrong.

Only the prose list can be stubbed, and only when an umbrella resolves. Everything else is
`copy` exactly as today — including every front-end glue generator, which is untouched by
this feature.

## Resolution  (serves: R1, R5, R6)

| Concern | Design |
|---|---|
| Where it is recorded | `umbrella.root:` in the child's `harness.config.yaml`, written by the cascade at `harness-install.sh:5136` (`install_one "$UMB/$name"`), which already knows the umbrella path |
| Value | the umbrella root **relative to the child's `.harness/`** (`../../`), so a whole umbrella tree stays movable and the value is diffable |
| Resolved by | one helper, `umbrella_body_dir <harness-dir>` — prints the absolute `<umbrella>/.harness` when it resolves, prints nothing otherwise |
| "Resolves" means | the path exists, is a directory, is **not** a symlink, and holds `.harness-version` — a directory that is merely present is not an installed body |
| No umbrella | prints nothing ⇒ every caller falls back to the full copy (R5) |

`umbrella.root` is read with the same section-scoped `awk` pattern the config already uses
for `telemetry.log` (`tools/harness-owned-paths.sh:157-168`) — reuse that shape rather than
inventing a third YAML reader, and strip both quote styles as it does.

## The stub  (serves: R3, R7)

One generator, `gen_body_stub <relpath> <resolved-umbrella-body> <dest>`. The text depends on
the **relative** umbrella path and the body-relative path — never on `VERSION`, never on
content — which is what makes R7 (byte-identical across upgrades) hold by construction rather
than by test.

```markdown
<!-- harness:umbrella-stub -->
# Umbrella-resolved: `agents/builder.md`

This repository's harness body is resolved from its umbrella. The authoritative copy of
this file is:

    ../../.harness/agents/builder.md

Read that file and follow it exactly. It — not this stub — is the role definition.

**If that path does not exist** you are in a checkout separated from its umbrella (a lone
clone, a CI job, a PR reviewer's tree). `.harness/init.sh`, the verification gate and the
PR loop all still work here; only the prose body is remote. To materialise a full local
copy, run the harness installer against this repository.
```

The `<!-- harness:umbrella-stub -->` sentinel on line 1 is the machine-readable marker: R9's
"is this child already full-copy?" test and the manifest reporting both key off it, never off
file size or a `grep` for prose.

## DO NOT TOUCH
- **`tools/harness-owned-paths.sh`.** Stubs are tracked files at the same pathspecs, so the
  ownership set is already correct. Editing it to "know about" stubs would re-open the exact
  false-positive class E99-F10 needed four corrections for.
- **The front-end glue generators.** All glue is standalone-tier. If a glue generator changes
  in this feature, the tier line has been crossed.
- **PROJECT-OWNED paths**, and `state/`/`progress`/`specs/epics/` in particular.
- **E24-F01's guard and E24-F02's audit semantics.** They keep working *because* stubs are
  ordinary tracked files; neither should need a line changed. Needing one is the signal that
  this design has drifted from ADR-0004.

## Approach notes

- **Ordering.** `umbrella.root` must be in the child's config *before* §1 copies the body,
  because §1 is what decides stub-vs-copy. The config seed/preserve stage currently runs
  after §1 — so the cascade writes the key itself, ahead of `install_one`, and the
  seed/preserve stage must **preserve** it like any other project-owned value rather than
  overwrite it.
- **R9 is a guard against this feature, not a feature.** A fresh cascade into an existing
  full-copy child must not silently swap 29 files to stubs — that is E24-F04's job, with its
  own pristine check. Detect via the sentinel: a resolvable-tier file that exists and does
  **not** start with `<!-- harness:umbrella-stub -->` means full-copy, so leave the whole
  tier alone and report it.
- **Assert fixture preconditions.** Every "the stub is there" case must first assert that the
  same path in a **non**-umbrella install is a full copy — otherwise "contains the sentinel"
  is satisfiable by a body that was never written at all. Same for R7: capture the stub bytes,
  bump `VERSION` in the source, re-run, compare — with a positive control proving the
  standalone tier *did* change in that same run, or the test proves only that nothing ran.
- **R6 needs a genuinely unreachable umbrella**, not a missing key: build a thin child, then
  move or rename the umbrella root, then run `init.sh`. A test that merely omits
  `umbrella.root` exercises R5's full-copy path instead and would pass with R6 unimplemented.
- **Mutation-test before hand-off.** Commit first. At minimum: force `umbrella_body_dir` to
  print nothing (R2 must die, R5 must live), make the stub text include `VERSION` (R7 must
  die), and make `init.sh` treat an unreachable umbrella as a failure (R6 must die).
