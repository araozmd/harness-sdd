# Thin the child: umbrella-resolved body with local fallback — Functional Spec

## Context

Every child in an umbrella carries a full copy of the harness body — 26–29 files per child,
five times over in the `~/repos/viernes` cascade, byte-identical, each able to diverge on its
own and each producing its own diff on every upgrade.

"Stop copying" is not available. The generated front-end glue resolves body paths **inside
the child's own `.harness/`** (`opencode.json` interpolates `{file:./.harness/agents/*.md}`,
the Codex role TOMLs say "Read `.harness/agents/<role>.md`"), so a body file can never be
absent from a child — only **redirected**. And redirection only works where the consumer
reads prose: `init.sh` `exec`s `tools/validate-board.py` and parses `store/tasks.schema.json`,
and a program cannot follow a pointer.

`ADR-0004` records the resulting design: **the prose tier becomes pointer stubs at the same
paths; the program-read tier stays a full local copy.**

### Resolved during specification

**The tier line is drawn by consumer, not by duplication.** The brief's open question asked
the Architect to derive it from "what does a child-rooted session actually read?" — the
answer is *everything*, which is why "what reads it, and can that reader follow a reference?"
is the question that actually separates the two tiers.

**This feature does not migrate existing children, and the honest reason is size.** The
mechanism (record the umbrella, stub the prose tier, keep the standalone tier) and the
migration of already-installed full-copy children (a destructive, pristine-only replacement,
plus a `--standalone` flag to re-materialise a full body) are separable, and specifying them
together exceeds what one review pass covers. Per E21 that split is declared here rather than
discovered at PR time: an existing target keeps its full copy, `manifest.txt` records which
layout it is in, and **E24-F04** carries the migration.

**The saving is large but not total.** The resolvable tier is `AGENTS.md`, `agents/` (11),
`docs/` (7), `specs/_templates/` (9) and `specs/glossary.md` — 29 of roughly 42 body files.
`init.sh`, `store/` (6) and `tools/` (15) stay local copies and still change on upgrade. The
claim is "an umbrella upgrade stops rewriting the prose body in N children", not "zero diffs".

## Business rules

- **Standalone entry is the acceptance bar.** A child entered on its own runs `init.sh`, runs
  its verification gate, and runs its PR loop. A design that breaks this is wrong regardless
  of how much duplication it removes.
- **Redirect only what reads prose.** A file whose consumer parses or executes it is never
  stubbed. When a new body file's tier is unclear, it belongs in the standalone tier — the
  wrong answer there costs a copy, the wrong answer the other way breaks a child at parse time.
- **The umbrella is recorded, never searched for.** An upward filesystem search binds a child
  to whatever ancestor happens to match.
- **No umbrella is a normal state, not a failure.** `init.sh` hard-fails on a broken
  environment, so "no umbrella found" must be unambiguously *not* broken.
- **Nothing is deleted from an existing target.** This feature only changes what a *fresh*
  child install writes.
- **The stub says what to do.** An unreachable umbrella must produce a legible instruction,
  not a dangling reference.

## Architecture alignment

- platform ADR-0004 — *a child resolves the harness body through pointer stubs at the same
  paths*: this feature is that decision's implementation — the tier split, the explicit
  `umbrella.root` key, stubs rather than symlinks, and the full-body fallback when no
  umbrella is recorded.
- platform ADR-0001 — *deterministic `next` selection*: untouched. Board state is
  project-owned and stays per-child; nothing about task selection moves to the umbrella.
- platform ADR-0003 — *one shared skill unit per command*: honored. The skill units are
  generated front-end glue and therefore standalone-tier — a thin child keeps its own,
  claimed and reclaimed exactly as today.

## Acceptance criteria (EARS)

- **R1** — When the cascade installs into a child, the system shall record that child's
  umbrella location in the child's `harness.config.yaml` as `umbrella.root`.
- **R2** — Where a child's `umbrella.root` resolves to a directory holding an installed
  harness body, the system shall write each resolvable-tier path as a pointer stub instead of
  a full copy.
- **R3** — Each stub shall state that the umbrella copy is authoritative, name the resolved
  path of that copy, and name the recovery step to take when the path is unreachable.
- **R4** — The system shall write the standalone tier — `init.sh`, `tools/`, `store/`,
  `harness.config.yaml`, the version stamp, the entrypoint blocks and every generated
  front-end glue file — as full local copies in every install, thin or not.
- **R5** — Where `umbrella.root` is absent, empty, or does not resolve to an installed harness
  body, the system shall install the complete body locally exactly as it does today.
- **R6** — While a thin child's umbrella is unreachable, `init.sh` in that child shall still
  exit zero and shall report the unreachable umbrella as information, not as a failure.
- **R7** — When the cascade is re-run at a different `VERSION`, the system shall leave a thin
  child's stub files byte-identical.
- **R8** — The system shall record in `manifest.txt` which paths a target holds as stubs and
  which it holds as local copies.
- **R9** — If a child already holds a full local copy of the resolvable tier, then the system
  shall leave those files unchanged and shall report that the child is in the full-copy
  layout.

## Out of scope

- **Migrating already-installed full-copy children**, and the `--standalone` flag that
  re-materialises a full body in a thin child. Both are **E24-F04**; see *Resolved above*.
- **PROJECT-OWNED paths.** `harness.config.yaml`, `init.project.sh`, `specs/product.md`,
  `specs/epics/`, `state/`, `progress/` stay per-child, always. Per-repo facts —
  `verification.test_command`, a language-tuned `change_size` budget, the child's own board —
  are not shareable, and moving them would break the standalone verification this feature
  exists to protect.
- **Single-repo installs.** With no umbrella recorded, nothing changes.
- **Changing what the coordinator does with slices, specs, or dispatch.** `docs/UMBRELLA.md`
  is correct as written; slicing is already umbrella-side.
- **Symlinking any body path.** ADR-0004 rejects it explicitly.

## Open questions

- **Should `--shared-repo` track anything differently at the umbrella root now that the
  umbrella body is authoritative for N children?** It already tracks `.harness/`, which is
  exactly the body being pointed at, so the answer is probably "no change" — but it is worth
  one deliberate look during implementation rather than an assumption.
