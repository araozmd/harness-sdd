# Feature-size budget in the Driller and Architect — Technical Plan

## Stack & dependencies
- POSIX sh (installer), markdown (agent role prompts), YAML (config). No new dependencies.

## Config surface  (serves: R1, R2)
New top-level block in `harness.config.yaml`, additive and inert-by-absence, matching the
`fix_lane:` / `models:` convention:

| key | default | meaning |
|---|---|---|
| `advise_lines` | `1500` | production lines added: split, or record one line saying why not |
| `escalate_lines` | `3000` | production lines added: recorded split plan, or an explicit override naming the reason |
| `advise_files` | `25` | files touched, advise tier |
| `escalate_files` | `50` | files touched, escalate tier |
| `max_requirements` | `12` | `R-id`s in ONE feature spec — the drill-time proxy |

The line/file keys are **defined here and consumed by E21-F02**; this feature only needs
`max_requirements` to be actionable, but shipping all five at once avoids a second config
migration for the sibling feature and keeps one source of truth for the numbers.

## DO NOT TOUCH
- `store/tasks.schema.json` — the budget is advisory and produces no new board field. Adding
  one would make an advisory rule into persisted state the Orchestrator would have to honor.
- `agents/orchestrator.md` — the Orchestrator neither decomposes nor specs; routing is
  unchanged by this feature. (E21-F02 touches the Reviewer→PR handoff; not this one.)
- `tools/tasks-lock.py`, `tools/validate-board.py` — no board write and no schema change.

## Approach notes
- **Presence check must tolerate a trailing comment** (`^change_size:[[:space:]]*(#.*)?$`),
  exactly as `models:` does, or a target that annotated the line gets a duplicate block on the
  next upgrade.
- **Fresh vs upgraded install must converge.** A fresh install copies `harness.config.yaml`
  verbatim; an upgrade only migrates. The heredoc in the installer must therefore be
  byte-identical to the block appended to the source config, or the two paths drift.
- **The prompts read the config, they do not restate the numbers.** Each role file names the
  keys and describes the behavior; the defaults appear once, in the config, with the doc
  repeating them as documentation rather than as a second source of truth.
- The Architect's stop-and-report is a *report to the human*, not a `blocked` record — the
  Orchestrator's `blocked` vocabulary is a closed set tied to dependency and ownership
  conditions, and size is neither.
