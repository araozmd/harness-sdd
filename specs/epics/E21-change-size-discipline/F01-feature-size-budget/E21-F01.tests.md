## Behavioral / end-to-end checks
- A fresh install copies `harness.config.yaml` verbatim; an upgrade only migrates. Both paths
  must converge on the same text, so the installer's heredoc is byte-identical to the source
  config's block — verified by regenerating the source block *from* the installer heredoc.
- Re-running the installer over a target that annotated `change_size:` neither duplicates the
  block nor rewrites the annotated line.

## Mutation checks — every assertion must die to its own mutation

| # | Mutation | Expected | Result |
|---|---|---|---|
| M1 | Delete the `change_size:` heredoc from the installer's migration path | R3 test fails | ✅ died |
| M2 | Replace the presence check with the anchored `^change_size:$` (no trailing-comment tolerance) | R3 annotated-line case duplicates the block and fails | ✅ died |
| M3 | Delete the never-`blocked` sentence from `agents/driller.md` | R6 test fails | ✅ died |
| M4 | Delete the override-line requirement from `agents/architect.md` | R8 test fails | ✅ died |
| M5 | Silently retune a shipped default (`max_requirements: 12` → `40`) | R1/R2 test fails | ✅ died |

> **M2 initially SURVIVED and the mutation was wrong, not the test.** The first attempt
> replaced the pattern with `^change_size:` — dropping the trailing-comment clause *and* the
> `$` anchor, which leaves a prefix match that still tolerates a trailing comment. The mutant
> has to keep the anchor (`^change_size:$`) to actually remove the tolerance. Recorded here
> because the same shape — a mutation that neuters itself — is how a guarantee ends up
> asserted by nothing.
