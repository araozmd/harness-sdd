# Pre-PR change-size check — Functional Spec

## Context
E21-F01 put a budget where the sizing *decision* is made. This feature puts a measurement
where that decision is last *reversible*.

The Orchestrator's flow is: local Reviewer approves → create the PR → request review. Nothing
between approval and the PR looks at how large the branch actually is. On
`viernes-bookings-api` E14-F05 the branch was 17,202 additions across 77 files before any
number was attached to it, and the first entity to notice was a paid reviewer, twelve times.

Splitting is cheap before the PR exists and expensive after — a PR carries review threads, a
review history, and a `depends_on` edge someone is waiting on.

## Business rules
- The check **never blocks**. It exits 0 at every tier and asks for a *recorded decision*.
  Only a usage error (not a repo, no base ref, bad flag) is non-zero, and that measures nothing.
- It reports **where** the lines are, not just how many. Review risk concentrates — 10% of
  PR #76's files carried 67% of its findings — so a bare total is true and unactionable.
- It measures against the **merge base**, because the branch may be rebased or carry merges
  and only the merge base is what a reviewer will read.
- Budgets come from E21-F01's `change_size:` block. One source of truth; this feature adds no
  second set of numbers.
- Classification is **configurable and additive**. A wrong classifier does not make the number
  slightly off — it makes it meaningless.

## Architecture alignment
ADRs touched: none — this adds a read-only local measurement and two prompt edits; it changes
no recorded structural decision.

## Acceptance criteria (EARS)

- **R1** — The system shall exclude test files, spec/progress/doc files and declared
  generated or vendored paths from the production line and file counts.
- **R2** — When the production counts exceed `advise_lines`/`advise_files` the system shall
  report tier `advise`, when they exceed `escalate_lines`/`escalate_files` it shall report
  tier `escalate`, and in every case it shall exit 0.
- **R3** — The system shall trip a tier on the **file** count independently of the line count.
- **R4** — Where the target's config carries no `change_size:` block, the system shall use the
  documented defaults (1500 / 3000 / 25 / 50).
- **R5** — The system shall measure the diff from the merge base of `HEAD` and the base ref,
  so a base ref that has advanced since branching does not distort the count.
- **R6** — While the branch is over budget, the system shall list the production files
  carrying the most additions; and while it is inside the budget it shall not.
- **R7** — Where `change_size.test_paths` or `change_size.generated_paths` are configured,
  the system shall **add** those patterns to the built-in classifiers rather than replacing them.
- **R8** — If invoked outside a git repository, with an unresolvable base ref, or with an
  invalid `--format`, then the system shall exit 4 having measured nothing.
- **R9** — The Reviewer shall run the check before approving and record the tier and the
  resulting decision; the Orchestrator shall run it before opening the PR and carry the tier
  into the PR body.
- **R10** — The installed harness body shall carry `tools/change-size.sh` as an executable
  file, and the installed role files shall reference it.

## Out of scope
- Blocking a PR, or any hard cap.
- Judging *risk* per file. The check reports where the lines are; it does not claim to know
  which of them are dangerous.
- Anything in `/sdd-pr-loop` — this must work on a target where `pr_loop.enabled: false` and
  no PR loop exists at all.

## Open questions
- The built-in classifier covers JS/TS, Python, Go, Ruby, Java/Kotlin/C# and the common
  lockfiles. Ecosystems beyond that rely on `test_paths`; whether the defaults should grow or
  stay deliberately small is unsettled.
- The override is currently recorded in the Reviewer's verdict and the PR body. A machine-
  readable record (telemetry, or a board field) was rejected for now: telemetry is
  gitignored and local-only, which is wrong for an audit trail someone else must read.
