# Pre-PR change-size check — Test Contract

Behavioral, not textual. Every assertion drives the tool against a **real throwaway git repo**
with a known diff, because the value of this feature is the number it produces — a grep over
the script would prove nothing about whether a test file is counted as production, which is
exactly the failure that makes the number meaningless.

## Fixture notes (learned the hard way)
- The fixture repo **gitignores its own `.harness/`**. The suite rewrites
  `.harness/harness.config.yaml` between assertions to vary the budget; without the ignore
  those rewrites land in the measured diff, the tool correctly counts the config as
  production, and every expected count drifts. The first draft of R7 failed for exactly this.
- R7 uses `spec/thing.rb`, **not** `thing_spec.rb`. The latter already matches the built-in
  `[._-]spec.<ext>` pattern, so it would have "passed" while proving nothing about the config
  hook — a test that cannot fail for the reason it claims to test.
- R5 writes its extra main-side commit at the repo root, because `src/` exists only on the
  feature branch.
