# Pre-PR change-size check — Technical Plan

## Stack & dependencies
POSIX sh + `git` + `awk` only — matching `init.sh`'s zero-dependency ethos and
`tools/fix-worktree.sh`'s shape. No `gh`, no network: the check runs *before* a PR exists, so
there is no PR number to query and nothing to ask GitHub about.

## Interface  (serves: R2, R8)
`tools/change-size.sh [--base <ref>] [--format text|json] [--repo <dir>]`

| exit | meaning |
|---|---|
| 0 | measured — at ANY tier (`ok`, `advise`, `escalate`). The tier is in the output. |
| 4 | usage error / not a git repo / no usable base ref — nothing measured |

There is deliberately no non-zero exit for "too big". A tool that can fail a branch for being
large would be a hard cap wearing an advisory label, and the first response to it would be to
stop running it.

## DO NOT TOUCH
- `store/tasks.schema.json` — the tier is advisory output, not persisted board state.
- `tools/wait-for-codex.sh`, `.claude/commands/sdd-pr-loop.md` — this check must work with
  `pr_loop.enabled: false`; coupling it to the loop would make it disappear where it is most
  needed (a repo with no automated review at all).
- `agents/driller.md`, `agents/architect.md` — E21-F01 owns those; the budget numbers are
  defined once and consumed here.

## Approach notes
- **Section-scoped YAML reads.** Budgets are parsed with the same `awk` idiom the installer's
  `_cfg_*` helpers use, anchored on the top-level `change_size:` header, so a same-named key
  elsewhere in the file is never picked up.
- **`LC_ALL=C`.** The script's `case` globs and `sort` must mean ASCII regardless of the
  caller's locale — the E99-F03 failure mode, already paid for once.
- **Classifier order matters**: generated → test → doc → production. Generated wins first so a
  vendored `*.test.js` is excluded rather than inflating the test count.
- **Binary files** (`-` in `git diff --numstat`) carry no line count and are skipped rather
  than counted as zero-line production files.
