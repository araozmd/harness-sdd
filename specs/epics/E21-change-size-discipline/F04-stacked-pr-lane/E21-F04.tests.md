Driven offline against fixture JSON, so the guard is exercised without `gh`, without a
network, and without a real stack — the same shape as `wait-for-codex.sh evaluate`.

## The assertion that matters
R4. A guard that silently treats an unreadable base as "the default branch" is worse than no
guard: it reports success on exactly the input it cannot evaluate, which is how a child PR
gets merged ahead of its parent by the mechanism installed to prevent it. The fixture feeds a
`pr.json` carrying `headRefOid` but no `baseRefName` — a shape a truncated fetch really
produces — and requires exit 4.

## Not covered here (and why)
- **Automated restacking** is out of scope for this feature, so nothing tests it. A rebase of
  children after a parent's review fix is a `git` workflow question; automating it wrongly
  loses commits, and `docs/WORKFLOW.md` states plainly that it is manual.
- **A live stack against GitHub.** The guard's whole design is that it needs no network; the
  caller's two `gh` invocations are ordinary reads already used elsewhere in the loop.

## Non-functional checks
- No new dependency: `jq` was already a `/sdd-pr-loop` precondition, and
  `test_init_has_no_new_dependency` still passes with neither `gh` nor `jq` on PATH.
- `./init.sh` clean; full `verification.test_command` suite green.
