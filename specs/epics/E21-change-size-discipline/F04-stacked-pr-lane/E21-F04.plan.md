# Stacked-PR lane — Technical Plan

## Stack & dependencies
POSIX sh + `jq`, already a `/sdd-pr-loop` precondition. `gh` is used by the *caller* to fetch
JSON; the guard itself is **offline** and takes files, which is what makes it testable without
a network or a real stack.

## Interface  (serves: R1–R5)
`tools/pr-stack-guard.sh evaluate <pr.json> <open-prs.json> [--default-branch <name>]`

| exit | meaning |
|---|---|
| 0 | safe — base is the default branch, or no open PR owns the base |
| 6 | **stacked** — the base is another open PR's head; merge the parent first |
| 4 | usage error / unreadable input (fail closed) |

`6` is deliberately its own code. Folding it into a generic failure would label a perfectly
healthy child PR `needs-human` on every round while its parent is still in review.

## DO NOT TOUCH
- `tools/wait-for-codex.sh` — a stacked base must not perturb the exit-code contract, the
  three clean-signal forms, or the `created_at >= trigger` freshness rule.
- `tools/pr-round-trend.sh` — E21-F03 owns it; a stack changes which PR is measured, not how.
- `store/tasks.schema.json` — no board representation for a stack in this feature.

## Approach notes
- **Fail closed on an unreadable base**, mirroring step 3's `head_ok` discipline. A base we
  could not read is not "the default branch"; assuming it is, is precisely how a guard meant
  to prevent out-of-order merges permits one.
- **Both command copies**, again — the source-layout file and the installer heredoc. The test
  asserts against the installed body.
- The guard answers one question and returns. It does not merge, does not rebase, does not
  reorder — anything more would need to own the `git` workflow, which this lane deliberately
  leaves to a human.
