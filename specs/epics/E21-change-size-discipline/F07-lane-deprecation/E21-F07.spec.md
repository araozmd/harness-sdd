# E21-F07 — Deprecate the stacked-PR lane and reclaim its machinery

The gate answered E21-F06's opening question — *does the stacked-PR lane earn its
keep?* — with **NO** (2026-08-17, recorded on the E21-F06 park). The sibling-feature
model already delivers budget-sized reviews with zero new machinery; measured, 0 of the
last 100 PRs targeted a non-default base, so `tools/pr-stack-guard.sh` has never fired.
This feature removes the lane per the design principle that a dead gate in a merge path
is indistinguishable from a live one (`docs/RATIONALE.md` → ablation doctrine).

## Requirements (EARS)

- **R1** — When the harness is installed or upgraded, the system SHALL NOT ship
  `tools/pr-stack-guard.sh`: the file is removed from the source tree, from the
  install copy list, and an upgrade SHALL reclaim the orphaned
  `.harness/tools/pr-stack-guard.sh` from an existing target.
- **R2** — The `/sdd-pr-loop` command body (source copy AND installer heredoc) SHALL
  contain no stacked-PR machinery: no base-change detection step, no merge-order
  guard invocation, no `guard_deferred` / exit-6 branch, and no restack instructions;
  the merge path is the single default-branch lane.
- **R3** — `docs/WORKFLOW.md` SHALL replace the stacked-PR lane section with a short
  deprecation notice that names the sibling-feature split (`depends_on`-sequenced
  features, E21-F01 R4) as the supported answer to an over-budget feature.
- **R4** — While a PR targets the default branch, the pr-loop's decisions SHALL be
  unchanged by this removal (the existing default-lane suites remain green), and a
  test SHALL prove no live reference to the guard remains in the source tree outside
  history/changelog/deprecation prose.
- **R5** — The E21-F04 spec SHALL record, append-only, that E21-F07 superseded the
  shipped lane, so a done spec does not describe behavior that no longer exists.
- **R6** — `VERSION` SHALL bump MINOR with a CHANGELOG entry justifying the removal
  (never-fired guard; reclamation included). When `pr_loop.enabled` is false the
  change SHALL remain inert (nothing new is stamped or executed).

## Out of scope

The sibling split model (unchanged); E21-F06 (not to be built); any other
`/sdd-pr-loop` behavior.
