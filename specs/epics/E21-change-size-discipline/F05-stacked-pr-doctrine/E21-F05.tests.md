> test. The Reviewer fails the feature if any `R-id` lacks a passing test.

All tests live in **one new suite, `tests/test_stacked_doctrine.sh`**, auto-discovered by

## Two mechanics every assertion in this suite depends on

**1. Extract the section first, with the FENCE-AWARE extractor.**

```sh
# sect <file> <heading-text> — ONE section body; stops at the next heading of ANY level.
sect() { awk -v h="$2" '/^```/{f=!f} !f && /^#+ /{k=(index($0,h)>0);next} k' "$1"; }

# span <file> <h2-heading-text> — a whole `## ` section INCLUDING its `###` subsections.
span() { awk -v h="$2" '/^```/{f=!f} !f && /^## /{k=(index($0,h)>0);next} k' "$1"; }
```

The `/^```/{f=!f}` toggle is not decoration. The house idiom at `agents/builder.md:87` is
fence-blind, and every shell fence in this document contains `#` comments. Measured on `main`
against the very file this feature edits: `sect docs/WORKFLOW.md '### Creating stacked
increments'` returns a `gh pr create` count of **1** with the bare idiom and **4** with the
fence-aware one. Any assertion counting inside a fenced section would pass on a section it
never read. A whole-file grep is forbidden for the same class of reason: it is satisfied by any
unrelated occurrence elsewhere, including one the same change just added.

**Both helpers are fence-aware, `span()` included.** `span()` would be safe on `main` as
written without the toggle — no shell comment in the lane's fences begins with `## ` — but
`span()` carries *every* ban sweep and *every* uniqueness count in this suite, and the Builder
is rewriting those very fences (T4, T6). A `## `-prefixed comment introduced inside a lane
fence would truncate the span and make three bans pass **vacuously**: exactly the defect class
that caused this re-drill. The toggle costs one clause and changes nothing today, so the
suite does not rely on the exemption.

**2. Count occurrences with `grep -o | wc -l`, never with `grep -c`.** Two separate hazards:

- **`grep -c` counts matching LINES, not occurrences.** Prose in `docs/WORKFLOW.md` wraps at
  ~92 columns, so two copies of an anchor on one physical line report `1`. Every "stated once"
  assertion below would then be satisfiable by the very duplication it exists to forbid.
  (Today's defect happens to sit on two different lines, which is why the "fails today"
  measurement of **2** is right and hides the hole.)
- **A possibly-zero `grep -c` bound under `set -eu` kills the suite on its PASSING path.**
  `grep` exits `1` on no match, so `n="$(… | grep -c foo)"` aborts silently. Verified on this
  machine: `sh -c 'set -eu; n="$(printf "a\n" | grep -c zzz)"; echo $n'` exits 1 and prints
  nothing.

Two legal forms only, and both dodge both hazards:

```sh
n="$(span "$WF" "$LANE" | grep -oi 'feature flag' | wc -l | tr -d ' ')"   # count
if span "$WF" "$LANE" | grep -qi 'atomic'; then fail "…"; fi              # absence
```

`wc` is the pipeline's last command and exits `0` on empty input, so the count form is safe
under `set -eu` with no `|| true`. `grep` here is **BSD grep**: `-o` is supported, `-P` is not,
and `(R[0-9][0-9]*)` is a BRE in which the parentheses are literal.

## Behavioral / end-to-end checks

- **Mutation check, mandatory (task T12).** For each `R-id`, revert its edit in place or perturb
  the single anchor it asserts, run the suite, and confirm it fails **with the symptom the
  failure message names** — not merely that something failed. Restore afterwards. Record the run
  in `progress/<run>/`.
  **One carve-out, named:** R8's *installed* half. The only mutation that makes it fail is
  removing `docs` from `HARNESS_BODY_PROSE` inside `harness-install.sh`, which is DO NOT TOUCH.
  Prove it discriminates against a **copy** of the installer inside the fixture directory, or
  record in `progress/<run>/` that it is a regression guard on a file this feature does not
  change. Do **not** edit the repo's installer, and do **not** tick T12 having skipped it
  silently. Every other assertion in the suite is over a file this feature edits.
- **Fence regression check.** Run one section-scoped count with the bare (fence-blind) idiom and
  with the fence-aware `sect()` on the *unedited* file and confirm they disagree (**1** vs
  **4** on `### Creating stacked increments`). That is the concrete demonstration that the
  extractor, not the count, is what makes these assertions real.
- **Heading-misfile check.** Move one correct paragraph — the entry condition is the clearest —
  under a neighbouring heading and confirm its test fails. This is the failure mode the whole
  extract-by-heading design exists to catch.
- **Installed-target read.** R8 reads the installed copy, not the source tree, so the test
  describes what a consumer actually receives.
