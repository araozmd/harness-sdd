# The stacked-PR lane's doctrine document — Tasks

> Small, sequential, independent steps. The Builder works these top to bottom, one at a time.
> Each task names the `R-id`(s) it satisfies. Check off when done. (The template's usual
> one-word description of a task's size is itself banned vocabulary in this feature.)
>
> **Read first:** `E21-F05.plan.md` → *Files to change*, *DO NOT TOUCH*, and the `sect()` /
> `span()` helpers; and `specs/epics/E21-change-size-discipline/F04-stacked-pr-lane/` for what
> is already shipped. This feature writes **prose and tests only** — no production code, and
> **no `agents/` file at all**.
>
> **Headings are part of the contract.** The suite extracts by heading, so a correct paragraph
> filed under the wrong subheading fails. If a heading below does not fit the prose you end up
> writing, hand back to the Orchestrator rather than renaming it in isolation.
>
> **Three vocabulary bans hold across every task, and across your commit messages:** no
> atomicity language anywhere, no `wave` inside the lane, no bare `(R<n>)` inside the lane.
