  subsection. Reduce them to: what the lane is for (bounding the size of each review), the

- [ ] **T2** (R1, R2) — Insert a new `### Entry condition` as the **first** subsection of the

  default branch, **and** every increment passes `verification.test_command` on its own. Then the
  refusal: a feature that cannot meet both is not a candidate — do not stack it; use feature
  flags to gate the incomplete work, or an aggregate landing strategy; and getting such a feature
  onto the default branch in one visible step is **an open problem this epic does not solve**.
  Use the phrases `independently safe`, `first increment PR` and `this epic does not solve`
  verbatim — they are asserted (see `E21-F05.tests.md` → load-bearing anchors). This subsection
  is the **only** place in the repo that states the condition.
