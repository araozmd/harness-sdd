## The design decision this feature turns on: how a doctrine statement gets a test

Carried from the predecessor spec — this answer **survived Codex review** and is not
re-derived. **Answer: greppable assertions, anchored on identifiers the system already owns,
extracted per section — not prose-only, and not frozen sentences.**

- **Prose-only is disqualified by measurement, not taste.** The predecessor of E21-F04 shipped
  a *false* doctrine claim that survived four `@codex review` rounds precisely because nothing
  could fail on it. For a feature whose entire deliverable is prose, an untested requirement is
  an unverifiable one, and `agents/reviewer.md` (a passing test per `R-id`) has nothing to check.
- **Freezing whole sentences is the opposite failure.** It turns every legitimate copy-edit
  into a red build, and the cheapest way out of a red build is to paste the sentence back.
- **So anchor on identifiers, not on English.** Where the requirement has a name the system
  already owns — `verification.test_command`, `pr_loop.enabled`, `baseRefName`, `change_size`,
  `E21-F01`, `(R<n>)` — assert *that*. An editor may reword freely around a config key; they
  cannot delete the key and still mean the same thing. Four anchors have no identifier
  available (`independently safe`, `first increment PR`, `this epic does not solve`,
  `ships with the harness body`); those are short, declared load-bearing in `E21-F05.tests.md`,
  and each failing test's message says so.
- **Extract the section first.** `agents/builder.md` already mandates this: *"A test that
  asserts a PROSE contract must grep the SECTION it names, not the whole file."* A whole-file
  grep is satisfied by any unrelated occurrence elsewhere — including one the same change just
  added.
- **Prefer counts to presence where "stated once" is the requirement.** R1's and R2's real
  content is *uniqueness*, and a presence check cannot see a second copy. An **occurrence**
  count can — but only if it counts occurrences. `grep -c` counts matching *lines*, and this
  document wraps at ~92 columns, so two copies of an anchor on one wrapped line would report
  `1` and let the very duplication these requirements forbid pass. Use
  `grep -o … | wc -l` (see the second correction below).

**Cost accepted, in one line:** a future editor who rewords the lane will occasionally trip a
token assertion that is not a real defect. That is bounded and visible; the alternative — a
false doctrine no gate can see — is why this epic exists.

### Section-extraction helpers (both live in the new suite)

```sh
# sect <file> <heading-text> — ONE section body; stops at the next heading of ANY level.
# FENCE-AWARE: `#` opens a comment in every shell fence in these docs, so the bare house
# idiom treats `# Increment 1 targets main` as a heading and stops extracting there.
sect() { awk -v h="$2" '/^```/{f=!f} !f && /^#+ /{k=(index($0,h)>0);next} k' "$1"; }

# span <file> <h2-heading-text> — a WHOLE `## ` section INCLUDING its `###` subsections;
# stops at the next `## `. Used for every lane-wide sweep and every uniqueness count.
# ALSO fence-aware: no shell comment in this file begins with `## ` TODAY, but this feature
# rewrites those very fences (T4, T6), and a `## ` comment introduced inside one would
# truncate the span and make three bans pass vacuously.
span() { awk -v h="$2" '/^```/{f=!f} !f && /^## /{k=(index($0,h)>0);next} k' "$1"; }
```

Both are `awk`, not `grep`, so neither depends on a `grep` dialect (see
`tests/test_grep_probe.sh` for why that distinction is live in this repo).

**Why `sect()` extends the house idiom at `agents/builder.md:87` rather than copying it — the
first hard-won correction, carried.** That idiom is `awk 'BEGIN{h="…"} /^#+ /{k=…;next} k'`,
which is fence-**blind**. Re-measured on `main` against the very file this feature edits:

| extractor | `sect docs/WORKFLOW.md '### Creating stacked increments'` → `gh pr create` count |
|---|---|
| bare house idiom (fence-blind) | **1** |
| `/^```/{f=!f}` fence-aware | **4** |

Extraction dies at the opening ` ```bash ` because the next line, `# Increment 1 targets main
(default):`, matches `/^#+ /`. Any assertion counting inside a fenced section would therefore
have passed on a section it never read — the expected value reachable by a second path, in the
exact shape `agents/builder.md`'s own Principles warn about. The toggle is the minimum fix and
changes nothing for fence-free sections.

### The second hard-won correction, carried: never bind a possibly-zero `grep -c` under `set -eu`

`grep` exits `1` on no match. Re-verified on this machine:

```
$ sh -c 'set -eu; n="$(printf "a\n" | grep -c zzz)"; echo "n=$n"'   # → rc=1, prints nothing
```

Under `set -eu` that **aborts the whole suite silently on the passing path** — which is the
passing path for R3's, R5's and R7's absence sweeps. Two forms only, and they dodge the
line-vs-occurrence hazard above at the same time:

- counts: `n="$(span … | grep -oi 'foo' | wc -l | tr -d ' ')"`, then `[ "$n" = 1 ]`. `wc` is
  the pipeline's last command and exits `0` on empty input, so no `|| true` is needed and the
  count is of occurrences, not lines;
- absence: `if span … | grep -q 'foo'; then fail "…"; fi`.

`grep` in this repo's scripts is **BSD grep** and `awk` is **BSD awk**: `-o` is supported, `-P`
is not, and `(R[0-9][0-9]*)` is a plain BRE where the parentheses are literal — which is
exactly what R7 wants (`(R[0-9])` alone would miss `(R10)`).

## Versioning

`docs/` is listed in `HARNESS_BODY_PROSE` and is stamped into every target, so this **does**
change the installed body and a `VERSION` bump is required.

**How `AGENTS.md` → *Versioning* is read here, since it does not disambiguate this case
itself.** It lists `docs/` inside the installed body ("bump only if the PR changes the
installed body … `agents/`, `docs/`, `store/` …") and, in the next sentence, exempts
"docs-only … changes" with no test to tell the two apart. The reading this feature takes: the
body list is authoritative for *which paths are stamped*, and the "docs-only" exemption means
repository documentation **outside** the body — `README.md`, `progress/`, `CHANGELOG.md`
prose. `docs/WORKFLOW.md` is stamped into `.harness/docs/` on every install, so it is a body
change and it is owed a bump. (Flagged rather than asserted: this spec's defect #3 is a
citation that claims more than its source says, so it does not commit the same error.)

**Level: PATCH.** `AGENTS.md` defines PATCH as a *body/installer bugfix* and MINOR as a *new
backward-compatible capability*. Every change here corrects a shipped statement that is false
or dangling; a target that upgrades gains **no** new capability, no new key, no new command and
no behavior it can call. New subsections are added, but they document conditions that were
already stated (twice, inconsistently) and board facts that are already true. **Argument for
MINOR, recorded so the gate can overrule:** the diff adds two subsections and renames two
headings, which is more than a typo fix. It is still not a capability, so PATCH is the honest
level. `CHANGELOG.md` gets a `### Fixed` entry, not `### Added`.

**No test may assert a `VERSION` value, in any form** — a repeat anti-pattern in this repo.

## Approach notes

### Sequencing

`docs/WORKFLOW.md` first and completely (T1–T8), then the vocabulary sweep over the finished
lane (T9), then the supersession note (T10), then the suite (T11), then the mutation proof
(T12), then `VERSION` + `CHANGELOG.md` (T13), then the gate (T14). Writing the suite first is
tempting and wrong: the assertions are derived from the finished headings, and a suite written
against imagined prose gets "fixed" by weakening it.

### The one trap in this feature

Every requirement is satisfiable by writing the right paragraph in the **wrong** section. The
suite extracts by heading for exactly that reason, so a correct sentence filed under a
neighbouring subheading fails. **The headings in the table above are part of the contract.** If
one does not fit the prose you end up writing, hand back to the Orchestrator rather than
renaming it in isolation.

### Vocabulary rules that bind the Builder, not just the document

- **No atomicity language anywhere** — not in `docs/WORKFLOW.md`, not in the suite's prose, not
  in `CHANGELOG.md`, **not in any commit message**. This is the specific defect that got the
  predecessor of E21-F04 withdrawn after four review rounds. The token appears in this feature
  only as the literal string R3's sweep bans.
- **No `wave`** anywhere in the lane, including example branch names and PR titles (R5).
- **No bare `(R<n>)`** anywhere in the lane (R7).

### Anti-patterns this suite must not commit

- No assertion on a `VERSION` value, in any form.
- No diff of any file against `main`, `origin/main`, or a DO-NOT-TOUCH path.
- No whole-file grep for a prose contract — always `sect`/`span` first, and always the
  **fence-aware** `sect()`, never the bare house idiom.
- **No `grep -c` at all** — it counts lines rather than occurrences, and a zero result bound
  under `set -eu` aborts the suite on its passing path (see above for the two legal forms).
- No frozen sentence and no frozen `VERSION`; anchor on identifiers, and where a short English
  phrase is the only anchor available, declare it load-bearing and say so in the failure
  message.
- Per-case `mktemp` fixtures with a cleanup `trap`; no writes into `state/`, `specs/` or
  `progress/`; the suite must pass standalone **and** under `tools/run-tests.sh`'s concurrency.
- The one installer-invoking case sandboxes **`HOME` and `CODEX_HOME`** — `install_at()` in
  `tests/test_pr_loop.sh` sets only `CODEX_HOME`, and `harness-install.sh` falls back to
  `${HOME}/.codex/prompts` when `CODEX_HOME` is unset, so a future refactor of that fallback
  must not be able to reach the developer's home.
