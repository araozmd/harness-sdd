beside E21-F03's, which is where this command's installed-body checks live. Every guard test
is fixture-driven and runs **offline** — no `gh`, no network, no real stack.

literal `'**both** terminal states'`, which R9 makes false. See "Existing tests this feature

## Fixtures

One `$T/stack/` directory, written once, reused by every guard test:

```
base-target.json    {"baseRefName":"develop"}                  ← note: NOT "main"
base-child.json     {"baseRefName":"feat/wave-a"}
base-orphan.json    {"baseRefName":"feat/gone"}
base-nokey.json     {"headRefOid":"abc"}                       ← parses, no .baseRefName
base-empty.json     {"baseRefName":""}
base-garbage.json   not json at all
open-parent.json    [{"number":80,"headRefName":"feat/wave-a"}]
open-none.json      []
open-object.json    {"number":80}                              ← array expected
open-zero.json      (zero bytes)                               ← jq exits 0 with no output
```

**The happy-path fixture deliberately uses `develop`, never `main`.** A fixture that used
`main` would pass against a guard that still carried the deleted literal, and R4/M5 would be
untestable in practice.

`open-zero.json` exists because the caller's `gh pr list` can leave a zero-byte file: `jq`
succeeds with no output, which without R5's array check reads as "nobody owns the base" and
returns a *verdict* (`6`) where the honest answer is "unreadable" (`4`).

## Mutation checks

Human-gate decision 1 keeps `auto_merge` enabled on a PR with a non-default base and puts
the entire correctness burden on the guard. So **every leg of the guard is individually
mutation-proved** — a leg whose mutation survives is a leg that is not really guarded.

## How the prose-shaped requirements are asserted

R7, R8, R9, R11 and R12 are behaviors of a **markdown command body**, which is the surface
where the false atomicity claim survived four review rounds. They get **greppable
assertions**, not prose promises:

- **R7** — a scoped sweep, not a blanket one. `atomic` appears legitimately across the
  harness ("atomic write", "atomic task checklist"), so the sweep is scoped to
  `tools/pr-stack-guard.sh` (which must contain **no** case-insensitive match for
  `atomic`) and to the merge-order section of the source-layout **and installed** bodies.
  Positive half: the guard header must state that it enforces **order** (a case-insensitive
  match for `merge order` / `order, not`).
- **R8** — extract byte offsets from the body for: the guard invocation, the
  `all gates green` summary block, `resolveReviewThread`, and each `gh pr merge`
  occurrence; assert the guard's offset is the lowest of all four. The summary-post offset
  matters as much as the merge ones — a guard placed after it lets the loop post
  "all gates green ✅" on a PR it then declines to merge.
- **R9** — assert the amended sentences literally: `three` + `merge order withheld` in the
  closing contract sentence; that the same sentence's tail names the exit-`4` route as a
  failure; the absence of the string `the one terminal state`; the presence of a
  `### Merge order withheld (success)` heading; `return success` inside that section; both
  legs' wording (`waiting on parent` **and** the retarget remedy); `any terminal-state
  comment` at the preamble and `every terminal state` at the posting rule; and that the
  needs-human "Reached by:" list does **not** mention exit `6`. Run every one of these
  against **both** bodies.
- **R11** — assert the body warns about `retarget`, **and** assert
  `tools/wait-for-codex.sh` contains no occurrence of `baseRefName`. The second half is a
  **regression anchor, not a proof of this feature**: it passes on today's tree unchanged
  (verified: zero occurrences). It is there so a later change cannot quietly make review
  freshness depend on the base ref. Only the `retarget` assertion is load-bearing for R11.
- **R12** — install into a temp target with the gate armed, then repeat R7/R8/R9's greps
  against `$target/.claude/commands/sdd-pr-loop.md`, plus
  `[ -x "$target/.harness/tools/pr-stack-guard.sh" ]`, plus `HARNESS_MERGE_TARGET` present
  in the installed body **and** in the seeded `harness.config.yaml` header comment.

## Behavioral / end-to-end checks

- **Exit-code disjointness.** `6` must not collide with any code the loop already branches
  on (`wait-for-codex.sh` uses `0/1/2/3/4/5`). Assert the guard emits only `0`, `4`, `6`.
- **Inert when the gate is off.** Install with `pr_loop.enabled` absent: no
  `.claude/commands/sdd-pr-loop.md` is stamped, so nothing invokes the guard. The tool still
  ships in `.harness/tools/` (the `copy tools` + `chmod +x` block is ungated) — assert that,
  and that no installed file references it.
- **Regression, no R-id — the pre-PR change-size check.** `agents/reviewer.md:136-143` and
  `agents/orchestrator.md:103` already tell the caller to pass `--base` when the PR targets
  something other than the default branch (landed in `2e71d2b`, already on `main`). Assert
  at **invocation granularity, not file granularity**: no line that invokes `change-size.sh`
  may also carry `--base origin/main` (match both tokens on the *same line*). A plain
  file-level `grep -q -- '--base origin/main' && fail` **false-fails on a correct tree** —
  `agents/reviewer.md:139` contains that literal inside the *prohibition* `2e71d2b` added
  ("**Do not hard-code `--base origin/main`.**"), as do `agents/orchestrator.md:103` and
  `docs/WORKFLOW.md:133`. Then assert separately that the prohibition sentence is still
  present, so the obvious wrong fix — deleting the guidance to green the suite — fails too.
- **Doctrine stays out.** E21-F05 owns the lane doctrine, the role contracts and the board
  representation. This is a **Reviewer-time check against `.plan.md`'s DO NOT TOUCH list**
  (no role-file edit; `docs/WORKFLOW.md` touched only in step 7's mechanism sentences),
  deliberately **not** an automated test: a permanent-suite test that `git diff`s files
  against `main` is a known anti-pattern here, and DO-NOT-TOUCH is a per-feature boundary
  rather than a permanent gate (`tests/test_reviewer.sh:91-96`).

## Non-functional checks

- No new hard dependency: `jq` is already a `/sdd-pr-loop` precondition, and the existing
  `test_init_has_no_new_dependency` assertion still passes with neither `gh` nor `jq` on
  PATH.
- `tools/pr-stack-guard.sh` parses under POSIX `sh` and under `dash` when available; no
  `[[ ]]`, no process substitution, no `(( ))` — the same shape asserted for
  `tools/wait-for-codex.sh`.
- `./init.sh` clean (including its ADR-citation sweep); full `verification.test_command`
  suite green.
- **No exact `VERSION` string is asserted anywhere**, and no test `git diff`s a file against
  `main` — both are recurring anti-patterns in this repo's permanent suite.
