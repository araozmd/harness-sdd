# Merge-order safety for a non-default PR base — Technical Plan

## Stack & dependencies

POSIX sh + `jq`. `jq` is already a hard precondition of `/sdd-pr-loop` (step 0's preflight
checks it), so this adds **no new dependency** to the harness — and `init.sh` must still
pass on a box with neither `gh` nor `jq`, which `tests/test_pr_loop.sh` already asserts.

No new runtime, no new config key, no board schema change.

## Interface — `tools/pr-stack-guard.sh`  (serves: R1–R7)

```
tools/pr-stack-guard.sh evaluate <pr.json> <open-prs.json> --merge-target <branch>
```

| Argument | Shape | Produced by |
|---|---|---|
| `pr.json` | object with `.baseRefName` | `gh pr view --json baseRefName` |
| `open-prs.json` | **array** of `{number, headRefName}` | `gh pr list --state open --json number,headRefName` |
| `--merge-target <branch>` | **required, non-empty** — the branch the caller declares it is safe to merge into | the caller (see below) |

| exit | meaning | R-id |
|---|---|---|
| `0` | base **is** the declared merge target — safe | R1 |
| `6` | withhold — base is another open PR's head (names it), or a branch nobody owns (says: retarget, waiting will not help) | R2, R3 |
| `4` | usage error / unreadable input / merge target missing **or empty** | R4, R5 |

**`6` is deliberately its own code**, disjoint from the watcher's `0/1/2/3/4/5`. A generic
failure would label a healthy PR `needs-human` on every round while its parent is in review.

### The flag is `--merge-target`, required and non-empty  (serves: R4)

The salvaged artifact carried `default_branch="main"` as a literal **and** called the flag
`--default-branch`. Both go:

- **Delete the literal outright.** Do **not** replace it with a different literal, a name
  list, or a `git`/`gh` lookup inside the guard (that would break R6's offline property). On
  a `develop`/`trunk` repo the literal made the guard read **every** PR as stacked ⇒ exit
  `6` ⇒ the loop merged nothing, ever.
- **Rename `--default-branch` → `--merge-target`** (human-gate decision). The flag's
  meaning under decision 3 is "the branch the caller declares it is safe to merge into",
  which on a release-flow repo is not the default branch. Move the **header comment, usage
  string, the escape-hatch comment that references the old flag name, and both verdict
  `printf`s** — the messages currently read `base=%s (default branch) — not stacked, safe to
  merge` and `is not the default branch (%s)`, which become inaccurate the moment the flag
  carries an integration branch.
- **Reject an empty value.** `--merge-target ""` is *supplied*, so a missing-argument check
  alone does not catch it — and an empty target matches no real base, so the guard would
  fall to its last leg and exit `6`. Under decision 2 that is a **success**, so a repo whose
  `gh repo view` briefly failed would report merge-order-withheld on every PR forever, with
  no label, no non-zero and no signal to anyone. Treat empty exactly as missing: exit `4`.

### Validate the open-PR list is an array  (serves: R5)

A zero-byte or truncated `open-prs.json` makes `jq` produce no output and exit `0`, which
reads downstream as "no open PR owns the base". That is still fail-closed (exit `6`), but
it is indistinguishable from a real verdict. Check the input parses as a JSON array before
using it and exit `4` when it does not, so an unreadable input is reported as unreadable.

### Offline  (serves: R6)

The guard reads two files and `jq`. It shall not invoke `gh`, `git`, `curl`, or read any
network. This is what makes every leg testable against fixtures, and it is why the artifact
was worth salvaging when the rest of its feature was withdrawn.

## The caller — where the guard runs  (serves: R8, R9)

The guard is a **merge gate, not an entry gate.** A PR with a non-default base must still be
reviewable while its parent is open — that is the entire point of having one. So the loop
runs the guard at the **very top of the "Ready to merge" terminal state**, after step 6's
gates are green, and **before** the all-gates-green summary comment, **before** the
thread-resolution block, and **before** both `gh pr merge` calls.

Placing it there (rather than duplicating it inside each merge arm) means:

- one call structurally precedes **both** merge paths — a mutation that removes it cannot
  survive on either arm;
- a withheld PR is left **completely untouched**: no "all gates green ✅" comment it then
  contradicts by not merging, no resolved thread, no label, no merge.

```bash
# ── merge-order guard: never merge ahead of the branch this PR is built on (E21-F04)
cache=".pr-loop/$pr_number"          # installed body: .harness/.pr-loop/$pr_number
merge_target="${HARNESS_MERGE_TARGET:-$(gh repo view --json defaultBranchRef --jq '.defaultBranchRef.name')}"
if [ -z "$merge_target" ]; then
  echo "could not resolve the merge target — needs-human, not merging" >&2
  stack_rc=4
else
  gh pr view "$pr_number" --json baseRefName > "$cache/base.json"
  gh pr list --state open --json number,headRefName > "$cache/open-prs.json"
  sh tools/pr-stack-guard.sh evaluate "$cache/base.json" "$cache/open-prs.json" \
    --merge-target "$merge_target"
  stack_rc=$?
fi
```

Then dispatch **before** anything else in the terminal state:

| `stack_rc` | Next |
|---|---|
| `0` | continue: post the all-gates-green summary, resolve Codex threads, merge as today |
| `6` | **merge order withheld** terminal state — post the summary + the guard's verdict verbatim, return **success** |
| `4` | `needs-human` terminal state, return failure — a base you could not read is not the merge target |

A failed `gh` fetch degrades safely without extra code: an empty `open-prs.json` is rejected
as a non-array (exit `4`), and an empty `base.json` yields exit `4` too. Note this in a
comment so the next reader does not "fix" it. The **empty merge target** is the one case the
guard cannot see as missing, which is why the caller checks it *and* R4 rejects it — belt
and braces, because decision 2 removed the non-zero that would otherwise expose it.

## Squash-message base  (serves: R10)

In the squash-merge prep block, the commit enumeration currently reads
`git log --reverse --format='- %s' "origin/$default_branch..HEAD"`, which on a PR with a
non-default base enumerates the **parent's** commits into the child's squash body. Enumerate
against the PR's own base instead:

```bash
base_ref=$(gh pr view "$pr_number" --json baseRefName --jq '.baseRefName')
git log --reverse --format='- %s' "origin/$base_ref..HEAD"
```

Keep it fail-soft: an unresolvable `origin/$base_ref` (a deleted base branch) must not abort
the squash path — the existing `[ -s "$msg" ] || rm -f "$msg"` fallback to GitHub's default
body already covers it, and that behavior must survive.

The **post-merge cleanup** block's `default_branch=$(gh repo view …)` is correct as it
stands — after a merge you do want to return to the default branch. Do not "fix" it.

## Retarget is not a review event  (serves: R11)

When the parent merges with `--delete-branch`, GitHub retargets the child onto the parent's
base and pushes **no commit**. `baseRefName` changes; `headRefOid` does not, and no comment
is created. So the watcher's three clean signals and the `created_at >= trigger` freshness
rule are structurally unaffected — `tools/wait-for-codex.sh` contains zero occurrences of
`baseRefName` today, and nothing in this feature may make it read one.

The loop body states the rule explicitly: on a retarget, **re-run the guard**; do not post
another `@codex review` and do not count a round.

## Approach notes

- **Two bodies, not one.** `.claude/commands/sdd-pr-loop.md` is the source-layout copy;
  `harness-install.sh:2969` writes the single heredoc that every other front-end copies
  from. Editing only the first is the exact wiring gap this repo has P1'd more than once, so
  the tests assert against the **installed** body and their failure messages name the trap
  (R12).
- **No new command is added**, so `tests/test_install.sh` needs no new command assertion;
  the wiring assertions belong in `tests/test_pr_loop.sh` beside E21-F03's, which is where
  the installed-body checks for this command already live.
- **Restore, then correct — in that order.** Recover the artifact verbatim first so the diff
  shows exactly what changed about it: the literal, the flag name, the empty/array
  validation, and the header claim.
- **B4 and B5 are the same shape.** Decision 2 traded a non-zero exit for a success return,
  so anywhere the loop can withhold forever it must *say* what will clear it — and where
  nothing will, say that instead. Both the empty merge target (edit to R4) and the
  unowned-base leg (R3's remedy clause) exist for that reason; treat them as one concern
  when reviewing.
- Do **not** freeze an exact `VERSION` string and do **not** diff DO-NOT-TOUCH files against
  `main` in any test added to `verification.test_command` — both are recurring anti-patterns
  in this repo's permanent suite.
