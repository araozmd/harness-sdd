# Automated scratch-dir sweep + role hand-off rules for finished features — Tasks

> Atomic, sequential, independent steps. The Builder works these top to bottom,
> one at a time. Each task names the R-id(s) it satisfies. Check off when done.

- [x] **T1** (R1) — Create `tools/sweep-scratch.sh`: parse `[<feature-id>] [--apply]`
  args, self-locate the canonical primary worktree and `HARNESS_DIR` (reuse the
  resolution approach in `tools/fix-worktree.sh`), and default to dry-run when `--apply`
  is absent.
- [x] **T2** (R2) — Implement classification: for each immediate subdirectory of the
  resolved `scratchpad/`, match `^(E[0-9]+-F[0-9]+)-.+$`; non-matching entries are
  `unrecognized` and are never acted on in any mode.
- [x] **T3** (R3, R4, R5) — Implement the TaskStore lookup, called once per run before
  any entry is classified against it: read `state/tasks.json` (source) or
  `.harness/state/tasks.json` (installed). A read/parse failure of that file **aborts the
  whole scan** — no entry is classified, nothing is removed, and the process exits
  non-zero (R5). Otherwise, for each classified entry, search `epics[].features[]` flat
  for its feature id and record the result as either a `status` value or "not found"
  (feeds R3/R4 below) — this per-entry lookup outcome never affects the exit code.
- [x] **T4** (R3) — For an entry whose feature status is `done`: in dry-run, report it
  `eligible`; with `--apply`, measure its size then remove the whole subdirectory.
- [x] **T5** (R4) — For an entry whose feature id is not found, or whose status is not
  `done`: skip it in every mode and report the specific reason (`not-found` vs.
  `status:<value>`); this must never affect the process exit code.
- [x] **T6** (R6) — Before any removal, resolve the entry's real path and confirm it is a
  direct child of the resolved real path of `scratchpad/`; on mismatch, skip and report
  the anomaly instead of removing anything. Never glob the scratchpad root and never
  resolve/act on `scratchpad/` itself.
- [x] **T7** (R7) — Implement reporting: one line per entry (`removed` / `eligible` /
  `skipped: <reason>` / `unrecognized`) plus a final summary (counts per verdict, total
  bytes reclaimed across removed subdirectories — 0 when none were removed). Exit
  non-zero only for T3's tool-level TaskStore failure or invalid arguments from T1 — never
  merely because entries were skipped (T5) or classified `unrecognized` (T2).
- [x] **T8** (R8) — Implement the optional `<feature-id>` scope argument: when given,
  restrict the scan to matching entries only; when absent, scan every immediate
  subdirectory.
- [x] **T9** (R9) — In `agents/orchestrator.md`'s "Writing `done`" section, after the
