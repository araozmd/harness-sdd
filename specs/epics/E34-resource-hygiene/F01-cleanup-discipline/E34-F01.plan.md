# Automated scratch-dir sweep + role hand-off rules for finished features — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it
> serves. Start high-level; don't over-specify internals that might be wrong.

## Stack & dependencies
- Language/framework: POSIX `sh`, the existing `git` CLI (for repository/canonical-
  primary resolution only — no worktree/branch mutation happens here), and `python3`
  (already a harness dependency, e.g. `tools/tasks-lock.py`) for read-only JSON parsing
  of the TaskStore. *(serves: R1–R8)*
- New dependencies: none.

## Data model  (serves: R2, R3, R4, R5)
No TaskStore or application schema changes; the tool only **reads**
`state/tasks.json` (source layout) / `.harness/state/tasks.json` (installed layout).

| Entity | Field | Type | Notes |
|---|---|---|---|
| scratch entry | dir name | string | Immediate child of `scratchpad/`. Parsed against `^(E[0-9]+-F[0-9]+)-.+$`; group 1 is the feature id, the remainder is opaque (role token, round suffix, etc. — never validated against a fixed role list). Serves R2. |
| feature lookup | status | enum | Read from the TaskStore feature object matching the parsed feature id (search is flat across every epic's `features[]`, matching how `E99-F##` quick-fix rows already live in the same array). A read/parse failure of the TaskStore file itself is NOT a per-entry lookup outcome — see R5 in the CLI design below. Serves R3, R4. |

## CLI design  (serves: R1, R2, R3, R4, R5, R6, R7, R8)

`tools/sweep-scratch.sh [<feature-id>] [--apply]`

- **Self-location, reused pattern.** Resolve the caller's repository top-level and the
  canonical primary worktree the same way `tools/fix-worktree.sh` already does (via
  `git worktree list --porcelain` + matching absolute Git common directory) — this makes
  the sweep correct even when invoked from inside an isolated worktree, always acting on
  the one canonical `scratchpad/` and the one canonical TaskStore. Resolve `HARNESS_DIR`
  from the invoking helper's own repo-relative path: `tools/sweep-scratch.sh` (source
  layout, board at `<primary>/state/tasks.json`) or `.harness/tools/sweep-scratch.sh`
  (installed layout, board at `<primary>/.harness/state/tasks.json`); reject any other
  layout. `scratchpad/` itself is always resolved at `<primary>/scratchpad`, never inside
  `.harness/` — it is where Builder/Reviewer/Fixer/PR-fixer sessions actually write, per
  the existing namespacing convention. *(serves: R1)*
- **Mode.** Default is dry-run (report only). `--apply` is the only way to mutate the
  filesystem; it changes no other behavior (classification and reporting are identical in
  both modes). *(serves: R1, R7)*
- **Scope.** An optional single positional `<feature-id>` argument (matching
  `E[0-9]+-F[0-9]+` exactly) restricts the scan to subdirectories whose parsed feature id
  equals it; anything else scans every immediate subdirectory of `scratchpad/`.
  *(serves: R8)*
- **Classification.** For each immediate subdirectory: parse the leading
  `E[0-9]+-F[0-9]+` token followed by a hyphen (see Data model). No match ⇒
  `unrecognized`, always skipped, in both modes. *(serves: R2)*
- **Liveness lookup.** For a matched feature id, read the TaskStore file **once per
  invocation, before classifying any entry**, with `python3 -c '...'` (or an inline
  embedded script — keep the tool a single file, matching `tools/fix-worktree.sh`'s
  self-contained shape), search `epics[].features[]` flat for the matching `id`, and read
  its `status`. These are two distinct outcomes, not one:
  - A read/parse failure of the TaskStore file itself is a **tool-level error**: abort
    the whole scan before classifying or removing anything, change nothing, and exit
    non-zero. This is the one case where a single problem stops the whole run, because
    the tool cannot safely evaluate *any* entry without the TaskStore. *(serves: R5)*
  - Feature id not found, or found with a status other than `done`, is a **per-entry
    skip** with a stated reason (`not-found` / `status:<value>`); it does not stop the
    scan and does not affect the exit code. *(serves: R3, R4)*
- **Safety check before any removal.** Resolve the subdirectory's real path
  (dereferencing symlinks) and confirm it is a **direct child** of the resolved real path
  of `scratchpad/`; if not, skip and report the anomaly rather than deleting through it.
  Never resolve or act on `scratchpad/` itself, and never use a wildcard glob at the
  scratchpad root — always the one already-classified, already-verified absolute path.
  *(serves: R6)*
- **Removal.** Only for `done`-classified entries, only with `--apply`: measure the
  subdirectory's size before removing it (for the summary), then remove the whole
  subdirectory (e.g. `rm -rf` scoped to the one verified absolute path — never a glob,
  never the scratchpad root). *(serves: R3)*
- **Reporting.** One line per classified entry naming the verdict (`removed`,
  `eligible` [dry-run], `skipped: <reason>`, `unrecognized`), plus a final summary of
  counts per verdict and total bytes reclaimed (0 in dry-run, and for any run with no
  `done`-classified entries). Diagnostics/summary to stdout is fine — this tool has no
  downstream parser to protect (contrast `tools/fix-worktree.sh`, whose `create` output
  F03 parses). *(serves: R7)*

## Orchestrator hook  (serves: R9)
In `agents/orchestrator.md`'s existing "Writing `done`" section, immediately after
`set-status <id> done --evidence <merge-commit>` (step 4 of "The order on the main
path"), add: invoke `sh tools/sweep-scratch.sh <id> --apply` (or the installed-layout
equivalent), best-effort — its exit status is recorded (e.g. alongside the
`progress/history.md` round line) but never re-opens or reverts the `done` write, and
never blocks the Orchestrator's loop. This mirrors the harness's existing best-effort
hook precedent (`store.on_write_command`'s "non-zero exit NEVER rolls back... and never
blocks the loop"), so the Reviewer/Orchestrator convention for a fire-and-forget
post-write hook is not new.

## DO NOT TOUCH
- `tools/fix-worktree.sh` — E15-F02's own worktree-per-fix lifecycle helper. This
  feature's sweep is the *general* backstop the inbox brief distinguishes from that lane;
  it must not modify, wrap, or duplicate that script's teardown logic.
- `state/tasks.json`, `store/tasks.schema.json`, and every status enum — the sweep only
  **reads** the TaskStore; it performs no `set_status` or `tasks-lock.py` write of any
  kind.
- `agents/driller.md`, `agents/planner.md`, and the `consumed:` marker mechanics they use
  for `progress/topology-handoff.md` — unrelated to this feature; the `progress/`
  handoff-file sweep is a deferred idea for a future, separate `/sdd-new` intake, not
  this one.
- Any git worktree or branch (local or remote) — no such operation exists in this
  feature; likewise deferred to a future `/sdd-new` intake.
- `harness.config.yaml`'s `verification.test_command` — `tools/run-tests.sh` already
  auto-discovers `tests/test_*.sh`.
- `harness-install.sh`'s `_root_ignores` list (target-root `.gitignore` seeding) — adding
  `scratchpad/` there is a related but distinct gap (git-tracking hygiene, not
  disk-accumulation hygiene) and is out of this feature's scope.

## Approach notes
- Reusing `tools/fix-worktree.sh`'s canonical-primary-worktree resolution (rather than a
  plain `git rev-parse --show-toplevel`) matters because a plain top-level lookup returns
  whichever worktree the tool happens to run from; the sweep must always act on the one
  canonical `scratchpad/` and the one canonical TaskStore regardless of which checkout
  invoked it.
- The tool is deliberately single-purpose (scratch dirs only), matching the "one helper,
  one lifecycle" shape `tools/fix-worktree.sh` already established, rather than a
  multi-kind CLI with stub subcommands for handoff files or worktrees/branches that don't
  exist yet. A follow-on feature speccing the `progress/` or worktree/branch sweep may
  choose to add sibling scripts (e.g. `tools/sweep-handoff.sh`) or extend this one with a
  subcommand — that choice belongs to that feature's own Architect pass, not this one.
- Tests must use disposable fixture repos/TaskStore files and must never touch this
  repository's real `scratchpad/`, `state/tasks.json`, or any real feature's directory.
