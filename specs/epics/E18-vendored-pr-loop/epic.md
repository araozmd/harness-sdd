# Epic E18 — Harness self-sufficiency: vendored PR review loop

## Business brief
The harness instructs its own agents to run `/pr-loop` — `agents/orchestrator.md:102`,
`CLAUDE.md:20`, and `docs/WORKFLOW.md:325` all reference it — but **the harness does
not ship it**. That command comes from the separate multi-cli-orchestrator (MCO)
project, installed as a *global* user skill at `~/.agents/skills/pr-loop/`. The moment
a user uninstalls the MCO skills, the harness's own documented review workflow breaks,
and a fresh consumer who installs the harness alone never had it in the first place.

This is the harness's only remaining dangling dependency on MCO. A sweep of the harness
body (`agents/`, `AGENTS.md`, `CLAUDE.md`, `docs/`, `tools/`) finds **no** `MCO_*` env
references, no `route-task`, and no `start-feature` — `/pr-loop` is the single coupling.
`route-task` and `start-feature` need no replacement: `/sdd-next` and `/sdd-new` already
cover that ground.

This epic vendors the review loop into the harness as a first-class, installer-generated
`/sdd-pr-loop` command, so a harness install is **self-sufficient**: it drives the Codex
review cycle with no external skill on disk.

It ships as a **command**, not a skill, deliberately. The installer has no skill-emission
machinery at all (zero `skills` references in `harness-install.sh`), whereas the existing
`HARNESS_SDD_CMDS` emitter, deselection/removal ledger, and neutral-CMDDIR mirror already
give every selected front-end a byte-identical copy. The Orchestrator invokes the loop
explicitly, so losing a skill's description-triggered activation costs nothing.

The loop is **not universally applicable**: it drives Codex reviews through GitHub PR
comments, which requires the Codex GitHub App installed on the target repo and an authed
`gh`. A repo without that setup would post `@codex review` and poll to the watcher's
15-minute ceiling for a review that can never arrive. The loop is therefore gated by a
`pr_loop.enabled` config key, and the whole workflow — command stamping and the review
step in the harness's own runbook — follows that key.

## Success criteria (epic level)
- A harness install with **no** MCO skills on disk can still drive a full Codex review
  cycle: trigger, poll, classify severity, fix via subagent, escalate, merge.
- `/sdd-pr-loop` is generated by `harness-install.sh` into every selected front-end and
  removed on deselection, exactly like the other `/sdd-*` commands.
- The Codex watcher script is vendored under the harness dir and invoked by a
  harness-relative path — never `~/.agents/skills/...`.
- With `pr_loop.enabled: false`, no `/sdd-pr-loop` glue is stamped and the harness's
  review workflow does not direct agents to a command that cannot work.
- With the Codex GitHub App absent or `gh` unauthed, the loop **fails fast with a clear
  diagnostic** rather than polling to the ceiling.
- No canonical `agents/*.md` role file is forked and `store/tasks.schema.json` is
  untouched.

## Notes
- **Source material** — `~/.agents/skills/pr-loop/` is 6 files / ~618 lines / 48K:
  `SKILL.md` (the runbook), `scripts/wait-for-codex.sh` (the background watcher), and
  four per-front-end `agents/<front-end>/pr-fixer.*` definitions (claude-code, codex,
  opencode, antigravity). The `codex` one is a `.toml`, which is a **new artifact shape**
  for that front-end — today `codex` stamps only the global `$CODEX_HOME/prompts`.
- **Human decisions already taken** (see the F01 brief): auto-merge defaults **on** via a
  `pr_loop.auto_merge` key, matching today's MCO behavior; env vars make a **clean break**
  to `HARNESS_*` with no `MCO_*` fallback.
- **Test wiring is mandatory, not optional.** A new `tests/test_pr_loop.sh` must be added
  to `verification.test_command` and must assert both that the command is generated and
  that deselection removes it. Codex has raised this exact installer-wiring gap as a P1
  twice before (E15-F03, E06-F03).
- **`pr_loop.enabled` interacts with E20.** E18 introduces the key and honors it; E20-F01
  surfaces it in the installer picker so it is togglable without hand-editing YAML.
