# `/sdd-pr-loop` command + vendored Codex watcher — Test Contract

> Every R-id in `E18-F01.spec.md` maps to a concrete, executable check. The Reviewer fails
> the feature if any R-id lacks a passing test.
>
> **Suite conventions (non-negotiable):**
> - Every installer-invoking test sets `CODEX_HOME` under its own temp dir — the codex glue
>   is machine-global and shared across targets.
> - No test freezes an exact `VERSION` string, and no test diffs a DO-NOT-TOUCH file
>   against `main`. Those anti-patterns have been reverted three times in this repo.
> - Fixture-driven `evaluate` assertions require `jq`. When `jq` is absent they print
>   `skip - <name> (jq not installed)` and continue; everything else runs unconditionally.
> - Test names below are shell function names in `tests/test_pr_loop.sh` unless another
>   file is named.
> - **The gate is opt-in.** A plain `install_at` is therefore a *gate-off* run. Any row
>   that asserts the loop IS installed arms the gate first — `install_on` (the
>   `HARNESS_PR_LOOP_ENABLED=true` env override) for rows that only need the glue present,
>   or `set_gate <target> true` for rows that exercise the config axis itself.
>   `tests/test_install.sh` exports `HARNESS_PR_LOOP_ENABLED=true` suite-wide for the same
>   reason; the opt-in default is owned by R3/R15/R18/R18b here and is never masked there.

## Fixture design (R25–R29)

`tests/test_pr_loop.sh` writes round-dir fixtures into its own temp dir and drives
`sh tools/wait-for-codex.sh evaluate <round-dir>` with `PATH` stripped of `gh`, so the
offline guarantee is proven by construction rather than asserted in prose.

Minimum fixture set:

| Fixture | Contents | Expected exit |
|---|---|---|
| `stale-reanchored` | inline comment with `commit_id == head` but `created_at` **before** `trigger-ts.txt` | `1` pending |
| `fresh-finding` | same comment with `created_at` **after** the anchor | `0` findings |
| `clean-review-banner` | `pr.json` `reviews[]` with `Reviewed commit: <7-char head>`, `submittedAt` after the anchor | `3` clean |
| `clean-issue-banner` | same banner in `issue-comments.json` (`.user.login`, `created_at` after the anchor) | `3` clean |
| `clean-thumbs` | `reactions.json` with `content: "+1"` by the bot | `3` clean |
| `bot-suffix` | the fresh-finding fixture with login `chatgpt-codex-connector[bot]` | `0` findings |
| `stale-banner` | clean banner whose timestamp precedes the anchor | `1` pending |
| `empty` | four empty arrays + `pr.json` with a head oid | `1` pending |

## Stubbed-`gh` design (R22–R24, R28, R30–R34)

Wait/preflight-mode tests prepend a temp `bin/` to `PATH` holding a `gh` shell stub whose
behavior is selected by an env var the test sets (`STUB_MODE=missing-auth|closed-pr|
no-activity|findings|clean|fetch-fail`). This keeps every exit-code and diagnostic
assertion hermetic — no network, no real repo, no live PR — and lets the timeout and
first-response paths run in about a second with `HARNESS_POLL_INTERVAL=1`.

## Behavioral / end-to-end checks (Reviewer performs)

- Install into a scratch repo with defaults; confirm the seeded config carries
  `pr_loop.enabled: false` and that **no** `/sdd-pr-loop` command and **no** `pr-fixer`
  artifact exists in any front-end, including the sandboxed `$CODEX_HOME/prompts/`.
- Set `pr_loop.enabled: true`, re-run the installer, confirm `/sdd-pr-loop` appears in
  `.claude/commands/`, `.opencode/command/`, `.agents/workflows/` and the sandboxed
  `$CODEX_HOME/prompts/`, all four byte-identical.
- Set `pr_loop.enabled: false` again, re-run the installer, confirm all four copies and
  every `pr-fixer` artifact are gone and no unrelated file changed; set it back to `true`
  and confirm a byte-identical restore.
- With the MCO skills absent from `~/.agents/skills/`, run `/sdd-pr-loop` against a real
  open PR in this repo and confirm the full cycle: preflight passes, `@codex review` is
  posted, the background watcher wakes the session on resolution, a clean review is
  detected by whichever of the three signals Codex used, and the PR merges (or reports
  `needs-human`) without any reference to `~/.agents/skills`.
- On a repo without the Codex GitHub App, confirm the loop aborts within the
  first-response window with a diagnostic naming the App — not at the 900s ceiling.

## Non-functional checks

- `./init.sh` exits 0 (and still does with `gh`/`jq` removed from `PATH`).
- Full `verification.test_command` chain exits 0, including the new
  `sh tests/test_pr_loop.sh`.
- `sh -n tools/wait-for-codex.sh` parses clean; a `dash`-style POSIX shell runs the
  `evaluate` and `preflight` modes without a bashism error.
- Lint / typecheck: not configured for this repo (`lint_command` and `typecheck_command`
  are empty) — no action.
