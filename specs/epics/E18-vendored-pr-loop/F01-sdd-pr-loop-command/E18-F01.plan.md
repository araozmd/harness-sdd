# `/sdd-pr-loop` command + vendored Codex watcher — Technical Plan

> Translates `E18-F01.spec.md` into design. Every decision cites the R-id(s) it serves.
> The Builder keeps freedom over anything not pinned here.

## Stack & dependencies

- Language: POSIX `sh` (installer, watcher, tests) + markdown command/role bodies.
- New **harness** dependencies: **none**. `init.sh` is untouched (R53).
- New **loop-runtime** dependencies, required only when `pr_loop.enabled` is true and only
  while `/sdd-pr-loop` runs: `gh` (authed, Codex GitHub App on the repo) and `jq`. Both are
  checked by the watcher's `preflight` mode and reported as a fail-fast diagnostic
  (R30, R31). `jq` is retained rather than rewritten to `python3` because the vendored
  evaluation filters are hard-won and a rewrite is pure correctness risk; the loop already
  hard-requires `gh`, so `jq` adds no new class of dependency.

## Config model  (serves: R15–R19)

New top-level block in `harness.config.yaml`, seeded on fresh install and appended by
`migrate_config` on upgrade — the two must be **byte-identical** (R17), which is the same
rule the `models:` block already follows.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `pr_loop.enabled` | bool | `true` | Master gate. false ⇒ no `/sdd-pr-loop` glue anywhere (R3) |
| `pr_loop.auto_merge` | bool | `true` | Merge when all gates are green (R43/R44) |
| `pr_loop.max_rounds` | int | `4` | Round cap; the cap round labels `needs-human` (R41) |
| `pr_loop.blocking_severities` | string | `"P0,P1"` | Comma-separated severities that block (R39) |
| `pr_loop.merge_strategy` | string | `"merge"` | `merge` or `squash` (R43) |

Env overrides (env wins over config, config wins over the built-in default — R20):
`HARNESS_PR_LOOP_ENABLED`, `HARNESS_AUTO_MERGE`, `HARNESS_MAX_ROUNDS`,
`HARNESS_BLOCKING_SEVERITIES`, `HARNESS_MERGE_STRATEGY`.
Env-only (never in config): `HARNESS_POLL_INTERVAL` (60), `HARNESS_POLL_CEILING` (900),
`HARNESS_FIRST_RESPONSE` (180), `HARNESS_DRY_RUN`.

Reader: a new `_cfg_pr_loop_value <file> <key>` in `harness-install.sh`, modeled
**exactly** on the existing `_cfg_models_value` (section-scoped `awk`, comment-stripped,
quote-stripped, empty when unset) so a same-named key under another section can never be
read (R19). A `pr_loop_enabled` helper returns exit 0 unless the resolved value is
literally `false` (absence ⇒ enabled, R18).

## Watcher interface  (serves: R21–R35)

`tools/wait-for-codex.sh` — three invocation forms, one script, one evaluation routine:

| Invocation | Mode | Exit codes |
|---|---|---|
| `<pr> <trigger-comment-id> <round-dir>` | wait (source contract, unchanged) | `0` findings · `2` timeout · `3` clean · `4` usage · `5` preflight/no-response |
| `preflight <pr>` | static checks, posts nothing | `0` ok · `5` failed (one-line diagnostic) |
| `evaluate <round-dir>` | offline re-evaluation of already-written files, no `gh` | `0` findings · `1` pending · `3` clean |

Design notes:

- The `evaluate` sub-mode exists so the classification step and the test suite can apply
  the *same* freshness logic without a live GitHub (R29) — this is the seam that makes
  R25/R26/R27 testable from fixtures.
- The freshness anchor is read from `<round-dir>/trigger-ts.txt` in `evaluate` mode and
  resolved once at startup in wait mode (R23/R24).
- The first-response probe (R32) counts **any** bot activity — any reaction on the trigger
  comment (Codex adds 👀 on pickup), any bot issue comment, any bot review. It arms only
  while nothing has been seen, disarms permanently on first sight, and is skipped when
  `HARNESS_FIRST_RESPONSE=0` (R33) or when it would exceed `HARNESS_POLL_CEILING`.
- POSIX conversion checklist (R21): `#!/bin/sh`; no `[[ ]]`; no `read a b < <(cmd)` process
  substitution (use a command substitution + `set --`/`cut`); no `${var:0:7}` (use
  `cut -c1-7`); no `(( ))` arithmetic command (use `[ "$a" -gt "$b" ]` / `$(( ))`).

## Installer changes  (serves: R1–R14)

| Symbol | Change | R-id |
|---|---|---|
| `HARNESS_SDD_CMDS` | **unchanged** — it drives unconditional emission | — |
| `HARNESS_PR_LOOP_CMDS` | new: `"sdd-pr-loop"`, emitted only when the gate is on | R2, R3 |
| `HARNESS_OWNED_CMDS` | new: `"$HARNESS_SDD_CMDS $HARNESS_PR_LOOP_CMDS"` — the **removal ledger** union used by every reclamation loop | R4, R5 |
| `HARNESS_CLAUDE_SHIMS` | add `pr-fixer` (ledger only; emission stays gated) | R4, R10 |
| `HARNESS_PR_LOOP_OWNED` | new: the non-command harness-owned pr_loop paths (`.claude/agents/pr-fixer.md`, `.opencode/agent/pr-fixer.md`, `.agents/agents/pr-fixer.md`) reclaimed on gate-off | R5 |

Emission and reclamation flow:

1. **§5 CMDDIR** — `sdd-pr-loop.md` is written into `CMDDIR` **unconditionally** (R1). This
   is load-bearing: the codex-prompts and antigravity reclamation paths compare against
   `$CMDDIR/<name>.md`, so gating generation would make an already-stamped file
   permanently unremovable.
2. **§5/§5b/§5c/§5d mirrors** — each per-front-end copy loop iterates
   `$HARNESS_SDD_CMDS` plus, **when the gate is on**, `$HARNESS_PR_LOOP_CMDS` (R2, R3).
3. **§5 claude shims** — a gated `emit_agent pr-fixer "Read, Edit, Bash, Grep, Glob" "…"`
   after the six existing calls (R10).
4. **§5b opencode** — a gated `gen_oc_agent pr-fixer` writing `.opencode/agent/pr-fixer.md`
   (new hoisted emitter, so §7 can byte-compare it) (R11). `gen_opencode_json` is
   **untouched** (R12).
5. **§5c antigravity** — a gated `gen_ag_persona pr-fixer "<desc>" .agents/agents/pr-fixer.md`
   call *outside* the `ag_personas` loop, so the model-routing role map is unchanged (R13,
   R14).
6. **§7 deselect loop** — every `$HARNESS_SDD_CMDS` iteration becomes
   `$HARNESS_OWNED_CMDS`; each front-end's arm additionally reclaims its `pr-fixer`
   artifact (by name in `.claude`/`.opencode`, `remove_if_pristine` in `.agents/`) (R4, R6,
   R7).
7. **§7b gate-off reclamation (new pass)** — after the deselect loop and **before** the
   `rm -rf "$CMDDIR"` cleanup: while `pr_loop.enabled` is false, for every **still
   selected** front-end, reclaim its `sdd-pr-loop` command and `pr-fixer` artifact under
   the R4 ownership rules, then prune empty dirs (R5). This is the axis the existing
   `PRIOR_AGENTS`-driven loop cannot cover, because the front-end is still selected.
8. `migrate_config` gains a `pr_loop:` arm following the `fix_lane`/`models` pattern
   (presence check tolerating a trailing comment, append-only at EOF, block text copied
   verbatim from the source `harness.config.yaml` tail) (R16, R17).
9. `manifest.txt` gains a line describing the gated pr_loop glue; `_ignores` (the seeded
   `.harness/.gitignore`) gains `.pr-loop/` (R35).
10. `chmod +x "$H/tools/wait-for-codex.sh"` beside the existing helper chmods (R21).

## Approach notes

- **Ordering matters in §7.** The CMDDIR cleanup (`rm -rf "$CMDDIR"`) is already deferred
  to after the deselect loop precisely because the pristine compares read from it; the new
  gate-off pass (§7b) must land **before** that cleanup for the same reason.
- **`remove_owned` is by-name and already `[ -f ]`-guarded**, so widening its stem list to
  `$HARNESS_OWNED_CMDS` / `HARNESS_CLAUDE_SHIMS + pr-fixer` is safe when the file is
  absent — no new guard is needed.
- **`.opencode/agent/` is a new directory** the harness owns. Create it only when the gate
  is on, remove only the harness-owned stem, `rmdir` it and its parent only when empty
  (R7).
- **Round-3 escalation without a router.** MCO handed off to `route-task`, which the
  harness deliberately does not vendor. The body instead says: escalate to a different
  worker if the host CLI offers one, otherwise run one combined in-session fix pass, and
  record `worker`/`role` files either way so the handover summary stays reconstructible.
- **The first-response probe must not create false negatives.** Arm it only until the
  first observed bot activity, and skip it when `HARNESS_FIRST_RESPONSE >= HARNESS_POLL_CEILING`
  (the ceiling already covers that case) or when it is `0`.
- **Keep the vendored jq filters intact.** Where the Builder must edit them (variable
  renames, `--arg` plumbing), change nothing about the predicate shapes: `startswith($bot)`
  for the bot login, `contains("Reviewed commit") and contains($sh)` for the banner,
  `(.created_at // "") >= $since` for freshness, `(.content // "") == "+1"` for the
  reaction.
- **`--paginate --slurp | jq 'add // []'`** must be preserved on both comment fetches —
  dropping `--slurp` makes multi-page REST output unparseable, and dropping `--paginate`
  reintroduces the past-page-1 blind spot.
- **Test isolation.** Every installer-invoking test sets `CODEX_HOME` under its own temp
  dir (the codex glue is machine-global and shared across targets). The jq-dependent
  fixture assertions print a `skip` line and continue when `jq` is absent, so a CI box
  without jq still exercises the whole installer surface.
