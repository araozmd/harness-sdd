## Anti-tautology

Three specific ways these cases could pass while proving nothing, and what stops each:

- **"Not selected" is the default for most boards.** A fixture where nothing was selectable
  anyway would satisfy R1 with the park doing no work. Every park case therefore runs on a
  fixture whose **positive control is the same feature unparked**: the case first asserts the
  feature IS selected with a known route, then parks it and asserts the block. R2 and R9 are
  that control made explicit rather than implied.

- **R7 ("no change") is an absence assertion.** Compared against a recorded baseline of the
  real selector output on the current board, captured in the same run — not against a
  hand-written expectation that could drift into agreement with a bug.

- **R3 could pass because the board was invalid for an unrelated reason.** Each invalid
  fixture is paired with the same board minus the bad `parked` key, asserted **valid** in the
  same run, so the rejection is attributable to the park and nothing else.

- **R3's fallback case must actually take the fallback path.** `jsonschema` is present on some
  machines and absent on others, and the fallback only runs when the import fails. The case
  forces the fallback explicitly rather than hoping for the ambient state, and asserts a
  precondition that the forced path was the one taken — otherwise it silently re-tests the
  `jsonschema` path already covered above.

## Mutation proof (required before the PR is opened)

Each mutation is reverted from the committed implementation, one at a time, with the tree
verified clean between, and must be caught by its own named case:

| mutation | must fail |
|---|---|
| drop the `parked` blocker record from `featureBlockers` | R1 |
| make `featureRoute` return `null` when parked (the wrong fix) | R2 / R9 |
| relax `minLength: 1` on `reason` | R3 |
| drop the parked marker from the `unmet-dependency` detail | R5 |
| remove the `set-status` refusal | R8 |

A surviving mutation is treated as a signal that the rule is under-specified, not merely that
the test is thin.
