# Feature-level park: hold a real feature before it has been specced — Functional Spec

## Context

Reported from a target running an installed `.harness/`. An operator needed to hold a **real
feature** — one that will need a full spec — because it was blocked on a Meta review cycle
and three product decisions. None of those are board dependencies, so `depends_on` could not
express it.

The route table has no row for *"this feature is real and not yet workable"*:

- `tools/next-task.mjs:352` — `if (feature.sdd) return 'architect'` on `pending`.
  **`autonomous` is never consulted on that branch.**
- `:353`, `:370`, `:372` — the three places `autonomous` bites are the quick-fix lane
  (`pending + !sdd`) and the `spec-ready` approval pause. It gates the *spec-ready pause*,
  never the Architect.
- The feature status enum is `pending, spec-ready, in-progress, in-review, done`. Epics get
  `draft`; features do not.

So the only lever that bites at `pending` is `sdd:false + autonomous:false`, which routes into
the **gated quick-fix** lane. That is what the operator had to use, and it mislabels a feature
needing a full spec as a fix needing none — they wrote a prose correction *inside the board
entry* warning the next reader not to skip the spec. **A board entry that needs a note saying
its own field is lying is the defect.**

`depends_on` covers board-internal blocking. Nothing covers external blocking.

### Resolved during specification

**Mirror `gated-epic` (`:364`), and copy what it does *not* do.** It leaves `featureRoute`
alone and holds the feature out with a blocker record. A park is the same concept one level
down, so it is built the same way and the two read alike. This is what makes R2 true by
construction rather than by test: parking cannot alter routing, because parking never touches
the routing function.

**A field, not a status enum value.** A `parked` status mirrors epics but loses *where to
return to*: a park can arrive **after** speccing — `spec-ready`, then product says hold — and
a status-based park has nowhere to record the prior state. A field composes with every status
and survives the round trip untouched.

**The reason is required (`minLength: 1`); presence means parked.** The failure mode being
fixed is a park with no legible reason, so a bare boolean would reproduce it exactly.

**`autonomous` is not repointed.** Making `autonomous:false` gate the Architect is the obvious
one-line fix and it is wrong. Measured on this board it would silently park five real
features — E17-F02/F03/F04, E21-F05, E24-F04 — including the one `/sdd-next` selects. Today
`autonomous:false` means "do not auto-approve my spec, do not auto-build"; it has never meant
"do not spec it". Changing that is a breaking semantic shift for every installed target.

### The four open questions, decided

1. **Does a park block dependents, and how legibly?** — A parked feature is not `done`, so
   `depends_on` already stalls dependents; that behaviour is correct and unchanged. What was
   missing is legibility: a dependent reported a generic `unmet-dependency` and the reason was
   invisible one hop away. The dependent's detail now **marks a parked blocker inline**
   (`E17-F02=pending (parked: <reason>)`), so a stalled chain explains itself. No new blocker
   code, no new code path — one richer string.

2. **Slices as well as features?** — **Features only, deliberately.** The field report is
   feature-level; slices are an umbrella concept with their own status enum and their own
   lane, and extending the park there without a reported need is speculation. Recorded here as
   a decision rather than an oversight, so a later slice park is a scoped follow-up.

3. **Does `parked` survive a status transition?** — **Yes, and a transition on a parked
   feature is refused.** A park that a status change silently clears is not a park; it is a
   suggestion, which is the advisory-prose failure this feature exists to end.
   `tools/tasks-lock.py set-status` therefore rejects the write, names the reason, and points
   at the unpark step. Unparking is a separate, explicit act (`apply`), after which the
   ordinary transition succeeds.

4. **A reporting surface so parks do not become invisible?** — **Deferred, and the gap is
   named.** Parked features appear in the `blocked` envelope with their reason whenever the
   board has no actionable work. They are **not** listed while other work is selectable,
   because `selectedResult` carries no blockers — so park-and-forget remains possible. Adding
   a dedicated listing means changing what a `selected` envelope contains, which is a consumer
   contract change and belongs in its own feature. Stated so the next reader inherits the gap
   rather than rediscovering it.

## Requirements (EARS)

| R-id | Requirement |
|---|---|
| **R1** | While a feature carries a `parked` object, when `/sdd-next` runs in board mode, the selector shall not select it and shall emit a blocker record with code `parked` whose detail carries the reason. |
| **R2** | While a feature is parked, the selector shall not alter the route that feature would otherwise take; when the park is removed, the feature shall become selectable with exactly the route and status it had before. |
| **R3** | When a board carries a `parked` object without a non-empty `reason`, the board shall be invalid — the schema requires `reason` with `minLength: 1`. |
| **R4** | When `/sdd-next` targets a parked feature explicitly, it shall return blocked with the `parked` record rather than selecting it. |
| **R5** | While a parked feature is an unmet dependency of another feature, the dependent's `unmet-dependency` detail shall name the park and its reason. |
| **R6** | While a feature is parked at any status, the park shall hold and the feature's `status` shall be unchanged by the park. |
| **R7** | When a board carries no `parked` key anywhere, every selector and validator outcome shall be byte-identical to the behaviour before this feature. |
| **R8** | When `tasks-lock.py set-status` targets a parked feature, it shall refuse the transition, name the reason, and state that the feature must be unparked first. |
| **R9** | When the `parked` object is removed from a feature, that feature shall be selectable again with the same route it would have had. |

## Out of scope

- Repointing `autonomous` (see above — it would park five live features).
- A `parked` **status** enum value.
- Any change to `featureRoute`.
- Slice-level parks (decision 2).
- A dedicated parked-feature report (decision 4).

## Non-functional

- **Additive schema.** Existing boards carry no `parked` key and must be unaffected (R7).
- Installed body ⇒ `VERSION` **MINOR** bump (new backward-compatible capability).
- POSIX sh / `dash` for tests; green under `sh tools/run-tests.sh`.

## ADR

No new ADR. This feature *applies* `ADR-0001` (deterministic next selection): the park is a
blocker record consumed by the same deterministic selector, not a new decision procedure.
