# E25-F01 — Claude-first selection defaults

Every active target is Claude-only (both umbrellas re-selected 2026-09-05) and the
multi-front-end matrix is the installer's largest complexity share. Park by DEFAULT
FLIP, not deletion (RATIONALE.md ablation doctrine: float, don't pin — the flip is
reversible and produces the opt-in evidence that justifies or refutes a later removal).

## Requirements (EARS)

- **R1** — When a FRESH target (no `.harness/.harness-version`) is installed with no
  `--agents`/`HARNESS_AGENTS` override and no TTY, the system SHALL select `claude`
  only (today: all front-ends).
- **R2** — When `--agents=host` resolves UNDETECTED on a FRESH target, the fallback
  SHALL be `claude` only, and the report line SHALL say so and name the opt-in.
- **R3** — When the interactive picker opens on a FRESH target with an undetected
  host, its pre-checked baseline SHALL be `claude` only (one keystroke re-adds any
  other front-end before confirming).
- **R4** — An EXISTING install's behavior SHALL be byte-identical to v0.71.0: a
  recorded `.harness/.agents` selection is preserved exactly as before, and the
  legacy stamped-but-unrecorded arm keeps its current answer.
- **R5** — Explicit selection SHALL keep working unchanged: every key remains legal in
  `--agents`/`HARNESS_AGENTS`, and `docs/INSTALL.md` SHALL name the park and the
  opt-in path.
- **R6** — `VERSION` MINOR bump + CHANGELOG entry; suites that need multi-front-end
  fixtures opt in explicitly and a new test pins the fresh claude-only default.
