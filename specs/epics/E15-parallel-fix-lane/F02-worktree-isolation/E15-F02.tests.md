## Behavioral / end-to-end checks
- Build each fixture with a bare/local `origin`, a primary checkout, configured
  local Git author identity, an `origin/HEAD` symbolic ref, minimal init entrypoint,
  and commits on the candidate base branches. No test fetches from a network.
- For R1/R2, place ambient `HEAD` on a commit distinct from the resolved base and
  assert the new branch points to the captured default/base ref, not ambient
  `HEAD`. Exercise an `origin/HEAD` default other than `main`, absent
  `origin/HEAD` with local `main`, and explicit local override.
- For R3–R5, snapshot `git show-ref`, `git worktree list --porcelain`, and the
  destination's absence before each invalid call; assert all remain unchanged
  afterward and diagnostics name the dirty/colliding/invalid resource. Base-name
  cases accept `release/1.2` when that exact local branch exists and reject
  `refs/heads/main`, `main~1`, `--help`, and a syntactically valid but absent local
  branch before mutation.
- For R6, create two distinct fixes, edit the same tracked filename differently in
  each, stage in only one, and assert the other worktree's file, index, branch, and
  `HEAD` are unchanged.
- For R7, seed all four allowlisted files, omit one in a second case, and seed a
  scheduler lock plus an arbitrary ignored secret. Resolve link targets and assert
  only the allowlist points to the primary checkout. Assert `git status` remains
  clean after linking.
- For R8/R10, use fixture init scripts that record cwd/layout, emit both stdout and
  stderr diagnostics, and then either succeed, fail before writing, or fail after
  creating unexpected non-ignored work. Assert successful create stdout is exactly
  one absolute worktree path line, init output remains available on stderr, safe
  rollback deletes only the unchanged-at-base case, and the dirty case is preserved
  with an actionable path/branch diagnostic. Also retarget an ignored helper-managed
  symlink during a failing init and assert its changed destination, worktree, and
  branch all survive.
- For R9, run a small argv-recording command containing spaces and glob characters;
  assert no shell re-parsing, exact worktree cwd, source/installed canonical
  `HARNESS_DIR`, and propagation of a chosen non-zero status.
- For R11, independently stage, modify, and create an untracked file; switch/alter
  branch identity where Git permits; leave a clean unmerged commit; and put the
  clean primary on a branch other than the resolved base even after merging.
  Every case must retain the branch, path, registration, and user files. Also
  statically reject `--force`, `branch -D`, and recursive filesystem deletion in
  the helper.
- For R12, merge the feature branch into the resolved local base from another
  checkout, restore the primary to a clean base checkout, and run teardown. Assert
  only the derived path/registration/branch and unchanged managed links disappear;
  an unrelated worktree and branch survive.
- For R13, call teardown again after R12 and assert zero/no changes. Construct an
  absent-path stale registration whose recorded branch is exact and whose recorded
  `HEAD` equals the merged branch tip, plus a merged lone branch; each may be
  reconciled while the clean primary is on base without a nonexistent-path dirt
  check. Assert a path without registration, a registration without the expected
  branch, a mismatched recorded `HEAD`, and unmerged remnants are preserved.
- For R14, installer coverage performs both fresh install and upgrade against a
  target with a pre-existing `.gitignore` entry. It asserts exactly one literal
  `.claude/worktrees/` line, preservation of the user's lines, and executable
  `.harness/tools/fix-worktree.sh`. The version-policy test locates the changelog
  section containing stable feature id `E15-F02`, parses that section's SemVer and
  the immediately older changelog section, asserts equal major, exactly
  one-greater minor, and patch zero, then asserts the current `VERSION` is at least
  that feature version. It uses neither tags nor Git history and remains valid
  after future releases.

## Non-functional checks
- POSIX shell syntax: `sh -n tools/fix-worktree.sh` and
  `sh -n tests/test_fix_worktree.sh`.
- Portability: no GNU-only `readlink -f`, `realpath`, `flock(1)`, arrays, or
  third-party utilities; Git is the only new runtime command.
- Safety: the suite owns every fixture under `mktemp -d`, records explicit paths,
  and cleans via a trap. The production helper itself contains no forced worktree
  removal, forced branch deletion, or recursive filesystem deletion.
- Regression: `./init.sh`, `sh tests/test_board_lock.sh`,
  `sh tests/test_install.sh`, and the full configured verification command pass.
