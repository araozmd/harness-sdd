# Worktree-per-fix isolation helper for concurrent fix branches — Functional Spec

## Context
Epic E15 will let several autonomous E99 fixes progress at once. Concurrent fixes
cannot share one checkout: branch switches and file edits would interleave. This
feature provides the single-fix lifecycle primitive that F03 can call to create,
enter, and safely retire one isolated Git worktree and branch. The user is the F03
parallel dispatcher and, secondarily, an operator recovering a failed fix.

## Business rules
- **One fix, one branch, one worktree.** A fix key formed from a validated E99 fix
  id and slug maps deterministically to branch `feat/<id>-<slug>` and an absolute
  worktree directory under the canonical repository's `.claude/worktrees/`.
- **Branch from the repository's default branch ref, never ambient `HEAD`.** The
  helper resolves the default local base branch from `origin/HEAD`, falling back to
  local `main`; an explicit local base override is allowed for repositories whose
  default branch cannot be discovered. It snapshots that ref's commit and uses the
  same commit for collision checks and `git worktree add`. It never includes
  uncommitted files from the primary checkout.
- **Fail closed before creation.** Creation refuses a dirty canonical primary
  checkout, an invalid id/slug/base, a missing base ref, an existing destination,
  an existing branch, or a branch already checked out in another worktree. It
  never adopts, resets, force-deletes, or overwrites a colliding resource.
- **Only an explicit personal-layer allowlist is linked.** After Git creates the
  worktree, the helper recreates existing personal configuration as absolute
  symlinks from the canonical checkout for
  `.claude/settings.local.json`, `AGENTS.local.md`, `CLAUDE.local.md`, and
  `AGENTS.override.md`. Missing source files stay absent. It does not sweep or copy
  arbitrary ignored files or secrets. `.claude/scheduled_tasks.lock` and other
  runtime locks/scratch remain worktree-local and are never linked.
- **The worktree must be runnable.** Provisioning completes only after the
  appropriate source-layout `./init.sh` or installed-layout
  `.harness/init.sh` succeeds inside the new worktree. A `run` operation executes
  exactly one caller-supplied command with the worktree as its current directory
  and with `HARNESS_DIR` set to the canonical main harness directory, preserving
  E15-F01's one-board/one-lock contract.
- **Safe teardown, no force.** Teardown refuses if the expected worktree is on a
  different branch, has staged, unstaged, or untracked non-ignored changes, or if
  the feature branch is not merged into the resolved base. It removes only
  helper-managed personal-layer symlinks whose targets still match the canonical
  sources, then uses non-forced Git removal and safe branch deletion.
- **Idempotent completed teardown.** Re-running teardown after both the worktree
  registration/path and branch are gone succeeds without side effects. A partial
  state is reconciled only when each remaining deletion is independently proven
  safe; otherwise teardown fails and names what was preserved.
- **Transactional provisioning.** If linking local files or running initialization
  fails after `git worktree add`, the helper rolls back only a still-clean,
  unchanged-at-base worktree and branch. If unexpected work appeared, it preserves
  both and reports the recovery path instead of forcing cleanup.
- **Installed harness capability.** The helper is part of the installed harness
  body, is executable in fresh installs, and the installer append-seeds
  `.claude/worktrees/` in the target root `.gitignore`. This additive capability
  requires a SemVer MINOR bump and matching changelog entry.

## Acceptance criteria (EARS)
> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md.

- **R1** — When creation receives a valid E99 fix id and slug, the helper shall
  create exactly one branch named `feat/<id>-<slug>` and exactly one linked Git
  worktree at `.claude/worktrees/<id>-<slug>` under the canonical repository.
- **R2** — When resolving the branch base, the helper shall use the local branch
  named by `origin/HEAD`, fall back to local `main` when that symbolic ref is
  absent, accept an explicitly named local base only when requested, and create the
  fix branch from the resolved ref's captured commit rather than ambient `HEAD`.
- **R3** — If the canonical primary checkout has staged, unstaged, or untracked
  non-ignored changes, then creation shall exit non-zero before creating a branch
  or worktree and shall report that the primary checkout must be clean.
- **R4** — If the fix id, slug, or base is unsafe or unresolved, then the helper
  shall exit non-zero without invoking a mutating Git operation; accepted ids shall
  match `E99-F[0-9]+`, slugs shall match `[a-z0-9]+(-[a-z0-9]+)*`, and base names
  shall pass `git check-ref-format --branch`, shall be local short names (not
  option-looking values, `refs/...` full refs, or revision expressions), and shall
  resolve exactly as `refs/heads/<base>^{commit}`.
- **R5** — If the derived branch, destination path, or Git worktree registration
  already exists, then creation shall exit non-zero with the colliding resource
  named and shall not adopt, reset, remove, or overwrite it.
- **R6** — When two distinct valid fix keys are provisioned sequentially while
  both remain active, the helper shall keep their paths, branches, checked-out
  files, indexes, and `HEAD`s independent under `.claude/worktrees/`.
- **R7** — When an allowlisted personal-layer source file exists in the canonical
  checkout, the helper shall create the corresponding absolute symlink in the new
  worktree; when it is absent, the destination shall remain absent; the helper
  shall never link `.claude/scheduled_tasks.lock` or an unallowlisted ignored file.
- **R8** — When provisioning a source-layout or installed-layout worktree, the
  helper shall run that worktree's initialization entrypoint and shall report
  success only when initialization exits zero.
- **R9** — When the caller uses the `run` operation, the helper shall execute the
  supplied command with its current directory at the registered worktree and
  `HARNESS_DIR` set to the canonical main harness directory, returning the
  command's exit status unchanged.
- **R10** — If provisioning fails after Git creation, then the helper shall remove
  the new worktree and branch only when both remain clean and at the captured base
  commit; otherwise it shall preserve them and return an actionable recovery error.
- **R11** — If teardown finds staged, unstaged, or untracked non-ignored work, an
  unexpected checked-out branch, or a feature branch not merged into the resolved
  base, or the clean canonical primary checkout is not currently on that resolved
  base, then the helper shall exit non-zero without forced removal or branch
  deletion and shall name the preservation reason.
- **R12** — When teardown finds the expected clean worktree and the feature branch
  merged into the resolved base while the clean canonical primary checkout is on
  that base, the helper shall remove only unchanged helper-managed symlinks, remove
  the worktree without force, prune its Git registration, and delete the branch
  with Git's safe delete.
- **R13** — When teardown is repeated after the expected worktree and branch are
  already absent, the helper shall exit zero without changing any other branch,
  path, or worktree; when only one resource remains, it shall remove it only after
  proving the same clean/merged safety conditions.
- **R14** — The harness installer shall ship the worktree helper as an executable,
  append-seed `.claude/worktrees/` exactly once in the target root `.gitignore`
  without clobbering existing entries, and the installed-body change shall carry a
  SemVer MINOR `VERSION` bump with a matching `CHANGELOG.md` entry.

## Out of scope
- F03's selection, dependency filtering, maximum concurrency, process scheduling,
  shared-path conflict guard, deferral logging, and `/sdd-fix-parallel` command.
- Board mutation logic; worktree commands only provide canonical `HARNESS_DIR` so
  callers use E15-F01's existing locked write path.
- Creating PRs, polling review, merging, or deciding when a branch is ready to
  merge.
- Auto-fetching or updating the default branch, auto-merging/rebasing feature
  branches, resolving merge conflicts, or force-removing work.
- Copying every gitignored file, user-global configuration, credentials, runtime
  locks, telemetry, caches, or tool scratch directories into worktrees.
- Windows support, distributed/multi-host coordination, or non-Git repositories.
- New TaskStore statuses, schema fields, or changes to `state/tasks.json`.

## Open questions
None blocking. The inbox choices are resolved as follows:
- The helper is `tools/fix-worktree.sh`, matching the repository's installed,
  executable helper convention.
- Active worktrees live directly at
  `<canonical-repo>/.claude/worktrees/<id>-<slug>`; Git continues to keep its
  internal administrative records under the shared Git common directory.
