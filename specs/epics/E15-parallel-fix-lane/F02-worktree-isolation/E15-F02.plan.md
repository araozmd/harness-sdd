# Worktree-per-fix isolation helper for concurrent fix branches — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it
> serves.

## Stack & dependencies
- Language/framework: POSIX `sh` plus the existing `git` CLI. *(serves: R1–R13)*
- New dependencies: none. `python3` remains an indirect harness prerequisite
  because initialization and E15-F01 require it; F02 adds no package. *(serves: R8,
  R9)*

## Data model
No TaskStore or application schema changes.

| Entity | Field | Type | Notes |
|---|---|---|---|
| fix key | `id` | string | Strict `E99-F[0-9]+`; retained as supplied in the branch/path. Serves R1, R4. |
| fix key | `slug` | string | Strict lowercase kebab case; no slash, dot segment, or shell metacharacter. Serves R1, R4. |
| branch | name | Git ref | `feat/<id>-<slug>`, created at one captured base commit. Serves R1, R2. |
| worktree | path | absolute directory | `<repo-root>/.claude/worktrees/<id>-<slug>`. The directory itself is the active-worktree registry. Serves R1, R5, R6. |
| personal link | source/destination | absolute symlink | Fixed four-path allowlist; runtime locks excluded. Serves R7, R12. |

## CLI interface
`tools/fix-worktree.sh` self-locates both source layout
(`<repo>/tools/fix-worktree.sh`) and installed layout
(`<repo>/.harness/tools/fix-worktree.sh`). Diagnostics go to stderr. Create prints
only the absolute worktree path to stdout so F03 can consume it without parsing
prose. *(serves: R1, R8, R9)*

| Invocation | Contract | R-id |
|---|---|---|
| `fix-worktree.sh create <E99-F##> <slug> [--base <local-branch>]` | Validate/preflight; capture base commit; create branch+worktree; link allowlisted local files; initialize; print absolute path. | R1–R8, R10 |
| `fix-worktree.sh run <E99-F##> <slug> -- <command> [args...]` | Resolve the exact registered path/branch; `cd` there; set canonical main `HARNESS_DIR`; execute without shell re-parsing and propagate status. | R5, R9 |
| `fix-worktree.sh teardown <E99-F##> <slug> [--base <local-branch>]` | Re-resolve base; verify identity, clean state, and merged ancestry; unlink unchanged managed links; non-force remove/prune/safe-delete. Already-absent is success. | R11–R13 |

### Repository, harness, and base resolution
- Determine the caller's repository top-level and absolute shared Git common
  directory using read-only `git rev-parse`; reject execution outside a non-bare
  Git repository. Parse each `worktree <path>` record from
  `git worktree list --porcelain`, query that candidate with
  `git -C <path> rev-parse --absolute-git-dir`, and select the **single** candidate
  whose absolute Git dir equals the absolute common directory. That is the
  canonical primary; zero or multiple matches, a `bare` record, an absent
  candidate path, or an unresolvable path fails closed. Do not assume porcelain
  emits a Git-dir field and do not assume the caller is primary. Resolve the
  harness directory as `<primary>` when the invoking helper's repo-relative path
  is `tools/fix-worktree.sh`, or `<primary>/.harness` when it is
  `.harness/tools/fix-worktree.sh`; reject any other layout. *(serves: R1, R9)*
- Base precedence is: explicit `--base`; else the local branch corresponding to
  `refs/remotes/origin/HEAD`; else local `main`. A remote-tracking ref is never
  itself the creation base: the corresponding local branch must exist. For an
  explicit value, require `git check-ref-format --branch` and reject a leading
  hyphen, a `refs/` prefix, and any value that is not an exact local short branch
  name; this admits names such as `release/1.2` but rejects `refs/heads/main`,
  `main~1`, and option-like input. Capture `refs/heads/<base>^{commit}` once after
  validation and pass that object id to `git worktree add -b`; do not fetch and do
  not use `HEAD`. *(serves: R2, R4)*
- Before mutation, check the primary checkout with
  `git status --porcelain --untracked-files=all`; ignored personal files do not
  make it dirty. *(serves: R3)*

### Local-layer materialization
Create parent directories as needed, then use absolute symlinks for exactly:
`.claude/settings.local.json`, `AGENTS.local.md`, `CLAUDE.local.md`, and
`AGENTS.override.md`. Refuse an unexpected destination. Do not materialize
`.claude/scheduled_tasks.lock`; each worktree/tool may create its own runtime lock.
Do not enumerate `git ls-files --others --ignored`, which would copy secrets and
caches outside the documented layer. *(serves: R7)*

### Safe cleanup and rollback
- Use `git status --porcelain --untracked-files=all` for dirt checks. Ignored
  helper-managed symlinks do not count as work, but remove a managed link only if it
  is still a symlink to the expected canonical source. A replaced file or retargeted
  link is user work and blocks teardown. *(serves: R11, R12)*
- Verify the worktree's symbolic branch exactly matches the derived branch and
  verify `git merge-base --is-ancestor <branch> <base>` before normal teardown.
  Also require the canonical primary to be clean and currently checked out on the
  resolved base; this makes Git's `git branch -d` safe-delete reference agree with
  the separately proven merge base rather than an unrelated ambient `HEAD`.
  Remove through `git worktree remove` without `--force`, run
  `git worktree prune`, then use `git branch -d`. Never call `rm -rf`,
  `git worktree remove --force`, or `git branch -D`. *(serves: R11, R12)*
- Rollback after a provisioning failure is narrower than normal teardown because
  the branch cannot be merged yet: it is allowed only if the worktree is clean
  after managed-link removal, its `HEAD` still equals the captured base commit, and
  its branch identity matches. Otherwise retain everything and report the exact
  path/branch. *(serves: R10)*
- For idempotence, classify path, worktree registration, and branch independently:
  **all absent** is success; **path absent + exact stale registration + branch
  present** may prune/delete only when the registration records the expected branch
  and a `HEAD` equal to the current branch tip, the branch is merged into the
  resolved base, and the clean primary is on that base (filesystem dirt is
  deliberately not checked because no path exists); **path and registration absent
  + lone branch present** may safe-delete only with the same merged/base proof;
  **path present without its exact registration**, **registration without its
  expected branch**, or any other shape is preserved and fails loudly. Unrelated
  paths are never touched. *(serves: R13)*

## Approach notes
- The chosen single helper is preferable to separate create/remove scripts because
  identity validation, base resolution, link ownership, and cleanup safety remain
  one contract. A prose-only convention would let F03 bypass those checks; a
  long-lived registry would duplicate Git's own worktree registry.
- The helper does not decide whether to run a fix or when it is merged. F03 supplies
  those lifecycle calls. `run` is deliberately synchronous and single-command; F03
  owns any parallel process management.
- Tests must use disposable Git repositories with local identity configuration and
  no network. They must never create under this repository's real
  `.claude/worktrees/`, alter live branches, or freeze the literal version.
