## Fixture and static contract checks
- Build a disposable TaskStore containing eligible E99 fixes out of array order,
  a dependency-done fix, a dependency-blocked fix, gated and `sdd:true` fixes,
  plus a lower-id non-E99 feature. The fixture oracle must produce numeric E99
  order and exclude every forbidden candidate. No fixture touches live
  `state/tasks.json`.
- Exercise absent `max_parallel`, values `1` and `2`, and invalid `0`, negative,
  fractional, string, and empty values. Require `shared_paths` to be a list of
  non-empty strings. For shared patterns, accept canonical exact repo-relative
  paths and `dir/*`; reject a scalar, map, non-string, empty string, absolute
  path, `.`, `./x`, `../x`, `a/../b`, `a//b`, `a/`, control characters, `*`,
  `a/**`, and `a/*.sh`. Snapshot the fixture board and assert invalid preflight
  leaves it byte-identical.
- Execute the temporary batch-claim mutator through a copied F01 helper against a
  disposable harness root with explicit `HARNESS_DIR`. Assert three valid claims
  all become `in-progress`; then select a fix with a done dependency, change that
  dependency to non-done immediately before locked apply, and assert the complete
  board remains byte-identical.
- Create briefs declaring `src/a.sh`, `harness-install.sh`,
  `tests/test_install.sh`, `tools/new.sh`, and a configured `docs/generated/*`
  descendant. Assert only the first is parallel-safe. Separately test absent
  brief, absent heading, absolute/traversing path, and ambiguous prose; each is
  guarded with a reason.
- Assert `agents/fixer.md`, `agents/orchestrator.md`, and both command bodies carry
  the explicit phase order: capability/config/in-session-Builder preflight →
  one-time F02 provisioning while primary is clean → complete manifest →
  bookkeeping branch + locked claim → safe fan-out before wait → guarded exclusive
  wave → bookkeeping PR/base reconciliation → final report. Assert no contract
  names a vendor Task API or instructs shell `&`/background agent prompts.
- Assert the targeted worker contract names the exact fix id, clean Builder and
  Reviewer contexts, feedback rounds, canonical `HARNESS_DIR`, F01 writes, the
  pre-provisioned branch/worktree, no second F02 create, only a post-approval code
  PR, per-PR `/pr-loop`, and merge-observed handoff. Assert failure wording
  explicitly continues siblings.
- In a disposable source-layout Git repository, run the copied real F02/F01
  helpers through one provision, locked claim on a bookkeeping branch, code merge,
  locked done persistence, bookkeeping merge, local-base fast-forward, and exact
  teardown. Assert create count remains one and an unrelated branch/worktree keeps
  its contents, HEAD, and registration.
- In a disposable installed-layout Git repository, run the real
  `.harness/tools/fix-worktree.sh create` for every selected fix and assert the
  canonical checkout is clean and no batch manifest exists before each attempt.
  After successes and a provisioning failure settle, write the manifest and assert
  it precedes claim/dispatch while retaining parallel-selected, guarded-selected
  with reason, provisioning-failed with reason, and cap-deferred entries.

## Reviewer behavioral checks
- Use two disposable autonomous E99 fixes whose briefs name only independent
  fixture paths and configure `max_parallel: 2`. Instrument workers with progress
  markers or barriers supplied by the current host and verify both start before
  either is released. Do not use this repository's live board, branches, or PRs.
- Repeat with one independent brief and two shared/unknown briefs. Verify the
  independent wave settles first and guarded workers never overlap, running in
  numeric id order. The manifest must name the guard reason and every outcome.
- Simulate one worker returning non-zero while its sibling succeeds. Verify the
  sibling is awaited and reported, the failed worker's branch/worktree/status are
  preserved, no sibling state is reverted, and the aggregate command exits
  non-zero only after both outcomes are recorded. Repeat with successful selected
  fixes plus cap-deferred candidates and assert aggregate zero.
- In a no-write dry run of the targeted worker contract, trace two fixes through
  distinct branch/worktree/PR identities. Verify each `/pr-loop` receives only
  its own PR, neither reaches `done` before a merge result, and cleanup targets
  only the merged fix.
- Run against a fixture with no ready candidate and assert zero exit, the explicit
  message, no batch directory, no worktree, and a byte-identical board. Run the
  missing-concurrency and delegate-backend preflights and assert non-zero with the
  serial fallback message and the same zero-mutation/resource snapshot.
