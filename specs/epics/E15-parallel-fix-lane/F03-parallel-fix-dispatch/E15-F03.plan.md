# /sdd-fix-parallel dispatch with shared-path conflict guard and installer wiring — Technical Plan

> Every design decision cites the requirement ids it serves.

## Stack & dependencies
- Markdown role/command contracts plus POSIX shell installer/tests, matching the
  existing harness. Python 3 is reused only through the existing
  `tools/tasks-lock.py apply --mutator` write seam. No new package, daemon,
  executor, or vendor-specific API is introduced. *(serves: R4, R9, R15)*
- Runtime concurrency is the host agent's native in-session sub-agent delegation,
  expressed portably as “spawn/start a clean sub-agent.” The coordinator must
  start all parallel-safe workers before awaiting results. It must not prescribe
  Claude's Task tool, Codex collaboration calls, or any other vendor spelling.
  *(serves: R7, R9, R13)*

## Data model and configuration
No TaskStore schema or status change is permitted.

```yaml
fix_lane:
  max_parallel: 3
  # Extension-only; these are added to immutable built-ins:
  # harness-install.sh, tests/test_install.sh, tools/*
  shared_paths: []
```

| Value | Type | Rules | R-id |
|---|---|---|---|
| `fix_lane.max_parallel` | positive integer | Absent ⇒ `3`; invalid/non-positive ⇒ fail before mutation. It bounds batch size and concurrent safe workers. | R2, R3 |
| built-in shared paths | static patterns | Always include two exact paths plus `tools/*`; configuration cannot remove them. | R5 |
| `fix_lane.shared_paths[]` | list of non-empty strings | Extension-only exact canonical repo-relative path or one canonical directory-prefix pattern ending `/*`. Reject a scalar/map/non-string, empty entry, absolute path, leading `./`, `.`/`..` component, empty/repeated/trailing separator, control character, or other wildcard form. Config entries are never normalized. | R3, R5, R6 |
| fix brief `## Files expected to change` | non-empty list of repo-relative paths | Added by `/sdd-fix`; missing/unsafe/ambiguous data is guarded, never presumed safe. | R6, R16 |
| batch manifest | Markdown under a timestamp-shaped `progress/E99-fix-parallel-YYYYMMDDTHHMMSSZ/summary.md` directory | Pre-dispatch candidate classification plus appended per-fix outcomes; local run memory, not TaskStore data. | R10, R11, R13, R14 |

### Shared-path match semantics
Normalize a brief-declared path by removing one leading `./`, then require a relative
path with no empty component, `.` component, `..` component, newline, or wildcard.
Configured patterns receive no normalization and must already be canonical. An
exact config entry matches only the same normalized brief path. A valid `dir/*`
pattern matches descendants under `dir/`, not the directory token alone. Any
brief that cannot be classified by these rules is guarded and its reason is
written to the manifest. *(serves: R3, R5, R6, R10)*

## Command and role interfaces

| Interface | Contract | R-id |
|---|---|---|
| `/sdd-fix-parallel` | Argument-free Fixer-family coordinator. Run init, reject missing native concurrency or delegate Builder before mutation, read config/board/briefs, classify/manifest, provision exactly once, persist shared state on a bookkeeping branch, fan out safe wave, run guarded fixes serially, reconcile through a bookkeeping PR, update the base, and tear down exact merged fixes. | R1–R15 |
| Fixer serial intake | Existing `/sdd-fix` behavior plus a `Files expected to change` brief section; no spec directory or new lane state. | R16 |

It does not run global `next()` or recreate F02 resources; it drives that id's Builder/Reviewer rounds, creates only the post-approval code PR, runs its review loop, and reports merge-observed for coordinator-owned done/reconciliation/teardown. | R12–R14 |
| `tools/fix-worktree.sh create/run/teardown` | Existing F02 API, consumed unchanged for per-fix isolation and safe cleanup. | R11, R12, R14 |
| `HARNESS_DIR="$HARNESS_MAIN" python3 "$WORKTREE_HARNESS/tools/tasks-lock.py" apply --mutator "$CLAIM_MUTATOR"` | Atomic fresh-board claim of the successfully provisioned subset. The mutator asserts E99 identity and every selected R1 predicate before changing all selected statuses to `in-progress`; any assertion raises and leaves the board unchanged. | R4, R12 |

### Scheduling sequence
1. Run `init.sh` in source or `.harness/init.sh` in installed layout. Resolve the
   canonical main harness directory once. *(R12)*
2. Preflight native concurrent sub-agent support and
   `execution.builder.backend: in-session` before any mutation. If concurrency is
   absent or the backend is `delegate`, fail with the serial fallback message.
   *(R9, R14)*
3. Validate config. Read E99, dependency statuses, and each candidate brief.
   Order ready fixes by numeric suffix; choose the first `N`; classify them;
   write the complete pre-dispatch manifest including cap-deferred candidates.
   If none are ready, report the clean no-op and exit zero before creating the
   manifest. *(R1–R6, R10, R19)*
4. While the canonical primary is still clean, provision selected fixes
   sequentially through F02. Record a failure locally, leave that fix `pending`,
   and continue provisioning siblings. *(R11, R13)*
5. Create a collision-checked coordinator bookkeeping branch from the captured
   base and switch the canonical primary to it. Atomically claim only the
   successfully provisioned subset using one temporary mutator through F01, with
   explicit canonical `HARNESS_DIR`. Re-check every predicate and dependency
   status under the lock; all flips succeed or none do. On claim failure, return
   the clean primary to base, safely tear down unclaimed worktrees, and remove
   only the uncommitted bookkeeping branch. On success, commit the claim before
   dispatch. F02 create occurs exactly once per fix; workers reuse those resources.
   *(R4, R11, R12, R14)*
6. For every provisioned parallel-safe fix, create its clean targeted
   Orchestrator worker with explicit canonical `HARNESS_DIR`; start all of them
   before awaiting any. Wait for the whole safe wave to settle. *(R7, R12, R13)*
7. Run provisioned guarded fixes in numeric order, one targeted worker at a time,
   after the safe wave has settled. *(R8)*
8. Append every result to the manifest. Workers report merge-observed without
   setting `done` or teardown. After all settle, the coordinator serializes
   history, uses one locked finalizer to mark only merge-observed fixes `done`,
   commits all final shared truth, and persists it through a bookkeeping PR.
   After observing that merge, fetch/switch/`--ff-only` the canonical local base,
   prove exact F02 primary preconditions, and teardown only merged fixes using
   their original identities. Preserve failed resources and unrelated state.
   *(R10, R13, R14, R20)*

### Targeted worker state and failure contract
- The coordinator owns the atomic `pending → in-progress` claim. The worker never
  selects or claims another id. *(R1, R4, R13)*
- Builder completion moves only its fix to `in-review`; Reviewer rejection writes
  file-based feedback and moves only that fix back to `in-progress` for the next
  round. A hard build/review failure leaves the fix and resources recoverable and
  returns a non-zero per-fix result; it does not throw away sibling results.
  *(R12, R13)*
- Reviewer approval precedes the fix code PR. PR creation and `/pr-loop` are scoped
  to the one pre-provisioned branch. P0/P1 fixes repeat review for that same fix.
  PR/review/merge failure preserves `in-review`, the worktree, branch, and PR URL.
  The worker reports an observed merge; only the coordinator may finalize `done`,
  persist the bookkeeping PR, update the local base, and invoke exact teardown.
  *(R14)*

## Approach notes and rejected alternatives
- **Chosen: native sub-agent fan-out behind a portable role contract.** It matches
  the existing Orchestrator execution model and keeps Builder/Reviewer contexts
  clean. The role states ordering/overlap requirements without assuming how a CLI
  spells “spawn” or “wait.”
- **Rejected: shell-background code-agent processes.** The harness has no portable
  command for starting an agent with role context, and `execution.builder.delegate_cmd`
  is empty by default. Pretending either exists would make the default install
  unusable.
- **Rejected: a new daemon/job queue or dynamic diff planner.** Both exceed a
  single-machine, static-guard feature and add dependencies without serving the
  brief.
- Tests must not attempt to execute prose as code. They verify the durable role and
  command contracts statically, exercise candidate/claim fixture mutators against
  disposable TaskStores, and rely on the existing F01/F02 behavioral suites for
  lock/worktree implementation. Reviewer behavioral checks exercise native worker
  fan-out in the current host.
