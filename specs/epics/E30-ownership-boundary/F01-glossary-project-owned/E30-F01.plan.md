# `specs/glossary.md` becomes project-owned — Technical Plan

> Every decision cites the `R-id`(s) it serves. The mechanism already exists three times in
> this installer (`init.project.sh`, `specs/product.md`, `progress/lessons.md`); this feature
> moves one path from one class to the other and makes six prose authorities agree with it.

## Stack & dependencies

- Language: POSIX `sh` (`harness-install.sh`, `tools/harness-owned-paths.sh`), Markdown docs,
  POSIX `sh` test suites under `tests/`.
- New dependencies: **none**. The comparison uses `cmp -s`, which the installer already
  requires (`remove_if_pristine`), and the stub probe uses `head -n 1 | grep -qxF`, which
  `child_is_full_copy` already uses.
- New config keys / CLI flags / prompts / files under `.harness/`: **none** (ablation
  doctrine; see the DO NOT TOUCH list).

## Design

### 1. Tier membership (serves R7, R8, R9)

`harness-install.sh:703` becomes exactly:

```sh
HARNESS_BODY_PROSE='AGENTS.md agents docs specs/_templates'
```

That single edit is the whole body-side change. It is deliberately **not** accompanied by a
special case anywhere downstream: `copy()`, `thin_prose_tier`, `prose_tier_blockers`,
`child_is_full_copy` and `stub_files_in` all derive their behaviour from this variable, and
all five become correct for free.

Consequences the Builder must verify rather than assume — one per use site:

| Line (pre-change) | Use | Effect of the removal |
|---|---|---|
| ~1316 | `prose_tier_blockers` no-`diff` fallback | glossary is no longer named as an unprovable blocker (R9) |
| ~1326 | `prose_tier_blockers` main loop | an edited glossary no longer blocks `--thin` (R9) |
| ~1341 | `child_is_full_copy` | one fewer stub probe; `AGENTS.md`/`agents/`/`docs/`/`specs/_templates/` still detect layout |
| ~3390 | `thin_prose_tier` build/swap set | the glossary is never staged, stubbed or swapped (R7, R8) |
| ~3500 | arm (1) `--standalone` | the glossary is not re-materialised over a project's edits (R7) |
| ~3553 | arm (3) full-copy child | the glossary is not overwritten on every cascade (R7) |
| ~3580 | arm (4) single-repo / coordinator | the glossary is not overwritten on every install (R7) |

### 2. The seed/preserve block (serves R1–R6, R8)

New block in **§2 project workspace** (`harness-install.sh`, the section opening at ~3620),
placed **immediately after the `specs/product.md` seed block** (3755-3776) so the two
project-owned `specs/` files sit together. `$H/specs` already exists at that point (§2's
`mkdir -p "$H/specs/epics" …`), and §1 has already run — that ordering is load-bearing: §1
must not have written the path, and §2 is the only writer.

Shape (the Builder owns the exact code; the **verdict substrings are pinned**, because the
tests grep them):

```sh
_gloss="$H/specs/glossary.md"; _gloss_src="$SRC/specs/glossary.md"
if [ -L "$_gloss" ] || { [ -e "$_gloss" ] && [ ! -f "$_gloss" ]; }; then
  info "specs/glossary.md preserved (not a regular file — left exactly as found)"
elif [ ! -e "$_gloss" ]; then
  cp "$_gloss_src" "$_gloss"
  info "seeded specs/glossary.md (project-owned — edit it freely, upgrades preserve your edits)"
elif cmp -s "$_gloss" "$_gloss_src"; then
  info "specs/glossary.md pristine (still byte-identical to the shipped example)"
elif head -n 1 "$_gloss" 2>/dev/null | grep -qxF "$HARNESS_STUB_SENTINEL"; then
  cp "$_gloss_src" "$_gloss"
  info "specs/glossary.md re-materialised from the shipped example (it held an umbrella pointer stub; the glossary is project-owned and has left the prose tier)"
else
  info "specs/glossary.md preserved (project-authored)"
fi
```

Pinned grep anchors for the tests — these four substrings must appear verbatim in the shipped
messages, and each run must emit **exactly one** line containing `specs/glossary.md` (R5):

| Verdict | Pinned substring |
|---|---|
| seeded (R1, R4) | `seeded specs/glossary.md` |
| pristine (R2) | `specs/glossary.md pristine` |
| preserved (R3) | `specs/glossary.md preserved` |
| stub re-materialised (R8) | `specs/glossary.md re-materialised` |

Notes the Builder must honor:

- **Order of the branches is load-bearing.** The non-regular-file guard runs first (`-L`
  before `-e`, because `-e` dereferences and a dangling symlink would otherwise read as
  "absent" and get a `cp` through the link). The pristine test runs before the stub test, so a
  shipped example that ever began with the sentinel could not be misread.
- **Byte identity, not `diff -w`.** `cmp -s`. A trailing space is an edit (R3).
- **`preserved` prints the same pinned substring in both preserve branches** (project-authored
  and non-regular-file). R5 counts one line; R3 greps `specs/glossary.md preserved`.
- **`$SRC` is the running installer's own source**, the same reference `copy()` used. There is
  no second authority, and the umbrella body is **not** consulted for this path — it is the
  project's file, not the umbrella's (D1).
- `--self` (`self_install`, ~7063) never calls `install_one`, so §2 does not run in source
  mode and there is no `cp` of a file onto itself. Verified; do not add a guard for it.
- `--dry-run`/`--list` never reaches `install_one`; nothing new to gate.

### 4. Ownership code (serves R10)

`tools/harness-owned-paths.sh` → `emit_body()` gains one exclusion line beside the existing
`specs/product.md` one, in the same `printf` style:

```sh
printf ':(exclude)%sspecs/glossary.md\n' "$pfx"
```

Without it the E24-F01 drift guard in `init.sh` and the E24-F02 post-cascade landing audit in
`harness-install.sh` both read an **uncommitted project glossary edit as harness drift** and
fail the mandatory gate — the exact false-positive class that file's header was written to
prevent. One file, two consumers, one edit.

### 5. The tripwire (serves R12)

Commit a byte copy of the shipped example as a test fixture (suggested
`tests/fixtures/glossary-shipped.md`) and `cmp -s` it against `specs/glossary.md` in
`tests/test_install.sh`, which `tools/run-tests.sh` runs. The failure message must state the
consequence (every pristine install silently stops tracking the example) and name the
`.harness/.glossary-seed` follow-up from D2, so whoever trips it is told what to do rather
than told to update a fixture.

The message half of R12 would otherwise be unfalsifiable — the only run that prints it is one
that has already changed the bytes — so the same test **statically greps its own suite file**
for `.glossary-seed` and for the consequence phrase. Two greps; without them R12 reads as
coverage that cannot fail.

This is the guard that makes D2's "deferring the stamp is free" true rather than hopeful.

### Test fixtures that currently stand on this path — read before editing `tests/test_umbrella.sh`

`specs/glossary.md` is not merely mentioned in that suite; it is **load-bearing** in two
fixtures, and both were written deliberately (see `progress/builder-E24-F04.md` → *Finding 4*).
Deleting the path from the tier without re-pointing them removes real coverage while leaving
the suite green — the exact failure mode `progress/lessons.md` warns about.

1. **`PROSE_TIER` (line 856) and `F04_TIER` (line 1306)** — drop `specs/glossary.md` from
   both. `PROSE_TIER` is a per-file sample and keeps its other entries. `F04_TIER` is the
   whole tier, and it must be **asserted equal** to the shipped value, not merely edited to
   match: extract the `HARNESS_BODY_PROSE=` value from `$SRC/harness-install.sh` and compare.
   **This is a new assertion, and it is not optional** — E24-F04's tests contract
   (`E24-F04.tests.md:266`) records "the prose sweep iterates a hardcoded tier list instead of
   `$HARNESS_BODY_PROSE`" as a killed mutant, and that kill worked *because the glossary was
   the tier's differentiating entry*. Once the glossary leaves the tier and item 2 below
   re-points to a file any hardcoded list would also contain, that mutant survives. The
   equality assertion is what keeps the kill.
2. **`thin_comparison_is_byte_identity` (1522-1589)** — the glossary carries the suite's only
   **whitespace-only** edit, the case that pins the comparison to *byte* identity rather than
   `diff -w`. Re-point it to another prose-tier **regular file that no other fixture in the
   suite touches**; `docs/SPEC-FORMAT.md` and `agents/reviewer.md` both qualify today (checked:
   the suite names `docs/UMBRELLA.md`, `docs/WORKFLOW.md`, `agents/builder.md`,
   `agents/orchestrator.md` and `agents/pr-fixer.md`, and no others). Keep **both**
   preconditions and the `differs: <path>` assertion, updating only the path — the blocker
   naming for a file **inside** a directory entry is already proven by the `agents/builder.md`
   / `docs/WORKFLOW.md` case at 1491-1510.
3. **`thin_umbrella_missing_entry_is_left_alone` (2321-2378)** — the glossary is the tier entry
   removed from the umbrella body to simulate an umbrella older than the installer. Re-point it
   to another entry the fixture can remove and assert on; update the `does not hold the
   prose-tier path '<rel>'` grep, the "still held by `$SRC`" control, the byte-identity
   reference copy, and the control loop over the remaining entries. Note the suite uses `$KN4`
   in an earlier block as well — confirm the chosen entry does not collide with it.

Both fixtures keep their comment blocks; update the prose so it explains the **new** choice
rather than leaving a comment that describes the glossary.

## DO NOT TOUCH

- **`specs/glossary.md` itself — its bytes.** Editing the shipped example is precisely what
  R12 exists to catch; changing it in this feature would trip the tripwire this feature adds
  and would silently freeze every pristine install (D2).
- **`specs/adr/0004-umbrella-resolved-body-via-pointer-stubs.md`.** An ADR is a historical
  record of a decision as it was made. The divergence is recorded in this spec's
  `## Architecture alignment`; the Architect does not author ADR deltas and neither does the
  Builder.
- **`agents/planner.md`, `docs/SPEC-FORMAT.md`, `specs/_templates/vision.md`.** They name
  `specs/glossary.md` as the project's term index — already correct under this feature, and
  the path does not move.
- **`copy()`, `thin_prose_tier`, `prose_tier_blockers`, `child_is_full_copy`,
  `stub_files_in`, `HARNESS_BODY_LOCAL`, `HARNESS_STUB_SENTINEL`.** The mechanisms are right;
  only tier **membership** changes. Do not add a glossary special case inside any of them — a
  second authority for this path is how the original defect was built.
- **No new CLI flag, no new `harness.config.yaml` key, no new prompt, no `.dist` file, no new
  path under `.harness/`** (`docs/RATIONALE.md` ablation doctrine; and D2 explicitly defers
  `.harness/.glossary-seed`).
- **`state/tasks.json` statuses** — the Orchestrator owns transitions.
- **Already-shipped specs** (`specs/epics/E24-*`, `specs/epics/E06-*`, `specs/epics/E00-*`) and
  **historical `CHANGELOG.md` entries**. They describe what was true when written; no
  retro-fit. Append a new CHANGELOG entry only.
- **`.claude/agents/*`, `.claude/commands/*`, `.agents/skills/*`, `.opencode/*`, `.codex/*`** —
  generated (E26-F01); regenerate with `sh harness-install.sh --self` only if an emitter
  changes, which this feature does not require.
- **`README.md:249`** — it lists the `specs/` layout, makes no ownership claim, and needs no
  edit.

## Approach notes

- **Migration story, stated once.** An install that last ran a pre-F01 installer has a glossary
  that pre-F01 wrote, i.e. byte-identical to that version's example. Because the shipped
  example has not changed since `b9921c9`, the first F01 run reads it as **pristine** — the
  correct verdict — and every later edit is preserved. A project that edited its glossary after
  its last upgrade is read as **preserved** on the very first F01 run, which is the outcome the
  field incident asks for. A thin child that holds a stub at that path is re-materialised (R8).
  No target requires operator action.
- **Sequence the work so the suite is never green-for-the-wrong-reason.** Land the tier removal
  and the §2 block together (a tier removal alone leaves targets with no glossary at all on a
  fresh install), then the ownership code, then the prose, then the tests. See `.tasks.md`.
- **Run the umbrella suite alone** after re-pointing its fixtures (`tools/run-tests.sh
  test_umbrella.sh`), then the full run — `progress/lessons.md` records that an 8-wide run can
  redden unrelated suites under load.
- **Suites run under the strictest available shell** (`tools/run-tests.sh` picks it and prints
  it). Keep the new test code POSIX; no `local`, no `[[ ]]`, no bashisms.
- **Do not assert exact exit codes for lookups**, and never assert a count of body files — this
  repo has a standing rule against pinning literal counts and `VERSION` strings.
