# `specs/glossary.md` becomes project-owned — Test Contract

> The traceability matrix: every `R-id` maps to a concrete, executable test. The Reviewer
> fails the feature if any `R-id` lacks a passing test.
>
> **Conventions this contract inherits from the suites it extends** (read them before
> writing): zero dependencies; POSIX `sh` only — `tools/run-tests.sh` executes every suite
> under the strictest shell it can probe, and `local`/`[[ ]]`/arrays parse fine under `dash`
> and fail at runtime; each suite builds its fixture under its own `mktemp -d` and sandboxes
> `HOME` and `CODEX_HOME`; `fail()` messages state the **consequence**, not just the symptom.
>
> **Constants discipline (`progress/lessons.md`).** No test below asserts a literal file
> count, a literal `VERSION`, or the number of prose-tier entries. `tests/test_umbrella.sh`'s
> `F04_TIER` is not a pin but a **derived equality this feature adds**: T9(a) extracts the
> `HARNESS_BODY_PROSE=` value from `$SRC/harness-install.sh` and asserts `F04_TIER` equals it.
> Today that constant is merely edited to match by hand, which is why F01 would otherwise
> retire E24-F04's "hardcoded tier list" mutation kill. Every string this contract asks a test
> to grep is a substring pinned in `.plan.md` §2 and shipped verbatim by `.tasks.md` T2.

## What each test must assert

### R1 — `test_glossary_seeded_on_fresh_install`
- `.harness/specs/glossary.md` exists after a fresh install and `cmp -s` equals
  `$SRC/specs/glossary.md`.
- The run's stdout contains `seeded specs/glossary.md`.
- **Control:** delete the target's copy and confirm the assertion fails without a run — i.e.
  the case must not be satisfiable by a file the fixture inherited. (`progress/lessons.md`,
  2026-09-05: *a fixture copied from the repo inherits the artifact under test*.)

### R2 — `test_glossary_pristine_verdict`
- On a target whose glossary was just seeded (untouched), a second install run leaves it
  `cmp -s`-equal to `$SRC/specs/glossary.md`.
- Stdout contains `specs/glossary.md pristine` **and does not contain**
  `specs/glossary.md preserved`. The negative half is the discriminator: without it, an
  implementation that preserves everything passes.

### R3 — `test_glossary_edit_preserved_on_upgrade`
- Write a **distinctive project glossary** into the target (the fixture's own bytes, not an
  append to the shipped example alone — e.g. a marker term plus a trailing-space line), take a
  reference copy, re-run the installer.
- `cmp -s` the file against the reference: byte-for-byte unchanged.
- Stdout contains `specs/glossary.md preserved`.
- **Whitespace control:** a second target whose only difference from the shipped example is a
  trailing space on line 1 is also preserved — pinning `cmp`-grade byte identity rather than
  `diff -w`. Assert both preconditions the way `tests/test_umbrella.sh` already does for this
  shape: `cmp -s` must fail (it is a real byte difference) and `diff -qw` must succeed (it is
  whitespace-only), or the case degenerates and pins nothing.
- **Non-regular-file arm:** on a third target, replace the path with `ln -s` pointing at a file
  **outside** the tree, run the installer, and assert all three: the path is still a symlink,
  its target is unchanged, and the link target's bytes were not replaced by the shipped
  example (i.e. nothing was written *through* the link). This is a real red-to-green — the
  naive `[ -e ]`-first implementation dereferences and writes through it.

### R4 — `test_glossary_reseeded_when_deleted`
- Install, `rm -f` the glossary, re-run.
- The file is back and `cmp -s`-equal to `$SRC/specs/glossary.md`; stdout contains
  `seeded specs/glossary.md`.
- Distinct from R1 because the run is an **upgrade** (`.harness-version` present), which takes
  a different path through `install_one` than a fresh target.

### R5 — `test_glossary_reports_one_verdict_line`
- Capture a single-target run's **stdout**; `grep -cF 'specs/glossary.md'` on it is exactly
  `1`, in each of the three states (seeded, pristine, preserved).
- Rationale for the count: the field incident's defining property was that the destructive run
  *printed nothing*. One line, always, is the visibility contract; two lines would mean two
  writers.

### R6 — `test_glossary_seed_is_idempotent`
- Run twice against an unchanged target; `cmp -s` the file after run 2 against a copy taken
  after run 1, and assert the same pinned verdict substring in both outputs.
- No sibling artifact was created: no path matching `glossary.md.*` exists in
  `.harness/specs/` (no `.dist`, `.orig`, `.bak`). Assert the **absence of the pattern**, not
  a directory entry count.

### R7 — `glossary_never_stubbed_in_any_layout` (+ R3's test for arm 4)
One case, four arms — one per body-copy arm named in `.plan.md` §1. Arm 4 lives in the other
suite, which is why the matrix row names **two** tests: a single `file::name` that exercises
three of four arms would overstate its own coverage.
- **arm 4 (single repo / coordinator)** — `test_glossary_edit_preserved_on_upgrade` in
  `tests/test_install.sh`; referenced from the matrix, not duplicated here.
- **arm 2 (thin maintenance)** — cascade an umbrella, edit the child's glossary, re-run the
  ordinary (unflagged) cascade: the edit survives `cmp -s` and the file's first line is not
  `$SENTINEL`.
- **arm 3 (full-copy child of a reachable umbrella)** — same edit, unflagged run, edit survives.
- **arm 1 (`--standalone`)** — detach a thin child with `--standalone`: the edited glossary
  survives, while `agents/builder.md` is re-materialised as real prose (the control that proves
  the run really took the standalone arm).
- **Sweep, not sample:** no file under the child's `.harness/specs/` has `$SENTINEL` as its
  first line.

### R8 — `glossary_stub_rematerialised_in_thin_child`
- **Fresh thin child:** after `cascade`, the child's `.harness/specs/glossary.md` exists, is
  **not** a stub, and `cmp -s` equals `$SRC/specs/glossary.md`. Control on the same child:
  `agents/builder.md` **is** a stub — otherwise the child is not thin and the case is vacuous.
- **Legacy stub migration:** hand-write a stub at that path (first line exactly `$SENTINEL`,
  as a pre-F01 installer would have left it), re-run: the file is no longer a stub, `cmp -s`
  equals the shipped example, and stdout contains `specs/glossary.md re-materialised`.
- **Negative control:** a project glossary whose first line is ordinary prose is **not**
  re-materialised — the sentinel, not "looks short", is the ownership signal.

### R9 — `glossary_edit_does_not_block_thin_conversion`
- Build a full-copy child of a reachable umbrella whose **only** divergence from the umbrella
  is an edited glossary; run with `--thin`.
- That child's output slice does not contain `differs: specs/glossary.md`; it reports the
  conversion (`CONVERTED`); its prose tier is all stubs; its glossary is **not** a stub and
  still `cmp -s` equals the edited bytes.
- **Control:** the suite's existing blocked-child cases (a still-tiered path edited ⇒ named and
  not converted) are the positive control that the blocker machinery still works. Reference
  them; do not re-seed them.

### R10 — `R4_project_owned_excluded` (extended, `tests/test_init_drift_guard.sh`)
- Add an uncommitted `.harness/specs/glossary.md` edit to the existing project-owned
  perturbation; the gate still exits `0`.
- The existing positive control on the same tree (an uncommitted `agents/reviewer.md` edit ⇒
  non-zero) must still fail the gate, so "excludes everything" cannot pass.
- **Assert the source directly, once:** `tools/harness-owned-paths.sh body <harness-dir>`
  prints `:(exclude).harness/specs/glossary.md`. `emit_body()` has two consumers — `init.sh`'s
  drift guard (exercised above) and the installer's post-cascade landing audit — and this
  assertion covers both at the one place the pathspec list exists, instead of arguing that the
  second consumer shares an implementation.

### R11 — `test_glossary_ownership_documented`
Placement, not mere presence — extract the span first, then assert inside it (the
`workers_block` extraction in `tests/test_install.sh` is the precedent):
- Installed `manifest.txt`: the `PROJECT-OWNED` block contains `.harness/specs/glossary.md`;
  the `HARNESS-OWNED` block does not; the `prose (stub-able)` tier line does not.
- `harness-install.sh` header ownership-class comment: the PROJECT-authored bullet names
  `specs/glossary.md`; the BODY bullet — its opening line AND any continuation line, the
  whole bullet through its structural end — does not.
- `docs/INSTALL.md`, **all three sites `.plan.md` names, not the table alone**: (1) the
  Layout & ownership table — the `project-owned` row names it, the `harness-owned body` row
  does not; (2) the "refreshed harness body" sentence in `## Install` (site 63) — extract
  that sentence itself (not the whole section, which legitimately names the glossary two
  sentences earlier) and require it does not; (3) the `--thin`/`--standalone` prose-tier
  enumeration under `### Body layout` (site 681) — extract the parenthetical enumeration
  itself (not the whole subsection, whose very next sentence correctly explains the glossary
  is in neither tier) and require it does not.
- `docs/UMBRELLA.md`: the **Prose** tier row does not name it, and a sentence elsewhere records
  that a child's glossary is project-owned and never a stub (decision D1).
- `docs/CONFIG-LAYERING.md` thin-child sentence — located by the **shape** `pointer stub`
  (one space; a two-stage negative whose first stage cannot match is decoration, not a test,
  E30-F01 round 1 Finding 1) — and the shipped `harness.config.yaml` `umbrella.root` comment:
  neither names it.
- **Scope of the negative.** These six authorities only. Historical records — `specs/adr/`,
  shipped `CHANGELOG.md` entries, already-shipped feature specs under `specs/epics/` — still
  name this path in the prose tier, correctly, and are on the plan's DO NOT TOUCH list. A
  repo-wide negative grep would be red on `main` the day it landed.
- **Ablation companion:** grep the two places a config key can actually be introduced — the
  shipped `harness.config.yaml` and `migrate_config`'s default table in `harness-install.sh` —
  for `glossar` **at any indentation**, and require zero *key* lines (a comment naming the path
  is expected in neither after T8, but a key is the thing forbidden). A column-0-only key sweep
  would miss the nested shape this config uses, and comparing a fresh install's config to the
  shipped seed compares the file with a verbatim `cp` of itself.

### R12 — `test_shipped_glossary_bytes_pinned`
- `cmp -s specs/glossary.md tests/fixtures/glossary-shipped.md`, in `tests/test_install.sh`,
  which `tools/run-tests.sh` executes — that runner is "the verification gate" R12 names.
- **The message half must be asserted, not merely written.** The only run that would print it
  is one that has already changed the bytes, so the test also greps **its own suite file** for
  `.glossary-seed` and for the consequence phrase. Without those two greps, half of R12 is
  coverage that cannot fail.
- The `fail()` message states the consequence and the remedy: *the shipped glossary example
  changed; every install still byte-identical to the old example will silently stop tracking
  it, because a single comparison cannot tell "pristine but older" from "project-edited".
  Implement the `.harness/.glossary-seed` stamp (E30-F01 decision D2) before changing these
  bytes, or record the accepted freeze — then refresh this fixture.*
- The fixture is created with `cp`, never retyped.

## Falsifiability — mutations this contract must kill

| Mutation | Killed by | Survives (and why that is correct) |
|---|---|---|
| `specs/glossary.md` put back into `HARNESS_BODY_PROSE` | R3 (single-repo edit clobbered), R7, R8 | R1, R4 — the file still exists and still matches the example |
| the §2 block deleted entirely | R1, R4, R5 | — |
| `cmp -s` relaxed to `diff -qw` | R3's whitespace control | R3's marker-term arm, which is not whitespace-only |
| the pristine branch and the preserve branch merged into one message | R2 (the negative half) | R3, R6 |
| the stub-sentinel branch dropped | R8's migration arm | R8's fresh-child arm — a fresh thin child never held a stub |
| the stub branch widened from "first line is the sentinel" to "contains the sentinel" or "file is short" | R8's negative control | R8's migration arm |
| the `-L` guard dropped, so `[ -e ]` dereferences first | R3's non-regular-file arm (the example is written *through* the link) | R1–R4's ordinary arms, where the path is a regular file |
| `emit_body()`'s new exclusion dropped | R10 (both halves) | every other suite |
| `$F04_TIER` left as a hand-edited constant | R7's new `F04_TIER` equality assertion | every case that merely consumes the constant |
| the docs updated but the code not (or the reverse) | R11 + R3 together — R11 alone cannot see behavior, R3 alone cannot see prose | — |

## Behavioral / end-to-end checks (Reviewer)

1. Install into a scratch dir; confirm `.harness/specs/glossary.md` exists and the run said
   `seeded`.
2. Replace it with a hand-written domain glossary; re-run; confirm the file is untouched and
   the run said `preserved` — the exact scenario that destroyed `previta/protocolos`'s
   90-line glossary on 2026-09-16.
3. `git status` in that scratch repo with the glossary edited but uncommitted; run
   `./.harness/init.sh`; confirm the drift gate still passes.
4. Read the installed `manifest.txt` and confirm a reader is told exactly one owner for that
   path.

## Non-functional checks

- `tools/run-tests.sh test_umbrella.sh` green **alone** before the wide run (fixture
  re-pointing is the highest-risk edit in this feature).
- `tools/run-tests.sh` green across all suites, under the shell the runner reports.
- `./init.sh` green from the repo root.
- `tools/change-size.sh` before the PR.

## Residual — stated, not hidden

- **The directory-at-the-path shape has no assertion**; only the symlink shape does (R3's
  third arm). A directory there is not a state any harness version produces, and provoking it
  tests the shell's `[ -f ]` more than it tests this feature. The guard covers both; the test
  covers the one a real target could reach.
- **R2's "refresh" is not falsifiable within a version.** With one comparison against the
  shipped example, a pristine copy is already identical, so the refresh writes nothing. This is
  the accepted consequence of decision D2, and R12 is the guard that keeps it true.
