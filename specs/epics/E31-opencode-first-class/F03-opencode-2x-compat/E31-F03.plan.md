# OpenCode 2.x compatibility — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it
> serves. The design rests on the empirical findings below, recorded with the commands that
> produced them.

## Stack & dependencies
- POSIX sh (`tools/opencode-model-helper.sh`, new suite wrapper), Python 3 stdlib (the
  `tests/test_codex_native.sh` heredoc), the `opencode` CLI when present (1.x or 2.x).
- New dependencies: none. The 2.x probe uses only `opencode serve` / `opencode api` /
  `opencode service status` and the Python stdlib.

## Empirical findings (2026-10-18, this repo, opencode 1.18.31 / 1.18.35 / 2.0.32)

**Safety envelope.** Before any probe ran, `pgrep -af 'opencode.exe serve'` showed **no**
daemon. Every run used a scratch dir with `XDG_CONFIG_HOME`, `XDG_DATA_HOME`,
`XDG_STATE_HOME` and `XDG_CACHE_HOME` pointed into it. The fixtures were a copy of the source
layout and a fresh `sh harness-install.sh --agents=opencode --pr-loop=true <tmp>` target.
After each step, `pgrep -af opencode` was checked. Every process started was reaped
(`kill` of the owned PID, or `opencode service stop`), and the final sweep was empty. No
command talked to a model.

**Binaries.** 2.x: `~/.local/share/mise/installs/opencode/2.0.32/node_modules/@opencode/cli/bin/opencode.exe`,
a compiled bun ELF with no separate JS, analyzed with `strings -n 6`. 1.x:
`~/.local/share/mise/installs/opencode/{1.18.31,1.18.35}/opencode`.
`opencode --version` prints `opencode v2.0.32` on 2.x and a bare `1.18.35` on 1.x, and
spawns nothing.

**Contradictions with the brief.**
- "may silently get no harness roles or commands": false for 2.0.32 (F6).
- "`debug agents` returned `[]`": a cold-start race (F7), not the agent dir, the key rename,
  or the service's cwd.
- "Emit glue that both majors accept, or select it by detected major": the current glue
  already is that layout (F13). Nothing is selected by major at install time.
- The TaskStore title's "emitted glue (`agents` key, agent dir)" names a change this design
  deliberately does **not** make.
- New in this feature, not in the brief: the model helper leaks a daemon on 2.x (F9), and a
  broken `{file:}` reference fails silently on 2.x (F8).

## Interfaces

### Version gate: `ocgate(text, rc)` in `tests/test_codex_native.sh` (serves R2)

A pure function, extended from E99-F172's version. It returns a route and a reason:

| `opencode --version` output | rc | Route | Reason contains |
|---|---|---|---|
| `1.18.35` | 0 | `v1` | — |
| `opencode v2.0.32` | 0 | `v2` | — |
| `10.1.2` | 0 | skip | `unsupported major 10` |
| `3.0.0` | 0 | skip | `unsupported major 3` |
| `0.9.1` | 0 | skip | `unsupported major 0` |
| `garbage` / `` | 0 | skip | `unparseable` |
| `1.2.3` | 3 | skip | `exited 3` |
| `garbage` | 3 | skip | `exited 3` |
| `opencode v2.0.32` | 1 | skip | `exited 1` |

The check order is unchanged: exit status, then parse, then major. The shape of the return
value is the Builder's choice. The table must be pinned hermetically, as today. The
`('opencode v2.0.32',0,'targets 1.x')` row changes meaning: 2.x now routes to `v2`. That
change is the intended behavior.

### Warm-up poll: `ocwarm(fetch, deadline, sleep, clock)` (serves R5)

A pure function. It calls `fetch(remaining)` until the result is a non-empty list, sleeping
between calls. `remaining` is the time left before the deadline, so the caller can bound each
per-call timeout by `min(15, remaining)` and the whole poll stays within 60 s. A `fetch` that
raises any `Exception` counts as "not warm yet". Once the deadline passes, the function raises
an `AssertionError` whose message contains `cold-start`. A hermetic table drives it with a fake
`fetch` and a fake clock:

- `[[], [], [x]]` returns `[x]`;
- `[[x]]` returns on the first call;
- `[raise, [x]]` returns `[x]`;
- always `[]` raises with `cold-start`;
- always raising raises with `cold-start`.

### 2.x probe: `oc2_probe(layout, agents_dir, cmd_stems)` (serves R3, R4, R6, R7)

1. Build the env: a copy of `os.environ` with `HOME` and
   `XDG_{CONFIG,DATA,STATE,CACHE,RUNTIME}_HOME`/`_DIR` set to fresh dirs under one
   `tempfile.mkdtemp()` (`XDG_RUNTIME_DIR` mode 0700). Drop **every** inherited `OPENCODE*`
   variable, so a user's `OPENCODE_CONFIG`-style override cannot leak in.
   - **Not verified:** whether the 2.x service registry also reads `XDG_RUNTIME_DIR`. F9 was
     observed with no daemon at baseline. Redirecting it costs nothing, and the R6
     `service status` check runs under the same env.
2. Start `opencode serve --hostname 127.0.0.1 --port 0`:
   - cwd = layout dir, `start_new_session=True`;
   - stdout and stderr go to a **file** (lessons 2026-09-18: pipes truncate at 64 KiB);
   - parse `server listening on (http://\S+)` and `server password (\S+)` from the file,
     with a 30 s deadline. If the process exits first, or the deadline passes, fail with
     `server did not start` (R5).
   - Never print the password.
3. `fetch(path, remaining)` runs `opencode api --server <url> GET <path>` with
   `OPENCODE_PASSWORD=<pw>` in the probe env and cwd = layout dir. Output is captured to a
   file with `timeout=min(15, remaining)`. It returns `json["data"]` and raises on a
   non-zero exit or invalid JSON.
4. Call `ocwarm(lambda r: fetch('/api/agent', r), …)`, then `fetch('/api/command', 15)`.
   Assert per R3/R4. The expected command set is passed in (`cmd_stems`):
   - R3: the literal F6 target list;
   - R4: stems read from the **repository's** `.opencode/command/`, never from the copy;
   - both: `'sdd-next' in names` asserted explicitly. For each role in the seven-role set:
   `agent["system"] == (layout/<agents-dir>/<role>.md).read_text().strip()`.
   For `pr-fixer`: `system == body.split('---',2)[2].strip()` of the `.opencode/agent/`
   file.
5. In `finally`:
   - `os.killpg(pgid, SIGTERM)`, wait up to 10 s, then `SIGKILL` and wait;
   - assert `os.killpg(pgid, 0)` raises `ProcessLookupError`;
   - run `opencode service status` under the same env, captured to a file, and assert its
     output starts with `stopped`;
   - remove the temp dir.

   These assertions run even after a failed resolution assertion: chain them so the original
   failure is not masked. (R6)

Permitted `opencode` invocations: `--version`, `serve --hostname 127.0.0.1 --port 0`,
`api --server <own url> …`, and `service status`. Nothing else, so no `debug`, `agent`,
`models` or `run`. (R6)

### 1.x probe (extended; serves R7, R8)

The existing source-layout probe is kept as-is: `agent list` substring checks, plus
`debug config` with the `'"sdd-next"' in …` check. Two changes:

- It now runs under the same isolated env builder as the 2.x probe (R7).
- A second pass runs on a fresh `--agents=opencode --pr-loop=true` target (R8). That pass
  asserts the seven roles and `pr-fixer` from `agent list` and
  `'sdd-next' in json.loads(debug_config)['command']`. Output is captured through a file.

1.x spawns no daemon, so no process-group kill is required. If the Builder reuses the 2.x
`finally` scaffolding, that is fine.

### Model helper: `tools/opencode-model-helper.sh` (serves R9, R10)

Before the `MODELS=` line:

```sh
# A NON-ZERO --version exit means "unknown" whatever it printed (R9) — never `|| true` here.
if _oc_ver="$(opencode --version 2>/dev/null)"; then
  # first X.Y.Z, major = first component — the SAME rule as test_codex_native.sh::ocgate (R2/R9)
  _oc_major="$(printf '%s\n' "$_oc_ver" | sed -n 's/[^0-9]*\([0-9][0-9]*\)\.[0-9][0-9]*\.[0-9][0-9]*.*/\1/p' | head -n 1)"
else
  _oc_major=''
fi
case "$_oc_major" in ''|0|1) _oc_models_flag='' ;; *) _oc_models_flag='--standalone' ;; esac
```

The `MODELS=` line becomes `opencode models $_oc_models_flag` (unquoted on purpose, so an
empty flag adds no argument). The rest of the script is untouched. The snippet is a sketch, and the
Builder may restructure it. Whatever the structure, a non-zero `--version` must fall to the
no-flag branch even when it printed `opencode v2.0.32`. `set -eu` is in force, so keep the
`if` form: a bare failing command substitution in an assignment would abort the script.

## Approach notes
- **Order.** Hermetic tests first (gate table, warm table, helper stub). Then the live 2.x
  probe. Then the 1.x extension. Docs and release last.
- **Running both majors locally (Reviewer).** `opencode` on PATH is 2.0.32. For the 1.x arm:
  `PATH="$HOME/.local/share/mise/installs/opencode/1.18.35:$PATH" sh tests/test_codex_native.sh`.
  Each arm prints `ok - opencode_<layout>_resolves (R…, live 1.x|2.x)` or a `skip -` line.
- **Network.** 2.x `serve` may fetch the models.dev catalog. Agent and command resolution
  does not depend on it (F6 ran without provider auth). An offline host that never warms
  fails per R5 rather than skipping. That is deliberate, because a skip would hide a real
  2.x regression. CI has no `opencode` and skips.
- **Two parsers, one table (complexity basis).** The Python `ocgate` and the sh helper must
  agree on `1.18.35` → 1, `opencode v2.0.32` → 2, `garbage` → none. `test_opencode_compat.sh`
  drives the helper stub with the same version strings as the R2 table.
- **Runtime.** F6 warmed in under 1 s. Budget is about 10 s per layout. Do not add sleeps
  beyond the poll interval.
- **Password hygiene.** `serve` prints a password. It lives only in the temp log file, which
  is deleted, and in the probe env. Assertion messages must not include it.
- **R1's real guard.** The frozen v0.78.1 oracle covers only the files that existed in 0.78.1,
  minus the `_regenerated` set. The complete guard for "no emission change" is that
  `git diff main -- harness-install.sh` is **empty**: the Reviewer checks it, and T14 records
  it.
- **Remaining limitation.** The warm-up rule assumes "non-empty agent list = registry
  loaded". F7 showed that agents and commands update together, but if a future 2.x loads
  commands later than agents, the command assertion could race. If that happens, poll
  `/api/command` for the expected stem set with the same `ocwarm` deadline.
