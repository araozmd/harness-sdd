# OpenCode 2.x compatibility — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E31-F03:R1 … E31-F03:R12`.

## Context

mise put opencode **2.0.32** on the maintainer's PATH on 2026-10-16. The inbox brief
(`progress/inbox/E31-F03.md`) feared that 2.x silently ignores the harness's 1.x-shaped
OpenCode glue: the `opencode.json` `agent` key, `.opencode/agent/*.md`, and
`.opencode/command/*.md`. The evidence was that `opencode debug agents` returned `[]` and
that `debug config` showed a renamed `agents` key.

**The open questions were settled empirically before this spec was written** (commands and
raw observations in `E31-F03.plan.md` → *Empirical findings*). The result contradicts the
brief's premise:

- **2.0.32 accepts the current 1.x emission unchanged.** Every config document goes through
  a normalizer (`Config.parseInfo` → `cP`) that maps `agent`→`agents`, `prompt`→`system`,
  and `command`→`commands`. `{file:…}` references are still substituted at load time.
  Agents and commands are still discovered from `{agent,agents}/**/*.md` and
  `{command,commands}/**/*.md`. File-agent frontmatter (`description`, `mode`,
  `permission`) and `provider/model` pins are honored. A real
  `--agents=opencode --pr-loop=true` target and a copy of the source layout both resolve all
  seven roles, `pr-fixer`, and every `/sdd-*` command on 2.0.32. Each role's resolved
  `system` is byte-equal to its referenced `agents/<role>.md`.
- **The `[]` was a cold-start race, not a shape problem.** The first agent query against a
  freshly started 2.x server returns `[]`, built-ins included. The second query against the
  same server returns the full set.
- **One layout already serves both majors.** 1.18.31 and 1.18.35 resolve the same files.
  Both also accept the 2.x-native shape (`agents` + `system`) through a forward-compat shim.
  The installer therefore needs **no** major detection, and an absent `opencode` changes
  nothing at install time.

The defects that are real are narrower:

1. **No live proof on 2.x.** `tests/test_codex_native.sh`'s live probe drives 1.x-only verbs
   (`agent list`, `debug config`). E99-F172 gated it to skip on any non-1 major, so the
   harness has no evidence on 2.x. The 1.x probe also covers only the source layout, never
   a real target.
2. **Every 2.x `debug` call and every bare service-backed verb leaves a detached
   `opencode serve --service` daemon (PPID 1).** That includes `opencode models` with no
   flag. A one-shot `--standalone` call leaves nothing behind, but it always answers from a
   cold registry (`[]`, or 404 for `agent.get`), so it cannot prove resolution. A probe must
   own a foreground server, wait for it to warm, and kill it.
3. **`tools/opencode-model-helper.sh` leaks that daemon on 2.x.** It runs bare
   `opencode models`. The output format is unchanged: 400 of 400 lines are `provider/model`
   on both majors, so the parsing still works. But every 2.x run leaves a daemon. The fix is
   not a blanket `--standalone`: 1.x rejects that flag (rc=1, usage text on stdout), so the
   flag must be chosen by major.
4. **A broken `{file:}` reference fails silently on 2.x.** The role still exists, with an
   empty `system` (verified by mutation). A name-only probe would stay green on a role with
   no instructions, so the probe must compare content.

### Why `complexity: complex`

Two of `agents/architect.md`'s stated bases hold:

1. **The feature is at the size budget**: 12 of `change_size.max_requirements` = 12.
2. **It re-enters a defect class the harness has paid for: a body and its copy diverging.**
   The rule "parse the OpenCode major from `--version`" now lives in two places, the test's
   `ocgate` (Python) and the helper (POSIX sh). They must agree row for row on the same
   version table (R2, R9). The live probe also re-enters E99-F172's process-group hygiene,
   which took two review rounds there.

## Business rules

- **No emission change.** The OpenCode glue a target receives is byte-identical to 0.96.3.
  That layout is the one shape verified on 1.18.31, 1.18.35 and 2.0.32. "Modernizing" it to
  the 2.x-native keys would gain nothing, would break the `.harness/.opencode.stamp` re-stamp
  contract for every installed target, and is unverified on older 1.x (the installer's host
  provenance cites 1.18.5).
- **A probe never leaves a daemon.** Any OpenCode process a test starts is killed by process
  group on every exit path. No test invokes a 2.x verb that starts the background service.
- **A probe never touches user or repository state.** OpenCode runs against a copied layout
  with `HOME` and the four `XDG_*_HOME` variables pointed into a temp dir.
- **Absence is a skip, not a failure.** No `opencode` binary, a non-zero `--version`, an
  unparseable version, or an unsupported major prints a `skip -` line with the reason. The
  static assertions stay mandatory.
- **The helper's 1.x behavior is unchanged.** Only a detected major ≥ 2 changes the command
  it runs.

## Architecture alignment

`specs/architecture.md` is **absent** in this repository. The ADR set is present, so the
touched decisions are cited:

- platform ADR-0002 — `builder-heavy` is a model tier, not a second Builder prompt: the 2.x
  probe asserts that `builder-heavy` resolves on 2.x as its own agent, with the
  `builder-heavy.md` body. A `pin.opencode.reasoning` pin was verified to arrive on 2.x as
  `{providerID, id}`, so escalation does not silently no-op on the new major. No emitter
  changes.
- platform ADR-0003 — one shared skill unit per command: unchanged. Observed on 2.0.32: the
  `.agents/skills/` units are **not** surfaced as commands (only `.opencode/command/*.md`
  and the built-ins `init` and `review` are). The native `.opencode/command/` copy F02
  committed is therefore the surface OpenCode 2.x actually uses. `/sdd-fix-parallel`, which
  has no native copy unless the capability gate passes, is unreachable as a 2.x command.
  That is the gate's safe direction, and this feature does not change it.
- platform ADR-0005 — source-only surfaces emit only under `--self`: honored. The source
  probe reads the committed `sdd-triage` command but asserts nothing about targets having
  it, and no emitter changes.

## Acceptance criteria (EARS)

- **R1** — The installer shall emit OpenCode glue for `--agents=opencode` that is
  byte-identical to the 0.96.3 emission: `opencode.json` with a top-level `agent` map whose
  `prompt` values are `{file:./.harness/agents/<role>.md}`, commands under
  `.opencode/command/`, and `pr-fixer` under `.opencode/agent/`. No `agents` key, `system`
  key, or plural directory shall be emitted.
- **R2** — When `tests/test_codex_native.sh` evaluates the `opencode --version` result, the
  version gate shall route by the first `X.Y.Z` in the output:
  - exit 0 and major `1` ⇒ the 1.x probe;
  - exit 0 and major `2` ⇒ the 2.x probe;
  - any other major, unparseable output, a non-zero exit, or a timeout/exception ⇒ skip,
    with a reason naming which case;
  - a missing binary ⇒ skip.
- **R3** — Where the gate selects the 2.x probe, the suite shall install a fresh
  `--agents=opencode --pr-loop=true` target in a temp dir and assert, from a warm server
  bound to that target:
  - the agent ids include `orchestrator, architect, builder, builder-heavy, reviewer, scout,
    doc-critic, pr-fixer`;
  - each of the seven role agents' `system` equals the whitespace-stripped text of
    `.harness/agents/<role>.md`;
  - `pr-fixer`'s `system` equals the stripped body of `.opencode/agent/pr-fixer.md` after its
    frontmatter;
  - the command names include `sdd-next` and the fixed target set `sdd-drill, sdd-fix,
    sdd-new, sdd-next, sdd-plan, sdd-pr-loop, sdd-report, sdd-test-concurrency` (F6). The
    expected set is a literal, independent of what the install wrote.
- **R4** — Where the gate selects the 2.x probe, the suite shall run the same resolution
  assertions against an isolated copy of the committed source layout (`opencode.json`,
  `AGENTS.md`, `.opencode/`, `agents/`), with `system` compared to `agents/<role>.md`. The command names
  shall include `sdd-next` and every `.opencode/command/*.md` stem read from the
  **repository** (not from the copy).
- **R5** — While the 2.x probe waits for its server, it shall poll the agent list until the
  list is non-empty, for at most 60 seconds in total. A fetch that raises (non-zero
  `opencode api`, invalid JSON, a per-call timeout) counts as "not warm yet". If the list is
  still not non-empty at the deadline, then the probe shall **fail** (not skip) with a
  message containing `cold-start`. If `opencode serve` exits early, or prints no
  `server listening` line within 30 seconds, then the probe shall **fail** with a message
  containing `server did not start`. The polling rule shall be a pure function that a
  hermetic table pins on every host, binary or not.
- **R6** — If the 2.x probe exits by any path (success, assertion failure, timeout, or
  exception), then:
  - it shall have killed the process group of the `opencode serve` it started, and confirmed
    that the group no longer exists;
  - `opencode service status`, run under the probe's environment, shall report `stopped`;
  - the only `opencode` invocations it shall have made are `--version`,
    `serve --hostname 127.0.0.1 --port 0`, `api --server <its own url> …` and
    `service status`. No `debug`, `agent`, `models`, `run`, or any verb that starts the
    background service.
- **R7** — The live probes for both majors shall run OpenCode with `HOME`,
  `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME` and
  `XDG_RUNTIME_DIR` pointed into a temp dir and every inherited `OPENCODE_*` variable
  removed, against copied layouts only. The repository's `git status --porcelain` shall be
  identical before and after the probe.
- **R8** — Where the gate selects the 1.x probe, the suite shall also assert on a fresh
  `--agents=opencode --pr-loop=true` target:
  - `opencode agent list` names the seven roles and `pr-fixer`;
  - the `command` map in `opencode debug config` contains `sdd-next`, parsed as JSON (not a
    substring match) and captured through a file.
- **R9** — When `tools/opencode-model-helper.sh` lists models, it shall read the major from
  `opencode --version` with the same first-`X.Y.Z` rule as R2:
  - major ≥ 2 ⇒ `opencode models --standalone`;
  - major 0 or 1, unparseable output, or a non-zero `--version` exit (whatever it printed)
    ⇒ `opencode models` with no flag, exactly as today.
- **R10** — Given `opencode models` output recorded from 2.0.32, the helper shall print the
  same `Suggested harness tier mapping` and `pin.opencode.*` snippet that it prints for the
  same model list from a 1.x binary.
- **R11** — `docs/INSTALL.md`'s OpenCode material shall state:
  - the verified versions (1.18.31, 1.18.35, 2.0.32);
  - that one emitted layout serves both majors and no flag selects it;
  - that 2.x `debug` commands and other service-backed verbs leave a background
    `opencode serve --service` running, stopped with `opencode service stop`;
  - that the model helper passes `--standalone` on 2.x;
  - that a freshly started 2.x server may list no agents on its first query.
- **R12** — The feature shall carry a MINOR `VERSION` bump to `0.97.0` with a matching
  `CHANGELOG.md` `## [0.97.0]` entry that names OpenCode 2.x support, the helper fix and the
  2.x live probe.

## Out of scope

- Changing any OpenCode emitter, `gen_opencode_json`, `gen_oc_agent`, the
  `.harness/.opencode.stamp` contract, or the frozen v0.78.1 oracle fixtures.
- Dropping 1.x support or adopting the 2.x-native `agents` / `system` / plural-dir shape.
- Install-time OpenCode major detection. It is not needed: one layout serves both.
- `HOST_MARKERS` / host detection. 2.x still exports `OPENCODE=1` to tool shells (static
  evidence only; see Open questions), and one present marker per row suffices.
- Exposing `/sdd-fix-parallel` as a 2.x command, or making 2.x surface `.agents/skills/`
  units as commands.
- Any probe that talks to a model (`opencode run` with a prompt).

## Open questions

- **Host-marker provenance for 2.x.** Static evidence only: the 2.0.32 shell tool sets
  `AGENT=1`, `OPENCODE=1`, `AI_AGENT=opencode` (when unset) and `OPENCODE_SESSION_ID`, but
  **not** `OPENCODE_PID`. `HOST_MARKERS`' `opencode OPENCODE OPENCODE_PID` row still detects
  2.x through `OPENCODE`. Its provenance block requires an *observed* session, which needs
  a model call this spec forbids, so the row and its provenance stay unchanged. Recording a
  2.x observation is a follow-up for whoever can run a session.
- **`#` in an OpenCode pin.** 2.x treats `#` in a `model` value as a variant separator. It
  drops a legacy `model` that does not match `^[^/#]+/[^#]+$`, with a "configuration
  normalization diagnostic" in its log. The installer's pin guard checks only for `/`. No
  shipped pin contains `#`. Tightening the guard is a candidate E99 fix, not this feature.
