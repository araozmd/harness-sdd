# OpenCode claims the shared `.agents/skills` units — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.

## Stack & dependencies

- Language/framework: POSIX shell (`harness-install.sh`), POSIX `sh` test suites under
  `tests/`. No new runtime dependencies (honors the harness's zero-dependency contract).
- New dependencies: none.

## Data model

Not applicable — this feature changes installer gating, a generated text body, and its
tests; it introduces no stored data.

The one durable artifact whose shape changes is the generated `SKILL.md` (a text contract,
not a schema), and the existing ownership ledger `.harness/.codex-skills/<cmd>/` is
**unchanged** (ADR-0003 keeps the historical name for ownership-proof continuity).

## API / interface

No runtime API. The installer-facing interfaces this feature changes:

| Interface | Current | New | R-id |

| `gen_skill_body()` adapter text | Codex-only (`$sdd-*` + `/skills`) | names Codex `$sdd-*` **and** OpenCode `/sdd-*`; no `/skills` claim | R4 |

## DO NOT TOUCH

- `gen_opencode_json` / `gen_oc_agent` / `self_install` — the source-glue work is E31-F02;
  changing it here would put two features in one PR (E21 change-size discipline).
- `HARNESS_SDD_CMDS` membership — the command **set** is unchanged; only the claiming gate
  and the body change.
- `.harness/.codex-skills/` — the historical ledger path is load-bearing (ADR-0003).
- `.claude/commands/sdd-fix-parallel.md` and `.opencode/command/sdd-fix-parallel.md` bodies —
  the gate is added to the shared **skill** body only; the `.opencode/command` copy is
  already withheld structurally (`:6479-6502`), and Claude's copy has no OpenCode concern.
- Any Codex agent TOML or per-role model routing.

## Approach notes

- **One predicate, two callers.** Install (§5d, `:6780`) and reclaim (§7, `:7087`) both call
  `skill_unit_claimed()`. Widening that one function is the whole R1–R3 change; do **not**
  add a second `agent_selected opencode` condition at either call site, or the two directions
  can diverge (the defect ADR-0003 describes).
- **Deselect-last only.** Verify the reclaim path runs on the transition where a claimant is
  removed and **no** claimant remains selected. The both-selected → deselect-one case is the
  only shape that can detect the bug; a single-selection test cannot (ADR-0003, "Consequences").
- **Adapter wording (R4).** State, in one sentence or two, that Codex invokes `$sdd-<name>`
  with trailing argument text and OpenCode invokes `/sdd-<name>`; keep the `$ARGUMENTS`
  mapping sentence host-neutral. Remove the `/skills` discovery instruction or scope it to
  Codex explicitly — OpenCode exposes skills through its command palette and `skill` tool,
  not a `/skills` command.
- **Gate wording (R5).** The precondition must be **unconditional in the body** but
  **conditional in effect**: it applies only when the running host is OpenCode. Phrase it so
  Codex reads a no-op. Do not gate on a file that does not exist on Codex turning into a hard
  stop for Codex.
- **Byte-stability for Codex (R6).** The new adapter text changes every `SKILL.md`, so this is
  an intentional byte change for all claimants; R6 means the change is **identical** whether
  or not `opencode` is selected, and the install/reclaim **behavior** for a `codex`-only
  selection is unchanged. Assertion: generate the units under `--agents=codex` and under
  `--agents=codex,opencode`; the `SKILL.md` bytes must be equal.
- **Ordering.** This feature must merge before E31-F02 (F02 commits source glue derived from
  the F01 body and claiming set).
