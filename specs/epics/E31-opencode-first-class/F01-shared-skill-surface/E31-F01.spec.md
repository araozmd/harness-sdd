# OpenCode claims the shared `.agents/skills` units — Functional Spec

> R-ids in this document are `R1 … R6`; their fully-qualified form is `E31-F01:R1 … E31-F01:R6`.

## Context

`.agents/skills/<cmd>/` is, by ADR-0003, **one harness-owned unit per command, shared by
every front-end that reads that surface**. The ADR states the claiming set was
`{codex, antigravity}` and warns explicitly: *"Every new front-end that learns to read
`.agents/skills/` must be added to the claiming set, and forgetting to do so fails
**silently in the destructive direction** (its units get reclaimed out from under it)."*

E29 retired Antigravity but the installer's claimant predicate was narrowed to Codex alone
(`skill_unit_claimed()` → `agent_selected codex`, `harness-install.sh:6519`). OpenCode
1.18.31 demonstrably reads `.agents/skills/*/SKILL.md` (probe in the epic Notes), so it is a
reader that is **not** in the claiming set — the exact omission ADR-0003 flags as
silent-destructive.

Two more defects ride on the same surface and are fixed here because they are the reason the
surface is wrong, not because they are separate features:

- `gen_skill_body` (`:6526`) hard-codes a Codex-only adapter (`:6535`). One body is read by
  two hosts, so it must be correct for both — ADR-0003's "one generator, one body" rule.
- `HARNESS_SDD_CMDS` includes `sdd-fix-parallel` and the shared units are written
  unconditionally (`:6781`), so OpenCode can invoke `/sdd-fix-parallel` even when
  `.harness/.opencode-parallel` says `sequential` — bypassing the gate the `.opencode/command`
  copy correctly honors. The gate is a property of the workflow, so it must hold on every
  surface, not one path.

### Why `complexity: complex`

Three of `agents/architect.md`'s stated bases hold:

1. **It honors an ADR whose constraints reach across several files.** ADR-0003 binds
   `harness-install.sh` (`skill_unit_claimed`, `gen_skill_body`, the §5d write gate and the
   §7 reclaim), `docs/INSTALL.md`, `docs/HARNESS.md`, `README.md`, and `tests/test_install.sh`'s
   mixed-selection assertions. All name the shared surface today.
2. **It re-enters a defect class the harness has already paid for.** "A body and its copy
   diverge" — ADR-0003 exists because two features wrote the same unit; this feature makes the
   single body speak two hosts, the same class one level up.
3. **Speccing it required resolving a contradiction between two live components.** The shared
   unit is one file by decision; the concurrency gate is per-host by necessity. The resolution
   (gate the workflow in the body, not the file) is the design decision this spec records.

## Business rules

- **One unit, one body, two claimants.** The `SKILL.md` bytes for a command do not depend on
  which claimant is selected. There is exactly one writer.
- **Install when *any* claimant is selected; reclaim only when the *last* claimant is
  deselected.** Deselecting `opencode` while `codex` remains must leave every unit in place.
- **A gate that only covers one path is not a gate.** The OpenCode concurrency requirement
  applies wherever the workflow can be invoked in OpenCode.
- **Codex is unchanged.** A `codex`-only selection must produce byte-identical units and
  identical reclaim behavior.

## Architecture alignment

- ADR-0003 — `.agents/skills/<name>/` holds ONE shared unit per command, claimed by every
  front-end that reads it: this feature adds `opencode` to the claiming set and makes the one
  body host-neutral, which is precisely the ADR's stated obligation on a new reader.
- ADR-0002 — `builder-heavy` is a model tier, not a second Builder prompt: untouched here, but
  it is why the shared body must not encode a host capability (a body that presumes a host's
  model-override mechanism would violate the ADR). F02 restores the tier on OpenCode.

## Acceptance criteria (EARS)

- **R1** — When `opencode` is selected and no other claimant is, the installer shall install
  the shared `.agents/skills/<cmd>/` units for the standard command set.
- **R2** — When `codex` remains selected and `opencode` is deselected, the installer shall
  leave every shared skill unit and its policy companion in place.
- **R3** — When the last claimant of the shared surface is deselected, the installer shall
  reclaim the proven-pristine shared skill units.
- **R4** — The shared `SKILL.md` invocation adapter shall name both the Codex `$sdd-*`
  invocation and the OpenCode `/sdd-*` invocation, and shall not instruct OpenCode to use
  `/skills`.
- **R5** — If the `sdd-fix-parallel` shared skill is invoked in OpenCode while
  `.harness/.opencode-parallel` does not read `supported`, then the skill shall stop before
  spawning any worker and report the capability gate and the override path.
- **R6** — A `codex`-only selection shall produce byte-identical shared skill units and
  identical install/reclaim behavior before and after this feature.

## Out of scope

- Emitting or regenerating OpenCode source glue (`opencode.json`, `.opencode/*`) — that is
  E31-F02.
- Changing any command's canonical workflow body beyond the `sdd-fix-parallel` precondition
  required by R5.
- Renaming `.harness/.codex-skills/` (ADR-0003 keeps the historical name).
- Retiring `.opencode/command/` in favor of the shared skills (deferred in the epic Notes).

## Open questions

- None for approval. The design choice (self-gate the workflow in the shared body rather than
  gate the file) is recorded in the plan; a reviewer who prefers a structural gate should
  reject with that alternative and the trade-off (Codex still needs the unit, OpenCode would
  still read it) stated.
