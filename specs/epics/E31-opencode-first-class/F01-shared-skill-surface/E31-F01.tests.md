## Behavioral / end-to-end checks

- **OpenCode resolves the seven workflows (R1/R4).** In a temp project with `--agents=opencode`
  and the PR-loop gate on, run `opencode serve` and `GET /command`; assert `sdd-next`,
  `sdd-new`, `sdd-plan`, `sdd-drill`, `sdd-fix`, `sdd-fix-parallel`, and `sdd-pr-loop` are
  present. Resolve the *surface*, not just the name: OpenCode's command table prefers a
  same-named `.opencode/command/<name>.md` over a skill, so the six base workflows are served
  from the native command copy; only `sdd-fix-parallel` (withheld from `.opencode/command/` by
  the E22-F01 gate) is served from `.agents/skills/`. That is the `source:"skill"` reading the
  epic's 2026-09-17 probe recorded for the source repo, which ships no `.opencode/command/`
  copy. If OpenCode is not installed in CI, gate this check on `command -v opencode` and
  report it as skipped, not failed — the unit/integration assertions above remain mandatory.
- **Gate holds in OpenCode (R5).** With `.harness/.opencode-parallel` absent or `sequential`,
  invoke `/sdd-fix-parallel` in OpenCode and confirm it stops before spawning workers and
  names `/sdd-test-concurrency`; then write `supported` and confirm the workflow proceeds.
  Gate on `command -v opencode`; otherwise assert the precondition text in the generated
  `SKILL.md` (the mandatory half).
- **Deselect-last only (R3).** The reclaim test must be a two-claimant fixture
  (`codex,opencode` → deselect one → units present; → deselect the other → units gone). A
  single-claimant test cannot detect the silent-destructive regression.
