# Source `--self` OpenCode glue — Functional Spec

> R-ids in this document are `R1 … R11`; their fully-qualified form is `E31-F02:R1 … E31-F02:R11`.

## Context

E26-F01 made the source repo's **Claude and Codex** glue generated rather than
hand-maintained: `harness-install.sh --self` runs the real installer on a throwaway target,
transforms the target layout into the source layout, and reconciles it against a checksum
ledger (`.claude/.glue-manifest`), with E26-F02's suite failing if an emitter changes without
regeneration. OpenCode was deliberately excluded (`harness-install.sh:7671` dies on
`opencode`), so its glue is the one remaining hand-maintained mirror — the exact defect class
E26 exists to kill.

It has already drifted. `gen_opencode_json` (`harness-install.sh:4416`) emits the
`builder-heavy` role for every real target, but the committed `opencode.json` has six agents
and omits it. On OpenCode that means escalation silently no-ops — the failure ADR-0002 was
written to prevent ("escalation would silently no-op on three of the five supported
front-ends"). A live probe on 2026-09-17 confirmed OpenCode exposes `orchestrator, architect,
builder, reviewer, scout, doc-critic` and no `builder-heavy`; `pr-fixer` and
`/sdd-test-concurrency` are absent too. There is no committed `.opencode/` directory at all,
so even the native command surface the installer already emits for targets is missing.

E31-F01 has since merged and made `{codex, opencode}` claimants of the shared
`.agents/skills/<cmd>/SKILL.md` surface with a host-neutral adapter (ADR-0003). This feature
therefore **consumes** F01's shared surface and does not re-implement it; it extends `--self`
to the OpenCode emitters so the source glue is generated, reclaimed, and drift-gated like the
other two hosts.

### Why `complexity: complex`

Three of `agents/architect.md`'s stated bases hold:

1. **It lands near the size budget** — 11 requirements against `change_size`'s default of 12,
   of which R3, R5, R6, R7 and R9 are regression locks for behavior a careless change silently
   breaks (role set, ownership guards, drift gate, path transform, host resolution).
2. **It re-enters a defect class the harness has already paid for** — a byte contract compared
   in more than one place. The OpenCode source glue is compared by `self_reconcile`'s `cksum`
   ledger, by E26-F02's `glue_diff`, and by `init.sh`'s manifest warn, so all three surfaces
   must move together. It also required resolving a contradiction: a bare `--self` must select
   `opencode` (or the drift gate is red on a clean tree) while the source seed pins no OpenCode
   model, so role existence — not model resolution — is the contract (ADR-0002).
3. **It honors ADRs whose constraints reach across files.** ADR-0002 requires `builder-heavy`
   to exist as a per-host agent definition; ADR-0003 requires the OpenCode command surface to
   reuse the one canonical command body rather than fork the shared skill.

## Business rules

- **Generated, not hand-maintained.** Every OpenCode glue file in the source repo is
  reproducible by re-running `--self`; a hand edit is caught by the drift gate.
- **The source tree is machine-independent.** `--self` output must not depend on any local
  capability marker or flag; the gated parallel lane and its marker never enter version
  control.
- **The PR-loop gate is bidirectional.** OpenCode `pr-fixer` glue appears when
  `pr_loop.enabled` is true and is reclaimed when it flips false, exactly as the Claude/Codex
  glue already is.
- **Ownership is guarded.** Foreign, edited, or symlinked files are preserved and never
  claimed; the reconciler never publishes a verdict the per-role-file model did not compute.
- **One shared surface, consumed not forked.** The `.agents/skills/` unit and its
  host-neutral adapter belong to E31-F01/ADR-0003; F02 references them and adds no second
  body.

## Architecture alignment

- platform ADR-0002 — `builder-heavy` is a model tier, not a second Builder prompt: the
  generated `opencode.json` must define the role so the per-host agent definition carries the
  escalation target; the source copy currently omits it, which is the defect this feature
  removes. The source seed pins no OpenCode model, so the role's *existence* is the
  requirement and the resolved verdict stays `neither` (see Open questions).
- platform ADR-0003 — `.agents/skills/<name>/` holds one shared unit per command, claimed by
  every front-end that reads it: the OpenCode commands emitted here reuse the canonical
  `$CMDDIR` body and do **not** fork the shared skill body; OpenCode's command table gives a
  same-named native command precedence over the skill, which is why the `.opencode/command/`
  copy is the host-correct surface while the F01 shared unit remains the fallback. F02 adds no
  claimant and re-implements no adapter.

## Acceptance criteria (EARS)

- **R1** — When `harness-install.sh --self` runs, the system shall regenerate the source repo's
  OpenCode glue (`opencode.json`, `.opencode/command/*.md`, and `.opencode/agent/pr-fixer.md`
  while the PR-loop gate is on) by running the existing OpenCode emitters through the temporary
  install and transforming to the source layout, with `opencode` in the default selection.
- **R2** — The committed source `opencode.json` shall define the six standard roles **and**
  `builder-heavy`, so OpenCode exposes an escalation role.
- **R3** — While `pr_loop.enabled` is `true`, `--self` shall write `.opencode/agent/pr-fixer.md`;
  if the gate is not `true`, then `--self` shall reclaim a pristine generated `pr-fixer` file
  and leave a foreign, edited, or symlinked one untouched and unclaimed.
- **R4** — When `--self` runs, the system shall force the OpenCode capability gate off for the
  temporary install, so it shall write `.opencode/command/sdd-test-concurrency.md` and shall
  write neither `.opencode/command/sdd-fix-parallel.md` nor `.opencode-parallel`.
  `--with-opencode-parallel=true` is the only lever that can reach the temporary install (its
  fresh `TARGET` cannot see a source-root marker by construction); `--self` shall neutralise it
  so its output is byte-identical with and without the flag.
- **R5** — The self reconciler shall treat `opencode.json`, each `.opencode/command/*.md`, and
  `.opencode/agent/pr-fixer.md` as per-file guarded ownership units, preserving foreign,
  edited, or symlinked files and recording adopted ones in `.claude/.glue-manifest`; it shall
  never own `.opencode-parallel`, and it shall record the config-derived `opencode=neither`
  with a `blocked` first line rather than an `opencode=unstamped` verdict the per-role-file
  model cannot compute.
- **R6** — When an OpenCode emitter changes without re-running `--self`, or a generated
  OpenCode source file is hand-edited or deleted, the E26-F02 drift gate
  (`tests/test_self_drift.sh`, and the `init.sh` manifest warn) shall fail/flag for the
  OpenCode glue byte-for-byte.
- **R7** — The generated OpenCode source glue shall carry the source layout: `"instructions":
  ["AGENTS.md"]`, prompts resolving to `{file:./agents/<role>.md}`, and no surviving
  `.harness/` prefix in any OpenCode-owned file.
- **R8** — The `.opencode/command/<cmd>.md` source files shall reuse the canonical `$CMDDIR`
  command body (the same one the target emission mirrors) with a non-empty length floor, so
  OpenCode's native command surface takes precedence over a same-named shared skill without
  forking a second body and without a trim-to-empty equality passing vacuously.
- **R9** — The source-repo OpenCode resolution check shall assert from the committed source
  layout that OpenCode's command and agent surfaces include `/sdd-next` and the
  `builder-heavy` and `pr-fixer` agents; where an OpenCode binary is available it shall verify
  this live, and where it is not it shall report the live probe skipped while the static
  assertions remain mandatory.
- **R10** — The shared `.agents/skills/<cmd>/SKILL.md` units written by `--self` shall retain
  E31-F01's host-neutral adapter (naming both `$sdd-*` and `/sdd-*`, no `/skills`) and the
  `{codex, opencode}` claiming set, so F02 reuses the F01 surface (ADR-0003) rather than
  re-implementing it.
- **R11** — The feature shall carry a MINOR `VERSION` bump with a matching `CHANGELOG.md`
  entry, and the `tests/test_codex_native.sh` VERSION literal shall be synced to it.

## Out of scope

- Any change to the shared skill adapter or claiming set — that is E31-F01, consumed as-is.
- Emitting `.opencode/command/sdd-fix-parallel.md` into source: the lane is capability-gated
  and machine-local by decision (E22-F01).
- Committing `.opencode-parallel`, or any per-machine state.
- Retiring `.opencode/command/` in favour of the shared skills (deferred in the epic Notes).
- Changing any target-side OpenCode emitter or command body; F02 wires existing emitters into
  `--self` only.
- Editing the E31-F01-owned shared skill body (`gen_skill_body`). Its source-checkout clause
  (`harness-install.sh:6800-6803`) says the source checkout has no OpenCode command surface;
  F02 makes that false by committing `.opencode/command/sdd-test-concurrency.md`, but the
  shared adapter is F01's and out of the brief's scope. The correction is a named follow-up
  (see Open questions) and is recorded in the epic Notes.

## Open questions

- The source repo has no `models.builder-heavy` pin (all roles inherit — the root config is the
  seed template), so `--self` cannot harvest an OpenCode model the way it harvests Claude/Codex
  tiers. R2 is therefore satisfied by the **role existing** (escalation is a routing decision;
  ADR-0002), and `.escalation-arming` records `opencode=neither` rather than pretending a model
  resolves. If the operator later pins an OpenCode tier, `self_install` should harvest it — a
  follow-up, not this feature.
- **Superseded F01 prose (follow-up required).** `gen_skill_body`
  (`harness-install.sh:6800-6803`) tells a source-checkout OpenCode user that "no OpenCode
  command surface is installed, so that probe is unavailable"; it is pinned by
  `tests/test_installer_toggles.sh:1520-1534`. After this feature the source checkout installs
  `.opencode/command/sdd-test-concurrency.md`, so the clause is false. Because the brief scopes
  the shared adapter to E31-F01, F02 does **not** edit `gen_skill_body`; the correction (body
  clause + that F01 assertion + the `docs/INSTALL.md:405-413` mirror) is deferred to a named
  follow-up feature under the maintenance epic (`E99`, to be seeded at Inception) and recorded
  in the epic Notes. F02 does update the `docs/INSTALL.md` mirror (docs are in scope), so the
  divergence is one generated body clause for one release — a deliberate, recorded state, not
  an omission.
