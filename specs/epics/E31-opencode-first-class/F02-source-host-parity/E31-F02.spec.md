# Source `--self` OpenCode glue — Functional Spec

> R-ids in this document are `R1 … R8`; their fully-qualified form is `E31-F02:R1 … E31-F02:R8`.

## Context

E26-F01 made the source repo's **Claude and Codex** glue generated rather than
hand-maintained: `harness-install.sh --self` runs the real installer on a throwaway target,
transforms the target layout into the source layout, and reconciles it against a checksum
ledger (`.claude/.glue-manifest`), with E26-F02's suite failing if an emitter changes without
regeneration. OpenCode was deliberately excluded (`harness-install.sh:7283`, re-asserted at
`:7292`), so its glue is the one remaining hand-maintained mirror — the exact defect class
E26 exists to kill.

It has already drifted. `gen_opencode_json` (`:4324`) emits the `builder-heavy` role for every
real target, but the committed `opencode.json` has six agents and omits it. On OpenCode that
means escalation silently no-ops — the failure ADR-0002 was written to prevent ("escalation
would silently no-op on three of the five supported front-ends"). A live probe on 2026-09-17
confirmed OpenCode exposes `orchestrator, architect, builder, reviewer, scout, doc-critic`
and no `builder-heavy`; `pr-fixer` and `/sdd-test-concurrency` are absent too. The committed
`opencode.json` also points at `{file:./agents/...}`, so it is *nearly* the source-layout
transform of the emitter — but not generated, and not checked, so nothing stops the next
divergence.

This feature extends `--self` to the OpenCode emitter so the source glue is generated,
reclaimed, and drift-gated like the other two hosts. It depends on E31-F01 because the shared
skill body and the claiming set must be correct before OpenCode source glue derived from them
is committed.

### Why `complexity: complex`

Three of `agents/architect.md`'s stated bases hold:

1. **It lands near the size budget** — 8 requirements, of which R2, R5, R6 and R7 are
   regression locks for behavior that a careless change silently breaks (role set, ownership
   guards, drift gate, path transform).
2. **It re-enters a defect class the harness has already paid for** — a byte contract compared
   in more than one place. The generated-glue bytes are compared by `self_reconcile`'s
   `cksum` ledger, by E26-F02's `glue_diff`, and by `init.sh`'s
   `harness-owned-paths.sh all` set.
3. **It honors ADRs whose constraints reach across files.** ADR-0002 requires
   `builder-heavy` to exist as a per-host agent definition; ADR-0003 requires the OpenCode
   command surface to reuse the one canonical command body rather than fork it.

## Business rules

- **Generated, not hand-maintained.** Every OpenCode glue file in the source repo is
  reproducible by re-running `--self`; a hand edit is caught by the drift gate.
- **The source tree is machine-independent.** `--self` output must not depend on any local
  capability marker; the gated parallel lane and its marker never enter version control.
- **The PR-loop gate is bidirectional.** Glue appears when `pr_loop.enabled` is true and is
  reclaimed when it flips false, exactly as the Claude/Codex glue already is.
- **Ownership is guarded.** Foreign, edited, or symlinked files are preserved and never
  claimed; the reconciler never publishes an optimistic arming verdict.

## Architecture alignment

- ADR-0002 — `builder-heavy` is a model tier, not a second Builder prompt: the generated
  `opencode.json` must define the role so the per-host agent definition carries the model;
  the source copy currently omits it, which is the defect this feature removes.
- ADR-0003 — `.agents/skills/<name>/` holds one shared unit per command: the OpenCode
  commands emitted here reuse the canonical `$CMDDIR` body and do **not** fork the shared
  skill body; OpenCode's command table gives a same-named command precedence over the skill,
  which is why the native command is the host-correct surface for OpenCode.

## Acceptance criteria (EARS)

- **R1** — When `harness-install.sh --self` runs, the system shall regenerate the source
  repo's OpenCode glue (`opencode.json`, `.opencode/command/*.md`, and
  `.opencode/agent/pr-fixer.md` while the PR-loop gate is on) from the same emitters used for
  targets.
- **R2** — The committed source `opencode.json` shall define the six standard agents **and**
  `builder-heavy`, so an escalation resolves a model on OpenCode.
- **R3** — While `pr_loop.enabled` is `true`, `--self` shall write `.opencode/agent/pr-fixer.md`;
  if the gate is not `true`, then `--self` shall reclaim a pristine `pr-fixer` file and leave
  a foreign or edited one untouched.
- **R4** — When `--self` runs, the system shall install
  `.opencode/command/sdd-test-concurrency.md` and shall write neither
  `.opencode/command/sdd-fix-parallel.md` nor `.opencode-parallel`, regardless of any local
  capability marker.
- **R5** — The self reconciler shall treat `opencode.json`, each
  `.opencode/command/*.md`, and `.opencode/agent/pr-fixer.md` as guarded ownership units,
  preserving foreign, edited, or symlinked files, and shall not publish a temporary install's
  optimistic arming verdict.
- **R6** — When an emitter changes without re-running `--self`, the E26-F02 drift gate shall
  fail for the OpenCode source glue.
- **R7** — The generated OpenCode source glue shall carry the source layout: `"instructions":
  ["AGENTS.md"]`, prompts resolving to `{file:./agents/<role>.md}`, and no surviving
  `.harness/` prefix in any OpenCode-owned file.
- **R8** — When the OpenCode host test runs, it shall assert that `/sdd-next` and the agents
  including `builder-heavy` resolve from the source repo.

## Out of scope

- Any change to the shared skill adapter or claiming set — that is E31-F01.
- Emitting `.opencode/command/sdd-fix-parallel.md` into source: the lane is capability-gated
  and machine-local by decision (E22-F01).
- Committing `.opencode-parallel`, or any per-machine state.
- Retiring `.opencode/command/` in favour of the shared skills.

## Open questions

- The source repo has no `models.builder-heavy` pin (all roles inherit), so `--self` cannot
  harvest an OpenCode model the way it harvests Claude/Codex tiers. R2 is therefore satisfied
  by the **role existing** (escalation is a routing decision; ADR-0002). If the operator later
  pins an OpenCode tier, `self_install` should harvest it — a follow-up, not this feature.
