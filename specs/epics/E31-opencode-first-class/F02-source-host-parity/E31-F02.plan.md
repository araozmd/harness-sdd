> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.
> Line references are to the post-E31-F01 `harness-install.sh` on `main`.

## Stack & dependencies

- Language/framework: POSIX shell (`harness-install.sh` `--self` pipeline), POSIX `sh` +
  Python-in-sh test suites under `tests/`.
- New dependencies: none.

## Reuse — already built, do NOT re-implement (revalidation, 2026-09-18)

The OpenCode *target* emitters exist and are validated; this feature only wires them into
`--self`, owns them, and gates them. F01 already built the shared surface. A Builder reading
R1 alone could wrongly write new emitters — it must instead call the existing ones through
the temporary `install_one` and `self_transform`.

  emission (§5b) and `gen_opencode_legacy` — F02 wires the existing emitters into `--self`,
  it does not change target output. The committed source `opencode.json` is fixed by
  regeneration, not by editing the emitter.
- `skill_unit_claimed()` / `gen_skill_body()` / the shared `.agents/skills/` body — owned by
  E31-F01 (ADR-0003); F02 consumes its output and adds no second body (R10). This includes

  follow-up, not F02 work (see the spec's Open questions).
- Claude/Codex source glue and their manifest entries — must stay byte-identical.
- `tests/fixtures/frontend-v0.78.1/**` and its `_regenerated` exclusion set
  (`tests/test_codex_native.sh:222`). F01 already excludes the intentionally regenerated
  command bodies (`sdd-pr-loop.md`, `sdd-plan.md`, `sdd-drill.md`); F02 changes no target
  emitter, so the frozen oracle needs **no** new exclusion, and adding/removing one would
  falsify the snapshot.

## Approach notes

- **The default selection is load-bearing for R1/R6 (change from the seeded draft).** The
  seeded plan said "keep the default `claude,codex`". That cannot satisfy R1: `test_self_drift.sh`
  runs a bare `sh harness-install.sh --self` and its `glue_diff` must reproduce the committed
  `.opencode/`/`opencode.json` byte-for-byte. If a bare `--self` skipped OpenCode, the gate
  would be red by construction on a clean tree. The default therefore becomes
  `claude,codex,opencode`; `--agents=claude`/`--agents=codex`/`--agents=opencode` remain
  available for a narrowed source regeneration.
- **First adoption of the stale committed `opencode.json`.** The reconciler treats an on-disk
  file that is neither in `prior` nor byte-identical to the staged copy as foreign: it warns
  and leaves it unchanged (R5's ownership guard). The committed `opencode.json` is currently
  hand-maintained and differs from the emitter, so the Builder must **write the emitter's
  source-transformed bytes into `opencode.json` deliberately** (simplest: remove the stale
  file, then run `--self` and let it be created and recorded) and commit the result. After
  that, `--self` maintains it and the drift gate is green. Do **not** weaken the foreign guard
  to force adoption — that would break R3/R5.
- **Machine-independence is the crux (R4).** `--self` must be deterministic on any machine.
  The temp install's `TARGET` is a fresh dir, so a source-root `.opencode-parallel` can never
  reach `opencode_parallel_wanted` — a marker arm in the test would be a dead predicate. The
  only lever is the `--with-opencode-parallel` CLI flag. Force
  `OPENCODE_PARALLEL_OVERRIDE=false` for the temp run and assert the gated artifacts are
  absent when the flag is passed, **and** that the bytes are identical with and without it.
- **Arming must not lie (R5).** `write_escalation_arming` iterates `$AGENT_KEYS`; once
  `opencode` is selected it emits an `opencode=` line. The existing self loop
  (`:7714-7725`) infers "unstamped" from `.opencode/agents/<role>.<ext>`, a per-role-file
  shape OpenCode does not use — it would publish `opencode=unstamped` for a correctly written
  `opencode.json`. Skip non-`claude`/`codex` front-ends in that loop; the config-derived
  verdict (`neither`, since the source seed pins no OpenCode model) is the honest one, and the
  combined first line stays `blocked`.
- **`self_transform` re-use (R7).** The generic `sed 's|\.harness/||g'` already turns
  `{file:./.harness/agents/<role>.md}` into `{file:./agents/<role>.md}` and
  `"instructions": [".harness/AGENTS.md"]` into `["AGENTS.md"]`, which matches the current
  committed shape. Verify this holds for the emitter's exact bytes before assuming it; if a
  path needs a second transform, add it beside the existing ones, not in a new pipeline.
- **Stripping a prefix is not the same as naming the root (R7, finding 4045793773).** The
  generic strip is correct for pointer paths but WRONG for the OpenCode agent body's
  `installed in` / `mentions against` sentences, each rooted at `.harness/`: it removes the
  prefix and leaves an empty inline-code span, i.e. a resolution instruction with no root at
  all — worse than the installed form for a session OpenCode starts outside the repo root.
  Fix with two pre-strip rules (they must run BEFORE the strip, matching the target-side
  `.harness/` text they replace) that rewrite both into an explicit `the repository root`,
  mirroring the `sdd-pr-loop` command glue's source-layout line. Pin BOTH halves over the
  folded body: a two-token positive anchor (`mentions … repository root`) and a
  no-empty-placeholder negative with a planted positive control
  (`tests/test_self_mode.sh::opencode_pr_fixer_root_explicit`, plus the committed-artifact
  check in `tests/test_source_shims.sh`).
- **Canonical body reuse (R8).** In a target, `.opencode/command/<cmd>.md` is copied raw from
  `$CMDDIR` (`:6724-6733`); in source, the same body runs through `self_transform`. So the
  source `.opencode/command/<cmd>.md` bytes must equal the source `.claude/commands/<cmd>.md`
  bytes for the shared command set — assert that, never a re-forked body. The equality is
  symmetric, so add a **length floor** (e.g. the file is non-empty and within a byte or two of
  the source command, or compare against `self_transform < "$CMDDIR/<cmd>.md"`) so two empty
  or truncated files cannot pass (the 2026-09-16 "both extracts empty ⇒ `cmp -s` passes"
  lesson).
- **Frozen-fixture discipline (`progress/lessons.md` 2026-09-16).** The golden
  `frontend-v0.78.1` oracle compares consumer `.opencode/command/*.md`/`opencode.json`; F02
  changes neither emitter nor command body, so it must leave the oracle and its exclusion set
  alone. If a later edit is tempted to add an exclusion, that is the signal the emitter
  changed when the spec said it must not.
- **A fourth suite breaks on the source tree change (H1).** `tests/test_source_shims.sh`
  inspects `$SRC` directly: its absence loop (`:90-104`) fails the moment `$SRC/.opencode`
  exists, and its `KNOWN_GAPS` xfails (`:76-77`) assert `builder-heavy:opencode` and
  `pr-fixer:opencode` are still unregistered. F02 retires both — `builder-heavy` via the
  `opencode-json` mechanism, `pr-fixer` via `opencode-file` (`.opencode/agent/pr-fixer.md`) —
  so the loop loses `.opencode` and both lines are deleted, letting the general registration
  rule cover them. Refresh the comments that describe OpenCode as `opencode.json`-only.
- **`test_codex_native.sh` currently pins the opposite (R1/R9).** Lines `:51-53` assert
  `--self --agents=opencode` (and host=opencode) exits non-zero and leaves the tree
  unchanged — that is the pre-F02 contract F02 deliberately reverses. Both arms must flip to
  positive expectations, with `gemini`/`antigravity` remaining the negative controls.
- **Keep the Codex arming test focused (H2).** The `models` fixture (`:56-67`) and the R11
  protected-Builder loop (`:91-113`) assert `armed`/`codex=unstamped` verdicts from bare
  `--self` runs. Once `opencode` joins the default selection, `opencode=neither` makes the
  conservative AND `blocked` and those assertions red for a reason unrelated to what they
  test. Pass explicit `--agents=claude,codex` to `:57`, `:61`, `:101` and `:113`; F02's own
  OpenCode arming verdict is pinned separately in `test_self_mode.sh` (R5).
- **Falsifiability of the drift gate (M4).** `test_self_drift.sh`'s green fixture inherits
  `opencode.json` through the `"$SRC"/*` copy, and `.opencode/` is absent by construction.
  Deleting the inherited `opencode.json` (and any copied `.opencode/`) before `--self` is
  **non-negotiable**: without it, the regenerated-vs-committed diff can be green on a stale
  artifact, proving the repo's state rather than the code (the 2026-09-05 copied-fixture
  lesson).
- **`VERSION` literal sync (R11).** `tests/test_codex_native.sh:230` pins
  `(src/'VERSION').read_text().strip()=='0.83.0'` as a literal — the known fragile
  permanent-suite anti-pattern (`progress/lessons.md` 2026-09-16). The MINOR bump must update
  that literal in the same PR, or the suite reds on the bump alone. (`test_agents_host.sh`'s
  CHANGELOG check compares parsed components and needs no edit.)
- **`.gitignore`.** F01 already added `/.opencode-parallel` and documented why; F02 verifies
  it and asserts the gated command/marker are absent, but adds no new root ignore. Never
  ignore `.opencode/command/` or `.opencode/agent/` — they are tracked generated glue.
- **Sequencing.** F02 depends on F01 (already merged). Both edit `harness-install.sh`, so
  they land in separate PRs, F01 first. Bump `VERSION` in F02 (installer body + capability)
  per `AGENTS.md`.
