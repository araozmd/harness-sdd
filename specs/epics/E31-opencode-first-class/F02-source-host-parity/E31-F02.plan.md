# Source `--self` OpenCode glue — Technical Plan

> Translates the `.spec.md` intent into design. Every decision cites the R-id(s) it serves.

## Stack & dependencies

- Language/framework: POSIX shell (`harness-install.sh` `--self` pipeline), POSIX `sh` tests.
- New dependencies: none.

## Reuse — already built, do NOT re-implement (revalidation, 2026-09-17)

The OpenCode *target* emitters exist and are validated; this feature only wires them into
`--self`, owns them, and gates them. A Builder reading R1 alone could wrongly write new
emitters — it must instead call the existing ones through the temp `install_one`.

| Already built | Location | Provides |
|---|---|---|
| `gen_opencode_json` (already emits `builder-heavy`) | `harness-install.sh:4324-4348` | target + source `opencode.json` (R1, R2) |
| `.opencode/command/*` emission + concurrency gate | `:6470-6502` | target + source commands (R1, R4) |
| `gen_oc_agent` — file-based `pr-fixer` | `:4330-4345`, gated `:6512` | `pr-fixer` (R3) |
| `/sdd-test-concurrency` body + marker handling | `:5401-5440`, `:4280-4295` | source command (R4) |
| Target drift coverage of `.opencode/` + `opencode.json` | `tools/harness-owned-paths.sh:76-79` | the paths are already recognised as glue (R6) |

The net-new work is therefore: the `--self` selection/copy/reconcile/arming wiring, the
machine-independence gate, and the source-side tests — not the emitters themselves.

## DO NOT TOUCH

- `skill_unit_claimed()` / `gen_skill_body()` — owned by E31-F01; this feature assumes F01 has
  merged and consumes its output.
- `gen_opencode_json`'s role set — it already emits `builder-heavy`; the fix is to make the
  source copy **generated**, not to change the emitter.
- Claude/Codex source glue and their manifest entries.
- `.harness/.codex-skills/` ledger path (ADR-0003).
- `--self`'s refusal of a target path, `--umbrella`, and `--print-agents` (E26-F01 R1).

## Approach notes

- **Machine-independence is the crux (R4).** `--self` must be deterministic on any machine.
  The OpenCode temp install would otherwise read the operator's `.harness/.opencode-parallel`
  and possibly emit `.opencode/command/sdd-fix-parallel.md`. Force the capability gate off for
  the temp install (the same way `self_install` already forces `BUILDER_BACKEND_OVERRIDE` and
  `PR_LOOP_OVERRIDE` from the source config), and assert the gated artifacts are absent.
- **`self_transform` re-use (R7).** The generic `sed 's|\.harness/||g'` already turns
  `{file:./.harness/agents/<role>.md}` into `{file:./agents/<role>.md}` and
  `"instructions": [".harness/AGENTS.md"]` into `["AGENTS.md"]`, which matches the current
  committed file. Verify this holds for the OpenCode emitter's exact bytes before assuming it;
  if a path needs a second transform, add it beside the existing ones, not in a new pipeline.
- **Ownership grouping (R5).** The reconciler groups some paths as atomic units (e.g. the
  Codex skill unit). Decide deliberately whether `opencode.json` is its own unit and whether
  `.opencode/command/*.md` are individually owned (they are independent files, so per-file
  ownership is correct). A foreign `opencode.json` (hand-edited) must be preserved with a
  warning and left unclaimed, exactly as the Claude shims are.
- **Arming (R5).** `write_escalation_arming` iterates `SELECTED`. If `opencode` is now
  selected, it will compute an `opencode=` verdict. Confirm the resolver returns a sane
  verdict for an inherited OpenCode tier and that the expected `.escalation-arming` body is
  updated in `tests/test_self_mode.sh`. If the resolver cannot answer for OpenCode, leave the
  arming file's front-end set unchanged and record that in the test — do not publish a verdict
  the resolver did not compute.
- **Sequencing.** F02 depends on F01; both edit `harness-install.sh`, so they land in separate
  PRs, F01 first. Bump `VERSION` in F02 (installer body change) per AGENTS.md.
- **`opencode.json` is a generated artifact in the source repo.** Unlike an installed target, the source
  repo's `opencode.json` is harness glue; the reconciler should still preserve a foreign file
  rather than clobber it, but the expectation is that it regenerates cleanly.
