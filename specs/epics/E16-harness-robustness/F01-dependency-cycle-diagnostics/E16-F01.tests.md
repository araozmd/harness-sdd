## Cycle-helper fixture checks
- Build a feature graph `E16-F01 -> E16-F02 -> E16-F03 -> E16-F01` and assert
  exactly `dependency-cycle<TAB>feature<TAB>E16-F01 -> E16-F02 -> E16-F03 ->
  E16-F01`. Build an equivalent board with epics, features, and dependency arrays
  reversed and assert byte-identical output.
- Build slice graph `E20-F01@api -> E20-F01@web ->
  E20-F01@worker -> E20-F01@api` and assert the exact canonical closed record with
  graph kind `slice`.
- Exercise one feature self-edge and one slice self-edge and assert each output is
  exactly `<id> -> <id>`.
- Include a feature dependency naming a nonexistent feature, a feature naming a
  slice id, and a slice naming a feature id. Assert none becomes a graph node or
  cycle; assert the vocabulary contract classifies them as
  `unmet-dependency` with `missing`.
- Include two disjoint cyclic components and assert one witness per component,
  feature records before slice records, and canonical numeric order (`E2` before
  `E10`).
- Include one strongly connected component with root edges into two different
  possible cycles. Assert exactly one witness selected by lowest root, lowest
  in-component neighbor, and sorted breadth-first return path; reorder every input
  array and assert the same bytes.

## Init integration checks
- Copy the minimum source harness needed by `init.sh` into `mktemp -d`, replace
  only the fixture TaskStore, and run the real copied helper/init pair. Assert a
  valid cyclic board emits every full-path warning and exits zero.
- Repeat in a fresh `harness-install.sh` target and assert installed
  `.harness/init.sh` finds `.harness/tools/task-diagnostics.py`, emits the same
  warning vocabulary, and exits zero.
- Run empty, feature-empty, absent-`depends_on`, empty-`depends_on`, and acyclic
  boards. Assert no `dependency-cycle` warning and zero exit.
- Run the helper directly with a missing path and malformed JSON. Assert non-zero
  stderr names the supplied path. Run malformed JSON through `init.sh` and assert
  the existing TaskStore validation failure remains the environment-gate result,
  not a successful cycle warning.

## No-selection contract checks
- Assert `agents/orchestrator.md`, `store/local.md`, and the helper reason constants
  contain exactly the seven stable codes and direct E16-F03 to reuse them
  verbatim.
- Assert records are `blocked <id> [<reason-code>]: <human text>`, candidate ids
  use lower numeric epic/feature ordering, reasons use the plan's fixed order,
  blockers are sorted, and the final summary follows the records.
- Assert a candidate can report both `dependency-cycle` and
  `unmet-dependency`; missing, non-done, and slice `done-but-unmerged` details are
  distinct.
- Assert draft features name `gated-epic`; non-autonomous `spec-ready` and gated
  quick fixes name `human-gate`.
- Assert `owner-excluded` applies only after ordinary actionability under
  resolved `--mine`, `owner-unresolved` is scoped-only, and bare selection never
  considers owner.
- Assert empty and all-done boards use the two exact `no-candidates` texts, emit
  no fabricated `blocked` subject, mutate no state, and remain informational.
- In a clean Reviewer context, apply the portable Orchestrator role to disposable
  board/config fixtures for all R8–R13 classes. Capture exact output and
  before/after hashes; require `blocked --mine` for unresolved scope, the exact
  empty/dynamic-lookup rendering, scoped-only owner reasons, all applicable
  dependency reasons, and the exact final summary.

## Non-functional and regression checks
- Generate 2,000 acyclic feature nodes with a single backward dependency chain,
  run the real helper under Python monotonic timing, require completion under five
  seconds, and assert empty cycle output.
- Import the helper with standard-library import blocking for known third-party
  names or inspect its imports; assert it requires no package outside Python
  stdlib and never writes its input fixture.
- Hash `store/tasks.schema.json` before/after focused tests and inspect its status
  enums; no schema field or status changes are permitted.
- Assert the installed helper is executable, installed init calls it, and installed
  Orchestrator carries every stable reason code.
- Run source helper compilation, focused shell syntax/suite, installer, epic
  lifecycle, ownership, `./init.sh`, and the exact full command from
  `verification.test_command`.
- Version tests locate the changelog section containing stable id `E16-F01`,
  compare it to the immediately older version, require one MINOR increment with
  patch zero, and permit future `VERSION` values at or above that feature version.
