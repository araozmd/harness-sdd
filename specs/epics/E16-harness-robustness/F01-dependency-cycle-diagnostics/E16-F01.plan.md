# Dependency-cycle detection and no-actionable-work diagnostics — Technical Plan

> Every design decision cites the requirement ids it serves.

## Stack & dependencies
- Python 3 standard library for one reusable graph/formatting helper; POSIX shell
  remains the integration layer in `init.sh` and the permanent test suite. No
  PyPI, npm, YAML, graph, or JSON-query package is introduced. *(serves: R1–R7,
  R14)*
- Markdown remains the portable runtime contract for current Orchestrator
  selection. E16-F03 will later implement the same vocabulary in
  `tools/next-task.mjs`; F01 does not introduce a second selector. *(serves:
  R8–R13)*

## Diagnostic data model

No persistent data model changes are permitted. The helper reads the existing
TaskStore and constructs ephemeral values only.

| Entity | Field | Type | Contract | R-id |
|---|---|---|---|---|
| graph node | `id` | string | Existing canonical feature id `E<n>-F<n>` or slice id `E<n>-F<n>@<repo>`; feature and slice namespaces remain disjoint. | R1–R4 |
| graph node | `kind` | enum | `feature` or `slice`; an edge resolves only within the same kind. | R1, R2, R4 |
| graph node | `depends_on` | list[string] | Existing field; absent is equivalent to an empty list for diagnostics. | R4, R6 |
| cycle record | `code` | string | Always `dependency-cycle`. | R1–R5 |
| cycle record | `kind` | string | `feature` or `slice`. | R1–R3 |
| cycle record | `path` | list[string] | Closed witness: length at least two and `path[0] == path[-1]`. | R1–R4 |
| selection record | `subject` | string | Canonical feature/slice id, or no subject for `no-candidates`. | R8–R13 |
| selection record | `code` | enum | `dependency-cycle`, `gated-epic`, `unmet-dependency`, `human-gate`, `owner-excluded`, `owner-unresolved`, or `no-candidates`. | R8–R13 |
| selection record | `detail` | string | Stable human-readable text with canonical ids/statuses; never state. | R8–R13 |

### Canonical identity and ordering
- Parse numeric epic and feature components as integers, so `E2-F10` sorts before
  `E10-F1`; slice ids extend the same key with the lexical repository suffix.
- Analyze feature and slice graphs independently and compute strongly connected
  components with nodes and adjacency sorted by that key. For each cyclic
  component, choose its lowest-key node `root`, then choose the lowest-key
  in-component neighbor in `adjacency[root]`. A self-edge immediately yields
  `root -> root`; otherwise run breadth-first search from that neighbor back to
  `root`, restricted to the component, visiting sorted adjacency and marking a
  node when enqueued. Reconstruct that first shortest path and prefix `root`.
  Strong connectivity guarantees a return path. Sort final records with feature
  before slice and then by the complete canonical path. This exact rule pins the
  same witness for a component with several possible cycles without enumerating
  every simple cycle.
- Resolve a dependency as an edge only if the exact id exists in that same graph.
  Missing ids and feature↔slice references are returned as unresolved blockers,
  never synthesized nodes. *(serves: R1–R4, R10)*

### Stable reason vocabulary and human text

| Code | Classification | Required human detail | R-id |
|---|---|---|---|
| `dependency-cycle` | dependency | `dependency cycle (<kind>): <id> -> ... -> <id>` | R1–R4, R10 |
| `gated-epic` | gate | `epic <id> is draft` | R9 |
| `unmet-dependency` | dependency | `blocking dependencies: <id>=missing, <id>=<status>, ...`; a completed unmerged slice is `<id>=done-but-unmerged`. | R4, R10 |
| `human-gate` | gate | Exactly `spec-ready requires approval` or `gated quick fix requires approval`. | R11 |
| `owner-excluded` | owner | Exactly `effective owner=<literal>` or `effective owner=unowned`; only after all ordinary actionability gates pass under resolved `--mine`. | R12 |
| `owner-unresolved` | owner | Subject is `--mine`; exactly `workflow.identity=<empty>` for absent/empty identity, or `workflow.identity=@me lookup failed` / `workflow.identity=self lookup failed` for a failed dynamic lookup. | R12 |
| `no-candidates` | terminal | The sole summary is exactly `no actionable work [no-candidates]: board has no features` or `no actionable work [no-candidates]: all features are done`; no `blocked` record precedes it. | R13 |

For one subject, emit all applicable non-owner gate/dependency reasons in the table
order above. Evaluate `owner-excluded` only for otherwise actionable candidates,
matching the current “scope after normal gates” contract. Sort subjects by canonical
numeric id and blockers by canonical id. When at least one `blocked` record exists,
the one final summary is exactly `no actionable work: selection blocked; see reasons
above`. The R13 `no-candidates` line is itself the sole summary. Every form is
informational. *(serves: R8–R13)*

There are two activation paths. A top-level `next()` no-result diagnoses unfinished
feature candidates across the board. If top-level selection has already returned a
sliced feature but `next_slice(feature)` returns no slice while unfinished slices
remain, diagnose only that selected parent's unfinished slices with the same record,
reason-order, summary, informational, and no-mutation rules. The slice path must not
fall through to whole-board top-level diagnostics or report unrelated features or
slices. E16-F03 reuses both activation paths and the vocabulary verbatim. *(serves:
R8, R10)*

## Helper interface

Create executable `tools/task-diagnostics.py` with import-safe functions and a
single cycle CLI:

```text
REASON_TEXT = {
  "dependency-cycle": ...,
  "gated-epic": ...,
  "unmet-dependency": ...,
  "human-gate": ...,
  "owner-excluded": ...,
  "owner-unresolved": ...,
  "no-candidates": ...,
}
node_sort_key(node_id) -> tuple
build_dependency_graph(board, kind) -> (adjacency, unresolved)
find_dependency_cycles(board) -> list[{"code", "kind", "path"}]
format_cycle(record) -> "dependency-cycle\t<kind>\t<id> -> ... -> <id>"

python3 tools/task-diagnostics.py cycles <tasks-json>
```

The CLI writes one tab-delimited formatted cycle record per line to stdout and
returns `0` for both acyclic and cyclic valid JSON. An unreadable or malformed
requested file returns non-zero and names the path on stderr. The implementation
may choose any deterministic strongly-connected-component algorithm, but witness
extraction must use the exact root/neighbor/BFS rule above, emit one canonical
closed witness per cyclic component, and remain `O(V+E)` overall because the
components are disjoint. It must not import `jsonschema` or mutate the input.
*(serves: R1–R7, R14)*

`init.sh`, after the existing successful TaskStore validation, invokes the helper
against the same `state/tasks.json`, reads each record without a pipeline that can
hide an exit status, and prints:

```text
⚠️  TaskStore dependency-cycle [<kind>]: <id> -> ... -> <id> (warn-only)
```

Cycles never affect `init.sh`'s exit status. A helper invocation failure after the
canonical validator succeeded is reported as a warning and does not replace
validator/project-check semantics. *(serves: R5–R7)*

## Approach notes and rejected alternatives
- **Chosen: one stdlib Python graph helper plus a portable prose selection
  contract.** The local backend already requires Python 3, the helper is directly
  testable and installable, and its vocabulary gives E16-F03 a pinned compatibility
  target without prematurely implementing selection.
- **Rejected: embed graph traversal in `init.sh`.** Non-trivial cycle
  canonicalization in shell would be fragile and not reusable by focused tests or
  later selection work.
- **Rejected: make cycles schema errors or init failures.** A draft/gated cycle
  is not an invalid JSON shape, and the approved product rule is warn-only.
- **Rejected: enumerate every simple cycle.** Dense components have exponentially
  many simple cycles. One deterministic closed witness per cyclic component gives
  an actionable path with linear graph analysis.
- **Rejected: implement selection diagnostics as executable selection code now.**
  That would duplicate or preempt E16-F03. F01 changes the current Orchestrator
  contract and pins codes/text. The Reviewer behaviorally exercises that portable
  role against disposable boards; F03 later moves the complete routing table into
  deterministic JavaScript.
