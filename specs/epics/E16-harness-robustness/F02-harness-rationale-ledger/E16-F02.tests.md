## Focused source checks
- Parse the rationale as lines and require the five section headings from the
  plan in order. Require an explicit definition of "harness", the intended
  newcomer/maintainer audiences, the two layer names, primary-purpose decision
  rule, and retain-by-default evidence posture. Do not freeze full prose.
- Locate the ledger header and count exactly 21 body rows before the next
  heading. For each row, split its five Markdown cells and require non-empty
  mechanism, layer, purpose, evidence, and repository-pointer cells.
- Match the stable C1–C8 and D1–D13 mechanism labels from the plan. These labels
  are the completeness boundary; prose inside cells may improve without
  breaking the test.
- Require the C8 row to link ADR-0001, name E16-F03, state that routing prose
  remains active until the replacement is reviewed/shipped, and preserve
  human-readable gate policy.
- Require descriptive links to the exact Anthropic, OpenAI, LangChain,
  Thoughtworks, and METR publisher URLs in the plan. Require the evidence section
  to say these are bounded reports rather than universal consensus and that
  METR's result is an early-2025 experienced-open-source-developer RCT snapshot.
  Never fetch the network or assert a changing benchmark/result number.
- Reject image syntax, HTML image/script tags, Mermaid fences, color-only
  language, an auxiliary `DELETION-LEDGER.md`, YAML/JSON ledger files, or claims
  that the ledger is machine-enforced. Require descriptive link text rather than
  bare URLs in rendered prose.

## Navigation and link checks
- Require README's introductory block and its `docs/` layout line to name and
  link `docs/RATIONALE.md`.
- Require one concise rationale row in AGENTS.md's "Where things live" table and
  at least one descriptive relative link from `docs/HARNESS.md`; assert neither
  navigation file contains the ledger's 21-row sequence.
- Extract every local Markdown link introduced in the three navigation files
  and `docs/RATIONALE.md`, resolve it relative to its containing file, strip
  anchors, and require the target path to exist. External links are shape-checked
  only and remain offline.

## Installed-layout checks
- Run the real installer into `mktemp -d` with a fixed non-interactive agent
  selection. Require `.harness/docs/RATIONALE.md`, compare it byte-for-byte with
  source `docs/RATIONALE.md`, and require the installed `AGENTS.md` and
  `.harness/docs/HARNESS.md` navigation to resolve to the installed rationale.
- Do not edit or special-case `harness-install.sh`: its existing `copy docs`
  contract is the behavior under test.

## Reviewer behavioral checks
- Verify README navigation in the source layout. Then read only the installed
  `AGENTS.md`, `.harness/docs/HARNESS.md`, and
  `.harness/docs/RATIONALE.md` in a disposable target. Confirm a cold reader can
  answer: what the harness is; why prompting alone is not this workflow's
  complete control plane; how the two layers differ; why compensation is
  retained today; what evidence permits removal; and why durable controls do not
  disappear solely because a model is stronger.
- Audit all 21 ledger rows against the plan. Each row must have a distinct
  observable criterion and a repository pointer; generic repeated text such as
  "remove when no longer needed" fails R6.
- Inspect external paraphrases against the primary pages. Reject universal
  consensus, causality, or cross-model claims not made by the bounded source and
  reject any METR extrapolation beyond its named study population/time.
- Inspect the final diff. Reject any modification under `agents/`, `tools/`,
  `store/`, `state/`, `init.sh`, `harness-install.sh`, `specs/adr/`, or schema
  files by the Builder, or any new runtime parser/automation/config key. Exclude
  normal Orchestrator-owned feature-status/history/telemetry/progress
  bookkeeping from the Builder-scope file check, but reject any schema or
  status-semantics change in that bookkeeping.
