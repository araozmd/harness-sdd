# Deterministic next-task selection — Technical Plan

> Every design decision cites the requirement ids it serves.

## Stack & dependencies
- Node.js 18 or newer, ECMAScript modules, and only `node:fs`,
  `node:path`, `node:url`, and `node:child_process`. `readFileSync(path,
  "utf8")` provides deterministic local reads; no package manifest or third-party
  YAML/CLI library is added. *(serves: R1, R2, R6, R9, R13, R16)*
- POSIX shell remains the permanent fixture-test layer and exercises the tool in
  both source and installed layouts. Python 3 may generate independent JSON
  fixtures/oracle expectations in the test only; production selection remains
  one zero-dependency Node file. *(serves: R15, R16)*

## Ephemeral data model
No persistent model changes are permitted. The selector reads the existing
TaskStore/config/optional manifest and constructs this fixed output envelope:

| Field | Type | Contract | R-id |
|---|---|---|---|
| `schema_version` | integer | Always `1`. | R1, R12, R13 |
| `mode` | enum | `board`, `mine`, or `target`. | R1, R6, R12 |
| `outcome` | enum | `selected`, `blocked`, `complete`, `halted`, or `error`. | R7, R8, R10, R12, R13 |
| `selected` | object/null | `{feature_id,slice_id,kind,status,route}`; `slice_id` is null for feature work. | R3, R10, R12 |
| `reason` | object | `{code,detail}`; selector-level reason, distinct from blocker records. | R8, R10, R12, R13 |
| `blocked` | array | Ordered `{subject,code,detail}` records using E16-F01 codes/text verbatim. | R5–R8, R11 |
| `summary` | string/null | Exact E16-F01 terminal/blocked summary or null for selected/error results. | R7, R8, R11, R12 |

Selector-level reason codes are `feature-actionable`, `slice-actionable`,
`slice-awaiting-merge`, `slice-failed`, `integration-ready`,
`selection-blocked`, `no-candidates`, `target-complete`, `usage-error`,
`input-error`, and `manifest-error`. They do not replace or extend the E16-F01
`blocked[].code` vocabulary. Selected reason detail is exactly
`route <route> for <selected-id> at status <status>`; halted/error detail names
the exact failed subject/input. JSON is serialized once with `JSON.stringify`
and a final newline, with fields inserted in the table order. *(serves: R7–R13)*

## CLI and path resolution

```text
node tools/next-task.mjs [--json] [--mine | --feature <E##-F##>]
                         [--tasks <path>] [--config <path>]
```

- `process.argv.slice(2)` is parsed left-to-right against the closed option set.
  `--json` is an accepted no-op because JSON is the only format. Any duplicate
  option, unknown option, positional token, absent/empty option value, or
  `--mine`+`--feature` combination is a usage error. *(serves: R1, R13)*
- `.claude/commands/sdd-next.md` maps no argument to no selector scope flag,
  maps the exact token `--mine` to `--mine`, and maps one valid positional
  feature id `E##-F##` to `--feature E##-F##`; it never forwards the feature id
  as a selector positional. *(serves: R1, R14)*
- Defaults derive from `dirname(fileURLToPath(import.meta.url))`: parent directory
  is the harness root, so the same code resolves source
  `<repo>/state/tasks.json` and installed
  `<repo>/.harness/state/tasks.json`. Explicit relative override paths resolve
  from the caller's current directory, matching ordinary CLI convention.
  `umbrella.manifest` resolves from the harness root, while child paths inside the
  manifest remain unused by this read-only selector. *(serves: R2, R9)*
- The minimal YAML reader accepts only the scalar keys
  `workflow.require_spec_approval`, `workflow.identity`, and
  `umbrella.manifest`, plus immediate mapping keys below a manifest's `repos:`.
  Quoted or unquoted scalar values and comments follow the repository's existing
  dependency-free reader pattern; malformed duplicate relevant keys, invalid
  booleans, or malformed `repos:` structure fail closed. *(serves: R3, R6, R9,
  R13)*

## Selection algorithm

### Canonical validation and ordering
Flatten exact epic, feature, and slice ids after structural validation. Reject
duplicate exact ids, feature ids whose numeric epic component differs from their
container, and slice ids whose exact prefix differs from their containing feature.
Sort valid ids by integer epic, integer feature, kind (feature before slice),
lexical repository suffix, and finally full literal id. The literal tie-breaker
makes `E1-F01` versus `E01-F1` deterministic without treating them as the same
stored identity; dependencies continue to resolve by exact string. Reuse the
E16-F01 cycle witness algorithm behavior, either by a faithful local
implementation or a small import-free equivalent pinned by differential
fixtures—do not spawn Python at runtime. *(serves: R4, R5, R11, R13, R17)*

### Feature phase
1. Resolve target mode first. A missing targeted feature is `input-error`; an
   existing targeted feature at `done` returns `outcome:"complete"`, reason
   `target-complete`, and summary `target <id> is already done`, without
   considering other candidates. Any other targeted feature is evaluated through
   every ordinary gate but does not fall through to another id, and its blocked
   result contains only that feature's records. Board/mine mode evaluates every
   feature canonically.
2. Exclude `done`. For each unfinished feature, collect ordinary blockers in
   E16-F01 order: same-kind cycle, draft epic, exact dependency blockers, then
   human gate. `pending+sdd:true` is architect-actionable regardless of later
   approval; `pending+sdd:false` needs `autonomous:true`;
   `spec-ready` needs `autonomous:true` only when
   `workflow.require_spec_approval` is true; `in-progress` and `in-review` route
   directly. Missing `autonomous` is false. *(serves: R3, R5, R7)*
3. In mine mode, first distinguish boards with no features or with every feature
   `done`; those return R8 `no-candidates` before identity lookup. Where at least
   one unfinished feature exists, resolve identity before actionability
   selection. Empty is the exact `<empty>` owner-unresolved record. For
   `@me`/`self`, call
   `gh api user --jq .login` with synchronous stdlib process execution and treat
   absence, nonzero, or empty output as the corresponding lookup-failed record.
   Literal identity comparison is exact. Only otherwise actionable candidates
   can receive `owner-excluded`; bare/target modes never inspect ownership.
   *(serves: R6, R7)*
4. Return the lowest actionable feature. When no feature survives, return the
   complete ordered blocker set and summary, or the no-candidates result. This
   is informational and exits zero. *(serves: R4, R7, R8)*

### Mode and terminal precedence

| Priority | Mode | Condition | Result |
|---|---|---|---|
| 1 | all | CLI/read/shape validation failure | nonzero `error` |
| 2 | target | requested id absent | nonzero `input-error` |
| 3 | target | requested feature `done` | zero `complete` / `target-complete` |
| 4 | board/mine | no features or all features `done` | zero `complete` / E16-F01 `no-candidates` |
| 5 | mine | unfinished work exists but identity is unresolved | zero `blocked` / `owner-unresolved` |
| 6 | all | ordinary gates and optional resolved ownership | selected or scoped blocked result |

This prevents irrelevant identity failure from hiding a terminal board and
prevents targeted mode from falling through to unrelated work. *(serves:
R6–R8, R13)*

### Slice phase
Slice selection runs only when all of these hold: the chosen feature has
`slices`, its route would be `builder` from stored status `in-progress`, and a
configured umbrella manifest file exists. Otherwise the chosen feature route is
returned unchanged. In active umbrella mode:

1. If any slice is `failed`, return the lowest failed slice as `halted` with
   reason `slice-failed`; this surfaces the existing fail-stop state and performs
   no fallback dispatch.
2. Else, if any slice is `done` and not merged, return the lowest such slice with
   route `observe-merge`. This resumes the existing advance→observe-merge
   discipline before new dispatch.
3. Else evaluate `pending`, `spec-ready`, `in-progress`, and `in-review` slices
   by exact same-kind dependencies. Every upstream must exist and be
   `done+merged`; pending/spec-ready/in-progress routes to `slice-loop`, while
   in-review routes to `slice-review`. Check the chosen slice's `repo` against
   manifest `repos:` immediately before returning it.
4. If all slices are `done+merged`, return the parent feature with route
   `integration`; the Orchestrator still owns running the configured integration
   command and persisting rollup.
5. If unfinished slices remain but none is selectable, return only their ordered
   E16-F01 cycle/unmet-dependency records and summary. Do not reconsider another
   top-level feature. A `done` but unmerged dependency renders
   `done-but-unmerged`; a `failed` dependency renders `failed`.

*(serves: R9–R12, R17)*

## Error and fallback behavior
- Build the complete result in memory before writing stdout. Successful selected,
  blocked, complete, and halted results exit zero and keep stderr empty. Usage,
  input, and manifest failures emit one versioned error envelope to stdout, one
  concise `next-task: ...` diagnostic to stderr, set `process.exitCode` nonzero,
  and return normally so both streams flush. Never use partial JSON or stack
  traces for expected input failures. *(serves: R1, R7–R13)*
- Update the Orchestrator's selection step to invoke
  `node tools/next-task.mjs --json` plus forwarded `--mine` or target mode. On a
  successful result it follows `selected.route` or reports the returned
  blocked/complete/halted result. If `node` is unavailable, invocation is
  nonzero, or the output cannot be parsed/has an unsupported schema version, it
  reports the condition and applies the still-present prose oracle. It never
  combines a tool choice with a separately derived choice. *(serves: R14)*
- The Orchestrator is Markdown, not an executable adapter. Permanent tests assert
  its invocation, schema-check, trust, and fallback language statically. The
  Reviewer manually checks missing-Node and bad-JSON decisions; no test-only
  runtime adapter is introduced. *(serves: R14, R17)*

## DO NOT TOUCH
- `store/tasks.schema.json` and `state/tasks.json` — no schema, status, or board
  mutation is part of selection.
- `tools/task-diagnostics.py` and `init.sh` — E16-F01's warning helper remains
  stable, and Node does not become an environment prerequisite.
- `specs/adr/0001-deterministic-next-selection.md` — implementation honors the
  accepted decision; it does not revise it.
- `agents/builder.md`, `agents/reviewer.md`, TaskStore writer helpers, telemetry
  schema, board mirror behavior, and umbrella integration/merge implementation.

## Rejected alternatives
- **Keep prose as runtime and add tests around documentation.** Rejected because
  the runtime would still depend on model interpretation and would not satisfy
  ADR-0001.
- **Import a YAML/CLI/graph package.** Rejected because selection only needs three
  known config scalars and manifest repo keys; a dependency would add installation
  and versioning surface without changing outcomes.
- **Make Node or the selector an `init.sh` gate.** Rejected because graceful
  fallback is an explicit compatibility requirement and selection is unrelated
  to structural environment validation.
