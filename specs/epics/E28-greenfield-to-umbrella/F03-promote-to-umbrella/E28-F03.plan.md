# Installer promotion — Technical Plan

> Translates `E28-F03.spec.md` into design. Every decision cites the `R-id`(s) it serves.
> The deliverable is one new umbrella-mode pre-pass in `harness-install.sh` (create missing
> children from the Planner's draft, re-base its `path:` values, seed the live root
> manifest), the documentation for it, and two test surfaces. The child install, manifest
> upsert, discovery and landing audit are **reused unchanged** (R5, R7, R9, R10).

## Stack & dependencies

- Language/framework: the harness's own POSIX `sh` installer (`harness-install.sh`),
  Markdown docs, and the existing `sh` test convention.
- New dependencies: **none**. Zero-dep `sh` + `awk` + `grep` + `git`.
- No new command, config key, status value, interactive prompt, or tool. The only new
  surface is the installer flag `--from-manifest <file>`.

## Data model / interface — draft manifest → live manifest (serves: R2, R3, R4, R5)

Promotion is a **transform**, not a file move. The draft's `path:` base is the draft file's
own directory (the harness dir, `.harness/`, so `../<child>`); the live manifest's base is
the umbrella root (`./<child>`). E28-F02's resolved Q1 flagged exactly this (R3).

| Aspect | Draft (`<umbrella>/.harness/umbrella.manifest.draft.yaml`) | Live (`<umbrella>/umbrella.manifest.yaml`) |
|---|---|---|
| Directory (path base) | the harness dir (`.harness/`) | the umbrella root |
| Top level | `repos:` mapping | `repos:` mapping |
| Entry key | a coordinator-safe logical name `^[a-z0-9-]+$` | the **same** key; must equal the child directory basename (R4) |
| `path:` | `../<key>` (relative to the draft's dir) | `./<key>` (re-based, R3) |
| `init` / `test_command` / `delegate_cmd` | present | carried over verbatim (R3) |
| `scaffold_cmd` | optional, opaque | carried over when present (R3, R6) |
| Header comment | `DRAFT` + inert marker | not copied; the live manifest keeps the documented project-owned shape |

The accepted draft shape is the one E28-F02 ships: a top-level `repos:` line, two-space
entry keys, and four-space `path`/`init`/`test_command`/`delegate_cmd`/`scaffold_cmd`
fields. A parser bounded to that shape is enough; anything else is refused (R2). The live
entry is inserted with a new helper that mirrors `manifest_upsert`'s non-clobber rule
(insert only when the key is absent under `repos:`), because the cascade's
`manifest_upsert` would otherwise write TODO placeholders instead of the draft's fields
(R3, R5).

## Content contract (serves: R1–R11)

The suites grep **pinned anchors**; they are pinned here and shipped by `E28-F03.tasks.md`.
Never assert an anchor not in this list. Anchors are matched **case-insensitively**
(`grep -qi`) so a heading-case edit does not manufacture a false red; the token spelling is
otherwise exact.

### Promotion invocation — `harness-install.sh` usage header + both docs surfaces (R1)

- the literal flag `--from-manifest <file>`, on the usage header, in `docs/UMBRELLA.md` and
  in `docs/INSTALL.md`;
- the draft path `umbrella.manifest.draft.yaml`;
- the phrase `single install` (the promotion is from a single-target install);
- the literal `umbrella mode` (the flag is umbrella-mode only);
- the re-base statement: the sentence naming `re-base` carries `path` and `umbrella root`
  (in `docs/UMBRELLA.md`);
- the local-git statement: the sentence naming `local git` carries `remote` and `owes` (the
  output names the remote work the human still owes);
- the fail-closed statement naming `repos:` and the exact token `fails closed`;
- the key-alignment statement: the sentence naming `key` carries `directory` and
  `promotion requires` — dispatch supports the split, promotion requires the aligned shape
  (the qualification of the existing "both work" sentence);
- the remedy statement: the sentence naming `remedy` carries `rename` and `/sdd-plan`
  (the abort names how to fix the refused shape);
- `scaffold_cmd` named as opaque and run only by promotion;
- the landing-audit statement naming `landing audit` and `3`;
- `--shared-repo` and `--dry-run` named as composing.

### Dry-run preview — printed, writing nothing (R8)

- a header containing `promotion preview`;
- one `would create child:` line per child to be created, naming the child key;
- `would git init` naming the child;
- `would run scaffold_cmd:` naming the child when a non-empty `scaffold_cmd` would run —
  **only for a child that would be created**, mirroring apply, which runs it only inside
  the missing-child branch; a pre-existing child's non-empty `scaffold_cmd` is not previewed;
- `would re-base path:` naming the entry.
- `--dry-run` still exits `0` and writes no directory, no `.git`, no live manifest, no body.

### Scaffold failure warning (R6)

- on **stderr**, one line containing `scaffold_cmd failed`, the child key, and the exit
  status; the run continues and the child still receives `.harness/`.

### Live manifest entry shape (R3, R5)

- top-level `repos:` precedes every entry (ordering is asserted);
- `  <key>:` at two spaces, then `    path: ./<key>`, `    init:`, `    test_command:`,
  `    delegate_cmd:`, and `    scaffold_cmd:` when the draft carried one.

### Promotion helper behavior

- `promotion_read_manifest <file>` — parse the bounded draft shape; on a missing/unreadable
  file, a missing top-level `repos:`, a `repos:` mapping with **zero entries**, or an entry
  with no `path`, print nothing and fail (the caller dies naming the file). It must not read
  the draft as a live manifest.
- `promotion_rebase_path <draft-dir> <umbrella-root> <key> <path>` — resolve `path` against
  `<draft-dir>`, require the result's parent to be `<umbrella-root>` and its basename to
  equal `<key>` and match `^[a-z0-9-]+$`; print `./<key>` or fail. It must never print a
  path that escapes the umbrella. For an **existing** child the parent check is **physical
  as well as lexical**: `<umbrella>/<key>` that is a symlink is resolved (`cd`/`pwd -P`)
  and its resolved parent must be the umbrella root, so a symlink to a git work tree outside
  the umbrella fails closed (the cascade's deliberate symlinked-child support does not
  extend to promotion). A missing child has no physical target and is unaffected.
- `promotion_existing_child <path>` — when the resolved child path already exists, require
  it to be a real directory with a `.git` entry (dir or file); otherwise fail naming the
  path, the reason, and the remedy (`rename` the directory to the key, or re-run
  `/sdd-plan`). A declared child that exists but is not a git work tree would become a
  phantom live entry the cascade never installs (R4). A symlink is refused **explicitly**
  with `-L` before the `-e`/`-d` tests: `-e` follows the link and is false for a dangling
  one, so an `-e`-only check treated a dangling link as missing and the apply phase then
  `mkdir`ed over it after an earlier missing child had already been created — a partial
  promotion, violating the pre-pass/apply fail-before-write split. `-L` is true for a
  dangling link, so the whole plan is refused in the pre-pass; promotion only ever creates
  ordinary real child directories. (The symlink-to-a-work-tree-**outside** case is still
  refused earlier, by `promotion_resolve_child`'s physical parent check, which names the
  draft path.)
- `promotion_seed_manifest <live> <key> <path> <init> <test> <delegate> <scaffold>` —
  ensure `repos:` exists and insert the entry **only when absent** under `repos:`, mirroring
  `manifest_upsert`'s scoping (a same-named key under an unrelated section is not the entry).
  A pre-existing key is preserved verbatim; promotion does not rewrite it (R5).

## Suite design — `tests/test_promote.sh` (serves: R2–R9, R11)

Mirror `tests/test_cascade.sh`'s house style: `#!/bin/sh`, `set -eu`, `SRC` from `$0`, a
suite-scoped `mktemp -d` with `trap 'rm -rf' EXIT`, `fail()` messages naming the
**consequence**, `pass` lines labelled with the R-id, and the env sandbox the sibling
suites use (`CODEX_HOME`, `HARNESS_AGENTS`, `HARNESS_PR_LOOP_ENABLED`) so nothing touches
the developer's real `~/.codex` or `~/.claude`.

Hard requirements the Builder must honour (each maps to an earned lesson in
`progress/lessons.md`):

1. **Positive control before every negative and every ordering claim.** Any "the gate
   refused" is paired with a positive run that succeeds on the same fixture with one fact
   changed; any ordering assertion asserts both anchors are present first. A predicate
   whose middle stage can match nothing is decoration (2026-09-16 lesson).
2. **Structural spans and length floors.** Any extracted span (a docs section, a manifest)
   is bounded structurally, asserted non-empty **and** given a line-count floor — never
   bounded on the line that happens to be last today (2026-09-16 lesson).
3. **No `VERSION` literal.** The bump sync is asserted by `tests/test_codex_native.sh` and
   the Reviewer's mutation, not by a self-grep.
4. **Isolation.** The suite writes only inside its `$T`; it never touches `state/`,
   `specs/`, `progress/`, or the developer's home. Fixtures are temp trees; the live
   `state/tasks.json` is never read or written.
5. **Byte-identity is compared with a floor, not a bare `cmp`.** The "identical to a plain
   cascade" check (R7) asserts the child tree is non-empty first, then diffs it; the
   manifest comparison asserts the entry count first (the vacuous "both extracts empty"
   shape the 2026-09-16 lesson names).
6. **`test_install.sh` owns the single-target/wiring assertions** (R1, R10); the focused
   suite must not duplicate a full single-target regression — it may build installs as
   fixtures, but the wiring contract lives in `test_install.sh`.

### Fixtures

- `build_single <dir>` — `sh "$INSTALL" "$dir"`, then (when git is available) `git init`,
  `git add -A`, commit, so the landing audit has a work tree to verify. Set a local git
  identity for the fixture (`export GIT_AUTHOR_NAME/EMAIL`, `GIT_COMMITTER_NAME/EMAIL`, or
  `git -c user.name=… -c user.email=… commit`) so the commit never depends on the box's
  global config. `git` absence is a **named** suite-level skip for the git-dependent cases,
  never a silent pass.
- `write_draft <file> [scaffold]` — the bounded draft shape with three entries
  (`alpha`/`beta`/`gamma`), each `path: ../<key>`, one with a sentinel-writing
  `scaffold_cmd`, one with `scaffold_cmd: ""` (or absent), one with a failing
  `scaffold_cmd`.
- A failing promotion accepts only `rc=3` for the unlanded audit (R9); the gate tests
  accept only non-zero **and** assert nothing was created/written. `|| true` is never used
  to swallow a real failure.

## Approach notes

- **One source, reused.** The promotion pre-pass lives in the `--umbrella` branch and
  hands the run to the unchanged cascade. The root is converted by the ordinary
  `install_one "$UMB"` the cascade already runs (which preserves project-owned state), so
  R11 needs no new code — only a test that proves it.
- **Ordering is load-bearing.** Validation must precede `install_one "$UMB"` (the first
  write), and the dry-run preview must precede the apply step. The gate tests assert a
  fail-closed run leaves `.harness/` byte-identical to its pre-run snapshot.
- **Re-base exactly once.** Because R4 requires `basename == key`, the live value is always
  `./<key>`; do not carry the draft's `../` prefix into the live manifest (the F02 Q1
  hazard) and do not re-base an entry twice.
- **`git init` is local only.** No remote, no branch, no commit. If `git` is unavailable,
  promotion fails closed naming it — a created directory without `.git` is invisible to the
  cascade's discovery, which is exactly the silent half-install the gates exist to prevent.
- **`scaffold_cmd` runs only on creation.** The apply loop runs it after `mkdir`/`git init`
  for a child it just created; an existing child never triggers it (R6, R7).
- **Promote before a plain cascade.** Promotion seeds the live manifest only for keys that
  are **absent** under `repos:` (R5). If a plain `--umbrella` cascade runs first, it writes
  its own TODO-placeholder entry for every discovered child, and promotion will then
  preserve those placeholders rather than fill in the draft's fields. The documented order
  is therefore: `/sdd-plan` (draft) → promote → bootstrap fills the placeholders. State
  this in the `docs/UMBRELLA.md` promotion section.
- **Sequencing.** T1–T4 (arg parsing, guards, helpers, pre-pass) first; T5 the apply step;
  T6 docs; T7–T8 the suites; T9 the bump + literal sync; T10 verify. Run the new suite
  alone first, then the full gate, then `./init.sh`.
- **Residual risk, stated.** The live manifest is written by `sh`/`awk` over a bounded
  draft shape; the suite pins the shape, the transform, and the non-clobber rule
  mechanically. The Planner's draft is the only producer, and F02's suite pins its shape,
  so the two suites together own both ends of the seam.
