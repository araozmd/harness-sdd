# Installer promotion — Test Contract

> The traceability matrix: every `R-id` in `E28-F03.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any `R-id` lacks a passing test.
>
> **Conventions inherited from the suites this one sits beside** (`tests/test_cascade.sh`,
> `tests/test_install.sh`, `tests/test_umbrella.sh`). Zero dependencies; POSIX `sh` only —
> `tools/run-tests.sh` executes every suite under the strictest shell it can probe, and
> `local` / `[[ ]]` / arrays parse fine under `dash` and fail at runtime; each suite builds
> its fixture under its own `mktemp -d`, exports `CODEX_HOME="$T/codex-home"`, pins
> `HARNESS_AGENTS`/`HARNESS_PR_LOOP_ENABLED`, and never touches `state/`, `specs/`,
> `progress/`, or the developer's home. `fail()` messages state the **consequence**.
>
> **Constants discipline (`progress/lessons.md`).** No test asserts a literal `VERSION`.
> Every string a test greps is a pinned anchor named in `E28-F03.plan.md` §"Content
> contract" and shipped verbatim by `E28-F03.tasks.md`. Any span a test extracts is bounded
> **structurally**, asserted non-empty, and given a **line-count floor** — never bounded on
> a line that happens to be last today.
>
> **Positive controls are mandatory.** Every gate test is paired with a passing run on the
> same fixture with one fact changed; every ordering claim asserts both anchors are present
> first; every "nothing was written" is paired with a successful run that did write, so a
> vacuous predicate cannot pass.

## What each test must assert

### R1 — `test_install.sh::from_manifest_requires_umbrella` / `from_manifest_single_target_rejected`
- `sh "$INSTALL" --from-manifest "$T/draft"` with no target and `sh "$INSTALL" "$T/single"
  --from-manifest "$T/draft"` each exit non-zero and create nothing (snapshot the target).
- `sh "$INSTALL" --from-manifest= --umbrella "$T/single"` (empty value) exits non-zero
  before any write; the same for a `--from-manifest` with no following argument.
- `sh "$INSTALL" --self --from-manifest "$T/draft"` and `--standalone`/`--thin`
  combinations exit non-zero.
- **Positive control:** the same draft with `--umbrella <dir> --from-manifest <file>` is
  accepted (the run starts; it is not a usage error) — asserted by the focused suite.
- A target with no `.harness/.harness-version` is refused non-zero naming the target **only
  when `--from-manifest` is given**. The draft is placed **inside** the non-install target
  (`<target>/.harness/umbrella.manifest.draft.yaml`) with an **aligned** `path: ../<key>`, so
  the existing-install guard is the only gate that can fire — a draft outside the target
  aborts at the later path-resolution gate and masks a deleted guard (2026-09-18 lesson).
  Assert the refusal names the target and the missing existing install, and that no child,
  no live manifest, and no `.harness-version` were written. **Positive control:** a plain
  `sh "$INSTALL" --umbrella <the same non-install dir>` (no `--from-manifest`) still succeeds.
- Composition probes (both in `tests/test_promote.sh` / `tests/test_install.sh`):
  `--shared-repo --from-manifest` git-inits the root, installs the child and records it, and
  `--shared-repo --from-manifest --dry-run` writes nothing; `--print-agents --from-manifest`
  is a usage error that writes nothing (the pre-existing umbrella-mode rejection covers it).

### R1 — `test_promote.sh::test_promotion_docs_contract`
- Extract each surface structurally and assert a **line-count floor** before any anchor:
  the `harness-install.sh` usage header (the comment block at the top of the file), the
  `docs/UMBRELLA.md` `## Promoting a single install to a coordinator` section
  (`^## ` → next `^## `), and the `docs/INSTALL.md` `## Umbrella mode` span (`^## ` → next
  `^## `).
- Anchors are matched **case-insensitively** (`grep -qi`) so a heading-case edit does not
  manufacture a false red; the token spelling is otherwise exact (F12).
- **Per-surface anchor sets, each asserted independently** (the E28-F02 lesson: a subset
  lets a one-surface drop survive):
  - usage header: `--from-manifest`, `umbrella mode`;
  - `docs/UMBRELLA.md` section: `--from-manifest <file>`, `umbrella.manifest.draft.yaml`,
    `single install`, the `re-base` sentence carrying `path` and `umbrella root`, the
    `local git` sentence carrying `remote` and `owes`, the fail-closed sentence carrying
    `repos:` and the exact token `fails closed`, the key-alignment sentence carrying
    `directory` and `promotion requires`, the remedy sentence carrying `rename` and
    `/sdd-plan`, `scaffold_cmd`, the `landing audit` sentence carrying `3`, and
    `--shared-repo`/`--dry-run`;
  - `docs/INSTALL.md`: `--from-manifest <file>`, `umbrella.manifest.draft.yaml`, and a
    pointer to `UMBRELLA.md`.
- Every sentence-scoped assertion is **bounded to the sentence naming its needle** (fold
  the span, split on sentence enders) and paired with the needle's presence as a positive
  control — a whole-span grep would be satisfied by an unrelated sentence (2026-09-17
  lesson).

### R2 — `test_manifest_gates_fail_closed`
- Three fixtures, each a fresh `build_single` target with a draft file that is (a) absent,
  (b) present but comments-only / no `repos:`, (c) present with `repos:` and zero entries.
- For each: the run exits **non-zero**, the output names the manifest path, and the target
  tree is **byte-identical to its pre-run snapshot** (no child dir, no live manifest, no
  `.harness` change) — assert with `diff -r` on `.harness` plus a snapshot of the root
  listing.
- **Positive control:** the valid draft in the same shape runs and creates children, so the
  "refused" claim is not satisfied by every run failing.

### R3 — `test_paths_rebased_to_umbrella_root`
- Run promotion on a valid three-entry draft; assert the live
  `<umbrella>/umbrella.manifest.yaml` exists with a **line-count floor**, a top-level
  `repos:` line, and `  <key>:` for each entry.
- For each entry assert `    path: ./<key>` is present and `path: ../<key>` is **absent**
  from the live manifest (the F02 Q1 re-base regression).
- Assert the live entry carries the draft's `init`, `test_command`, `delegate_cmd` and the
  non-empty `scaffold_cmd` value (not the `TODO` placeholders `manifest_upsert` writes).
  The fixture's `init`/`delegate_cmd` are **non-default** (`./boot.sh` / `./delegate.sh`);
  a fixture equal to the code default cannot distinguish "carried over" from "defaulted"
  (2026-09-18 lesson), so each field is asserted with its distinctive value.
- **Ordering:** assert `repos:` physically precedes the first entry key.

### R4 — `test_path_gates_fail_closed`
- Fixtures, each on a fresh `build_single` target: (a) `path: ../../evil` (escapes the
  umbrella); (b) `path: ../sub/alpha` (not a direct child); (c) key `api-v2` with
  `path: ../api.v2` (basename ≠ key); (c2) key `Alpha` with `path: ../Alpha` (basename ==
  key **but** the key fails `^[a-z0-9-]+$` — so only the grammar arm can refuse it; the
  basename≠key arm must be mutation-tested separately, 2026-09-18 lesson); (d) an entry with
  no `path` key; (e) a declared child directory that **exists but has no `.git`**; (f) a
  declared child path that exists as a **regular file**.
- Each exits non-zero, names the offending path, and creates **nothing** (`evil` absent
  anywhere under `$T`, `sub` absent, `api.v2` and `Alpha` absent, `.harness` unchanged).
- For (c), (c2), (e) and (f) assert the message names the **remedy** (`rename` and
  `/sdd-plan`), so a refusal without a way out is a red.
- **Positive control (F15):** on a **separate** fixture whose single entry is the aligned
  `path: ../<key>`, promotion is accepted and the child appears — the refusal claim is not
  satisfied by every run failing, and the aligned shape is demonstrably accepted.

### R5 — `test_missing_children_created_and_recorded`
- Run promotion on the valid draft; accept `rc=0` or `rc=3` (fresh children are unlanded —
  R9). For each entry assert: the child directory exists, `<child>/.git` exists (local
  git), `<child>/.harness/agents/builder.md` exists (the cascade installed it), and the
  live manifest has `  <key>:` + `    path: ./<key>`.
- **Non-clobber:** pre-seed the live root manifest with `  alpha:` carrying a
  bootstrap-filled `test_command: "keep me"`, run promotion, and assert the field is
  unchanged and the key appears **exactly once** under `repos:`. Precedence is explicit:
  R3's re-based shape governs only entries promotion **inserts**; a pre-existing key is
  preserved verbatim, which is why the documented order is promote **before** a plain
  cascade (R5).
- **Positive control:** the child install genuinely happened (`.harness/.harness-version`
  equals `$SRC/VERSION`), so "created and recorded" is not satisfied by empty directories.

### R6 — `test_scaffold_cmd_best_effort`
- Entry `alpha`'s `scaffold_cmd` writes a sentinel file inside the child; assert it exists
  after promotion (scaffold ran).
- Entry `gamma`'s `scaffold_cmd` exits non-zero; assert the run still installs gamma
  (`.harness` present), and that **stderr alone** (`2>"$ERR"`, `1>/dev/null`) contains a
  line with `scaffold_cmd failed`, `gamma`, and the exit status. **Positive control:** the
  stderr span is non-empty and also contains the command text.
- Assert no child's stdout carries the warning (the stream is named, not just the text —
  2026-09-16 lesson).

### R7 — `test_rerun_idempotent_and_matches_plain_cascade`
- First run creates children; snapshot the live manifest, each child's tree hash, and a
  scaffold append-counter. Re-run promotion on the **uncommitted** tree (R9: no dirty-tree
  refusal); accept `rc=0` or `rc=3`.
- Assert: the live manifest is byte-identical to the snapshot **and** the entry count is
  asserted `≥ 3` first (never a bare `cmp` on possibly-empty extracts); each child tree is
  unchanged; the scaffold counter did **not** increment (scaffold never re-runs).
- **Identical to a plain cascade:** build `$T/plain` with an `alpha` git repo, run
  `sh "$INSTALL" --umbrella "$T/plain"` (no `--from-manifest`), assert the plain child tree
  is non-empty, then `diff -r` `$T/promoted/alpha/.harness` against `$T/plain/alpha/.harness`
  and require no differences.

### R8 — `test_dry_run_writes_nothing`
- On a fresh `build_single` + valid draft, run with `--dry-run`; assert `rc=0`, the output
  contains `promotion preview` and a `would create child:` line naming each key, a
  `would git init` line, a `would run scaffold_cmd:` line for the scaffold entry, and a
  `would re-base path:` line naming an entry (F6).
- Assert nothing was written: no child directory, no `<umbrella>/umbrella.manifest.yaml`,
  and `.harness` byte-identical to the pre-run snapshot.
- **Positive control:** the same fixture without `--dry-run` does create the children and
  the live manifest, so the "writes nothing" claim is discriminating.

### R9 — `test_landing_audit_is_the_gate`
- Run promotion into a git-work-tree target with fresh children; assert `rc=3`, the output
  contains `landing audit`, and the unlanded lines name the coordinator and each fresh
  child. Assert no commit was created: the root's `git rev-parse HEAD` and each child's
  (nonexistent) HEAD are unchanged by the run. **Positive control:** the children and the
  coordinator `.harness/` exist after the run, so "HEAD unchanged" is asserted over a run
  that actually wrote files.
- **Non-git target:** promote into a target whose root is not a work tree; assert the audit
  reports it as not verifiable and does **not** count it as unlanded.
- **No other gate:** run promotion twice without committing in between; the second run must
  not be refused for dirtiness — assert its exit code is in `{0, 3}` (F7). That accepted
  `rc` **is** the kill: a dirty-tree refusal exits outside `{0, 3}`, so no vague
  "refusal string is absent" predicate is used.
- **Positive control:** a promotion into a fully committed target exits `0` (commit the
  coordinator and children first), proving the `3` above is the audit and not a broken run.

### R10 — `test_install.sh::single_install_makes_no_umbrella_artifacts` / `test_promote.sh::test_no_promotion_without_flag`
- Plain single install: no `<target>/umbrella.manifest.yaml`, no
  `<target>/.harness/umbrella.manifest.draft.yaml` written by the installer, no child
  directories.
- **Positive control:** place a valid draft in the target's `.harness/`, run a plain
  `--umbrella <dir>` cascade with **no** `--from-manifest`, and assert no child from the
  draft was created (the draft's presence is not the trigger). The plain cascade **does**
  write its normal `<dir>/umbrella.manifest.yaml` for the children it discovered — that is
  today's behavior and is asserted, not denied.

### R11 — `test_board_and_project_state_preserved`
- Seed sentinels in the single install before promotion: append a unique marker to
  `.harness/state/tasks.json`, `.harness/specs/product.md`, `.harness/progress/history.md`,
  and set a distinctive `verification.test_command` value.
- After promotion, assert each file still contains its marker **and** is byte-identical to
  its pre-run copy (`cmp`), and the config value survived. Assert the root board was not
  replaced by a fresh one (the marker is the proof) and no child gained a promotion-written
  board (a child's `state/tasks.json` is the cascade's normal fresh seed, not the root's).
- **Positive control:** the files existed and were non-empty before the run, so a
  "preserved" claim cannot pass on missing files.
