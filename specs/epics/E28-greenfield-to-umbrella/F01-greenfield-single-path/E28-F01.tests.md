# Greenfield single-repo path — Test Contract

> The traceability matrix: every `R-id` in `E28-F01.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any `R-id` lacks a passing test.
>
> **Conventions inherited from the suites this one sits beside** (read them before writing):
> zero dependencies; POSIX `sh` only — `tools/run-tests.sh` executes every suite under the
> strictest shell it can probe, and `local` / `[[ ]]` / arrays parse fine under `dash` and
> fail at runtime; each suite builds its fixture under its own `mktemp -d` and sandboxes
> `HOME` and `CODEX_HOME`; `fail()` messages state the **consequence**, not just the symptom.
>
> **Constants discipline (`progress/lessons.md`).** No test below asserts a literal `VERSION`.
> Every string a test greps is a pinned anchor named in `E28-F01.plan.md` §"Docs content
> contract" and shipped verbatim by `E28-F01.tasks.md`. Any span a test extracts is bounded
> **structurally** (heading → next `## `; `Next steps:` → blank line), asserted non-empty,
> and given a length floor — never bounded on a line that happens to be last today.

## What each test must assert

### R1 — `test_greenfield_section_documents_sequence`
- Extract the span from the line matching `^## Starting from nothing` to the next `^## ` line
  (exclusive). **Guard:** the span is non-empty and at least 6 lines, or `fail` naming the
  section as stale/moved.
- **Positive control before ordering:** assert every anchor is present — `harness-install.sh`,
  `git init`, `/sdd-plan`, `/sdd-drill`, `/sdd-next`. A missing anchor must `fail` here, not
  silently make the position comparison below pass on an absent token.
- Assert first-occurrence order within the span:
  `harness-install.sh` ≤ `git init` ≤ `/sdd-plan` ≤ `/sdd-drill` ≤ `/sdd-next`.
  (The new section's prose must not mention `/sdd-next`/`/sdd-drill` before the `/sdd-plan`
  step — `plan.md` pins this.)

### R2 — `test_greenfield_section_states_non_git_and_human_git_init`
- Same extracted span. Assert the tokens `empty`, `non-git`, `commit`, and `drift` are present
  (positive shape controls).
- Assert the pinned sentence is present **verbatim** (one `grep -qF`):
  `The installer does not create a git repository.`
  This is the discriminator: without it, a section that tells the reader to install but says
  nothing about who creates the repo passes.

### R3 — `test_one_front_door_story`
- Extract **two** spans: the greenfield span (as R1) and the Bootstrap span from
  `^## Bootstrap \(first run\)` to the next `^## ` line (exclusive). Guard each: non-empty
  and at least 4 lines.
- For **each** span: assert both `/sdd-plan` and `/sdd-next` are present (positive control),
  then assert first `/sdd-plan` < first `/sdd-next`.
- Rationale: today's Bootstrap span contains `/sdd-next` and no `/sdd-plan`, so this reds on
  the unfixed document — that red-to-green is the point, not a side effect.

### R4 — `test_bootstrap_section_reconciled`
- `grep -qF 'docs/INSTALL.md#bootstrap-first-run' README.md` — the anchor **consumer** still
  exists (if README changed the anchor, this is the signal to update the heading text
  deliberately).
- `grep -qF '## Bootstrap (first run)' docs/INSTALL.md` — the heading the anchor resolves to.
- In the Bootstrap span: assert `E00-F01` and `/sdd-next` are present, and that `/sdd-plan`
  occurs before `/sdd-next` (shared with R3; keep the assertions separate so a mutation to
  the `E00-F01` sentence alone reds R4 only).

### R5 — `test_banner_points_at_sdd_plan`
- Capture the fresh install's **stdout** alone (`>"$T/install.out" 2>"$T/install.err"`); the
  contract names stdout, so a `2>&1` capture would pin only half of it (2026-09-16 lesson).
- Extract the block from the line matching `^Next steps:` to the next blank line (or EOF).
  **Guard:** non-empty and at least 2 lines.
- Assert both `/sdd-plan` and `/sdd-next` are present (positive control), then assert first
  `/sdd-plan` < first `/sdd-next`.

### R6 — `test_install_creates_no_git`
- After the install, assert `[ ! -e "$TGT/.git" ]`.
- **Positive control:** assert the target is non-empty and `.harness/.harness-version` exists,
  so "no `.git`" cannot be satisfied by an install that never ran (a failed install leaves the
  empty dir, which trivially has no `.git`).

### R7 — `test_empty_non_git_install_succeeds`
- Before installing, assert all three preconditions: `[ -d "$TGT" ]`,
  `[ -z "$(ls -A "$TGT")" ]`, `[ ! -e "$TGT/.git" ]`. These close the 2026-09-05
  "fixture copied from the repo inherits the artifact under test" false green.
- Install with `sh "$SRC/harness-install.sh" --agents=claude --builder-backend=in-session
  --pr-loop=false "$TGT"` (explicit overrides suppress every pre-existing prompt; stdin is not
  a TTY in the runner) and `fail` on a non-zero exit.
- Assert `.harness/.harness-version` exists afterwards — the install landed in **this** fixture.

### R8 — `test_installed_layout_usable`
- `[ -f "$TGT/AGENTS.md" ]`, `[ -d "$TGT/.harness" ]`, `[ -s "$TGT/.harness/state/tasks.json" ]`.
- The board parses as JSON **and** contains the seeded bootstrap id `E00-F01` (proves the
  seeded board, not some other non-empty file).
- `[ -f "$TGT/.claude/commands/sdd-plan.md" ]` — the selected front-end's `/sdd-plan` command
  artifact (Claude was selected explicitly in R7). Do not assert Codex/OpenCode paths here;
  those are ADR-0003's shared units and a different artifact.

### R9 — `test_init_passes_in_non_git_target`
- Run the installed gate through its own shebang: `( cd "$TGT" && ./.harness/init.sh )` exits
  `0`. Never `sh init.sh` (bash shebang; `sh` is dash on some hosts).
- Assert `[ ! -e "$TGT/.git" ]` at this point too — the case is specifically the non-git
  target, which `init.sh`'s drift guard must skip silently.
- **Execution control:** the captured output contains the harness init banner (e.g.
  `harness-sdd init`), so a zero exit from a file that never ran is not accepted as a pass.

### R10 — `test_version_stamp_reads_source_version`
- `SRC_VER="$(cat "$SRC/VERSION")"`; assert `"$(cat "$TGT/.harness/.harness-version")" = "$SRC_VER"`.
- The suite reads `$SRC/VERSION` at run time; it must not contain the current version as a
  literal. This is **not** proven by an in-suite self-grep for an absent string (the
  2026-09-16 dead-predicate shape — without a positive control such a negative is
  decoration). It is proven by the Reviewer's mutation: bump `VERSION`, re-run the suite, and
  require it still green.

## Falsifiability — mutations this contract must kill

| Mutation | Killed by | Survives (and why that is correct) |
|---|---|---|
| Banner reverted to `/sdd-next` first | R5 | R7–R9 — the install still works |
| `## Starting from nothing` section deleted | R1, R2 | — |
| Section present but `/sdd-plan`/`/sdd-drill`/`/sdd-next` re-ordered | R1 | R5 — the banner is separate |
| Bootstrap section left as-is (no `/sdd-plan`) | R3 (and R4's ordering half) | R1, R2 — the new section is independent |
| Bootstrap heading renamed, breaking the README anchor | R4 | R3 — ordering still holds |
| `E00-F01` sentence deleted while keeping `/sdd-plan` | R4 | R3 |
| Installer made to `git init` the target | R6 | R5, R7–R9 |
| Fixture pointed at a repo copy / emptiness assert dropped | R7's preconditions | R8–R10 — they read the (wrong) fixture and can pass, which is exactly why R7 owns the precondition |
| Install asserted from `2>&1` after the banner moves to stderr | R5 (stdout-only capture) | R7–R9 |
| Version compared against a literal | **survives the suite until `VERSION` is bumped**; killed by the Reviewer's bump mutation (R10 row) | the run at the original version — stated residual, not hidden |

## Behavioral / end-to-end checks (Reviewer)

1. From a scratch empty, non-git directory, run the installer with a stdin that is not a TTY
   (`</dev/null`); confirm exit 0, `.harness/.harness-version` present, and the `Next steps`
   block names `/sdd-plan` first.
2. `( cd scratch && ./.harness/init.sh )` exits 0 and does **not** fail on the non-git tree.
3. Read `docs/INSTALL.md` end to end; confirm there is exactly one front-door order for a new
   product (`/sdd-plan` → `/sdd-drill` → `/sdd-next`) and the Bootstrap section is subordinate
   to it.
4. In the scratch target: `git init`, `git add -A`, commit, re-run `./.harness/init.sh`; confirm
   the drift guard now reports the committed body (the documented payoff of the `git init` step).
5. Bump `VERSION` temporarily and re-run `tests/test_greenfield.sh`; confirm it stays green
   (the R10 no-literal proof), then restore `VERSION`.

## Non-functional checks

- `sh tools/run-tests.sh tests/test_greenfield.sh` green **alone** before the wide run.
- `sh tools/run-tests.sh` green across all suites, under the shell the runner reports.
- `./init.sh` green from the repo root.
- `sh tools/change-size.sh` before the PR hand-off (advisory tier recorded).
- No new interactive prompt: the installer runs with `</dev/null` and does not hang.
- `tests/test_greenfield.sh` is executable (`chmod +x`) — a `#!/bin/sh` suite without it is a
  "Permission denied" the mutation runner would misread as a kill (2026-09-06 lesson).

## Residual — stated, not hidden

- **The docs order assertion is a prose first-occurrence check.** A later re-wrap that moves
  `/sdd-drill` after `/sdd-next` in prose reds R1 even if the numbered steps are correct. That
  is the intended trade: one front-door order is the feature's contract.
- **R10 is not self-proving within a version** — the no-literal half is only falsifiable by a
  `VERSION` bump, which is the Reviewer mutation above.
- **The Bootstrap span reaches to the next `## `**, so it includes the `### /sdd-pr-loop`
  subsection. That subsection must not mention `/sdd-plan`/`/sdd-next` out of order; it does
  not today, and the `plan.md` DO NOT TOUCH list keeps it untouched.
