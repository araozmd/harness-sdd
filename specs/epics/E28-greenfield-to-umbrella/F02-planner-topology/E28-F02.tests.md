# Planner topology output — Test Contract

> The traceability matrix: every `R-id` in `E28-F02.spec.md` maps to a concrete, executable
> test. The Reviewer fails the feature if any `R-id` lacks a passing test.
>
> **Conventions inherited from the suites this one sits beside** (read them before writing):
> zero dependencies; POSIX `sh` only — `tools/run-tests.sh` executes every suite under the
> strictest shell it can probe, and `local` / `[[ ]]` / arrays parse fine under `dash` and
> fail at runtime; each suite builds its fixture under its own `mktemp -d` and never touches
> `state/`, `specs/`, `progress/`, or the developer's `~/.codex`; `fail()` messages state the
> **consequence**, not just the symptom.
>
> **Constants discipline (`progress/lessons.md`).** No test below asserts a literal
> `VERSION`. Every string a test greps is a pinned anchor named in `E28-F02.plan.md`
> §"Docs/platform content contract" and shipped verbatim by `E28-F02.tasks.md`. Any span a
> test extracts is bounded **structurally** (a `## ` heading → the next `## `; the
> `cat > "$CMDDIR/sdd-plan.md"` heredoc → its closing `^EOF$`), asserted non-empty, and
> given a line-count floor — never bounded on a line that happens to be last today.
>
> **Positive controls are mandatory.** Every ordering claim asserts both anchors are
> present first; every negative is paired with a positive shape from the same extraction, so
> a predicate that can match nothing cannot pass as a test.

## What each test must assert

  output` → next `^## `, exclusive). **Guard:** non-empty and at least 8 lines, or `fail`

- **Positive controls:** assert `more than one deployable` and `repo-topology ADR` are
  present in the span.
- Assert the ADR's path/id and allocation anchors, verbatim and all pinned in the plan:
  `specs/adr/`, `ADR-` and `above the max existing ADR number` (no inline emphasis inside
  the pinned phrase). The ADR-index rule (`architecture.md` references each ADR by id) is
  **existing coverage reused**, not re-derived here — the new assertion is the ADR's
  existence/path/allocation.
- R7 additionally asserts the span states the draft path, the inert rule, and the
  single-writer rule — the portable contract carries the whole rule, not a pointer to the
  command.

### R2 — `test_role_and_body_name_the_draft_and_keys`

### R4 — `test_draft_is_inert`

### R5 — `test_draft_header_and_path_base`
- In the role span and the command-body span, assert `DRAFT` and `inert` are stated as the
  draft's header/marker.
- Assert the `path:` base rule: `path` and `own directory` co-occur in the same folded
  sentence (both pinned in the plan's content contract) — naming `path:` without its base
  is the defect that puts child paths under the wrong root.
- **Negative (bounded to the base sentence).** On each of the four surfaces (role, emitted
  body, `.claude/commands/sdd-plan.md`, `.agents/skills/sdd-plan/SKILL.md`), the sentence
  naming `own directory` must carry neither `harness directory` nor `project root`. In an
  installed target the draft lives in the harness directory, so a clause forbidding that
  base ("never relative to the harness directory") requires and forbids the same base and
  resolves `path:` one level off. The positive pair check above cannot see this — both
  tokens survive the contradiction — so this negative is what pins the correction.

### R6 — `test_scaffold_cmd_optional_and_opaque`
- In the role span and the command-body span, assert `scaffold_cmd`, `optional` and
  `opaque` are present (positive controls).
- **Bounded attribution:** isolate the sentence containing `scaffold_cmd` and require that
  sentence to carry `opaque` **and** `F03` (the runner attribution). Split on
  **sentence-ending punctuation followed by whitespace or end** (`[.!?] ` / `[.!?]$`), never
  a bare `.` — the sentence contains dotted tokens (`umbrella.manifest.draft.yaml`,
  `scaffold_cmd`) that a bare-dot split would fragment and turn the check into a false
  negative. Attribution stated positively is falsifiable without a polarity trap: a rewrite
  that has the harness itself run `scaffold_cmd` drops the `opaque`/`F03` pair and reds
  here. Do **not** assert the absence of an execution verb (`runs` / `interprets`): a
  correct sentence contains `interprets` inside the negation, so a token-absence predicate
  is the polarity defect the 2026-09-06 lesson records.
- Emission/execution belongs to E28-F03 only.

### R8 — `test_command_body_matches_role_no_divergence`
- Extract three spans:
  1. the heredoc body in `harness-install.sh` from the line matching
     `cat > "\$CMDDIR/sdd-plan\.md" <<'EOF'` to the next line equal to `EOF`
     (**guard:** non-empty, ≥ 20 lines);
  2. `.claude/commands/sdd-plan.md` (whole file);
  3. `.agents/skills/sdd-plan/SKILL.md` from `^## Canonical workflow` to EOF.
- Assert on **each** span, separately, the pinned step anchors (`more than one deployable`,
  `repo-topology ADR`, `umbrella.manifest.draft.yaml`, `scaffold_cmd`, `does not engage
  umbrella mode`, `specs/adr/`, `ADR-`, `above the max existing ADR number`). A rule present
  in one and missing in another reds the missing surface.
- **Bound the ADR anchors to the topology sentence.** The emitted body carries
  `specs/adr/`/`ADR-`/the allocation phrase in the *earlier generic architecture-ADR step*
  too, so a whole-span token check leaves the topology step's own path/allocation rule
  renameable or deletable. On each surface, isolate the sentence naming
  `more than one deployable` (positive control: it must exist) and require **that** sentence
  to carry `specs/adr/`, `ADR-` and `above the max existing ADR number`. This is what reds a
  renamed ADR path or a dropped allocation clause on the executable body.
- **Positive control on the shared unit:** the `.agents/skills/sdd-plan/SKILL.md` span must
  retain `## Invocation adapter` (the ADR-0003 header), so a blanked or truncated artifact
  cannot pass the anchor checks by being empty.
- **Bound the post-plan handoff.** On each of the four report surfaces — the role's

  `.agents/skills/sdd-plan/SKILL.md` — the sentence naming `artifacts written` must carry
  `umbrella.manifest.draft.yaml`. Each surface is asserted independently, so a divergence on
  one reds there while the others stay green. This closes Reviewer finding 4042832630: the
  report enumerated the vision/architecture/ADRs/epics but omitted the draft, so a user
  following the handoff could commit every listed planning artifact while leaving the
  untracked draft behind, and E28-F03 would find nothing to promote in another checkout.
- **Limit, stated:** this is pinned-anchor presence (including the bounded ADR-step
  attribution above), **not** a byte comparison — a divergence in an *unpinned* prose token
  or in whitespace between the surfaces survives.
- Assert none of the three spans names a host-specific fork of the rule (no `Codex:` /

### Fixture plan run — `test_fixture_plan_run_draft_shape_and_inertness` (R2, R4, R9)
Build `$T/plan/` from the plan's "Fixture plan run": a `specs/architecture.md` naming three
deployables (`bff`, `web`, `api`), a draft manifest at `umbrella.manifest.draft.yaml`
written from the pinned content contract with one entry per deployable, a fixture board and
three fixture configs. **All `umbrella.manifest` values are absolute paths into `$T/plan/`**:
`next-task.mjs` resolves the value against its own source root, not the `--config` file's
directory, so a relative value would silently resolve into the source checkout (F8).
- **Shape — the suite's own parser.** A `repos:` mapping whose keys are exactly the three
  deployables; each entry a mapping with `path`, `init`, `test_command`, `delegate_cmd`;
  `scaffold_cmd` optional. **Guard:** the parse extracts ≥ 3 repos, so an empty/renamed
  `repos:` reds rather than passing on zero. This check is the suite's parser (mirroring
  `tests/test_umbrella.sh` R5), **not** a coordinator claim.
- **Run 1 — config-default inertness (R4):** draft present, `umbrella.manifest: ""` → run
  `node "$SRC/tools/next-task.mjs" --tasks … --config … --json` (the `tests/test_next_task.sh`
  override — no install, no repo created); require exit 0 and no `manifest-error`. The claim
  is **config-default inertness**: the file name is not a switch. It is not a claim of
  general inertness — the config pointer is the switch.
- **Run 2 — coordinator-grammar acceptance (R2/R9):** `umbrella.manifest` points at the
  draft itself → exit 0, `repos:` accepted, no `manifest-error`. This is the run that proves
  the artifact F03 consumes is well-formed under the coordinator's own `manifestRepos()`
  parser; run 1 alone does not.
- **Run 3 — positive control on the switch:** `umbrella.manifest` points at an existing
  manifest that lacks a `repos:` mapping → `manifest-error`, proving the config pointer is
  the switch and the fixture can engage it — without which run 1 proves nothing.

## Residual — stated, not hidden

- **The emission is LLM-driven.** The suite pins the contract wording, the draft format and
  the config-default inertness invariant; it cannot execute the Planner. This is the same
  verification shape `tests/test_sdd_plan.sh` uses for the Planner role.
- **R4's prohibition is prose-token-presence only.** The suite asserts the inert anchors are
  present and that the shipped config default is `""`; it cannot prove no run ever sets the
  key. That is why the single-writer rule and the explicit F03 promotion boundary exist, and
  why `umbrella.manifest.yaml` can only be asserted as a token co-occurring with
  `never`/`not` (it is a negative statement, not an absence).
- **R8 pins the pinned anchors, including a bounded ADR-step attribution — not byte
  identity.** On each surface the topology sentence (the one naming `more than one
  deployable`) must carry `specs/adr/`, `ADR-` and `above the max existing ADR number`, so a
  renamed ADR path or a dropped allocation clause on the executable body reds. It does
  **not** prove the three surfaces are byte-identical: a divergence in an unpinned prose
  token or in whitespace between them survives.
- **The `path:`-base assertion is a prose pair check plus a bounded negative.** A later
  re-wrap that separates `path` from its base sentence reds R5 even if the meaning is
  unchanged — the intended trade, and the plan keeps both tokens on one line. The negative
  forbids `harness directory`/`project root` only in the sentence naming `own directory`; it
  cannot prove the emitted draft honours the base at write time (the emission is
  LLM-driven, as below).
- **`/sdd-drill`'s absence of a manifest contract is an absence check.** It is paired with
  the Planner-side positive statement so it cannot pass vacuously; a future Driller feature
  that legitimately adds one must update R10 deliberately.
- **F03 must re-base each `path:`.** The draft's base is `.harness/` (`../<child>`); a live
  manifest at the umbrella root uses `./<child>`. The suite cannot check F03's transform
  (out of scope); it is recorded here and in the plan's F03 hand-off note.
