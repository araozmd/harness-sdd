# Planner topology output — Technical Plan

> Translates `E28-F02.spec.md` into design. Every decision cites the `R-id`(s) it serves.
> The deliverable is one rule added to the portable Planner contract and the generated
> `/sdd-plan` body, an additive manifest key, and one new test suite. No installer behavior,
> no repo creation, no promotion (F03).

## Stack & dependencies

- Language/framework: the harness's own POSIX `sh` test convention, Markdown role/docs, the
  existing `harness-install.sh` shell installer, and `python3` (already required by the
  local TaskStore) for the fixture's manifest parse.
- New dependencies: **none**. Zero-dep `sh` + `grep` + `python3`.
- No new command, flag, config key, interactive prompt, status value, or tool.

## Data model / interface — the draft manifest (serves: R2, R5, R6)

The draft is a file, not a schema change. Its path and shape are the contract:

| Aspect | Contract |
|---|---|
| Path | `umbrella.manifest.draft.yaml` in the harness dir (installed: `.harness/umbrella.manifest.draft.yaml`). Never `umbrella.manifest.yaml` (R4) |
| Header | a comment marking the file a **DRAFT** and stating it is **inert** (R5) |
| Top level | `repos:` — a mapping, one entry per deployable (R2) |
| Entry key | a coordinator-safe logical name matching `[a-z0-9-]+` (the slice-id suffix grammar: `store/tasks.schema.json`'s `^E[0-9]+-F[0-9]+@[a-z0-9-]+$` and `tools/next-task.mjs`'s `SLICE_RE`, so `slices[].repo` can equal it); the actual directory/repo name goes in `path` (`api.v2` ⇒ key `api-v2`, `path: ../api.v2`) — `tools/next-task.mjs`'s `manifestRepos()` rejects a dotted key as `malformed repos entry`, and this feature does **not** change the parser. Keys are **unique after normalization**: two names can normalize to one key (`api.v2` and `api-v2` both yield `api-v2`), and `manifestRepos()` rejects duplicate repository keys, so the Planner allocates keys in the architecture's naming order while probing the **complete set** already assigned — take the normalized name if unused, otherwise append `-2`, `-3`, … and take the smallest suffix whose candidate is unused (`api`, `api!`, `api-2` ⇒ `api`, `api-2`, `api-2-2`) |
| Entry fields | `path` (relative to the draft's own dir — the child sibling), `init`, `test_command`, `delegate_cmd` (empty), optional `scaffold_cmd` (R2, R5, R6) |
| Switch | **not** a switch: engagement requires `umbrella.manifest` in `harness.config.yaml` to point at an existing manifest (R4) |

The four-key/entry-field check in the suite is the **suite's own parser** (mirroring
`tests/test_umbrella.sh` R5), not a claim about coordinator acceptance. The
**coordinator-grammar acceptance proof** is the fixture run below that points
`umbrella.manifest` at the draft itself and requires a clean parse (`repos:` accepted, exit
0) — that is what F03 will consume, so it is the run that matters.

`tools/next-task.mjs` resolves the `umbrella.manifest` value against its **own source root**
(`resolve(HARNESS, config.manifest)`), not against the `--config` file's directory. The
fixture must therefore set `umbrella.manifest` to an **absolute path** into `$T/plan/`, or
the pointer silently resolves into the source checkout.

## Docs/platform content contract (serves: R1–R10)

### Topology step — must appear in `agents/planner.md` AND the emitted `/sdd-plan` body

The same step text, modulo the `.harness/` prefix the installer adds. It must contain, in
one section/step:

- the trigger phrase `more than one deployable`;
- `repo-topology ADR`;
- the ADR path/id anchors `specs/adr/` and `ADR-`, and the allocation phrase
  `above the max existing ADR number` shipped verbatim (no inline emphasis inside the
  pinned phrase, or the grep misses it);
- `umbrella.manifest.draft.yaml`;
- the no-op phrase `exactly one deployable`, with the no-op sentence naming **both**
  artifacts (`repo-topology ADR` **and** `umbrella.manifest.draft.yaml`);
- `umbrella.manifest` (the config key), the inert statement `does not engage umbrella mode`,
  and the literal `umbrella.manifest.yaml` (the never-write target, R4);
- `DRAFT` and `inert` (the draft's header/marker rule);
- `path` and `own directory` (the `path:` base rule, both tokens on one line); the base
  sentence states **only** that base — no `harness directory`/`project root` clause, since
  in an installed target the draft's own directory *is* the harness directory (R5's bounded
  negative);
- `scaffold_cmd`, `optional`, `opaque`, and the runner attribution `F03` (the sentence
  containing `scaffold_cmd` must carry `opaque` and `F03`);
- the single-writer statement naming `/sdd-drill` and `amend`, plus the re-plan clause
  `a topology change is a /sdd-plan amend` (asserted as its own phrase, since the
  `/sdd-drill` sentence's `amends` would otherwise satisfy a bare `amend`);
- the coordinator-safe key rule (R2): the sentence naming `logical name` must carry
  `[a-z0-9-]+` (the slice-id suffix grammar), the worked example `api-v2`, `directory` and
  `path`, on **every** surface the step lives on (role,
  emitted body, `.claude/commands`, `.agents/skills`) — a dotted key is a
  `malformed repos entry`, so a hand-edit dropping the rule on the executable body alone
  must red;
- the collision-safe key rule (R2): the sentence naming `unique` must carry
  `normalizing`, `collide`, `-2`, `-3`, `order` and `manifestRepos` **plus** the
  full-set-probe anchors `complete set`, `already assigned` and the resolved example
  `api!` ⇒ `api-2-2` (`api`, `api!`, `api-2` allocate `api`, `api-2`, `api-2-2`), on
  **every** surface the key rule lives on — two names that normalize to one key are
  disambiguated deterministically (`-2`, `-3`, …) by probing the complete set of already
  assigned keys until the candidate is unused, because `manifestRepos()` rejects duplicate
  repository keys; `-3` is pinned alongside `-2` because the worked example `api-2-2`
  contains `-2`, and `api!`/`api-2-2` are reachable only through the full-set probe;
- the append-only amend mechanics (R11): the sentence naming `topology change` must carry
  `/sdd-plan`, `amend`, `append-only` and `reconciles the draft`; the sentence naming
  `## Repo topology` must carry `append-only`, `dated`, `delta`, `specs/architecture.md`
  and `ADR`; the sentence naming `complete replacement snapshot` must carry `full`,
  `superseded`, `latest delta` and `original` (the latest delta names the full effective
  set and earlier deltas are superseded); the sentence naming `rename` must carry `add`,
  `remove`, `naming`, `removes` and `frontend` (add/remove/rename are all expressible by
  naming the resulting set); the sentence naming `effective set` must carry `trigger`,
  `one deployable`, `removes`, `umbrella.manifest.draft.yaml` and `reconciles` (when the
  effective set falls to one deployable or none the derived draft is removed while the
  committed repo-topology ADRs are preserved); and the sentence naming `collapse` must
  carry `always`, `appends`, `repo-topology ADR`, `removal` and `one deployable` (every
  set-changing amend always appends the ADR, including a collapse, so the ADR rule and the
  draft-removal rule agree). No sentence naming `collapse` or `effective set` may carry
  `writes no new` (the old contradiction).

Pinned for the R8 positive control only: the `.agents/skills/sdd-plan/SKILL.md` span must

## Suite design — `tests/test_planner_topology.sh` (serves: R1–R10)

Structure mirrors `tests/test_sdd_plan.sh` / `tests/test_greenfield.sh`: `#!/bin/sh`,
`set -eu`, `SRC` resolved from `$0`, a suite-scoped `mktemp -d` with `trap 'rm -rf' EXIT`,
`fail()` messages naming the **consequence**, `pass` lines labelled with the R-id.

Hard requirements the Builder must honour (each maps to an earned lesson in
`progress/lessons.md`):

1. **Positive control before every negative and every ordering claim.** Any ordering
   assertion asserts both anchors are present first; any "does not name X" is paired with a
   positive shape the same extraction carries. A predicate whose middle stage can match
   nothing is decoration (2026-09-16 lesson).
2. **Structural spans, not line anchors.** Extract the new section from
   `agents/planner.md` (`^## Repo topology output` → next `^## `), the command heredoc in
   `harness-install.sh` (from `cat > "$CMDDIR/sdd-plan.md" <<'EOF'` to the next `^EOF$`),
   and the `docs/UMBRELLA.md` Manifest-reference span (heading → next `^## `). Guard each:
   non-empty **and** a line-count floor — never bound on the line that happens to be last
   today (2026-09-16 lesson).
3. **No `VERSION` literal.** Do not freeze the version; the bump sync is asserted by
   `tests/test_codex_native.sh` and the Reviewer's mutation, not by a self-grep.
4. **Isolation.** The suite writes only inside its `$T`; it never touches `state/`,
   `specs/`, `progress/`, or the developer's `~/.codex`. The fixture board/config are temp
   files, never the live `state/tasks.json` (the fixture-inherits-the-artifact lesson).
5. **The fixture plan run is install-free.** Use `tools/next-task.mjs`'s existing
   `--tasks`/`--config` override (see `tests/test_next_task.sh`) against a temp fixture, so
   this feature runs no installer (boundary) and creates no repo/dir.

## Fixture plan run (serves: R2, R3, R4, R5, R6)

A temp `$T/plan` represents what a `/sdd-plan` run leaves on disk:

```
$T/plan/
  specs/architecture.md          # names 3 deployables (bff, web, api.v2)
  umbrella.manifest.draft.yaml   # written from the content contract above
  state/tasks.json               # fixture board
  harness.config.yaml            # workflow.require_spec_approval: true; umbrella.manifest: ""
```

Three runs, each with a distinct claim (all via the install-free
`next-task.mjs --tasks/--config` override; values are **absolute paths** into `$T/plan/` —
the selector resolves them against its own source root, F8):

1. **Config-default inertness (R4).** Draft present, `umbrella.manifest: ""` → the selector
   stays single-repo (exit 0, no `manifest-error`). This pins that the *file name* is not a
   switch; it is **not** a claim of general inertness — the config pointer is.
2. **Coordinator-grammar acceptance (R2/R9).** `umbrella.manifest` points at the draft
   itself → exit 0, `repos:` accepted, no `manifest-error`. This is the run that proves the
   artifact F03 consumes is well-formed under the coordinator's own `manifestRepos()`
   parser. (The suite's four-key/field check is its own parser, not this proof.)
3. **Positive control on the switch.** `umbrella.manifest` points at an existing manifest
   lacking a `repos:` mapping → `manifest-error`, proving the config pointer is the switch
   and the fixture can engage it — without which run 1 proves nothing.

With no more than one deployable, the same fixture writes neither artifact (R3).

## Approach notes

- **One source, three surfaces.** The durable installed body is the `harness-install.sh`
  heredoc; `.claude/commands/sdd-plan.md` and `.agents/skills/sdd-plan/SKILL.md` are
  source-mode outputs (`self_install` runs `install_one` into a temp dir, applies
  `self_transform` which strips `.harness/`, and reconciles them). Edit the role file and
  the heredoc, then reconcile the glue with
  `./harness-install.sh --self --agents=claude,codex`. **The selection must be
  claimant-preserving:** the shared skill unit is gated on `{codex, opencode}` (ADR-0003)
  and `self_reconcile` deletes manifest-owned paths this run does not regenerate, so
  `--agents=claude` alone removes the committed Codex/OpenCode glue and R8 can never pass.
  R8's anti-divergence assertion is what makes a hand-edit to one surface fail.
- **Hand-off to F03 — re-base the `path:` values.** The draft's base is the harness dir
  (`.harness/`, so `path: ../<child>`); a live manifest at the umbrella root uses
  `path: ./<child>`. Promotion must transform each `path:`, not merely move the file, or
  every child resolves one level off.
- **R8 pins the pinned anchors, including a bounded ADR-step attribution — not bytes.** Each
  surface's topology sentence naming `more than one deployable` must carry `specs/adr/`,
  `ADR-` and `above the max existing ADR number`, so a renamed ADR path or a dropped
  allocation clause on the executable body reds (a whole-span check would not: the emitted
  body carries those tokens in the earlier generic architecture-ADR step too). It does not
  prove the three surfaces are byte-identical.
- **Numbering in the command body is the Builder's.** Insert the topology step after the
  architecture/ADR write and renumber consistently, or add it as a sub-step — the suite
  asserts the step's anchors, not its number.
- **The trigger's judgment stays with the Planner.** Only the non-guessable facts are
  pinned (file name, keys, the `DRAFT`/inert rule, and that >1 deployable is the trigger);
  do not add prose instructing how to decide whether a component is a deployable.
- **Sequencing.** T1–T2 (role + command body) first; T3 reconcile the glue; T4–T5 (example +
  UMBRELLA reference); T6 the suite last, once the anchors it greps are on disk; T7 the
  bump + literal sync; T8–T9 verify. Run the new suite **alone** first, then the full gate.
- **Residual risk, stated.** This is a prose contract: the emission itself is
  LLM-driven, so the suite pins the contract wording and the draft format, and proves the
  inertness invariant mechanically. That is the same verification shape the Planner feature
  (E06-F02, `tests/test_sdd_plan.sh`) has always used.
