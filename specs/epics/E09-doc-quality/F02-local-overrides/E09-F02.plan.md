# Per-developer local-overrides convention — Technical Plan

> Translates the .spec.md intent into design. Every decision cites the R-id(s) it serves. This feature changes installer-generated prompt surfaces, documentation, tests, and version metadata only.

## Stack & dependencies
- Language/framework: POSIX shell installer (`harness-install.sh`), Markdown docs/specs, shell-based installer tests (`tests/test_install.sh`).
- New dependencies: none.
- Runtime behavior: no new daemon, loader, parser, command, schema, or TaskStore state.

## Data model  (serves: R1–R16)
**No schema change.** This feature introduces no new persisted data model. The convention is represented by generated Markdown guidance and gitignored optional files at the repository root.

| Entity | Field | Type | Notes |
|---|---|---|---|
| Local prompt file | `AGENTS.local.md` | Markdown file path | Portable repo-local personal prompt convention; optional and gitignored. |
| Local prompt file | `CLAUDE.local.md` | Markdown file path | Claude Code native/local personal prompt file; optional and gitignored. |
| Local prompt file | `AGENTS.override.md` | Markdown file path | Codex native override file; optional and gitignored. |

## Approach notes
- Keep the entrypoint guidance short and tool-agnostic. It should say to read `AGENTS.local.md` only if present, and that committed instructions win on conflicts.
- Do not hard-code behavior that assumes every CLI loads local files the same way. Use the generated marker block for the portable convention and docs for native files.
- Reuse the existing root `.gitignore` seeding block in `harness-install.sh`; this is the required append-only/idempotent mechanism already covered by installer tests.
- The test assertions should check stable phrases or file names, not the entire generated marker block, so future wording changes remain possible while preserving the contract.
- `VERSION` should be bumped once by MINOR according to the repository's installed-body policy; tests should not freeze the exact pre-change value.

## Risks
- **Precedence confusion.** Mitigation: generated marker blocks and docs both state that committed instructions win on conflict.
- **Over-engineering a loader.** Mitigation: the plan explicitly forbids a new loader/parser and leans on optional files plus native CLI support.
- **Gitignore duplication.** Mitigation: reuse the existing append-only loop and extend existing idempotence tests.
- **Tool-specific drift.** Mitigation: docs distinguish portable `AGENTS.local.md` from native `CLAUDE.local.md` and `AGENTS.override.md`.
