# Per-developer local-overrides convention — Functional Spec

## Context
Developers sometimes need personal, uncommitted prompt instructions for the harness: local house rules, preferred tone, debug notes, or shortcuts that should not become shared project facts. The harness already documents project, personal, and user-global configuration layers, but the personal layer currently covers local settings/runtime files rather than prompt instructions. This feature establishes a thin, portable convention for local prompt overrides that can be gitignored and read on top of committed entrypoints without inventing a new loader.

## Business rules
- **Committed entrypoints remain the source of shared truth.** `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, and `.harness/AGENTS.md` continue to carry instructions that are true for everyone.
- **Local prompt files are personal and uncommitted.** Personal override files are ignored by the installer-seeded root `.gitignore` and must not be committed by default.
- **Native mechanisms are preferred.** Where a CLI already supports a native local prompt file, the harness documents and ignores that file rather than implementing a loader.
- **Portable convention is additive.** The shared entrypoint marker blocks may conditionally tell agents to read a local override file when one exists, but no behavior changes when the file is absent.
- **Committed instructions win on conflict.** Local prompt files add personal guidance; they must not override project facts, workflow rules, status gates, or safety constraints in committed instructions.
- **Installer seeding is append-only and idempotent.** Existing `.gitignore` content must survive installs/upgrades, and seeded ignore entries must not be duplicated.
- **Installed-body change requires versioning.** Because this changes generated entrypoint bodies, installer behavior, docs, and tests, it ships with one SemVer MINOR `VERSION` bump and a matching `CHANGELOG.md` entry.

## Acceptance criteria (EARS)
> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md.

- **R1** — When the installer writes or refreshes a harness-managed entrypoint marker block for `AGENTS.md`, `CLAUDE.md`, or `GEMINI.md`, the marker block shall include conditional guidance to read a repo-local personal prompt file when the file exists.
- **R2** — The installer shall preserve existing non-harness prose outside the managed marker block when adding the local-override guidance to entrypoint files.
- **R3** — The local-override guidance shall state that committed project instructions remain authoritative when local personal instructions conflict with committed instructions.
- **R4** — The local-override guidance shall name `AGENTS.local.md` as the portable repo-local personal prompt convention for tools that do not provide a better native local file.
- **R5** — The documentation shall describe the native local prompt files the harness supports as personal-layer files, including `CLAUDE.local.md` for Claude Code and `AGENTS.override.md` for Codex.
- **R6** — When the installer seeds the project-root `.gitignore`, the installer shall append ignore entries for `AGENTS.local.md`, `CLAUDE.local.md`, and `AGENTS.override.md` using the existing append-only seeding logic.
- **R7** — If the project-root `.gitignore` already contains one of the local prompt ignore entries, then the installer shall not duplicate that entry on install or upgrade.
- **R8** — If a project-root `.gitignore` contains user-authored entries, then the installer shall preserve those entries while adding any missing local prompt ignore entries.
- **R9** — `docs/CONFIG-LAYERING.md` shall document the personal prompt layer alongside the existing personal settings/runtime layer, including that local prompt files are gitignored and additive.
- **R10** — `docs/CONFIG-LAYERING.md` shall document per-tool caveats for the convention: local files do not automatically follow fresh worktrees unless recreated or linked from a user-global location, and tool-native local-file support differs by CLI.
- **R11** — `umbrella.gitignore.example` shall include the same personal prompt ignore entries when those files can exist at an umbrella/shared-spec repository root.
- **R12** — `tests/test_install.sh` shall assert that a fresh install seeds the project-root `.gitignore` with the personal prompt ignore entries.
- **R13** — `tests/test_install.sh` shall assert that a repeated install or upgrade keeps the personal prompt ignore entries idempotent and preserves user-authored `.gitignore` content.
- **R14** — `tests/test_install.sh` shall assert that generated entrypoint marker blocks include the conditional local-override guidance.
- **R15** — The repository shall record this installed-body change as one SemVer MINOR `VERSION` bump with a matching `CHANGELOG.md` entry.
- **R16** — If no local prompt override file exists in a repository, then the generated entrypoint guidance shall not require any additional file to be present for the harness to operate.

## Out of scope
- Implementing a new runtime loader or parser for local prompt files.
- Changing `state/tasks.json`, TaskStore schema, task statuses, or human gates.
- Changing personal settings behavior for `.claude/settings.local.json`.
- Making local prompt files committed, synchronized, or copied between worktrees.
- Supporting every editor or agent-specific rule system beyond documenting caveats for known native/local files.
- Changing precedence semantics beyond documenting that committed project instructions win on genuine conflicts.

## Open questions
- None for implementation. The spec resolves the brief's open questions as follows: use `AGENTS.local.md` as the portable convention, also ignore native `CLAUDE.local.md` and `AGENTS.override.md`, document precedence explicitly, include worktree/tool-native caveats in `docs/CONFIG-LAYERING.md`, and include the same ignore entries in `umbrella.gitignore.example`.
