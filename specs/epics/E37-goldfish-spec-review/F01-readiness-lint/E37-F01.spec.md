# Implementation-readiness lint: every path and symbol a plan/tasks file names must resolve — Functional Spec

> R-ids in this document are `R1 … R12`; their fully-qualified form is `E37-F01:R1 … E37-F01:R12`.

## Context

The Builder receives only the four spec files, in a clean context. When the `.plan.md`'s
`## Files to change` table or the `.tasks.md` task list names a file, a function or a test
suite that does not exist — a typo, a renamed tool, a path copied from another repo — the
Builder either invents it or stalls, and the defect surfaces as a Reviewer rejection or a
Codex review round instead of at `spec-ready`. `tools/plan-cite-check.py` (E36-F04) already
lints the plan's tables, but only for `R-id` / `ADR` citations: a row may cite correctly and
still name a file that does not exist. This feature is the deterministic half of the epic's
EGM comparison — "does every named path and symbol resolve?" — shipped as **code, not
prose** (`docs/RATIONALE.md` principle 1), fail-closed like its two sibling lints.

The mechanism is `tools/readiness-check.py`: a **new**, stdlib-only Python tool, a pure
function of the feature's spec files and the repository tree. It is a new file rather than a
`--readiness` mode on `plan-cite-check.py`, as the brief leans: plan-cite-check's contract is
byte-pinned (`tests/test_install.sh` compares source and installed copies with `cmp`, and
`tests/test_plan_cite.sh` pins its every output line), so a mode would widen a frozen
surface for no gain. It **reuses plan-cite-check's fence-blind, section-scoped table
grammar by the same deliberate-second-copy convention** that tool documents for
`iter_unfenced()` and `grandfather()`: the functions are copied, not imported. Importing
would couple two tools that install and run independently — the installer copies `tools/`
wholesale, but a tool that imports its sibling breaks when either is pinned, moved or
removed, and a consumer may legitimately delete one (E36-F04's recorded decision). The
copies are **parity-tested**: the fence corpus against `tests/lib/fence.awk`, and the parsed
`## Files to change` rows against `plan-cite-check.parse_sections()` on the plan-cite
positive fixture. The grandfather rule is the same deliberate copy keyed on **this** tool's
own paths — keying on plan-cite-check's merge (2026-10-27) would reject every plan authored
since it and before this tool lands.

The users are the Architect (pre-hand-off step, exit 0 required), the Reviewer (a numbered
check beside check 8, same grandfather posture), the doc-critic (reports the tool's lines at
the `feature-spec` checkpoint) and the human at the gate who today eyeballs paths. The
tool's posture is **precision over recall**: an unrecognised token is ignored, never
flagged; a flagged reference is one the Builder would certainly fail to find.

Three items here go beyond the inbox brief's in-scope list and are intentional, directed by
the Orchestrator's spec task for this feature: a one-paragraph note in `docs/WORKFLOW.md`, a
sentence in `README.md` where the Reviewer's checks are described, and a `--root <dir>` flag
(the suite needs it to lint a fixture repo that has no `.git`; every role invocation omits
it). The brief's "run from any cwd and in an installed target" is met by root discovery, not
by the flag.

**Complexity basis.** `complex`, on three stated signals from `agents/architect.md`:

- the spec sits exactly at `change_size.max_requirements` (12 of 12). The seam I would
  split on — tool + suite + installer first, gate prose + docs second — would ship a lint
  nothing runs, or a Reviewer check naming a tool that does not exist; the same reasoning
  E36-F04 recorded, so it is not split;
- the tool carries a **deliberate copy** of another tool's grammar (section bounds, table
  rows, fence rule) — a body and its copy diverging is a defect class the harness has paid
  for (lessons 2026-09-05, 2026-09-16), so each copy is parity-tested, not trusted;
- the gate reaches `tools/`, `init.sh`, `agents/architect.md`, `agents/reviewer.md`,
  `agents/doc-critic.md`, four docs, the installer, its test, the deletion ledger and the
  version.

## Business rules

- **Scope of the scan — three files, three unit kinds.** Given a feature directory (or its
  `.plan.md`), the tool reads `<stem>.plan.md` and, when present, `<stem>.tasks.md` and
  `<stem>.tests.md`. It scans (a) every **data row** of every table under the plan's
  `## Files to change` heading — section bounds, table runs, header/separator detection and
  cell splitting read exactly as plan-cite-check reads them; in a row, **path references are
  read from the first cell only** (the template's `path/to/file` cell), while the two symbol
  forms are read from every cell; (b) every **list item** of the
  `.tasks.md` (a line starting with `- ` after optional indentation, plus its continuation
  lines indented by at least two spaces, up to a blank line or a non-continuation line); and
  (c) every **table data row** and every **list item** of the `.tests.md`. Prose
  paragraphs, blockquotes and headings are never scanned; fenced code is invisible
  (CommonMark rule, `tests/lib/fence.awk`). The `.spec.md` is never scanned.
- **What is a reference.** A reference is the text of a single-backtick span with no
  whitespace. After stripping a `::<name>` suffix (a test reference — only the file part is
  checked), a trailing `:<digits>` or `:<digits>-<digits>` (a line reference), and a
  trailing `:<identifier>` (the **symbol form**, below), the remainder is a **path
  candidate** when it contains a `/` or its last segment has a dotted extension
  (`\.[A-Za-z0-9]{1,5}$`). A candidate is **ignored** — never flagged — when it contains
  any of `< > * ? [ ] { } $ ~ |`, the ellipsis `…` or `://`; starts with `/` or `-`; is a
  bare extension (`^\.[A-Za-z0-9.]+$` — `.py`, `.plan.md`, `.mutbak`); starts with
  `scratchpad/` or `progress/` (roles write there at run time); or contains a `/` whose
  **first segment is not a known root** — a known root is an existing directory at the root
  (or under `.harness/`), or the first segment of a path the plan creates — so `origin/main`,
  `feat/E37-F01-x` and a fixture-internal path are not references. A candidate with **no**
  `/` (a bare basename such as `init.sh`, `fence.awk`) is a reference in a `## Files to
  change` first cell (that cell is a path by the template's contract) but, in a `.tasks.md` /
  `.tests.md` unit, is ignored when it exists at neither the root nor the feature directory
  (a basename in prose may name a file anywhere; v1 does not search the tree). A leading
  `./` is stripped. A trailing `/` means the reference is a directory. **House convention:**
  a path that is not in this repository (a fixture-internal path, a consumer's file) is
  written with a placeholder prefix (`<repo>/tools/x.py`) or inside fenced code — the tool
  cannot tell a fixture path from a typo, and this spec's own tasks and tests follow it.
- **Resolution — the root, the two layouts, the created set.** The **root** is `--root`
  when given, else the nearest ancestor of the plan's directory that contains `.git` (a
  directory or a file — a linked worktree has a file); none ⇒ exit 2. A reference
  **resolves** when, in this order: it is in the **created set** or under a directory in it;
  it exists relative to the root; it starts with `.harness/` and the remainder exists at the
  root, or it does not and `.harness/<path>` exists (the source and installed layouts are
  both tried); or it has no `/` and exists in the feature directory (the four spec files name
  each other by bare filename). The **created set** is every path candidate in the first
  cell of a `## Files to change` data row whose Change cell's first word (after stripping
  `*`, `` ` ``, `"`, `'`), case-insensitively, is `create` — the plan template's vocabulary
  (`<create / modify: what>`). A reference that does not resolve is
  `unresolved-path <file>:<line> <path>`.
- **Exemptions, by declaration.** A creating row's first-cell paths are not checked (they
  are the declaration). A `.tasks.md` / `.tests.md` unit whose text matches
  `(?i)(?<![A-Za-z0-9_])creat(e|es|ed|ing)(?![A-Za-z0-9_])` — the word `create` in any
  inflection, not adjacent to a letter, digit or underscore (`recreate` and `created_x` are
  not exemptions) — is exempt from path and symbol checks for the **whole unit** (the
  Builder is being told to make the thing; a unit-wide exemption is the deliberate reading,
  because a task that creates one file routinely names its siblings on the same lines). A
  row whose Change cell's first word is `add` still has its path checked (you add *to* a file
  that exists) but is exempt from symbol checks, as is a creating row; the word `create`
  later in an `add`/`modify` cell does not make the row creating.
- **Symbols, minimal in v1.** Two forms. (1) A backticked `name()` — an identifier
  `[A-Za-z_][A-Za-z0-9_]*` followed by exactly `()` — inside a `## Files to change` data row
  whose first cell holds **exactly one** path candidate that resolves to an existing regular
  file and whose Change cell is neither `create` nor `add`: the name (read from any cell of
  the row) must occur in that file as a whole word (`(?<![A-Za-z0-9_])name(?![A-Za-z0-9_])`).
  A call with arguments (`fence_delim($0)`) is not a symbol. (2) The **symbol form**
  `path:name` in any cell of a plan row or anywhere in a tasks/tests unit: when the path
  resolves to an existing regular file that is not in the created set, the name must occur
  there as a whole word; when the path does not resolve, the form yields no symbol finding
  (in a first cell or a tasks/tests unit the path itself is a reference and gets the path
  finding; in another plan cell it is ignored). A miss is
  `unresolved-symbol <file>:<line> <path>:<name>`. A target file that is not valid UTF-8 is
  not searched (no finding). Whether a symbol *should* be there, or a resolving path is the
  *right* one, stays human and doc-critic judgment (out of scope).
- **Exit codes and output, as plan-cite-check's.** Exit `0` with one line
  `readiness-check: ok <plan>: <n> reference(s) resolved, <k> created, tasks: read|absent,
  tests: read|absent` on stdout when nothing is unresolved. Exit `1` with one
  `readiness-check: <code> <file>:<line> …` line per finding, in file order (plan, then
  tasks, then tests; by line within each), then `readiness-check: FAIL <n> finding(s)`. Exit
  `2` on every usage, input or internal error — stderr `readiness-check: error: <what>` and
  the usage, stdout empty, no traceback — and exit 2 is "the check did not run" on every
  consuming surface, never a pass. Paths on `argv` are taken verbatim (no shlex, glob or
  `~` expansion); `-h`/`--help` is help only as an option token, never as a flag's value.
  Files are read as strict UTF-8, one leading BOM dropped, trailing `\r` stripped per line.
- **The Reviewer gate rejects; the doc-critic is advisory; the Architect runs it first.**
  `agents/architect.md` gains a section telling the Architect to run the tool on the feature
  directory before the doc-critic checkpoint and that it must exit 0, and to declare every
  file the feature creates with `create` as the first word of its Change cell.
  `agents/reviewer.md` gains numbered check **9** directly after check 8: exit 1 ⇒ reject
  quoting the output; exit 2 ⇒ the check did not run, never approve on it; the grandfather
  rule is `readiness-check.py --grandfathered <plan>` with check 8's three verdicts; `sdd:
  false` items are exempt; checks 2, 7 and 8 are unchanged. `agents/doc-critic.md` gains a
  section telling the critic to run the same command at the `feature-spec` checkpoint and
  report every line as an advisory finding, exit 2 as "lint did not run: <stderr>", and —
  because its Claude and pi shims grant no shell tool — to record "implementation-readiness
  lint did not run: no shell tool" rather than judge the references resolved by reading.
- **Grandfathering is the E36-F01/E36-F04 merge-time rule, keyed on this tool's merge.**
  `readiness-check.py --grandfathered <plan> [--base <ref>]` is the same algorithm with
  `TOOL_PATHS` = `tools/readiness-check.py` / `.harness/tools/readiness-check.py`: the tool's
  date is the committer time of the first first-parent commit on the default branch
  touching either path; the plan's date is the author time of the earliest commit on `HEAD`
  that added it; older ⇒ exit 0 (flag), else exit 1 (reject class), exit 2 when outside a
  work tree or no base resolves. While the tool is not on the default branch every plan is
  flagged. Today's board has no `spec-ready`/`in-progress`/`in-review` `sdd: true` feature,
  so nothing is ambushed here; the rule exists for consumer repos.
- **`init.sh` runs it warn-only, beside 2d.** A new section **2e** lints every board feature
  in `spec-ready`, `in-progress` or `in-review` with `sdd: true` and a `spec_path`, prints
  each non-zero result as a `⚠️  readiness:` line (exit 2 as "did not run") and never fails
  the gate — the Reviewer owns the verdict. It passes **no `--root`**: `init.sh` runs with
  its cwd at `$HARNESS_DIR` (`.harness/` in an installed target), so a `--root .` would make
  the sweep resolve against the harness body while the Architect's and Reviewer's runs
  resolve against the project; discovery from the plan's `.git` ancestor gives every surface
  the same root. A target that is not a git work tree gets a "did not run" warning, never a
  pass. It follows 2d's SIGPIPE-proof shape (first and last lines by parameter expansion,
  every non-zero call captured with `|| rc=$?`).
- **Installed and asserted.** The installer `chmod +x`s the tool (the recurring Codex P1
  when a tool ships without it), `tests/test_install.sh` asserts the executable bit, source
  and installed copies identical, the chmod line, and that the installed `init.sh`,
  `agents/architect.md`, `agents/reviewer.md`, `agents/doc-critic.md` and
  `docs/SPEC-FORMAT.md` name the tool. Generated glue (`.claude/`, `.agents/`, `.codex/`,
  `.opencode/`, `.pi/`) embeds no role text (the shims point at `agents/*.md`), and this
  feature changes no emitter, so `sh harness-install.sh --self` must produce **no** diff —
  the Builder runs it to prove that, never to commit a regen.
- **Docs, ledger, version.** `docs/SPEC-FORMAT.md` gains a one-paragraph section stating
  the reference grammar above as the schema the tool lints; `docs/WORKFLOW.md` gains one
  paragraph in `## Doc-critic checkpoints` naming the four surfaces; `README.md` names the
  three spec lints where it describes the Reviewer's checks. `docs/RATIONALE.md`'s deletion
  ledger gains `C11 — Implementation-readiness lint` in the *Capability compensation* layer
  (the lint compensates for a model tendency — inventing or misnaming files in a clean
  context — and its removal threshold is an ablation, C9/C10's shape), with
  `tests/test_rationale_docs.sh` moved to 25 rows / 11 compensation rows / bounds `C1–C11`.
  `VERSION` steps to the next MINOR over the then-current `main` value; `CHANGELOG.md` gets
  the matching section. No test freezes the version literal or diffs a DO-NOT-TOUCH file
  against `main` (`cksum` before and after instead).
- **Suite hygiene.** The new suite `tests/test_readiness_check.sh` is POSIX `sh`
  (`set -eu`, `LC_ALL=C`, executable, `trap 'exit 1' HUP INT TERM`), runs the tool via
  `python3` and shell scripts via their shebang, asserts `rc -eq N` never a lookup miss's
  exact code, loads `tests/lib/fence.awk` for every heading slicer (`test_change_size.sh`
  R9d), and is not added to `tests/dash-allowlist.txt`. Fixtures live under
  `tests/fixtures/readiness/` with a positive and a negative feature, each planted defect
  documented in the fixture `README.md`.

## Acceptance criteria (EARS)

> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md.

- **R1** — When `python3 tools/readiness-check.py <feature-dir>` (or `<feature>.plan.md`) is
  run on a readable feature whose every scanned reference resolves (exists at the root, is
  declared `create` in `## Files to change` or sits under a created directory, resolves
  through the `.harness/` remap, or is a bare filename present in the feature directory)
  and whose every checked symbol occurs in its file, the tool shall exit `0` and print
  exactly one stdout line beginning `readiness-check: ok ` — including when the files are
  CRLF-terminated or BOM-prefixed, when an unresolvable reference sits inside fenced code,
  when `.tasks.md` / `.tests.md` are absent (the ok line says `tasks: absent` /
  `tests: absent`), and for this feature's own directory (dogfood).
- **R2** — If a `## Files to change` data row (outside fenced code, neither header nor
  separator) holds in its first cell a path candidate that does not resolve and the row's
  Change cell does not start with `create`, then the tool shall exit `1` and print
  `readiness-check: unresolved-path <plan>:<line> <path>` for it — including a bare
  basename in the first cell (`REDME.md`) and a first cell holding two paths of which one is
  missing (one line, naming the missing one); while a creating row, a path under a directory
  another row creates, a row whose Change cell starts with `add` (even when the word `create`
  appears later in that cell) and whose path exists, a header or separator row, and a pipe
  row under any other heading (`## Data model`, `## DO NOT TOUCH`) shall produce no such
  line.
- **R3** — If a `.tasks.md` list item or a `.tests.md` table data row or list item (outside
  fenced code) holds a path candidate that does not resolve and the unit's text contains no
  inflection of the word `create`, then the tool shall exit `1` and print
  `readiness-check: unresolved-path <file>:<line> <path>` naming the **physical** line of
  the reference (a continuation line is reported at its own number), the plan's findings
  preceding the tasks file's, and those the tests file's; while a reference the plan's
  created set covers, a `file::name` test reference whose file resolves (the name after `::`
  is never checked), a unit matching the `create` regex (not `recreate`, not `created_x`), a
  bare basename present at the root or in the feature directory, and a bare basename present
  in neither (ignored, not a finding — `fence.awk`, `E01-F09.tests.md`) shall produce no
  such line.
- **R4** — The tool shall ignore — produce no finding for — a backticked token that contains
  whitespace, any of `< > * ? [ ] { } $ ~ |`, `…` or `://` (asserted with tokens under a
  **known** root, `tools/<x>.py`, so the character rule and not the root rule is what
  ignores them); that starts with `/` or `-`; that is a bare extension (`.py`, `.plan.md`);
  that starts with `scratchpad/` or `progress/` while those directories exist at the root;
  that has no `/` and no dotted extension; or whose first path segment is not a known root
  (`origin/main`, `tols/x.py`) — where a first segment that some created path begins with
  **is** known (a created `contract/api.yaml` makes `contract/missing.yaml` a finding, and
  without that created row `contract/missing.yaml` is ignored); and shall treat a trailing
  `/` as a directory reference (unresolved when no such directory exists, and when the path
  is a regular file), strip a leading `./`, and resolve a `.harness/`-prefixed reference
  against the bare path and a bare reference against `.harness/<path>` — each case asserted
  as one planted token on an otherwise clean copy.
- **R5** — If a `## Files to change` data row whose Change cell starts with neither `create`
  nor `add`, and whose first cell holds exactly one path candidate resolving to an existing
  UTF-8 regular file, names in any of its cells a backticked `name()` that does not occur in
  that file as a whole word — or if any cell of a plan row, or any line of a tasks/tests
  unit, holds a symbol form `path:name` whose path resolves to an existing UTF-8 regular file
  outside the created set and `name` does not occur there as a whole word — then the tool
  shall exit `1` and print
  `readiness-check: unresolved-symbol <file>:<line> <path>:<name>`; while a present symbol, a
  `create`/`add` row, a call with arguments (`fence_delim($0)`), a `path:<digits>` line
  reference, a row whose first cell holds two paths, and a target file that is not valid
  UTF-8 shall produce no such line.
- **R6** — If the positional is missing or given twice, a flag is unknown, `--root` or
  `--base` lacks its value, the directory holds zero or more than one `*.plan.md`, the plan
  or a present sibling is absent, unreadable, not a regular file or not valid UTF-8, `--root`
  is not a directory, or `--root` is absent and no ancestor of the plan holds `.git`, then
  the tool shall exit `2` and write `readiness-check: error: <what>` plus the usage to stderr
  and nothing to stdout — never exit `0`; and any other exception shall exit `2` with
  `readiness-check: error: internal: <type>: <msg>` and no traceback; while a feature
  directory whose path contains a space and a single quote, passed verbatim in `argv`, shall
  be read as that path (exit `0` on a clean feature), and `-h`/`--help` as an option token
  shall print the usage to stdout and exit `0`.
- **R7** — `init.sh` shall carry a section `2e` that, when `tools/readiness-check.py` and
  `state/tasks.json` exist, runs the tool **without `--root`** on the `spec_path` of every
  board feature in `spec-ready`, `in-progress` or `in-review` with `sdd: true` and a
  `spec_path` (so a reference to a project file outside `.harness/` resolves in an installed
  target, and a target with no `.git` ancestor is reported as "did not run"), prints
  `⚠️  readiness: <id> <first finding> (+<n> more; warn-only — Reviewer check 9 rejects)` on
  exit 1, `⚠️  readiness: <id> check did not run: <first stderr line> (warn-only)` on exit 2
  or a missing plan, an `✅` line containing `implementation readiness` when all are clean,
  prints nothing from 2e when the tool is absent, and exits `0` in every case — including
  when the tool's output exceeds the pipe buffer (a generated 2000-finding plan).
- **R8** — When `python3 tools/readiness-check.py --grandfathered <plan> [--base <ref>]` is
  run inside a git work tree, the tool shall exit `0` with `readiness-check: grandfather
  flag: <reason>` when the tool is not yet on the default branch or the plan's first-add
  author time on `HEAD` is strictly older than the committer time of the first first-parent
  commit on the default branch touching `tools/readiness-check.py` or
  `.harness/tools/readiness-check.py`; exit `1` with `readiness-check: grandfather reject:
  <reason>` otherwise (including a plan with no commit on `HEAD`, and a plan added after the
  merge then edited with an older `GIT_AUTHOR_DATE`); and exit `2` with an `error:` line
  when the path is outside a git work tree, `--base` does not resolve, or `--base` is absent
  and no default branch resolves.
- **R9** — `agents/architect.md` shall carry a section headed exactly
  `## Implementation readiness — every named path resolves (E37-F01)` between
  `## Umbrella mode` and `## Doc-critic checkpoint` telling the Architect to run
  `python3 "$HARNESS_DIR/tools/readiness-check.py" <feature-dir>` before the doc-critic
  checkpoint, that it must exit 0 (the Reviewer rejects on exit 1, check 9), and that a file
  the feature creates is declared with `create` as the first word of its Change cell;
  `agents/reviewer.md` § `## What you check` shall carry numbered item **9** directly after
  item 8 that runs the tool on the feature directory, rejects on exit 1 quoting the output,
  treats exit 2 as a check that did not run, names `.harness/tools/readiness-check.py`,
  states the `--grandfathered` rule (exit 0 flag, 1 reject, 2 flag "did not run"), exempts
  `sdd: false`, says it judges resolution only, leaves items 2, 7 and 8 unchanged, and
  contains no sentence of the shape `exit 2 → approve`; and `agents/doc-critic.md` shall
  carry a section headed exactly `## Implementation readiness (E37-F01)` after the E36-F04
  section and before `## Epic-decomposition checks` telling the critic to run the
  same command at `feature-spec`, report each line as an advisory finding, record exit 2 as
  "lint did not run: <stderr>", record "implementation-readiness lint did not run: no shell
  tool" when it has no shell and never judge the references resolved by reading — advisory,
  never blocking.
- **R10** — A fresh `harness-install.sh` run shall ship `.harness/tools/readiness-check.py`
  executable and byte-identical to the source; the installer source shall carry the line
  `chmod +x "$H/tools/readiness-check.py"`; the installed `init.sh`, `agents/architect.md`,
