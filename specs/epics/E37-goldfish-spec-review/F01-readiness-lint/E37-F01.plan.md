# Implementation-readiness lint: every path and symbol a plan/tasks file names must resolve — Technical Plan

> Translates the .spec.md intent into design. Every table row cites the `R-id`(s) it serves
> or the `ADR-NNNN` that defers it (ADR-0009) — this plan must exit `0` under
> `tools/plan-cite-check.py` **and** under the tool it ships (R1 dogfood: every first cell
> below either exists today or has `create` as the first word of its Change cell). Start
> high-level; don't over-specify internals that might be wrong. The Builder reads
> `progress/lessons.md` first; the lessons this plan leans on are named inline.

## Stack & dependencies

- Language/framework: Python 3 **stdlib only** (`re`, `os`, `sys`, `subprocess` for
  `--grandfathered`), like `tools/plan-cite-check.py`; POSIX `sh` for the suite and the
  `init.sh` block (run under dash by `tools/run-tests.sh`); Markdown.
- New dependencies: **none**. The tool imports nothing from any other tool (no tool-to-tool
  coupling — a deliberate copy, parity-tested); `init.sh` calls it; three role files name it.
- Repo root for every command: the `feat/E37-F01-readiness-lint` checkout; every board write
  carries `HARNESS_DIR=/Users/araozmd/repos/harness-sdd` (lesson: tasks-lock remaps linked
  worktrees).
- **Test-runner slot.** One `run-tests.sh` at a time on this machine, `--jobs ≤ 4`; while
  iterating run only the suites you touched (`sh tests/test_readiness_check.sh`,
  `sh tests/test_install.sh`, `sh tests/test_rationale_docs.sh`, `sh tests/test_plan_cite.sh`,
  `sh tests/test_stage_nfrs.sh`, `sh tests/test_reviewer.sh`, `sh tests/test_doc_critic.sh`,
  `sh tests/test_change_size.sh`, `sh tests/test_self_drift.sh`), one at a time; the full
  `sh tools/run-tests.sh` once, serially, before hand-off — never relaunch a run that was
  killed. `TMPDIR` for the suites: a path with **no ancestor relationship to the repo**
  (`/var/tmp/E37-F01-builder/`, created first) — lessons 2026-09-25/28.

## Data model  (serves: R1, R2, R3, R4, R5, R8)

No stored state. The data model is what the tool reads: plan-cite-check's section/table
grammar (copied, parity-tested) plus this feature's reference grammar (the spec's *Business
rules*, restated here as the tool's contract).

| Entity | Form (byte-exact where quoted) | Tool reading where the grammar is silent | R-id |
|---|---|---|---|
| input | one positional: a directory holding exactly one `*.plan.md`, or a `*.plan.md` path; siblings `<stem>.tasks.md` / `<stem>.tests.md` read when present (`<stem>` = the plan's basename minus `.plan.md`); `--root <dir>` optional | a directory with zero or ≥2 plans ⇒ exit 2; an absent sibling is `absent` in the ok line, never an error; every file read as plan-cite-check's `_read()` does (strict UTF-8, one BOM dropped, `\r` stripped) | R1, R6 |
| root | `--root`, else the nearest ancestor of the plan's directory containing `.git` (`os.path.exists(join(d, ".git"))` — dir or file) | none ⇒ exit 2 `no ancestor of <plan> holds .git; pass --root`; walked on the absolute path, symlinks not resolved (as `specs_dir_for`) | R1, R6 |
| plan unit | a data row of a table under `^## Files to change(\s|$)` outside fences; section to the next `^##? `; table = run of `^\|` lines; separator = cells each empty or `^:?-+:?$` (≥1 not empty); header = row before a separator; cells split on `(?<!\\)\|` | `parse_sections()`, `cells()`, `is_separator()`, `iter_unfenced()` pasted from `tools/plan-cite-check.py` unchanged except `CHECKED_RE` reduced to the one heading; parity-tested (R10) | R2, R5 |
| tasks unit | a list item: a line matching `^[ \t]*- ` outside fences plus following lines matching `^[ \t]{2,}\S` until a blank line, a fence, or a line that does not; the item's text is the joined lines, each reference keeps its physical line | `- [ ]` / `- [x]` task lines are list items like any other; a blockquote `> …`, heading or paragraph is never a unit | R3 |
| tests unit | a table data row (any table in the file, same table grammar) or a list item | prose rows of `## Behavioral …` sections are list items when bulleted, else unscanned | R3 |
| reference | the text of a single-backtick span (`` `([^`\n]+)` ``) containing no whitespace; strip in order: `::.*$` (test ref — file part only), `:[0-9]+(-[0-9]+)?$` (line ref), `:([A-Za-z_][A-Za-z0-9_]*)$` (symbol form, keep the name), a leading `./`; **candidate** iff it contains `/` or `re.search(r"\.[A-Za-z0-9]{1,5}$", last_segment)`; in a plan row, path references come from the **first cell only**; symbol forms from every cell | a span with two tokens (`set -eu`) is no reference; a span wrapping a span is not parsed | R3, R4, R5 |
| ignore rule | candidate contains any of `<>*?[]{}$~\|`, `…`, `://`; starts with `/` or `-`; matches `^\.[A-Za-z0-9.]+$`; starts with `scratchpad/` or `progress/`; contains `/` and its first segment is not a **known root**; or has no `/`, sits in a tasks/tests unit, and exists at neither the root nor the feature dir | **known root** = `isdir(root/<first>)` or `isdir(root/.harness/<first>)` (`<first>` = the segment after a leading `.harness/` when present) or any created path starts with `<first>/`; computed after the created set so M4e is observable; a bare basename in a plan first cell is never ignored by the no-slash rule (it is a path by the template's contract) | R2, R3, R4 |
| resolution | in order: created set (exact, or `startswith(created_dir)` for a created path ending `/`); `exists(root/path)` (a trailing `/` requires `isdir` — a regular file is unresolved); `.harness/` remap (strip the prefix if present, else prepend it); no `/` ⇒ `exists(feature_dir/path)` | a symlink is followed (`os.path.exists`); a dangling symlink is unresolved | R1, R2, R3 |
| created set | first-cell candidates of every `## Files to change` data row whose Change cell's first word, after stripping `` *`"' `` and leading whitespace, lowercased, is `create` | `add`, `modify`, `bump`, `prepend` or any other word ⇒ not creating; a first cell with several spans adds each | R2, R3 |
| exemptions | creating row: first-cell paths unchecked, symbols unchecked; `add` row: paths checked, symbols unchecked; tasks/tests unit whose joined text matches `(?i)(?<![A-Za-z0-9_])creat(e|es|ed|ing)(?![A-Za-z0-9_])`: paths and symbols unchecked | the exemption is per unit, not per reference; the verb is the Change cell's **first** word only (`add … then create` is an `add` row) | R2, R3, R5 |
| symbol | form 1: `` `([A-Za-z_][A-Za-z0-9_]*)\(\)` `` in any cell of a plan unit whose first cell has exactly one candidate resolving to an existing regular file not in the created set and whose verb is neither `create` nor `add`; form 2: the `:name` kept above (any plan cell; any tasks/tests line), whose path resolves to such a file; check `re.search(r"(?<![A-Za-z0-9_])" + name + r"(?![A-Za-z0-9_])", text)` over the file decoded strictly as UTF-8 | decode failure ⇒ not searched, no finding; `name(x)` is not form 1; a `:name` on a created or unresolved path ⇒ no symbol finding (the path finding fires only where the path is itself a reference: a first cell or a tasks/tests unit) | R5 |
| finding | `unresolved-path <file>:<line> <path>` and `unresolved-symbol <file>:<line> <path>:<name>`, `<file>` = the path as derived from `argv` (`<dir>/<stem>.plan.md` joined verbatim; a plan path as given; siblings by replacing the suffix), `<path>` as written in the span (before stripping) minus the `::…` tail | order: plan findings, then tasks, then tests; by line within each; one line per (line, path/name), duplicates on one line collapsed | R2, R3, R5 |
| grandfather verdict | `--grandfathered <plan> [--base <ref>]`: a paste of plan-cite-check's `_git`, `_git_ok`, `_resolves`, `default_branch`, `grandfather`, `main_grandfathered`, `BASE_FALLBACKS`, with `TOOL_PATHS = ("tools/readiness-check.py", ".harness/tools/readiness-check.py")` and `PFX = "readiness-check: "` | reasons keep plan-cite-check's shape; exit 2 when not in a work tree, `--base` unresolvable, no base resolves | R8 |

**Decision — the tool reads files, not the board.** Lint and grandfather modes are pure
functions of the paths on `argv` and the tree under the root; only `init.sh` reads
`state/tasks.json` to choose which features to sweep (board read, never written).
**Decision — a deliberate copy of plan-cite-check's grammar, not an import.** Recorded in the
spec's Context; the copy is pinned two ways (R10): the fence corpus, and the parsed
`## Files to change` rows on `tests/fixtures/plan-cite/`'s positive plan. **Decision — the
`.harness/` remap is a resolution step, not a root choice.** The same spec is read in the
source repo (`tools/x`) and in an installed target (`.harness/tools/x`); trying both
spellings keeps one spec valid in both layouts without a flag. **Decision — precision over
recall is encoded as an allow-list of what is checked**, not a deny-list of what is skipped:
a token must be a backticked, whitespace-free, slash-or-extension-bearing candidate whose
first segment is a known root before anything is looked up; the known-root rule costs
first-segment typos and buys silence on branch refs, fixture-internal paths and prose.

## Approach notes

**Sequencing.** Walking skeleton first: R1 (the tool exits `0` with an `ok` line on the
positive fixture, including CRLF, BOM, fenced decoys and absent siblings) forces the input
locator, the root finder, the pasted parser, the span classifier and the resolver into
existence with no finding emitted. Then the finding classes R2 → R3 → R4 → R5 (each adds one
rule to a pure function), the error surface R6, `init.sh` R7, grandfather R8, installer R10
(the tool must ship before prose can point at it), the gate prose R9, the docs R11, then the
ledger, version and CHANGELOG R12.

**Pasting from plan-cite-check.** Copy `iter_unfenced()`, `_read()`, `cells()`,
`is_separator()`, `parse_sections()`, `strip_wrappers()`, `parse_args()`, `wants_help()`,
`InputError`, `BOM`, `SEP_CELL_RE`, `CELL_SPLIT_RE`, `CLOSE_RE`, the git helpers and
`grandfather()` **unchanged** except: `CHECKED_RE` names one heading; `TOOL_PATHS`, `PFX`,
`USAGE`, `VALUE_FLAGS = ("--root", "--base")`. Each copy's parity is a suite row, not a
comment: R10 feeds the fence corpus to `fence.awk` and to `iter_unfenced` via `importlib`,
and feeds `tests/fixtures/plan-cite/specs/epics/E01-x/F01-good/E01-F01.plan.md` to both
modules' `parse_sections()` and compares the `## Files to change` data-row line numbers.
The docstring states the copy rule and points at the originals, as plan-cite-check's does.

**Classifying a span.** Work on the span text as written. Order of stripping matters:
`::` first (a test ref `tests/test_x.sh::R1_name` must not read `R1_name` as a symbol), then
the line ref, then the symbol name, then `./`. Decide *candidate* before *ignore*: a bare
word (`VERSION`, `check 8`, `R1`) is not a candidate and never reaches the ignore rules or
the finding path. Apply the created-set check before the known-root rule so a plan that
creates a new top-level directory or file still has its siblings checked (`contract/api.yaml`
created ⇒ `contract/missing.yaml` is a finding). A no-slash candidate is resolved against
the root and the feature dir; in a tasks/tests unit a miss is *ignored*, in a plan first
cell a miss is a finding — the one place the same token reads differently, because the
first cell is a path by the template's contract and prose is not. Print the span text as
written (minus the `::` tail) in the finding so the Reviewer can `grep -F` it in the file.

**List items.** Build units from the unfenced `(n, text)` list: a line matching
`^[ \t]*- ` opens an item; a following line matching `^[ \t]{2,}\S` continues it; anything
else closes it. Keep `(n, text)` per line inside the unit so a finding reports the physical
line (R3's continuation row pins this). The `create` exemption is tested on the joined text.

**Resolution and the two layouts.** `resolve()` returns the first hit of: created set,
`root/path`, remap, feature dir. `os.path.exists` follows symlinks; a dangling link is
unresolved and that is the right verdict (the Builder cannot read it). A directory reference
(`tools/`) needs `isdir`. The `.harness/` remap applies to the *whole* path once, in whichever
direction applies.

**Symbols.** Read the target with `_read()`-like strict decoding inside a `try`; on
`UnicodeDecodeError` return "not searched" (no finding) — a binary fixture must not block a
spec. The whole-word regex escapes nothing because the name is already `[A-Za-z_][A-Za-z0-9_]*`.

**Exit codes under dash.** Assert `rc -eq N`; capture with `set +e; …; rc=$?; set -e`; a
`var="$(… | grep …)"` under `set -eu` needs `|| true`. Each exit-2 row uses the **minimal
argv that only that branch can reject** (lesson 2026-10-26: `main --bogus` alone). The
internal-error row uses the deterministic BrokenPipe shape from lesson 2026-10-27 (a stdout
pipe with no reader and >8 KB of output).

**`init.sh` 2e.** Model the block on 2d line for line (board snippet, `while read` over a
heredoc, `case "$rc"`, parameter-expansion first lines, one `ok`). Prefix every variable
`rd_`/`RD_` so 2d's `pc_*` names are untouched. The suite exercises the block by installing
into a temp target, planting a board with one `spec-ready` feature whose `spec_path` is the
negative fixture copied under `$I/specs/epics/…`, running `.harness/init.sh` and asserting
exit 0 plus the `⚠️  readiness:` line (whole line with `grep -qxF`, including the `(+N more`
tail — lesson 2026-10-27 round 2); then the positive fixture ⇒ the `✅` line; `in-review` ⇒
swept, `done` ⇒ not; a deleted tool ⇒ no 2e output and still exit 0; a 2000-finding plan ⇒
exit 0 (SIGPIPE row).

**Grandfather fixture (R8).** As `tests/test_plan_cite.sh` builds it: `git init` under
`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TEMPLATE_DIR=''`,
`GIT_CEILING_DIRECTORIES="$T"`; commit a plan, then commit `tools/readiness-check.py` on
`main` with `GIT_COMMITTER_DATE` +1h ⇒ flag; plan after ⇒ reject; no tool commit ⇒ flag;
uncommitted plan ⇒ reject; outside a repo ⇒ exit 2; `--base nope` ⇒ exit 2; only branch
`trunkless`, no origin ⇒ exit 2; a side-branch tool commit older than the plan merged
`--no-ff` later ⇒ flag; a plan only on a rebased side branch ⇒ flag (lesson 2026-10-27:
commit the subject on a side branch, or the HEAD/base clause is unpinned); an edit with an
older `GIT_AUTHOR_DATE` after the merge ⇒ reject.

**Prose rows (R9, R11).** Install once into `$T/tgt` (`CODEX_HOME="$T/ch" HOME="$T/home"
sh "$ROOT/harness-install.sh" --agents=claude "$T/tgt"`), grep the **installed** copy inside
a **bounded** slice: `## What you check` and the doc-critic / architect sections through the
fence-aware slicer, item 9 from `^9\. ` to the next `^[0-9]+\. `/`^## `, SPEC-FORMAT by
`span '## Implementation readiness' '## Frontmatter'`, WORKFLOW by `span '## Doc-critic
checkpoints' '## Drift check on epic rollup'`, README (source, not installed) by
`span '## How it works' '## Quick start'`. Anchor whole sentences from their **subject**
(lesson 2026-10-26: subject, quantifier and direction each get a mutant); pair each positive
with a negative that fails on any sentence letting the critic declare references resolved
without the tool. Verify each anchor is RED on the pre-change blob (install from a
`git stash`-ed tree into a second temp dir) before trusting it — lesson 2026-09-06.

**Ledger row (R12)** — one table row after `C10`, *Capability compensation* layer. *Why it
exists now*: "A Builder in a clean context cannot tell a renamed tool from a typo and will
invent or stall on a file the plan names but the repo lacks; the lint turns 'every named path
and symbol resolves, or is declared created' into a deterministic exit code the Reviewer
rejects on, before the Builder is spawned." *Evidence to reconsider or remove*: "Ablation:
controlled runs on a materially newer model where the Architect, given the plan template
and the `create` declaration rule but **without** the lint, emits zero `unresolved-path` /
`unresolved-symbol` findings across a predeclared feature set; retest with the Reviewer's
check 9 also removed. Retain while it catches any." Pointers: `tools/readiness-check.py`
and `agents/reviewer.md`.

**Mutation protocol** — see `E37-F01.tests.md`; every row names the mutant that kills it.
One at a time, `cp <file> <file>.mutbak` / `mv` back, print each applied diff (empty diff =
void run), restore in `finally`, `sha256` compare after each (lesson 2026-10-26), under
`scratchpad/E37-F01-builder/`; re-install into a fresh temp dir after each prose mutant.
Confirm the tree is at rest (`git diff --quiet HEAD -- <file>`) before any equivalence probe
(lesson 2026-10-27).
