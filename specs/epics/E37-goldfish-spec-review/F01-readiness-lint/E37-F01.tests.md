# Implementation-readiness lint: every path and symbol a plan/tasks file names must resolve — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and every row names the mutant that kills it. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives.
>
> **Suite.** A new POSIX `sh` suite, `tests/test_readiness_check.sh` (RC), executable,
> `set -eu`, `LC_ALL=C`, `fail`/`pass`, run by `tools/run-tests.sh` under the strictest shell it
> can probe (dash on CI) — assert `rc -eq N`, never a shell-dependent code; capture with
> `set +e; …; rc=$?; set -e`. `TOOL="$ROOT/tools/readiness-check.py"`;
> `FX="$ROOT/tests/fixtures/readiness"`; each behavioral row copies the fixture repo into its
> own `$T/<row>/repo` (`cp -R`), passes `--root "$T/<row>/repo"`, and derives its variant with
> `sed`/`awk`/`printf` so every row has exactly one cause. Prose rows run **one fresh install**
> (`CODEX_HOME="$T/ch" HOME="$T/home" sh "$ROOT/harness-install.sh" --agents=claude "$T/tgt"`,
> `I="$T/tgt/.harness"`) and grep the **installed** copy inside a **bounded slice**: role
> sections and `## What you check` through the fence-aware slicer (`tests/lib/fence.awk` — the
> house awk heading extractor is fence-blind; `test_change_size.sh` R9d requires `fence_delim`),
> doc sections by heading line numbers (`lineno`/`span`). Co-occurrence anchors fold newlines
> (`tr '\n' ' ' | tr -s ' '`) and anchor whole sentences from their subject; every positive
> anchor on a gate sentence is paired with a negative on the same slice. The suite never reads
> `VERSION` as a literal, never diffs a DO-NOT-TOUCH file against `main` (`cksum` instead),
> never writes `state/` or a live spec. Installer behavior (R10's first half) lives in
> `tests/test_install.sh`.
>
> **Fixture layout and the `<repo>/` convention.** `tests/fixtures/readiness/` holds the mini
> repo; paths inside it are written `<repo>/…` in this document and in the tasks file (the
> house convention this feature introduces: a path that is not in this repository carries a
> placeholder prefix, so the readiness lint ignores it instead of reading it as a typo). The
> fixture holds `<repo>/tools/real.py`, `<repo>/tests/test_real.sh`, `<repo>/docs/NOTES.md`,
> `<repo>/README.md`, `<repo>/tests/lib/.keep`, `<repo>/scratchpad/.keep`,
> `<repo>/progress/.keep`; `<repo>/specs/epics/E01-x/F01-good/` holds the POSITIVE feature
> (`E01-F01.{spec,plan,tasks,tests}.md`) and `F02-bad/` the NEGATIVE one (`E01-F02.*`);
> `tests/fixtures/readiness/README.md` names every planted defect with its file and line. The
> fixture README's line numbers are a precondition the suite asserts (`grep -n` the planted
> token) so a fixture edit cannot silently move a finding. Every fixture-internal path in the
> rows and the mutant table below carries the `<repo>/` prefix; the tool itself prints the
> path as planted (without the prefix), which is why the quoted finding regexes read
> `tools/missing\.py$` — a regex token carries `\` or `$` and is ignored by the lint.
>
> **Pre-change RED (Builder obligation).** Confirm each prose anchor RED on the pre-change
> blob (install from a `git stash`-ed tree into a second temp dir) before trusting it, and
> record the check in `progress/E37-F01/builder.md` — lesson 2026-09-06.

## Mutation protocol (Builder T14; Reviewer 3b)

One mutant at a time, `cp <file> <file>.mutbak` before, `mv` back after (restore in
`finally`, `sha256` compare after each), print the applied diff (non-empty, or the run is
void), under `scratchpad/E37-F01-builder/` (or `-reviewer/`). Re-install into a fresh temp dir
after each prose mutant (prose rows read installed copies). Record free space before and after.
