# Advisory drift report: living docs (product, architecture, ADRs) versus current code — Functional Spec

> R-ids in this document are `R1 … R10`; their fully-qualified form is `E37-F03:R1 … E37-F03:R10`.

## Context

`specs/product.md`, `specs/architecture.md` and the ADRs under `specs/adr/` (and under a
product space `specs/<product>/adr/`) are the harness's **living documents**: every role reads
them, the Driller amends them, the Architect cites them. Nothing checks that the code still
matches them. The existing drift guards cover other surfaces — `init.sh` section 1b compares
the installed body with the committed one, `tools/test-drift-check.sh` reports weakened test
assertions, and the Scout's epic-rollup drift mode re-validates *planned epics* against a
completed one — and feature specs are historical once `done`. EGM ships a weekly
`drift-report` for exactly this gap: a document that names a path, a tool or a symbol the code
no longer has, or code that no document names.

This feature ships that report as a **plain tool**, `tools/drift-report.py`, not a slash
command: E34 set the precedent (a `tools/` helper, no new command), a command would need five
front-end emitters plus their install assertions for an on-demand read, and the harness's
command set is a deliberately small, generated surface (`harness-install.sh`,
`.claude/commands/*` are never hand-edited). The tool is **advisory**: it never gates, never
writes the board, never edits a document or the code. It writes one dated report,
`progress/drift/<YYYY-MM-DD>.md` under the harness directory, prints that path, and exits `0`
whenever the report was written — findings are **not** a failure — and `2` only when it could
not run. A second run on the same day **overwrites** that day's report: the report is a pure
function of the tree, so there is nothing to append, and a dated filename is the contract.
`progress/drift/` falls under the existing `progress/*/` ignore in both layouts (the source
`.gitignore` and the seeded `.harness/.gitignore`), so a report is a run artifact like every
other progress note; a maintainer who wants to keep one copies it.

**The deterministic half ships as code and reuses E37-F01's resolver.** A reference is what
`docs/SPEC-FORMAT.md` → *Implementation readiness* says it is — a backticked, whitespace-free
token holding a `/` or a dotted extension, with the same ignore rules (placeholders, globs,
URLs, absolute paths, flags, bare extensions, `scratchpad/` and `progress/`, a first segment
that is not a known root, a bare basename found nowhere) and the same resolution (the root, the
`.harness/` remap both ways, a bare basename against the document's own directory) — except
that every unfenced line of a living document is scanned, not only list items and table rows,
because an ADR's decisions live in paragraphs. The tool **imports** `tools/readiness-check.py`
from its own directory (`importlib` by file path — the name is hyphenated) and calls its
`spans()`, `classify()`, `ignored()`, `resolve()`, `symbol_present()`, `iter_unfenced()`,
`_read()`, `find_root()`, `parse_args()` and `wants_help()`; it defines none of them. This is
a **stated departure from E37-F01's recorded decision** ("no tool-to-tool coupling — a
deliberate copy, parity-tested"): the brief's constraint is *reuse, do not reimplement* ("a
reimplemented tool is a bug per feature", lesson 2026-10-27), and a second copy of a
~15-rule grammar would be exactly the body-and-copy divergence class the harness has paid
for. The cost is accepted and bounded: a consumer that deletes `readiness-check.py` gets
exit `2` naming it ("could not run"), never a silent pass, and the suite pins the reuse as
object identity, not as a parity corpus. Shelling out was rejected because the resolver has
no text-scanning mode — the drift tool would have to fabricate a feature plan to feed it,
which is the unit grammar reimplemented by another name.

**The judgment half is deferred, and the report says so.** The brief's third divergence kind
— *replaced patterns*, a document describing a mechanism the code now implements differently
— is a judgment read, not an extraction. v1 does **not** spawn the Scout or add a mode to any
role file; instead every report ends with a fixed `## Not checked by this tool` section stating
that replaced patterns are not detected and what "No drift detected" therefore means. This
keeps the feature one standard Builder pass with no prose-anchor campaign on a role file (the
E37-F02 rounds), and it leaves the Scout read as a follow-up with the report as its input. The
inverse direction — *code that no living document names* — ships, **opt-in**: a run on this
repository today lists 27 unnamed files under `tools/` and `agents/` because `specs/product.md`
is the Viernes example stub, so the inventory is requested with `--inventory <dir>`
(repeatable), never assumed.

A dogfood note the Reviewer will meet: on this repository today the tool reports findings in
`specs/adr/0003-one-shared-skill-unit-per-command.md` — retired Antigravity glue it still names
(`.agents/workflows/`, `.agents/agents/`, `.agents/skills/agy-sdd-next/`: true drift) beside
paths that are relative to another root (`docs/skills.md` inside Antigravity's bundled guide,
`agents/openai.yaml` inside a skill directory: the precision cost the resolver's known-root
rule accepts). This feature fixes none of them (no retro-fit of a living document by a tool
feature); they are the evidence that the tool works and the reconciliation choice is the
human's. The house convention for the second kind is the one E37-F01 introduced: write a path
that is not in this repository with a placeholder prefix (`<guide>/docs/skills.md`).

The users are the human maintainer (reads the report, decides doc-or-code per divergence), the
Planner on an amend (what the docs promise that the code lacks), and the Architect when a plan
cites an ADR the code no longer honours. The suggested cadence is **once per release, before
the `VERSION` bump** — recorded in `docs/WORKFLOW.md`, not enforced anywhere.

Three items go beyond the inbox brief's in-scope list and are intentional, directed by the
Orchestrator's spec task for this feature: the one `README.md` sentence, the `--root <dir>`
flag (the suite needs it to run the tool against a fixture repository that has no `.git`;
every role invocation omits it) and the `--date <YYYY-MM-DD>` flag (so the suite can pin the
report's filename without a midnight race; every role invocation omits it).

**Complexity basis.** `standard`: 10 `R-id`s against the 12-`R-id` budget
(`change_size.max_requirements`); no ADR whose constraints reach across
several files is touched (ADR-0008 governs only this spec's task shape); no paid defect class
— the tool imports the resolver rather than copying it, so there is no second body to diverge,
and no role file or emitter changes (`sh harness-install.sh --self` must produce no diff); and
speccing it resolved no contradiction between two components — the departure from E37-F01's
copy decision is a brief-directed choice, recorded above, not a conflict between two shipped
contracts.

## Business rules

- **Where things are: root, harness directory, living documents, report.** The **root** is
  `--root <dir>` when given, else the nearest ancestor of the tool's own directory that holds
  `.git` (a directory or a file), found with the resolver's `find_root()` (so
  `GIT_CEILING_DIRECTORIES` bounds the walk exactly as it does for the readiness lint); none ⇒
  exit `2`. The **harness directory** is `$HARNESS_DIR` when set to a non-empty value (an empty
  value is ignored; a relative value is taken against the current working directory; a value
  naming no directory, or a directory without `specs/`, is still the harness directory — exit `2`
  naming `<value>/specs`, never a fallback to the root), else `<root>/.harness` when
  `<root>/.harness/harness.config.yaml` exists, else `<root>` — the `tools/change-size.sh`
  idiom, so the source layout and an installed target both work from any cwd. The full
  decision table, cell by cell with its pinning row, is in `E37-F03.tests.md`. The **living
  documents**, in report order, are `<harness>/specs/product.md`,
  `<harness>/specs/architecture.md`, every `<harness>/specs/adr/NNNN-*.md` (sorted), then every
  `<harness>/specs/<ns>/adr/NNNN-*.md` (sorted by namespace, then file; `<ns>` is any directory
  under `specs/` other than `adr`, `epics` and `_templates`). `product.md` or `architecture.md`
  absent is **recorded as absent, not a finding** (a repository planned without `/sdd-plan`
  has no architecture); zero documents present ⇒ exit `2`. The **report** is
  `<harness>/progress/drift/<date>.md`, `<date>` = `--date` when given (must match
  `YYYY-MM-DD` and be a real date), else today's local date; the directory is created when
  absent; the path printed is `os.path.abspath` of that path, symlinks not resolved.
- **What is scanned and what is a reference — the resolver's grammar, over every unfenced
  line.** Every document is read with the resolver's `_read()` (strict UTF-8, one BOM dropped,
  `\r` stripped; not valid UTF-8 ⇒ exit `2`), and every line outside fenced code
  (`iter_unfenced()`) is scanned — paragraphs, list items, table rows, blockquotes and headings
  alike; fenced code is invisible. A reference is a `spans()` span that `classify()` turns into
  a path candidate; it is skipped when `ignored(path, root, [])` says so (the created set is
  empty: a living document creates nothing). A candidate with no `/` that resolves nowhere is
  prose, never a finding (the readiness lint's tasks/tests rule). Resolution is
  `resolve(path, root, <the document's directory>, [])` — the root, the `.harness/` remap both
  ways, and a bare basename against the document's own directory (so `glossary.md` in
  `specs/product.md` resolves). The symbol form `path:name` is checked with
  `symbol_present()` when the path resolves to an existing regular file; a target that is not
  valid UTF-8 is not searched. The `name()` symbol form is **not** read (it is defined only
  for a single-path plan row).
- **Three finding codes, one line grammar, one reconciliation sentence each.** Inside a
  document's section, each finding is one list item
  `- <code> <doc>:<line> \`<token>\` — reconcile: <choice>` where `<doc>` is the document's
  path relative to the harness directory, `<line>` the physical line of the span, `<token>` the
  span as written — `classify()`'s `display`, which keeps a `:name` suffix and drops only a
  `::<name>` test-reference suffix (`tests/x.sh::R1_name`), the one form the resolver strips —
  and `<code>` one of: `doc-names-missing` (a `/`-bearing
  candidate that does not resolve; choice: `update doc (rewrite the path as it is today, or
  give it a placeholder prefix if it is not in this repository, or supersede the decision) or
  update code (restore it)`), `doc-names-missing-symbol` (a `path:name` whose file resolves but
  lacks the whole word; choice: `update doc (name the symbol as it is today) or update code
  (restore it)`), and — only in the inventory section — `code-unnamed` (`- code-unnamed
  \`<dir>/<file>\` — reconcile: update doc (name it in the decision that owns it) or update code
  (remove it)`). One line per (line, token); findings in document order, then by line, then
  discovery order within a line.
- **The inventory is opt-in and strict.** `--inventory <dir>` (repeatable; a path relative to
  the root — an absolute value or one holding a `..` segment is rejected with exit `2` before
  any lookup, the system-edge validation — with `<root>/.harness/<dir>` tried when
  `<root>/<dir>` is not a directory; neither ⇒ exit `2`) lists every **regular file directly under** `<dir>` whose name does not start with
  `.` (sorted; subdirectories and their contents are not entries). An entry is **named** when
  some reference in some living document resolves (as above) to that same file — compared by
  `os.path.realpath` so a `.harness/` remap or a symlinked root still matches; a reference to
  the directory itself (`tools/`) names no file inside it. Every unnamed entry is a
  `code-unnamed` finding under `## Code no living document names`. Without the flag, the
  header reads `inventory: not requested (pass --inventory <dir>)` and the section is absent.
- **The report shape is fixed.** In order: the title line
  `# Living-doc drift report — <date>`; the sentence `Advisory: this report changes nothing.
  For each finding a human decides: update the doc, or update the code.`; a header list —
  `- root: <abs root>`, `- harness: <abs harness dir>`, `- documents:` followed by one indented
  item per document in report order, `specs/product.md (read)` / `(absent)`, the same for
  `specs/architecture.md`, one `(read)` item per ADR found or the single item `ADRs: none
  found`, and `- inventory: <dir>[, <dir>…] (<n> entries)` or the not-requested line; one
  `## <doc>` section per **present** document in report order, holding either its finding
  items or the line `No drift detected.`, and for an absent `product.md` / `architecture.md`
  a section holding `Absent — not a finding.`; when an inventory was requested, `## Code no
  living document names` holding its `code-unnamed` items or `No drift detected.`; the fixed
  section `## Not checked by this tool` with the sentence `Replaced patterns — a document that describes a mechanism the code now implements
  differently — are not detected, and neither is a token outside the shapes the tool
  extracts: a backticked path whose first directory does not exist at the root (a typo such
  as tols/x.py), a bare file name found nowhere, or any token the implementation-readiness
  grammar ignores (placeholders, globs, URLs, absolute paths). "No drift detected" means
  every backticked repo-rooted path and path:name symbol the tool recognised resolves, and
  nothing in the requested inventory is unnamed.`; and last `## Summary` with exactly one line, `drift-report: <n> finding(s)
  across <d> document(s) read, <k> code entries unnamed` when `n + k > 0`, else
  `drift-report: No drift detected (<d> document(s) read)`. **Pluralisation:** `finding(s)` and
  `document(s)` are literal (the readiness lint's form); the inventory count is spelled out —
  `1 entry` / `<n> entries` in the header and `1 code entry unnamed` / `<k> code entries
  unnamed` in the summary, including `0 code entries unnamed`. The file is written whole (a
  temporary file in the same directory, then replaced), so a reader never sees a partial
  report and a same-day rerun leaves exactly one title line.
- **Exit codes and streams.** Exit `0` after the report is written, with **exactly one**
  stdout line — the report's absolute path — and nothing on stderr, whether or not there are
  findings; the tool never exits `1` (an advisory report has no failing verdict, and a reader
  must never mistake a finding for a failure). Exit `2` on every usage, input or internal
  error — stderr `drift-report: error: <what>` and the usage, stdout empty, no report written,
  no traceback: a positional argument (the tool takes none), an unknown flag (including
  `--fix` or `--write`), a flag without its value, `--root` not a directory, no `.git` ancestor
  and no `--root`, zero living documents present, a living document that is not valid UTF-8,
  `--inventory` naming no directory or given an absolute or `..` value, `--date` malformed or
  not a real date, the resolver
  `tools/readiness-check.py` absent from the tool's directory or failing to load, or the
  report directory unwritable (`progress` is a regular file). `-h` / `--help` print the usage
  to stdout and exit `0`, only as an option token (the resolver's `wants_help()`, with
  `VALUE_FLAGS` = `--root`, `--inventory`, `--date`). Arguments are taken verbatim from `argv`
  (`parse_args()`; `--flag=value` and `--flag value` both accepted). Any other exception exits
  `2` with `drift-report: error: internal: <type>: <msg>`.
- **The tool writes one file and reads the tree; nothing else changes.** After a run, every
  file under the root other than the report is byte-identical to before (the suite records a
  `cksum` manifest of the fixture tree before and compares after); `state/tasks.json` is never
  opened for writing and never read — the tool consumes no board state; no document is edited;
  there is no `--fix`.
- **Installed and asserted; generated glue untouched.** `harness-install.sh` copies `tools/`
  wholesale and gains one line, `chmod +x "$H/tools/drift-report.py"` beside the
  `readiness-check.py` chmod (the recurring Codex P1 when a tool ships without it);
  `tests/test_install.sh` gains `test_drift_report_installed_contract` asserting the installed
  copy is executable and byte-identical to the source, the source mode is executable, the chmod
  line exists, the installed `docs/WORKFLOW.md` names `tools/drift-report.py`, and the seeded
  `.harness/.gitignore` ignores `.harness/progress/drift/<file>` (via the existing
  `progress/*/`). No emitter and no role file changes, so `sh harness-install.sh --self` must
  produce **no** diff; `.claude/agents/*` and `.claude/commands/*` are never hand-edited
  (E26-F01).
- **Docs, ledger, version.** `docs/WORKFLOW.md` gains one section headed exactly
  `## Living-doc drift report (E37-F03)` directly after `## Drift check on epic rollup` and
  before `## Epic lifecycle` (the cadence note: on demand, suggested once per release, the
  command, the three finding codes, the reconciliation choice, advisory / exit codes / report
  path / same-day overwrite, how it differs from the three other drift guards, and what is not
  checked); `README.md` → `## How it works` gains one sentence after the E37-F02 paragraph.
  `docs/RATIONALE.md`'s deletion ledger gains `C13 — Living-doc drift report` in the
  *Capability compensation* layer directly after `C12` (a structural tool compensating for a
  model tendency — changing a path, tool or symbol without amending the document that names it
  — with an ablation threshold, C11's shape); `tests/test_rationale_docs.sh` moves to 27 rows /
  13 compensation rows / bounds `C1[0-3]` at every site. `VERSION` steps `0.107.0` →
  `0.108.0` (one MINOR: the installed body changes); `CHANGELOG.md` gets `## [0.108.0]`. No
  test freezes the version literal or diffs a DO-NOT-TOUCH file against `main` (`cksum`
  before and after instead).
- **Suite hygiene.** The new suite `tests/test_drift_report.sh` is POSIX `sh` (`set -eu`,
  `LC_ALL=C`, executable, `trap 'exit 1' HUP INT TERM`, `GIT_CEILING_DIRECTORIES="$T"`), runs
  the tool via `python3` with `HARNESS_DIR` unset (`env -u HARNESS_DIR`) so the row's root
  decides the harness directory, asserts `rc -eq N` never a lookup miss's exact code, loads
  `tests/lib/fence.awk` for every heading slicer (`tests/test_change_size.sh` R9d), never
  writes into the real repository (the dogfood row runs on a `git archive HEAD` copy, never a
  symlink farm — lesson 2026-11-09 r3), and is not added to `tests/dash-allowlist.txt`.
  Fixtures live under `tests/fixtures/drift/`: a clean mini repository `repo/` and a
  `defects/` directory of documents the negative rows plant, each planted defect documented
  in the fixture `README.md` with its file and line.

## Architecture alignment

> `specs/architecture.md` is **absent** in this repo (never written; the ADR set exists under
> the single platform space `specs/adr/`). Per `agents/architect.md` graceful degradation the
> section is not strictly required; it is written because the epic records the decisions this
> tool sits beside. The inbox brief records no `ADR-NNNN` ids; the ones below are those this
> feature's own shape touches. The tool itself handles an absent `architecture.md` as a
> recorded absence, which is the case it meets on this very repository.

- platform ADR-0008 — Vertical slices / red-green pairs: this feature's `.tasks.md` is in pair
  form, walking-skeleton `R1` first (a clean fixture produces a dated report and the printed
  path — the one behavior observable at the product boundary); `tools/tasks-pair-check.py`
  exits 0 on it.
- platform ADR-0009 — Stage-aware NFRs: untouched; the plan's `## Deferred` is `none` (stage
  `production`), and every plan row cites an `R-id`.
- platform ADR-0001 — Deterministic next selection: untouched; the tool reads no board state
  and writes none — it is not a selector input and not a gate.

ADR-0002 (`builder-heavy` is a tier) is not touched: `complexity: standard` selects the ordinary
Builder. ADR-0005 (source-only surfaces) is not touched: the tool ships to every target like
its sibling lints, it is not source-only. No divergence from any ADR. The departure from
E37-F01's **Context** decision (copy, not import) is recorded in this spec's Context; it is a
feature-level decision, not an ADR.

## Acceptance criteria (EARS)

> Each is one testable behavior with a stable id. See docs/SPEC-FORMAT.md. The system under
> test is `tools/drift-report.py` as shipped from the source tree and as installed by
> `harness-install.sh`, run against fixture repositories under `tests/fixtures/drift/`.

- **R1** — When `python3 tools/drift-report.py --root <dir>` is run on a root whose present
  living documents name only references that resolve (at the root, through the `.harness/`
  remap, or a bare basename in the document's own directory) and whose every `path:name` names
  a present whole word, the tool shall exit `0`, write `<harness>/progress/drift/<date>.md`
  (creating `progress/drift/` when absent), print exactly one stdout line equal to that file's
  absolute path, write nothing to stderr, and the report's `## Summary` line shall be
  `drift-report: No drift detected (<d> document(s) read)` — including when
  `specs/architecture.md` is absent (listed `(absent)`, its section `Absent — not a finding.`,
  not counted in `<d>`), when a product-space ADR `specs/<ns>/adr/NNNN-*.md` is present (listed
  and read after the platform ADRs), when `--root` is omitted and the root is discovered from
  the tool's own `.git` ancestor, when the harness directory is `<root>/.harness` (an installed
  layout: documents read from `.harness/specs/`, a reference to `src/app.py` resolving against
  the root, the report under `.harness/progress/drift/`); and a run on a `git archive HEAD` copy of this repository
  shall exit `0` and print a path to an existing report whose documents list holds at least
  eleven `specs/adr/` items (dogfood — findings are expected there and are not asserted).
- **R2** — If a living document holds, outside fenced code, a `/`-bearing path candidate that
  `ignored()` does not skip and that does not resolve, then the report's section for that
  document shall hold one line `- doc-names-missing <doc>:<line> \`<token>\` — reconcile: …`
  naming the physical line and the span as written; and if it holds a `path:name` whose path
  resolves to a UTF-8 regular file lacking the whole word `name`, one line
  `- doc-names-missing-symbol <doc>:<line> \`<path>:<name>\` — reconcile: …`; the tool shall
  still exit `0`, and the `## Summary` line shall count them (`<n> finding(s)`); while the same
  token inside fenced code, a token containing any of `< > * ? [ ] { } $ ~ |`, `…` or `://`, an
  absolute path, a bare extension, a `scratchpad/` or `progress/` path, a path whose first
  segment is not a known root (`origin/main`, `tols/x.py`), a bare basename found nowhere
  (`fence.awk`), a `path:name` whose path does not resolve (path finding only), a line
  reference `path:12`, a present symbol, and a `path:name` whose target is not valid UTF-8
  shall each produce no such line — each case asserted as one planted token on an otherwise
  clean copy — findings shall appear in document order, then by line, one line per
  (line, token), a span in a heading, a paragraph, a blockquote or a table row shall be
  scanned alike, and the same findings shall be reported when the document is
  CRLF-terminated or BOM-prefixed (a fence still closes, so a defect after a fenced block is
  still found).
- **R3** — Where `--inventory <dir>` is passed (once or repeatedly), the report shall hold the
  section `## Code no living document names` listing, as `- code-unnamed \`<dir>/<file>\` —
  reconcile: …`, every regular file directly under `<dir>` (resolved at the root, else under
  `<root>/.harness/`) whose name does not start with `.` and to which no reference in any
  present living document resolves — a reference through the `.harness/` remap names its file,
  a reference to the directory itself (`tools/`) names nothing inside it, a subdirectory is not
  an entry — and the header line `- inventory: <dirs> (<n> entries)` (`1 entry` when one); while without the
  flag the header shall read `- inventory: not requested (pass --inventory <dir>)` and the
  section shall be absent; and `--inventory nope` (no such directory at the root or under
  `.harness/`) shall exit `2`, as shall an absolute value (`--inventory /tmp`) or one holding a
  `..` segment (`--inventory ../x`), before any lookup.
- **R4** — The tool shall write the report in the fixed shape: the first line
  `# Living-doc drift report — <date>`, the advisory sentence, the `- root:` / `- harness:` /
  `- documents:` / `- inventory:` header list with one item per document in report order
  (`(read)` / `(absent)`; `ADRs: none found` when no ADR exists), one `## <doc>` section per
  document in report order holding its findings or `No drift detected.`, the `## Not checked by
  this tool` section holding the replaced-patterns sentence, and `## Summary` as the last
  section with exactly one `drift-report:` line; `--date 2026-01-02` shall name the file
  `2026-01-02.md` and the title line; and a second run on the same tree and date shall leave a
  byte-identical file, while a run after a defect is planted shall leave exactly one title
  line, the new finding exactly once and no line from the previous content that the new tree
  does not produce (overwrite, never append).
- **R5** — If the invocation holds a positional argument, an unknown flag (`--bogus`, `--fix`),
  `--root` / `--inventory` / `--date` without its value, `--root` naming no directory, no
  `--root` with no `.git` ancestor of the tool's directory (`GIT_CEILING_DIRECTORIES` set), a
  harness directory with zero living documents present, a living document that is not valid
  UTF-8, `--inventory` given an absolute path or a `..` segment, a malformed or impossible
  `--date` (`2026-1-1`, `2026-02-30`), a `progress` entry that
  is a regular file, or a tool directory lacking `readiness-check.py`, then the tool shall
  exit `2`, write `drift-report: error: <what>` as the first stderr line (naming
  `readiness-check.py` in the last case and `--root` in the no-ancestor case) plus `usage:`,
