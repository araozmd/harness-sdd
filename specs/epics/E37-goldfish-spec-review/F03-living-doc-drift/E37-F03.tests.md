# Advisory drift report: living docs (product, architecture, ADRs) versus current code — Test Contract

> The traceability matrix: every R-id in the `.spec.md` maps to a concrete, executable test,
> and every row names the mutant that kills it. The Reviewer fails the feature if any R-id
> lacks a passing test, or if a named mutant survives that is not a listed known limit.
>
> **Suite.** A new POSIX `sh` suite, `tests/test_drift_report.sh` (DR), executable, `set -eu`,
> `LC_ALL=C`, `trap 'exit 1' HUP INT TERM`, `GIT_CEILING_DIRECTORIES="$T"`, `fail`/`pass`, run
> by `tools/run-tests.sh` under the strictest shell it can probe (dash on CI) — assert `rc -eq N`,
> never a shell-dependent code; capture with `set +e; …; rc=$?; set -e`.
> `TOOL="$ROOT/tools/drift-report.py"`; `FX="$ROOT/tests/fixtures/drift"`; each behavioral row
> copies the clean fixture into its own `$T/<row>/repo` (`cp -R`; `R="$T/<row>/repo"`), runs
> `env -u HARNESS_DIR python3 "$TOOL" --root "$R" …` and derives its variant with
> `sed`/`awk`/`printf`/`cp` so every row has exactly one cause; `plant_bad` copies
> `$FX/defects/0002-bad.md` to `<repo>/specs/adr/0002-bad.md`; `D="$(date +%Y-%m-%d)"` is read
> once per row right before the run, and rows that pin a filename pass `--date` instead.
> `section <doc>` slices `## <doc>` from the report through the fence-aware slicer
> (`tests/lib/fence.awk`, `fence_delim($0)` first — `tests/test_change_size.sh` R9d). Prose rows
> slice `docs/WORKFLOW.md` and `README.md` the same way, fold (`tr '\n' ' ' | tr -s ' '`) and
> anchor whole sentences from their subject. The suite never reads `VERSION` as a literal, never
> diffs a DO-NOT-TOUCH file against `main` (`cksum` instead), never writes `state/`, a live spec
> or anything under `$ROOT` (the dogfood row runs on a `git archive HEAD` copy). Installer
> behavior (R8) lives in `tests/test_install.sh`. Every row is dispatched from one flat list through
> `row <name>`, which fails the suite when the row returns without a `pass` line under its own name
> — so a silent early `return` in any row reds the suite instead of vanishing (F18a); a row that
> returns early but still prints its own `pass` is not seen by the wrapper (F18b, a disclosed limit) —
> and a `chk_exit2` row prints its `pass` line after **every** sub-case, so in a multi-case row
> (`R5_date_malformed`, `R5_inventory_not_relative`, `R5_help_as_value_is_not_help`,
> `R5_date_impossible`) an early return after the first case is not seen either; those arms are
> pinned by their mutants (F4, F13, M5k, N11), not by the wrapper. The suite ends with a loop over
> every `R*()` function defined in the file, failing `<name>: defined but not dispatched from the row
> list` when that name printed no `pass` line (P10): it sees a row that exists but was dropped from
> the dispatch list; it does not see a row deleted together with its definition — that is the
> R-id coverage table above, read by the Reviewer, not a suite check.
>
> **Fixture layout and the `<repo>/` convention.** `tests/fixtures/drift/repo/` is the clean
> mini repository (every reference its living documents name resolves; a run yields `No drift
> detected`); `tests/fixtures/drift/defects/0002-bad.md` is the negative ADR the rows plant;
> `tests/fixtures/drift/README.md` names every planted defect with file and line, and the suite
> asserts each line number against `grep -n` of the planted token (a fixture edit that moves a
> defect fails setup instead of moving a finding). Fixture-internal paths in this document and
> the tasks file carry the `<repo>/` prefix; the tool prints them without it, which is why the
> quoted finding regexes read `tools/missing\.py` — a regex token carries `\` and is ignored by
> the readiness lint.
>
> **Pre-change RED (Builder obligation).** Confirm each prose anchor RED on the pre-change blob
> (`git show HEAD:docs/WORKFLOW.md`, `git show HEAD:README.md`; an install from a `git stash`-ed
> tree into a second temp dir for the TI row) one anchor at a time before trusting it, and record
> the check in `progress/E37-F03/builder.md` — lesson 2026-09-06.
>
> **What is not tested by machine.** Whether a maintainer reads the report, and whether the
> reconciliation it suggests is right, are human judgments. The judgment half (replaced
> patterns) is out of scope by design and the report says so (R4's fixed section).
