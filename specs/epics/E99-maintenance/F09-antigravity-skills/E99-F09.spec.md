# Antigravity claims the shared skill unit — Functional Spec

## Context

Antigravity discovers workspace skills at `.agents/skills/<name>/SKILL.md`. The harness
already writes exactly that layout — but only when `codex` is selected. So an
Antigravity-only target gets `.agents/workflows/*.md`, a tree Antigravity's own documented
customization discovery does not read, and no discoverable `/sdd-*` command at all.

The unit the Codex path writes is already a **valid Antigravity skill**: `name` +
`description` frontmatter over the canonical workflow body, verified on a real install
against Antigravity's bundled customization guide. So this is not a migration. Two things
are wrong and both are about *ownership*: the install gate is too narrow (Antigravity never
gets the unit), and the reclaim gate is too wide (deselecting `codex` deletes units an
Antigravity selection still depends on).

### Resolved during specification

**One shared unit, not two namespaced ones** — recorded as `ADR-0003`. The parked branch
`fix/agy-skills` @ `16994a5` (PR #87, fifteen rounds) predates E23-F01 and assumes
`.agents/skills/` is Antigravity's exclusive territory. Its diff is reference material for
edge cases only and is not replayed.

**Personas stay out of scope.** `.agents/agents/*.md` and `.agents/workflows/*.md` are not
Antigravity customization types; `.agents/rules/harness.md` is, and it already routes to the
canonical role bodies. Retiring the two unrecognised trees would delete files from installed
targets and needs its own migration decision (see *Out of scope*).

**One existing assertion inverts.** `tests/test_install.sh`'s codex-deselect block installs
`--agents=antigravity,codex`, deselects `codex`, and asserts the skill units are **removed**.
That is correct today and wrong after this feature. It is a deliberate contract change, not
a test to quietly flip.

## Business rules

- **One unit, one writer.** A command's `SKILL.md` bytes never depend on which front-ends
  are selected.
- **A unit is claimed, not owned by one front-end.** It is installed while at least one
  claiming front-end is selected, and reclaimed when the last claimant goes.
- **The unit is atomic.** `agents/openai.yaml` follows the discoverable `SKILL.md`, not the
  selection — Codex discovers repository skills from the directory, so a unit without its
  explicit-only policy is an implicitly-invocable mutating workflow for anyone who runs
  Codex in that repo.
- **Reclaim scoping is destructive when wrong.** The failure mode of a too-wide reclaim is
  silent deletion of another front-end's live glue, so the both-selected case is a
  first-class requirement, not a bonus test.
- **Ownership rules themselves do not change.** Stamp-and-pristine comparison, foreign/edited
  preservation, and the symlink refusals carry over unchanged; only the conditions under
  which they run change.

## Architecture alignment

- platform ADR-0003 — *`.agents/skills/<name>/` holds one shared unit per command*: this
  feature is that decision's implementation — it widens the install gate to the claiming set
  `{codex, antigravity}`, narrows reclaim to "last claimant", and keeps the historical
  `.harness/.codex-skills/` stamp path the ADR requires be left alone.
- platform ADR-0001 — *deterministic `next` selection*: untouched; this feature changes
  installer gating only, not board state or task selection.
- platform ADR-0002 — *`builder-heavy` is a tier, not a second prompt*: untouched; no role
  is added, and the skill unit list is the command list, not the role list.

## Acceptance criteria (EARS)

- **R1** — Where `antigravity` is selected, the system shall install the shared skill unit
  `.agents/skills/<cmd>/` for every harness-owned command it exposes, whether or not `codex`
  is selected.
- **R2** — The bytes of a command's unit — `SKILL.md` and `agents/openai.yaml` — shall be
  identical across every selection that includes at least one claiming front-end.
- **R3** — The system shall write the explicit-only policy companion `agents/openai.yaml`
  wherever it writes a unit's `SKILL.md`, including where `codex` is not selected.
- **R4** — When a claiming front-end is deselected while another claiming front-end remains
  selected, the system shall leave the unit's files and their ownership stamps unchanged.
- **R5** — When the last claiming front-end is deselected, the system shall reclaim the whole
  unit under the existing stamp-and-pristine ownership rules and prune only the directories
  it empties.
- **R6** — While `pr_loop.enabled` is not true, the system shall reclaim the `sdd-pr-loop`
  skill unit from a target whose only claiming front-end is `antigravity`.
- **R7** — If a live unit's `SKILL.md` is foreign or edited, then the system shall leave it
  unchanged and warn, whichever claiming front-end triggered the install or the reclaim.

## Out of scope

- **Changing Codex's shipped layout.** E23-F01 is released (v0.49.0+); moving it is a
  breaking change for every upgraded target and needs its own decision.
- **Retiring `.agents/workflows/` and `.agents/agents/`.** Antigravity's documented
  discovery does not read them, but removing them deletes files from installed targets and
  is a separate feature with its own migration story (ADR-0003 → *Deferred*).
- **Renaming the `.harness/.codex-skills/` stamp directory.** ADR-0003 requires it stay.
- **Antigravity model routing.** PR #87 retired it in round 13 by editing E17-F01's approved
  spec files; that is a spec-level change to a completed feature and goes back through the
  gate on its own if still wanted.
- **Replaying the parked branch's diff.** `fix/agy-skills` @ `16994a5` stays reachable as
  reference; it is not merged, rebased, or cherry-picked.
