# Antigravity claims the shared skill unit — Technical Plan

## Stack & dependencies
- Language: POSIX `sh` (must run under `dash` — `/bin/sh` on Ubuntu CI).
- New dependencies: none. No new on-disk path, no new stamp directory, no config key.

## The claim predicate  (serves: R1, R4, R5, R6)

One predicate replaces every `agent_selected codex` that guards the skill surface:

```sh
# skill_unit_claimed — true while ANY front-end that reads .agents/skills/ is selected.
# ADR-0003: the unit is shared; add a front-end here the moment it learns to read that
# surface, or its units get reclaimed out from under it — silently, in the destructive
# direction.
skill_unit_claimed() {
  agent_selected codex || agent_selected antigravity
}
```

It is evaluated **after** selection is resolved, so inside the §7 deselection loop
`agent_selected <other>` is exactly "another claimant remains" — no separate bookkeeping,
and no dependence on `PRIOR_AGENTS`.

## Gates that change  (serves: R1, R3, R4, R5, R6)

| Site | Today | After |
|---|---|---|
| §5d install (`harness-install.sh:4354`) | `if agent_selected codex` | `if skill_unit_claimed` |
| §7 `codex)` (`:4613`) | always `reclaim_codex_skills "$HARNESS_OWNED_CMDS"` | reclaim only when `! agent_selected antigravity` |
| §7 `antigravity)` (`:4563`) | never touches skills | reclaim `$HARNESS_OWNED_CMDS` when `! agent_selected codex` |
| §7b gate-off (`:4681`) | `if agent_selected codex` | `if skill_unit_claimed` |

Both front-ends deselected in one run visits the reclaim twice; the second pass finds the
paths already gone. **Reclaim is idempotent today and must stay so** — every branch is
guarded by `[ -e ]` and the `rmdir`s are `2>/dev/null || true`. Do not add a "nothing to do"
error path.

`gen_codex_skill_policy` stays unconditional inside the unit writer (R3): the companion
follows the discoverable `SKILL.md`, never the selection. No install-time parameterisation —
that is the whole point of ADR-0003's atomic-unit bullet, and it keeps `install_*`'s
two-file safety check (`_ics_safe`) intact.

runtime, which the suites catch — but check with `grep -n 'codex_skill\|codex_skills'` after
the rename rather than trusting the diff.

## DO NOT TOUCH
- `.harness/.codex-skills/` — the on-disk stamp path. ADR-0003: renaming it orphans the
  ownership proof on every installed target, after which each live unit reads as "foreign or
  edited" and becomes permanently unreclaimable.
- `gen_skill_body`'s output format. R2 is a byte-identity requirement; changing the body in
  the same PR makes every cross-selection `cmp` vacuously true against itself and destroys
  the one signal that says the unit is genuinely shared.
- E23-F01's ownership semantics — stamp-then-pristine comparison, foreign/edited
  preservation, every symlink refusal, and "a surviving `SKILL.md` retains its companion".
  Only the *conditions* under which they run change.
- `agents/*.md`, `.agents/agents/`, `.agents/workflows/` — out of scope per the spec.

## Approach notes

- **Ordering is load-bearing.** §5 install runs before §7 reclaim. A run that both installs
  (because a claimant is selected) and deselects the other claimant therefore writes the unit
  first and evaluates reclaim after — which is correct under R4, but means a test asserting
  "unchanged" must compare against bytes captured *before* the run, not against a freshly
  generated reference.
- **`$CMDDIR` lifetime.** §7b's pristine references are the still-present `$CMDDIR/<name>.md`
  bodies and `rm -rf "$CMDDIR"` is deferred until after it (`:4689-4692`). Widening the §7b
  gate does not change that, but do not move the reclaim below the cleanup.
- **`HARNESS_OWNED_CMDS` vs `HARNESS_SDD_CMDS`.** Install picks the list from
  `pr_loop_enabled`; reclaim always uses `HARNESS_OWNED_CMDS` so a unit stamped while the
  gate was on is still reclaimable after it flips off. Keep that asymmetry.
- **Mutation-test every new case before claiming it passes.** Commit first, then break the
  specific gate the case owns (e.g. revert §7 `codex)` to the unconditional reclaim) and
  confirm *that* case fails and the others do not. A case that survives its own mutation is
  proving something else.
- **Assert the fixture precondition.** Each new case must assert the unit exists (and, where
  it matters, that its stamp exists) *before* the deselect run. "Still present afterwards" is
  satisfiable by an install that never wrote it.
