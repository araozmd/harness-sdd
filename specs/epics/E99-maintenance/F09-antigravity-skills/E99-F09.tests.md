## The R4 case is the whole feature

A test that selects **one** front-end cannot detect this defect class — that is why the
collision reached round 15 on PR #87 unnoticed. R4 is the only shape that can: install with
both claimants, deselect one, assert the other's glue is intact. It is asserted in **both
directions** because the two reclaim paths are different code (`§7 codex)` and
`§7 antigravity)`), and a fix applied to one proves nothing about the other.

R4 also asserts the **stamps**, not just the files. A reclaim that spared the live files but
wiped `.harness/.codex-skills/<cmd>/` would pass a files-only assertion and leave every unit
permanently unreclaimable — it would read as "foreign or edited" forever after.

## Anti-tautology

- **Fixture preconditions are asserted, always.** Every deselect case asserts the unit **and
  its stamp** exist before the second run. "Present afterwards" is trivially satisfiable by an
  install that never wrote the unit, and "absent afterwards" by one that never wrote it either
  — four tests went green this way in the E99-F11 session.
- **R2 compares across *runs*, not against a generated reference.** Regenerating the reference
  in-process compares the generator with itself and passes even if the install writes nothing.
  Three separate installs into three `mktemp -d` targets, then `cmp`.
- **R4 compares against bytes captured before the deselect run**, not against freshly generated
  output — §5 install runs before §7 reclaim, so a fresh reference would also match a unit that
  had been deleted and rewritten.
- **R5 is paired with R4 on the same fixture shape.** "Removed" alone is reachable by an
  install that never wrote it; R4 proves the same fixture retains the unit when a claimant
  remains, so R5's removal is attributable to the deselect.
- **R6 asserts a removal and a survival in the same run** — the `sdd-pr-loop` unit goes, the
  ungated units stay. A gate-off that reclaimed everything would pass the removal alone.
- **R7's warning is asserted on stderr *and* the foreign bytes are compared**, so a path that
  warns and deletes anyway fails.

## Suite-wide constraints

Carried from the existing suites: never assert an exact `VERSION` literal; never couple a
CHANGELOG assertion to the top version; never `git diff` a DO-NOT-TOUCH file against `main`;
every fixture under its own `mktemp -d`; sandbox `CODEX_HOME` **and** `HOME` on every
`harness-install.sh` invocation.

## Non-functional

- `sh tools/run-tests.sh` fully green — in particular every **existing** skill-unit assertion
  in `test_install.sh`, `test_pr_loop.sh`, `test_installer_toggles.sh` and `test_model_routing.sh`
  passes unchanged, with the single deliberate exception of the rewritten codex-deselect block
  (R4). That block is the only permitted assertion change; any other suite going red is a
  regression, not a contract update.
- The suites must pass under `dash` (`/bin/sh` is dash on Ubuntu CI).
- `sh -n harness-install.sh` clean; `sh tools/change-size.sh` within budget.
