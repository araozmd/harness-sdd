# E26-F01 — `--self` mode

The repo's `.claude/agents/*` and `.claude/commands/*` are hand-maintained mirrors of
what the installer generates for targets. Measured drift (2026-09-05): every one of
the 15 glue files has forked — 6 of 7 command bodies differ on nearly every line, and
the divergence runs in BOTH directions (the committed `sdd-next.md` carries
inception-brief routing the heredoc lacks; the heredoc carries `baseRefOid`
base-change fields the committed `sdd-pr-loop.md` lacks). Multiple such divergences
were found by review this campaign; this feature makes them impossible by
construction instead.

**The reconciliation IS the feature.** Byte-equality between committed and generated
glue is only meaningful after each divergence is resolved deliberately — richer
content upstreamed into the ONE canonical emitter, layout differences parametrized,
repo-specific asides dropped. E26-F02 then arms the gate that keeps it true.

## Requirements (EARS)

- **R1** — `harness-install.sh --self` SHALL regenerate the SOURCE repo's own
  `.claude/agents/*.md` and `.claude/commands/*.md` from the same emitters used for
  targets, with every path resolved to the source layout (no `.harness/` prefix:
  `init.sh`, `agents/…`, `tools/…`, `progress/…`, `harness.config.yaml`). `--self`
  takes no target dir and SHALL refuse to combine with a target argument or
  `--umbrella`.
- **R2** — After reconciliation, each glue artifact SHALL have exactly ONE canonical
  body (the emitter); the committed source copies are replaced by `--self` output.
  Divergences are resolved richer-side-wins: content improvements present only in the
  committed copies are upstreamed into the emitters (so targets receive them on their
  next upgrade), and content present only in the emitters is kept. Repo-specific
  asides (e.g. "as this one does" severity phrasing) SHALL be dropped in favor of the
  generic text; layout is the only permitted variance between the self and target
  renderings of a body, plus the one source-layout banner line in `sdd-pr-loop.md`.
- **R3** — `--self` SHALL preserve each existing shim's recorded `model:` line
  (today: builder=sonnet, builder-heavy=opus) when regenerating — the source repo's
  tiering lives in the shims, never in the seed-template `harness.config.yaml`. A
  shim with no `model:` line stays model-less.
- **R4** — `--self` SHALL write the repo root's `.escalation-arming` from the real
  `escalation_verdict` computed over those preserved models.
- **R5** — pr-loop glue (`sdd-pr-loop.md` command, `pr-fixer` shim) SHALL regenerate
  under `--self` exactly when the repo's own `pr_loop.enabled` is true (it is), via
  the same gate targets use.
- **R6** — `--self` SHALL be idempotent (a second run changes zero bytes) and SHALL
  NOT touch anything outside `.claude/agents/`, `.claude/commands/`, and
  `.escalation-arming` — no body copy, no config seeding, no version stamp, no
  `.agents`/selection writes.
- **R7** — Target installs SHALL be unaffected in mechanism: same emitters, same
  gating, `.harness/`-prefixed paths — only the upstreamed content improvements
  change target output (a versioned, reviewable diff, not silent drift).
- **R8** — `VERSION` MINOR bump + CHANGELOG; new suite `tests/test_self_mode.sh`
  covering R1, R3–R6 and spot-checking R2 reconciliation sentinels.
