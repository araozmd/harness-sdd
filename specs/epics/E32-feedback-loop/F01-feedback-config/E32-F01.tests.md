## Discrimination requirements (the Reviewer mutates these)

- **R3:** the fixture must **delete** the block from a freshly seeded config before
  migrating (lesson 2026-09-05: a copied fixture otherwise already carries the artifact).
  The block extract must have a line-count floor, and a semantic `key=value` compare must sit
  next to `cmp`. A one-sided edit to the template or to the heredoc must turn
  `test_template_and_heredoc_converge` red.
- **R4:** use a distinctive, non-default value for each key (e.g.
  `repo: ghe.example.com/acme/fork`), so that a mutant that rewrites or refills the block
  cannot pass by coincidence with the defaults (lesson 2026-09-18). Fixture (b) must turn
  red under a mutant that narrows the presence check back to `^feedback:[[:space:]]*(#.*)?$`.
- **R5:** capture stdout only. Assert all three tokens with **one** `grep` on a single line,
  not three separate greps over the whole output. Assert the count is exactly 1, not ≥1.
  A mutant that moves the notice to stderr, prints it twice, or drops the path must turn
  the test red.
- **R6:** assert the count is 0. Also run the positive control (R5) in the same suite, so
  that an absent notice cannot pass vacuously.
- **R7:** run against a **copy** of the source repo, never the working tree. Compare the
  config with `cmp` before and after.
- **R8:** the notice lines must be matched per target path, so that a mutant that prints
  one notice for the whole cascade turns the test red.
- **R9/R10:** extract the section span before grepping. Keep each token pair on one line,
  and for any negative, check that its middle grep matches ≥1 line on the pristine file.

## Behavioral / end-to-end checks
- Fresh-install a scratch target and read the notice by eye. Set
  `feedback.enabled: false` and re-run: there should be no notice and the value should be
  preserved. Delete the block and re-run: the block is re-seeded with `true` and the notice
  prints.

## Non-functional checks
- `./init.sh` green; `./tools/run-tests.sh` green (re-run any unrelated red suite alone
  before chasing it).
- `sh harness-install.sh --self` produces no diff in generated glue.
- The new suite is POSIX sh, executable (`[ -x "$SRC/tests/test_feedback_config.sh" ]`), and
  passes under dash.
