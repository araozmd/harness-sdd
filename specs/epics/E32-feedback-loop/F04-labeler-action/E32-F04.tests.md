> Every R-id in `E32-F04.spec.md` maps to a concrete test in
> `tests/test_feedback_labeler.sh` (the suite `tools/run-tests.sh` picks up by glob). The

## Discrimination requirements (the Reviewer mutates these)

**Any negative must ship with a positive control on its own shape.** The middle predicate, run
alone against the pristine artifact, must match ≥1 line (or the block extractor must return a
non-empty result of the expected length) — otherwise the `fail` branch is unreachable for
every input (lessons 2026-09-16 "dead two-stage negative", 2026-09-17 "count the assertions").

- **R1:** extract the `on:` block (column-0 `on:` to the next column-0 key, blank/comment lines
  dropped) and assert **full-string equality** with the three pinned lines
  (`on:` / two-space `issues:` / four-space `types: [opened]`). Do **not** assert "does not
  contain `edited`" — a mutation that *adds* `edited` must change the exact string and red.
  Positive control: the extractor returns ≥3 lines (a renamed/removed `on:` key reddens the
  guard before any equality check). Mutations to run: add `edited` to `types:`; add
  `workflow_dispatch:`; delete the `types:` line; move an unrelated workflow's `on:` block in
  (the block must be isolated to THIS file).
- **R2:** assert the extracted `run:` block contains **no** `${{` (positive control: the whole
  file does contain `${{` in `env:`). Assert the set of `github.event.issue.<field>` tokens,
  `sort -u`, equals exactly `github.event.issue.number` (positive control: the extraction is
  non-empty). Assert `github.event.comment` occurs 0 times (positive control: `github.event`
  occurs ≥1 time so the search token space is live). Assert the body reaches the parser as a
  file: with `GITHUB_EVENT_PATH` pointing at a fixture JSON payload, `label-issue` reads
  `.issue.body` into the temp file and records **no** `api repos/<repo>/issues/<n>` fetch; with
  `GITHUB_EVENT_PATH` unset it falls back to `gh api "repos/<repo>/issues/<n>" --jq .body`. In
  either arm the body never appears as an argv token. Mutations: add
  `${{ github.event.issue.body }}` to `env:` of the step and to a `run:` line; add
  `github.event.issue.title`; read the body as a shell word instead of into a file; drop the
  API fallback; make the API the primary and ignore the snapshot (a later edit could then
  reclassify — the R1 intent).
- **R3:** extract the `permissions:` block and assert full-string equality with the two pinned
  lines (order as written), plus every `uses:` value matches `@[0-9a-f]{40}$`. Positive
  controls: the `permissions:` block extracts to exactly 3 lines and at least one `uses:` line
  exists. Mutations: add `contents: write`; drop `contents: read`; shorten the SHA to a tag
  (`@v4`); add a second `uses:` without a SHA.
- **R4:** assert `parse` output **full-string equality** against the expected multi-line label
  set (`harness-feedback`/`bug`), not a substring or a single grep over joined output. Use a
  fixture whose first line is the exact emitted marker. Mutations: swap `host` and `version`
  order; drop a field; double the spaces; change `v1` to `v2`; prefix the line with a space.
  Positive control: the fixture file's first line matches the grammar when read alone.
- **R5:** one fixture per rejection shape, each asserting (a) `parse` prints **zero** bytes
  (not just "no `bug`"), (b) `label-issue` records zero `label create`, zero `issue edit`, and
  zero `issue comment` calls, (c) exit 0. Shapes: no marker; marker on line 2; `v2` marker;
  missing `trigger`; extra field; bad trigger; non-semver `version`; and a valid marker plus a
  second `harness-feedback:` token on a later line. Positive control: the same fixture harness
  with a valid marker **does** produce a label set and one `issue edit` (so the zeroes are not
  the only possible outcome). Mutations: relax the grammar to a substring match; drop the
  second-marker check; accept a `v2` token.
- **R6:** four fixtures, one per trigger, each asserted by full-string equality of the label
  set. A mutant that maps `missing-capability` to `bug`, or drops `harness-feedback`, or maps
  any of the other three to `enhancement`, must red. Positive control: all four fixtures are
  grammar-valid first lines.
- **R7:** fixture bodies that carry `$(touch "$CANARY")`, backticks around a `touch`, a `;`-run
  command, `${{ github.event.issue.body }}` text, and an embedded-newline "field" attempt. Run
  `parse` and `label-issue`; assert the canary file was not created, **and** assert the canary
  string is present in the fixture file (positive control on the search shape). Assert the
  resulting label set equals the first-line marker's set when line 1 is valid, and is empty when
  the forged marker is the only marker. Mutations: pipe the body into `sh -c`; `eval` the first
  line; use the body as a label value.
- **R8:** stub the label probe to yield three distinguishable outcomes: a definitive **present**
  (`200` / an exact `label list` hit), a definitive **absent** (`404` / an empty list), and a
  **hard error** (`500` / non-zero). One label in the set is present, the other absent: assert
  exactly one `label create` with the pinned color/description for the absent one, and **zero**
  create/update for the present one. Separately, stub the probe to a hard error and assert
  `label-issue` exits non-zero with **zero** `label create` calls — a transient error must not be
  read as "absent". Positive control: a run where both labels are absent creates both.
  Mutations: create with `--force` (would update an existing label); create every label
  unconditionally; collapse present/absent/error into "probe failed ⇒ absent".
- **R9:** record argv and assert the `issue edit` call's `--add-label` value is the full comma
  list in the pinned order, and that `issue comment` appears **zero** times. Positive control:
  the same log contains ≥1 `issue edit` call. Also make the body read fail (unreadable
  `GITHUB_EVENT_PATH` snapshot and a non-zero `gh api` fallback) and assert `label-issue` exits
  non-zero with zero `issue edit`/`issue comment` calls. Mutations:
  post a comment; issue two `edit` calls (one label each) where the contract says one; reorder
  the list; swallow a failing body read with `|| true`.
- **R10:** assert `harness-install.sh` contains no `feedback-labeler` and no `.github/workflows`
  reference; positive control: `harness-install.sh` **does** reference `harness-report.sh`
  (F02's installed tool), proving the grep is live. Assert the two source paths exist. For the
  no-bump clause: diff `VERSION` and `CHANGELOG.md` against `origin/main` (else `main`) and
  require an empty name list; when neither ref resolves, mark N/A and say so in the log — do
  not treat it as a pass. Mutation: add a `chmod +x` entry for the labeler script to
  `harness-install.sh`.
- **R11:** assert **both** `[ -x .github/scripts/feedback-labeler.sh ]` (the worktree bit) and
  the tracked mode via `git ls-files -s` showing `100755` (the committed contract) — a bare
  `chmod -x` and a `git update-index --chmod=-x` are two different mutants and each must red
  its own arm (E99-F164). Assert `sh -n` parses it under the strict shell, and that `parse`
  drives from a fixture with `PATH` stripped of `gh` (proving no GitHub access is needed).
  Mutations: remove the worktree executable bit; strip it in the index; break the `parse` mode
  name. The declaration arm is proved by the **existing** `test_install.sh` derived-set
  equality: delete the `.github/scripts/feedback-labeler.sh` token from `_sse_expected` and that
  suite must red "derived set includes undeclared script(s)" — run it standalone to confirm the
  edit is load-bearing.

## Behavioral / end-to-end checks

- Reviewer runs `sh .github/scripts/feedback-labeler.sh parse <fixture>` by hand for one valid
  and one invalid body and reads the output.
- Reviewer confirms the workflow file is valid YAML by inspection and that GitHub would see
  `issues: opened` — the suite's static extraction is the enforced proxy, since no sandbox runs
  Actions here.
- Reviewer confirms no comment path exists in the script (`grep -n 'issue comment'` → 0;
  positive control: the script contains `issue edit`, so the search space is live).

## Non-functional checks

- `./init.sh` green; `./tools/run-tests.sh` green, reporting the strict shell used — including
  the existing `tests/test_install.sh::test_source_scripts_are_executable`, which stays green
  only because `.github/scripts/feedback-labeler.sh` is declared in its `_sse_expected` set.
  Re-run any unrelated red suite alone before chasing it (lessons 2026-09-05, 2026-09-16).
- Fixture bodies for this feature are written under the suite's `mktemp -d` tree at run time;
  nothing is committed under the frozen `tests/fixtures/**` tree.
- The new suite and script are POSIX `sh`, executable, and dash-clean; `sh -n` clean under the
  strict shell. No entry is added to `tests/dash-allowlist.txt`.
- No `VERSION` bump and no `CHANGELOG.md` entry (R10) — CI-only change per AGENTS.md.
- `sh harness-install.sh --self` produces no generated-glue diff (this feature emits no glue).
- No test makes a network call; every `gh` is the stub. No test writes outside its `mktemp`
  tree.
- The new suite slivers no Markdown, so it does not need the shared `fence_delim()` helper
  (`tests/test_change_size.sh` R9d); if a future revision slices Markdown, it must call it.
