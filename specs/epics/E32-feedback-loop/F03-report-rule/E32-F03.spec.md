# Reporting rule + `/sdd-report` command — Functional Spec

> R-ids in this document are `R1 … R11`; their fully-qualified form is `E32-F03:R1 … E32-F03:R11`.

## Context

E32 closes the harness feedback loop. **F01** shipped the `feedback:` switch, **F02** shipped
the deterministic reporter `tools/harness-report.sh` (allow-listed fields, versioned body
marker, duplicate search, per-session cap, `progress/feedback/` fallback), and **F04** shipped
the labeler Action. None of them decides **when** to report: the tool is inert until something
calls it. This feature supplies that "when" — a short reporting rule on every front-end
surface and a `/sdd-report` (`$sdd-report` in Codex) command that drafts the structured report
and calls F02's tool.

The users are the agents and operators of every installed harness: a session that hits a
harness defect must (a) notice it is one of the four narrow triggers rather than a project
failure, and (b) file it at a defined moment — end of task, or early stop — without a human
in the loop. The privacy and filing mechanics are F02's; **this feature owns only the prompt
glue that invokes them**, and must not redesign the tool. The expedient shape — every role
calling the reporter ad hoc — is deliberately rejected: F02's per-session cap and duplicate
search are single-writer, so exactly one role files, and sub-agents merely leave notes.

**Complexity basis (`complex`).** Four signals, all from this feature's own design:
(1) it presses the budget — 11 R-ids of the configured `change_size.max_requirements: 12`,
one seam short of a split; (2) it must honor **ADR-0003** end-to-end — one shared
`.agents/skills/sdd-report/` unit plus the `.claude/`/`.opencode/` mirrors, with the
installer's emit *and* reclaim loops, `--self` regeneration and the `.glue-manifest` all
moving together; (3) it carries the defect class this harness has repeatedly paid for — a
generated artifact diverging from its emitter, and a validator (F02's `_shipped_sdd_cmds`)
disagreeing with its consumer (the installer's command lists) — and adds a second instance:
F03 adds a command that F02's allow-list must learn or its convergence test reds; (4) the
release sweep crosses features — `VERSION` is pinned as a literal by three existing suites,
and adding a command shifts the committed glue a fourth (`test_self_drift.sh`) byte-compares.

## Business rules

- **The four triggers are F02's vocabulary, verbatim:** `harness-malfunction`,
  `contradictory-instruction`, `workaround`, `missing-capability`. F03 never invents a fifth
  and never renames one.
- **The non-triggers are as binding as the triggers.** Failures of the project's own code or
  tests, transient network or auth errors, and agent mistakes the harness correctly caught
  are **never** reported.
- **File late, never mid-flow.** A report is filed when the task ends or when the session
  stops early (aborted, parked, or failed) — because a harness malfunction is most likely to
  fire on an early stop — and never in the middle of a build.
- **Single writer.** Only the **session-owning top-level role** files: the Orchestrator, or
  Fixer / Inception / Planner / Driller when it owns the session. Sub-agents (Architect,
  Builder, Reviewer, Scout, Doc-critic, pr-fixer) append trigger notes under `progress/feedback/` for
  the owning role to pick up; they never invoke the reporter. That is what keeps F02's
  per-session cap and duplicate search single-writer.
- **`/sdd-report` is a target surface, emitted normally.** It ships to Claude, Codex, and
  OpenCode through the existing emitters (ADR-0003), like every other `HARNESS_SDD_CMDS`
  unit — it is **not** a source-only `--self` surface (that is `/sdd-triage`, ADR-0005).
- **The command drafts; F02 files.** `/sdd-report` assembles only allow-listed structured
  fields, supplies **at least one harness-owned `--file`** (F02 files nothing upstream without
  one), and calls `tools/harness-report.sh`. Free-form text is never sent upstream: it is
  passed via the local-only `--notes-file` so it lands in F02's `progress/feedback/` copy. The
  command does not re-implement redaction, marker, duplicate search, or the cap.
- **One token per session.** The session-owning role mints `HARNESS_FEEDBACK_SESSION_ID` once
  and reuses it for every report in the session, so F02's per-session cap ledger is coherent;
  `/sdd-report` owns a grammar-safe fallback for the `init.sh` hard-stop path, where no
  `session-start` marker exists.
- **`init.sh` gets exactly one narrow exception, and only reporting.** Advisory "STOP and
  report" gains the right to make **one** reporter call as the report, then stop. That call
  makes no repair and no board write, and the session does not continue — reporting is never
  a way around the gate.
- **Reporting never blocks or fails the task.** Consistent with F02, a missing/unauthenticated
  `gh`, a duplicate, a capped session, or a bad field degrades to a local copy and exit 0.
  F03's rule must not turn that into a task failure.
- **Short rule text.** The rule is a few lines in `AGENTS.md` and one line per role prompt;
  role prompts are a context budget and the rule must not crowd out the role contract.

## Architecture alignment

`specs/architecture.md` is **absent** in this repo; the ADR set is present and cited below.
There is exactly one ADR namespace (`specs/adr/`), cited as `platform`.

- **platform ADR-0003** — one shared `.agents/skills/<name>/` unit per command, claimed by
  every front end that reads it: `/sdd-report` is emitted as one shared
  `.agents/skills/sdd-report/` unit (SKILL.md + its `agents/openai.yaml` policy companion)
  with the `.claude/commands/` and `.opencode/command/` mirrors off the same canonical body,
  and it joins `HARNESS_SDD_CMDS` so the existing emit/reclaim loops manage it unchanged
  (R7, R10).
- **platform ADR-0004** — a child resolves the body through pointer stubs at the same paths:
  the rule lives in the **prose tier** (`AGENTS.md`, `agents/*.md`), which a thin umbrella
  child resolves to the umbrella's authoritative copy; the command bodies and `tools/` stay
  in the standalone tier exactly as F02 left them (R5, R6).
- **platform ADR-0006** — the versioned body marker is the only reporter↔triage contract:
  F03 does not touch the marker. It only decides *when* to call the reporter; the marker,
  allow-list, and redaction remain F02's, so reporter and triage cannot drift through this
  feature (R8).
- **platform ADR-0005** — source-only surfaces are emitted only under `--self`, never into a
  target: `/sdd-report` is explicitly a **target** surface and is emitted normally to every
  selected front end. Only its identity as a non-source-only surface is in scope; the
  source-only `/sdd-triage` stays F05's (R7).

## Acceptance criteria (EARS)

- **R1** — The harness source `AGENTS.md` shall carry a short reporting rule that names the
  four reportable conditions with the exact F02 trigger tokens `harness-malfunction`,
  `contradictory-instruction`, `workaround`, and `missing-capability`, gives each a one-clause
  gloss of its semantics — `harness-malfunction` (a harness script such as `init.sh`,
  `harness-install.sh`, `tools/*`, or a TaskStore write fails while the project itself is
  healthy), `contradictory-instruction` (role prompts or docs conflict, or a gate cannot be
  satisfied as written), `workaround` (the agent had to leave the documented workflow to
  finish), and `missing-capability` (a recurring situation has no path in the workflow) — and
  states that these are the only reportable conditions.
- **R2** — The rule shall name exactly the three non-trigger categories — a failure of the
  project's own code or tests, a transient network or auth error, and an agent mistake the
  harness correctly caught — and shall state that none of them produces a report.
- **R3** — The rule shall state that a report is filed when the task ends **or** when the
  session stops early (aborted, parked, or failed), and that a report is never filed
  mid-flow.
- **R4** — The rule shall name only the **session-owning top-level role** (the Orchestrator,
  or Fixer / Inception / Planner / Driller when it owns the session) as the role that invokes
  the reporter, and shall direct every sub-agent (Architect, Builder, Reviewer, Scout,
  Doc-critic, pr-fixer) to append trigger notes to `progress/feedback/notes.md` in a fixed entry format
  (the trigger token, plus the symptom / command / phase fields the reporter accepts) and
  never to invoke the reporter itself.
- **R5** — Each session-owning top-level role prompt under `agents/` (`orchestrator.md`,
  `fixer.md`, `driller.md`, `planner.md`, `inception.md`) shall carry the end-of-task /
  early-stop filing duty and the `/sdd-report` invocation, and each sub-agent role prompt
  (`architect.md`, `builder.md`, `reviewer.md`, `scout.md`, `doc-critic.md`, `pr-fixer.md`)
  shall carry the `progress/feedback/notes.md` note duty and the prohibition on invoking the
  reporter.
- **R6** — While any one of `claude`, `codex`, or `opencode` is selected, the installed body
  (`.harness/AGENTS.md` and `.harness/agents/<role>.md`) shall carry the reporting rule, and
  that front end's generated artifact shall resolve it (Claude `.claude/agents/<role>.md`
  → `.harness/agents/<role>.md`; Codex `.codex/agents/<role>.toml` → `.harness/agents/<role>.md`;
  OpenCode `opencode.json` → `.harness/agents/<role>.md` and `instructions` →
  `.harness/AGENTS.md`), so the rule reaches all three front ends through the existing
  emitters and no emitter re-implements it.
- **R7** — The `sdd-report` command shall be added to the installer's `HARNESS_SDD_CMDS`
  emitted set and shall ship to each selected front end through the existing emitters:
  `.claude/commands/sdd-report.md` for `claude`, `.opencode/command/sdd-report.md` for
  `opencode`, and the shared `.agents/skills/sdd-report/SKILL.md` with its
  `agents/openai.yaml` policy companion for the claiming set `{codex, opencode}`; running
  `sh harness-install.sh --self` shall regenerate the committed source copies plus
  `.claude/.glue-manifest`, and no `.claude/*` file shall be hand-edited.
- **R8** — The `/sdd-report` command body shall instruct the agent to draft the structured
  report from the trigger note(s) and direct evidence and to call `tools/harness-report.sh`
  with only allow-listed **upstream** fields (`--trigger`, `--symptom`, `--file`, `--command`,
  `--exit-code`, `--role`, `--phase`), and shall state all three of:
  - **at least one harness-owned `--file` is required** — F02 rejects the whole report to a
    local copy when no supplied path is harness-owned (F02 R5), so the body must pass one
    (`init.sh` for the `init.sh`-failure path; otherwise the failing harness tool's own
    concrete tracked body path — e.g. `tools/harness-report.sh`, `init.sh`, or
    `harness-install.sh`; never an `sdd-*` command basename such as `sdd-next`);
  - the session token is passed via `--session-id` as `HARNESS_FEEDBACK_SESSION_ID`, minted
    **once per session** by the session-owning role as a token matching F02's
    `^[A-Za-z0-9._-]{1,64}$` grammar (origin in Open questions), with the command's own
    grammar-safe fallback when the variable is unset and a persisted fallback value
    re-validated against that grammar before reuse — so the per-session cap ledger is not
    silently bypassed and no report degrades to F02's `no-session` path for want of a token;
  - free-form text reaches F02's local `progress/feedback/` copy via `--notes-file` and is
    never sent upstream — it is local-only, not one of the allow-listed upstream fields.

  It shall name F02's fixed symptom vocabulary (at minimum mapping an `init.sh` failure to
  `init-failure`) and shall not re-implement any F02 mechanism.
- **R9** — The `AGENTS.md` "STOP and report" rule for a non-zero `init.sh` exit shall gain
  exactly one narrow exception: when that non-zero exit is a harness malfunction, the session
  may call F02's reporter **once** (trigger `harness-malfunction`) as the *report*, and then
  stops — the rule shall state that the call makes no repair and no board write, that the
  session does not continue, and that reporting is never a way around the gate.
- **R10** — `tools/harness-report.sh`'s `_shipped_sdd_cmds` allow-list shall include
  `sdd-report`, so `/sdd-report` is accepted as a `--command` value. F03's suite asserts the
  membership of `sdd-report` in both the tool's allow-list and the installer's
  `HARNESS_SDD_CMDS`; the full-set equality of the two lists stays owned by F02's
  `tests/test_feedback_report.sh::test_shipped_command_set_converges`, which must remain green.
- **R11** — The change shall bump `VERSION` by one MINOR step from `0.86.0` to `0.87.0`, add
  a `CHANGELOG.md` `## [0.87.0]` entry naming reporting going live, update the
  `docs/INSTALL.md` feedback section so it states reporting is live (the report tool ships
  *and* the triggers call it; no "inert until E32-F03" sentence remains), update `README.md`'s
  Supported-CLIs table (and its `$sdd-*` sentence) to list `/sdd-report`/`$sdd-report`, and
  sync every current-version literal and base-relative test coupling the bump/release breaks
  (`tests/test_codex_native.sh`, `tests/test_feedback_config.sh`, and
  `tests/test_feedback_report.sh`, including its pristine-bytes control), leaving the full
  `sh tools/run-tests.sh` suite green.

## Out of scope

- The filing mechanics themselves — redaction, marker, duplicate search, per-session cap,
  `progress/feedback/` fallback (E32-F02, done).
- The `harness-feedback` label mapping / GitHub Action (E32-F04, done) and
  `/sdd-triage` (E32-F05).
- Any change to the `feedback:` config block or its resolution contract (E32-F01).
- New trigger vocabulary, new symptom codes, or an extension of the redaction corpus.
- Telemetry or usage analytics; any channel other than GitHub issues.
- Retrying a report that fell back to `progress/feedback/`.

## Open questions

- None blocking. The brief's open question — *the exact `progress/` location/format of
  sub-agent trigger notes* — is resolved here: `progress/feedback/notes.md`, an append-only
  ledger under F02's already-gitignored directory, with one entry per event carrying the F02
  trigger token plus the symptom / command / phase fields the reporter accepts (R4).
- The brief's carried question — *which session token F03 supplies and how it obtains it* —
  is resolved here (R8), concretely and grammar-first:
  - The **session-owning role mints `HARNESS_FEEDBACK_SESSION_ID` once per session** and
    exports it, so every `/sdd-report` in that session shares one token and F02's per-session
    cap ledger is coherent (a fresh token per call would reset the cap).
  - The minted value matches F02's `^[A-Za-z0-9._-]{1,64}$` grammar. Its origin is the
    telemetry `session-start` marker's `started_at` with every character outside
    `[A-Za-z0-9._-]` removed — `2026-06-06T09:00:00Z` → `2026-06-06T090000Z` (the hyphens are
    inside the retention set and are kept; only the `:` are dropped).
  - On the **`init.sh` hard-stop path** there is no `session-start` marker for the current
    session (the marker is written only after `init.sh` passes), so the role mints the token
    from the current UTC stamp `date -u +%Y%m%dT%H%M%SZ` (already grammar-safe:
    `20260925T201500Z`); the same expression is `/sdd-report`'s fallback when
    `HARNESS_FEEDBACK_SESSION_ID` is unset. A report therefore never degrades to F02's
    `no-session` path for want of a token.
