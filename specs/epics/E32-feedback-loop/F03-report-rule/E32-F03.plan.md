# Reporting rule + `/sdd-report` command — Technical Plan

> Translates `.spec.md` intent into design. Every decision cites the R-id(s) it serves. The
> Builder picks internals not pinned here — start high-level; do not over-specify prose.

## Stack & dependencies  (serves: R1–R11)
- POSIX `sh` for the installer change and the new test suite (dash-clean; `tools/run-tests.sh`
  picks the strictest probeable shell). Markdown for the rule and role prompts.
- No new runtime dependency. `/sdd-report` is a prompt-level command that invokes the
  already-shipped `tools/harness-report.sh` (F02). No new tool, no new config key.
- Tests use the house style of `tests/test_feedback_config.sh` / `test_feedback_labeler.sh`:
  zero dependencies, self-cleaning `mktemp` tree, `fail`/`pass`, `CODEX_HOME` sandbox, and
  `tests/lib/fence.awk` for any markdown heading slice (see Approach notes).

## Surfaces & content contract  (serves: R1–R6, R8, R9)

### The rule — one short section in `AGENTS.md`, pointers in the role prompts

Add a `## Reporting harness defects` section to the source root `AGENTS.md` (which installs
verbatim as `.harness/AGENTS.md`). It must carry, in a few lines:

- the four F02 trigger tokens verbatim and "these are the only reportable conditions" (R1);
- the three non-trigger categories and "no report" (R2);
- file at **end of task** or on **early stop** (aborted / parked / failed), **never
  mid-flow** (R3);
- **only the session-owning top-level role** invokes `/sdd-report`; sub-agents append notes
  to `progress/feedback/notes.md` and never invoke the reporter (R4).

The note ledger format (pinned so the top-level role can read it and the test can assert it):
append-only `progress/feedback/notes.md`, one entry per event, each entry a `## <trigger>`
heading (one of the four tokens) followed by the allow-listed reporter fields
`symptom:` / `command:` / `phase:` (and an optional harness `file:`). It lives under F02's
already-gitignored `progress/feedback/`, so no ignore change is needed.

In `AGENTS.md`'s **Start every session** step 1, extend the existing "STOP and report"
sentence with the one exception (R9): on a non-zero `init.sh` exit that is a harness
malfunction, the session may call F02's reporter **once** (trigger `harness-malfunction`) as
the report, then stop — no repair, no board write, no continuation, and never a way around
the gate. Keep it to the existing bullet.

Role-prompt edits, one short line or bullet each (R5):

| Role class | Files | Line to add |
|---|---|---|
| Session-owning top-level | `agents/orchestrator.md`, `agents/fixer.md`, `agents/driller.md`, `agents/planner.md`, `agents/inception.md` | at end-of-task/early-stop, if a trigger fired, invoke `/sdd-report`; you are the only filer. |
| Sub-agent | `agents/architect.md`, `agents/builder.md`, `agents/reviewer.md`, `agents/scout.md`, `agents/doc-critic.md`, `agents/pr-fixer.md` | on a trigger, append a note to `progress/feedback/notes.md`; never invoke the reporter. |

`agents/builder-heavy.md` needs no edit — it delegates to `agents/builder.md`. Do not add a
second copy of the rule.

### The command — `.claude/commands`, `.opencode/command`, shared skill unit  (serves: R7, R8)

Add a canonical body in `harness-install.sh`'s command-body block, beside the others:

```sh
cat > "$CMDDIR/sdd-report.md" <<'EOF'
---
description: File a harness-feedback report through tools/harness-report.sh for one of the four triggers
---
...
EOF
```

The body (installed layout uses `.harness/` paths; `--self` strips the prefix) must:

1. Identify the trigger from `progress/feedback/notes.md` and direct evidence, and refuse a
   non-trigger (R2, R8).
2. Pick the symptom from F02's fixed nine-code vocabulary, mapping an `init.sh` failure to
   `init-failure` (R8). Do not invent codes.
3. Call `.harness/tools/harness-report.sh` with the allow-listed upstream flags —
   `--trigger`, `--symptom`, `--file` (harness-owned), `--command`, `--exit-code`, `--role`,
   `--phase` — and **at least one harness-owned `--file`** (`init.sh` for the `init.sh`-failure
   path; otherwise the failing harness tool/path, e.g. `tools/harness-report.sh`). F02 rejects
   the whole report to a local copy when no supplied path is harness-owned (F02 R5), so a body
   without one never files upstream (R8).
4. Pass `--session-id "$HARNESS_FEEDBACK_SESSION_ID"`, falling back to
   `--session-id "$(date -u +%Y%m%dT%H%M%SZ)"` when unset. The variable is minted **once per
   session** by the session-owning role, with the telemetry `session-start` `started_at`
   normalized to F02's grammar (`2026-06-06T09:00:00Z` → `20260606T090000Z`); the `date -u`
   form is the grammar-safe origin for the `init.sh` hard-stop path, where no `session-start`
   marker exists (R8). Never leave the token unset — F02 fails closed to a local copy.
5. Pass the free-form summary through the local-only `--notes-file` (a temp file), so it
   reaches F02's `progress/feedback/` copy; state that it is never an upstream field and never
   sent to `gh` (R8).
6. Do not re-implement redaction, the marker, the duplicate search, or the cap (R8).

### Front-end parity  (serves: R6)

The rule needs no per-front-end emitter. The chain that already exists:
- Claude `.claude/agents/<role>.md` → `.harness/agents/<role>.md`;
- Codex `.codex/agents/<role>.toml` `developer_instructions` → `.harness/agents/<role>.md`;
- OpenCode `opencode.json` `agent.*.prompt` = `{file:./.harness/agents/<role>.md}` and
  `instructions` = `.harness/AGENTS.md`.

Because the rule lives in `AGENTS.md` + `agents/*.md` — the body every front end reads — one
edit reaches all three. The test asserts the chain resolves on each selection, not that any
emitter duplicates the text.

## Approach notes

- **The release sweep is load-bearing, not cosmetic (serves R11).** Three existing suites pin
  the CURRENT `VERSION` as a literal (`tests/test_codex_native.sh:283`,
  `tests/test_feedback_config.sh:438`, `tests/test_feedback_report.sh:744`) — the documented
  "current-version literal" anti-pattern. A MINOR bump reds all three; sync each literal and
  its pass message, but **never** touch the historical CHANGELOG-heading anchors
  (`## [0.85.0]`, `## [0.86.0]`) or the deliberate `0.86.0-rc1` non-semver fixture
  (`test_feedback_report.sh:183`), which stay as-is.
- **The F02 pristine-bytes control needs re-anchoring, not deletion (serves R11).**
  `test_feedback_report.sh` R12 currently asserts the pre-change base carries
  `No reporter ships yet` whenever the base differs from the working `docs/INSTALL.md`. That
  phrase is already gone from `origin/main`, so the first feature to edit `docs/INSTALL.md`
  (this one) reds it. Re-anchor the control on the F02 sentence F03 actually removes
  (`Reporting stays inert until … E32-F03 …`) **and make the liveness half self-limiting**:
  enforce it only while the base actually carries the anchored pre-change sentence, and report
  N/A once a base no longer does. A plain re-anchor alone merely moves the landmine to the next
  `docs/INSTALL.md` edit (after F03 merges, that sentence is gone from `main`, so the following
  docs feature reds the same control); the self-limiting form is what makes it safe beyond this
  edit. Record the reason in the suite comment.
- **R10 defers full-set equality to F02 (serves R10).** F03's suite asserts only that
  `sdd-report` is present in `tools/harness-report.sh`'s `_shipped_sdd_cmds` and in
  `HARNESS_SDD_CMDS`; the existing `test_feedback_report.sh::test_shipped_command_set_converges`
  owns full-set equality and must stay green (the full suite runs it). Do not duplicate the
  whole-set predicate in the new suite.
- **`--self` is the only writer of committed glue.** After changing the emitter, run
  `sh harness-install.sh --self` and commit `.claude/commands/sdd-report.md`,
  `.opencode/command/sdd-report.md`, `.agents/skills/sdd-report/*` and
  `.claude/.glue-manifest`. `tests/test_self_drift.sh` diffs regenerated against committed
  glue byte-for-byte; a hand-edited `.claude/*` or a forgotten regeneration reds it.
- **New test suite must satisfy repo-wide conventions (serves R1–R11).**
  `tests/test_change_size.sh` R9d requires every markdown heading slicer to call the shared
  `fence_delim()` from `tests/lib/fence.awk` — build `_section`-style helpers on that (see
  `tests/test_feedback_config.sh`). Run `sh tests/test_change_size.sh` standalone after
  authoring the suite, per the E32-F01 lesson.
- **Prompt-contract tests are mutation-shaped (serves R1–R11).** Extract the exact rule
  section / role file / command body and assert the pinned anchors *inside that span*, each on
  its own surface, so the Reviewer can mutate one surface (AGENTS.md, one role file, the
  command body, the installer wiring) at a time. Every negative ships a positive control on
  its own shape.
- **Dash-clean, `set -eu`-safe (serves R1–R11).** `var="$(pipeline-that-can-match-nothing)"`
  aborts silently under `set -e`; use `|| true` on such assignments. Never invoke a
  bash-shebang script via `sh`.
- **Order (serves R1–R11):** rule + role prompts first (R1–R5), then the command wiring +
  `--self` (R6–R8), then the init.sh exception (R9), then the F02 allow-list (R10), then the
  release sweep (R11), then tests.
