# Reporting rule + `/sdd-report` command — Test Contract

> Every R-id in `E32-F03.spec.md` maps to a concrete test in
> `tests/test_reporting_rule.sh` (the suite `tools/run-tests.sh` discovers by its
> `tests/test_*.sh` glob). The Reviewer fails the feature if any R-id lacks a passing test.
> Every check is a **prompt-contract** check — no LLM runs, no network. Fixture scenarios are
> the per-trigger and per-non-trigger assertions extracted from the rule/command spans, plus
> real installer runs into temp targets for the emitted surfaces.

## Fixture scenarios (per trigger and per non-trigger)

Each of the four triggers gets a positive scenario and each non-trigger a negative scenario,
asserted inside the spans the rule owns (the `## Reporting harness defects` AGENTS.md slice,
the role-prompt lines, and the installed `/sdd-report` body):

| Scenario | Fixture | Assertion |
|---|---|---|
| harness malfunction | token `harness-malfunction` + `init.sh` non-zero | present in R1 span; command maps to `init-failure` and passes `--file init.sh` (R8); exception permits exactly one call (R9) |
| contradictory instruction | token `contradictory-instruction` | present in R1 span |
| workaround | token `workaround` | present in R1 span |
| missing capability | token `missing-capability` | present in R1 span |
| project code/test failure | phrase naming the project's own code/tests | present **only** in the R2 non-trigger span; no report stated |
| transient network/auth error | phrase naming transient network/auth | present **only** in the R2 span; no report stated |
| agent mistake the harness caught | phrase "correctly caught" / equivalent | present **only** in the R2 span; no report stated |

A non-trigger token must never satisfy the R1 trigger set (and vice versa): the two spans are
extracted separately, so a rule that collapses them into one list reds at least one of R1/R2.

Two R8 fixture scenarios exercise the invocation shape (not an LLM run): the `init.sh`
scenario must yield `--trigger harness-malfunction --symptom init-failure --file init.sh`
with a grammar-valid `--session-id`; and a session-token scenario **executes** the command's
marked minting span twice, a second apart, against a fixture telemetry log — asserting one
stable token derived from the latest `session-start` marker, the exported env value
preferred, and a grammar-safe `date -u +%Y%m%dT%H%M%SZ` fallback when no marker exists — so a
per-call `date` token that would reset F02's `.session-count` cannot pass by prose alone.

## Behavioral / end-to-end checks

- Install the real installer into a temp target with `--agents=claude`, then `codex`, then
  `opencode`; each selection's `.harness/AGENTS.md` equals the source `AGENTS.md`, the body
  rule anchors are present, and the front-end artifact resolves the body
  (Claude shim → `.harness/agents/<role>.md`; Codex toml `developer_instructions` →
  `.harness/agents/<role>.md`; `opencode.json` `{file:./.harness/agents/<role>.md}` and
  `instructions` `.harness/AGENTS.md`) (R6).
- The same three installs each contain the `/sdd-report` surface for that front end; a copy of
  the source tree run through `sh harness-install.sh --self` produces the three source glue
  files and a `.claude/.glue-manifest` listing them (R7).
- `tests/test_self_drift.sh` (existing, run by the full suite) proves the committed glue
  equals regenerated glue byte-for-byte **and** its manifest ledger lists
  `.claude/commands/sdd-report.md` and the `sdd-report` skill units. The byte-diff alone
  cannot see a hand edit to `.claude/commands/` (the fixture inherits that dir and `--self`
  leaves an edited file unclaimed), so the ledger is what pins a hand-edited
  `.claude/commands/sdd-report.md` — and the diff pins a forgotten regeneration (R7).

## Discrimination requirements (the Reviewer mutates these)

- **R1/R2 — mutate each trigger token and each non-trigger phrase separately, in the AGENTS.md
  span only.** A single combined mutation can be masked by the other list. Each R1/R2 check
  must first assert its extracted span is non-empty (length floor) and must run the middle
  predicate alone against the pristine file so the negative is not a dead predicate
  (`progress/lessons.md` 2026-09-16, "two-stage negative"). Positive control: the pristine span
  matches each anchor.
- **R3 — assert both filing moments and the polarity anchor ("never … mid-flow") as separate
  clauses.** Deleting only the early-stop branch or only "aborted/parked/failed" must red.
- **R4 — mutate the note path, the filer clause, and the sub-agent prohibition separately.**
  Removing "never invoke" while keeping the note path must red.
- **R5 — mutate each role file independently.** A whole-corpus grep is not enough: a rule
  restored to `AGENTS.md` but deleted from one role prompt must red on that role's own
  assertion (the E28-F02 per-surface lesson). Positive control per role file.
- **R6 — mutate `AGENTS.md` and one `agents/<role>.md` separately, then each front end's
  artifact separately.** A rule present in the body but with a front end no longer resolving
  it must red on that front end's chain assertion.
- **R7 — mutate the installer wiring (`HARNESS_SDD_CMDS` entry), then the command body, then
  the `--self` glue, separately.** Deleting the entry from `HARNESS_SDD_CMDS` must red the
  emitted-surface assertions and the deselect/reclaim behavior; a stale committed glue file
  with a correct emitter must red `test_self_drift.sh`. The emitted-surface test must DELETE
  each target's inherited copy first (a copied fixture inherits the artifact — the
  `progress/lessons.md` 2026-09-05 lesson).
- **R8 — mutate the tool path, the `--file` requirement (and its concrete-tracked-body-path
  shape: replacing it with an `sdd-*` command basename must red too), the optional-field clauses
  (`--command` / `--exit-code` / `--phase`), the `--session-id` token wiring and its
  once-per-session stability, the `date -u +%Y%m%dT%H%M%SZ` fallback, the read-back grammar
  guard on a persisted token, the `--notes-file`
  local copy, the `init-failure` mapping, and the free-form-off-upstream clause separately.**
  A body that reads well but drops `--file` (F02 rejects → silent local-only) or drops
  `--session-id` must red; so must a body whose token expression is rejected by F02's grammar,
  one that returns a corrupt persisted `.session-id` verbatim, or one that re-runs `date` on
  every call (execute the marked minting span twice and assert
  one stable token — a body naming `--session-id` but no stable source is insufficient).
  Positive control: the pristine body satisfies each anchor.
- **R9 — mutate the "one call", "no repair", "no board write", and "does not continue"
  clauses separately; assert the exception is scoped to a non-zero `init.sh` harness
  malfunction.** A wording that permits a repair or a board write in the same breath must red.
- **R10 — assert `sdd-report` is a member of the tool's `_shipped_sdd_cmds` and of the
  installer's `HARNESS_SDD_CMDS`; do not duplicate the full-set predicate.** Full-set equality
  is F02's `test_feedback_report.sh::test_shipped_command_set_converges` (run by the full
  suite). Deleting `sdd-report` from either list must red this membership check; deleting it
  from the installer must additionally red F02's equality test.
- **R11 — extract the `## [0.87.0]`, `## Harness feedback` and README Supported-CLIs spans
  before grepping; pin the stale-literal predicate to the exact shape, not a bare `0.86.0`
  grep.** Assert the three coupled suites contain **no** current-version comparison of the
  form `= "0.86.0"` / `=='0.86.0'` (nor a pass message naming `0.86.0` as the current
  release), while `## [0.85.0]`/`## [0.86.0]` historical headings and the deliberate
  `0.86.0-rc1` non-semver fixture case remain byte-intact. Deleting the CHANGELOG entry,
  reverting the INSTALL sentence (or README row), or leaving one current literal un-swept must
  red; the `-rc1` fixture or a historical heading must not false-red.
