# Feedback triage — Technical Plan

## Stack & dependencies

POSIX installer shell, existing Markdown role contracts and Python 3 standard library
for a source-only read helper. Existing authenticated `gh` is the only network client.
No service, database, new package or TaskStore schema change (R1–R12).

## Data model (R3–R11)

- `progress/triage/<run>/issues.json`: complete read snapshot, explicit host/owner/repo,
  issue number/title/body/url and validity diagnostic. Raw public text is untrusted.
- `proposal.md`: each issue, canonical duplicate group and evidence/rationale,
  `fix|new|close`, independently composed intake scope, and optional exact comment and
  closure reason. Invalid markers appear only in the rejection section.
- `actions.md`: proposal revision, human approval scope, per-action pending/started/
  succeeded/failed/uncertain state and returned feature id/URL. This is local progress,
  not a second TaskStore. Persist `started` before a mutation; on resume reconcile
  against the existing brief/board or remote issue before retrying an uncertain action.
  A new invocation creates a distinct run; resuming requires identifying the existing
  run explicitly. Never infer approval from another run or a different proposal revision.
- Inbox brief `## Source issues`: `Repository: <host>/<owner>/<repo>` and
  `Issues: #<positive integer>[, #<positive integer> ...]`, written from approved
  provenance before downstream build dispatch. Append/deduplicate for new's altitude 1.
  Keep prose context separately; do not parse arbitrary issue-body `Fixes` strings.

## API / interface (R3–R5, R11)

Create `.github/scripts/feedback-triage.py` as a source-only, read-only helper:
`python3 .github/scripts/feedback-triage.py --repo <host/owner/repo>` returns a JSON
snapshot on stdout, nonzero with diagnostic on errors. Resolve `feedback.repo` using
F01's existing default/normalization policy in the command guidance; pass explicit
host and repository to every read. Fetch all pages of open labeled issues, excluding
API pull-request records. Missing gh, unauthenticated/read failures, malformed JSON
and page failure are failures, never a successful empty snapshot. Empty success is
explicit. Use subprocess argv, never shell=True/eval or issue-derived command text.

Match the existing F02 v1 grammar and F04 parser behavior exactly: first line is
`<!-- harness-feedback:v1 host=[A-Za-z0-9._-]+ version=[0-9]+\.[0-9]+\.[0-9]+ trigger=(harness-malfunction|contradictory-instruction|workaround|missing-capability) -->`
with whole-line anchoring, and no additional `harness-feedback:` token later in the
body. Unsupported versions, duplicate tokens or malformed fields are rejected.
The marker is identity/classification only. Neither F06 fingerprints nor evidence
section names are a new parser contract. Grouping is an agent judgment backed by
source/evidence inspection, never title-equality alone (R4–R6).

## DO NOT TOUCH

- Reporter, labeler, their marker format and historical specs: consumed unchanged.
- TaskStore schema, selector and lock implementation: existing intake owns writes.
- General target command ownership, model-role roster, unrelated front-end migration:
  no triage wildcard or unconditional owned-command registration.
- Generated glue by hand: changes originate in the installer and --self regeneration.

## Approach notes

**Alternatives (R3–R11).** A prompt-only reader minimizes code but leaves pagination
and marker validation untestable. A full automatic planner/executor duplicates
intake and introduces unnecessary mutation authority. Choose a small deterministic
read helper plus the existing Orchestrator's human-facing triage guidance: parsing is
fixture-testable and judgment/approval stays in the host conversation.

**Emission (R1–R2).** Keep source commands separate from `HARNESS_SDD_CMDS` and the
normal target owned/reclaim union. Only SELF_MODE extends effective emitted/owned
sets. Preserve shared skill atomic policy and last-claimant handling. Test normal
target collision preservation with user-authored triage files, including existing front-end deselection/reclamation.
The helper remains under `.github/`, which is not installed into targets. No new
role definition or named-role/model plumbing is necessary.

**Approval and routing (R5–R9).** Init runs first and halts on failure. Present the
persisted proposal and stop until a human explicitly approves a whole plan or named
subset. A fix proposal explains that `/sdd-fix` continues into Builder→Reviewer by
its existing autonomous default; offer its existing `--gated` choice when requested.
Do not invent seed-only behavior. Invoke fixes sequentially, respecting their merge
and handback boundaries before continuing the batch. `/sdd-new` retains all three
altitudes, Q&A, pending-only behavior and no Architect spawn. Put provenance in the
approved file handoff, then have the intake role persist it before its downstream
handoff. Every delegated role gets fresh context and file-only inputs.

Comments and closes are separate approval items, never implied by approval to seed.
Use structured arguments/body files for external text, not shell interpolation.
A completed intake does not imply its PR merged or the issue closed. Never post a
success comment before intake success. Resume reads actions/proposal; approval is
valid only for unchanged pending actions and a reconcilable repository/issue state.
If scope or state changed materially, re-present for approval (R7, R9, R11).

**Provenance (R10).** Normal PR preparation in Orchestrator consumes only validated
Source issues from the brief, including fix/new handoffs and externally delegated
Builder PR preparation. Carry this requirement in delegated instructions and verify
or update the resulting PR body before review handoff. Deduplicate positive issue
numbers and compare source repository to the actual PR repository. Missing/malformed
or cross-repository provenance yields no `Fixes #N`, with a local diagnostic for
invalid/cross-repository provenance; never close a same-number unrelated issue.
