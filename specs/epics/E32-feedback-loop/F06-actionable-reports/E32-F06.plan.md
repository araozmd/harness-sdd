# Actionable reports — Technical Plan

## Stack & dependencies

Retain POSIX shell reporting and the existing shell/stub-gh tests. Use Python 3
stdlib for bounded JSON parsing, sanitation validation, and SHA-256 if useful; no
new package, network service, or public API dependency. A helper, if introduced,
must be explicitly installed in the standalone tools tier. (R1–R8)

## Data model (R1–R4)

`--details-file PATH` is separate from `--notes-file PATH`. Read at most 16,384 bytes
plus one overflow-detection byte; UTF-8 JSON, one object, no duplicate/unknown keys.
Reject missing/unreadable/nonregular files and malformed encodings. Fail local-only
if the parser/runtime is unavailable. No implicit notes conversion.

| Key | Type and bound after trimming | Meaning |
|---|---|---|
| `summary` | string, 20–240 Unicode characters | specific harness defect |
| `observed` | string, 20–1500 characters | verified actual behavior |
| `expected` | string, 20–1500 characters | applicable documented behavior |
| `reproduction` | string, 20–1500 characters | minimal synthetic steps, or concrete source inspection procedure |
| `evidence` | string, 20–1500 characters | decisive observed result/source excerpts; reference an accepted harness path |
| `context` | object, exact keys below | trigger-specific proof; each value a string, 20–1000 characters |

Trigger selects the context schema (all listed keys required; others rejected):

| Trigger | Context keys | Required factual content |
|---|---|---|
| harness-malfunction | `failure`, `project_health` | failing harness operation/result and evidence project itself is healthy |
| contradictory-instruction | `instruction_a`, `instruction_b` | each incompatible obligation with harness source reference; observed explains incompatibility |
| workaround | `documented_path`, `failed_because`, `alternative` | intended path, concrete obstacle, actual departure used |
| missing-capability | `occurrences`, `workflow_gap`, `impact` | at least two concrete observed occasions, unavailable workflow path, consequence |

The tool enforces shape and lexical rules; the reporting command enforces factual
meaning, including recurrence and both sides of an instruction conflict. Tests for
prompt responsibility inspect the contract, not pretend that regex proves truth.
`evidence` must contain at least one accepted `--file` path as a complete path token,
optionally suffixed `:line`; substring matches inside larger paths are insufficient.

## API / interface (R1–R8)

Keep all current flags, `redact` mode and exit-0 reporting convention. Add only
`--details-file`. A metadata-only old invocation now writes local rejection details.
Validation must complete before auth/search/create; disabled/malformed-repo behavior
still makes no `gh` call and writes no report. Every enabled attempt retains local
metadata, raw notes if present, accepted public details when available, and outcome.
Unsafe details may be retained only locally. Diagnostics list specific failing
field paths (e.g. `context.instruction_b: missing`); never echo rejected payload
values into console diagnostics. Missing fields do not consume the creation cap.

Validation sequence:
1. Existing config/metadata/ownership/session gates; read bounded payload.
2. Strict schema, bounds, control and unsafe-corpus checks over decoded strings.
3. Trim public values and apply the existing redactor; validate useful content again.
4. Assemble the body and fingerprint exclusively from accepted sanitized data.
5. Existing cap, authenticated duplicate search, create, and local outcome handling.

Placeholder detection is case-insensitive, after whitespace/punctuation normalization:
reject values consisting solely of `todo`, `tbd`, `unknown`, `n/a`, `none`, `not
available`, `pending`, `placeholder`, `see logs`, `see notes`, `redacted`, or repeated
combinations of those tokens. Reject text consisting only of field labels, accepted
metadata values (version/trigger/symptom/files/command/role/phase/exit), punctuation,
or `[REDACTED-*]` placeholders. Minimum lengths apply after this normalization to
substantive content as well; a long placeholder or metadata list cannot pass.
The owner also rejects generic filler or unsupported evidence that passes lexical
checks. Do not implement an NLP classifier. (R2, R3)

Unsafe corpus, tested before sanitation: any token/email match in the existing
redaction corpus; private-key delimiters; credential assignments with keys
`token`, `secret`, `password`, `api_key`, or `authorization` (case-insensitive,
`:` or `=` delimiter and a nonempty value); URI schemes/URLs; absolute POSIX paths,
Windows drive/UNC paths, tilde-home paths, or relative `..` traversal components;
slash-separated relative paths not in the accepted harness `--file` set (optional
line-number suffix allowed). Prose mentioning a harness path must supply it as an
accepted `--file`; ordinary slash prose can be rewritten with words. Reject C0/C1
controls except LF and TAB, DEL, bidi overrides/isolates U+202A–U+202E and
U+2066–U+2069, HTML comment delimiters, and `harness-feedback:` case-insensitively.
Also reject lone Unicode surrogates. No executing, sourcing, evaluating, or shell
interpolating any field; backticks, `$()` and quotes are inert data and must be
covered by a canary test. (R4, R5)

The unchanged marker starts the body. Existing metadata lines precede headings
Summary, Observed, Expected, Reproduction or inspection, Evidence, Trigger context.
Render values as inert Markdown text, preserving useful newlines; ensure only one
marker token occurs. All auth/search arguments remain validated categorical data;
public prose reaches GitHub only in its body-file. (R5, R6)

## Duplicate identity (R7)

New title: `[harness-feedback] <trigger> <symptom> in <first-file> [<digest>]`, where
`digest` is the first 16 lowercase hex SHA-256 characters of canonical UTF-8 JSON
containing trigger, symptom, sorted unique accepted files, and the entire sanitized
details object. Canonicalize strings by collapsing whitespace runs to one space;
sort JSON object keys with fixed compact separators. Exclude session, phase, role,
version and command metadata from the fingerprint. The title uses the first path
from the same sorted unique file set, replacing F02's caller-order first-file rule;
reordered `--file` arguments cannot change identity. Search by the new title and
retain client-side exact equality. Never search using raw summary text, and never
let a matching legacy metadata-only title suppress a new detailed finding. No
migration or comment on legacy issues. Changes in factual wording can produce a
new identity; fuzzy matching is deliberately out of scope.

## Approach notes

Reporting skill composes a local JSON file afresh from verified evidence, inspects
it for confidentiality/completeness, passes it alongside optional raw notes, then
returns to its caller. No user question for missing details: preserve diagnostics
locally and continue authorized work. Subagent notes retain existing trigger,
symptom, command, phase and optional file plus named public-detail candidate fields;
unknown facts are explicitly missing. Owners inspect new notes at existing control
boundaries, including delegation returns, not through a new polling mechanism.
Ready reports can be filed before task/session end; end-of-session drain remains
for newly ready unfiled findings. Reuse one session token throughout. (R9–R11)

Regenerate with `sh harness-install.sh --self`. If a helper is added, update the
canonical installed tools inventory as required; verify it is available in targets
and thin children without relying on the source checkout. Keep source-only triage
and shared skill ownership unchanged. (R8, R12)
