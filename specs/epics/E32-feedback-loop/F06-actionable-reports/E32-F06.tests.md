## Behavioral checks

- Schema gate: no details flag, missing/unreadable/nonregular path, invalid UTF-8,
  malformed JSON, duplicate keys, extra keys at each level, nonstring/null values,
  wrong trigger-context keys, oversized file, field min/max boundaries, surrogate.
  Rejected enabled attempts return 0, create local diagnostics and make zero gh calls.
- Completeness: each missing field is named locally; blank/placeholder/repeated
  placeholder/metadata-only/padded redaction-token strings fail. Include length-valid
  metadata lists. Post-sanitation useful-content check is directly exercised, not
  just asserted in prose. Supplying missing facts on a later invocation with the same
  token can file once; withheld attempts do not consume the cap.
- Trigger matrix: one factually useful positive fixture for each of four triggers,
  each with required context; remove each context key in turn. Conflict fixture
  references two actual harness sources; capability fixture describes two occasions.
  A concrete inspection procedure passes without an invented runtime exit code.
- Unsafe corpus: test every defined class, including paths outside common home
  prefixes, Windows/UNC, traversal, URL, secret assignments, emails/tokens, controls,
  forged markers and HTML comments. Assert no auth/list/create call, not merely no
  creation. Exercise accepted-path token boundaries; an embedded path in a longer
  foreign path does not satisfy evidence linkage. Known unsafe material anywhere
  in nested context fails too.
- Privacy/canary: raw notes contain secrets and shell payload; valid public details
  contain inert quotes/backticks/command substitutions. Assert notes stay only in
  local copy, payload is never executed, and gh receives a body-file argument with
  the intended bytes. Canary must be executable if the implementation mistakenly
  evaluates the field; avoid hiding it behind invalid shell syntax.
- Body: capture body-file at stub gh creation, assert exact first marker, exactly
  one marker token, all common/context headings and accepted facts. No dropped file,
  raw note, session token or details-file absolute path appears upstream.
- Fingerprint: same details with reordered JSON keys/whitespace/`--file` arguments and changed session,
  version/phase produce identical title; different observed defect in same file
  yields different title. Exact open match suppresses issue/comment; substring and
  legacy metadata-only title do not. Search contains fixed title/digest, never prose.
- Guards: use complete valid details for enabled happy path, disabled/malformed repo,
  rejected metadata/path/session, cap 0/default/explicit and same-session repeated
  calls. Force each auth/list/create failure separately and missing gh/parser;
  all fall back without failing caller. Test source, normal installed and thin-child
  governing roots with local paths and version resolution correct. Existing suites
  remain the contract for unchanged behavior.
- Prompt contracts: inspect canonical sections and freshly installed artifacts for
  all three hosts. Require immediate automatic filing, no permission question,
  factual owner inspection, raw notes local, no invented evidence, single writer,
  stable token, resume after reporting, and init hard stop. Remove/replace obsolete
  end-only/never-mid-flow assertions. Historical specifications are excluded from
  current-doc scans. Check the canonical emitter, not only committed copies.
