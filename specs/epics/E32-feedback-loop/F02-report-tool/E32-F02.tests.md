## Discrimination requirements (the Reviewer mutates these)

- **R1:** assert the marker against the full anchored regex (`^<!-- harness-feedback:v1 … -->$`),
  not a substring, and assert the count is exactly 1. The regex has **three** `key=value`
  groups (`host`, `version`, `trigger`) after the `harness-feedback:v1` token; a test that
  expects four `=` groups is wrong. A mutant that drops `trigger`, swaps field order, or bumps
  `v1` must red. Positive control: the extracted body must be non-empty (length floor), so a
  missing body cannot pass vacuously. Add a non-semver `VERSION` fixture (e.g. `0.86.0-rc1`):
  no `issue create`, a local report, exit 0.
- **R2:** assert **both** zero recorded `gh` invocations and zero files under
  `progress/feedback/`. Run the R11 positive control (same fixture, `enabled: true`) in the
  suite so an absent file cannot pass because the whole path is broken.
- **R3:** use distinct non-default values (`repo: ghe.example.com/acme/fork` → host
  `ghe.example.com`; the two-part form → `github.com`). Malformed values (a scheme, a
  trailing `/`, four parts) must turn reporting off, asserted as R2's shape.
- **R4:** for each field, a distinctive out-of-list value must produce a local report and no
  `issue create`; a valid value for the same field must produce a create. Never assert only
  the negative — the positive control is what proves the predicate is live. For `--command`,
  a plausible-but-unshipped name (`my-project-tool`) must reject, and a shipped basename
  (`run-tests.sh`) must create — this is what proves the field is a semantic allow-list rather
  than a charset. Add the missing-`--trigger` case: no `issue create`, a local report, exit 0.
  Assert `$?` is 0 for every case in this test (the tool has no non-zero exit path).
- **R5:** the dropped project path must be **distinctive** (`src/secret-app.py`) and asserted
  absent from title **and** body; the harness path must be asserted present in both. A
  mutant that skips validation must red. Middle-grep control: the pristine created body must
  contain the harness path ≥1 time.
- **R6:** full-string equality on the `--title` argv value, not a substring or a multi-grep
  over the log. A mutant that changes the prefix, the word `in`, or the field order must red.
- **R7:** put a distinctive free-form token in `--notes-file`; assert it is absent from the
  created body (a `grep -F` that must match nothing) and present in the local copy. Positive
  control: the same grep against the local copy matches ≥1 line, so the negative is not
  dead.
- **R8:** for each named corpus shape, assert the raw shape is absent downstream and the
  `[REDACTED-…]` token is present; positive control: the raw shape is present in the input fed
  to `redact`. Exercise the pass on the real create path with a fixture-created harness-owned
  file whose basename is token-shaped (e.g. a file under `.harness/tools/` named
  `ghp_…`) — it passes R5 and must be redacted in the `File:` line. **Marker-preservation
  control:** use a grammar-valid repo host that itself looks like a corpus token (e.g.
  `sk-…/acme/fork`) and assert the marker line is byte-exact and unredacted while a label line
  is redacted; a mutant that redacts the whole body must red.
- **R9:** the stub's `issue list` must be asserted to carry `in:title` and the R6 title. Two
  controls: (a) an issue whose title merely *mentions* the words (not equal to the title) must
  still create; (b) an issue whose title equals the R6 title exactly must produce zero
  `issue create` **and** zero `comment`. A mutant that matches substrings must turn control
  (a) red.
- **R10:** count creates across calls against one ledger. A mutant that counts per-invocation
  (never persisting) or never resets on token change must red. Assert the boundary exactly
  (`max_per_session: 2` → exactly two creates, third none), not `≥`. Add the missing/invalid
  token case: zero creates and a local report whose outcome is `no-session`.
- **R11:** run the missing-`gh` case (PATH without it) and the failing-`gh` case (stub exits
  non-zero), asserting the local file exists and `$?` is 0 in each. Positive control: the
  normal stub creates and **also** writes the local copy.
- **R12:** extract the `## [0.86.0]` CHANGELOG span before grepping the tool name, and the
  `## Harness feedback` INSTALL.md span before asserting the corrected sentence, so a token
  elsewhere in the file cannot satisfy it. The pristine-bytes control compares the base
  branch's `docs/INSTALL.md` (`origin/main`, else `main`) with the working copy: while they
  differ the base IS the pre-change text and MUST contain `No reporter ships yet` on ≥1 line
  (a base that lost or never had the phrase reds), and the working copy must always contain
  0 lines. Once the base already carries the change (post-merge) the liveness assertion is
  N/A and only the working-file negative runs. The positive control asserts the replacement
  span names `E32-F02` and `E32-F03`.

## Behavioral / end-to-end checks
- Build an installed-target fixture with `feedback.enabled: true` and an authenticated stub
  `gh`. Run the tool by hand: an issue is created, the title/marker/body match, and the local
  copy exists. Re-run with `enabled: false`: nothing happens, exit 0. Empty `PATH` of `gh`:
  the local copy is written and the task is not failed.
- Confirm a duplicate (stub returns the same issue) opens nothing and comments on nothing.
- Confirm `progress/feedback/` is not newly tracked by git in either layout (the existing
  `progress/*/` ignore already covers it).

## Non-functional checks
- `./init.sh` green; `./tools/run-tests.sh` green (re-run any unrelated red suite alone
  before chasing it).
- The new suite is POSIX sh, executable (`[ -x tests/test_feedback_report.sh ]`), and passes
  under dash.
- `sh harness-install.sh --self` produces no diff in generated glue.
- No test makes a network call; every `gh` is the stub.
